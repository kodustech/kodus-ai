## Como a Z.AI funciona

A Z.AI serve a família de modelos GLM. O **GLM Coding Plan** é uma assinatura de taxa fixa: o uso é limitado por créditos em janelas de 5 horas e semanais, em vez de cobrança por token.

A Z.AI também oferece acesso pay-per-token na sua Developer API padrão.

Os dois caminhos expõem um endpoint compatível com OpenAI, então a Kodus pode se comunicar com eles pelo provedor **OpenAI-compatible**. A Kodus também tem um provedor **Z.ai** dedicado, que se conecta pelo endpoint compatível com Anthropic da Z.AI (`https://api.z.ai/api/anthropic`).

## Visão geral dos planos

<Info>
  Use uma chave da **Developer API** para rodar reviews na Kodus. A Z.AI restringe o GLM Coding Plan às [ferramentas que ela autoriza](https://docs.z.ai/devpack/tool/others#supported-tools). Confirme a elegibilidade com a Z.AI antes de usar uma assinatura do Coding Plan na Kodus.
</Info>

### GLM Coding Plan (assinatura)

| Tier | Créditos de 5 horas | Créditos semanais |
| ---- | ------------------- | ----------------- |
| **Lite** | 2.000 | 10.000 |
| **Pro**  | 12.000 | 60.000 |
| **Max**  | 28.000 | 140.000 |

- Os créditos de 5 horas são redefinidos 5 horas depois de você usá-los. Os créditos semanais começam quando você assina e são redefinidos a cada 7 dias. Planeje-se em torno desses tetos, não de um limite mensal.
- Os planos começam em $18 por mês. O preço de cada tier está em [z.ai/subscribe](https://z.ai/subscribe).
- Os limites de simultaneidade dependem do tier (Max o maior, depois Pro, depois Lite). A documentação da Z.AI não lista os números.
- Todos os planos incluem GLM-5.3 e GLM-5.3-Flash. Requisições para modelos GLM mais antigos são roteadas para estes.
- Endpoints do Coding Plan: `https://api.z.ai/api/anthropic` (compatível com Anthropic — o que o provedor **Z.ai** da Kodus usa) e `https://api.z.ai/api/coding/paas/v4` (compatível com OpenAI). O endpoint padrão `/api/paas/v4/` não consome do Coding Plan.

### Developer API pay-per-token

Preços e disponibilidade de modelos mudam. Confirme na [página de preços da Z.AI](https://docs.z.ai/guides/overview/pricing) antes de escolher um modelo. Endpoint padrão: `https://api.z.ai/api/paas/v4/` (compatível com OpenAI).

## Criando uma Chave de API

<Warning>Uma conta Z.AI é necessária para criar uma chave de API.</Warning>

<Tabs>
  <Tab title="Assinante do Coding Plan">
    1. Faça login em [z.ai](https://z.ai).
    2. Confirme com a Z.AI que seu uso do Coding Plan na Kodus é permitido antes de contratar a assinatura.
    3. Abra [z.ai/manage-apikey/apikey-list](https://z.ai/manage-apikey/apikey-list) e crie uma chave de API em **Personal Coding Plan**.

    <Note>
      A Z.AI gerencia separadamente as chaves do Coding Plan, do Team Plan e da API padrão, e elas não são intercambiáveis. Use uma chave do Coding Plan nos endpoints do Coding Plan (`/api/anthropic` e `/api/coding/paas/v4`). Chamadas ao endpoint padrão `/api/paas/v4/` são cobradas do saldo da sua conta, não da cota do Coding Plan.
    </Note>
  </Tab>

  <Tab title="Developer API (pay-per-token)">
    1. Faça login em [z.ai](https://z.ai).
    2. Abra [z.ai/manage-apikey/apikey-list](https://z.ai/manage-apikey/apikey-list).
    3. Crie uma chave de API em **Standard API Key**.

    <Note>
      Chaves da API padrão são cobradas por token. Enviadas a um endpoint do Coding Plan, elas não usam a cota do Coding Plan.
    </Note>
  </Tab>
</Tabs>

## Configurar a Z.AI na Kodus

O fluxo principal é a página **AI providers**, que é a mesma na Kodus Cloud e em uma instância self-hosted. Usuários self-hosted que preferem fixar o provedor no nível do processo podem usar variáveis de ambiente.

### Opção 1 — Provedor Z.ai com o endpoint Anthropic

Para a **Developer API**, siga a Opção 2 com uma conexão OpenAI-compatible.

<Steps>
  <Step title="Abrir AI providers e escolher Z.ai">
    Na barra lateral, abra **AI providers** ([app.kodus.io/byok](https://app.kodus.io/byok) no Cloud, `/byok` na sua própria instância). Na aba **Providers**, clique no card **Z.ai** (em **Connect your first provider**, ou em **Add another provider** se você já conectou um).
  </Step>

  <Step title="Colar sua chave de API e informar o modelo">
    Cole sua chave da Z.AI no card **API key** e digite o ID do modelo (ex.: `glm-5.3`) em **Model**. A Kodus preenche o endpoint `https://api.z.ai/api/anthropic` para você — o endpoint compatível com Anthropic que a Z.AI documenta para o GLM Coding Plan — então este card não tem seletor de plano nem campo de base URL. Para usar um endpoint compatível com OpenAI específico, use a Opção 2 abaixo.
  </Step>

  <Step title="Definir a simultaneidade (Coding Plan)">
    A Kodus não preenche a simultaneidade. No Coding Plan, abra **Advanced (optional)** → **Advanced settings** e defina **Max concurrent requests**. A Z.AI atrela o limite ao seu tier e a documentação dela não lista os números, então comece baixo e aumente enquanto você não vir erros 429.
  </Step>

  <Step title="Test & save">
    Clique em **Test & save**. A Kodus testa a conexão e salva a configuração em caso de sucesso. Um erro de autenticação significa que a chave não corresponde ao endpoint.
  </Step>
</Steps>

### Ajustar o reasoning (opcional)

**Thinking / Reasoning** fica em **Advanced (optional)** → **Advanced settings**.

O GLM-5.3 e o GLM-5.3-Flash sempre fazem reasoning, e a Z.AI não permite desligá-lo: `thinking.type` aceita apenas `enabled`, e uma requisição com `disabled` falha. A Kodus não envia nada para esses modelos quando **Thinking / Reasoning** está em **Off**.

No GLM-5.3, a Z.AI aceita `reasoning_effort` com `low`, `high` ou `max` (padrão `max`). Para definir isso pela Kodus, conecte por **OpenAI-compatible** (Opção 2) e escolha **Low**, **Medium** ou **High**, que enviam `low`, `high` e `max`. O card **Z.ai** não consegue definir isso: ele envia um budget de thinking.

<Note>
  Para enviar outras opções do provedor, mude **Thinking / Reasoning** para **Custom**. A Kodus envolve o JSON no namespace do provedor ativo. Veja [Custom JSON override](/pt-BR/how_to_use/byok/model_settings#custom-json-override).
</Note>

### Ajustar a simultaneidade

- **Coding Plan**: defina **Max concurrent requests** com um valor baixo, já que a Z.AI limita a simultaneidade por tier. Ir mais alto pode retornar 429.
- **Developer API**: comece vazio (sem limite). Se você vir erros de rate limit, defina um limite e vá aumentando. Veja a página de [rate limits](https://docs.z.ai/api-reference/rate-limit) da Z.AI.

<Note>
  Em **Code review → Routing** (o botão **Configure routing** em **AI providers**), defina seu modelo GLM como **Default model** e um modelo da OpenAI ou Anthropic como **Fallback model**, para que as revisões continuem funcionando quando os créditos do seu Coding Plan acabarem. A Kodus faz o failover automaticamente.
</Note>

### Opção 2 — Endpoint compatível com OpenAI

Para se conectar por um dos endpoints compatíveis com OpenAI da Z.AI, abra **AI providers**, escolha **OpenAI-compatible** em **Custom** na aba **Providers** e preencha:

| Campo | Valor |
| --- | --- |
| **Base URL** | `https://api.z.ai/api/coding/paas/v4` (Coding Plan)<br />`https://api.z.ai/api/paas/v4/` (Developer API) |
| **Model** | ex.: `glm-5.3` ou `glm-5.3-flash` |
| **Key** (no card **API key**) | sua chave da Z.AI (correspondente à base URL acima) |
| **Max concurrent requests** (em **Advanced (optional)** → **Advanced settings**) | um valor baixo no Coding Plan; deixe vazio na Developer API |

### Opção 3 — Self-hosted (variáveis de ambiente)

Para dar a uma instância self-hosted um modelo via `.env`:

```env
API_LLM_PROVIDER=openai_compatible
API_LLM_PROVIDER_MODEL="glm-5.3"
API_LLM_BASE_URL="https://api.z.ai/api/paas/v4/"
API_LLM_API_KEY="your-z-ai-api-key"
```

Para usar o endpoint compatível com Anthropic, defina `API_LLM_PROVIDER=anthropic_compatible` e `API_LLM_BASE_URL="https://api.z.ai/api/anthropic"`.

Siga o guia de instalação para [aplicar a mudança de modelo](/pt-BR/how_to_deploy/deploy_kodus/generic_vm#aplicar-mudanças-no-modelo).

## Escolhendo entre o Coding Plan e pay-per-token

- Use a **Developer API** para reviews na Kodus, com cobrança por token.
- Para usar uma assinatura do Coding Plan, confirme seu caso de uso com a Z.AI antes de depender das cotas.

## Solução de problemas

<AccordionGroup>
  <Accordion title="O teste falha — a chave não corresponde ao endpoint">
    - Chaves do Coding Plan são para `/api/anthropic` e `/api/coding/paas/v4`. Chaves da API padrão são para `/api/paas/v4/`. As duas não são intercambiáveis.
    - O card **Z.ai** sempre usa `https://api.z.ai/api/anthropic`. Para usar outro endpoint, conecte por **OpenAI-compatible** com essa **Base URL**.
    - Com **OpenAI-compatible**, confirme que a **Base URL** corresponde à origem da chave.
    - O erro `1113 Insufficient balance` em um Coding Plan pode significar a base URL errada, uma ferramenta que a Z.AI não suporta, ou um modelo diferente de GLM-5.3 ou GLM-5.3-Flash.
  </Accordion>

  <Accordion title="429 na hora da revisão">
    - A Z.AI retorna HTTP 429 quando você atinge um rate limit (erro `1302`). Diminua **Max concurrent requests** em **Advanced (optional)** → **Advanced settings**.
    - A Z.AI limita a simultaneidade por tier. Um tier maior permite mais.
  </Accordion>

  <Accordion title="Cota esgotada no Coding Plan">
    - A Z.AI aplica um limite de créditos de **5 horas** e um **semanal**. Atingir um deles retorna HTTP 429 (erro `1308` ou `1310`) com o horário em que é redefinido.
    - Confira seus créditos restantes no console da Z.AI.
    - Opções: esperar a redefinição, fazer upgrade para um tier maior, ou ter uma chave da Developer API configurada como **Fallback model** em **Code review → Routing** para cobrir a lacuna.
  </Accordion>

  <Accordion title="Modelo não encontrado">
    - Verifique se o ID do modelo corresponde ao catálogo da Z.AI (por exemplo `glm-5.3` ou `glm-5.3-flash`). IDs GLM mais antigos são roteados para os modelos atuais no Coding Plan.
    - O Coding Plan cobre apenas GLM-5.3 e GLM-5.3-Flash. Outros nomes de modelo são rejeitados.
  </Accordion>

  <Accordion title="Erros de conexão (timeout, DNS)">
    - Confirme que seu servidor pode alcançar `api.z.ai`.
    - Verifique os logs da API e do worker para o erro upstream exato.
    - Se você está em uma região com tráfego de saída restrito, roteie as requisições por um proxy reverso que sua infra permita.
  </Accordion>
</AccordionGroup>
