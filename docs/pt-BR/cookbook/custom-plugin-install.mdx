## Por que plugins personalizados

Um plugin personalizado permite que o Kody leia seus sistemas internos, como uma base de conhecimento, um dashboard de incidentes ou um mecanismo de políticas, enquanto responde num pull request. Os revisores param de colar capturas de tela e trechos desatualizados nos comentários.

<Callout icon="globe">
  O Kodus suporta **apenas servidores MCP remotos**. O servidor precisa ser acessível a partir da infraestrutura do Kodus: nada de `localhost`, nada de endpoints MCP de desktop.
</Callout>

## Prepare as informações do seu plugin

Reúna estes detalhes antes de abrir a página de Plugins:

| Campo | Por que é importante |
| ----- | -------------------- |
| **URL** | O endpoint MCP, por exemplo `https://acme-internal-tools.com/mcp`. |
| **Protocol** | **HTTP** ou **SSE**. |
| **Authorization** | **None**, **Bearer Token**, **Basic Auth**, **API Key** (e o header em que ela vai) ou **OAuth 2.0** (um client ID, ou registro dinâmico de cliente). |
| **Descrição e logo** | Opcional. Ajudam os colegas a reconhecer o plugin. |

Procurando servidores MCP remotos para experimentar?

- [Smithery.ai](https://smithery.ai/) seleciona serviços MCP implantáveis.
- [Awesome Remote MCP Servers](https://github.com/sylviangth/awesome-remote-mcp-servers) lista endpoints mantidos pela comunidade.

## Instalar o plugin no Kodus

<Frame caption="Plugins → card Add Custom Plugin → Add Plugin abre este formulário">
  <img src="/images/custom-plugin.png" alt="Add Custom Plugin form" />
</Frame>

<Steps>
  <Step title="Abra o formulário">
    Na barra lateral, abra **Plugins**. No card **Add Custom Plugin**, clique em **Add Plugin**.
  </Step>
  <Step title="Preencha o formulário">
    ```text
    Plugin Name: Descriptive label (for example "Security Runbooks MCP")
    Description: What data it exposes (optional)
    Logo URL: Optional
    URL: https://your-domain.com/mcp
    Protocol: HTTP or SSE
    Authorization: None, Bearer Token, Basic Auth, API Key or OAuth 2.0
    Custom Headers: Any extra header your server needs (optional)
    ```

    Clique em **Create Plugin**.
  </Step>
  <Step title="Escolha as ferramentas e instale">
    O plugin abre. Com OAuth 2.0, clique primeiro em **Authenticate with** o plugin. Em **Selected tools**, mantenha só as ferramentas de que o Kody precisa e clique em **Install plugin**. Um plugin instalado mostra **Installed** no card.
  </Step>
</Steps>

Se **Selected tools** mostrar 0 of 0, o Kodus não conseguiu listar as ferramentas do servidor. Abra o plugin, clique em **Edit Plugin** e confira a URL, o protocolo e a autorização.

<Warning>
  O Kody pode chamar qualquer ferramenta que você selecionar. Instale só endpoints em que a sua organização confia e selecione só as ferramentas de que o Kody precisa.
</Warning>

## Verificar a conexão

1. Abra um pull request num repositório em que o Kody está habilitado.
2. Comente com `@kody` e uma pergunta que só o plugin consegue responder:

   ```
   @kody can you fetch the deployment checklist from our MCP and confirm whether feature flags are required?
   ```

3. Confira a resposta do Kody. Ela deve incluir dados retornados pelo seu plugin. Se não incluir, abra o plugin na página **Plugins** e confira a URL, o protocolo e a autorização.

<Info>
  Para ensaiar o fluxo sem construir um servidor, adicione `https://docs.kodus.io/mcp` como plugin personalizado: protocolo **HTTP**, autorização **None**.
</Info>

## Use num agente personalizado

Um agente personalizado lê de um plugin instalado quando você o liga em **Tools → Plugins**, na página do agente. Só ferramentas de leitura são oferecidas. Veja [Skills, documentação e ferramentas](/pt-BR/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp).

## Checklist rápido

- [ ] O servidor é acessível pelo Kodus via HTTP ou SSE.
- [ ] A autorização dele funciona com o método que você escolheu.
- [ ] **Selected tools** lista ferramentas, e só as de que o Kody precisa estão selecionadas.
- [ ] O plugin mostra **Installed**.
- [ ] Um comentário de teste num pull request retornou dados do plugin.
- [ ] Alguém é responsável por monitorar e atualizar a integração.
