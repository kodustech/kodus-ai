<Note>
  Este guia é destinado ao desenvolvimento local. Para implantação em produção,
  consulte o guia [Implantar Kodus](/pt-BR/how_to_deploy/deploy_kodus/generic_vm).
</Note>

<Note>
  O `.env.example` é o template compartilhado com o Kodus Cloud, então um `.env` novo vem com
  `API_CLOUD_MODE=true` e `SANDBOX_PROVIDER=e2b`. Para rodar do jeito de uma instância
  self-hosted, defina `API_CLOUD_MODE=false` e
  `SANDBOX_PROVIDER=local` no `.env` antes de iniciar os serviços. Com
  `API_CLOUD_MODE=false`, o heartbeat anônimo diário para `telemetry.kodus.io`
  vem habilitado por padrão. Se você não quiser que seus experimentos locais
  apareçam na frota, defina `KODUS_TELEMETRY_DISABLED=true`. Veja
  [Telemetria Anônima](/pt-BR/how_to_deploy/deploy_kodus/telemetry) para
  saber o que é enviado e como inspecionar.
</Note>

## Pré-requisitos

- Node.js (veja o `.nvmrc` para a versão fixada)
- pnpm
- Docker
- OpenSSL
- Uma chave de API de LLM

<Note>
  O kodus-ai é um workspace pnpm — o `pnpm-lock.yaml` é o único lockfile do repositório. npm e yarn
  não são suportados para desenvolvimento local.
</Note>

## Executando o projeto

<Tabs>
  <Tab title="Configuração Automatizada (Recomendada)">
      Para uma configuração rápida e automatizada, use nosso script de setup:

      ```bash
      git clone https://github.com/kodustech/kodus-ai.git
      cd kodus-ai
      pnpm run setup
      ```

      <Warning>
        Use `pnpm run setup`, não `pnpm setup` — este último é o comando nativo do próprio pnpm para
        configurar seu diretório home e não executa o script do projeto.
      </Warning>

      Este script irá automaticamente:
      - Verificar todas as dependências necessárias (Node.js, pnpm, Docker, OpenSSL)
      - Instalar as dependências do projeto
      - Criar o arquivo `.env` a partir do `.env.example`
      - Gerar as chaves de segurança
      - Criar as redes Docker `kodus-backend-services` e `shared-network`
      - Exibir os próximos passos

      Depois, [conecte um modelo](#conectar-um-modelo) e inicie os serviços:

      ```bash
      pnpm run docker:start
      ```

      **Com integrações externas (webhooks, etc.):**
      ```bash
      pnpm run docker:start
      pnpm run tunnel  # Creates public endpoint for external services
      ```

      <Info>
        As migrations e os seeds do banco rodam **automaticamente** no boot do container — o arquivo
        compose de desenvolvimento usa `RUN_MIGRATIONS` e `RUN_SEEDS` com padrão `true`. Você não
        precisa de um passo separado.

        Se você definir essas variáveis como `false` para gerenciá-las por conta própria, rode
        `pnpm run migration:run` e `pnpm run seed` a partir do host.
      </Info>

      Após tudo estar em execução, abra **http://localhost:3000** no seu navegador.
  </Tab>
  <Tab title="Configuração Manual">
      Se preferir configurar tudo manualmente:

      ### 1. Clonar o repositório

      ```bash
      git clone https://github.com/kodustech/kodus-ai.git
      cd kodus-ai
      ```

      ### 2. Instalar dependências

      ```bash
      pnpm install
      ```

      ### 3. Configurar variáveis de ambiente

      ```bash
      cp .env.example .env
      ```

      ### 4. Gerar chaves de segurança

      Gere valores seguros para os segredos do `.env`:

      ```bash
      # JWT secrets and the NextAuth secret
      openssl rand -base64 32

      # Encryption key and code management secret
      openssl rand -hex 32

      # Webhook token (URL-safe)
      openssl rand -base64 32 | tr -d '=' | tr '/+' '_-'
      ```

      Defina estas variáveis:
      - `API_JWT_SECRET` (use `openssl rand -base64 32`)
      - `API_JWT_REFRESH_SECRET` (use `openssl rand -base64 32`)
      - `API_CRYPTO_KEY` (use `openssl rand -hex 32`)
      - `CODE_MANAGEMENT_SECRET` (use `openssl rand -hex 32`)
      - `CODE_MANAGEMENT_WEBHOOK_TOKEN` (use `openssl rand -base64 32 | tr -d '=' | tr '/+' '_-'`)
      - `WEB_NEXTAUTH_SECRET` e `NEXTAUTH_SECRET`, com o mesmo valor (use `openssl rand -base64 32`)

      ### 5. Configurar redes Docker

      Crie as redes Docker necessárias:

      ```bash
      docker network create kodus-backend-services || true
      docker network create shared-network || true
      ```

      ### 6. Conectar um modelo

      Siga [Conectar um modelo](#conectar-um-modelo) abaixo.

      ### 7. Iniciar o ambiente de desenvolvimento

      Inicie os serviços usando Docker:

      ```bash
      pnpm run docker:start
      ```

      Este comando inicia:

      - Kodus API
      - Worker (tarefas assíncronas)
      - Serviço de Webhooks
      - Aplicação Web do Kodus
      - Banco de dados PostgreSQL
      - Banco de dados MongoDB
      - RabbitMQ

      Para também criar um endpoint público para serviços externos:
      ```bash
      pnpm run tunnel
      ```

      ### 8. Configuração inicial

      Nada a fazer — o container da API roda migrations e seeds no boot, porque o
      `docker-compose.dev.yml` usa `RUN_MIGRATIONS` e `RUN_SEEDS` com padrão `true`.

      <Accordion title="Rodando migrations manualmente">
        Se você definir `RUN_MIGRATIONS=false` / `RUN_SEEDS=false` no seu `.env` (por exemplo
        para controlá-las você mesmo), rode a partir do host com:

        ```bash
        pnpm run migration:run   # OLTP database
        pnpm run seed            # initial data
        ```

        Há comandos separados para os outros datastores:

        ```bash
        pnpm run analytics:migration:run     # analytics warehouse
        pnpm run mcp-manager:migration:run   # MCP manager
        pnpm run mongo:migrate               # MongoDB
        ```
      </Accordion>

      ### 9. Endpoints dos serviços

      Acesse os serviços em:

      - Web UI: `http://localhost:3000`
      - API: `http://localhost:3001`
      - Webhooks: `http://localhost:3332`
      - Gerenciamento RabbitMQ: `http://localhost:15672`
      - PostgreSQL: `localhost:5432`, MongoDB: `localhost:27017`
      - Porta de debug da API: `9229`

  </Tab>
</Tabs>

## Conectar um modelo

O Kodus precisa de um modelo para executar reviews. Escolha uma opção antes de iniciar os serviços:

- **No app.** Depois de entrar, abra **AI providers** na barra lateral e conecte um provedor com a sua chave. Veja [BYOK](/pt-BR/how_to_use/byok).
- **No `.env`.** Um modelo para a instância inteira:

  ```env
  API_LLM_PROVIDER=openai                  # openai, openai_compatible, anthropic, anthropic_compatible, google_gemini or google_vertex
  API_LLM_PROVIDER_MODEL="your-model-id"
  API_LLM_API_KEY="your-api-key"
  # API_LLM_BASE_URL="https://your-provider.example.com/v1"   # required for the *_compatible providers
  ```

  Veja [Configuração do Provedor de LLM](/pt-BR/how_to_deploy/deploy_kodus/generic_vm#configuração-do-provedor-de-llm) para saber o que cada provedor exige. Um modelo conectado na página **AI providers** substitui o do `.env`.

## Serviços opcionais

O `pnpm run docker:start` não inicia o MCP Manager nem o analytics worker. Adicione-os com `KODUS_DEV_EXTRAS`:

```bash
KODUS_DEV_EXTRAS=mcp pnpm run docker:start          # MCP Manager (also set API_MCP_SERVER_ENABLED=true)
KODUS_DEV_EXTRAS=analytics pnpm run docker:start    # analytics worker
KODUS_DEV_EXTRAS=mcp,analytics pnpm run docker:start
```

## Fluxo de desenvolvimento

### Desenvolvimento Local Básico

1. **Iniciar serviços**: `pnpm run docker:start` (migrations e seeds rodam automaticamente)
2. **Abrir o app**: Acesse `http://localhost:3000`
3. **Verificação de saúde**: `pnpm run dev:health-check`

### Desenvolvimento com Integrações Externas

Se precisar testar integrações com serviços externos (como webhooks Git):

1. **Iniciar serviços**: `pnpm run docker:start`
2. **Criar tunnel**: `pnpm run tunnel` (cria endpoint público)
3. **Atualizar URLs de webhook**: O comando tunnel atualiza seu `.env` automaticamente
4. **Configurar provedor Git**: Use a URL do tunnel nas configurações de webhook do seu provedor Git
5. **Testar integração**: Dispare webhooks e monitore os logs

<Info>
  **Benefícios do Tunnel:**
  - Testar integrações reais de webhook localmente
  - Depurar comunicações com serviços externos
  - Compartilhar seu ambiente de desenvolvimento com membros da equipe
  - Testar aplicativos móveis ou outros clientes externos
</Info>

## Solução de Problemas

### Verificação Rápida de Saúde

```bash
pnpm run dev:health-check
```

Esta verificação de saúde valida:
- **Serviços**: os contêineres da API, worker, webhooks, web, PostgreSQL, MongoDB e RabbitMQ
- **Disponibilidade de portas**: Web (3000), API (3001), PostgreSQL (5432), MongoDB (27017), RabbitMQ (5672)
- **Configuração do banco de dados**: migrations e dados iniciais
- **Endpoints da API**: `/health/simple`, `/health` e conectividade básica


### Verificação Manual

1. **Verificar Web UI**: Acesse `http://localhost:3000` no seu navegador
2. **Verificar saúde da API**: Acesse `http://localhost:3001/health`
3. **Verificar RabbitMQ**: Acesse `http://localhost:15672` (credenciais padrão: `dev`/`devpass`, de `RABBITMQ_DEFAULT_USER` e `RABBITMQ_DEFAULT_PASS` no `.env`)
4. **Verificar conexões com banco de dados**: Verifique os logs para conexões bem-sucedidas
5. **Testar endpoints de webhook**: Os webhooks do seu provedor Git devem apontar para `http://localhost:3332/[provider]/webhook` (ou para o domínio da sua API se um proxy reverso rotear `/.../webhook` para o serviço de webhooks)


### Problemas com o Script de Setup

Se o script de configuração automatizada (`pnpm run setup`) falhar:

**Dependências ausentes:**
```bash
# Check if all required tools are installed
node --version
pnpm --version
docker --version
openssl version
```

**Problemas de permissão com Docker:**
```bash
# Add your user to the docker group (Linux)
sudo usermod -aG docker $USER
# Then log out and log back in
```

**Erros na criação de redes:**
```bash
# Check if networks already exist
docker network ls | grep -E "kodus|shared"
# Remove conflicting networks if needed
docker network rm kodus-backend-services shared-network
```

### Problemas Comuns

**Conflitos de porta:**
- Certifique-se de que as portas 3000 (Web), 3001 (API), 3332 (Webhooks), 5432 (PostgreSQL), 27017 (MongoDB) e 5672/15672 (RabbitMQ) estão disponíveis
- Pare outros serviços que usam essas portas antes de iniciar o Kodus

**Variáveis de ambiente não carregando:**
- Verifique se o arquivo `.env` existe na raiz do projeto
- Confira se não há espaços no final das atribuições de variáveis
- Certifique-se de que todas as chaves de segurança necessárias foram geradas corretamente

**Falhas na verificação de saúde:**
- Execute `pnpm run dev:health-check` para obter diagnósticos detalhados
- Verifique se os contêineres estão totalmente iniciados (aguarde 1-2 minutos após `pnpm run docker:start`)
- Confirme que as migrations e dados iniciais foram carregados
- Verifique os logs da API com `pnpm run docker:logs` para erros de inicialização

**API sem resposta:**
- A API leva algum tempo para inicializar completamente após a inicialização do contêiner
- Verifique se as migrations e dados iniciais foram carregados
- Confirme que o arquivo `.env` possui todas as variáveis necessárias
- Execute a verificação de saúde para ver quais componentes específicos estão falhando

**Os reviews não rodam:**
- Nenhum modelo está conectado. Abra **AI providers** ou defina `API_LLM_PROVIDER_MODEL` e uma chave no `.env`.

**Os reviews não têm contexto entre arquivos:**
- `SANDBOX_PROVIDER=e2b` sem `API_E2B_KEY` executa os reviews sem sandbox. Defina `SANDBOX_PROVIDER=local`.

**Problemas de webhook com serviços externos:**
- Use `pnpm run tunnel` para criar um endpoint público para webhooks externos
- Atualize as URLs de webhook do seu provedor Git para usar a URL do tunnel
- Certifique-se de que o tunnel está em execução ao testar integrações de webhook
- Verifique os logs do tunnel para problemas de conexão
