## Configuração das Variáveis de Ambiente

Use esta seção para preencher seu `.env`. Comece pelas URLs públicas, depois configure o provedor de LLM, os bancos de dados e o RabbitMQ, e por fim adicione as configurações específicas dos provedores. O `./scripts/generate-secrets.sh` já preencheu os segredos.

### URLs Públicas

Estas configurações dizem à Kodus onde ela pode ser acessada. Troque os domínios de exemplo pelos seus.

```env
NEXTAUTH_URL="https://kodus-web.yourdomain.com"          # Full public URL of the web app
API_FRONTEND_URL="https://kodus-web.yourdomain.com"      # Same URL: CLI login, SSO and GitHub App redirects
API_USER_INVITE_BASE_URL="https://kodus-web.yourdomain.com" # Same URL: links in emails and review comments
API_HOST=0.0.0.0

# How the web app's server reaches the API. Keep the defaults.
WEB_HOSTNAME_API=localhost    # Kodus resolves this to GLOBAL_API_CONTAINER_NAME
WEB_PORT_API=3001

# Only for SSO (Enterprise): the public API URL your identity provider redirects back to.
# API_URL="https://kodus-api.yourdomain.com"
```

<Info>
  Com o padrão `WEB_HOSTNAME_API=localhost`, o app web localiza a API usando `GLOBAL_API_CONTAINER_NAME` (`kodus_api` no instalador).

  O navegador fala com o app web, e o servidor do app web chama a API. Quando `WEB_PORT_API` está definido, o app web chama `http://<WEB_HOSTNAME_API>:<WEB_PORT_API>`, então precisa ser um endereço HTTP simples que o container web consiga alcançar. Não o defina como um endereço HTTPS público com porta 443. O `install.sh` avisa quando `WEB_HOSTNAME_API` é `localhost`. Você pode ignorar esse aviso: os provedores Git chegam à Kodus pelas URLs de webhook abaixo, não por esta variável.
</Info>

### Configuração do Provedor de LLM

A Kodus roda os reviews com o seu próprio modelo. Escolha uma forma de conectá-lo:

- **No app (recomendado).** Abra **AI providers** na barra lateral, conecte um provedor com a sua chave e direcione modelos para tarefas. Veja [BYOK](/pt-BR/how_to_use/byok). Um modelo conectado ali sobrepõe o definido no `.env`.
- **No `.env`.** Um modelo para a instância inteira. Declare o provedor, o modelo e a chave:

```env
API_LLM_PROVIDER=openai_compatible        # See the table below
API_LLM_PROVIDER_MODEL="your-model-id"
API_LLM_BASE_URL="https://your-provider.example.com/v1"
API_LLM_API_KEY="your-api-key"
```

| `API_LLM_PROVIDER` | Também necessário |
| --- | --- |
| `openai` | Uma chave: `API_LLM_API_KEY` ou `API_OPEN_AI_API_KEY`. `API_LLM_BASE_URL` é opcional e o padrão é `https://api.openai.com/v1`. |
| `openai_compatible` | `API_LLM_BASE_URL` e uma chave (`API_LLM_API_KEY` ou `API_OPEN_AI_API_KEY`). Para qualquer endpoint com protocolo OpenAI, como um gateway ou um modelo open-source hospedado. |
| `anthropic` | Uma chave. `API_LLM_API_KEY` ou `API_ANTHROPIC_API_KEY`. |
| `anthropic_compatible` | `API_LLM_BASE_URL` e `API_LLM_API_KEY`. Para endpoints com protocolo Anthropic. |
| `google_gemini` | Uma chave. `API_LLM_API_KEY` ou `API_GOOGLE_AI_API_KEY`. |
| `google_vertex` | `API_LLM_API_KEY` como o JSON da service account em base64, ou deixe vazio para usar o Application Default Credentials com `GOOGLE_CLOUD_PROJECT`. `API_VERTEX_AI_LOCATION` define a localização. |

Se `API_LLM_PROVIDER` estiver vazio, a Kodus deduz o provedor pelo nome do modelo e pelas chaves definidas. A página **AI providers** mostra qual modelo o ambiente configura e qualquer problema com ele.

Guias de provedores com valores prontos: [Chutes](/pt-BR/cookbook/chutes), [Fireworks](/pt-BR/cookbook/fireworks), [Groq](/pt-BR/cookbook/groq), [Moonshot](/pt-BR/cookbook/moonshot), [Novita](/pt-BR/cookbook/novita), [Synthetic](/pt-BR/cookbook/synthetic), [Together](/pt-BR/cookbook/together) e [Z.AI](/pt-BR/cookbook/z-ai).

#### Aplicar mudanças no modelo

Depois de editar as variáveis de LLM em uma instalação existente com Docker Compose, rode o instalador de novo no diretório `kodus-installer` para aplicar os valores. Depois confira o modelo com o script de diagnóstico.

```bash
./scripts/install.sh
./scripts/doctor.sh
```

### Configuração do Banco de Dados

Por padrão, o instalador inicia containers de PostgreSQL e MongoDB. Os padrões do `.env.example` funcionam como estão; o `generate-secrets.sh` define as senhas.

```env
# Use local containers for Postgres and MongoDB
USE_LOCAL_DB=true

# PostgreSQL Settings
API_DATABASE_ENV="development"                # development, production, test
API_PG_DB_HOST=db_kodus_postgres              # PostgreSQL host
API_PG_DB_PORT=5432                           # PostgreSQL port
API_PG_DB_USERNAME=kodusdev                   # Database username
API_PG_DB_PASSWORD=                           # Database password
API_PG_DB_DATABASE=kodus_db                   # Database name

# MongoDB Settings
API_MG_DB_HOST=db_kodus_mongodb               # MongoDB host
API_MG_DB_PORT=27017                          # MongoDB port
API_MG_DB_USERNAME=kodusdev                   # Database username
API_MG_DB_PASSWORD=                           # Database password
API_MG_DB_DATABASE=kodus_db                   # Database name
API_MG_DB_PRODUCTION_CONFIG=''                # Additional production settings

# SSL — the local Postgres container ships without SSL. This global switch
# covers ALL data sources (default + analytics). Leaving it false makes the
# api crash in a connect-retry loop.
API_DATABASE_DISABLE_SSL=true                 # disable SSL for local DBs
```

<Tip>
  Para bancos de dados embutidos, deixe `API_PG_DB_PASSWORD` e `API_MG_DB_PASSWORD` em branco e rode `./scripts/generate-secrets.sh` uma única vez para gerá-las, ou defina as suas. Para bancos de dados externos, use a senha do banco de dados existente.
</Tip>

Para usar seu próprio PostgreSQL ou MongoDB, defina `USE_LOCAL_DB=false` e aponte as variáveis `API_PG_DB_*` e `API_MG_DB_*` para eles. Os containers locais continuam subindo, porque os serviços da Kodus dependem deles no `docker-compose.yml` do instalador, mas a Kodus não os usa. Seu PostgreSQL precisa da extensão `vector` (pgvector), e o usuário da Kodus precisa poder criar schemas. Para um PostgreSQL gerenciado que exige TLS, defina `API_DATABASE_DISABLE_SSL=false`. A Kodus se autentica no MongoDB contra o banco `admin`, então crie o usuário lá. Uma única connection string também funciona: `DATABASE_URL` para o PostgreSQL e `MONGODB_URI` para o MongoDB substituem as variáveis individuais de host, porta e credenciais.

A API aceita `DATABASE_URL` e `MONGODB_URI`. Ao usar o instalador, mantenha `API_PG_DB_PASSWORD` e `API_MG_DB_PASSWORD` preenchidos. O instalador exige os dois e o Compose ainda sobe os contêineres embutidos.

### Configuração do RabbitMQ

O RabbitMQ é obrigatório. Mantenha a URI sincronizada com o usuário, a senha e o virtual host.

```env
# RabbitMQ Configuration
USE_LOCAL_RABBITMQ=true
RABBITMQ_HOSTNAME=rabbitmq                   # RabbitMQ hostname in Docker network
RABBITMQ_DEFAULT_USER=kodus                  # RabbitMQ user (change in production)
RABBITMQ_DEFAULT_PASS=kodus                  # RabbitMQ password (change in production)

# Keep the URI in sync with the user, password, and vhost above
API_RABBITMQ_URI=amqp://kodus:kodus@rabbitmq:5672/kodus-ai # RabbitMQ connection URI
API_RABBITMQ_ENABLED=true                    # RabbitMQ is required
```

O virtual host precisa ser `kodus-ai`. Com seu próprio broker, defina `USE_LOCAL_RABBITMQ=false`, habilite o plugin `rabbitmq_delayed_message_exchange`, crie os virtual hosts `kodus-ai` e `kodus-ast` e defina `consumer_timeout = 7200000` no `rabbitmq.conf`. O padrão de 30 minutos fecha o canal dos reviews que demoram mais.

### Configuração do Worker

O container do worker precisa de um papel para saber qual carga tratar. O worker principal sempre roda o papel de code review.

<Warning>
  Deixar `WORKER_ROLE` sem definir derruba o worker no boot. Como é o worker que cria as filas `workflow.jobs.*` na primeira conexão, a api e os webhooks passam a falhar todo evento de webhook com o erro `QueueBind 404`.
</Warning>

```env
# Worker role — required.
WORKER_ROLE=code-review
```

O papel `analytics` roda em um container separado e é exclusivo do self-hosted Enterprise. Veja [Analytics Worker](/pt-BR/how_to_deploy/deploy_kodus/analytics_worker).

### Configuração do Provedor Git

Escolha e configure seu provedor Git preferido. Você pode configurar um ou mais provedores; pelo menos uma URL de webhook é obrigatória, e ela precisa começar com `https://`.

<Info>
  Os webhooks são tratados por um serviço separado (porta 3332). Suas URLs de webhook precisam alcançar esse serviço. Você pode usar um domínio dedicado para webhooks, ou manter o domínio da API e rotear os caminhos `/.../webhook` para o serviço de webhooks no seu proxy reverso.
  Usando OAuth do GitHub ou do GitLab? Veja <a href="/pt-BR/how_to_deploy/platforms/github/github_oauth">GitHub OAuth App</a> ou <a href="/pt-BR/how_to_deploy/platforms/gitlab/gitlab_oauth">GitLab OAuth App</a>. Para a configuração do GitHub App, veja <a href="/pt-BR/how_to_deploy/platforms/github/github_app">GitHub App</a>.
</Info>

<Tabs>
  <Tab title="Github">
    ```env
    API_GITHUB_CODE_MANAGEMENT_WEBHOOK="https://kodus-api.yourdomain.com/github/webhook"
    ```

  </Tab>
  <Tab title="GitLab">
    ```env
    API_GITLAB_CODE_MANAGEMENT_WEBHOOK="https://kodus-api.yourdomain.com/gitlab/webhook"
    ```

  </Tab>
  <Tab title="Bitbucket">
    ```env
    GLOBAL_BITBUCKET_CODE_MANAGEMENT_WEBHOOK="https://kodus-api.yourdomain.com/bitbucket/webhook"
    ```

  </Tab>

  <Tab title="Azure DevOps">
    ```env
    GLOBAL_AZURE_REPOS_CODE_MANAGEMENT_WEBHOOK="https://kodus-api.yourdomain.com/azure-repos/webhook"
    ```

  </Tab>

  <Tab title="Forgejo">
    ```env
    API_FORGEJO_CODE_MANAGEMENT_WEBHOOK="https://kodus-api.yourdomain.com/forgejo/webhook"
    ```

  </Tab>
</Tabs>

Use o host dedicado de webhooks se tiver um. A Kodus usa essas URLs ao cadastrar webhooks por repositório. Se usar um [GitHub App](/pt-BR/how_to_deploy/platforms/github/github_app), configure a URL do webhook nas configurações do App.

### Configuração do MCP Manager

<Info>
  Necessário apenas se você quiser usar o MCP Manager.
</Info>

O MCP Manager é o serviço que conecta a Kody a ferramentas externas e as expõe na tela de Plugins. Consulte a [documentação do MCP Manager](/pt-BR/how_to_deploy/deploy_kodus/mcp_manager) para mais informações.

```env
API_MCP_SERVER_ENABLED=true   # The installer starts kodus-mcp-manager when this is true
API_KODUS_SERVICE_MCP_MANAGER=http://kodus-mcp-manager:3101
API_KODUS_MCP_SERVER_URL=https://kodus-api.yourdomain.com/mcp
API_MCP_MANAGER_REDIRECT_URI=https://kodus-web.yourdomain.com/setup/mcp/oauth
```

`API_MCP_MANAGER_JWT_SECRET` e `API_MCP_MANAGER_ENCRYPTION_SECRET` são gerados pelo `generate-secrets.sh`. As demais variáveis `API_MCP_MANAGER_*` do `.env.example` têm padrões que funcionam.

### Configuração de Serviços Externos (Opcional)

Estes serviços são opcionais, mas melhoram a qualidade do code review da Kodus. Cada um exige que você crie uma conta e gere uma chave de API.

<AccordionGroup>
  <Accordion title="E2B — Sandbox de Execução de Código">
    Por padrão, a Kodus processa os repositórios dentro do container do worker (`SANDBOX_PROVIDER=local`). O E2B roda esse trabalho em um sandbox remoto, o que o isola do seu host e serve para repositórios muito grandes.

    1. Crie uma conta em [e2b.dev](https://e2b.dev)
    2. Gere uma chave de API no seu painel
    3. Adicione ao seu `.env`:

    ```env
    SANDBOX_PROVIDER=e2b
    API_E2B_KEY=your-e2b-api-key
    ```

    Veja [Sandbox & AST Graph](/pt-BR/how_to_deploy/deploy_kodus/sandbox) para os modos.
  </Accordion>

  <Accordion title="MorphLLM — Modelo de Edição de Código">
    O MorphLLM é um modelo especializado em edição de código rápida e precisa. A Kodus o usa para aplicar as sugestões de review com mais precisão.

    1. Crie uma conta em [morphllm.com](https://morphllm.com)
    2. Gere uma chave de API no seu painel
    3. Adicione ao seu `.env`:

    ```env
    API_MORPHLLM_API_KEY=your-morphllm-api-key
    ```
  </Accordion>

  <Accordion title="Exa — Busca em Documentação">
    Com uma chave do Exa, a Kody consulta a documentação de bibliotecas enquanto revisa. Sem ela, a busca em documentação fica desligada.

    1. Crie uma conta em [exa.ai](https://exa.ai)
    2. Gere uma chave de API no seu painel
    3. Adicione ao seu `.env`:

    ```env
    API_EXA_KEY=your-exa-api-key
    ```
  </Accordion>
</AccordionGroup>

### Beta

Para ativar recursos que exigem a opção de beta no self-hosted, adicione `BETA_FEATURES=true` ao `.env` no diretório `kodus-installer`. Em uma instalação existente, aplique com `docker compose up -d --no-deps kodus-web api worker webhooks` para que os containers recebam a variável. Cada recurso tem seus próprios requisitos de plano e configuração.
