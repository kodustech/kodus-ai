<Info>
Pule esta página se um balanceador de carga ou outro proxy já roteia o tráfego para a Kodus.
</Info>

Para tornar sua instância da Kodus acessível a partir de sistemas externos (necessário para webhooks de Code Review e acesso público), você precisará configurar um proxy reverso com Nginx. Ele roteia três serviços: o app web (porta 3000), a API (porta 3001) e o serviço de webhooks (porta 3332). O instalador publica os três no host.

Aqui está um exemplo de configuração do Nginx para dois subdomínios:

```nginx
# Server block for the Kodus Web Application
server {
    listen 80;
    server_name kodus-web.yourdomain.com; # Replace with your actual web app domain

    location / {
        proxy_pass http://localhost:3000; # Points to the Kodus Web App container
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        proxy_buffer_size 16k;
        proxy_buffers 8 16k;
        proxy_busy_buffers_size 32k;
    }
}

# Server block for the Kodus API
server {
    listen 80;
    server_name kodus-api.yourdomain.com; # Replace with your actual API domain

    client_max_body_size 50m;

    location ~ ^/(github|gitlab|bitbucket|azure-repos|forgejo)/webhook {
        proxy_pass http://localhost:3332; # Points to the Kodus Webhooks service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    location / {
        proxy_pass http://localhost:3001; # Points to the Kodus API service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

<Note>
  Os webhooks são tratados por um serviço separado (porta 3332). O bloco `location ~ ^/(github|gitlab|bitbucket|azure-repos|forgejo)/webhook` é obrigatório se suas URLs de webhook usam o domínio da API. O mesmo domínio da API também serve `/mcp` quando `API_MCP_SERVER_ENABLED=true`.
</Note>

### Opcional: Subdomínio Dedicado para Webhooks

Se você prefere um domínio separado para os webhooks (ex.: `kodus-webhooks.yourdomain.com`), adicione um server block que aponte para o serviço de webhooks:

```nginx
server {
    listen 80;
    server_name kodus-webhooks.yourdomain.com;

    location / {
        proxy_pass http://localhost:3332; # Webhooks service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

Salve esta configuração em `/etc/nginx/sites-available/kodus` (ou com um nome de sua preferência, ex.: `kodus-web` e `kodus-api` como arquivos separados) e crie um link simbólico para habilitá-la:

```bash
sudo ln -s /etc/nginx/sites-available/kodus /etc/nginx/sites-enabled/
sudo nginx -t  # Test the configuration
sudo systemctl reload nginx  # Apply the changes
```

<Info>
  **Ajuste o `.env` às URLs públicas.** Depois que o proxy estiver no ar, defina estas variáveis no `.env` e rode `./scripts/install.sh` de novo para recriar os containers:

  - `NEXTAUTH_URL`, `API_FRONTEND_URL` e `API_USER_INVITE_BASE_URL`: a URL pública `https://` do app web.
  - As URLs de webhook (por exemplo `API_GITHUB_CODE_MANAGEMENT_WEBHOOK`): uma URL `https://` que alcança o **serviço de webhooks**. Use o domínio da API apenas se `/.../webhook` roteia para a porta `3332`, ou use um domínio dedicado para webhooks, como `https://kodus-webhooks.yourdomain.com/github/webhook`.
  - `API_URL`, só se você usa SSO: a URL pública da API, como `https://kodus-api.yourdomain.com`.

  `WEB_HOSTNAME_API` e `WEB_PORT_API` não apontam para o proxy. O servidor do app web chama a API pela rede Docker, então mantenha os padrões (`localhost` e `3001`). Quando `WEB_PORT_API` está definido, o app web chama `http://<WEB_HOSTNAME_API>:<WEB_PORT_API>`, então um host HTTPS público com a porta `443` falha.

  Uma URL de webhook errada não gera erro: o repositório conecta e os reviews nunca começam.
</Info>

### Habilitando SSL (Recomendado)

Para implantações em produção, recomendamos fortemente configurar o SSL com Let's Encrypt:

```bash
# Install Certbot for Let's Encrypt
sudo apt-get update
sudo apt-get install certbot python3-certbot-nginx

# Obtain and install certificates (add -d for the webhooks domain if you use one)
sudo certbot --nginx -d kodus-web.yourdomain.com -d kodus-api.yourdomain.com # Replace with your actual domains
```

Isso configura automaticamente o seu Nginx para usar HTTPS e redirecionar o tráfego HTTP desses domínios.
