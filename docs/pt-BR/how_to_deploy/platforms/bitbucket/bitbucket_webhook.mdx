---
title: Criando um Webhook
description: "Crie manualmente o webhook do Bitbucket quando o registro automático não aconteceu, e marque só os triggers de pull request que o Kodus consome."
icon: webhook
---

O Kodus geralmente cria o webhook automaticamente. Se isso não aconteceu, siga estas etapas para configurá-lo manualmente:

<Note>
  As URLs de webhook devem alcançar o serviço de Webhooks (porta 3332). Usar o domínio da API só funciona se seu proxy reverso rotear os caminhos `/.../webhook` para o serviço de webhooks.
</Note>

1. Navegue até seu repositório no Bitbucket
2. Clique em "Repository settings" na barra lateral esquerda
3. Selecione "Webhooks"
4. Clique em "Add webhook"
5. Configure seu webhook:

   - **Title**: Kodus Code Review
   - **URL**: Insira a URL onde deseja receber as notificações, a URL que você colocou em `GLOBAL_BITBUCKET_CODE_MANAGEMENT_WEBHOOK` no arquivo `.env`
   - **Status**: Active
   - **SSL/TLS**: Marque Enable SSL verification
   - **Triggers**: Selecione estes eventos:
        - Pull Request
            - Created
            - Updated
            - Merged
            - Declined
            - Comment created

6. Clique em "Save"

Pronto! Você configurou com sucesso um webhook para revisões de código no seu repositório Bitbucket.

<Note>
  O Kodus só consome eventos de Pull Request — `created`, `updated`, `merged`, `declined` e
  `comment created`. Triggers de Repository, Issue e build status são descartados na chegada;
  deixá-los desmarcados reduz o tráfego do webhook.

  No Bitbucket Data Center os eventos equivalentes são `pr:opened`, `pr:modified`,
  `pr:reviewer:updated`, `pr:comment:added`, `pr:merged` e `pr:declined`.
</Note>
