O Kodus geralmente cria o webhook automaticamente quando você salva a seleção de repositórios. Isso exige acesso de admin ao repositório: no Bitbucket Cloud, também os escopos `read:webhook:bitbucket` e `write:webhook:bitbucket` no API token; no Bitbucket Data Center, a permissão **Repository admin**. Se isso não aconteceu, **Repositories** lista o repositório com o motivo, e você pode configurar o webhook manualmente:

<Note>
  As URLs de webhook devem alcançar o serviço de Webhooks (porta 3332). Usar o domínio da API só funciona se seu proxy reverso rotear os caminhos `/.../webhook` para o serviço de webhooks.
</Note>

## Bitbucket Cloud

1. Navegue até seu repositório no Bitbucket
2. Clique em "Repository settings" na barra lateral esquerda
3. Selecione "Webhooks"
4. Clique em "Add webhook"
5. Hora de configurar seu webhook:

   - **Title**: Kodus Code Review
   - **URL**: A URL que você colocou em `GLOBAL_BITBUCKET_CODE_MANAGEMENT_WEBHOOK` no arquivo `.env` (ela termina com `/bitbucket/webhook`)
   - **Status**: Active
   - **SSL/TLS**: Marque Enable SSL verification
   - **Triggers**: Selecione estes eventos:
        - Pull Request
            - Created
            - Updated
            - Merged
            - Declined
            - Comment created

6. Clique em "Save"

## Bitbucket Data Center

O suporte ao Bitbucket Data Center está em alpha. Abra o repositório, vá em **Repository settings** > **Webhooks** e crie um webhook com:

- **URL**: o mesmo valor de `GLOBAL_BITBUCKET_CODE_MANAGEMENT_WEBHOOK`
- **Events**: os eventos de pull request `pr:opened`, `pr:modified`, `pr:comment:added`, `pr:merged` e `pr:declined`

<Note>
  O Kodus só consome eventos de pull request: no Cloud `created`, `updated`, `merged`, `declined` e `comment created`, no Data Center os cinco listados acima. Triggers de Repository, Issue e build status são descartados na chegada, então deixá-los desmarcados reduz o tráfego do webhook. O registro automático no Data Center também assina `pr:reviewer:updated`, que o Kodus recebe e ignora.
</Note>

### Pushes em um pull request aberto

No Data Center, um push de novos commits em um pull request aberto chega como `pr:from_ref_updated`. O Kodus não assina esse evento e o descarta, então um push não inicia um review. `pr:modified` dispara quando o título, a descrição, a branch de destino ou o estado de draft mudam. O Kodus o ignora, a menos que o último commit seja novo para o Kodus ou o pull request saia de draft. Para fazer o review de novos commits, comente `@kody start-review` no pull request.

No Cloud, o Kodus trata `pullrequest:updated` da mesma forma: ele só inicia um review quando o último commit é novo para o Kodus ou o pull request sai de draft.
