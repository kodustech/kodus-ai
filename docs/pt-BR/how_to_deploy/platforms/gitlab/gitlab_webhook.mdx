---
title: Criando um Webhook
description: "Crie manualmente o webhook do GitLab quando o registro automático não aconteceu, e selecione os eventos que a Kodus consome."
icon: webhook
---

A Kodus geralmente cria o webhook automaticamente quando você salva a seleção de repositórios. Isso exige o papel **Maintainer** ou **Owner** no projeto. Se isso não aconteceu, **Repositories** lista o projeto com o motivo, e você pode configurar o webhook manualmente:

<Note>
  As URLs de webhook devem alcançar o serviço de Webhooks (porta 3332). Usar o domínio da API só funciona se seu proxy reverso rotear os caminhos `/.../webhook` para o serviço de webhooks.
</Note>

1. Navegue até seu projeto no GitLab
2. Vá em "Settings" > "Webhooks"
3. Configure seu webhook:

   - **URL**: Insira a URL do seu arquivo `.env`: `API_GITLAB_CODE_MANAGEMENT_WEBHOOK` (ela termina com `/gitlab/webhook`)
   - **Marque Show full URL**
   - **Name**: (opcional) Kodus Code Review
   - **Description**: (opcional) Kodus Code Review Webhook
   - **Secret token**: Deixe em branco
   - **SSL verification**: Habilite a verificação SSL
   - **Trigger**: Selecione os seguintes eventos:
     - Comments
     - Merge request events

4. Clique em "Add webhook"

Você configurou com sucesso um webhook para code reviews no seu projeto GitLab.

<Note>
  A Kodus consome apenas eventos de comentário e de merge request. Eventos de issue são descartados na chegada.
</Note>
