---
title: "Como reduzir ruído e falsos positivos na revisão de código"
description: "Ajuste sua revisão de código com IA para exibir apenas as sugestões mais relevantes e evitar o cansaço por excesso de alertas."
---

Muitas sugestões de baixa prioridade podem fazer os desenvolvedores ignorarem completamente o feedback das revisões de código. O segredo é ajustar a revisão para que ela mostre o que importa e fique quieta no que não importa.

## Limite de severidade

O Kodus filtra quais achados são efetivamente publicados:

- **Minimum severity to post** — publica apenas sugestões no nível escolhido ou acima (padrão: Medium). O Kody ainda encontra problemas de severidade menor; ele apenas não comenta sobre eles.
- **Apply the threshold to Kody Rules** — desligado por padrão, para que as regras do seu time sempre apareçam

Configure na barra lateral em **Code review → What to review**, ou no `kodus-config.yml`:

```yaml
suggestionControl:
  severityLevelFilter: medium   # low | medium | high | critical
  applyFiltersToKodyRules: false
```

Os trechos de `kodus-config.yml` desta página só têm efeito quando **Prefer kodus-config.yml settings** está ativado para o repositório (**Code review → General**, no escopo de repositório). O Kody lê o arquivo na raiz do repositório, na branch padrão. Veja [Prioridade de configuração](/pt-BR/how_to_use/code_review/configs/general#prioridade-de-configuração).

## Ignorar arquivos e caminhos

Ignore arquivos que geram ruído (arquivos de lock, código gerado, configurações). Adicione-os em **Ignored files** em **Code review → General**, ou no `kodus-config.yml`:

```yaml
ignorePaths:
  - yarn.lock
  - package-lock.json
  - "**/*.generated.ts"
  - dist/**
```

Uma lista no arquivo substitui a lista definida no app, incluindo os padrões default. Copie para ela os padrões que você quer manter.

## Ignorar PRs pelo título

Ignore PRs que não precisam de revisão (releases, atualizações de versão). Adicione palavras-chave em **Ignore title keywords** em **Code review → General**, ou no `kodus-config.yml`:

```yaml
ignoredTitleKeywords:
  - "release"
  - "bump version"
  - "chore"
```

## Alternar categorias de análise

Desative categorias inteiras de revisão que você não precisa com os switches **Bug**, **Performance**, **Security** e **Business Logic** em **Code review → What to review**, ou no `kodus-config.yml`:

```yaml
reviewOptions:
  bug: true
  security: true
  performance: false        # disable if too noisy
  business_logic: false     # disable if not relevant
```

## Cadência de revisão

Use **Auto-pause** (**Code review → General** → **Automated code review** → **Review Cadence**) para evitar spam durante o desenvolvimento ativo. O Kodus pausa um PR depois de uma sequência de revisões (padrão: 3 revisões em 15 minutos) até alguém comentar `@kody start-review`.

## Mensagens de início e de fim

O Kody posta uma mensagem quando uma revisão começa e outra quando termina. Em **Code review → What Kody writes → Comments during the review**, use **Post this message** para postar cada uma apenas quando o PR é aberto, ou nunca. Veja [Mensagens personalizadas](/pt-BR/how_to_use/code_review/configs/custom_messages).

## Comentários de Business Logic

Quando um PR atende à sua tarefa, o Kody posta um comentário de uma linha. Desative **Comment when every requirement is met** nas configurações de **Business Logic** para ouvir apenas sobre as lacunas. Veja [Business Logic Validation](/pt-BR/how_to_use/code_review/business_logic_validation).

Para detalhes, consulte [Configuração Geral](/pt-BR/how_to_use/code_review/configs/general) e [Severidade mínima](/pt-BR/how_to_use/code_review/configs/suggestion_control).
