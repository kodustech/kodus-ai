---
title: "Como reduzir ruído e falsos positivos na revisão de código"
description: "Ajuste sua revisão de código com IA para exibir apenas as sugestões mais relevantes e evitar o cansaço por excesso de alertas."
---

Muitas sugestões de baixa prioridade podem fazer os desenvolvedores ignorarem completamente o feedback das revisões de código. O segredo é ajustar a revisão para que ela mostre o que importa e fique quieta no que não importa.

## Limite de severidade

O Kodus filtra quais achados são efetivamente publicados:

- **Minimum severity to post** — publica apenas sugestões no nível escolhido ou acima (padrão: Medium). O Kody ainda encontra problemas de severidade menor; ele apenas não comenta sobre eles.
- **Apply the threshold to Kody Rules** — desligado por padrão, para que as regras do seu time sempre apareçam

Configure na barra lateral em **Code review → What to review** (antes **Review filters**), ou no `kodus-config.yml`:

```yaml
suggestionControl:
  severityLevelFilter: medium   # low | medium | high | critical
  applyFiltersToKodyRules: false
```

Os trechos de `kodus-config.yml` desta página só têm efeito em um repositório quando **kodus Config File Overrides Web Preferences** está ativado em **Code review → General** (escopo de repositório ou diretório).

## Ignorar arquivos e caminhos

Ignore arquivos que geram ruído (arquivos de lock, código gerado, configurações). Adicione-os em **Ignored files** em **Code review → General**, ou no `kodus-config.yml`:

```yaml
ignorePaths:
  - yarn.lock
  - package-lock.json
  - "**/*.generated.ts"
  - dist/**
```

## Ignorar PRs pelo título

Ignore PRs que não precisam de revisão (releases, atualizações de versão). Adicione palavras-chave em **Ignore title keywords** em **Code review → General**, ou no `kodus-config.yml`:

```yaml
ignoredTitleKeywords:
  - "release"
  - "bump version"
  - "chore"
```

## Alternar categorias de análise

Desative categorias inteiras de revisão que você não precisa com os switches **Bug**, **Performance**, **Security** e **Business Logic** em **Code review → What to review**, ou no `kodus-config.yml`:

```yaml
reviewOptions:
  bug: true
  security: true
  performance: false        # desligue se gerar muito ruído
  business_logic: false     # desligue se não for relevante
```

## Cadência de revisão

Use **Auto-pause** (**Code review → General** → **Enable Automated Code Review** → **Review Cadence**) para evitar spam durante o desenvolvimento ativo — o Kodus pausa as revisões quando detecta pushes consecutivos rápidos (padrão: 3 pushes em 15 minutos).

Para detalhes, consulte [Configuração Geral](/pt-BR/how_to_use/code_review/configs/general) e [Limite de severidade](/pt-BR/how_to_use/code_review/configs/suggestion_control).
