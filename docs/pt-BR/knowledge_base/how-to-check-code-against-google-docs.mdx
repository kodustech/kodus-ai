---
title: "Como verificar código contra especificações no Google Docs"
description: "Valide a implementação do seu pull request contra especificações escritas no Google Docs."
---

Especificações de produto e requisitos frequentemente ficam no Google Docs. O Google Docs não é uma fonte de tarefas nativa da Business Logic Validation, que lê tarefas do Linear, Jira, Notion, Git Issues ou de um plugin personalizado. Um link do Google Docs no comando não é lido.

Há duas formas de verificar um PR contra uma especificação de um Google Doc:

## Cole os requisitos no comando

Copie os requisitos do documento e comente no seu PR:

```
@kody -v business-logic
## Requirements
1. Users with role "admin" can delete any comment
2. Users can only edit their own comments within 24 hours
3. Deleted comments show "[removed]" placeholder
```

O Kody verifica o PR contra o texto que você escreveu. Não é preciso um tracker, mas o texto precisa ter pelo menos 40 caracteres. O resultado é um único comentário no PR, **Kody · Business Logic**, com cada requisito marcado como **MET**, **PARTIAL**, **MISSING**, **CHECK MANUALLY** ou **NOT IN TASK**.

## Mantenha os requisitos em uma tarefa

Copie os requisitos para a descrição de uma tarefa no seu tracker, sob um título como `Acceptance criteria`, e cite a tarefa no título, na branch ou na descrição do PR. O Kody então verifica todo PR que referencia a tarefa, sem precisar de um comando. Se os critérios ficam sob um título ou em um campo personalizado, defina **Requirements → Where acceptance criteria live** nas configurações de Business Logic. Uma página do Notion funciona como uma tarefa: coloque a URL dela no PR.

## Dicas

- Mantenha as especificações estruturadas, com seções claras e requisitos numerados.
- Divida documentos grandes em seções e verifique uma de cada vez para um feedback mais focado.
- Depois de corrigir uma lacuna, comente `@kody -v business-logic` de novo. O mesmo comentário é atualizado.

Para detalhes, consulte [Business Logic Validation](/pt-BR/how_to_use/code_review/business_logic_validation).
