Todo time tem contexto não escrito — preferências tecnológicas, convenções de nomenclatura, decisões arquiteturais, detalhes de migração. Em vez de documentar tudo isso antecipadamente, você pode ensinar o Kody por meio de conversas naturais para que as revisões futuras sejam mais relevantes e sugestões ruins e repetitivas desapareçam.

## Como funciona

Quando você pede ao Kody em um comentário de PR para lembrar de algo, ele salva isso como uma **Memória**. Quando você apenas declara contexto do codebase ou uma preferência do time, o Kody se oferece para salvar e salva assim que você disser que sim. As Memórias passam então a ser usadas como contexto de alta prioridade em code reviews e conversas futuras.

### Ensino explícito

Diga diretamente ao Kody para lembrar de algo:

```
@kody remember: this repo mirrors a third-party API, so some payload fields intentionally stay snake_case.
```

```
@kody please remember: this service follows hexagonal architecture and keeps adapters at the edge.
```

### Declarando uma convenção

Declare uma convenção, ou explique por que uma sugestão não se aplica, e o Kody se oferece para salvá-la como uma memória. Responda `@kody yes` para salvar. Por exemplo:

```
@kody this repo mirrors a third-party API, so some payload fields intentionally stay snake_case.
```

```
@kody in this service, tests usually live next to the implementation files rather than in a central test folder.
```

```
@kody the billing module is mid-migration, so prefer incremental fixes over broad refactors.
```

## O que o Kody não salva

O Kody é seletivo sobre o que vira uma memória:

- Instruções temporárias ("corrija isso agora", "ignore isso por hoje")
- Perguntas ("qual é o prazo?")
- Conversa de depuração ("estou vendo um erro")
- Declarações vagas, sem informação acionável
- Pedidos com escopo em um único PR ou tarefa

## Escopos de memória

Cada memória se aplica em um nível específico:

| Escopo | Exemplo |
|--------|---------|
| **Directory** | "Em `src/components/ui`, sempre use os tokens do nosso design system" |
| **Repository** | "Este repositório usa arquitetura hexagonal" |
| **Organization** | "Todos os repositórios usam ESLint flat config" |

## Fluxo de aprovação

Se você quiser revisar as memórias que o Kody cria antes que entrem em vigor, abra **Code review → Kody Rules**, clique em **Configuration** e ative **Kody knowledge approval**. As novas memórias (e as regras geradas pelo Kody) passam a aguardar na seção **Pending review** até você usar **Approve** ou **Discard**. As memórias que você escreve com **New memory** ficam ativas na hora.

## Gerenciando memórias

Vá em **Code review → Kody Rules** → aba **Memories** para ver, editar ou excluir memórias. Você também pode criar memórias manualmente com **New memory**.

Para detalhes, consulte [Kody Rules — Memories](/pt-BR/how_to_use/code_review/configs/kody_rules#memórias).
