---
title: "Como revisar PRs com contexto específico do projeto"
description: "Dê ao Kody acesso aos documentos, manuais e guias de arquitetura do seu projeto para revisões de código mais relevantes."
---

Revisões de código genéricas identificam problemas genéricos. Para obter feedback realmente relevante para o seu projeto, o Kody precisa entender seu contexto específico — decisões arquiteturais, convenções e regras de negócio.

## Formas de fornecer contexto

### Memórias

Ensine o Kody sobre suas convenções por meio de conversas:

```
@kody remember: this project uses hexagonal architecture.
Domain layer must never depend on infrastructure.
```

As memórias persistem e são aplicadas em todas as revisões futuras.

### Referências de arquivo nas regras

Referencie sua própria documentação diretamente nas regras:

```
Instructions: Validate that new endpoints follow the patterns
in @file:docs/api-conventions.md and use the base classes
defined in @file:src/shared/base-controller.ts.
```

### Instruções de categoria

Adicione instruções específicas do projeto que o Kody inclui em cada revisão:

1. Na barra lateral, abra **Code review → What to review**
2. Edite as **Instructions** da categoria **Bug**, **Performance** ou **Security** com contexto como descrições de arquitetura, diretrizes do time ou conhecimento de domínio
3. O Kody inclui isso em cada análise de code review

Para mudar como o Kody redige suas sugestões (tom, tamanho), use **Kody's personality** em **Code review → What Kody writes**.

### Task trackers

Conecte Linear, Jira (**Atlassian Rovo**), Notion ou Git Issues em **Plugins**. Quando um PR referencia uma tarefa, o Kody confere o PR com os requisitos e critérios de aceitação da tarefa. Veja [Business Logic Validation](/pt-BR/how_to_use/code_review/business_logic_validation).

### Plugins

Os plugins que você instala também são ferramentas que o Kody pode usar quando você o menciona em um comentário de PR, e ferramentas que você pode ativar para um [agente personalizado](/pt-BR/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp). Adicione seu próprio servidor MCP como um plugin personalizado para trazer outras ferramentas.

## Exemplo de fluxo de trabalho

1. Defina regras de arquitetura via **Memories**: `@kody remember: we follow CQRS pattern in this service`
2. Crie **Review Rules** que referenciam seus documentos: `@file:docs/architecture.md`
3. Conecte seu task tracker para que o Kody valide PRs contra os requisitos das tarefas
4. Adicione **Instructions** de categoria em **What to review** para conhecimento específico de domínio

Para detalhes, consulte [Instruções de categoria](/pt-BR/how_to_use/code_review/configs/custom_prompts) e [Plugins](/pt-BR/how_to_use/code_review/plugins).
