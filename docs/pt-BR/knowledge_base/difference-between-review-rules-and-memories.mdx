---
title: "Qual é a diferença entre Regras de Revisão e Memórias"
description: "Entenda quando usar Regras de Revisão ou Memórias na Kody para obter os melhores resultados de revisão de código."
---

Na interface de Kody Rules, você configura duas coisas diferentes, e saber quando usar cada uma torna suas revisões de código mais eficazes.

Uma regra prática:

- **Memórias** ensinam à Kody como seu codebase funciona para que futuras revisões e sugestões sejam mais relevantes.
- **Regras de Revisão** dizem à Kody o que sinalizar quando um PR não bate com seus padrões.

## Regras de Revisão

Regras de Revisão são **verificações** que rodam durante o code review. Cada regra é aplicada ao diff de um arquivo ou ao PR inteiro, e a Kody reporta uma sugestão quando a mudança a quebra.

**Melhores para:**
- Limites de arquitetura ("a camada de domínio não deve importar infraestrutura")
- Padrões de código ("evite `==` em condições de loop")
- Requisitos de PR ("todo arquivo de serviço deve ter um teste")
- Requisitos sobre o próprio PR, como a descrição ou o tamanho

**Como funcionam:**
- Rodam por arquivo ou por PR (o **Execution mode** da regra)
- Rodam apenas durante o code review
- Podem apontar para um arquivo do repositório com `@file:path/to/file`
- Produzem sugestões com níveis de severidade
- Podem ser limitadas a caminhos e adicionadas a partir da Rules Library

## Memórias

Memórias são **instruções contextuais persistentes** que a Kody usa em code reviews e em conversas com a Kody. Elas representam o conhecimento de contexto que a Kody deve carregar sobre seu codebase, suas convenções e suas preferências.

**Melhores para:**
- Contexto do codebase ("este repositório espelha uma API de terceiros, então alguns campos externos permanecem intencionalmente em snake_case")
- Preferências de sugestão ("ao sugerir utilitários JS aqui, prefira métodos nativos em vez de Lodash")
- Contexto de migração ("o módulo de billing está no meio de uma migração, então prefira mudanças incrementais a refactors amplos")
- Contexto arquitetural ("este serviço segue arquitetura hexagonal e mantém adapters nas bordas")

**Como funcionam:**
- Adicionadas como contexto de alta prioridade em code reviews e conversas
- Melhoram sugestões futuras ao dar à Kody contexto específico do repositório
- Criadas via conversa (`@kody remember: ...`) ou manualmente com **New memory** na aba **Memories** de **Code review → Kody Rules**
- Com escopo de diretório, repositório ou organização
- A Kody confere as memórias existentes antes de salvar uma nova, e ignora duplicatas ou atualiza a memória existente

## Quando usar cada uma

| Cenário | Use |
|---------|-----|
| Verificar se existe um arquivo de teste para cada serviço | Regra de Revisão |
| "Este repositório espelha uma API externa, então alguns campos de resposta permanecem intencionalmente em snake_case" | Memória |
| A descrição do PR deve seguir um template | Regra de Revisão |
| "Neste serviço, os testes normalmente ficam ao lado dos arquivos de implementação, não em uma pasta central de testes" | Memória |
| Sinalizar importações que violam camadas de arquitetura | Regra de Revisão |
| "O módulo de autenticação está no meio de uma migração, então prefira mudanças incrementais a refactors amplos" | Memória |

## Posso converter entre elas?

Não diretamente — não há uma ação de conversão no app. Memórias pendentes aparecem na seção **Pending review** de **Code review → Kody Rules**, onde você pode usar **Approve** ou **Discard**. Se uma memória precisar de uma aplicação mais estruturada, com caminhos de arquivo e níveis de severidade, crie uma Regra de Revisão com **New rule** na aba **Review Rules** e exclua ou descarte a memória.

Para detalhes, consulte [Kody Rules](/pt-BR/how_to_use/code_review/configs/kody_rules).
