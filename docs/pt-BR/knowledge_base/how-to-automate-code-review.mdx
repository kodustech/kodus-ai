Revisões de código manuais criam gargalos. Revisores mudam de contexto, PRs se acumulam e a qualidade do feedback varia. A revisão de código com IA executa instantaneamente em cada PR, identificando problemas antes mesmo que um revisor humano olhe para o código.

## Como o Kodus automatiza a revisão de código

Uma vez conectado, o Kodus revisa automaticamente cada pull request. Ele analisa o código em busca de vulnerabilidades de segurança, problemas de performance, tratamento de erros, manutenibilidade e suas regras personalizadas — e então posta comentários diretamente no PR.

### Plataformas suportadas

- **GitHub** — via GitHub App (ou um personal access token)
- **GitLab** — via OAuth (ou um personal access token)
- **Bitbucket** — via API token
- **Azure DevOps** (Azure Repos) — via personal access token
- **Forgejo** — via personal access token

### O que é analisado

Por padrão, o Kodus verifica as categorias que você pode ativar ou desativar em **Code review → What to review**, além das suas próprias regras:
- Problemas de segurança (SQL injection, XSS, segredos hardcoded)
- Problemas de performance (queries N+1, índices ausentes)
- Bugs em potencial (ponteiros nulos, vazamentos de recursos, lacunas no tratamento de erros)
- Conformidade com lógica de negócio (valida contra os requisitos da tarefa vinculada)
- Suas Regras do Kody personalizadas (use-as para estilo de código e convenções do time)

### Opções de cadência de revisão

Defina a cadência em **Code review → General**, em **Enable Automated Code Review** → **Review Cadence**.

| Modo | Comportamento |
|------|---------------|
| **Automático** | Revisa a cada push — feedback contínuo |
| **Pausa automática** | Pausa durante pushes rápidos (ex.: 3 em 15 minutos) para evitar ruído |
| **Manual** | Apenas revisa quando você comenta `@kody start-review` |

## Como começar

1. Crie um workspace em [kodus.io](https://kodus.io) ou [hospede o Kodus por conta própria](/pt-BR/how_to_deploy/deploy_kodus/generic_vm)
2. Conecte seu provedor Git (GitHub, GitLab, Bitbucket, Azure DevOps ou Forgejo)
3. Selecione quais repositórios monitorar
4. Abra um PR — o Kodus o revisa automaticamente
