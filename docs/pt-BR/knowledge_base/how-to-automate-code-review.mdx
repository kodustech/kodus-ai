Revisões de código manuais criam gargalos. Revisores trocam de contexto, PRs se acumulam e a qualidade do feedback varia. A revisão de código com IA roda instantaneamente em cada PR, identificando problemas antes mesmo de um revisor humano olhar o código.

## Como o Kodus automatiza a revisão de código

Depois de conectado, o Kodus revisa automaticamente cada pull request. Ele analisa o código em busca de vulnerabilidades de segurança, problemas de performance, tratamento de erros, manutenibilidade e das suas regras personalizadas — e então posta comentários diretamente no PR.

### Plataformas suportadas

- **GitHub** — via GitHub App (ou um personal access token)
- **GitLab** — via OAuth (ou um personal access token)
- **Bitbucket** — via API token
- **Azure DevOps** (Azure Repos) — via personal access token
- **Forgejo** — via personal access token

### O que é analisado

Por padrão, o Kodus verifica as categorias que você pode ativar ou desativar em **Code review → What to review**, além das suas próprias regras:
- Problemas de segurança (SQL injection, XSS, segredos hardcoded)
- Problemas de performance (queries N+1, índices ausentes)
- Bugs em potencial (ponteiros nulos, vazamentos de recursos, lacunas no tratamento de erros)
- Conformidade com a lógica de negócio (valida contra os requisitos da tarefa vinculada)
- Suas Kody Rules personalizadas (use-as para estilo de código e convenções do time)

### Opções de cadência de revisão

Defina a cadência em **Code review → General**, em **Automated code review** → **Review Cadence**.

| Modo | Comportamento |
|------|---------------|
| **Automatic** | Revisa a cada push, para um feedback contínuo |
| **Auto-pause** | Pausa um PR depois de uma sequência de revisões (padrão: 3 em 15 minutos) para evitar ruído |
| **Manual** | Revisa o PR quando ele é aberto e, depois, só quando você comenta `@kody start-review` |

Você também pode rodar uma revisão sob demanda em qualquer PR com `@kody start-review`. Veja o [Fluxo da revisão](/pt-BR/how_to_use/code_review/flow) para todos os comandos e para os motivos pelos quais uma revisão é ignorada.

### O que acontece depois da revisão

O Kody também pode aprovar PRs sem problemas (veja [Aprovação automática](/pt-BR/how_to_use/code_review/configs/auto_approve)) e solicitar mudanças em problemas críticos (veja [Política de revisão](/pt-BR/how_to_use/code_review/policy)). Ambos vêm desativados por padrão. O Kodus nunca faz merge de um PR.

## Como começar

1. Crie um workspace em [kodus.io](https://kodus.io) ou [hospede o Kodus por conta própria](/pt-BR/how_to_deploy/deploy_kodus/generic_vm)
2. Conecte seu provedor Git (GitHub, GitLab, Bitbucket, Azure DevOps ou Forgejo)
3. Selecione quais repositórios monitorar
4. Abra um PR — o Kodus o revisa automaticamente
