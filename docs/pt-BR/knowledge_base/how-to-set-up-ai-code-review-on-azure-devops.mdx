---
title: "Como configurar revisão de código com IA no Azure DevOps"
description: "Conecte o Azure DevOps ao Kodus e selecione os repositórios para revisão automática."
---

O Kodus se conecta ao Azure DevOps Services (`dev.azure.com`) com um personal access token e recebe os eventos de pull request por meio de service hooks.

## Passos

1. **Crie uma conta** em [kodus.io](https://kodus.io) ou [hospede o Kodus por conta própria](/pt-BR/how_to_deploy/deploy_kodus/generic_vm)
2. **Conecte o Azure DevOps** — na etapa **Connect your Git tool** do onboarding, abra a aba **Azure Repos**, clique em **Connect via token** e informe o nome da sua organização no Azure Repos e seu Personal Access Token (você também pode conectar depois em **Repositories** na barra lateral: clique em **Azure Repos** em **Connect a provider**)
3. **Selecione os repositórios** — escolha quais repositórios do Azure DevOps o Kodus deve revisar, ou ative [Review every repository](/pt-BR/how_to_use/code_review/configs/review_all_repositories) em **Repositories**
4. **Webhooks** — o Kodus cria os service hooks de pull request automaticamente quando você salva a seleção. Isso exige a permissão **Edit subscriptions** no projeto (os Project Administrators têm). Confira-os em **Project settings** → **Service hooks**; **Repositories** lista um repositório cujos hooks falharam, com o motivo, apenas quando **Review every repository** está ativado. Se estiverem ausentes, registre os hooks manualmente com o guia [Azure DevOps Webhooks](/pt-BR/how_to_deploy/platforms/azure_devops/azdevops_webhook)
5. Abra um pull request em um repositório selecionado. Veja [o que o Kody publica e como conferir o status](/pt-BR/how_to_use/code_review/flow).

Para validar o PR com um work item do Azure Boards, selecione um plugin customizado como **Task source**. [Veja as configurações de validação](/pt-BR/how_to_use/code_review/business_logic_validation).

## Configuração personalizada

Use o [kodus-config.yml](/pt-BR/how_to_use/code_review/configs/general#kodus-config-yml) para personalizar a revisão por repositório.

## Usando um Personal Access Token

O Azure DevOps exige um PAT para que o Kodus acesse seus repositórios e publique comentários de revisão. Crie-o com os escopos listados no guia [PAT do Azure DevOps](/pt-BR/how_to_use/code_review/general_config/azure_devops_pat); sem **Code: Read & Write**, o Kodus consegue ler seus repositórios, mas não consegue comentar.

Para o guia completo de configuração, consulte [Azure DevOps Webhooks](/pt-BR/how_to_deploy/platforms/azure_devops/azdevops_webhook) e [PAT do Azure DevOps](/pt-BR/how_to_use/code_review/general_config/azure_devops_pat).
