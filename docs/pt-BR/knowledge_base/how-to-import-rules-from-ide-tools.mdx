Se sua equipe já mantém instruções para o Cursor, GitHub Copilot, Claude ou outros agentes de código, o Kody pode lê-las durante a revisão de código e apontar mudanças que as quebram.

## Como funciona

O Kody lê os arquivos de instrução que cobrem os arquivos alterados por um pull request. Os arquivos suportados incluem:

- `.cursorrules` e `.cursor/rules/**/*.mdc` (Cursor)
- `.github/copilot-instructions.md` e `.github/instructions/**/*.instructions.md` (GitHub Copilot)
- `CLAUDE.md` (Claude)
- `AGENTS.md` e `.agents/rules/**` (convenção agents.md)

Uma mudança que quebra uma delas é reportada com o rótulo **Repo Instruction**, citando a instrução e o arquivo de onde ela vem. Os arquivos nunca são transformados em Regras do Kody, então não podem mudar sua política de revisão sem que você perceba.

## Configurando

1. Selecione **Global** ou um repositório no seletor de escopo no topo do grupo **Code review** na barra lateral e abra **What to review**
2. Ative **Coding-agent instructions**
3. O próximo pull request revisado nesse escopo é verificado contra os arquivos de instrução que cobrem suas mudanças

Novos workspaces recebem essa pergunta durante o onboarding, com a lista de arquivos de agentes de código encontrados em cada repositório.

## Aplicando uma convenção em toda revisão

Instruções para agentes de código são contexto: o Kody só reporta uma instrução quebrada quando ela claramente se aplica às linhas alteradas. Para uma convenção que você quer aplicar como qualquer outra regra de revisão, escreva-a como uma [Regra de Repositório](/pt-BR/how_to_use/code_review/configs/repository_rules) em `.kody/rules`. Arquivos de regra sincronizam no merge, um arquivo por regra, exatamente como escritos.

Para detalhes, consulte [Instruções para Agentes de Código](/pt-BR/how_to_use/code_review/configs/rules_file_detection).
