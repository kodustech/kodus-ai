Se o repositório já está conectado, comente `@kody review` no PR para pedir uma revisão. Se ela não apareceu, [confira o motivo](#quando-o-kody-pula).

## O que você recebe

- Comentários inline com uma sugestão concreta.
- Um resumo do PR, se estiver ativado.
- Opcionalmente, uma aprovação ou um pedido de alterações. Veja [Política de revisão](/pt-BR/how_to_use/code_review/policy).
- No GitHub (instalado como GitHub App) e no Forgejo, um check **Kody Code Review** no commit head do PR: completo, completo com avisos, falhou ou pulado. Ele informa se o review rodou, não se o PR tem apontamentos.
- Uma reação no PR mostrando o status do review.

## O que inicia um review

**Automaticamente**, quando um pull request é aberto, quando novos commits são enviados a ele ou quando um draft é marcado como pronto para review (em todos os providers, exceto Forgejo). O Kody revisa drafts, a menos que **Review draft pull requests** esteja desativado.

### Comandos em comentários no PR

**Sob demanda**, com um comentário no PR. O comando precisa iniciar o comentário:

| Comando | O que faz |
| --- | --- |
| `@kody start-review` ou `@kody review` | Revisa os commits desde o último review (o PR inteiro em um primeiro review). Retoma um PR pausado. |
| `@kody review --force` | Revisa o PR inteiro de novo, mesmo sem novos commits. |
| `@kody review --heavy` ou `--balanced` | Escolhe o modo de review desta execução. Veja [Modos e modelos de revisão](/pt-BR/how_to_use/code_review/configs/routing). |
| `@kody review focus on the auth logic` | Direciona o review. Veja [Direcionar a revisão](/pt-BR/how_to_use/code_review/review_directive). |
| `@kody -v <agent>` | Roda um [custom agent](/pt-BR/how_to_use/code_review/custom_agents) no PR inteiro. |
| `@kody -v business-logic` | Verifica o PR contra a sua tarefa. Veja [Business Logic Validation](/pt-BR/how_to_use/code_review/business_logic_validation). |
| `@kody <question>` | Inicia uma conversa sobre o PR ou sobre uma sugestão. |

Um comando de review ignora **Automated code review**, **Review Cadence**, **Ignore title keywords**, **Base Branches** e **Review draft pull requests**. Licenças, autores ignorados e arquivos ignorados continuam valendo.

Se já existe um review rodando no PR, o comando espera e roda quando o review atual termina. Um push que chega nesse meio-tempo não inicia um segundo review: comente `@kody review` para revisá-lo.

No GitHub, quando o Kody revisa como uma conta de usuário (um personal access token), **Re-request review** no Kody funciona como `@kody start-review` em um PR que ele já revisou.

## Reações de status

O Kody mostra o status de um review como uma reação no seu provider Git e substitui a anterior pela mais recente (por exemplo 🚀 e depois 🎉).

<Note>
  As **reações nativas** funcionam no GitHub, no GitLab e no Forgejo.

  O Azure DevOps e o Bitbucket não têm API de reações, então o Kody publica o emoji de status como um **comentário**: 👀 (pulado), 😕 (erro) e 👎 (sem licença), mas não o par 🚀 e 🎉.
</Note>

### O que cada emoji significa

- 🚀 Processando: o Kody está trabalhando no review.
- 🎉 Concluído: o review terminou e os comentários foram postados.
- 👀 Pulado: o review não rodou. Veja [Quando o Kody pula](#quando-o-kody-pula).
- 👎 Sem licença: o autor do PR não tem licença. O GitLab mostra um cadeado (🔒) no lugar.
- 😕 Erro: o review falhou. Rode de novo com `@kody start-review`. Se continuar falhando, confira [Solução de Problemas](/pt-BR/how_to_use/code_review/troubleshooting) ou pergunte no [Discord](https://discord.gg/TFZBRk9fT6).

### Onde as reações aparecem

- Review automático: na descrição do PR.
- Comando de review: no seu comentário.

### Desative o feedback de skip e de bloqueio

**Code review → General → Review feedback → Show status feedback** controla as reações 👀 e 👎 e os comentários de assinatura. Com ele desativado, o Kody ainda mostra 🚀, 🎉 e 😕. Com **Automated code review** desativado, o Kody não reage aos PRs que pula.

## Quando o Kody pula

A menos que o status feedback esteja desativado, o Kody mostra 👀 em um review pulado. Ele registra o motivo de qualquer forma. O motivo aparece no check **Kody Code Review** (GitHub App e Forgejo). Os PRs bloqueados por configuração (licença, cadência manual ou pausada, autor ignorado) são listados na página **Pull Requests** em **Kody skipped**.

| Motivo | Por quê | O que fazer |
| --- | --- | --- |
| Automated Review is disabled | **Automated code review** está desativado. | Ative, ou comente `@kody start-review`. |
| Title Ignored | O título contém uma entrada de **Ignore title keywords**. | Remova a palavra-chave, ou comente `@kody start-review`. |
| Draft PR Skipped | **Review draft pull requests** está desativado. | Marque o PR como pronto, ou ative a configuração. |
| Branch Mismatch | A branch de destino não é a branch padrão nem está em **Base Branches**. | Adicione a branch a **Base Branches**. |
| PR is Closed, PR is Locked | Os reviews automáticos pulam PRs fechados e mesclados, e o `@kody review --force` também. Um `@kody review` simples revisa um PR fechado ou mesclado. PRs bloqueados (locked) não são revisados. | Reabra ou desbloqueie o PR, ou comente `@kody review` em um PR fechado. |
| No New Commits | Os últimos commits já foram revisados. | Comente `@kody review --force`. |
| Only Merge Commits | Os novos commits apenas mesclam outra branch. | Envie uma mudança de código, ou comente `@kody review --force`. |
| Rebase Without Changes | Um rebase não mudou nada no código já revisado. | Comente `@kody review --force`. |
| No Files Changed, No changed files in this pull request, All Files Ignored | Nenhum arquivo alterado pode ser revisado nessa execução. Arquivos removidos ficam de fora. Arquivos ignorados só entram quando um custom agent dessa execução os inclui explicitamente. Um comando de review em um PR sem commits desde o último review também pode terminar aqui. | Confira **Ignored files**, ou comente `@kody review --force` para revisar o PR inteiro. |
| Too Many Files | O review principal e os custom agents somam mais de 2.000 arquivos revisáveis. | Divida o PR. |
| Changes Unreadable, Provider Rate Limited | O provider Git não devolveu o diff completo, ou limitou a requisição. | Rode o review de novo mais tarde. |
| User is ignored by configuration | O autor do PR está excluído por **Repositories → PR author filters**. | Veja [Atribuição Automática de Licença](/pt-BR/how_to_use/auto_license_assignment#filtros-de-autor-de-pr). |
| Code reviews are disabled for the centralized config repository, or for the global Kody Rules source repository | O Kody não revisa o repositório que guarda as suas configurações ou regras compartilhadas. | Revise um repositório diferente. |
| User Not Licensed | O autor do PR não tem licença. | Atribua uma licença ou ative a [Atribuição Automática de Licença](/pt-BR/how_to_use/auto_license_assignment). |
| No Active Subscription, Plan Limit Exceeded, Trial Reviews Used Up, BYOK Configuration Required, Subscription Check Unavailable | A organização não pode rodar reviews agora. O Kody também comenta no PR, a menos que **Show status feedback** esteja desativado. | Siga o comentário. Veja [Limites e Preços](/pt-BR/how_to_use/pricing). |
| PR is paused, Manual mode requires @kody start-review | **Review Cadence** está em Auto-pause ou Manual. | Comente `@kody start-review`. |

<Note>
  `--force` roda de novo um review que foi pulado por já ter sido revisado. Ele não ignora um skip por licença, plano ou limite de arquivos, nem um PR fechado ou mesclado.
</Note>

## Configurações importantes

- [Mudar quando o Kody revisa](/pt-BR/how_to_use/code_review/configs/general). Ajuste a revisão automática, a cadência, os rascunhos, as branches de destino e os arquivos ignorados.
- [Mudar o que o Kody reporta](/pt-BR/how_to_use/code_review/configs/what_to_review). Escolha as categorias e a severidade mínima das sugestões.
- [Escolher a profundidade e os modelos](/pt-BR/how_to_use/code_review/configs/routing). Selecione Balanced ou Heavy e confira os modelos usados.
- [Controlar as aprovações](/pt-BR/how_to_use/code_review/policy). Decida quando o Kody aprova ou solicita mudanças no PR.
- [Resolver problemas de revisão](/pt-BR/how_to_use/code_review/troubleshooting). Descubra por que uma revisão não rodou ou por que o resultado veio diferente.

## Cadência de review

**Code review → General → Automated code review** ativa ou desativa os reviews automáticos. **Review Cadence** decide o que acontece nos pushes depois do primeiro review:

- **Automatic:** todo push é revisado.
- **Auto-pause:** o Kody conta os reviews que terminou no PR dentro da **Time window (minutes)**. Quando a contagem chega a **Pushes to trigger pause** (padrão: 3 em 15 minutos), o próximo push pausa o PR e o Kody comenta "Auto-paused – comment @kody start-review when you're ready." Os pushes são pulados até alguém comentar `@kody start-review`.
- **Manual:** o primeiro review roda quando o PR é aberto. Os pushes seguintes são pulados até alguém comentar `@kody start-review`.

## O que o Kody faz

1. Verifica se o PR pode ser revisado: licença, filtros, cadência e novos commits.
2. Resolve as configurações que se aplicam (global, repositório, diretório) e as valida.
3. Quando a [avaliação de risco](/pt-BR/how_to_use/code_review/configs/risk) está ativada, avalia o PR e escolhe o modo de review.
4. Carrega os arquivos alterados e o contexto, pulando os arquivos ignorados.
5. Posta o comentário de abertura, se estiver ativado em **What Kody writes**.
6. Verifica o PR contra a sua tarefa, se o PR referencia uma e **Business Logic** está ativado.
7. Revisa as mudanças: encontra problemas, aplica as Kody Rules e os custom agents, verifica cada apontamento, remove duplicatas e aplica o **Minimum severity to post**.
8. Posta os comentários inline, os comentários no nível do PR e o resumo.
9. Aprova o PR ou solicita alterações, se estiver ativado.

O Kody guarda o último commit revisado, então o próximo review cobre apenas o que mudou desde então. Depois de um rebase ou force-push, o Kody revisa apenas o que mudou onde consegue comparar o novo diff com o que revisou, e o PR inteiro nos demais casos.

## Dicas

- Mantenha os PRs pequenos. Diffs grandes reduzem a qualidade do review.
- Vincule a tarefa no título, na branch ou na descrição do PR para o Kody poder verificar o PR contra ela.
