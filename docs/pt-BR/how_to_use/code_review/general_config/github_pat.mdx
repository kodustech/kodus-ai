## Introdução ao FGPAT

Para habilitar o Kody a realizar Code Reviews automáticos, você precisa gerar um Fine-Grained Personal Access Token (FGPAT) no GitHub. Esse token permite que o Kody acesse seus repositórios de forma segura e realize a análise de código de maneira controlada.

## Verificar as permissões de acesso Fine-Grained

Por padrão, um Fine-Grained PAT pode não ter acesso ao conteúdo da sua organização. Garanta o acesso seguindo estas etapas:

![title](/images/fgpat.png)

1. Você precisa ser o owner da organização.
1. Vá para as configurações da sua organização no GitHub:
   - Você pode usar esta URL, substituindo pelo nome da sua organização: <small>https://github.com/organizations/YOUR_ORG_NAME/settings/personal-access-tokens</small>.
1. Na barra lateral esquerda, em **Personal access tokens**, clique em **Settings**. Na aba **Fine-grained tokens**, selecione **Allow access via personal access tokens** e clique em **Save**.

## Gerando o FGPAT (Fine-Grained Personal Access Token)

Siga estas etapas para configurar o token corretamente:

1. **Acesse o GitHub e vá para as configurações do seu perfil**:

   - [Clique aqui para acessar a página de configurações do perfil](https://github.com/settings/profile).

2. **Navegue até `Developer Settings`**:

   - Na barra lateral esquerda, role para baixo até encontrar `Developer Settings` e clique nele.

3. **Vá para `Personal Access Tokens`**:

   - Ainda na barra lateral esquerda, em `Developer Settings`, selecione `Personal Access Tokens`.
   - Depois, clique em [Fine-grained Tokens](https://github.com/settings/tokens?type=beta).

4. **Gere um novo token**:

   - Clique no botão `Generate new token`.

5. **Configure o novo token com as seguintes especificações**:

   - **Token Name**: Escolha um nome fácil de identificar, como `kody_code_review`.
   - **Expiration Date**: Se possível, selecione uma data de expiração longa, de preferência de pelo menos 180 dias.
   - **Resource Owner**: Garanta que a organização esteja definida como dona do token, já que os repositórios do time ficam na organização.
   - **Repository Access**: Selecione **All repositories** para permitir que o token acesse todos os repositórios.
   - **Permissions**: Configure as seguintes permissões:
   - **Repository**:
     - **Commit statuses**: Permissão de leitura.
     - **Contents**: Permissão de leitura e escrita.
     - **Issues**: Permissão de leitura.
     - **Metadata**: Permissão de leitura.
     - **Pull requests**: Permissão de leitura e escrita.
     - **Webhooks**: Permissão de leitura e escrita.
   - **Organization**:
     - **Members**: Permissão de leitura.

   O Kody não usa **Actions** nem **Deployments**; deixe os dois em **No access**.

6. **Finalize e salve o token**:
   - Depois de configurar as permissões, clique em `Generate token`.
   - Copie o token gerado e guarde-o com segurança, pois você precisará dele para configurar o Kody.

## Adicionando o Token ao Kody

Depois de gerar o token, cole-o no Kodus:

- **Durante o onboarding**: em **Connect your Git tool**, escolha a aba **Github** e clique em **Connect via token**.
- **Depois**: na barra lateral, abra **Repositories**, clique em **Github** em **Connect a provider**, mude para a aba **Token**, cole o token e clique em **Validate and save**.
- **Trocando um token**: em **Repositories**, clique em **Reset** no card **Github**, escolha **Just reset the integration** e conecte novamente com o novo token, como descrito acima.

Com um token, as revisões são publicadas com o seu perfil do GitHub em vez do perfil do Kody, e GitHub Checks / status de PR não ficam disponíveis.

## GitHub Enterprise Server (Beta)

Para conectar o GitHub Enterprise Server com um token, o workspace no Cloud precisa ter acesso a esse beta. No Kodus self-hosted, defina `BETA_FEATURES=true`.

1. Crie o token na sua instância do GitHub Enterprise Server.
2. No diálogo de token do **Github**, ative **Self-hosted** e informe a **GitHub Enterprise URL**, por exemplo `https://github.your-company.com`. Ela precisa começar com `http://` ou `https://`.
3. Cole o token e clique em **Validate and save**.

O Kodus chama a API da instância em `<GitHub Enterprise URL>/api/v3`. Se o token ou a URL estiverem errados, o diálogo mostra **Invalid Token or GitHub Enterprise URL**.
