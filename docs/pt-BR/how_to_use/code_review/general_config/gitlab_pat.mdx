## Introdução ao PAT

Para habilitar a Kody a realizar Code Reviews automáticos, você precisa gerar um Personal Access Token (PAT) no GitLab. Esse token permite que a Kody acesse seus repositórios de forma segura e conduza a análise de código de maneira controlada.

A Kody publica as revisões como o usuário do GitLab dono do token. Com um personal access token, as revisões aparecem na sua própria conta, assim como quando você conecta com OAuth. Para que apareçam em um usuário bot separado, use um group access token, descrito abaixo.

## Gerando o PAT (Personal Access Token)

Siga estas etapas para configurar o token corretamente:

1. **Acesse o GitLab e vá para as configurações do seu perfil**:

   - [Clique aqui para acessar a página de configurações do perfil](https://gitlab.com/-/user_settings/personal_access_tokens).

2. **Navegue até `Access Tokens`**:

   - Na barra lateral esquerda, role até encontrar `Access Tokens` e clique nele.

3. **Adicione um novo token**:

   - Clique no botão `Add new token`. Nas versões recentes do GitLab, abra o dropdown `Generate token` e selecione `Legacy token`.

4. **Configure o novo token com as seguintes especificações**:

   - **Token Name**: Escolha um nome fácil de identificar, como `kody_code_review`.
   - **Expiration Date**: Se possível, selecione uma data de expiração longa, de preferência de pelo menos 180 dias.
   - Em **Scopes**, selecione apenas `api` para um token de acesso pessoal. Esse escopo cobre as chamadas da Kody à API e o acesso aos repositórios via HTTPS.

5. **Finalize e salve o token**:
   - Depois de configurar as permissões, clique em `Generate token`.
   - Copie o token gerado e guarde-o com segurança, pois você precisará dele para configurar a Kody.

## Usando um Group Access Token

Um group access token publica as revisões como um usuário bot que o GitLab cria para o token, com o nome do token. O bot tem acesso a todos os projetos do grupo e dos seus subgrupos.

<Note>
  No GitLab.com, group access tokens exigem uma assinatura Premium ou Ultimate e não estão disponíveis durante um trial. No GitLab Self-Managed e no GitLab Dedicated, estão disponíveis em qualquer licença.
</Note>

1. **Abra os access tokens do grupo**:

   - No GitLab, abra o grupo que contém seus repositórios e vá em `Settings` > `Access tokens`.

2. **Adicione um novo token**:

   - Clique no botão `Add new token`.

3. **Configure o novo token com as seguintes especificações**:

   - **Token name**: O nome que as revisões da Kody vão exibir, como `Kody`.
   - **Expiration date**: Se possível, selecione uma data de expiração longa, de preferência de pelo menos 180 dias.
   - **Role**: `Maintainer`. A Kody precisa dele para criar o webhook em cada projeto.
   - Em **Scopes**, selecione `api` para as chamadas à API e `read_repository` para a Kody clonar os repositórios do grupo via HTTPS.

4. **Finalize e salve o token**:
   - Clique em `Create group access token`.
   - Copie o token e guarde-o com segurança. O GitLab o mostra apenas uma vez.

## Adicionando o Token à Kody

Depois de gerar o token, cole-o na Kodus:

- **Durante o onboarding**: em **Connect your Git tool**, escolha a aba **Gitlab** e clique em **Connect via token**.
- **Depois**: na barra lateral, abra **Repositories**, clique em **Gitlab** em **Connect a provider**, mude para a aba **Token**, cole o token e clique em **Validate and save**. Para um GitLab self-managed, ative **Self-hosted** e informe a **Gitlab URL**.
- **Trocando um token**: em **Repositories**, clique em **Update token** no card **Gitlab**, cole o novo token e clique em **Update token**. Os webhooks e os repositórios selecionados são mantidos.
- **Saindo do OAuth**: **Update token** não é oferecido para uma conexão feita com OAuth. Clique em **Reset**, escolha **Just reset the integration**, conecte novamente com o token como descrito acima e selecione seus repositórios.
