## Visão Geral

Um escopo de diretório aplica as próprias configurações de code review a uma ou mais pastas de um repositório. Use em monorepos, onde áreas diferentes têm padrões ou responsáveis distintos.

A Kody usa uma única configuração por pull request: **Diretório** → **Repositório** → **Global**.

<Note>
  Saiba como as configurações fluem entre os níveis em <a href="/pt-BR/how_to_use/code_review/configs/inheritance_overrides">Herança de configurações</a>.
</Note>

## Como Funciona

- Um escopo de diretório pode ter uma pasta ou várias. Todas as pastas dele compartilham as mesmas configurações.
- As pastas podem estar em qualquer profundidade, por exemplo `api/src/services`.
- Você pode adicionar quantos escopos de diretório precisar.
- Uma pasta pertence a um único escopo de diretório. Pastas dentro de uma pasta que já tem escopo não podem ser selecionadas.

### Regras de Seleção

A Kody verifica quais escopos de diretório o pull request toca:

- **Um escopo tocado:** usa as configurações desse escopo. Arquivos fora de qualquer escopo não mudam isso.
- **Nenhum escopo tocado:** usa as configurações do repositório, ou do Global se o repositório não tiver.
- **Dois ou mais escopos tocados:** usa as configurações do repositório, ou do Global se o repositório não tiver.

<Note>
  A Kody usa uma configuração por pull request para manter as revisões previsíveis. Misturar configurações causa conflitos.
</Note>

## Exemplos

<Tabs>
  <Tab title="Único diretório configurado">
    Você adicionou um escopo para `src/microservice-alpha`. Um pull request altera arquivos em `src/microservice-alpha` e em pastas não configuradas.

    Usa as configurações de **microservice-alpha**.
  </Tab>
  <Tab title="Nenhum diretório configurado">
    Um pull request toca apenas pastas sem escopo.

    Usa as configurações do **repositório** (ou do **Global** se o repositório não tiver).
  </Tab>
  <Tab title="Vários diretórios configurados">
    Você adicionou escopos para `src/microservice-alpha` e `src/microservice-beta`. Um pull request toca os dois.

    Usa as configurações do **repositório** (ou do **Global** se o repositório não tiver).
  </Tab>
</Tabs>

## Configuração

1. Na barra lateral, escolha o repositório no seletor de escopo no topo do grupo **Code review**.
2. Abra o seletor de novo e escolha **Add directory scope** no final.
3. No diálogo **Add directory scope**, marque as pastas em **Select directories**. Elas aparecem em **Selected directories**. Clique em **Add directory scope**.
4. Escolha o novo escopo. Ele aparece indentado sob o repositório dele no seletor. Altere as configurações em qualquer página e clique em **Save settings**.

Para alterar as pastas depois, abra o menu **⋯** ao lado do seletor de escopo e escolha **Edit directories**, depois **Save directories**. **Delete configuration** remove o escopo; as configurações do repositório voltam a valer para essas pastas.

## kodus-config.yml e escopos de diretório

- A Kody lê o `kodus-config.yml` apenas da raiz da branch padrão do repositório. Ela nunca lê um `kodus-config.yml` colocado dentro de uma pasta.
- Ela só lê o arquivo da raiz quando **Prefer kodus-config.yml settings** está ligado no escopo de **repositório**. A chave também aparece no escopo de diretório, mas não muda uma revisão: ligá-la ali não faz a Kody ler um arquivo para esse diretório, e desligá-la não impede que o arquivo do repositório seja aplicado.
- Uma configuração sobrescrita no escopo de diretório tem precedência sobre a mesma configuração no arquivo do repositório.
- Para manter as configurações de um escopo de diretório em arquivos, use um repositório de [configuração centralizada](/pt-BR/how_to_use/code_review/configs/centralized_config), onde um `kodus-config.yml` na pasta do escopo é sincronizado com as configurações do escopo de diretório.

Veja [Geral](/pt-BR/how_to_use/code_review/configs/general#prioridade-de-configuração) para o arquivo em si e [Herança de configurações](/pt-BR/how_to_use/code_review/configs/inheritance_overrides#kodus-config-yml) para a ordem.

## Kody Rules em um escopo de diretório

Um pull request é revisado com as Kody Rules do escopo de diretório sob a mesma seleção das configurações acima. Quando nenhum escopo único é selecionado, valem as regras de todos os escopos de diretório do repositório. Veja [Herança de regras](/pt-BR/how_to_use/code_review/configs/rules_inheritance).
