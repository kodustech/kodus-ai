Abra **Code review → What Kody writes**. As mensagens ficam na seção **Comments during the review**, com uma aba por mensagem: **Review starts**, **Review ends** e **Review fails**. Cada aba tem uma caixa **Message** e um menu **Reset to…**. O menu oferece **Inherited message** nos escopos de repositório e de diretório, e **Default message** no Global.

As mensagens podem ser definidas nos escopos Global, Repository e Directory.

## Como as mensagens aparecem

A Kody posta a mensagem de início quando uma revisão começa. Quando a revisão termina, ela edita esse mesmo comentário para virar a mensagem de fim. As sugestões são postadas como comentários de review entre as duas.

- **Início e fim postados:** um comentário, que mostra primeiro a mensagem de início e, quando a revisão termina, a mensagem de fim.
- **Início não postado nesta execução:** a mensagem de fim é postada como um novo comentário depois da revisão.
- **Fim definido como Never:** o comentário de início fica como está, também após uma revisão que falhou. A reação 😕 passa a ser o único sinal da falha.
- **A revisão falha:** a Kody posta o comentário de erro padrão dela no lugar da sua mensagem de fim, com o texto de **Review fails** abaixo.

No GitHub, quando uma nova revisão começa, a Kody recolhe o comentário da revisão anterior.

## Post this message

Em **Review starts** e **Review ends**, o seletor **Post this message** define quando aquela mensagem é postada. Cada mensagem tem a sua própria configuração.

- **On every push** (`every_push`, padrão) — postada a cada execução de revisão: quando o pull request é aberto e após cada push que dispara uma revisão.
- **Only when the PR opens** (`only_when_opened`) — postada uma vez, na primeira execução de revisão.
- **Never** (`off`) — não é postada. O texto é mantido, e a caixa **Message** e o **Add context** ficam desabilitados. A Kody continua rodando a revisão e postando sugestões.

As mensagens só são postadas quando uma revisão roda. Com uma cadência de revisão **Manual** e **Automated code review** ligado, a primeira revisão roda quando o pull request é aberto; os pushes seguintes não postam nada até alguém comentar `@kody start-review`.

## Add context

O menu **Add context** ao lado de **Message** insere um token que a Kody substitui por dados reais do pull request.

| Item do menu | Token | O que adiciona |
| --- | --- | --- |
| **Changed files** | `@changedFiles` | Uma tabela recolhível dos arquivos alterados, com status, adições e remoções. |
| **Changes summary** | `@changeSummary` | Totais de arquivos, linhas adicionadas, linhas removidas e alterações. |
| **Review options** | `@reviewOptions` | Quais categorias de revisão estão ligadas ou desligadas. |
| **Review cadence** | `@reviewCadence` | Como funcionam as revisões seguintes: automática, auto-pause com seus limites, ou manual. |
| **Review scope** | `@reviewScope` | Qual nível, global, de repositório ou de diretório, foi usado nesta revisão. |
| **Agent Prompt** | `@agentPrompt` | Todas as sugestões da revisão como um único prompt para colar em um agente de código, em um bloco recolhível **Open Agent Prompt**. |

`@agentPrompt` é oferecido apenas em **Review ends**, porque o conteúdo dele só existe depois da revisão.

## Mensagem de falha da revisão

Escreva um texto na aba **Review fails** para acrescentá-lo abaixo do comentário que a Kody posta quando uma revisão falha, por exemplo quando nenhum provedor de IA está configurado ou o provedor rejeitou a requisição. Use para apontar as pessoas para um responsável interno ou um runbook.

Não há chave liga/desliga para essa mensagem: o texto é a chave. Vazio (o padrão) mantém o comentário de erro padrão da Kody como está.

## Visibilidade dos comentários

A seção **Comment visibility** tem duas configurações.

| Configuração | Padrão | O que faz |
| --- | --- | --- |
| **Post as hidden comment** (`hideComments`) | Desligado | O comentário que carrega as mensagens **Review starts** e **Review ends** é postado recolhido, como desatualizado, para que a conversa do pull request fique curta. Sugestões inline e comentários no nível do PR não são recolhidos. Apenas GitHub; a chave fica oculta quando o GitHub não está conectado. |
| **Add a copyable prompt to each suggestion** (`suggestionCopyPrompt`) | Ligado | Cada sugestão traz um prompt que o desenvolvedor pode colar em um assistente de IA para aplicar a correção. No Bitbucket o prompt é postado como resposta na mesma thread; com a configuração desligada, os comentários do Bitbucket não mostram a correção. |

## YAML

As mensagens são armazenadas como `customMessages` nos arquivos `kodus-config.yml` de um repositório de [configuração centralizada](/pt-BR/how_to_use/code_review/configs/centralized_config). Um `kodus-config.yml` na raiz de um repositório revisado não as altera; use o app.

```yaml
customMessages:
    startReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: |
            Review started. @changedFiles
    endReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: |
            Review finished. @changeSummary
    errorReviewMessage:
        status: 'active' # off | active; a review reads only content
        content: |
            Reviews failing? Ping #platform-eng.
    globalSettings:
        hideComments: false
        suggestionCopyPrompt: true
```
