## Visão Geral

Personalize as mensagens que Kody envia no início e no fim das revisões de código. Este recurso permite personalizar o estilo de comunicação e adicionar contexto específico ou instruções para sua equipe.

Na barra lateral, abra **Code review → What Kody writes**. As mensagens ficam na seção **Comments during the review**, com uma aba por mensagem: **Review starts**, **Review ends** e **Review fails**. Cada aba tem uma caixa **Message** e um menu **Reset to…** (restaura a mensagem herdada, ou a mensagem padrão no escopo Global).

## Comportamento Padrão

Quando você não personalizou nenhuma mensagem, Kody funciona da seguinte forma:

1. **Mensagem Inicial**: Kody envia uma mensagem padrão de início de revisão
2. **Sugestões**: Kody fornece todas as sugestões de code review
3. **Mensagem Final**: Kody atualiza a mensagem inicial com um resumo da revisão

## Comportamento com Mensagens Personalizadas

Assim que você editar a mensagem de início ou fim de revisão pela primeira vez, o comportamento de Kody muda para:

1. **Mensagem Inicial**: Kody envia sua mensagem personalizada de início de revisão
2. **Sugestões**: Kody fornece todas as sugestões de code review
3. **Mensagem Final**: Kody envia sua mensagem personalizada de fim de revisão (sem atualizar a mensagem inicial)

Isso cria uma linha do tempo completa: **Mensagem Inicial → Sugestões → Mensagem Final**

## Opções de Configuração de Mensagens

### Post this message

Nas abas **Review starts** e **Review ends**, use o seletor **Post this message**
para decidir quando Kody deve postar aquela mensagem (cada mensagem tem sua própria
configuração):

- **Importante:** As mensagens são enviadas apenas quando uma revisão de fato é executada.  
  Se a sua cadência de revisão for **Manual**, as mensagens são postadas somente quando alguém executa `@kody start-review`.

- **On every push** (`every_push`): postada quando o pull request é aberto e novamente
  após cada novo push **que aciona uma revisão**. Isso acontece automaticamente
  apenas quando a cadência é **Automática** ou **Auto-pause**.
- **Only when the PR opens** (`only_when_opened`): postada apenas uma vez, logo
  após a primeira execução da revisão. Se a cadência for **Manual**, a primeira execução
  é quando você chama `@kody start-review`. Pushes futuros apenas adicionam sugestões
  de revisão mais a reação usual para que os autores saibam que a revisão foi reexecutada.
- **Never** (`off`): a mensagem não é postada; o texto é guardado para depois. Kody
  ainda executa a revisão e posta sugestões.

Quando uma mensagem está definida como **On every push** ou **Only when the PR opens**, Kody usa os
templates que você preencheu. Se você personalizar apenas a mensagem de início, apenas essa
mensagem é enviada; o mesmo vale para a mensagem de fim. Isso mantém a linha do tempo familiar de
**Mensagem Inicial → Sugestões → Mensagem Final** sempre que o comportamento permite
que as mensagens sejam postadas.

**Exemplo (cadência Manual)**  
PR aberto → nenhuma mensagem ainda  
`@kody start-review` → mensagem de início → sugestões → mensagem de fim

## Contexto Dinâmico

Você pode enriquecer suas mensagens personalizadas com contexto dinâmico usando o menu **Add context** ao lado de **Message** (nas abas **Review starts** e **Review ends**). Isso permite incluir:

### changedFiles

Um resumo dos arquivos alterados, mostrando adições e exclusões por arquivo. Fornece um detalhamento completo do que foi modificado no pull request.

### changeSummary

Um resumo abrangente de todas as alterações no pull request, dando uma visão geral de todo o escopo das modificações.

### reviewOptions

Um reflexo das configurações de revisão da equipe, mostrando quais categorias de revisão estão habilitadas ou desabilitadas para a revisão.

### reviewCadence

Fornece a política exata de revisão de acompanhamento para que os autores saibam o que acontece após
a primeira revisão automatizada:

- **Automático**: Kody revisita cada push assim que chega.
- **Auto-pause**: Kody revisita pushes automaticamente, mas se detectar uma
  "rajada de pushes" (por exemplo, 3 pushes em 15 minutos, com base nos seus
  limites) pausa as revisões de acompanhamento até que você as retome. O contexto de cadência
  inclui os limites de push e tempo para que a equipe saiba quando a pausa pode
  ser acionada.
- **Manual**: Kody aguarda alguém executar `@kody start-review` antes de fazer
  outra passagem.

### reviewScope

Mostra qual nível de configuração — global, repositório ou diretório — foi usado para revisar
este pull request, para que os autores saibam quais configurações valeram.

### agentPrompt

<Note>
  **Apenas na mensagem de fim de revisão.** Ela agrupa as sugestões de comentário de linha da
  revisão, que só existem depois que a revisão rodou — por isso não é oferecida na mensagem de
  início.
</Note>

Agrupa todas as sugestões da revisão em um único bloco de prompt para copiar e colar
(renderizado como um **Open Agent Prompt** recolhível). Cole no seu agente de código para
aplicar de uma vez todas as correções da revisão.

<Info>
  Essas variáveis de contexto serão preenchidas automaticamente com os dados reais
  do seu pull request quando Kody enviar a mensagem.
</Info>

<Note>
  No `kodus-config.yml` esses tokens são escritos com prefixo `@` — `@changedFiles`,
  `@changeSummary`, `@reviewOptions`, `@reviewCadence`, `@reviewScope`, `@agentPrompt` —
  em qualquer posição dentro do `content` da mensagem. O menu **Add context** insere os
  mesmos tokens pra você na interface web.
</Note>

## Mensagem de erro

Separada do par início/fim, você pode anexar seu próprio texto ao comentário que o Kody publica
quando uma revisão **falha** — por exemplo quando não há provider BYOK configurado, ou quando o
provider rejeitou a requisição. Escreva-o na aba **Review fails**.

Não existe um ajuste de ligar/desligar para essa mensagem: o próprio texto é o interruptor.

- **Vazio** (padrão) — o Kody publica a mensagem de erro padrão, sem alteração.
- **Preenchido** — seu texto é anexado abaixo da mensagem de erro padrão.

Use para apontar as pessoas ao responsável certo ou ao runbook, em vez de deixá-las com uma
falha genérica:

```yaml
customMessages:
    errorReviewMessage:
        status: 'active' # off | active
        content: |
            Revisões falhando? Chame o #platform-eng — a chave da API do Kodus é nossa.
```

Deixar `content` vazio mantém a mensagem de erro padrão inalterada.

## Visibilidade dos comentários (configurações globais)

Dois toggles que valem para todo comentário do Kody, não só para as mensagens customizadas. Eles ficam na
seção **Comment visibility** de **What Kody writes**:

| Configuração | Padrão | O que faz |
| --- | --- | --- |
| `hideComments` | `false` | Publica toda mensagem de revisão como comentário oculto/minimizado. Aparece na interface como **Post as hidden comment**. **Apenas GitHub** — o toggle fica escondido quando não existe nenhuma conexão com o GitHub. |
| `suggestionCopyPrompt` | `true` | Adiciona às sugestões o recurso de copiar como prompt, para você colar num agente de código. Aparece na interface como **Add a copyable prompt to each suggestion**. **Não disponível no Bitbucket** — o toggle fica escondido quando o Bitbucket é sua única plataforma conectada. |

```yaml
customMessages:
    globalSettings:
        hideComments: false # apenas GitHub
        suggestionCopyPrompt: true # não disponível no Bitbucket
```

<Note>
  Você sempre pode reverter para o comportamento padrão desabilitando ambas as mensagens
  personalizadas ou limpando o conteúdo da mensagem.
