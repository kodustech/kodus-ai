A Kody pode escrever uma descrição do que um pull request altera. Abra **Code review → What Kody writes**; as configurações ficam na seção **PR summary**. Elas podem ser definidas nos escopos Global, Repository e Directory.

A prévia da página (**Show preview** / **Hide preview**) mostra como o resumo fica em um pull request de exemplo.

## Escreva um resumo

Ative **Write a summary on every pull request**. Ele vem ativado por padrão. Com ele desativado, a Kody não escreve resumo e as opções abaixo ficam desabilitadas.

A Kody escreve o resumo no idioma definido em **Kody Language** em [General](/pt-BR/how_to_use/code_review/configs/general).

## Quando o PR já tem uma descrição

Escolha o que a Kody faz com uma descrição escrita pelo autor:

- **Replace** (padrão) — escreve uma nova descrição do zero.
- **Concatenate** — adiciona o resumo ao final da descrição existente.
- **Complement** — lê a descrição existente e escreve uma que destaca apenas o que é novo ou relevante.

Replace e Complement mantêm no topo da nova descrição as linhas da descrição antiga que vinculam uma tarefa, como `Closes #12`, `AB#12` ou um link do tracker. Concatenate deixa a descrição inteira como está.

O texto da Kody fica entre dois marcadores de comentário ocultos, então uma nova execução atualiza esse bloco em vez de empilhar outro.

## Quando chegam novos commits

Escolha o que acontece com o resumo da Kody quando commits são enviados depois que o pull request foi aberto:

- **Do nothing** (padrão) — o resumo fica como está.
- **Concatenate new summary** — um resumo dos novos commits é adicionado ao bloco existente da Kody.
- **Replace Kody's summary** — o bloco da Kody é substituído por um resumo do pull request inteiro.

Apenas o bloco da Kody muda. O texto escrito pelo autor permanece.

## Instruções do resumo

O campo opcional **Summary instructions** diz à Kody no que o resumo deve focar ou o que deve deixar de fora. Os chips de **Examples** adicionam linhas prontas.

- "Foque nas alterações de segurança e nos impactos de performance"
- "Resuma de forma concisa, destacando as APIs públicas modificadas"

As instruções também podem se referir ao que o review encontrou, por exemplo para mencionar a maior severidade. As instruções podem referenciar arquivos do repositório; veja [External References](/pt-BR/how_to_use/code_review/configs/custom_prompts#referências-externas).

**Try on a real PR** executa as configurações atuais em um dos seus pull requests. Ele fica disponível quando o resumo está ativado e você pode ler pull requests. A prévia roda antes de qualquer review, então não mostra apontamentos do review.

<Note>
  Em um pull request muito grande, que não cabe no contexto do modelo em poucas passadas, a Kody pula o resumo.
</Note>

Uma descrição que excede o limite do provider é cortada com uma nota de truncamento: 4.000 caracteres no Azure DevOps, 32.768 no Bitbucket e 65.536 no GitHub. No Azure DevOps, a Kody mantém o resumo curto para deixar espaço para a descrição existente.

## YAML

```yaml
summary:
    generatePRSummary: true
    behaviourForExistingDescription: 'replace' # replace | concatenate | complement
    behaviourForNewCommits: 'none' # none | concatenate | replace
    customInstructions: ''
```

O arquivo só é lido depois que **Prefer kodus-config.yml settings** estiver ativado. Veja [General](/pt-BR/how_to_use/code_review/configs/general#prioridade-de-configuração).
