O recurso **Kody Issues** mantém uma lista em tempo real das sugestões que a Kody fez e que **não foram implementadas** quando o pull request delas foi fechado, e as fecha conforme o código muda. Ele funciona sozinho; desative-o com o switch **Auto-create issues**.

Em qualquer plano, incluindo self-hosted sem licença, Owners, Repo Admins e Contributors podem abrir **Issues** pela paleta de comandos ⌘K. A entrada abre a lista mesmo quando aparece com um cadeado e a tag **Teams**.

Quem tem [acesso ao Cockpit](/pt-BR/how_to_use/cockpit/overview) pode abrir a lista pela aba **Issues**, que mostra a contagem de issues abertas.

A lista mostra **Status**, **Severity**, **Category**, **Title**, **Repository**, **File**, **Age** e **#PR(s)**. Por padrão, ela exibe as issues abertas.

Owners, Repo Admins e Contributors podem ler issues de todos os repositórios; Billing Managers não. Owners podem alterar qualquer issue, Repo Admins apenas as dos repositórios atribuídos a eles, e Contributors nenhuma.

Para consultar issues pelo terminal, veja a disponibilidade e os filtros de [`kodus issues`](/pt-BR/how_to_use/cli/commands#kodus-issues).

## Como as issues são criadas

<Note>
  As issues só são criadas quando os PRs são **fechados**, não quando são abertos
  nem durante a revisão. No GitLab e no Azure Repos, só conta um PR com merge.
</Note>

- Quando um PR é fechado, a Kody pega as sugestões que fez naquele PR e que não foram implementadas e cria uma **Issue** para cada uma, vinculada ao repositório. Cada issue guarda a explicação original, o arquivo, a severidade e a categoria.
- Se uma issue aberta no mesmo arquivo já cobre o mesmo problema, a Kody adiciona a nova sugestão a ela em vez de criar uma duplicata. **#PR(s)** lista todos os PRs que contribuíram.
- Isso inclui sugestões que a Kody não postou por estarem abaixo da severidade mínima ou acima de um limite de comentários. Sugestões que a Kody descartou por estarem erradas, por serem repetidas ou porque a categoria delas está desativada não viram issues.

<Warning>
  Kody Rules **Per PR** não geram issues. Apenas sugestões no nível de arquivo criam issues rastreáveis.
</Warning>

## Como as issues são resolvidas

Cada vez que um PR é fechado, a Kody confere as issues abertas nos arquivos que aquele PR alterou com o código atual:

- Se o código não tem mais o problema, a issue passa para **Resolved**.
- Se o arquivo foi excluído, a issue passa para **Dismissed**.

Isso também roda com **Auto-create issues** desativado, então as issues existentes continuam sendo fechadas.

## Trabalhando com issues

Clique em uma linha para abrir o painel de detalhes da issue, com os links do repositório, do PR e do arquivo, a descrição e **Team feedback from PR reactions** (a contagem de 👍 / 👎). Navegue entre as issues com **J** / **K**, e **Share** copia um link para a issue.

### Status

- **Open**: precisa de atenção.
- **Resolved**: definido pela Kody quando o problema sumiu do código.
- **Dismissed**: não relevante. Defina manualmente quando uma sugestão não se aplica ao seu time; a Kody também define quando o arquivo é excluído.

Altere o status no seletor no topo do painel de detalhes.

### Severity

Cada issue tem uma severidade (`Critical`, `High`, `Medium`, `Low`) que parte da severidade da sugestão. Altere-a no painel de detalhes para refletir as prioridades do seu time.

### Filters

Abra **Filters** no topo da lista (o botão mostra quantos estão ativos) para filtrar por **Status**, **Severity**, **Category**, **Title**, **Repository**, **File path** e **PR numbers**. **Set as default filters** aplica seus filtros toda vez que você abrir Issues neste navegador; **Reset to default filters** os traz de volta.
