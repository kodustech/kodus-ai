O Kodus CLI revisa suas alterações de código diretamente do terminal, antes que cheguem a um pull request. Aponte-o para sua árvore de trabalho, diff staged, branch ou commit. Ele aplica as Kody Rules e as configurações de code review da sua equipe.

Conecte o CLI ao [Kodus Cloud](/pt-BR/how_to_use/cli/getting_started) ou a uma [instância self-hosted](/pt-BR/how_to_use/cli/self_hosted). Dá para testar reviews básicos sem login, com limite de uso. Comandos do workspace exigem login ou chave de equipe, conforme o comando.

## Para quem é

- **Desenvolvedores solo** executando uma verificação pré-commit antes de fazer push.
- **Equipes** que desejam um conjunto de regras de revisão compartilhado em todos os clones, IDEs e jobs de CI — sem que cada desenvolvedor precise fazer login.
- **Agentes de código com IA** (Claude Code, Cursor, Codex, Windsurf e outros) executando loops de revisão e correção com saída estruturada.
- **Pipelines de CI/CD** que falham builds em problemas acima de um limite de severidade.

## Como é

Executar `kodus review` em uma alteração lista os achados com severidade, localização e uma correção sugerida. Em um terminal interativo no macOS e no Linux, os achados abrem no visualizador de diff Hunk, ao lado do código.

<img src="/images/kodus_cli_review.jpg" alt="AI code review in your CLI"/>

Com `--prompt-only`, a mesma revisão vira um texto compacto e estruturado para um agente de IA analisar e agir. Com `--fail-on`, o código de saída diz a um script se ele deve parar.

## Limites

|                  | Trial (sem conta)                                               | Logado ou com chave de equipe                                             |
| ---------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| Limite de taxa       | 2 revisões por hora, para cada usuário, dispositivo e pasta de repositório | 1.000 requisições por hora, por equipe                                 |
| Enviado ao Kodus    | Apenas o diff                                                    | O diff, mais os arquivos alterados em uma revisão de árvore de trabalho ou staged |
| Diff             | 20 milhões de caracteres                                            | 20 milhões de caracteres                                             |
| Arquivos por revisão | —                                                                | 500                                                               |
| Diff por arquivo    | —                                                                | 500.000 caracteres                                              |
| Conteúdo por arquivo | —                                                                | 2.000.000 de caracteres                                              |
| Tamanho da requisição     | 25 MB                                                            | 24 MB                                                             |

A hora do trial é uma janela móvel. Nenhum limite de arquivos ou linhas se aplica a uma revisão trial. Para uma equipe logada, as 1.000 requisições contam revisões, verificações de validação de negócio e eventos de sessão do [Kodus Trace](/pt-BR/how_to_use/cli/trace).

Com login ou chave de equipe, um arquivo acima dos limites por arquivo é ignorado com um aviso. `--branch`, `--commit` e `--fast` enviam apenas o diff, o que mantém revisões grandes abaixo do limite da requisição.

No modo trial, `kodus auth status` mostra seu uso e quando ele é reiniciado.

## CLI vs Kodus Web

O CLI e o web app do Kodus compartilham as Kody Rules e as configurações de code review. Use o CLI quando quiser uma revisão **antes de o PR existir** — em uma branch local, em um diff staged ou dentro de um loop de agente. Use o web app para revisões de PR, Cockpit e configuração em nível de equipe.

Uma revisão pelo CLI aplica as Kody Rules da sua equipe. Quando o remote git corresponde a um repositório adicionado ao Kodus, ela também aplica as regras desse repositório, o modo de revisão e as instruções do repositório (`CLAUDE.md`, `AGENTS.md`). Sem correspondência, rodam apenas as regras que valem para todos os repositórios. Uma revisão trial não tem equipe: roda com as configurações padrão e sem Kody Rules.

As revisões feitas pelo CLI aparecem no web app em **Reviews → CLI**. Uma revisão feita com chave de equipe é rotulada como **Team · &lt;key name&gt;**, e uma feita com login é rotulada como **Personal**.
