---
title: "Configuração Self-Hosted"
description: "Conecte o Kodus CLI à sua instância self-hosted do Kodus."
---

Se você estiver executando o Kodus na sua própria infraestrutura, o CLI funciona da mesma forma — você só precisa apontá-lo para a sua API.

## Conectar à Sua Instância

<Steps>
  <Step title="Definir a URL da API">
    Informe ao CLI onde sua API do Kodus está. Escolha um método:

    <Tabs>
      <Tab title="Variável de Ambiente (Recomendado)">
        ```bash
        export KODUS_API_URL=https://kodus-api.yourcompany.com
        ```

        Adicione isso ao seu perfil de shell (`~/.bashrc`, `~/.zshrc`, etc.) para torná-lo permanente:

        ```bash
        echo 'export KODUS_API_URL=https://kodus-api.yourcompany.com' >> ~/.zshrc
        source ~/.zshrc
        ```
      </Tab>
      <Tab title="Arquivo de Configuração">
        Crie ou edite `~/.kodus/config.json`:

        ```json
        {
          "apiUrl": "https://kodus-api.yourcompany.com",
          "teamKey": "kodus_xxxxx",
          "teamName": "Your Team",
          "organizationName": "Your Org"
        }
        ```

        O CLI cria esse arquivo automaticamente quando você executa `kodus auth team-key` e mantém um `apiUrl` que já esteja nele. Você também pode criá-lo manualmente.

        <Warning>
          `kodus auth login` e `kodus auth logout` apagam esse arquivo, inclusive o `apiUrl`. Se você entrar com um login, use a variável de ambiente.
        </Warning>
      </Tab>
      <Tab title="Inline (Uso Pontual)">
        ```bash
        KODUS_API_URL=https://kodus-api.yourcompany.com kodus review
        ```
      </Tab>
    </Tabs>

    <Warning>
      **HTTPS é obrigatório.** O CLI rejeita URLs que não sejam HTTPS por segurança. A única exceção é `localhost` e `127.0.0.1` para desenvolvimento local.
    </Warning>

    **Ordem de prioridade:** variável de ambiente `KODUS_API_URL` > `apiUrl` em `~/.kodus/config.json` > padrão (`https://api.kodus.io`).
  </Step>

  <Step title="Autenticar">
    <Tabs>
      <Tab title="Chave de Equipe (Recomendado)">
        Gere uma chave de equipe no app self-hosted do Kodus em **Organization → CLI keys**. Defina-a na variável de ambiente `KODUS_TEAM_KEY` no shell em que você executa o CLI.

        <Tip>Chaves de equipe são ideais para ambientes compartilhados e configurações com agentes de IA — sem necessidade de login individual.</Tip>
      </Tab>
      <Tab title="Login Pessoal">
        ```bash
        kodus auth login
        ```

        O CLI abre a página **Authorize Kodus CLI** do seu web app self-hosted. Entre com a conta registrada na sua instância (depois de entrar você cai no dashboard, então abra novamente a URL que o CLI imprimiu) e clique em **Authorize CLI**. Em uma máquina sem navegador, execute `kodus auth login --device-code` em um terminal privado. O CLI mostra a URL de autorização da sua instância e um código de uso único. Na barra de endereços do navegador, adicione o código como parâmetro `code` e clique em **Authorize CLI**. Mantenha o código e o link completo fora de logs e mensagens compartilhadas.

        Seu login é armazenado em `~/.kodus/credentials.json` com permissões restritas (600).

        <Info>
          O endereço dessa página vem da configuração `API_FRONTEND_URL` da sua API do Kodus. Ela precisa ser a URL do seu web app, ou a página de login abre no host errado.
        </Info>

        No CI, armazene uma chave de equipe no secret `KODUS_TEAM_KEY`.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Verificar a Conexão">
    ```bash
    kodus status
    ```

    `kodus status` mostra o modo de autenticação detectado localmente. Para conferir a URL da API, adicione `--verbose` a um comando que chame a API. Por exemplo, com uma chave de equipe que permite configurar repositórios, execute:

    ```bash
    kodus config remote list --verbose
    ```
  </Step>
</Steps>

## Cloudflare Access (Zero Trust)

Se sua API self-hosted estiver atrás do [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/applications/), o CLI suporta autenticação por service token.

<Tabs>
  <Tab title="Variáveis de Ambiente">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export CF_ACCESS_CLIENT_ID=your-client-id.access
    export CF_ACCESS_CLIENT_SECRET=your-client-secret
    ```
  </Tab>
  <Tab title="Arquivo de Configuração">
    ```json
    {
      "apiUrl": "https://kodus-api.yourcompany.com",
      "teamKey": "kodus_xxxxx",
      "cfAccessClientId": "your-client-id.access",
      "cfAccessClientSecret": "your-client-secret"
    }
    ```
  </Tab>
</Tabs>

Quando o client ID e o secret estão definidos, o CLI envia os headers `CF-Access-Client-Id` e `CF-Access-Client-Secret` em toda requisição à API. Prioridade: variáveis de ambiente > arquivo de configuração.

## Referência do Arquivo de Configuração

O CLI armazena a configuração em `~/.kodus/config.json`:

```json
{
  "apiUrl": "https://kodus-api.yourcompany.com",
  "teamKey": "kodus_xxxxx",
  "teamName": "Engineering",
  "organizationName": "Acme Corp",
  "cfAccessClientId": "your-client-id.access",
  "cfAccessClientSecret": "your-client-secret"
}
```

| Campo | Obrigatório | Descrição |
|-------|----------|-------------|
| `apiUrl` | Não | A URL da sua API self-hosted. Sobrescrita pela variável de ambiente `KODUS_API_URL`. |
| `teamKey` | Não | Chave de API da equipe (começa com `kodus_`). Sobrescrita pela variável de ambiente `KODUS_TEAM_KEY`. |
| `teamName` | Não | Nome de exibição da equipe. |
| `organizationName` | Não | Nome de exibição da organização. |
| `cfAccessClientId` | Não | Client ID do Cloudflare Access. Sobrescrito pela variável de ambiente `CF_ACCESS_CLIENT_ID`. |
| `cfAccessClientSecret` | Não | Client secret do Cloudflare Access. Sobrescrito pela variável de ambiente `CF_ACCESS_CLIENT_SECRET`. |

<Info>
  O arquivo de configuração é criado com permissões `0600` (leitura e escrita apenas para o dono). O diretório `~/.kodus/` é criado com permissões `0700`.
</Info>

## Resumo das Variáveis de Ambiente

| Variável | Descrição |
|----------|-------------|
| `KODUS_API_URL` | Endpoint da API self-hosted (HTTPS obrigatório, exceto localhost) |
| `KODUS_APP_URL` | URL do seu web app, para a qual `kodus config remote open` aponta (padrão `https://app.kodus.io`) |
| `KODUS_TEAM_KEY` | Chave de equipe para acesso compartilhado |
| `KODUS_TOKEN` | Um token de acesso de login, usado como está e sem renovação. Tem prioridade sobre qualquer outra credencial. Para CI, use uma chave de equipe |
| `CF_ACCESS_CLIENT_ID` | Client ID do Cloudflare Access |
| `CF_ACCESS_CLIENT_SECRET` | Client secret do Cloudflare Access |
| `KODUS_REQUEST_TIMEOUT_MIN` | Timeout de cada requisição à API em minutos (padrão `60`) |
| `KODUS_DISABLE_UPDATE_CHECK` | Defina como `1` para desativar o aviso de atualização |

## Integração com CI/CD

Para instâncias self-hosted em pipelines de CI/CD, defina a URL da API e uma chave de equipe como variáveis de ambiente. Um checkout novo não tem alterações não commitadas, então revise a branch contra a sua base com `--branch`. A branch base precisa estar disponível no checkout, então busque o histórico completo.

<Tabs>
  <Tab title="GitHub Actions">
    ```yaml
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0
    - name: Kodus Review
      env:
        KODUS_API_URL: ${{ secrets.KODUS_API_URL }}
        KODUS_TEAM_KEY: ${{ secrets.KODUS_TEAM_KEY }}
      run: npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
  <Tab title="GitLab CI">
    ```yaml
    kodus-review:
      variables:
        GIT_DEPTH: "0"
      script:
        - git fetch origin main
        - npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```

    Adicione `KODUS_API_URL` e `KODUS_TEAM_KEY` como variáveis de CI/CD nas configurações do projeto.
  </Tab>
  <Tab title="Genérico">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export KODUS_TEAM_KEY=kodus_xxxxx
    npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
</Tabs>

<Tip>
  Use `--fail-on error` ou `--fail-on critical` para falhar o pipeline quando forem encontrados problemas acima de um limite de severidade. Pull requests são revisados pela integração Git, então não precisam de um job no pipeline.
</Tip>

## Distribuindo para Sua Equipe

Compartilhe com sua equipe as [instruções de instalação do CLI](/pt-BR/how_to_use/cli/getting_started) e a URL da API self-hosted. Cada pessoa configura `KODUS_API_URL` no perfil do shell ou `apiUrl` em `~/.kodus/config.json`. Distribua a chave de equipe pelo gerenciador de segredos e defina-a como `KODUS_TEAM_KEY` antes de usar o CLI.

## Solução de Problemas

<AccordionGroup>
  <Accordion title="Erro de Segurança: A URL da API deve usar o protocolo HTTPS">
    O CLI exige HTTPS para todas as URLs que não sejam localhost. Ele então volta para o padrão `https://api.kodus.io`, então leia a mensagem antes de autenticar. Verifique se a sua instância self-hosted tem um certificado TLS válido. Se estiver testando localmente, use `http://localhost:<port>`.
  </Accordion>

  <Accordion title="Conexão recusada ou timeout">
    - Verifique se a URL está acessível: `curl -I https://kodus-api.yourcompany.com`
    - Confira se um firewall ou VPN está bloqueando a conexão
    - Se estiver atrás do Cloudflare Access, garanta que `CF_ACCESS_CLIENT_ID` e `CF_ACCESS_CLIENT_SECRET` estejam definidos
    - Use `--verbose` para ver a URL exata em uso
  </Accordion>

  <Accordion title="Falha de autenticação (401)">
    - Execute `kodus status` para checar seu estado de autenticação atual
    - Se estiver usando uma chave de equipe, confirme que ela ainda está **Active** em **Organization → CLI keys** no seu web app self-hosted
    - Se estiver usando login pessoal, o CLI atualiza seu login automaticamente; se a atualização falhar, execute `kodus auth login` novamente
    - Garanta que `KODUS_API_URL` aponta para a instância correta
  </Accordion>

  <Accordion title="API retornou resposta inválida (esperava JSON, recebeu HTML)">
    Isso geralmente significa que a URL está chegando a um proxy reverso, load balancer ou página do Cloudflare Access em vez da API de fato. Verifique:
    - O caminho da URL está correto (sem `/api` ou similar no final)
    - As credenciais do Cloudflare Access estão configuradas, se aplicável
    - O proxy reverso está encaminhando as requisições corretamente
  </Accordion>

  <Accordion title="Limite de dispositivos atingido">
    Sua instância self-hosted pode impor limites de dispositivos por organização. O web app não tem uma lista de dispositivos para limpar, então fale com seu admin para aumentar o limite (a configuração `CLI_DEVICE_LIMIT` da API; `0`, o padrão, significa sem limite).
  </Accordion>
</AccordionGroup>
