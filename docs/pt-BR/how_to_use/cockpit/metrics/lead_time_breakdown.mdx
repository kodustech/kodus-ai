## O que é Detalhamento do Lead Time

O Detalhamento do Lead Time divide o tempo desde o primeiro commit de um PR até o seu fechamento em três fases: tempo de codificação, tempo de pickup e tempo de review. Mostra onde o seu fluxo de trabalho desacelera.

No Cockpit, é o gráfico **Lead Time Breakdown** na aba **Productivity**: uma barra empilhada por semana, com **Coding Time**, **Pickup Time** e **Review Time** em horas. Clique em um nome abaixo do gráfico para esconder ou mostrar aquela fase.

## Como Calculamos

```
Coding Time = (Last Commit Time) - (First Commit Time)
Pickup Time = (PR Opened Time) - (Last Commit Time)
Review Time = (PR Closed Time) - (PR Opened Time)
```

- **Coding Time**: do primeiro ao último commit do PR, incluindo commits enviados depois que o PR foi aberto.
- **Pickup Time**: do último commit até a abertura do PR. É negativo para um PR que recebeu novos commits depois de aberto.
- **Review Time**: da abertura do PR até o seu fechamento, com merge ou não.

Para cada semana, cada fase é o 75º percentil (P75) entre os PRs fechados naquela semana, para que outliers incomumente longos não distorçam o resultado. Um PR cujo valor para uma fase é exatamente zero, como o coding time de um PR de um único commit, fica de fora do P75 daquela fase. Só contam commits feitos até 30 dias antes da abertura do PR, porque commits mais antigos em uma branch com rebase geralmente pertencem a outro trabalho. Um PR sem dados de commit fica de fora.

O tempo antes do primeiro commit (planejamento, design) e depois do fechamento (deploy) não é contado.

## Por que é Importante

Entender onde o tempo é gasto ajuda a otimizar a parte certa do seu processo:

- **Coding Time**: mostra a eficiência do desenvolvimento
- **Pickup Time**: revela gargalos no fluxo entre terminar o código e pedir review
- **Review Time**: indica a eficácia do processo de review

## Como Melhorar

### Reduzir o Coding Time
- Deixe os requisitos claros antes de o trabalho começar
- Divida grandes funcionalidades em partes gerenciáveis
- Faça pareamento em problemas complexos

### Reduzir o Pickup Time
- Abra o PR logo depois de terminar o código
- Automatize a criação e a configuração do PR
- Defina quando o código está pronto para review

### Reduzir o Review Time
- Defina expectativas claras para os revisores
- Use verificações automatizadas para detectar problemas antes do review
- Distribua a carga de review por todo o time
- Responda prontamente aos comentários de review
- Mantenha os PRs pequenos
