## O que é Frequência de Deploy

A Frequência de Deploy é o número médio de pull requests que o seu time fecha por semana. O Cockpit não lê deploys do seu CI/CD, então usa pull requests fechados como substituto de com que frequência o código chega à produção.

No Cockpit, é o card **Deploy Frequency** na aba **Productivity**.

## Como Calculamos

```
Deploy Frequency = (PRs closed in the range) ÷ (weeks in the range)
```

- O intervalo é o intervalo de datas selecionado no topo do Cockpit. Sua duração em semanas é arredondada para cima, com mínimo de uma semana.
- Todo PR fechado conta, qualquer que seja sua branch base, e um PR fechado sem merge conta igual a um mergeado.

Por exemplo, se 12 PRs são fechados em um intervalo de 4 semanas, a Frequência de Deploy é 3 por semana.

Se o seu time faz deploy em um ritmo diferente do que fecha PRs (por exemplo, release trains ou deploys a partir de feature branches), leia esse número como throughput de PRs, não como deploys.

## Lendo o card

O card mostra a média por semana, um badge de nível e o valor do período anterior de mesma duração, com a variação percentual. O rodapé diz "Last 2 weeks was …" qualquer que seja o intervalo selecionado; o número é do período anterior. Passe o mouse sobre o badge para ver os níveis:

| PRs fechados por semana | Nível |
| --- | --- |
| Mais de 5 | Elite |
| 2 a 5 | High |
| 1 a 2 | Fair |
| Menos de 1 | Need focus |

## Como Melhorar

- Divida grandes alterações em PRs menores
- Implemente pipelines CI/CD para deploys automatizados
- Use feature flags para fazer deploy sem expor funcionalidades
- Configure monitoramento e rollback rápido
