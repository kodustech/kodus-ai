## O que é PRs por Desenvolvedor

PRs por Desenvolvedor conta os pull requests que cada membro do time teve **fechados**, agrupados por semana. Foca no trabalho concluído, para você ver a produção e como ela se distribui pelo time.

No Cockpit, é o gráfico **PRs Merged By Developer** na aba **Productivity**: uma barra empilhada por semana, com uma cor por desenvolvedor. Passe o mouse sobre uma barra para ver a contagem de cada desenvolvedor.

## Como Calculamos

```
Weekly PRs per Developer = COUNT(closed PRs) per developer per week
```

- Um PR conta na semana em que foi **fechado**, com merge ou fechado sem merge. Apesar do nome do gráfico, o Cockpit não distingue os dois.
- O desenvolvedor é o nome de usuário do autor do PR no seu provedor Git.
- As semanas começam na segunda-feira.
- PRs abertos e em rascunho, PRs sem data de fechamento e PRs sem autor não são contados.

## Developer Activity vs. PRs by Developer

| | Developer Activity | PRs by Developer |
| --- | --- | --- |
| **Conta** | PRs abertos | PRs fechados |
| **Base da data** | Data de abertura | Data de fechamento |
| **Filtro de status** | Nenhum | Apenas PRs fechados |
| **Exibido como** | Tabela, uma coluna por semana | Barras empilhadas por semana |

## Contexto a Ter em Mente

- Um desenvolvedor com PRs menos numerosos, porém maiores, pode ser igualmente produtivo. Leia o gráfico junto com [PR Size](/pt-BR/how_to_use/cockpit/metrics/pr_size).
- A produção varia com o tipo de trabalho, o papel e a fase do projeto.
- O trabalho revisado ou feito em pareamento não aparece aqui.
