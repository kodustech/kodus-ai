## O que é Taxa de Bugs

A Taxa de Bugs (Bug Ratio) é a porcentagem de pull requests fechados que são correções de bugs. Mostra quanto da sua entrega vai para corrigir problemas em vez de construir funcionalidades.

No Cockpit, é o card **Bug Ratio** na aba **Productivity**. Não é a change failure rate do DORA: ela conta PRs de correção de bug, não deploys que falharam.

## Como Calculamos

Um job em segundo plano pede a um modelo de IA que classifique cada pull request **somente pelo título** como **Bug Fix**, **Feature**, **Refactor** ou **Test**. A descrição do PR, as labels e o diff não são usados, e não há nada a configurar.

```
Bug Ratio = (PRs classified as Bug Fix) ÷ (PRs closed in the range) × 100
```

O intervalo é o intervalo de datas selecionado no topo do Cockpit, e um PR fechado é um PR mergeado ou fechado sem merge. Um PR que ainda não foi classificado conta no total, mas não como correção de bug. Por exemplo, se 3 de 15 PRs são classificados como correções de bug, sua Taxa de Bugs é 20%.

Quando a taxa é 0% tanto no intervalo selecionado quanto no período anterior, o card mostra **Once we have enough data, your metrics will appear here.** em vez de 0%.

## Lendo o card

O card mostra a porcentagem, um badge de nível e o valor do período anterior de mesma duração, com a variação percentual (quanto menor, melhor). O rodapé diz "Last 2 weeks was …" qualquer que seja o intervalo selecionado; o número é do período anterior. Passe o mouse sobre o badge para ver os níveis:

| Bug Ratio | Nível |
| --- | --- |
| Menos de 5% | Elite |
| 5% a 10% | High |
| 10% a 20% | Fair |
| Mais de 20% | Need focus |

## Por que os Títulos dos PRs Importam

Como só o título é lido, um título descritivo dá uma taxa mais precisa.

| Bons títulos de correção de bug | Títulos vagos |
| --- | --- |
| "Fix: User login fails with invalid credentials" | "Fix stuff" |
| "Resolve issue: API returns 500 error for large requests" | "Update code" |
| "Patch: Fix null pointer exception in user service" | "Improve performance" |

## Como Melhorar

- Teste mais nos níveis unitário, de integração e end-to-end
- Use linters e analisadores estáticos antes da produção
- Divida grandes funcionalidades em partes menores e testáveis
- Use feature flags para implantações mais seguras
- Realize revisões pós-incidente para prevenir recorrências
