## O que é PRs Abertos vs Fechados

Este gráfico coloca duas contagens semanais lado a lado: quantos pull requests foram **abertos** e
quantos foram **fechados** na mesma semana. Ele mostra se o time dá conta do trabalho que abre,
ou se os pull requests se acumulam mais rápido do que são fechados.

## Como Calculamos

Para cada semana do intervalo de datas selecionado:

- **Opened**: pull requests abertos naquela semana, qualquer que seja o status hoje. Para um PR aberto antes de
  o repositório ser conectado, e que não esteja entre os PRs importados na conexão, a data é quando
  o Kodus o registrou pela primeira vez.
- **Closed**: pull requests fechados naquela semana, com merge ou fechados sem merge.

As duas contagens são independentes: um PR aberto em uma semana e fechado três semanas depois
conta na barra **Opened** da primeira semana e na barra **Closed** da quarta. É isso que torna o
backlog visível.

## Como Ler

- **Closed próximo de Opened, semana após semana**: regime estável. O time fecha o que abre.
- **Opened acima de Closed por várias semanas**: o backlog está crescendo.
- **Closed bem acima de Opened**: geralmente um lote de PRs parados fechado de uma vez. Confirme antes
  de ler como ganho de produtividade.
- **Ambos caem ao mesmo tempo**: normalmente um feriado, um freeze ou um incidente.

<Tip>
  Leia este gráfico junto com [PR Cycle Time](/pt-BR/how_to_use/cockpit/metrics/lead_time_for_changes).
  Uma distância crescente aqui somada a um cycle time subindo aponta o review como o gargalo.
</Tip>

## Onde Encontrar

Cockpit → aba **Productivity**, na seção de gráficos detalhados. As semanas começam na segunda-feira, e você pode esconder **Opened** ou **Closed** clicando no nome abaixo do gráfico.

<Note>
  Este gráfico pode ser escondido para toda a organização. Se você não o vê, confira
  **Organization → Cockpit visibility**. Veja [Configuração do Cockpit](/pt-BR/how_to_use/cockpit/configuration).
</Note>
