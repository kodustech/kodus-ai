パーソナルアクセストークンを使用する場合、Kodusはリポジトリの選択を保存する際に、各リポジトリにWebhookを作成します。これにはリポジトリのWebhookへの読み取りと書き込みのアクセスが必要です。classicトークンでは`admin:repo_hook`、fine-grainedトークンでは**Webhooks: Read and write**です。トークンにこの権限がない場合、**Repositories**にそのリポジトリが理由とともに表示されるので、次の手順でWebhookを手動で作成できます。

GitHub Appの場合、リポジトリごとのWebhookはありません。イベントはAppのWebhookから届きます。[GitHub Appの作成](/ja/how_to_deploy/platforms/github/github_app)を参照してください。

<Note>
  WebhookのURLはWebhooksサービス（ポート3332）に到達できる必要があります。APIドメインを使用するのは、リバースプロキシが`/.../webhook`パスをWebhooksサービスにルーティングする場合のみ機能します。
</Note>

1. GitHubリポジトリに移動
2. 「Settings」をクリック
3. 左サイドバーの「Webhooks」を見つける
4. 「Add webhook」をクリック
5. Webhookを設定します：

   - **Payload URL**: `.env`ファイルのURLを入力：`API_GITHUB_CODE_MANAGEMENT_WEBHOOK`（末尾は`/github/webhook`）
   - **Content type**: `application/json`
   - **Secret**: 空欄のまま
   - **SSL verification**: SSL検証を有効にする
   - **Which events would you like to trigger this webhook?**: 個別のイベントを選択する
   - 以下のボックスにチェックを入れます：
     - Issue comments
     - Pull request review comments
     - Pull requests

6. 「Add webhook」をクリック

GitHubリポジトリのコードレビュー用Webhookのセットアップが完了しました。

<Note>
  トークンによるインテグレーションで利用するのは、これらのイベントだけです。Kodusはpush、プルリクエストのレビュー、レビュースレッドなど、それ以外を無視するため、選択してもトラフィックが増えるだけです。
</Note>
