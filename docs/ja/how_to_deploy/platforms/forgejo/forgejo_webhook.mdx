---
title: Webhookの作成
description: "自動登録が行われなかった場合にForgejoのWebhookを手動で作成し、Kodusが利用するイベントを選択する手順。"
icon: webhook
---

<Note>
  Forgejoのサポートはコミュニティによって維持されています。
</Note>

Kodusは通常、リポジトリの選択を保存する際にWebhookを自動的に作成します。これにはリポジトリへの管理者アクセスと、トークンの`write:repository`スコープが必要です。自動作成が行われなかった場合は、**Repositories**にそのリポジトリが理由とともに表示されるので、Webhookを手動で設定できます：

<Note>
  WebhookのURLはWebhooksサービス（ポート3332）に到達できる必要があります。APIドメインを使用するのは、リバースプロキシが`/.../webhook`パスをWebhooksサービスにルーティングする場合のみ機能します。
</Note>

1. Forgejoリポジトリに移動します
2. リポジトリの**Settings**タブを開きます
3. **Webhooks**を選択します
4. **Add webhook** → **Forgejo**をクリックします
5. Webhookを設定します：

   - **Target URL**: `.env`ファイルの`API_FORGEJO_CODE_MANAGEMENT_WEBHOOK`に設定したURLを入力します（末尾は`/forgejo/webhook`）
   - **HTTP method**: POST
   - **POST content type**: `application/json`
   - **Trigger on**: **Custom events**を選択し、次を選択します：
        - Repository events: **Push**
        - Pull request events: **Modification**、**Synchronized**、**Comments**
   - **Active**: チェック

6. **Add webhook**をクリックします

これで、ForgejoリポジトリでコードレビューのためのWebhookが正常に設定されました。

<Note>
  Forgejoはプルリクエストのコメントを`issue_comment`として配信し、Kodusは`pull_request`、`push`、`issue_comment`の配信に対応します。プルリクエストのイベントのうち、対応するのは`opened`、`synchronized`、`reopened`、`closed`です。プルリクエストの新しいコミットを配信するのは**Synchronized**です。

  Forgejoでは、pushイベントが特に重要です。ブランチの変更前と変更後のheadを両方含む唯一のイベントであり、Kodusはこれでforce-pushを検出し、ブランチをオープンなプルリクエストに対応づけます。issueイベントは届いた時点で破棄されます。
</Note>
