<Info>
ロードバランサーなどの別のプロキシがすでに Kodus へのトラフィックをルーティングしている場合は、このページをスキップしてください。
</Info>

Kodus インスタンスを外部のシステムからアクセス可能にするには（コードレビューの webhook とパブリックアクセスに必要です）、Nginx でリバースプロキシを設定する必要があります。ルーティングするサービスは 3 つで、Web アプリ（ポート 3000）、API（ポート 3001）、webhooks サービス（ポート 3332）です。インストーラーは 3 つすべてをホスト上に公開します。

2 つのサブドメインを使う場合の Nginx 設定のサンプルです。

```nginx
# Server block for the Kodus Web Application
server {
    listen 80;
    server_name kodus-web.yourdomain.com; # Replace with your actual web app domain

    location / {
        proxy_pass http://localhost:3000; # Points to the Kodus Web App container
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        proxy_buffer_size 16k;
        proxy_buffers 8 16k;
        proxy_busy_buffers_size 32k;
    }
}

# Server block for the Kodus API
server {
    listen 80;
    server_name kodus-api.yourdomain.com; # Replace with your actual API domain

    client_max_body_size 50m;

    location ~ ^/(github|gitlab|bitbucket|azure-repos|forgejo)/webhook {
        proxy_pass http://localhost:3332; # Points to the Kodus Webhooks service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    location / {
        proxy_pass http://localhost:3001; # Points to the Kodus API service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

<Note>
  Webhook は別のサービス（ポート 3332）が処理します。webhook URL に API のドメインを使う場合は、`location ~ ^/(github|gitlab|bitbucket|azure-repos|forgejo)/webhook` ブロックが必須です。`API_MCP_SERVER_ENABLED=true` の場合、同じ API ドメインが `/mcp` も提供します。
</Note>

### 任意：専用の Webhooks サブドメイン

webhook 用に別のドメイン（例：`kodus-webhooks.yourdomain.com`）を使いたい場合は、webhooks サービスを指す server ブロックを追加します。

```nginx
server {
    listen 80;
    server_name kodus-webhooks.yourdomain.com;

    location / {
        proxy_pass http://localhost:3332; # Webhooks service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

この設定を `/etc/nginx/sites-available/kodus` に保存し（任意の名前でも構いません。たとえば、必要なら `kodus-web` と `kodus-api` を別々のファイルにします）、シンボリックリンクを作成して有効にします。

```bash
sudo ln -s /etc/nginx/sites-available/kodus /etc/nginx/sites-enabled/
sudo nginx -t  # Test the configuration
sudo systemctl reload nginx  # Apply the changes
```

<Info>
  **`.env` をパブリック URL に合わせてください。** プロキシが起動したら、`.env` に次を設定し、`./scripts/install.sh` をもう一度実行してコンテナを再作成します。

  - `NEXTAUTH_URL`、`API_FRONTEND_URL`、`API_USER_INVITE_BASE_URL`：Web アプリのパブリックな `https://` URL。
  - webhook URL（たとえば `API_GITHUB_CODE_MANAGEMENT_WEBHOOK`）：**webhooks サービス**に到達する `https://` URL。API のドメインを使うのは、`/.../webhook` がポート `3332` にルーティングされる場合だけです。それ以外は、`https://kodus-webhooks.yourdomain.com/github/webhook` のような専用の webhooks ドメインを使います。
  - `API_URL`（SSO を使う場合のみ）：`https://kodus-api.yourdomain.com` などのパブリックな API URL。

  `WEB_HOSTNAME_API` と `WEB_PORT_API` は、プロキシを指しません。Web アプリのサーバーは Docker ネットワーク経由で API を呼び出すため、デフォルト（`localhost` と `3001`）のままにしてください。`WEB_PORT_API` を設定すると、Web アプリは `http://<WEB_HOSTNAME_API>:<WEB_PORT_API>` を呼び出すため、ポート `443` のパブリックな HTTPS ホストは失敗します。

  webhook URL が間違っていてもエラーは発生しません。リポジトリは接続されますが、レビューは開始されません。
</Info>

### SSL の有効化（推奨）

本番環境のデプロイでは、Let's Encrypt による SSL の設定を強くお勧めします。

```bash
# Install Certbot for Let's Encrypt
sudo apt-get update
sudo apt-get install certbot python3-certbot-nginx

# Obtain and install certificates (add -d for the webhooks domain if you use one)
sudo certbot --nginx -d kodus-web.yourdomain.com -d kodus-api.yourdomain.com # Replace with your actual domains
```

これにより、Nginx の設定が自動的に HTTPS を使うように構成され、それらのドメインの HTTP トラフィックがリダイレクトされます。
