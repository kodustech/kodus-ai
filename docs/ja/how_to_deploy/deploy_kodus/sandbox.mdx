適切なコンテキストで PR をレビューするため、Kodus はリポジトリ全体を
**AST グラフ**（ノードとエッジ）に解析し、それを使って cross-file
コンテキストを取得し、提案を検証し、エージェントに入力します。パーサーは
**サンドボックス**内で実行されるため、API プロセスから隔離された状態で `git clone`、依存関係のインストール、
CLI の実行ができます。

同じサンドボックスは、レビューエージェントに、チェックアウトされたリポジトリに対するファイルツール（検索、ファイル読み取り、
ディレクトリ一覧）も提供します。レビューでも `@kody`
の会話でも同様です。

このページでは、選択できるサンドボックスのモード、AST
グラフとは何か、キャッシュによって PR レベルのレビューがどのように高速に保たれるかを説明します。

## AST グラフの仕組み

Kodus は [`@kodus/kodus-graph`](https://www.npmjs.com/package/@kodus/kodus-graph)
を使います。これはリポジトリをたどって JSON グラフ（関数、クラス、
ファイル、インポート、呼び出し）を出力する CLI です。この CLI は **Kodus のイメージに
プリインストールされている**（`kodus-ai-worker` を含む）ため、`local` モードでは追加のセットアップ手順はありません。

ライフサイクル：

1. **リポジトリを選択したとき**（セットアップ中、または UI であとからリポジトリを追加したとき）— Kodus は
   `AstGraphBuild` ジョブをキューに入れます。このジョブはデフォルトブランチに対して
   `kodus-graph parse --all` を実行し、結果を Postgres（`ast_graph_*` テーブル）に保存し、
   リポジトリをインデックス済みとしてマークします。これはバックグラウンドで行われるため、
   完了を待たずに PR を開けます。
2. **PR がデフォルトブランチにマージされたとき** — webhook ハンドラーが
   増分リビルドをキューに入れます。変更されたファイルだけを再解析し、
   差分をキャッシュ済みのグラフにマージします。500 ファイルを超える変更を含むマージでは、
   代わりに完全なリビルドが実行されます。
3. **すべての PR レビューで** — Kodus はキャッシュ済みのグラフを読み込み、PR が触れた
   ファイルだけを解析して、エージェントに絞り込まれたサブグラフを渡します。
   これがホットパスであり、リポジトリ全体を再解析することはありません。

キャッシュのおかげで、大規模リポジトリのレビューが現実的になります。最初のビルドは
リポジトリのオンボーディング時に 1 回だけ実行され、それ以降のすべての PR は Postgres から読み取ります。

## サンドボックスのモード

サンドボックスは、`.env` の `SANDBOX_PROVIDER` で選択します。

| モード | 動作 | トレードオフ |
|---|---|---|
| **`local`** _（インストーラーのデフォルト）_ | `kodus-graph` を `worker` コンテナ自体の中で実行します。Bun と CLI はプリインストールされています。 | 外部への依存がありません。worker コンテナの CPU とメモリを共有します。 |
| **`e2b`** | ジョブごとにリモートの [E2B](https://e2b.dev) サンドボックスを起動します。`API_E2B_KEY` が必要です。 | 強力な分離があり、巨大なリポジトリにも対応できます。**有料のサードパーティサービスです。** |
| **`auto`** | `API_E2B_KEY` が設定されている場合は `e2b` を使い、そうでなければ `local` を使います。 | `SANDBOX_PROVIDER` を設定しない場合の動作です。 |
| **`null`** | サンドボックスなし。 | レビューは diff しか参照できません。cross-file コンテキストもコードグラフもありません。 |

### モードの選び方

- **まず始めたい、「とにかく動かしたい」** → `local`。これが
  インストーラーのデフォルトで、外部アカウントは一切不要です。
- **リポジトリが非常に大きい、または厳格な分離が必要** →
  `e2b`。[e2b.dev](https://e2b.dev) にサインアップし、`API_E2B_KEY` を設定して、
  `SANDBOX_PROVIDER=e2b` に切り替えます。

`API_E2B_KEY` なしで `SANDBOX_PROVIDER=e2b` を設定すると、レビューはサンドボックスなしになります。
cross-file コンテキストもコードグラフもありません。`SANDBOX_PROVIDER=local` のまま
`API_E2B_KEY` だけを設定した場合は、ローカルのサンドボックスが維持されます。

サンドボックスをオフにするには、`SANDBOX_PROVIDER=null` を設定します。オフの場合は `./scripts/doctor.sh` が警告を表示します。`./scripts/validate-env.sh` が `null` を拒否する場合は、インストーラーの `.env.example` に記載された有効値を確認してください。古いインストーラーのスキーマに記載されている `none` は、ワーカーでは `auto` として扱われます。

## 既存のセルフホスト環境の移行

AST グラフより前のリリースからアップグレードした場合、**すでに選択済みのリポジトリ**にはまだグラフがありません。ビルドが
自動的に実行されるのは、**新しい**リポジトリを選択したときだけです。それらをインデックスするには、
インストーラーに同梱のバックフィルスクリプトを実行します。

```bash
# From the kodus-installer directory, with the stack running:
./scripts/backfill-ast-graph.sh
```

このスクリプトはインスタンス内のすべてのチームをたどり、グラフのステータスが未設定、`pending`、または
`failed` の選択済みリポジトリごとに `AstGraphBuild`
ジョブをキューに入れます。ビルドはバックグラウンドで実行されるため、完了するまでの間も
Kodus を使い続けられます。

このスクリプトは**冪等**です。再実行しても、すでに
`ready` のリポジトリはスキップされ、`building` のジョブが再度キューに入ることはなく、
自由に中断して再開できます。

主なフラグ：

```bash
./scripts/backfill-ast-graph.sh --org <id>          # restrict to one org
./scripts/backfill-ast-graph.sh --org <id> --team <id>  # one team only
./scripts/backfill-ast-graph.sh --force             # also rebuild ready graphs
./scripts/backfill-ast-graph.sh --limit 50          # cap jobs per team (default: 10)
./scripts/backfill-ast-graph.sh --dry-run           # list teams, enqueue nothing
```

進捗は、worker のログで確認できます。

```bash
docker compose logs -f worker | grep -i ast-graph
```

## 設定

```bash
# Default for self-hosted — runs in the worker container.
SANDBOX_PROVIDER=local

# Or use E2B (paid) for stronger isolation.
SANDBOX_PROVIDER=e2b
API_E2B_KEY=your-e2b-api-key
```

E2B には [e2b.dev](https://e2b.dev) でサインアップし、ダッシュボードで API キーを生成して、
`.env` に追加し、`./scripts/install.sh` をもう一度実行します。

`local` モードでは、worker は 120 秒の制限時間でリポジトリをクローンします。非常に大きなモノレポを
ゆっくりクローンすると、この時間を超えることがあり、その場合レビューはサンドボックスなしで実行されます。
制限時間をミリ秒で引き上げます。

```bash
API_SANDBOX_CLONE_TIMEOUT_MS=300000
```

## 何がどこで実行されるか

```mermaid
flowchart LR
    pr[PR webhook] --> worker[worker]
    worker -->|local mode| sandbox_local[kodus-graph CLI<br/>inside worker container]
    worker -.->|e2b mode| sandbox_e2b[E2B remote sandbox<br/>kodus-graph runs there]
    sandbox_local --> graph[(Postgres • ast_graph_*)]
    sandbox_e2b --> graph
    graph --> agent[code-review agent]
```

## リソースのサイジング

`local` サンドボックスは、`git clone` と `kodus-graph parse` を
`worker` コンテナ内で実行するため、worker のメモリ制限がそれらにも適用されます。Helm
チャートは、worker に `1536Mi` の制限を設定します。グラフのビルド中にメモリ不足で worker が強制終了される場合は、
`services.worker.resources` で制限を引き上げるか、
`e2b` を使ってホスト外で解析します。

## トラブルシューティング

**レビューに cross-file コンテキストが含まれない（`local` モード）：**

worker のログで、クローンまたは `kodus-graph` の解析エラーを確認します。

```bash
docker compose logs -f worker | grep -iE "sandbox|kodus-graph"
```

worker がクローンするには、Git プロバイダーへのネットワークアクセスが必要です。`./scripts/doctor.sh` は、選択済みのリポジトリに対して読み取り専用の
`git ls-remote` を実行し、失敗を報告します。

**`e2b` のジョブがハングする、または起動に失敗する：**

`API_E2B_KEY` が設定されていて有効であることを確認します。

```bash
docker compose exec worker sh -c 'if [ -n "$API_E2B_KEY" ]; then echo "API_E2B_KEY is set"; else echo "API_E2B_KEY is missing"; fi'
```

E2B のダッシュボードには、ライブセッションとクォータの使用状況が表示されます。
