<Note>
  このガイドはローカル開発を目的としています。本番環境へのデプロイについては、
  [Kodusのデプロイ](/ja/how_to_deploy/deploy_kodus/generic_vm)ガイドを参照してください。
</Note>

<Note>
  `.env.example`はKodus Cloudと共有されているテンプレートのため、新しい`.env`には
  `API_CLOUD_MODE=true`と`SANDBOX_PROVIDER=e2b`が設定されています。セルフホスト型
  インスタンスと同じ動作にするには、サービスを起動する前に`.env`で
  `API_CLOUD_MODE=false`と`SANDBOX_PROVIDER=local`を設定してください。
  `API_CLOUD_MODE=false`の場合、`telemetry.kodus.io`への匿名の日次ハートビートが
  デフォルトで有効になります。ローカルでの実験をフリートに表示させたくない場合は、
  `KODUS_TELEMETRY_DISABLED=true`を設定してください。送信される内容と確認方法は
  [匿名テレメトリ](/ja/how_to_deploy/deploy_kodus/telemetry)を参照してください。
</Note>

## 前提条件

- Node.js（固定バージョンは`.nvmrc`を参照）
- pnpm
- Docker
- OpenSSL
- LLM APIキー

<Note>
  kodus-aiはpnpmワークスペースです。リポジトリ内のロックファイルは`pnpm-lock.yaml`のみです。
  ローカル開発ではnpmとyarnはサポートされていません。
</Note>

## プロジェクトの実行

<Tabs>
  <Tab title="自動セットアップ（推奨）">
      クイックかつ自動化されたセットアップには、セットアップスクリプトを使用してください：

      ```bash
      git clone https://github.com/kodustech/kodus-ai.git
      cd kodus-ai
      pnpm run setup
      ```

      <Warning>
        `pnpm setup`ではなく`pnpm run setup`を使用してください。`pnpm setup`はpnpm自身の組み込みコマンド
        （ホームディレクトリの設定用）であり、プロジェクトのスクリプトは実行されません。
      </Warning>

      このスクリプトは自動的に以下を行います：
      - 必要な依存関係（Node.js、pnpm、Docker、OpenSSL）をすべて確認
      - プロジェクトの依存関係をインストール
      - `.env.example`から`.env`ファイルを作成
      - セキュリティキーを生成
      - `kodus-backend-services`と`shared-network`のDockerネットワークを作成
      - 次のステップを表示

      その後、[モデルを接続](#モデルを接続する)してから、サービスを起動します：

      ```bash
      pnpm run docker:start
      ```

      **外部インテグレーション（Webhooksなど）を使用する場合：**
      ```bash
      pnpm run docker:start
      pnpm run tunnel  # Creates public endpoint for external services
      ```

      <Info>
        データベースのマイグレーションとシードは、コンテナ起動時に**自動的に**実行されます —
        開発用composeファイルでは`RUN_MIGRATIONS`と`RUN_SEEDS`のデフォルトが`true`です。
        別途の手順は不要です。

        これらを`false`にして自分で管理する場合は、ホストから`pnpm run migration:run`と
        `pnpm run seed`を実行してください。
      </Info>

      すべてが起動したら、ブラウザで **http://localhost:3000** を開いてください。
  </Tab>
  <Tab title="手動セットアップ">
      すべてを手動で設定する場合：

      ### 1. リポジトリのクローン

      ```bash
      git clone https://github.com/kodustech/kodus-ai.git
      cd kodus-ai
      ```

      ### 2. 依存関係のインストール

      ```bash
      pnpm install
      ```

      ### 3. 環境変数の設定

      ```bash
      cp .env.example .env
      ```

      ### 4. セキュリティキーの生成

      `.env`内のシークレットに、安全な値を生成します：

      ```bash
      # JWT secrets and the NextAuth secret
      openssl rand -base64 32

      # Encryption key and code management secret
      openssl rand -hex 32

      # Webhook token (URL-safe)
      openssl rand -base64 32 | tr -d '=' | tr '/+' '_-'
      ```

      以下の変数を設定します：
      - `API_JWT_SECRET`（`openssl rand -base64 32`を使用）
      - `API_JWT_REFRESH_SECRET`（`openssl rand -base64 32`を使用）
      - `API_CRYPTO_KEY`（`openssl rand -hex 32`を使用）
      - `CODE_MANAGEMENT_SECRET`（`openssl rand -hex 32`を使用）
      - `CODE_MANAGEMENT_WEBHOOK_TOKEN`（`openssl rand -base64 32 | tr -d '=' | tr '/+' '_-'`を使用）
      - `WEB_NEXTAUTH_SECRET`と`NEXTAUTH_SECRET`（同じ値にします。`openssl rand -base64 32`を使用）

      ### 5. Dockerネットワークのセットアップ

      必要なDockerネットワークを作成します：

      ```bash
      docker network create kodus-backend-services || true
      docker network create shared-network || true
      ```

      ### 6. モデルの接続

      下記の[モデルを接続する](#モデルを接続する)に従ってください。

      ### 7. 開発環境の起動

      Dockerを使用してサービスを起動します：

      ```bash
      pnpm run docker:start
      ```

      このコマンドは以下を起動します：

      - Kodus API
      - Worker（非同期ジョブ）
      - Webhooksサービス
      - Kodus Webアプリケーション
      - PostgreSQLデータベース
      - MongoDBデータベース
      - RabbitMQ

      外部サービス用のパブリックエンドポイントも作成する場合：
      ```bash
      pnpm run tunnel
      ```

      ### 8. 初回セットアップ

      することはありません — `docker-compose.dev.yml`が`RUN_MIGRATIONS`と`RUN_SEEDS`を
      デフォルトで`true`にしているため、APIコンテナが起動時にマイグレーションとシードを実行します。

      <Accordion title="マイグレーションを手動で実行する">
        `.env`で`RUN_MIGRATIONS=false` / `RUN_SEEDS=false`にした場合（自分で管理したい場合など）は、
        ホストから次を実行します：

        ```bash
        pnpm run migration:run   # OLTP database
        pnpm run seed            # initial data
        ```

        他のデータストアには個別のコマンドがあります：

        ```bash
        pnpm run analytics:migration:run     # analytics warehouse
        pnpm run mcp-manager:migration:run   # MCP manager
        pnpm run mongo:migrate               # MongoDB
        ```
      </Accordion>

      ### 9. サービスエンドポイント

      以下のURLでサービスにアクセスできます：

      - Web UI: `http://localhost:3000`
      - API: `http://localhost:3001`
      - Webhooks: `http://localhost:3332`
      - RabbitMQ管理コンソール: `http://localhost:15672`
      - PostgreSQL: `localhost:5432`、MongoDB: `localhost:27017`
      - APIデバッグポート: `9229`

  </Tab>
</Tabs>

## モデルを接続する

Kodusがレビューを実行するにはモデルが必要です。サービスを起動する前に、次のいずれかの方法を選んでください。

- **アプリで設定する。** サインイン後、サイドバーの**AI providers**を開き、キーを使ってプロバイダーを接続します。[BYOK](/ja/how_to_use/byok)を参照してください。
- **`.env`で設定する。** インスタンス全体で1つのモデルを使用します：

  ```env
  API_LLM_PROVIDER=openai                  # openai, openai_compatible, anthropic, anthropic_compatible, google_gemini or google_vertex
  API_LLM_PROVIDER_MODEL="your-model-id"
  API_LLM_API_KEY="your-api-key"
  # API_LLM_BASE_URL="https://your-provider.example.com/v1"   # required for the *_compatible providers
  ```

  各プロバイダーに必要な設定は、[LLM Provider Configuration](/ja/how_to_deploy/deploy_kodus/generic_vm#llm-プロバイダーの設定)を参照してください。**AI providers**ページで接続したモデルは、`.env`のモデルより優先されます。

## オプションのサービス

`pnpm run docker:start`では、MCP Managerとanalytics workerは起動しません。`KODUS_DEV_EXTRAS`で追加します：

```bash
KODUS_DEV_EXTRAS=mcp pnpm run docker:start          # MCP Manager (also set API_MCP_SERVER_ENABLED=true)
KODUS_DEV_EXTRAS=analytics pnpm run docker:start    # analytics worker
KODUS_DEV_EXTRAS=mcp,analytics pnpm run docker:start
```

## 開発ワークフロー

### 基本的なローカル開発

1. **サービスの起動**: `pnpm run docker:start`（マイグレーションとシードは自動実行）
2. **アプリを開く**: `http://localhost:3000`にアクセス
3. **ヘルスチェック**: `pnpm run dev:health-check`

### 外部インテグレーションを使用した開発

外部サービス（GitのWebhookなど）とのインテグレーションをテストする必要がある場合：

1. **サービスの起動**: `pnpm run docker:start`
2. **トンネルの作成**: `pnpm run tunnel`（パブリックエンドポイントを作成）
3. **Webhook URLの更新**: トンネルコマンドが`.env`を自動的に更新します
4. **Gitプロバイダーの設定**: GitプロバイダーのWebhook設定でトンネルURLを使用
5. **インテグレーションのテスト**: Webhookをトリガーしてログを監視

<Info>
  **トンネルのメリット：**
  - 本物のWebhookインテグレーションをローカルでテスト
  - 外部サービス通信のデバッグ
  - チームメンバーとの開発環境の共有
  - モバイルアプリやその他の外部クライアントのテスト
</Info>

## トラブルシューティング

### クイックヘルスチェック

```bash
pnpm run dev:health-check
```

このヘルスチェックは以下を検証します：
- **サービス**: API、worker、webhooks、web、PostgreSQL、MongoDB、RabbitMQの各コンテナ
- **ポートの可用性**: Web（3000）、API（3001）、PostgreSQL（5432）、MongoDB（27017）、RabbitMQ（5672）
- **データベースセットアップ**: マイグレーションとシードデータ
- **APIエンドポイント**: `/health/simple`、`/health`、基本的な接続性


### 手動での確認

1. **Web UIの確認**: ブラウザで`http://localhost:3000`にアクセス
2. **APIヘルスの確認**: `http://localhost:3001/health`にアクセス
3. **RabbitMQの確認**: `http://localhost:15672`にアクセス（デフォルト認証情報: `dev`/`devpass`。`.env`の`RABBITMQ_DEFAULT_USER`と`RABBITMQ_DEFAULT_PASS`の値）
4. **データベース接続の確認**: ログでデータベース接続の成功を確認
5. **Webhookエンドポイントのテスト**: GitプロバイダーのWebhookは`http://localhost:3332/[provider]/webhook`を指すようにします（またはリバースプロキシが`/.../webhook`をwebhooksサービスにルーティングする場合はAPIドメインを使用）


### セットアップスクリプトの問題

自動セットアップスクリプト（`pnpm run setup`）が失敗した場合：

**依存関係が見つからない場合：**
```bash
# Check if all required tools are installed
node --version
pnpm --version
docker --version
openssl version
```

**Dockerのパーミッション問題：**
```bash
# Add your user to the docker group (Linux)
sudo usermod -aG docker $USER
# Then log out and log back in
```

**ネットワーク作成エラー：**
```bash
# Check if networks already exist
docker network ls | grep -E "kodus|shared"
# Remove conflicting networks if needed
docker network rm kodus-backend-services shared-network
```

### よくある問題

**ポートの競合：**
- ポート3000（Web）、3001（API）、3332（Webhooks）、5432（PostgreSQL）、27017（MongoDB）、5672/15672（RabbitMQ）が使用可能であることを確認
- Kodusを起動する前にこれらのポートを使用している他のサービスを停止

**環境変数が読み込まれない：**
- プロジェクトルートに`.env`ファイルが存在することを確認
- 変数の代入に末尾のスペースがないことを確認
- 必要なセキュリティキーがすべて正しく生成されたことを確認

**ヘルスチェックの失敗：**
- `pnpm run dev:health-check`を実行して詳細な診断を確認
- コンテナが完全に起動しているか確認（`pnpm run docker:start`後、1〜2分待機）
- データベースマイグレーションとシードデータが読み込まれていることを確認
- `pnpm run docker:logs`でAPIのログを確認して起動エラーを確認

**APIが応答しない：**
- APIはコンテナ起動後に完全に初期化されるまでに時間がかかります
- マイグレーションとシードデータが読み込まれているか確認
- `.env`ファイルに必要な変数がすべて含まれていることを確認
- ヘルスチェックを実行して、どのコンポーネントが失敗しているかを確認

**レビューが実行されない：**
- モデルが接続されていません。**AI providers**を開くか、`.env`で`API_LLM_PROVIDER_MODEL`とキーを設定してください。

**レビューにクロスファイルコンテキストがない：**
- `API_E2B_KEY`なしで`SANDBOX_PROVIDER=e2b`を指定すると、サンドボックスなしでレビューが実行されます。`SANDBOX_PROVIDER=local`を設定してください。

**外部サービスとのWebhookの問題：**
- `pnpm run tunnel`を使用して外部Webhook用のパブリックエンドポイントを作成
- GitプロバイダーのWebhook URLをトンネルURLに更新
- Webhookインテグレーションのテスト中はトンネルが稼働していることを確認
- トンネルのログで接続の問題を確認
