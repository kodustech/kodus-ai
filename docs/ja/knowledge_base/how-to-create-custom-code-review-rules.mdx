---
title: "カスタムコードレビュールールを作成する方法"
description: "チームのアーキテクチャ、パターン、コーディングの好みに合わせたルールを定義し、すべての PR でチェックします。"
---

どのチームにも、汎用のリンターではカバーできない規約があります。アーキテクチャの境界、命名パターン、テスト要件、ビジネス固有の制約などです。カスタムコードレビュールールを使うと、それらを、Kody がすべての Pull Request で実行するチェックとして定義できます。

## Kodus でルールを作成する

1. サイドバーの **Code review** グループ上部にあるスコープピッカーで **Global**（またはリポジトリ / ディレクトリ）を選択し、**Kody Rules** を開きます
2. **Review Rules** タブで **New rule** をクリックします
3. 次を設定します。
   - **Rule name**：ルールが確認する内容（例：「サービスファイルにはテストが必要です」）
   - **Execution mode**：**Per file**（変更された各ファイルをチェックし、インラインでコメント）または **Per PR**（PR 全体をチェックし、PR コメントを 1 件投稿）
   - **Path**：Per file ルールを特定のファイルに限定する glob パターン（例：`src/services/**/*.ts`）。Per PR ルールでは使用されません
   - **Instructions**：何をチェックするか、どう判断するか
   - **Severity**：Critical、High（デフォルト）、Medium、Low

**Advanced settings** では **Bad example** と **Good example** を追加でき、Kody が違反と準拠したコードを見分けるのに役立ちます。

## ルールが機能するための工夫

- **具体的にする。** パターン、パス、何を違反とみなすかを明記します。
- **標準を指し示す。** `@file:docs/architecture.md` のようにファイルをパスで指定すると、Kody はルールを判断するときにそれを読み取ります。ファイルは Pull Request のターゲットブランチから読み取られます。
- **適切なモードを選ぶ。** 1 つのファイルで確認できる内容には Per file を、Pull Request 全体に関する要件（説明、サイズ、関連ファイルが一緒に変更されるかどうかなど）には Per PR を使います。

### 例：命名規則の適用

次のようなファイルレベルのルールを作成できます。

- **Rule name**：「React コンポーネントは PascalCase のファイル名を使用する必要があります」
- **Path**：`src/components/**/*.tsx`
- **Severity**：High
- **Instructions**：「PascalCase の命名に従っていないコンポーネントファイルを指摘します。」

### 例：アーキテクチャ境界のルール

```
Name: Domain layer must not depend on infrastructure
Execution mode: Per PR
Instructions: Flag any import added in src/domain/ that
points to src/infrastructure/. The allowed dependencies are
described in @file:docs/architecture.md.
```

### 例：テストカバレッジのルール

```
Name: Every service change needs a test change
Execution mode: Per PR
Instructions: For each file modified in src/services/, check that the
PR also changes a matching test file under test/services/.
```

## ルールを追加するその他の方法

- **Rules Library**：Kody Rules ページで **Discovery** をクリックして、既製のルールやパックを追加します
- **リポジトリルール**：リポジトリの `.kody/rules` に、1 ルールにつき 1 つの markdown ファイルとして保存します
- **自動生成**：Kody がレビュアーの過去のコメントからルールの下書きを作成します
- **レビュースレッド内**：Kody にルールの作成や変更を依頼します。例：`@kody update this rule to ignore test files`

Kody に Pull Request を `CLAUDE.md`、`AGENTS.md`、Cursor や Copilot の指示に照らしてチェックさせるには、[コーディングエージェントの指示](/ja/how_to_use/code_review/configs/rules_file_detection)を参照してください。

完全なリファレンスについては、[Kody Rules](/ja/how_to_use/code_review/configs/kody_rules) を参照してください。
