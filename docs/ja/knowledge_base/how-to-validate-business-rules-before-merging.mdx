コードレビューは通常、セキュリティ、パフォーマンス、スタイルといったコード品質に焦点を当てます。しかし、**このコードはビジネスが求めたことを実際に行っているか？** という問いは見落とされがちです。Business Logic Validation は、そのギャップを埋めます。

## チェックする内容

Kody は、PR が参照しているタスクを見つけてタスクトラッカーから読み取り、すべての要件について、コード上でどの状態にあるかを一覧にします。結果は、最新の状態に保たれる PR への 1 件のコメントです。各要件には状態が付きます。

| 状態 | 意味 |
|---|---|
| **MET** | diff で実装されています。 |
| **PARTIAL** | 要件に書かれている内容の一部が実装されています。 |
| **MISSING** | PR の diff に証拠がない、または PR が依拠しているコードがそれを行っていません。 |
| **CHECK MANUALLY** | ビジュアルやフローに関する要件、またはコードからは Kody が判断できないものです。 |
| **NOT IN TASK** | タスクが求めていない変更です。 |

すべての行には、根拠となるファイルと行が示され、何を変更すべきかが記載されます。

## 使い方

### 自動（デフォルト）

**Code review → What to review** で **Business Logic** カテゴリがオン（デフォルトでオン）で、タスクトラッカーが接続されている場合、PR のタイトル、ブランチ名、説明にタスクが記載されていれば、Kody は最初のレビューで PR をチェックします。記載の形式は、`PROJ-123` またはタスクのリンク、あるいはタイトルやブランチに `#123`（説明では `Closes #123`）です。その後は、依頼されたとき、または **Re-check after a push** を設定している場合はプッシュのたびに、再チェックします。

### オンデマンド

PR に（コードの行ではなく）コメントします。

```
@kody -v business-logic https://kodustech.atlassian.net/browse/KC-1292
```

```
@kody -v business-logic
Orders above $500 must issue cashback credits.
Discount codes cannot be combined with loyalty rewards.
Free shipping applies only to domestic orders.
```

コマンドの後にタスクがない場合、Kody は PR が参照しているタスクを再チェックします。40 文字以上のテキストがある場合は、書かれた内容に対して PR をチェックし、トラッカーは不要です。

## サポートされているタスクソース

[Plugins](/ja/how_to_use/code_review/plugins) でトラッカーを接続します。Kody はタスクを ID でのみ読み取ります。

| ソース | 参照方法 |
|--------|-----------------|
| **Linear** | Issue キー（`TEAM-123`）または Issue の URL |
| **Jira**（Atlassian Rovo） | Issue キー（`PROJ-123`）または Issue の URL |
| **Notion** | ページの URL |
| **Git Issues** | GitHub、GitLab、Bitbucket、Forgejo の `#123`、`owner/repo#123`、または Issue の URL |
| **その他のトラッカー**（例：ClickUp） | カスタムプラグイン経由。名前がトラッカーであることを示していない場合は、**Task source** として選択します。 |
| **Inline** | PR コメントに要件を書きます |

## ヒント

- 明示的な受け入れ基準があるタスクほど、徹底的に検証されます。
- 不足を修正したら、もう一度 `@kody -v business-logic` とコメントします。同じコメントが更新されます。
- PR がタスク全体を完了する場合は **Closes PROJ-1**、一部を完了する場合は **Part of PROJ-1** を使います。
- タスクにタイトルしかない場合、Kody は推測せずに受け入れ基準を尋ねます。

詳細については、[Business Logic Validation](/ja/how_to_use/code_review/business_logic_validation) を参照してください。
