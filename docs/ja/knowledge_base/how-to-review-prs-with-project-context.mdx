---
title: "プロジェクト固有のコンテキストで PR をレビューする方法"
description: "Kody にプロジェクトのドキュメント、ハンドブック、アーキテクチャガイドへのアクセスを与え、より的確なコードレビューを実現します。"
---

汎用的なコードレビューでは、汎用的な問題しか見つかりません。プロジェクトに本当に関連するフィードバックを得るには、Kody があなたのプロジェクト固有のコンテキスト、つまりアーキテクチャの決定、規約、ビジネスルールを理解している必要があります。

## コンテキストを提供する方法

### メモリ

会話を通じて Kody に規約を教えます。

```
@kody remember: this project uses hexagonal architecture.
Domain layer must never depend on infrastructure.
```

メモリは保持され、今後のすべてのレビューに適用されます。

### ルール内のファイル参照

ルール内で、自分たちのドキュメントを直接参照します。

```
Instructions: Validate that new endpoints follow the patterns
in @file:docs/api-conventions.md and use the base classes
defined in @file:src/shared/base-controller.ts.
```

### カテゴリの指示

Kody がすべてのレビューに含める、プロジェクト固有の指示を追加します。

1. サイドバーで **Code review → What to review** を開きます
2. **Bug**、**Performance**、**Security** カテゴリの **Instructions** を、アーキテクチャの説明、チームのガイドライン、ドメイン知識などのコンテキストで編集します
3. Kody はこれをすべてのコードレビュー分析に含めます

Kody の提案の書き方（トーン、長さ）を変更するには、**Code review → What Kody writes** の **Kody's personality** を使用します。

### タスクトラッカー

**Plugins** で Linear、Jira（**Atlassian Rovo**）、Notion、Git Issues を接続します。PR がタスクを参照している場合、Kody はその PR をタスクの要件と受け入れ基準に照らしてチェックします。[Business Logic Validation](/ja/how_to_use/code_review/business_logic_validation)を参照してください。

### プラグイン

インストールしたプラグインは、PR コメントで Kody にメンションしたときに Kody が使えるツールであり、[カスタムエージェント](/ja/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp)でオンにできるツールでもあります。独自の MCP サーバーをカスタムプラグインとして追加すると、他のツールも取り込めます。

## ワークフローの例

1. **Memories** でアーキテクチャのルールを定義します：`@kody remember: we follow CQRS pattern in this service`
2. ドキュメントを参照する **Review Rules** を作成します：`@file:docs/architecture.md`
3. タスクトラッカーを接続して、Kody が PR をタスクの要件に照らして検証するようにします
4. ドメイン固有の知識のために、**What to review** でカテゴリの **Instructions** を追加します

詳細については、[カテゴリの指示](/ja/how_to_use/code_review/configs/custom_prompts)と[プラグイン](/ja/how_to_use/code_review/plugins)を参照してください。
