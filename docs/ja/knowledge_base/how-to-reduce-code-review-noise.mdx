---
title: "コードレビューのノイズと誤検知を減らす方法"
description: "AI コードレビューを調整して、最も関連性の高い提案だけを表示し、通知疲れを避けます。"
---

優先度の低い提案が多すぎると、開発者はコードレビューのフィードバックを完全に無視してしまうことがあります。重要なことは表示し、重要でないことには沈黙するように、レビューを調整することが鍵です。

## 重要度のしきい値

Kodus は、どの検出結果を実際に投稿するかをフィルタリングします。

- **Minimum severity to post** — しきい値以上の提案のみを投稿します（デフォルト：Medium）。Kody はより低い重要度の問題も検出しますが、それらにはコメントしません。
- **Apply the threshold to Kody Rules** — デフォルトではオフで、チーム独自のルールは常に表示されます

これらはサイドバーの **Code review → What to review**、または `kodus-config.yml` で設定します。

```yaml
suggestionControl:
  severityLevelFilter: medium   # low | medium | high | critical
  applyFiltersToKodyRules: false
```

このページの `kodus-config.yml` のスニペットは、リポジトリで **Prefer kodus-config.yml settings** がオン（リポジトリスコープの **Code review → General**）の場合にのみ有効になります。Kody は、デフォルトブランチのリポジトリルートにあるファイルを読み取ります。[設定の優先順位](/ja/how_to_use/code_review/configs/general#設定の優先度)を参照してください。

## ファイルとパスを無視する

ノイズを生むファイル（ロックファイル、生成されたコード、設定ファイル）をスキップします。**Code review → General** の **Ignored files** に追加するか、`kodus-config.yml` で設定します。

```yaml
ignorePaths:
  - yarn.lock
  - package-lock.json
  - "**/*.generated.ts"
  - dist/**
```

ファイル内のリストは、デフォルトのパターンを含め、アプリで設定したリストを置き換えます。残したいデフォルトはそこにコピーしてください。

## タイトルで PR をスキップする

レビューが不要な PR（リリース、バージョンの更新）をスキップします。**Code review → General** の **Ignore title keywords** にキーワードを追加するか、`kodus-config.yml` で設定します。

```yaml
ignoredTitleKeywords:
  - "release"
  - "bump version"
  - "chore"
```

## 分析カテゴリの切り替え

**Code review → What to review** の **Bug**、**Performance**、**Security**、**Business Logic** のスイッチ、または `kodus-config.yml` で、不要なレビューカテゴリ全体を無効にします。

```yaml
reviewOptions:
  bug: true
  security: true
  performance: false        # disable if too noisy
  business_logic: false     # disable if not relevant
```

## レビュー頻度

開発が活発な間のスパムを防ぐには、**Auto-pause**（**Code review → General** → **Automated code review** → **Review Cadence**）を使用します。Kodus は、短時間に連続したレビュー（デフォルト：15 分以内に 3 回）の後、誰かが `@kody start-review` とコメントするまで PR を一時停止します。

## 開始と終了のメッセージ

Kody は、レビューの開始時と終了時にそれぞれメッセージを投稿します。**Code review → What Kody writes → Comments during the review** の **Post this message** で、PR のオープン時にのみ投稿するか、まったく投稿しないかを、メッセージごとに選べます。[カスタムメッセージ](/ja/how_to_use/code_review/configs/custom_messages)を参照してください。

## Business Logic のコメント

PR がタスクを満たしている場合、Kody は 1 行のコメントを投稿します。不足点だけを通知してほしい場合は、**Business Logic** の設定で **Comment when every requirement is met** をオフにします。[Business Logic Validation](/ja/how_to_use/code_review/business_logic_validation)を参照してください。

詳細については、[一般設定](/ja/how_to_use/code_review/configs/general)と[重要度のしきい値](/ja/how_to_use/code_review/configs/suggestion_control)を参照してください。
