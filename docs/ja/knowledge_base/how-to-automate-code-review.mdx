手動のコードレビューはボトルネックを生み出します。レビュアーはコンテキストを切り替え、PRが溜まり、フィードバックの品質にばらつきが生じます。AI搭載のコードレビューは、人間のレビュアーがコードを見る前に、すべてのPRで即座に実行され、問題を発見します。

## Kodusがコードレビューを自動化する方法

接続されると、Kodusはすべてのプルリクエストを自動的にレビューします。セキュリティの脆弱性、パフォーマンスの問題、エラー処理、保守性、カスタムルールについてコードを分析し、PR内に直接コメントを投稿します。

### サポートされているプラットフォーム

- **GitHub** — GitHub App（またはパーソナルアクセストークン）を通じて
- **GitLab** — OAuth（またはパーソナルアクセストークン）を通じて
- **Bitbucket** — APIトークンを通じて
- **Azure DevOps**（Azure Repos）— パーソナルアクセストークンを通じて
- **Forgejo** — パーソナルアクセストークンを通じて

### 分析される内容

デフォルトでは、Kodusは **Code review → What to review** でオン/オフを切り替えられるカテゴリと、独自のルールを確認します：
- セキュリティ問題（SQLインジェクション、XSS、ハードコードされた秘密情報）
- パフォーマンスの問題（N+1クエリ、インデックスの不足）
- 潜在的なバグ（nullポインタ、リソースリーク、エラー処理のギャップ）
- ビジネスロジックへの準拠（リンクされたタスク要件に対して検証）
- カスタムKodyルール（コードスタイルやチームの規約に使用します）

### レビューの頻度オプション

頻度は **Code review → General** の **Enable Automated Code Review** → **Review Cadence** で設定します。

| モード | 動作 |
|------|----------|
| **自動** | すべてのプッシュをレビュー — 継続的なフィードバック |
| **自動一時停止** | 急速なプッシュ時に一時停止（例：15分以内に3回）してノイズを避ける |
| **手動** | `@kody start-review` とコメントしたときのみレビュー |

## はじめに

1. [kodus.io](https://kodus.io)でワークスペースを作成するか、[Kodusをセルフホスト](/ja/how_to_deploy/deploy_kodus/generic_vm)します
2. Gitプロバイダーを接続します（GitHub、GitLab、Bitbucket、Azure DevOps、またはForgejo）
3. 監視するリポジトリを選択します
4. PRをオープンします — Kodusが自動的にレビューします
