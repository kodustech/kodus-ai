---

プロダクトが複数のリポジトリに分かれている場合、たとえばバックエンド API を呼び出すフロントエンドや、共有コントラクトのパッケージに依存するサービスでは、単一リポジトリのレビューでは境界での破壊的変更を見逃すことがあります。**リンクリポジトリ（Linked repositories）** は、コードレビュー中に、それらの兄弟コードベースから任意でオンデマンドのコンテキストを Kody に提供します。

> **プランの要件：** リンクリポジトリは **Teams** と **Enterprise** プラン、およびトライアル期間中に利用できます。Free プランにはクロスレポのコンテキストは含まれません。セルフホストには Enterprise ライセンスが必要です。

これは、[リポジトリ間でコーディング標準を共有する](/ja/knowledge_base/how-to-share-standards-across-repositories)（組織レベルのルールと継承）こととは異なります。リンクリポジトリが共有するのは、レビューのための**ソースコンテキスト**であり、レビュールールではありません。

## 何をするか

レビュー対象のリポジトリに対して、同じ組織内の最大 **3 つ**のリンクリポジトリを宣言します。レビュー中は次のように動作します。

1. Kody はまず、PR の diff が境界となる部分に触れているかを確認します。これは高速で固定のチェックであり、コストはかかりません。
2. diff が**コントラクトの接点**（DTO、エクスポート、文字列リテラル、ステータスキー、API を思わせるパスなど）に触れているように見える場合、クロスレポのツールが有効になります。
3. リンクされたリポジトリは、Kody が実際に読み取りや検索を必要としたときにのみ、**遅延してクローン**されます。
4. 指摘は引き続き、**レビュー対象の PR の行にのみアンカー**されます。リンク先のコードは根拠であり、2 つ目のレビュー対象ではありません。

リンクが設定されていない場合、この機能は完全にオフです（追加コストなし）。

## ダッシュボードでの設定

リンクリポジトリは**リポジトリごと**であり、グローバルではありません。関係には方向があります。`frontend` に設定したリンクは、`frontend` の PR をレビューするときにのみ適用されます。

1. サイドバーの **Code review** グループ上部にあるスコープピッカーで、**特定のリポジトリ**を選択します（Global ではありません）。
2. **Linked repositories** を開きます（リポジトリスコープでのみ表示されます）。
3. **Add repository** をクリックし、組織にすでに接続されている兄弟リポジトリを選択します。
4. 必要に応じて、リンクをクリックして次を設定します。
   - **Instructions · optional** — Kody へのフリーテキストのヒント（例：「このフロントエンドが利用する REST API」）。
   - **Branch / ref pin · optional** — ブランチ/タグの固定。空のままにすると、自動の ref カスケード（下記）を使用します。
5. **Save settings** をクリックします。

リンクできるリポジトリは最大 **3 つ**です。同じ組織にすでに接続されているリポジトリのみ受け付けられます。

## `kodus-config.yml` での設定

リポジトリの設定ファイルでもリンクを宣言できます。

```yaml
linkedRepositories:
  - repository: "org/backend-api"
    instructions: "REST API this frontend consumes"
    ref: main   # optional pin; omit for same-branch cascade
```

- `repository`（必須）：組織に接続されているリポジトリのフルネーム（`owner/repo`）。
- `instructions`（任意）：リンクが存在する理由の短い説明。
- `ref`（任意）：ブランチ、タグ、コミットを固定します。省略すると、Kody は ref カスケードを使用します。

空の `linkedRepositories: []` は、機能がオフであることを意味します。このファイルは、リポジトリで **Prefer kodus-config.yml settings**（**Code review → General**）がオンの場合にのみ読み取られ、そのリストは Web アプリで設定したリストを置き換えます。[設定リファレンス](/ja/how_to_use/code_review/configs/linked_repositories#kodus-config-yml-で)を参照してください。

## ref の選ばれ方

リンクされたリポジトリごとに、Kody は次の順序で ref を試し、最初にクローンに成功したものを使用します。

1. そのリポジトリに対する **PR の説明による上書き**（下記参照）
2. **設定の `ref` による固定**（設定されている場合）
3. ヘッドブランチが PR のヘッドブランチと一致する、リンク先リポジトリの**オープン中の PR**
4. リンク先リポジトリにある **PR のヘッドブランチ名**
5. リンク先リポジトリの**デフォルトブランチ**
6. フォールバック：`main`、次に `master`

これにより、サービス間で同じブランチ名が存在する場合は複数リポジトリにまたがる機能開発の足並みが揃い、通常の PR では安全にフォールバックされます。

## PR の説明から ref を上書きする

1 回限りのレビュー（たとえば、特定のバックエンドの PR に対してレビューする場合）では、レビュー対象の PR の**タイトルまたは説明**でリンク先のリポジトリに言及します。上書きは、設定ですでに**リンクされている**リポジトリにのみ適用されます。

サポートされる形式：

| 形式 | 意味 |
| --- | --- |
| `owner/repo#123` | そのリポジトリの PR/MR `#123` のヘッドを使用する |
| PR/MR の URL | 上記と同じ。`github.com`、`bitbucket.org`、`dev.azure.com`、または名前に `gitlab` を含むホストの URL が対象 |
| `owner/repo@branch` | リンク先リポジトリでそのブランチを固定する |

例：

```text
Depends on org/backend-api#842
Also needs org/shared-contracts@feature/new-events
```

リンクされた各リポジトリへの言及は 1 回にしてください。複数の言及がある場合、`owner/repo@branch` による固定は、どこに書かれていても PR の参照より優先され、同じ形式の言及が複数ある場合は最後のものが優先されます。リンクされていないリポジトリへの言及は無視されます（新しいリンクは作成されません）。

## クロスレポのコンテキストが有効になるとき（境界ゲート）

リンクを設定していても、Kody が兄弟リポジトリを常に開くわけではありません。低コストで決定論的なゲートが PR の diff の**追加された行**をスキャンし、次のような**境界となる部分**を見つけた場合にのみ有効になります。

- 文字列リテラル（パスのセグメント、コード、イベント名など）
- エクスポート（`export function`、型、クラスなど）
- Enum / 型 / インターフェース
- オブジェクトやペイロードのフィールドキー
- ステータス / 状態 / エラーコード形式の識別子
- コントラクトらしいファイルパス（`dto`、`schema`、`api`、`client`、`openapi`、`proto` など）

境界ではないコードを移動または整形するだけの内部リファクタリングでは、通常ゲートはオフのままになるため、クローンや境界用プロンプトは起動しません。

## Kody がリンクリポジトリでできること、できないこと

**できること：**

- ゲートがオンのとき、リンクされたリポジトリのファイルを検索して読み取る
- **instructions** を使って関係を理解する
- 現在の PR に対する指摘で、リンク先のコードを裏付けの根拠として引用する

**できないこと / しないこと：**

- リンクされたリポジトリにのみ存在するファイルにレビューコメントを投稿する
- リンクされたリポジトリ全体を PR であるかのようにレビューする
- 組織外の、または Kodus に接続されていないリポジトリをリンクする
- レビュー対象のリポジトリごとに 3 つを超えるリンクリポジトリを使用する（`kodus-config.yml` では、3 つ目以降のエントリは破棄されます）

## レビューに表示される内容

Kody がリンクされたリポジトリを読み取った場合、レビュー終了時に投稿されるコメントに **Additional context used:** が含まれ、読み取ったリポジトリと ref（例：`org/backend-api@main`、または使用したオープン中の PR）が示されます。この行がない場合、リンクされたリポジトリは読み取られていません。取得できないリンクや、組織に接続されていないリンクはスキップされ、レビューはそれなしで続行されます。

## 推奨される構成

| シナリオ | リンク元 | 一般的な instructions |
| --- | --- | --- |
| フロントエンド ↔ バックエンド | フロントエンド → バックエンド API のリポジトリ | 「この UI が依存する HTTP/REST クライアントのコントラクト」 |
| サービス ↔ 共有コントラクト | サービス → コントラクト/パッケージのリポジトリ | 「共有のイベント、DTO、protobuf」 |
| BFF ↔ 複数のバックエンド | BFF → 最大 3 つのバックエンドのリポジトリ | サービスの境界ごとに短い 1 行 |

すべてのリポジトリを互いにリンクするよりも、**範囲を絞った方向のある**リンク（利用側が提供側を指す）を推奨します。
