---
title: "Google Docs の仕様に対してコードを確認する方法"
description: "Google Docs に書かれた仕様に対して、Pull Request の実装を検証します。"
---

製品の仕様や要件は Google Docs に書かれていることがよくあります。Google Docs は、Linear、Jira、Notion、Git Issues、カスタムプラグインからタスクを読み取る Business Logic Validation の組み込みのタスクソースではありません。コマンドに Google Docs のリンクを含めても読み取られません。

Google Docs の仕様に対して PR を確認する方法は 2 つあります。

## コマンドに要件を貼り付ける

ドキュメントから要件をコピーし、PR にコメントします。

```
@kody -v business-logic
## Requirements
1. Users with role "admin" can delete any comment
2. Users can only edit their own comments within 24 hours
3. Deleted comments show "[removed]" placeholder
```

Kody は、書いたテキストに対して PR を確認します。トラッカーは不要ですが、テキストは 40 文字以上である必要があります。結果は PR への 1 件のコメント **Kody · Business Logic** で、各要件に **MET**、**PARTIAL**、**MISSING**、**CHECK MANUALLY**、**NOT IN TASK** のいずれかが付きます。

## 要件をタスクに保存する

要件を、トラッカーのタスクの説明に `Acceptance criteria` などの見出しの下にコピーし、PR のタイトル、ブランチ、説明にそのタスクを記載します。すると Kody は、コマンドなしで、そのタスクを参照するすべての PR を確認します。基準が見出しの下やカスタムフィールドにある場合は、Business Logic の設定で **Requirements → Where acceptance criteria live** を設定します。Notion のページはタスクとして使えます。その URL を PR に記載してください。

## ヒント

- 仕様は、明確なセクションと番号付きの要件で構造化しておきます。
- 大きなドキュメントはセクションに分け、1 つずつ確認すると、より焦点の絞られたフィードバックが得られます。
- 不足を修正したら、もう一度 `@kody -v business-logic` とコメントします。同じコメントが更新されます。

詳細については、[Business Logic Validation](/ja/how_to_use/code_review/business_logic_validation) を参照してください。
