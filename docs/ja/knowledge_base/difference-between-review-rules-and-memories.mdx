---
title: "レビュールールとメモリの違いとは"
description: "最良のコードレビュー結果を得るために、Kody でレビュールールとメモリをどう使い分けるかを理解します。"
---

Kody Rules の UI では 2 つの異なるものを設定します。どちらをいつ使うかを理解すると、コードレビューはより効果的になります。

実用的な目安は次のとおりです。

- **メモリ** は、今後のレビューや提案がより的確になるように、Kody にコードベースの仕組みを教えます。
- **レビュールール** は、PR がチームの基準に合っていないときに Kody が何を指摘すべきかを定義します。

## レビュールール

レビュールールは、コードレビュー中に実行される**チェック**です。各ルールはファイルの diff または PR 全体に適用され、変更がそれに違反すると Kody が提案を報告します。

**最適な用途：**
- アーキテクチャの境界（「ドメイン層はインフラストラクチャをインポートしてはいけません」）
- コードパターン（「ループ条件で `==` を使用しないでください」）
- PR の要件（「すべてのサービスファイルにはテストが必要です」）
- PR の説明やサイズなど、PR 自体に関する要件

**動作方法：**
- ファイルごとまたは PR ごとに実行されます（ルールの **Execution mode**）
- コードレビュー中にのみ実行されます
- `@file:path/to/file` でリポジトリ内のファイルを指定できます
- 重要度レベルを持つ提案を生成します
- パスを限定でき、Rules Library から追加できます

## メモリ

メモリは、コードレビューや Kody との会話で Kody が使用する**永続的なコンテキスト指示**です。Kody がコードベース、規約、好みについて保持しておくべき背景知識を表します。

**最適な用途：**
- コードベースの文脈（「このリポジトリはサードパーティ API を反映しているため、一部の外部ペイロードフィールドは意図的に snake_case のままです」）
- 提案の好み（「ここで JS ユーティリティを提案するなら、Lodash よりネイティブメソッドを優先します」）
- 移行の文脈（「課金モジュールは移行の途中なので、大規模なリファクタより段階的な修正を優先します」）
- アーキテクチャの文脈（「このサービスはヘキサゴナルアーキテクチャを採用し、アダプターは境界に置きます」）

**動作方法：**
- 高優先度のコンテキストとして、コードレビューと会話に追加されます
- リポジトリ固有の文脈を Kody に与えることで、今後の提案を改善します
- 会話（`@kody remember: ...`）で作成するか、**Code review → Kody Rules** の **Memories** タブで **New memory** を使って手動で作成します
- ディレクトリ、リポジトリ、または組織レベルにスコープを設定できます
- Kody は新しいメモリを保存する前に既存のメモリを確認し、重複はスキップするか、既存のメモリを更新します

## どちらを使うか

| シナリオ | 使用するもの |
|----------|-----|
| すべてのサービスにテストファイルが存在するか確認する | レビュールール |
| 「このリポジトリは外部 API を反映しているため、一部のレスポンスフィールドは意図的に snake_case のままです」 | メモリ |
| PR の説明がテンプレートに従う必要がある | レビュールール |
| 「このサービスのテストは、中央の test フォルダではなく実装ファイルの隣に置くのが通常です」 | メモリ |
| アーキテクチャ層に違反する import を指摘する | レビュールール |
| 「認証モジュールは移行の途中なので、大規模なリファクタより段階的な変更を優先します」 | メモリ |

## 相互に変換できますか？

直接はできません。アプリに変換のアクションはありません。保留中のメモリは **Code review → Kody Rules** の **Pending review** セクションに表示され、そこで **Approve** または **Discard** できます。メモリに、ファイルパスと重要度レベルを使ったより構造化された適用が必要な場合は、**Review Rules** タブの **New rule** でレビュールールを作成し、メモリを削除または破棄してください。

詳細については、[Kody Rules](/ja/how_to_use/code_review/configs/kody_rules) を参照してください。
