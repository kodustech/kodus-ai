---
title: "コードレビューに独自の LLM プロバイダーを使用できますか"
description: "独自の API キーを持ち込み、Kodus での AI コードレビューに好みの LLM プロバイダーを選択します。"
---

はい。Kodus はすべてのプランで Bring Your Own Key（BYOK）をサポートしており、好みの LLM プロバイダーを使用できます。トークンの料金はプロバイダーから直接請求され、キーは暗号化されて保存され、平文で再表示されることはありません。

## 使い方

1. サイドバーで **AI providers** を開きます（[app.kodus.io/byok](https://app.kodus.io/byok)）
2. **Providers** タブでプロバイダーを選びます。その他のエンドポイントには **Custom** の下の **OpenAI-compatible** / **Anthropic-compatible** を選びます
3. API キーを貼り付けてモデルを選び、**Test & save** をクリックします。Kodus は保存前に、モデルへ最小限の実リクエストを送信します

## サポートされているプロバイダー

グリッドの **Providers** セクションには、Anthropic、OpenAI、Google、OpenRouter、Novita、Moonshot、Z.ai などの主要プロバイダーが並びます。**Custom** セクションは、Kodus の接続先を自分で指定するエンドポイントを扱います：OpenAI-compatible、Anthropic-compatible、Google Vertex AI、Amazon Bedrock、Azure OpenAI。

Kodus がプロバイダーのモデル一覧を取得できる場合、**Model** ピッカーにそれらが表示されます（推奨モデルが先頭に並び、**Type model manually** もあります）。取得できない場合は、正確なモデル ID を入力します。Thinking/reasoning、temperature、トークン上限、最大同時リクエスト数は **Advanced (optional)** にあります。

## 独自のプロバイダーを使用する理由

- **データ管理** — リクエストはプロバイダーに直接送信されます
- **コスト管理** — プロバイダーとの既存の請求関係を利用できます
- **モデル選択** — コードベースに最適なモデルを選べます
- **コンプライアンス** — AI ツールの使用に関する社内要件を満たせます
- **フォールバックによる耐障害性** — **Code review → Routing** で **Fallback model** を設定すると、プロバイダー障害中もレビューを継続できます

## その他のエンドポイントとセルフホストのエンドポイント

**OpenAI-compatible** と **Anthropic-compatible** プロバイダーを使うと、BYOK を次のようなホスト型またはセルフホストのエンドポイントに向けられます。

- Groq、Together AI、Fireworks AI
- Chutes、Synthetic
- 独自の Ollama / vLLM / TGI インスタンス（**OpenAI-compatible** プロバイダー経由）

ベース URL は `https://` を使用し、パブリックなアドレスに解決される必要があります。セルフホストの Kodus では、プライベートネットワーク上のエンドポイントは代わりに環境変数で設定します。[インストール](/ja/how_to_deploy/deploy_kodus/generic_vm)を参照してください。

セットアップガイドについては、[クックブック](/ja/cookbook/fireworks)のプロバイダーページを参照してください。

完全な BYOK フロー（プロバイダー、ルーティング、高度なチューニング）については、[Bring Your Own Key](/ja/how_to_use/byok) を参照してください。
