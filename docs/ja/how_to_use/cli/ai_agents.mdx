---
title: "AIエージェント"
description: "Kodus CLI を AI コーディングエージェントと統合して、自律的なレビュー・修正ループを実現します。"
---

CLI には、AI コーディングエージェントが解析して行動するための、最小限の構造化出力モード（`--prompt-only`）が用意されています。チームキーと組み合わせると、エージェントは人間が介在することなく、自分の変更をレビューし、指摘された点を修正して、再度レビューできます。また CLI は、お使いのマシン上のエージェントに Kodus のスキルをインストールするため、エージェントはどのコマンドを実行すべきかを把握できます。

## 対応エージェント

`kodus skills install` は、カレントディレクトリとホームフォルダにあるエージェントの設定フォルダを手がかりにエージェントを検出し、そこに Kodus のスキルを書き込みます。検出対象は次のとおりです。

| エージェント         | 設定フォルダ                                      |
| ------------- | -------------------------------------------------- |
| Claude Code   | `.claude`, `~/.claude`, `~/.config/claude`         |
| Cursor        | `.cursor`, `~/.cursor`                             |
| Codex         | `.codex`, `~/.codex`                               |
| Windsurf      | `.windsurf`, `~/.codeium/windsurf`                 |
| Gemini        | `.gemini`                                          |
| Antigravity   | `.agent`, `~/.gemini/antigravity`                  |
| OpenCode      | `.opencode`, `~/.config/opencode`                  |
| Kiro          | `.kiro`, `~/.kiro`                                 |
| Goose         | `.goose`, `~/.config/goose`                        |
| Roo Code      | `.roo`, `~/.roo`                                   |
| Kilo Code     | `.kilocode`, `~/.kilocode`                         |
| Droid         | `.factory`, `~/.factory`                           |
| AiderDesk     | `.aider-desk`, `~/.aider-desk`                     |
| その他のエージェント  | `.agents`, `~/.agents`, `~/.config/agents`         |

シェルコマンドを実行してテキストを読み取れるその他のエージェントでは、スキルなしでも `kodus review --prompt-only` が動作します。

## 最速のセットアップ

CLI とスキルを一度にインストールします。

```bash
curl -fsSL https://review-skill.com/install | bash -s -- --team-key kodus_xxxxx
```

このコマンドは次の処理を行います。

1. npm で `@kodus/cli` をグローバルにインストールします。
2. `kodus auth team-key` でチームキーを適用し、`~/.kodus/config.json` に保存します。
3. `kodus skills install` を実行し、検出されたすべてのエージェントにスキルを追加します。

個別のログインやインタラクティブなプロンプトは不要です。スキルを後から追加または更新するには、`kodus skills install` または `kodus skills resync` を実行します。

## スキル

| スキル                             | エージェントがスキルでできること                                                      |
| --------------------------------- | ---------------------------------------------------------------------------------- |
| `kodus-review`                    | `kodus review --prompt-only` でローカルの変更をレビューし、指摘された点を修正する       |
| `kodus-pr-suggestions-resolver`   | プルリクエストの提案を取得し、妥当なものを適用して、そのレビュー履歴を読む |
| `kodus-business-rules-validation` | ローカルの変更をタスクの受け入れ基準に照らして確認する                           |
| `kodus-kody-rules`                | Kody Rules を表示、作成、更新、一時停止、再開、削除する                         |
| `kodus-review-settings`           | コードレビューの設定とレビューモデルを表示、変更する                          |
| `kodus-custom-agents`             | カスタムエージェントを一覧表示、作成、編集、オン/オフの切り替え、削除、試行する                  |
| `kodus-cockpit-usage`             | Cockpit のメトリクスとトークン使用量を読む                                               |
| `kodus-centralized-config`        | 集中設定を確認、有効化、同期、ダウンロードする                           |
| `kodus-trace`                     | 変更しようとしているコードについて記録された判断を読む                     |

ルール、設定、エージェントを変更するスキルには、ログイン、またはそれを許可するチームキーが必要です。[認証モード](/ja/how_to_use/cli/concepts#認証モード)を参照してください。

## レビュー・修正ループ

<Steps>
  <Step title="エージェントがレビューを実行する">
    ```bash
    kodus review --prompt-only
    ```

    CLI は、ファイルパス、行番号、重要度、提案された修正を含む構造化された問題を、LLM 向けのコンパクトなテキスト形式で返します。出力は `REVIEW_ANALYSIS_COMPLETE` で始まり、`END_REVIEW` で終わります。
  </Step>
  <Step title="エージェントが修正を適用する">
    エージェントは出力を読み取り、どの修正を適用するかを判断して、ファイルを編集します。誤検知をスキップしても問題ありません。その場合、エージェントは理由を説明する必要があります。
  </Step>
  <Step title="エージェントが再度レビューを実行する">
    ```bash
    kodus review --prompt-only --fail-on error
    ```

    `--fail-on error` を指定すると、エラーレベル以上の問題が残っている間、コマンドは終了コード 1 で終了します。レビューがクリーンになると `NO_ISSUES_FOUND` が出力されて終了コード 0 で終了し、エージェントは次に進みます。
  </Step>
  <Step title="エージェントがコミットしてプッシュする">
    レビューがクリーンになったら、エージェントはコミットしてプッシュします。オプションで、手動でプッシュする場合のセーフティネットとして、pre-push フックをインストールできます（`kodus hook install`）。
  </Step>
</Steps>

<Note>
  `--fix` はターミナルで確認を求めるため、無人で動作するエージェントは、代わりに自分で修正を適用する必要があります。
</Note>

## エージェント用のチームキー認証

エージェントにはチームキーを強く推奨します。個別のサインアップもインタラクティブなログインも不要で、ローテーションが簡単で、デバイスごとに追跡できます。

```bash
export KODUS_TEAM_KEY=kodus_xxxxx
kodus review --prompt-only
```

**Organization → CLI keys**（<a href="https://app.kodus.io/organization/cli-keys" target="_blank">app.kodus.io/organization/cli-keys</a>）でキーを生成し、新しいキーとともに表示されるインストールコマンドをチームに配布してください。

<Warning>キーは表示されたときに保存してください。再表示されません。</Warning>

## 重要な出力フラグ

| フラグ             | 用途                                                                 |
| ---------------- | ------------------------------------------------------------------- |
| `--prompt-only`  | 解析用のコンパクトな構造化出力。レビューループで使用します。`kodus review` のみ |
| `--agent`        | 1 つの JSON エンベロープ（`ok`、`command`、`data`、`error`、`meta`）。すべてのコマンドが対応しているわけではありません。[グローバルフラグ](/ja/how_to_use/cli/commands#グローバルフラグ)を参照してください |
| `--format json`  | `review` と `pr` の完全な JSON ペイロード                             |
| `--fail-on`      | 終了コードのゲート。指定した重要度に該当する問題がある場合に 1 を返します                  |
| `--fields <csv>` | JSON ペイロードを絞り込みます（例：`summary,issues.file,issues.severity`）。エージェントのコンテキストを小さく保てます。`--format json` または `--agent` が必要です |

その他のコマンドは `--json` を受け付けます。`kodus schema` は、すべてのコマンドとフラグを JSON で出力します。何が存在するかを確認する必要があるエージェント向けです。

## 例：ビジネス検証を含む Claude Code のループ

```bash
# In a Claude Code session, the agent can run:
kodus review --prompt-only --fail-on error                      # general review
kodus pr business-validation --task-id KC-1441 --format json    # check against the task
kodus review --prompt-only --fail-on error                      # re-run after fixes
git commit -am "fix: KC-1441 address review findings"
```

スキルをインストールしておけば、エージェントはこれらをいつ実行すべきかを把握しています。

## エージェントの判断を記録する

`kodus trace enable` は、Claude Code、Cursor、Codex 向けに各セッションを記録するフックを追加します。これにより、エージェントが変更を加えた理由が保持され、パスを指定して読み返せます。[Kodus Trace](/ja/how_to_use/cli/trace) を参照してください。
