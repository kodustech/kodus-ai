---
title: "セルフホストセットアップ"
description: "Kodus CLI をセルフホスト型の Kodus インスタンスに接続します。"
---

独自のインフラで Kodus を実行している場合も、CLI は同じように動作します。API の接続先を指定するだけです。

## インスタンスへの接続

<Steps>
  <Step title="API URL を設定">
    Kodus API の場所を CLI に伝えます。方法を1つ選択してください。

    <Tabs>
      <Tab title="環境変数（推奨）">
        ```bash
        export KODUS_API_URL=https://kodus-api.yourcompany.com
        ```

        永続化するには、シェルプロファイル（`~/.bashrc`、`~/.zshrc` など）に追加します。

        ```bash
        echo 'export KODUS_API_URL=https://kodus-api.yourcompany.com' >> ~/.zshrc
        source ~/.zshrc
        ```
      </Tab>
      <Tab title="設定ファイル">
        `~/.kodus/config.json` を作成または編集します。

        ```json
        {
          "apiUrl": "https://kodus-api.yourcompany.com",
          "teamKey": "kodus_xxxxx",
          "teamName": "Your Team",
          "organizationName": "Your Org"
        }
        ```

        CLI は `kodus auth team-key` を実行したときにこのファイルを自動的に作成し、すでに含まれている `apiUrl` はそのまま保持します。手動で作成することもできます。

        <Warning>
          `kodus auth login` と `kodus auth logout` は、`apiUrl` を含めてこのファイルを削除します。ログインでサインインする場合は、代わりに環境変数を使用してください。
        </Warning>
      </Tab>
      <Tab title="インライン（一回限り）">
        ```bash
        KODUS_API_URL=https://kodus-api.yourcompany.com kodus review
        ```
      </Tab>
    </Tabs>

    <Warning>
      **HTTPS が必要です。** CLI はセキュリティ上の理由から、HTTPS 以外の URL を拒否します。唯一の例外は、ローカル開発用の `localhost` と `127.0.0.1` です。
    </Warning>

    **優先順位:** `KODUS_API_URL` 環境変数 > `~/.kodus/config.json` の apiUrl > デフォルト（`https://api.kodus.io`）。
  </Step>

  <Step title="認証">
    <Tabs>
      <Tab title="チームキー（推奨）">
        セルフホスト版の Kodus Web アプリで **Organization → CLI keys** を開き、チームキーを生成します。CLI を実行するシェルで、環境変数 `KODUS_TEAM_KEY` にキーを設定します。

        <Tip>チームキーは共有環境や AI エージェントのセットアップに最適です。個別のログインは不要です。</Tip>
      </Tab>
      <Tab title="個人ログイン">
        ```bash
        kodus auth login
        ```

        CLI がセルフホスト型 Web アプリの **Authorize Kodus CLI** ページを開きます。インスタンスに登録されたアカウントでサインインし（サインイン後はダッシュボードに移動するため、CLI が出力した URL をもう一度開いてください）、**Authorize CLI** をクリックします。ブラウザーのないマシンでは、他の人と共有していないターミナルで `kodus auth login --device-code` を実行します。CLI にインスタンスの認証 URL とワンタイムコードが表示されます。ブラウザーのアドレスバーで URL に `code` クエリパラメーターとしてコードを追加し、**Authorize CLI** をクリックします。コードやコード付きの URL は、ログや共有メッセージに含めないでください。

        ログイン情報は、制限されたパーミッション（600）で `~/.kodus/credentials.json` に保存されます。

        <Info>
          そのページのアドレスは、Kodus API の `API_FRONTEND_URL` 設定から取得されます。Web アプリの URL を指定する必要があります。そうでないと、ログインページが誤ったホストで開きます。
        </Info>

        CI では、チームキーをシークレット `KODUS_TEAM_KEY` に設定します。
      </Tab>
    </Tabs>
  </Step>

  <Step title="接続を確認">
    ```bash
    kodus status
    ```

    `kodus status` はローカルで検出した認証方法を表示します。API の URL を確認するには、API を呼び出すコマンドに `--verbose` を追加します。たとえば、リポジトリの設定を許可されたチームキーを使う場合は、次を実行します。

    ```bash
    kodus config remote list --verbose
    ```
  </Step>
</Steps>

## Cloudflare Access（Zero Trust）

セルフホスト型 API が [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/applications/) の背後にある場合、CLI はサービストークン認証をサポートします。

<Tabs>
  <Tab title="環境変数">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export CF_ACCESS_CLIENT_ID=your-client-id.access
    export CF_ACCESS_CLIENT_SECRET=your-client-secret
    ```
  </Tab>
  <Tab title="設定ファイル">
    ```json
    {
      "apiUrl": "https://kodus-api.yourcompany.com",
      "teamKey": "kodus_xxxxx",
      "cfAccessClientId": "your-client-id.access",
      "cfAccessClientSecret": "your-client-secret"
    }
    ```
  </Tab>
</Tabs>

クライアント ID とシークレットの両方が設定されている場合、CLI はすべての API リクエストで `CF-Access-Client-Id` と `CF-Access-Client-Secret` ヘッダーを送信します。優先順位: 環境変数 > 設定ファイル。

## 設定ファイルリファレンス

CLI は `~/.kodus/config.json` に設定を保存します。

```json
{
  "apiUrl": "https://kodus-api.yourcompany.com",
  "teamKey": "kodus_xxxxx",
  "teamName": "Engineering",
  "organizationName": "Acme Corp",
  "cfAccessClientId": "your-client-id.access",
  "cfAccessClientSecret": "your-client-secret"
}
```

| フィールド | 必須 | 説明 |
|-----------|------|------|
| `apiUrl` | いいえ | セルフホスト型 API の URL。`KODUS_API_URL` 環境変数で上書きされます。 |
| `teamKey` | いいえ | チームの API キー（`kodus_` で始まる）。`KODUS_TEAM_KEY` 環境変数で上書きされます。 |
| `teamName` | いいえ | チームの表示名。 |
| `organizationName` | いいえ | 組織の表示名。 |
| `cfAccessClientId` | いいえ | Cloudflare Access クライアント ID。`CF_ACCESS_CLIENT_ID` 環境変数で上書きされます。 |
| `cfAccessClientSecret` | いいえ | Cloudflare Access クライアントシークレット。`CF_ACCESS_CLIENT_SECRET` 環境変数で上書きされます。 |

<Info>
  設定ファイルは `0600` パーミッション（所有者のみ読み取り/書き込み可）で作成されます。ディレクトリ `~/.kodus/` は `0700` パーミッションで作成されます。
</Info>

## 環境変数のまとめ

| 変数 | 説明 |
|------|------|
| `KODUS_API_URL` | セルフホスト型 API のエンドポイント（localhost を除き HTTPS 必須） |
| `KODUS_APP_URL` | `kodus config remote open` が指す Web アプリの URL（デフォルト `https://app.kodus.io`） |
| `KODUS_TEAM_KEY` | 共有アクセス用のチームキー |
| `KODUS_TOKEN` | ログインのアクセストークン。そのまま使用され、更新されません。他のすべての認証情報より優先されます。CI ではチームキーを使用してください |
| `CF_ACCESS_CLIENT_ID` | Cloudflare Access クライアント ID |
| `CF_ACCESS_CLIENT_SECRET` | Cloudflare Access クライアントシークレット |
| `KODUS_REQUEST_TIMEOUT_MIN` | 各 API リクエストのタイムアウト（分）（デフォルト `60`） |
| `KODUS_DISABLE_UPDATE_CHECK` | `1` に設定すると、更新の通知をオフにします |

## CI/CD 統合

CI/CD パイプラインでセルフホスト型インスタンスを使用する場合は、API URL とチームキーを環境変数として設定します。新規チェックアウトにはコミットされていない変更がないため、`--branch` でブランチをベースと比較してレビューします。ベースブランチがチェックアウトに存在する必要があるため、履歴全体を取得してください。

<Tabs>
  <Tab title="GitHub Actions">
    ```yaml
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0
    - name: Kodus Review
      env:
        KODUS_API_URL: ${{ secrets.KODUS_API_URL }}
        KODUS_TEAM_KEY: ${{ secrets.KODUS_TEAM_KEY }}
      run: npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
  <Tab title="GitLab CI">
    ```yaml
    kodus-review:
      variables:
        GIT_DEPTH: "0"
      script:
        - git fetch origin main
        - npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```

    プロジェクト設定の CI/CD 変数として `KODUS_API_URL` と `KODUS_TEAM_KEY` を追加します。
  </Tab>
  <Tab title="汎用">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export KODUS_TEAM_KEY=kodus_xxxxx
    npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
</Tabs>

<Tip>
  重大度のしきい値を超える問題が見つかったときにパイプラインを失敗させるには、`--fail-on error` または `--fail-on critical` を使用してください。プルリクエストは Git 連携によってレビューされるため、パイプラインのジョブは不要です。
</Tip>

## チームへの配布

[CLI のインストール手順](/ja/how_to_use/cli/getting_started)とセルフホスト API の URL をチームに共有します。各自がシェルプロファイルに `KODUS_API_URL` を設定するか、`~/.kodus/config.json` に `apiUrl` を設定します。チームキーはシークレット管理ツールで配布し、CLI を使う前に `KODUS_TEAM_KEY` に設定します。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="セキュリティエラー: API URL は HTTPS プロトコルを使用する必要があります">
    CLI は、localhost 以外のすべての URL に HTTPS を要求します。その後デフォルトの `https://api.kodus.io` にフォールバックするため、認証する前にメッセージを確認してください。セルフホスト型インスタンスに有効な TLS 証明書があることを確認してください。ローカルでテストしている場合は、代わりに `http://localhost:<port>` を使用してください。
  </Accordion>

  <Accordion title="接続拒否またはタイムアウト">
    - URL に到達できることを確認します: `curl -I https://kodus-api.yourcompany.com`
    - ファイアウォールや VPN が接続をブロックしていないか確認します
    - Cloudflare Access の背後にある場合は、`CF_ACCESS_CLIENT_ID` と `CF_ACCESS_CLIENT_SECRET` が設定されていることを確認します
    - `--verbose` を使用して、実際に使用されている URL を確認します
  </Accordion>

  <Accordion title="認証失敗（401）">
    - `kodus status` を実行して、現在の認証状態を確認します
    - チームキーを使用している場合は、セルフホスト型 Web アプリの **Organization → CLI keys** で、まだ **Active** であることを確認します
    - 個人ログインを使用している場合、CLI はログインを自動的に更新します。更新に失敗した場合は、もう一度 `kodus auth login` を実行してください
    - `KODUS_API_URL` が正しいインスタンスを指していることを確認します
  </Accordion>

  <Accordion title="API が無効なレスポンスを返した（JSON が期待されたが HTML が返された）">
    これは通常、URL が実際の API ではなく、リバースプロキシ、ロードバランサー、または Cloudflare Access のページに到達していることを意味します。次を確認してください。
    - URL のパスが正しいこと（末尾に `/api` などが付いていないこと）
    - 該当する場合は、Cloudflare Access の認証情報が設定されていること
    - リバースプロキシがリクエストを正しく転送していること
  </Accordion>

  <Accordion title="デバイス制限に達しました">
    セルフホスト型インスタンスでは、組織ごとにデバイス数の上限が適用されている場合があります。Web アプリには整理できるデバイス一覧がないため、上限を引き上げるよう管理者に連絡してください（API の `CLI_DEVICE_LIMIT` 設定。デフォルトの `0` は無制限を意味します）。
  </Accordion>
</AccordionGroup>
