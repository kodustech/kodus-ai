## Kodus とは

**Kody** は GitHub、GitLab、Bitbucket、Azure Repos、Forgejo のプルリクエストをレビューし、変更がチームのルールに沿っているかチェックします。Kodus はオープンソースで、自社インフラにも導入できます。

## Kodus にできること

- [レビュー結果を読む](/ja/how_to_use/code_review/flow#得られるもの)。Kody が PR に投稿する内容と、再レビューの依頼方法を確認します。
- [レビュー対象を調整する](/ja/how_to_use/code_review/configs/what_to_review)。カテゴリ、重大度の下限、チェック対象を選びます。
- [チームの基準を Kody に教える](/ja/how_to_use/code_review/configs/kody_rules)。ルールとメモリを使って、チームの規約をレビューに適用します。
- [PR がタスクを満たすか確認する](/ja/how_to_use/code_review/business_logic_validation)。実装をタスク管理ツールの要件と照合します。

## レビューを拡張し、結果を追跡する

- [カスタムエージェント](/ja/how_to_use/code_review/custom_agents)。専用の指示、ガイド、ツールを持つレビュアーを追加します。
- [プラグイン](/ja/how_to_use/code_review/plugins)。タスク管理ツールなどの外部ツールをレビューのコンテキストに使います。
- [Cockpit](/ja/how_to_use/cockpit/overview)。レビューの有効性とデリバリーの指標を確認します。
- [Kody Issues](/ja/how_to_use/issues/overview)。PR が閉じた後も未解決のレビュー提案を追跡します。

## ワークスペースを設定する

- [AI プロバイダー](/ja/how_to_use/byok)。自分のキーを接続し、モデルを選びます。
- [ロールと権限](/ja/how_to_use/workspace_roles)。設定やリポジトリを管理できるユーザーを決めます。
- [プランとライセンス](/ja/how_to_use/pricing)。プランごとの機能、トライアルの上限、開発者ライセンスを確認します。
- [セルフホストのインストール](/ja/how_to_deploy/deploy_kodus/generic_vm)。自社インフラで Kodus を実行します。

## 対応言語

Kody は、セマンティック（LLM）分析により、あらゆるプログラミング言語やファイルタイプにそのまま対応します。分析は、精密でリポジトリ全体にわたるコンテキストを得るためのコード検索（grep スタイル）に支えられています。
