プラグインは、ワークスペースに接続されたリモートの Model Context Protocol（MCP）サーバーです。チケットトラッカー、Wiki、エラーモニターなどが該当します。Kody はそこから読み取り、依頼されたときだけ操作を行います。

| 場所 | 動作 |
| --- | --- |
| `@kody` をメンションしたコメント | Kody はインストール済みのプラグインを呼び出し、同じスレッドで返信します。チケットの移動やルールの編集など、何かを変更するのは、コメントで求められたときだけです。 |
| [ビジネスロジック検証](/ja/how_to_use/code_review/business_logic_validation) | Kody は、プルリクエストが参照するタスクをトラッカーから読み取ります。 |
| [カスタムエージェント](/ja/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp) | エージェントは、そのエージェント用にオンにしたプラグインから読み取ります。読み取りツールのみです。 |

## Plugins ページ

サイドバーで **Plugins** を開きます。プラグインをインストールまたは変更できるのはオーナーだけです。Billing Manager、Repo Admin、Contributor は閲覧できます。各カードにはプラグインが表示され、接続後は **Installed**、**Default**、**Locked** のいずれかが表示されます。セルフホスト環境では、このページに [MCP Manager](/ja/how_to_deploy/deploy_kodus/mcp_manager) が必要です。

| プラグイン | Kody が読み取れるもの | サインイン |
| --- | --- | --- |
| **Git Issues** | リポジトリのトラッカー（GitHub、GitLab、Bitbucket、Forgejo）の Issue。Git 接続を通じて読み取ります | なし |
| **Linear** | Issue、プロジェクト、サイクル | OAuth または API キー |
| **Atlassian Rovo** | Jira と Confluence | OAuth または API トークン |
| **Notion** | ページ、データベース、ドキュメント | OAuth |
| **Sentry** | プロジェクト、Issue、イベント | OAuth |
| **Fireflies** | 会議の文字起こし、サマリー、アクションアイテム | API キー |
| **Kodus Docs** | Kodus のドキュメント | なし |
| **Exa Search** | Web 検索とコード検索 | なし |
| **Kodus OSV** | パッケージの既知の脆弱性 | なし |

**Kodus MCP** はすべてのワークスペースに接続されています（**Default**）。Git プロバイダーからリポジトリ、プルリクエスト、コミット、ファイル、差分を読み取り、Kody Rules、メモリ、Kody の Issue を管理します。常にオンで、以下の Free プランの上限にはカウントされません。

## プラグインをインストールする

<Steps>
  <Step title="プラグインを開く">
    カードをクリックします。
  </Step>
  <Step title="接続する">
    サインインが必要なプラグインでは、最初にサインインを求められます。プラグインの **Authenticate with** をクリックするか（OAuth）、フィールドに入力して **Connect** をクリックします（API キーまたはトークン）。接続するとすぐにインストールされます。Kody は、プラグインが読み取り専用とマークしたツールから始めます。マークされたツールがない場合は、すべてのツールから始めます。

    サインインが不要なプラグインは、そのまま **Selected tools** に進みます。Kody に使わせるツールを選び、**Install plugin** をクリックします。
  </Step>
  <Step title="あとからツールを変更する">
    インストール済みのプラグインを開き、**Selected tools** を変更して **Update Tools** をクリックします。**Reset Authentication** で接続を解除します。
  </Step>
</Steps>

名前から破壊的な操作（delete、remove、archive）を思わせるツールには警告が付き、未選択の状態から始まります。それらを選択してインストールするには、下部のチェックボックスで確認してください。Kody は選択したどのツールでも使えるため、必要なものだけを選択してください。

<Note>
  Free プラン（およびライセンスのないセルフホスト）では、Kody が同時に実行するインストール済みプラグインは最大 3 つで、古いものが優先されます。スキップされたプラグインは Plugins ページのバナーに表示され、カードには **Locked** と表示されます。コードプロバイダーが Azure Repos または Bitbucket Data Center の場合、ネイティブの課題トラッカーがないため、**Git Issues** はインストールできません。
</Note>

## カスタムプラグイン

カタログがカバーしていないツールには、独自の MCP サーバーを追加します。サーバーは Kodus から到達できる必要があります。`localhost` ではなく、リモートの HTTP または SSE エンドポイントです。

<Steps>
  <Step title="追加する">
    **Add Custom Plugin** カードで **Add Plugin** をクリックします。
  </Step>
  <Step title="フォームに入力する">
    | フィールド | 説明 |
    | --- | --- |
    | **Plugin Name** | 必須。 |
    | **Description**、**Logo URL** | 任意。カタログでチームメンバーが見分けやすくなります。 |
    | **URL** | MCP エンドポイント。 |
    | **Protocol** | **HTTP** または **SSE**。 |
    | **Authorization** | **None**、**Bearer Token**、**Basic Auth**、**API Key**（ヘッダー名付き）、**OAuth 2.0**。OAuth 2.0 では、**Use Dynamic Client Registration**、または **Client ID**、任意の **Client Secret**、任意の **Scopes** を使います。 |
    | **Custom Headers** | 追加のヘッダー。**Add Header** で追加します。Authorization が設定するヘッダーは、Authorization によって上書きされます。 |

    **Create Plugin** をクリックします。
  </Step>
  <Step title="インストールする">
    プラグインが開きます。OAuth 2.0 の場合は、最初にプラグインの **Authenticate with** をクリックします。続いて **Selected tools** でツールを選び、**Install plugin** をクリックします。一覧が空の場合は、URL、プロトコル、Authorization を確認してください。
  </Step>
</Steps>

カスタムプラグインを開くと、**Edit Plugin** または **Delete Plugin** ができます。詳しい手順は [カスタム MCP プラグインのインストール](/ja/cookbook/custom-plugin-install) を参照してください。

## 返信でプラグインを使う

<img src="https://kodus.io/wp-content/uploads/2025/10/comment-mcp.gif" alt="サジェストでのプラグイン使用例" />

サジェストまたはプルリクエストへのコメントで Kody をメンションします。Kody は必要なプラグインを呼び出し、同じスレッドで返信します。

- `@kody, この kody ルールをテストファイルを無視するよう更新してください`
- `@kody, このタスク https://jira.com/task-123 を DONE に移動してください`

## ビジネスロジックを検証する

`@kody -v business-logic` は、プルリクエストを、それが参照するタスク（トラッカーのプラグイン経由で読み取り）と比較します。
