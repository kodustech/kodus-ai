接続済みリポジトリの PR を今すぐレビューするには、PR のコメントを `@kody review` で始めます。レビューが表示されない場合は、[スキップ理由](#kody-がスキップするタイミング)を確認してください。

## 得られるもの

- 具体的なサジェストを含むインラインコメント。
- 有効な場合は、PR サマリー。
- オプションで、承認または変更のリクエスト。[レビューポリシー](/ja/how_to_use/code_review/policy) を参照してください。
- GitHub（GitHub App としてインストールされている場合）と Forgejo では、PR の head コミットに **Kody Code Review** チェックが付きます。complete、completed with warnings、failed、skipped のいずれかです。PR に指摘があるかではなく、レビューが実行されたかどうかを報告します。
- レビューのステータスを示す、PR へのリアクション。

## レビューが始まるタイミング

**自動：** プルリクエストが開かれたとき、新しいコミットがプッシュされたとき、またはドラフトがレビュー準備完了にされたとき（Forgejo を除くすべてのプロバイダー）です。**Review draft pull requests** がオフでない限り、Kody はドラフトもレビューします。

### PR コメントのコマンド

**オンデマンド：** PR へのコメントで実行します。コマンドはコメントの先頭に書く必要があります。

| コマンド | 動作 |
| --- | --- |
| `@kody start-review` または `@kody review` | 前回のレビュー以降のコミットをレビューします（初回のレビューでは PR 全体）。一時停止中の PR を再開します。 |
| `@kody review --force` | 新しいコミットがなくても、PR 全体を再度レビューします。 |
| `@kody review --heavy` または `--balanced` | この実行のレビューモードを選びます。[ルーティング](/ja/how_to_use/code_review/configs/routing) を参照してください。 |
| `@kody review focus on the auth logic` | レビューの方向を指示します。[レビューを誘導する](/ja/how_to_use/code_review/review_directive) を参照してください。 |
| `@kody -v <agent>` | PR 全体に対して 1 つの [カスタムエージェント](/ja/how_to_use/code_review/custom_agents) を実行します。 |
| `@kody -v business-logic` | PR をそのタスクと照合します。[Business Logic Validation](/ja/how_to_use/code_review/business_logic_validation) を参照してください。 |
| `@kody <question>` | PR またはサジェストについての会話を始めます。 |

レビューコマンドは、**Automated code review**、**Review Cadence**、**Ignore title keywords**、**Base Branches**、**Review draft pull requests** を無視します。ライセンス、無視する作成者、無視するファイルは引き続き適用されます。

PR ですでにレビューが実行中の場合、コマンドは待機し、現在のレビューが終了してから実行されます。その間に届いたプッシュによって 2 回目のレビューが始まることはありません。レビューするには `@kody review` とコメントしてください。

GitHub で、Kody がユーザーアカウント（パーソナルアクセストークン）としてレビューしている場合、すでにレビュー済みの PR で Kody に対して **Re-request review** を行うと、`@kody start-review` と同じように動作します。

## ステータスリアクション

Kody はレビューのステータスを Git プロバイダー上のリアクションとして表示し、前のリアクションを最新のものに置き換えます（例：🚀 の次に 🎉）。

<Note>
  **ネイティブのリアクション** は GitHub、GitLab、Forgejo で動作します。

  Azure DevOps と Bitbucket にはリアクション API がないため、Kody はステータス絵文字を **コメント** として投稿します。そこでは 👀（スキップ）、😕（エラー）、👎（ライセンスなし）が表示されますが、🚀 と 🎉 のペアは表示されません。
</Note>

### 各絵文字の意味

- 🚀 処理中：Kody がレビューを実行しています。
- 🎉 完了：レビューが終了し、コメントが投稿されました。
- 👀 スキップ：レビューは実行されませんでした。[Kody がスキップするタイミング](#kody-がスキップするタイミング) を参照してください。
- 👎 ライセンスなし：PR の作成者にライセンスがありません。GitLab では代わりに鍵（🔒）が表示されます。
- 😕 エラー：レビューが失敗しました。`@kody start-review` で再実行してください。失敗が続く場合は、[トラブルシューティング](/ja/how_to_use/code_review/troubleshooting) を確認するか、[Discord](https://discord.gg/TFZBRk9fT6) で質問してください。

### リアクションが表示される場所

- 自動レビュー：PR の説明。
- レビューコマンド：あなたのコメント。

### スキップとブロックのフィードバックをオフにする

**Code review → General → Review feedback → Show status feedback** は、👀 と 👎 のリアクションとサブスクリプションのコメントを制御します。オフにしても、Kody は 🚀、🎉、😕 を表示します。**Automated code review** がオフの場合、Kody はスキップした PR にリアクションしません。

## Kody がスキップするタイミング

ステータスフィードバックがオフでない限り、Kody はスキップしたレビューに 👀 を表示します。どちらの場合も理由は記録されます。理由は **Kody Code Review** チェックに表示されます（GitHub App と Forgejo）。設定によってブロックされた PR（ライセンス、manual または一時停止中の cadence、無視する作成者）は、**Pull Requests** ページの **Kody skipped** に一覧表示されます。

| 理由 | 内容 | 対処 |
| --- | --- | --- |
| Automated Review is disabled | **Automated code review** がオフです。 | オンにするか、`@kody start-review` とコメントします。 |
| Title Ignored | タイトルに **Ignore title keywords** のエントリが含まれています。 | キーワードを削除するか、`@kody start-review` とコメントします。 |
| Draft PR Skipped | **Review draft pull requests** がオフです。 | PR をレディ状態にするか、設定をオンにします。 |
| Branch Mismatch | ターゲットブランチがデフォルトブランチでも **Base Branches** にもありません。 | ブランチを **Base Branches** に追加します。 |
| PR is Closed, PR is Locked | 自動レビューはクローズ済みやマージ済みの PR をスキップし、`@kody review --force` も同様です。通常の `@kody review` は、クローズ済みやマージ済みの PR をレビューします。ロックされた PR はレビューされません。 | PR を再オープンまたはロック解除するか、クローズ済みの PR には `@kody review` とコメントします。 |
| No New Commits | 最新のコミットはすでにレビュー済みです。 | `@kody review --force` とコメントします。 |
| Only Merge Commits | 新しいコミットは別のブランチをマージするだけです。 | コードの変更をプッシュするか、`@kody review --force` とコメントします。 |
| Rebase Without Changes | リベースで、すでにレビュー済みのコードに変更はありませんでした。 | `@kody review --force` とコメントします。 |
| No Files Changed, No changed files in this pull request, All Files Ignored | 今回の実行でレビューできる変更ファイルがありません。削除されたファイルは対象外です。無視されたファイルは、今回実行されるカスタムエージェントが明示的に含めた場合に対象になります。前回のレビュー以降にコミットがない PR でレビューコマンドを実行したときも、この状態になることがあります。 | **Ignored files** を確認するか、`@kody review --force` とコメントして PR 全体をレビューします。 |
| Too Many Files | メインレビューとカスタムエージェントを合わせたレビュー対象が 2,000 ファイルを超えています。 | PR を分割します。 |
| Changes Unreadable, Provider Rate Limited | Git プロバイダーが差分を完全には返さなかったか、リクエストを制限しました。 | しばらくしてからレビューを再実行します。 |
| User is ignored by configuration | PR の作成者が **Repositories → PR author filters** によって除外されています。 | [ライセンスの自動割り当て](/ja/how_to_use/auto_license_assignment#pr-作成者フィルター) を参照してください。 |
| Code reviews are disabled for the centralized config repository, or for the global Kody Rules source repository | Kody は、共有設定やルールを保持するリポジトリをレビューしません。 | 別のリポジトリをレビューしてください。 |
| User Not Licensed | PR の作成者にライセンスがありません。 | ライセンスを割り当てるか、[ライセンスの自動割り当て](/ja/how_to_use/auto_license_assignment) をオンにします。 |
| No Active Subscription, Plan Limit Exceeded, Trial Reviews Used Up, BYOK Configuration Required, Subscription Check Unavailable | 組織が現在レビューを実行できません。**Show status feedback** がオフでない限り、Kody は PR にもコメントします。 | コメントに従ってください。[制限と料金](/ja/how_to_use/pricing) を参照してください。 |
| PR is paused, Manual mode requires @kody start-review | **Review Cadence** が Auto-pause または Manual です。 | `@kody start-review` とコメントします。 |

<Note>
  `--force` は、レビュー済みとしてスキップされたレビューを再実行します。ライセンス、プラン、ファイル数上限によるスキップや、クローズ済みまたはマージ済みの PR は上書きしません。
</Note>

## 重要な設定

- [レビューのタイミングを変える](/ja/how_to_use/code_review/configs/general)。自動レビュー、頻度、ドラフト、ベースブランチ、無視するファイルを設定します。
- [Kody が報告する内容を変える](/ja/how_to_use/code_review/configs/what_to_review)。レビューのカテゴリと重大度の下限を選びます。
- [レビューの深さとモデルを選ぶ](/ja/how_to_use/code_review/configs/routing)。Balanced または Heavy を選び、適用されるモデルを確認します。
- [承認を制御する](/ja/how_to_use/code_review/policy)。Kody が変更を要求する条件と、問題のない PR を承認する条件を確認します。
- [レビューの問題を解決する](/ja/how_to_use/code_review/troubleshooting)。レビューが実行されない場合や、結果が予想と異なる場合の原因を調べます。

## レビューの頻度

**Code review → General → Automated code review** で、自動レビューのオンとオフを切り替えます。**Review Cadence** は、最初のレビュー後のプッシュで何が起こるかを決めます。

- **Automatic：** すべてのプッシュがレビューされます。
- **Auto-pause：** Kody は、**Time window (minutes)** 内にその PR で完了したレビューの数を数えます。その数が **Pushes to trigger pause**（デフォルトは 15 分間に 3 回）に達すると、次のプッシュで PR が一時停止され、Kody は "Auto-paused – comment @kody start-review when you're ready." とコメントします。誰かが `@kody start-review` とコメントするまで、プッシュはスキップされます。
- **Manual：** 最初のレビューは PR が開かれたときに実行されます。それ以降のプッシュは、誰かが `@kody start-review` とコメントするまでスキップされます。

## Kody が行うこと

1. PR をレビューできるかを確認します。ライセンス、フィルター、cadence、新しいコミットです。
2. 適用される設定（グローバル、リポジトリ、ディレクトリ）を解決し、検証します。
3. [リスク評価](/ja/how_to_use/code_review/configs/risk) がオンの場合、PR を評価してレビューモードを選びます。
4. 変更されたファイルとコンテキストを読み込みます。無視するファイルはスキップします。
5. **What Kody writes** で有効になっていれば、冒頭のコメントを投稿します。
6. PR がタスクを参照していて **Business Logic** がオンの場合、PR をそのタスクと照合します。
7. 変更をレビューします。問題を見つけ、Kody Rules とカスタムエージェントを適用し、各指摘を検証し、重複を取り除き、**Minimum severity to post** を適用します。
8. インラインコメント、PR レベルのコメント、サマリーを投稿します。
9. 有効になっていれば、PR を承認するか、変更をリクエストします。

Kody は最後にレビューしたコミットを保持するため、次のレビューは前回以降に変更された部分だけを対象にします。リベースや force-push のあとは、新しい差分をレビュー済みの差分と比較できる場合は変更された部分だけを、そうでない場合は PR 全体をレビューします。

## ヒント

- PR を小さく保ってください。大きな差分はレビューの品質を低下させます。
- PR のタイトル、ブランチ、または説明にタスクをリンクすると、Kody が PR をそのタスクと照合できます。
