## PAT の概要

Kody が自動コードレビューを実行できるようにするには、Azure DevOps で Personal Access Token（PAT）を生成する必要があります。このトークンにより、Kody はリポジトリに安全にアクセスし、制御された方法でコード分析を実行できます。

## PAT（Personal Access Token）の生成

PAT の設定は `https://dev.azure.com/<organization>/_usersSettings/tokens` から直接開けます。

トークンを正しく設定するには、次の手順に従ってください。

1. **Azure DevOps にアクセスし、トークンの設定に移動します：**

   - `https://dev.azure.com/<organization>` で組織にサインインします。
   - 右上のプロフィール画像の横にあるアイコンから **User settings** を開きます。
   - **Personal access tokens** を選択します。

2. **新しい PAT を作成します：**

   - **+ New Token** をクリックします。

3. **新しいトークンを次の内容で設定します：**

   - **Name:** `kody_code_review` など、識別しやすい名前を付けます。
   - **Organization:** 対象の組織を選択します。**All accessible organizations** は選択しないでください。Azure DevOps は、すべての組織を対象にしたトークンを廃止する予定です。
   - **Expiration:** 適切な有効期限を選択します（例：90 日または 180 日）。
   - **Scopes:** Microsoft の[スコープ一覧](https://learn.microsoft.com/en-us/azure/devops/integrate/get-started/authentication/oauth#available-scopes)にある名称で、次の権限を選択します。

     | Scope | Id | Kody での用途 |
     | --- | --- | --- |
     | **Code (read and write)** | `vso.code_write` | リポジトリとプルリクエストの読み取り、レビューコメントの投稿、プルリクエストイベントを配信するサービスフックの作成。 |
     | **Project and team (read)** | `vso.project` | プロジェクト、チーム、チームメンバーの一覧取得。 |
     | **Analytics (read)** | `vso.analytics` | リポジトリの言語メトリクスの読み取り。 |
     | **Graph (read)** | `vso.graph` | 組織ユーザーの検索。 |
     | **Identity (read)** | `vso.identity` | ID とグループの読み取り。 |
     | **User profile (read)** | `vso.profile` | トークン所有者のプロフィールの読み取り。 |

4. **Create をクリックします。**

生成されたトークンをコピーして安全に保管してください。Kody の設定に必要になります。

<Note>
  Kody がコメントを投稿し、プルリクエストのフィードバックを管理するには、Code への書き込みアクセスが必要です。
</Note>

<Note>
  Kody は、プルリクエストイベントとリポジトリごとに 1 つのサービスフックサブスクリプションを作成します。Microsoft の [Create Subscription](https://learn.microsoft.com/en-us/rest/api/azure/devops/hooks/subscriptions/create?view=azure-devops-rest-7.1) エンドポイントはこれらのイベントに対して `vso.code` を受け付け、**Code (read and write)** にはそれが含まれるため、サービスフック用の別のスコープは不要です。トークンの所有者には、プロジェクトに対する **Edit subscriptions** 権限も必要です。Project Administrators はこの権限を持っています。
</Note>

## Kody へのトークンの追加

トークンを生成したら、Kodus に貼り付けます。オンボーディング中（**Connect your Git tool** → **Azure Repos** タブ → **Connect via token**）、または後からサイドバーの **Repositories** → **Connect a provider** → **Azure Repos** で行います。**Organization name**（`dev.azure.com/<organization>` の名前）と **Personal Access Token** を入力し、**Validate and save** をクリックします。Kodus は `dev.azure.com` の Azure DevOps Services に接続します。

## トラブルシューティング：Kody が Azure DevOps で PR をレビューしない

Kody は接続されているのに、**新しいプルリクエストで何も起きない**（リアクションもコメントもなく、Kodus ダッシュボードにも PR が表示されない）場合、原因はほぼ次の 3 つのいずれかです。発生頻度の高い順に並べています。

### 1. PAT のスコープを確認する

Azure DevOps で PAT を開き、[PAT の生成](#pat（personal-access-token）の生成)に記載されているすべてのスコープが有効になっていることを確認します。最も見落とされやすいのは **Code (read and write)** です。**Code (read)** だけでは、Kody はリポジトリを読み取れてもレビューコメントを投稿できないため、レビューが「サイレントに実行」されます。

スコープが追加される前に作成された PAT には、Azure DevOps が後からスコープを追加することはありません。完全なスコープ一覧で新しい PAT を作成し、それで再接続してください（**Repositories** → プロバイダーカードの **Reset** → **Just reset the integration** を選び、新しいトークンで Azure Repos を再度接続します）。

### 2. ユーザーのプロジェクト権限を確認する

PAT は、それを作成した Azure DevOps ユーザーの権限を継承します。そのユーザーが対象のプロジェクト、リポジトリ、PR ワークフローにアクセスできない場合、スコープが正しい PAT であっても Azure に黙って拒否されます。

PAT の所有者が Web UI から次の操作をできることを確認してください。

- リポジトリを開いてプルリクエストを表示する。
- プルリクエストにコメントを投稿する。
- PR のスレッドとリアクションを確認する。

上記のいずれかがそのユーザーで失敗する場合、Kody も同じ操作ができません。再試行する前に、そのユーザーにリポジトリの **Contribute** と **Contribute to pull requests** を付与してください。

### 3. 最終手段：ユーザーを Project Collection Administrators に追加する

一部の Azure DevOps 組織では、組織レベルのより厳格なポリシーにより、適切な権限を持つユーザーであっても PAT 経由での PR コメント投稿がブロックされます。手順 1 と 2 が正しいのに Kody が何も投稿しない場合は、PAT の所有者を **Project Collection Administrators** グループに追加します。

1. **Organization Settings** → **Permissions**（左サイドバー）を開きます。
2. **Project Collection Administrators** グループをクリックします。
3. **Members** タブを開き、**Add** をクリックします。
4. Kodus の PAT を生成したユーザーを追加します。

<Warning>
  **Project Collection Administrators は高い権限を持つグループです** — Azure DevOps 組織全体の管理権限を付与します。これは問題が権限に起因するかどうかを確認するための診断として使用してください。確認できたら、PAT 所有者を PCA のままにせず、Azure DevOps 管理者と協力して、必要な特定の権限（通常は関連するプロジェクトでの Contribute と Contribute to pull requests）のみを付与してください。
</Warning>

権限が設定されると、Kody は次の PR イベントからリアクションとレビューの投稿を開始するはずです。再起動は不要です。

### それでも解決しない場合

上記のいずれでも解決しない場合、問題は通常 PAT ではなく Webhook 側にあります。[Webhook の作成](/ja/how_to_deploy/platforms/azure_devops/azdevops_webhook)を参照してください。特に、Azure Repos だけが持つ `?token=` 署名付き URL の要件を扱うトラブルシューティングのセクションを確認してください。
