## サジェスト対ブロッキング

- **サジェスト：** デフォルトでは、Kody は PR をブロックしないコメントを投稿します。どれを適用するかはあなたが決めます。
- **クリティカルな問題で Request changes（オプション）：** Kody がクリティカルな問題を見つけると、PR への自分のレビューを Request Changes に設定します。これを行うのはクリティカルな指摘だけです。それらの指摘が解決されると、Kody は承認しない PR でもリクエストを取り下げます。この設定は **Code review → General → Review feedback** にあります。GitLab が唯一の接続済みプロバイダーである場合は利用できません。
- **PR の自動承認（オプション）：** レビューがクリーンな場合、Kody は PR を承認します。マージは行いません。承認ポリシーを設定している場合は、ポリシーに一致する PR だけが承認されます。[自動承認](/ja/how_to_use/code_review/configs/auto_approve) を参照してください。

<Note>
  しきい値についてチームが合意し、強力な CI が整っている場合にのみブロッキング動作を有効にしてください。
</Note>

## ブロックしないもの

- **Kody Code Review チェック**（GitHub App と Forgejo）は、レビューが実行されたことを報告します。未対応のサジェストがあっても成功し、レビュー自体を実行できなかった場合にのみ失敗します。必須チェックにすると、レビューが行われたことは保証されますが、Kody の指摘によってマージがブロックされることはありません。
- **Business Logic** はコメントを投稿するだけで、チェックやステータスは作成しません。[Business Logic Validation](/ja/how_to_use/code_review/business_logic_validation) を参照してください。
- **リスク評価** と **ルーティング** は、Kody のレビューの方法と、承認できるかどうかを変更します。マージをブロックすることはありません。[リスク評価](/ja/how_to_use/code_review/configs/risk) と [ルーティング](/ja/how_to_use/code_review/configs/routing) を参照してください。

## Request changes をいつ有効にするか

- クリティカルな問題が決して出荷されてはならないセキュリティ重要領域。
- 回帰が高コストなパフォーマンスのホットスポット。
- 明確なコーディング標準と安定したレビュールールを持つリポジトリ。

## 自動承認をいつ有効にするか

- ドキュメントやテストなど、小規模で低リスクの変更。一部の PR だけを対象にしたい場合は、承認ポリシーを追加してください。
- 高いテストカバレッジと信頼できる CI を持つチーム。

## 人間の判断が常に重要

Kody はフィードバックを加速しますが、人間の判断の代わりにはなりません。チームがどのサジェストを採用するかとマージのタイミングを決定します。
