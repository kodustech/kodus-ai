## Kody からの応答やコメントがない場合

まず、PR のリアクションを確認してください。👀 は Kody がレビューをスキップしたこと、😕 は失敗したこと、🎉 は完了したことを意味します（クリーンなレビューではインラインコメントは投稿されません）。GitHub（GitHub App）と Forgejo では、**Kody Code Review** チェックにスキップの理由が表示されます。[Kody がスキップするタイミング](/ja/how_to_use/code_review/flow#kody-がスキップするタイミング) に、すべての理由とその対処方法が一覧表示されています。

### 自動レビューが始まらない場合

1. **Repositories** でリポジトリが選択されているか、**Review every repository** の対象であることを確認します。
2. Git プロバイダーが PR イベントを配信したか確認します。[Webhook の配信を診断する方法](/ja/knowledge_base/how-to-fix-webhook-issues)を参照してください。
3. リポジトリスコープで **Code review → General** を開き、**Automated code review** を確認します。[kodus-config.yml](/ja/how_to_use/code_review/configs/general#kodus-config-yml) を使っている場合は、ファイルの `automatedReviewActive` も確認します。
4. すぐにレビューを依頼するには PR に `@kody start-review` とコメントします。スキップされた場合は[記録された理由](/ja/how_to_use/code_review/flow#kody-がスキップするタイミング)を確認します。

### レビューが完了しても提案がない場合

Kody がサジェストを提供するために少なくとも 1 つのカテゴリ（Bug、Performance、Security、Business Logic）がオンになっていることを確認し、**Minimum severity to post** も確認します。どちらも **Code review → What to review** にあります（[開く](https://app.kodus.io/settings/code-review/global/review-scope)）。

## プッシュ後にレビューが止まった場合

一時停止した PR を再開する場合や **Manual** モードでレビューを依頼する場合は、`@kody start-review` とコメントします。毎回のプッシュを自動レビューするには **Automatic** を選びます。各モードの動作は[レビューの頻度](/ja/how_to_use/code_review/flow#レビューの頻度)を参照してください。

## トークンの問題

トークンが有効か、リポジトリにアクセスできるか、プロバイダーに必要な権限が付いているかを確認します。

[GitHub](/ja/how_to_use/code_review/general_config/github_pat) · [GitLab](/ja/how_to_use/code_review/general_config/gitlab_pat) · [Bitbucket](/ja/how_to_use/code_review/general_config/bitbucket_pat) · [Azure DevOps](/ja/how_to_use/code_review/general_config/azure_devops_pat) · [Forgejo](/ja/how_to_use/code_review/general_config/forgejo_pat)

## グローバル設定対リポジトリ設定

**Code review** のスコープピッカーでリポジトリやディレクトリの設定を確認します。[設定の継承](/ja/how_to_use/code_review/configs/inheritance_overrides)で上書き元を確認してください。

`kodus-config.yml` は、そのリポジトリの **Code review → General** で **Prefer kodus-config.yml settings** がオンの場合にのみ適用されます。スコープピッカーの下のバッジに、ファイルが適用されたか、見つからなかったか、利用できないかが表示されます。

## Kody が、この PR はすでにレビュー中だと表示する

同じ PR で別のレビューが実行されている間に送信されたレビューコマンド（`@kody review`、`@kody -v …`）は、待機し、現在のレビューが終了してから開始されます。Kody が待つのをやめた時点（最大で約 25 分）でそのレビューがまだ実行中の場合、Kody は "Kody is already reviewing this PR" とコメントし、そのコマンドを開始しません。レビューが終了するのを待ってから、もう一度依頼してください。

## Kody Code Review の待機中にマージキューが PR を外す

GitHub で `Kody Code Review` が必須チェックになっていて、PR がマージキューに入ると、Kody はキューがテストするコミットに、その PR の最後に完了したレビュー結果を報告します。新しいレビューは実行されません。これには、Kody が GitHub App を通じて接続されている必要があります。パーソナルアクセストークンでは、Kody はチェックを投稿しません。

このチェックは、Kody が PR をレビューしたことを意味するもので、PR に問題がないことを意味するものではありません。クリティカルなサジェストが未対応のままでも成功し、PR 上では、レビュー自体を実行できなかった場合にのみ失敗します。必須にすると、レビューが行われたことは保証されますが、Kody の指摘によってマージがブロックされることはありません。

PR がキューに入った時点で、その PR の最新コミットに完了した Kody のレビューがない場合（たとえば、管理者が必須チェックをバイパスした場合）、チェックは **No finished Kody review** ですぐに失敗し、キューは PR を外します。PR に `@kody start-review` とコメントし、レビューが終了するのを待ってから、もう一度キューに追加してください。**Could not carry Kody's review** は、GitHub がレビュー結果を返さなかったことを意味します。PR をもう一度キューに追加してください。
