title: "設定の継承とオーバーライド"

## 概要

Kodus の設定は、**Global**、**Repository**、**Directory** の3つのレベルで機能します。

<Note>
最も具体的なレベルが優先されます: Directory > Repository > Global
</Note>

```
Global
 ├─ Repository A
 │   ├─ Directory A1
 │   └─ Directory A2
 └─ Repository B
```

## 仕組み

フィールドは、デフォルトで親レベルから継承されます。Global でフィールドを変更すると、オーバーライドのないすべてのリポジトリとディレクトリが自動的に更新されます。

<Info>
オーバーライドはフィールドごとです。1つのフィールドだけをオーバーライドし、残りはすべて継承できます。
</Info>

オーバーライドされたフィールドは、親に従わなくなり、代わりにローカルの値を使用します。

## アプリでの操作

- **レベルの切り替え:** サイドバーの **Code review** グループ上部にあるスコープピッカーには、**Global**（"applies to every repository"）、続いて Kody がレビューするすべてのリポジトリが、ディレクトリスコープをインデントした形で一覧表示されます。独自の設定を持たないリポジトリには **Inherits Global** と表示されます。スコープを切り替えても、新しいスコープに同じページがある場合は、同じページにとどまります。
- **レベルの追加:** リポジトリは、そのスコープで最初に変更を保存したときに、独自の設定を持つようになります。ディレクトリスコープを追加するには、リポジトリを選択し、ピッカーの下部にある **Add directory scope** を選択します。[ディレクトリレベルの設定](/ja/how_to_use/code_review/configs/directory_level)を参照してください。
- **オーバーライドの確認:** サイドバーのスコープやページの横にある数値のピルは、そのレベルでオーバーライドされた設定の数を示します（"N settings overridden at this level"）。ページ上では、オーバーライドされた各フィールドに **Overridden** バッジが表示され、その元に戻すボタンでフィールドを継承に戻せます。
- **レベルの削除:** スコープピッカーの横にある **⋯** メニューには、**Delete configuration**（ディレクトリスコープでは **Edit directories** も）があります。削除すると、リポジトリは Global の設定を使用し、ディレクトリのフォルダーはそのリポジトリの設定を使用します。リポジトリの設定を削除できるのは、そのディレクトリスコープを削除した後のみです。

## kodus-config.yml

リポジトリで **Prefer kodus-config.yml settings** がオンの場合、Kody はリポジトリのデフォルトブランチのルートから `kodus-config.yml` を読み取ります。これは Global とリポジトリ自身の設定の上に適用され、ディレクトリスコープがオーバーライドする設定よりは下になります。[一般設定](/ja/how_to_use/code_review/configs/general#設定の優先度)を参照してください。

```
Global
 └─ Repository
     └─ kodus-config.yml at the repository root (optional)
         └─ Directory
```

- Kody が読み取るのは、ルートのファイルのみです。フォルダー内の `kodus-config.yml` は読み取りません。
- ルートのファイルが読み取られるのは、**リポジトリ**スコープでスイッチがオンの場合のみです。このスイッチはディレクトリスコープにも表示されますが、レビューには影響しません。
- ディレクトリスコープの設定は、アプリ、または[集中設定](/ja/how_to_use/code_review/configs/centralized_config)リポジトリから取得されます。集中設定リポジトリは、同じ Global、リポジトリ、ディレクトリの設定に書き込みます。
- ディレクトリレベルが適用されるのは、プルリクエストがちょうど1つのディレクトリスコープに触れている場合のみです。[ディレクトリレベルの設定](/ja/how_to_use/code_review/configs/directory_level#選択ルール)を参照してください。

## 例

<Tabs>
  <Tab title="Global の変更が伝播する">
    Global で **Minimum severity to post**（**What to review** 上）を変更します。

    オーバーライドのないすべてのリポジトリとディレクトリが自動的に更新されます。オーバーライドされたものは変更されません。
  </Tab>

  <Tab title="リポジトリのオーバーライド">
    リポジトリ X で、**Review starts** メッセージ（**What Kody writes → Comments during the review** 上）をオーバーライドします。

    リポジトリ X 内のディレクトリは、リポジトリ X から継承するようになります（独自のオーバーライドがない限り）。
  </Tab>

  <Tab title="継承に戻す">
    リポジトリ Y で、**What to review** のカテゴリスイッチのオーバーライドを削除します。

    フィールドは再び Global に従い、今後の Global の変更を受け取ります。
  </Tab>
</Tabs>

## ベストプラクティス

- 適切なデフォルトを設定して Global から始める
- そのリポジトリ/ディレクトリに特定のニーズがある場合のみオーバーライドする

## よくある質問

<AccordionGroup>
  <Accordion title="Global で何かを変更すると、ローカルの調整が壊れますか?">
    いいえ。ローカルのオーバーライドは変更されません。
  </Accordion>

  <Accordion title="1つのフィールドだけをオーバーライドして、残りを継承できますか?">
    はい。オーバーライドはフィールドごとです。
  </Accordion>

  <Accordion title="Directory は Repository と Global のどちらから継承しますか?">
    まず Repository から継承します。優先されている場合は、リポジトリの `kodus-config.yml` も含まれます。Repository にそのフィールドのオーバーライドがない場合は、Global から継承します。
  </Accordion>
</AccordionGroup>
