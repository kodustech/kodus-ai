Kody の PR サマリー機能を使用すると、簡潔でアクション可能なプルリクエストの説明を自動生成できます。
この設定ガイドでは、チームのワークフローと設定に合わせて機能をカスタマイズする方法を説明します。

サイドバーで **Code review → What Kody writes** を開きます。これらの設定は **PR summary**
セクションにあります。ページのライブプレビュー（**Show preview** / **Hide preview**）では、サンプルの
プルリクエストにサマリーがどのように表示されるかを確認できます。

## 自動サマリーの有効化

プルリクエストサマリーの自動生成を有効または無効にします：

**Write a summary on every pull request** をトグルします。

有効にすると、Kody はすべてのプルリクエストのサマリーを生成し、一貫性を保ち、時間を節約します。

## PR にすでに説明がある場合

Kody が既存のプルリクエストの説明とどのようにやり取りするかを制御します。3 つのモードから選択できます：

### 置き換え（デフォルト）：

既存の説明を最初から新しく生成されたサマリーで上書きします。

### 追加：

生成されたサマリーを既存の説明の末尾に追加します。

### 補完：

Kody が生成したインサイトと現在の説明を組み合わせ、新しいまたは関連する内容のみをハイライトします。

## 新しいコミットが届いたとき

PR がオープンされた後に新しいコミットがプッシュされたとき、Kody のサマリーをどう扱うかを制御します：

- **Do nothing**（デフォルト）— サマリーはそのまま残ります。
- **Concatenate new summary** — Kody の既存のサマリーに新しいサマリーが追加されます。
- **Replace Kody's summary** — Kody の既存のサマリーが新しいものに置き換えられます。

## サマリーの指示

特定のガイドラインを提供することで、Kody がサマリーを生成する方法を微調整します：

任意の **Summary instructions** フィールドに指示を追加します — サマリーで重視すべきことや省くべきことです。
**Examples** チップを使うと、用意された指示を挿入できます。

**例：**

* 「セキュリティの変更とパフォーマンスへの影響に焦点を当てる。」
* 「変更されたパブリック API をハイライトしながら簡潔にサマリーする。」

**Try on a real PR** をクリックすると、これらの設定で生成されるサマリーを自分のプルリクエストの 1 つで
プレビューできます。
