Kody は PR 全体のリスクを評価します。[レビューモード](/ja/how_to_use/code_review/configs/routing)とリスク条件付きのカスタムエージェントは、評価結果に応じてレビュー方法を決めます。[自動承認](/ja/how_to_use/code_review/configs/auto_approve)がオンの場合、評価結果によって承認が止まることもあります。

## リスク評価を有効にする

1. **Code review → Risk assessment** を開きます。
2. **Risk assessment** をオンにし、**Save settings** をクリックします。

リスク評価の初期設定はオフです。自動承認をオフにしたままでも使えます。

## 結果

- **Risk found：** PR が有効な[リスクルール](#リスクルール)の少なくとも 1 つに該当します。リスク条件付きのエージェントが実行される場合があり、Routing はリスクありのモードを使用し、自動承認はブロックされます。承認コメントには該当したルールが示されます。
- **No risk found：** Routing はリスクなしのモードを使用します。承認には、引き続きクリーンなレビューと一致するポリシーが必要です。
- **Unavailable：** Routing は設定されたデフォルトのレビューモードを使用します。自動承認はブロックされ、リスクの確定を必要とするエージェントは自動では実行されません。承認コメントにはその理由が示されます。たとえば、Git プロバイダーがコードファイルの差分を返さなかった場合です。

評価をオフにすると、Routing はすべての PR に対して設定された 1 つのモードを使用します。条件付きエージェントはリスクが確定しない限り実行されません。手動のエージェントコマンドを明示的に実行した場合は、その条件をバイパスします。

評価の対象は、1 つの PR の head、タイトル、説明です。新しいコミットがあると、そのコミットのレビューが終わるまで自動承認は保留されます。タイトル、説明、またはリスク設定だけが変わった場合、Kody は承認を判断する前に同じコミットを再評価します。

## PR でプレビュー

**Preview on a PR** はサイドパネルを開きます。接続済みのリポジトリと PR 番号を選択すると、未保存の編集も含めて現在のルールを試せます。設定されたリスク評価モデルを使用し、コメントの投稿や PR の承認は行いません。

## リスクルール

PR が有効なルールに該当すると、Kody はリスクありと判定します。Kodus は次のルールを提供しており、すべてオンになっています。

- `kodus-security` **Security and permissions：** 認証、認可、権限、テナント分離、入力検証、またはデータや操作を保護するあらゆるチェック。周辺のコードにあるガードを持たないまま、データを読み取ったり変更したりする新しいエンドポイント、ハンドラー、ジョブも含みます。
- `kodus-money` **Money, billing and licensing：** 支払い、価格、課金、クレジット、請求書、サブスクリプション、ライセンス。
- `kodus-data` **Stored data and migrations：** データまたはスキーマのマイグレーション、保存済みデータの削除や書き換え、永続化されるデータの形と、それを読み書きするクエリ。
- `kodus-infrastructure` **Secrets and infrastructure：** シークレット、認証情報、インフラ、ネットワーク、実行環境。
- `kodus-ci-build` **CI, build, release and dependencies：** CI、ビルド、リリース、デプロイの設定、または依存関係やツールのバージョン。
- `kodus-shared-contract` **Shared contracts and public interfaces：** 他のコード、ユーザー、インテグレーションが依存しているもの。たとえば、公開 API、ライブラリ関数、CLI の結果などです。
- `kodus-concurrency` **Concurrency, retries, queues and caching.**
- `kodus-ai-behavior` **Production prompts and model behavior：** 本番の機能が使用するプロンプト、モデルの選択、モデル設定。
- `kodus-broad-change` **Broad or mixed changes：** コアとなるパスの大規模な書き換え、または影響の大きい複数の変更を 1 つにまとめた PR。

Kodus のルールは、オフにしたり、名前、指示、ファイルフィルターを編集したりできます。編集した内容は、**Reset** をクリックするまで Kodus 版の代わりに使われます。変更していない部分は Kodus の更新に追従します。アカウント権限の変更や顧客データの削除がもたらす結果など、チームのコンテキストを加えるには独自のルールを追加します。

ルールには、名前、指示、スイッチ、および任意の対象／除外ファイルパターンがあります。設定には、独自のルールと変更した Kodus のルールを合わせて最大 50 件まで保存できます。名前は最大 120 文字、指示は最大 4,000 文字で、ファイルでは各 `id` が一意である必要があります。ファイルフィルターを持つルールは、一致するファイルの変更にのみ適用されます。PR の残りの部分は、Kody が他のルールに照らして引き続き評価します。変更されたファイルに適用される有効なルールが 1 つもない場合、Kody はモデルを呼び出さずにリスクなしと判定するため、クリーンなレビューであれば承認できます。

リスクルールの導入前に保存されたリスクの指示は、**Team context** として表示されます。Kody はこれをルールではなくコンテキストとして読みます。変更に人の確認が必要だと示すことも、不要だと示すこともできます。人の確認を求めている場合、承認コメントには **Team context** が示されます。

評価では、差分、PR のタイトルと説明、変更された領域のバグ修正履歴を読み取ります。履歴がない場合は不明な情報として扱われ、安全であることの証拠にはなりません。

## YAML

リポジトリの設定ファイルを使用する前に、**Code review → General**（リポジトリスコープ）で **Prefer kodus-config.yml settings** をオンにしてください。

```yaml
riskAssessmentActive: true
riskCriteria:
  - id: kodus-shared-contract # A Kodus rule, turned off
    enabled: false
  - id: kodus-ci-build # A Kodus rule, limited to release workflows
    enabled: true
    includedFiles:
      - '.github/workflows/release*.yml'
  - id: access-control
    name: Access control
    enabled: true
    instructions: 'Check whether permission changes expose data across accounts. Distinguish them from equivalent refactors.'
    includedFiles:
      - 'src/access/**'
    excludedFiles:
      - '**/*.test.ts'
```

Kodus のルールは、`id` と変更する項目だけを記載します。どの Kodus ルールにも一致しない `id` のエントリには、名前と指示が必要です。`riskCriteria: []` にすると、Kodus のルールが提供されたとおりに適用されます。`riskCriteria` を設定したリポジトリまたはディレクトリは継承したリストを置き換えるため、組織独自のルールも含め、必要な変更をすべてそこに記載してください。`kodus config remote risk-rules .` は、適用中のルールを id とともに一覧表示します。評価を止めるには、`riskAssessmentActive: false` を設定します。

**Risk assessment** を一度も設定していない構成は、この設定を変更するまで、既存の承認時のリスクの挙動を維持します。自動承認をオンまたはオフにしても、**Risk assessment** のスイッチは変わりません。
