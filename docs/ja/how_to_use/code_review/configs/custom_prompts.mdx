---
title: "指示とパーソナリティ"
description: "各レビューカテゴリで Kody が何を探すか、サジェストをどのような文章で書くかを指定します。"
---

Kody が何を報告し、どのように読ませるかは、2つの設定で決まります。どちらも Global、Repository、Directory のスコープで設定できます。

| 設定 | 場所 | 制御する内容 |
| --- | --- | --- |
| **Instructions** | **Code review → What to review** の Bug、Performance、Security の行 | そのカテゴリで Kody が何を探すか。 |
| **Personality instructions** | **Code review → What Kody writes** の **Kody's personality** | すべてのサジェストのトーンと長さ。 |

## カテゴリの指示

[What to review](/ja/how_to_use/code_review/configs/what_to_review) で有効になっている **Bug**、**Performance**、**Security** の各行には、エディター（*What counts as a bug issue* など）を開く **Instructions** ボタンがあります。

- エディターには Kody のデフォルトのテキストが表示されます。変更するまでチップには **Kody's default** と表示され、変更すると **Custom** になります。
- **Reset to default** でデフォルトに戻ります。テキストを空にした場合も同じです。
- 上限は2000文字です。
- カテゴリがオフの間、このボタンは表示されません。Business Logic には、ここで設定する指示はありません。

Kody は、あなたのテキストをそのカテゴリのガイドラインに追加します。使用しているスタックと、重視するパターンを書いてください。

```text
Focus on SQL injection and missing authorization checks in our API
handlers. Treat unvalidated user input reaching a query as a finding.
```

## Personality instructions

**Kody's personality** にある **Personality instructions** エディター（上限2000文字、**Reset to default** あり）は、すべてのサジェストにおける Kody の語り口を設定します。各カテゴリの指示の上に適用されます。

- Kody のデフォルトでは、各サジェストは2つの短い文、つまり影響と、何を変更するかにまとめられます。独自の指示を書くと、この制限は適用されなくなるため、サジェストの長さも指定してください。
- 何を書いても守られるルールがあります。Kody はサジェストのタイトルを繰り返さず、修正は別に表示されるため本文にコードブロックを入れず、行番号も追加しません。
- 決定論的なスキャナーの検出結果を除く、すべてのサジェストに適用されます。カスタムエージェント独自の文章の指示は、そのエージェントの検出結果についてこれを置き換えます。

```text
Be direct. State the impact in one sentence, then the change to make.
Write in the second person and skip pleasantries.
```

## 外部参照

カテゴリの指示、パーソナリティの指示、[サマリーの指示](/ja/how_to_use/code_review/configs/pr_summary)は、ファイルを参照できます。保存すると、Kody は参照を検出し、以降のレビューでそれらのファイルを読み込みます。エディターの下のステータスインジケーターで、処理が完了したことを確認できます。

- `@file:path/to/file.ts` — レビュー対象のリポジトリ内のファイル。行範囲を指定するには `#L10-L50` を追加します。
- `@file:repo-name:path/to/file.ts` — 別のリポジトリ内のファイル。

「CONTRIBUTING.md のガイドラインに従う」のような言及も検出されます。Kody が正しいファイルを見つけられるよう、正確なパスを使用してください。

## `kodus-config.yml` で設定する

同じフィールドが `v2PromptOverrides` の下で使用できます。

```yaml
v2PromptOverrides:
    generation:
        main: |
            Tone and length for every suggestion.
    categories:
        descriptions:
            bug: |
                What Kody should look for in the Bug category.
            performance: |
                What Kody should look for in the Performance category.
            security: |
                What Kody should look for in the Security category.
```

このファイルは、アプリのどのページでも編集できないグループをもう1つ受け付けます。Kody が検出結果を分類するために使用する重大度のルーブリックです。

```yaml
v2PromptOverrides:
    severity:
        flags:
            critical: |
                What counts as critical.
            high: |
                What counts as high.
            medium: |
                What counts as medium.
            low: |
                What counts as low.
```

<Warning>
  これは、Kody が検出結果をどのように書くかだけでなく、どのように*分類*するかを変更します。不適切なルーブリックは、すべてのレビューで重大度を気づかないうちに下げたり、引き上げたりする可能性があります。ルーブリックをゼロから書くのではなく、
  [`default-kodus-config.yml`](https://github.com/kodustech/kodus-ai/blob/main/default-kodus-config.yml)
  のデフォルトから始めてください。
</Warning>

<Note>
  `default-kodus-config.yml` には `v2PromptOverrides.level` グループも含まれています。これは受け付けられますが無視されます。レビューに反映されるのは `categories.descriptions`、`severity.flags`、`generation.main` のみです。
</Note>

このファイルは、**Prefer kodus-config.yml settings** がオンの場合にのみ読み込まれます。[一般設定](/ja/how_to_use/code_review/configs/general#設定の優先度)を参照してください。

## ヒント

- **自分のコンテキストに特化する。** 「バグを探す」よりも、「Java サービスのヌル参照と、DAO 層で閉じられていない接続に焦点を当てる」のほうが効果的です。
- **カテゴリを分ける。** Bug、Security、Performance で同じ指示を繰り返さないでください。
- **1つの例ではなく、パターンを記述する。** 文字列結合の特定の1例のような例を挙げると、Kody が指摘する対象がその形に狭まる場合があります。
- **まず1つの設定から始める。** デフォルトで1週間実行し、誤検知や見逃しを記録して、それに関係する指示だけを変更してください。

## よくある質問

<AccordionGroup>
  <Accordion title="これらはすべてのリポジトリに適用されますか?">
    Global で設定した場合、独自の値を持たないすべてのリポジトリに適用されます。リポジトリやディレクトリで上書きできます。
  </Accordion>

  <Accordion title="変更すると、既存のプルリクエストはどうなりますか?">
    変更は新しいレビューにのみ影響します。新しいテキストで既存のプルリクエスト全体をレビューするには、`@kody review --force` とコメントしてください。`--force` がない場合、レビューコマンドが対象とするのは、前回のレビュー以降のコミットのみです。
  </Accordion>

  <Accordion title="レビューのノイズが多すぎます。何を変更すべきですか?">
    What to review の **Minimum severity to post** を引き上げ（[重大度しきい値](/ja/how_to_use/code_review/configs/suggestion_control)を参照）、そのうえでカテゴリの指示をより具体的にしてください。
  </Accordion>

  <Accordion title="Kody が検出すべき問題を見逃します。">
    カテゴリがオンであること、および検出結果の重大度がしきい値を下回っていないことを確認してください。**Reset to default** を使用して、あなたの指示がレビューを狭めすぎていないかを確認してください。
  </Accordion>

  <Accordion title="カテゴリの指示とパーソナリティの指示の違いは何ですか?">
    カテゴリの指示は、各カテゴリで Kody が何を分析するかを制御します。パーソナリティの指示は、すべての検出結果をどのような文章で書くかを制御します。それぞれ独立して変更できます。
  </Accordion>
</AccordionGroup>
