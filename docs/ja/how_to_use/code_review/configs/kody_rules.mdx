## 場所

**Code review** グループ上部のスコープピッカーで **Global**、リポジトリ、またはディレクトリを選択し、**Kody Rules** を開きます。このページで作成または変更した内容は、選択したスコープに適用されます。スコープの組み合わせ方については、[ルール継承](/ja/how_to_use/code_review/configs/rules_inheritance)を参照してください。

ヘッダーには3つのアクションがあります。

- **Configuration**: このスコープで、ルールとメモリをどのように作成し、承認するか。
- **Discovery**: [Rules Library](/ja/how_to_use/code_review/configs/rules_library)。**Review Rules** タブに表示されます。
- **New rule**（**Memories** タブでは **New memory**）。

## 2つの種類

<Tabs>
  <Tab title="Review Rules">
    コードレビュー中に実行され、違反をサジェストとして報告するチェックです。

    - **Per file** ルールは、変更されたファイルごとに1回実行され、インラインでコメントします。
    - **Per PR** ルールは、プルリクエスト全体に対して1回実行され、PR コメントを1つ投稿します。
    - 各ルールには重大度があり、パスで限定できます。
  </Tab>

  <Tab title="Memories">
    Kody がコードレビューや Kody との会話で、優先度の高いコンテキストとして使用する背景知識です。メモリはコードベースの仕組みを説明するもので、チェックではなく、重大度もありません。

    - PR コメントで Kody に話しかけるか、**New memory** で作成します。
    - ディレクトリ、リポジトリ、または組織全体にスコープできます。
  </Tab>
</Tabs>

## Review Rule を作成する

**Review Rules** タブで、**New rule**（リストが空の場合は **Write a rule**）をクリックします。

| フィールド | 内容 |
|-------|--------------|
| **Rule name** | 最大300文字。 |
| **Execution mode** | **Per file** または **Per PR**。 |
| **Path** | **Per file** ルールを、一致するファイルに限定する glob。複数の glob はカンマで区切ります。いずれかに一致するファイルがチェックされます。空の場合はすべてのファイルが対象です。**Per PR** ルールでは使用されません。また、ルールがディレクトリスコープに属するディレクトリスコープでは編集できません（適用されるタイミングについては[ルール継承](/ja/how_to_use/code_review/configs/rules_inheritance)を参照）。 |
| **Instructions** | Kody が何をチェックし、どのように判断するか。必須です。新しいルールでは **Start with a popular template** を選択できます。**Variables** メニューは、`fileDiff` や `pr_title` などの名前を挿入します。これらは、Kody が参照する差分や PR の詳細を指すために使用できます。 |
| **Severity** | **Critical**、**High**（デフォルト）、**Medium**、**Low**。 |
| **Advanced settings** | **Inheritable**（デフォルトでオン）と **Code examples**（**Bad example** と **Good example**）。 |

重大度は、指摘にどのようなラベルを付けるかを決めます。特定の重大度未満の指摘をそもそも投稿するかどうかは、[重大度しきい値](/ja/how_to_use/code_review/configs/suggestion_control#kody-rules-にしきい値を適用)で設定します。

### Kody が参照する内容

- **Per file:** そのファイルの差分、ファイルが十分に小さい場合はファイルの残りの部分、PR のタイトルと説明（最初の1,000文字）。
- **Per PR:** PR のタイトルと説明（最初の1,000文字）、変更されたファイルの一覧、およびすべてのファイルの差分。非常に大きな PR では、差分の予算を超えたファイルは、名前のみが一覧表示されます。

Kody が違反を報告するのは、プルリクエストが追加または変更した行のみです。指示に言語を指定しているルール（「Ruby ファイルでは…」）は、その言語のファイルに限定されます。これは、ルールを保存するときに Kody が判断します。

### ルールでファイルを参照する

指示の中でパスを指定してファイルに言及する（たとえば `@file:docs/architecture.md`）と、Kody がルールを判断するときに、その内容が渡されます。

- Kody は、ルールを保存するときにファイル参照を検出します。エディターの横のステータスには、参照が解決されたタイミングと、読み取れなかったファイルが表示されます。
- ファイルは、プルリクエストのターゲットブランチから読み取られます。
- プレースホルダーではなく、リポジトリ内の実際のパスを使用してください。

### 例

<Tabs>
  <Tab title="Per file">
    - **Rule name:** Avoid equality operators in loop termination conditions
    - **Path:** `src/**/*.ts`
    - **Severity:** Critical
    - **Instructions:** Using `==` or `!=` in a loop condition can cause infinite loops when the exact value is never hit.

    **Bad example**

    ```typescript
    // Infinite if the increment is not exactly 1
    for (let i = 0; i != 10; i += 2) {
      console.log(i);
    }
    ```

    **Good example**

    ```typescript
    for (let i = 0; i < 10; i += 2) {
      console.log(i);
    }
    ```
  </Tab>

  <Tab title="Per PR">
    - **Rule name:** New routes must be registered
    - **Execution mode:** Per PR
    - **Instructions:** When the PR adds a route to a controller, check that it is also added to `@file:routes.json`.

    Per PR ルールでチェックできるその他の例:

    - PR の説明に、何が追加または削除されたかが記載されている。
    - 変更されたすべてのサービスファイルに、対応するテストファイルが PR に含まれている。
    - PR が変更するファイル数が、設定した数を超えない。
  </Tab>
</Tabs>

## ルールを追加するその他の方法

- **[Rules Library](/ja/how_to_use/code_review/configs/rules_library):** **Discovery** で、既製のルールとパックを追加します。
- **[リポジトリルール](/ja/how_to_use/code_review/configs/repository_rules):** リポジトリの `.kody/rules` に、1つのルールにつき1つのマークダウンファイルとして保管します。
- **[グローバルルールソース](/ja/how_to_use/code_review/configs/global_rule_sources):** standards リポジトリのルールファイルを、グローバルルールとしてインポートします。
- **[Automatic Rules Generation](/ja/how_to_use/code_review/learning/kody_rules_generation):** Kody が、レビュアーの過去のコメントからルールの下書きを作成します。
- **レビューのスレッド内:** Kody に、ルールの作成、変更、削除を依頼します。たとえば `@kody update this rule to ignore test files` のようにします。この方法で作成されたルールには、**MCP/Agent** の由来が表示され、**Pending review** で待機します。

## ルール一覧

一覧には、選択したスコープのルールと、上位のスコープから継承したルールが表示されます。行をクリックすると、サイドパネルでルールが開き、**Pause** または **Resume**、**Edit**（編集権限がない場合は **View**）、削除ができます。

フィルターの横にあるテーブル表示とカード表示のスイッチを使用します。選択内容はブラウザに保存されます。検索の対象は、タイトル、パス、指示、例です（`/` を押すとフォーカスされます）。一覧の上にある重大度チップで、重大度による絞り込みができます。

**Filters** では、最近の更新、重大度、名前で並べ替えたり、継承されたルールと **Disabled Rules** の表示/非表示を切り替えたり、由来、**Has sync errors**（参照されているファイルを読み取れなかったルール）、**Paused only** で絞り込んだりできます。

### Origin

| Origin | ルールの出どころ |
|--------|--------------------------|
| **Manual** | アプリで作成。 |
| **Library** | Rules Library から追加。 |
| **Auto-sync** | リポジトリ内のルールファイル。同期された状態が保たれます。 |
| **Kody-generated** | 過去のレビューから下書きを作成。 |
| **Onboarding** | オンボーディング中に提案。 |
| **MCP/Agent** | Kodus MCP ツールで作成。レビューのスレッド内の Kody、または MCP クライアントによるもの。 |
| **CLI** | Kodus CLI で作成。 |
| **Agent file** | コーディングエージェントのファイルが、ルールにならなくなる前にインポートされたもの。固定されています。[コーディングエージェント向け指示](/ja/how_to_use/code_review/configs/rules_file_detection#コーディングエージェント向けファイルからインポートされたルール)を参照してください。 |

### Status

| Status | 意味 |
|--------|---------|
| **Active** | 新しい PR ごとにチェックされます。 |
| **Paused** | 一覧には残りますが、すべての PR でスキップされます。 |
| **Paused by Kody** | **Pause ignored and noisy rules** によって一時停止されました。 |
| **Locked** | Free プランの上限のためにスキップされます（後述）。 |
| **Disabled** | このスコープで無効としてマークされた、継承されたルール。レビューでは引き続き適用されます。[ルール継承](/ja/how_to_use/code_review/configs/rules_inheritance)を参照してください。 |
| **Pending add**、**Pending edit**、**Pending delete** | [集中設定](/ja/how_to_use/code_review/configs/centralized_config)のプルリクエストで待機している変更。 |

### 一括操作

**Review Rules** タブで、ルールにチェックを入れる（または **Select all visible**）と、まとめて **Pause**、**Resume**、**Delete** できます。選択できるのは現在のスコープのルールのみで、継承されたルールは選択できません。

### 影響と使用状況

サイドパネルには、過去30日間の **Impact** ブロックが表示されます。ルールが発動した回数、発動したプルリクエストの数、最近のサジェストです。Cockpit が利用できる場合（Teams および Enterprise プラン、およびトライアル）は、実装されたサジェストの数、高評価と低評価のフィードバックも表示され、テーブルに **Usage** 列が追加されます。注意が必要なルールには、チップが表示されます。

- **Stale:** 過去30日間に発動しなかった。
- **Ignored:** 5回以上発動し、サジェストのうち実装されたのが20%以下。
- **Noisy:** 5回以上発動し、低評価が3件以上、低評価が高評価より多く、サジェストの10%以上に低評価が付いている。

### Pause ignored and noisy rules

Teams および Enterprise プランでは、**Configuration → Pause ignored and noisy rules** により、過去30日間で **Ignored** または **Noisy** となった、そのスコープ内の有効なルールが、1日1回一時停止されます。手動で作成したルールも含まれます。それらには、根拠となる数値とともに **Paused by Kody** と表示されます。管理者には通知され、いつでもルールを **Resume** できます。再開後は、その後に検出された内容のみがカウントされます。[集中設定](/ja/how_to_use/code_review/configs/centralized_config)で管理されているルールは一時停止されません。デフォルトではオフです。

## ルールの上限

クラウドの **Free** プラン（またはサブスクリプションがキャンセル済みか期限切れ）の組織と、有効なライセンスのないセルフホストインスタンスでは、1回のレビューで実行される有効なルールは、古いものから最大**10件**です。10件には、Global、リポジトリ、ディレクトリのルールが合算され、メモリもカウントされます。上限を超えたルールは **Locked** として一覧に残り、すべての PR でスキップされ、ページのバナーに件数が表示されます。有料のクラウドプランと、ライセンスのあるセルフホストインスタンスには上限がありません。

## Memories

メモリは、Kody が覚えておく短い記述です。システムの仕組みや、チームがすでに決定したことなどです。メモリは、Kody がリポジトリについて誤った前提を繰り返さないようにするのに役立ちます。

- メモリは、コードレビューと Kody との会話のコンテキストに追加されます。
- Kody がメモリを保存しようとするとき、既存のメモリを確認し、作成する、重複としてスキップする、または既存のメモリを更新する、のいずれかを行います。

### メモリを作成する

**PR コメントで。** Kody は、明示的な記述と暗黙的な記述の両方を拾います。

```
@kody remember: this repo mirrors a third-party API, so some payload fields intentionally stay snake_case.
```

```
@kody in this service, tests usually live next to implementation files rather than in a central test folder.
```

Kody がメモリを保存または更新すると、アプリ内のメモリへのリンクとともに返信します。

<Info>
  Kody は、一時的な指示（「今すぐ修正して」）、デバッグのやり取り、質問、曖昧な記述、1つのタスクや PR にのみ当てはまるリクエストは、メモリとして保存しません。
</Info>

**アプリで。** スコープを選択し、**Memories** タブを開き、**New memory**（リストが空の場合は **Add a memory**）をクリックして、**Memory name** と **Instructions** を入力し、**Create memory** をクリックします。

### メモリのスコープ

| スコープ | 適用先 |
|-------|------------|
| **Directory** | 設定済みのディレクトリのファイル。PR コメントで作成されたメモリは、`src/components/**` のようなパスに限定することもできます。 |
| **Repository** | リポジトリ全体。 |
| **Organization**（スコープピッカーでは **Global**） | 組織内のすべてのリポジトリ。 |

## 承認

デフォルトでは、過去のレビューから生成されたルール、オンボーディング中に提案されたルール、Kody が保存するメモリは、作成されるとすぐに有効になります。先にレビューするには、**Configuration** を開き、**Kody knowledge approval** をオンにします。

承認をオンにすると、次のものは承認されるまで **Pending review** で待機します。

- 過去のレビューから生成された、またはオンボーディング中に提案されたルール
- レビューのスレッド内で Kody が保存するメモリ
- リポジトリのルールファイルから同期されたルール。[グローバルルールソース](/ja/how_to_use/code_review/configs/global_rule_sources)でインポートされたルールは、すぐに有効になります。

Kodus MCP ツールで作成されたルール（レビューのスレッド内で Kody が作成するルールを含む）は、設定にかかわらず、常に **Pending review** で待機します。手動で作成したルール、ライブラリから追加したルール、CLI で作成したルールは、すぐに有効になります。

### Pending review

**Review Rules** タブと **Memories** タブのバッジに、保留中の件数が表示されます。**Pending review** セクション（"Rules and memories awaiting approval."）には、それらがまとめて一覧表示され、それぞれに **Rule**、**Memory**、**Update** のいずれかのマークが付きます。

- **新しいルールとメモリ:** **Approve** で有効化、**Discard** で却下します。
- **更新:** 既存のアイテムへの変更案で、差分として表示されます。**Update existing** で適用し、**Create new instead** で元のものを残して提案を別のアイテムとして追加し、**Discard** で却下します。

複数を選択し、**Bulk actions**（**Approve N**、**Create as new (N)**、**Discard N**）で一括処理できます。
