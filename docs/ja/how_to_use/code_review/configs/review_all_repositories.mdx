---
title: "すべてのリポジトリをレビュー"
description: "Git 連携から見えるすべてのリポジトリを、あとから作成されたものも含めて、1 つずつ追加することなく Kody にレビューさせます。"
---

デフォルトでは、Kody は **Repositories** で選択したリポジトリをレビューします。**Review every
repository** をオンにすると、Kody は接続済みの認証情報から見えるすべてのリポジトリをレビューし、
あとから作成されたリポジトリも自動的に取り込みます。GitHub、GitLab、Bitbucket Cloud、
Bitbucket Data Center、Azure DevOps、Forgejo のいずれでも、クラウドでもセルフホストでも同じように動作します。

## オンにする

1. サイドバーで **Repositories** を開きます。
2. **Review every repository** をオンに切り替えます。
3. 件数を確認します。Kody は、レビューを開始するリポジトリの数とスキップするリポジトリの数を表示します。
4. **Review every repository** をクリックします。

オンとオフを切り替えられるのは、組織のオーナーだけです。

Kody はバックグラウンドでリポジトリをセットアップし、カードに進行状況が表示されます
（「Setting up repositories: 320 of 487.」）。プルリクエストのレビューは、各リポジトリの Webhook が
設定され次第、開始されます。

<Note>
  これらのリポジトリでのレビューは、他のリポジトリでのレビューと同じようにカウントされ、そこでの
  プルリクエストの作成者はライセンスシートを消費する場合があります。
</Note>

## レビュー対象

- **認証情報から見えるすべてのリポジトリ。** Kodus アプリを使用する GitHub では、アプリがインストールされている
  リポジトリです。GitHub トークンを使用する場合は、接続済みの組織のリポジトリのうち、トークンでアクセスできるもの
  （個人アカウントの場合は、そのアカウントがアクセスできるすべてのリポジトリ）です。GitLab では、トークンのユーザーが
  メンバーになっているプロジェクトです。
- **アーカイブ済みのリポジトリは対象外です。** 常にスキップされます。Azure DevOps では無効化されたリポジトリを
  アーカイブ済みとして扱います。Kody は Bitbucket Cloud ではアーカイブ済みのリポジトリを検出しません。
- **フォークとミラーは対象外です。** ただし、オンにするときに **Also review forks and mirrors** にチェックを入れた場合を除きます。

## 新しいリポジトリ

Kody は 10 分ごとに新しいリポジトリを確認し、手動で追加したリポジトリと同じ方法でセットアップします。
Webhook、設定、コードグラフ、最近のプルリクエスト履歴です。

- セットアップ **後** に新しいリポジトリでオープンされたプルリクエストは、通常どおりレビューされます。
- それ **より前**（リポジトリ作成直後の数分間）にオープンされたプルリクエストは、次のプッシュ時、または
  `@kody start-review` ですぐにレビューされます。
- Kodus アプリを使用する GitHub では、GitHub から通知があり次第、新しいリポジトリがセットアップされます。
  すべてのリポジトリへのアクセスを許可してアプリをインストールしたあとに作成されたリポジトリについては、
  アプリに **Repository** Webhook イベントが必要です（セルフホスト：GitHub App の設定で追加します）。

セルフホスト：確認の間隔は `API_CRON_SYNC_ALL_REPOSITORIES` です（デフォルトは 10 分ごと）。

## リポジトリを対象から外す

リポジトリのコードレビュー設定を開き、**Automated code review** をオフにします（**Code review → General**）。
Kody は同期のたびにその状態を維持し、そのプルリクエストの作成者は自動レビューによるライセンスシートを
消費しません。`@kody` コマンドは引き続き使用できます。

**Review every repository** がオンの間は、**Repositories** でリポジトリを手動で追加または削除することは
できません。削除したリポジトリは、次の同期で再び追加されてしまうためです。

## リポジトリをセットアップできない場合

Kody は、各リポジトリに Webhook を作成する権限を必要とします。プロバイダーが拒否した場合、そのリポジトリは
理由とともに **Repositories** に一覧表示され、Kody は同期のたびに再試行します。

[プロバイダー別の Webhook 権限](/ja/knowledge_base/how-to-fix-webhook-issues#プロバイダー別の-webhook-権限)を参照してください。

多数のリポジトリをセットアップしている間にプロバイダーが Kody をレート制限した場合、Kody は停止して次の
同期で再開するため、大規模な初回実行には数サイクルかかることがあります。コードグラフとプルリクエスト履歴も、
数サイクルにわたってバックグラウンドで完了します。カードには、同期が停止または失敗した場合の理由、最後に
同期に成功した時刻、そして残りのコードグラフと履歴の数が表示されます。

## オフにする

**Review every repository** をオフに切り替えます。現在レビューされているリポジトリはそのまま残り、
新しいリポジトリは追加されなくなります。
