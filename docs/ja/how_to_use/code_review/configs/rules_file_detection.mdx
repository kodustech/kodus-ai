`CLAUDE.md`、`AGENTS.md`、`.cursor/rules`、`.github/copilot-instructions.md` のようなファイルは、チームの作業方法をコーディングエージェントに伝えるものです。これらはレビューポリシーではないため、Kodus が Kody Rules に変換することはありません。この設定をオンにすると、Kody はプルリクエストで変更されたファイルをカバーする指示ファイルを読み、その内容に反する変更を指摘します。

規約をレビューで強制されるルールにしたい場合は、`.kody/rules` に [リポジトリルール](/ja/how_to_use/code_review/configs/repository_rules) として記述してください。

## 有効にする

- **オンボーディング中**：**Teach Kody how your team builds software** ステップで、選択した各リポジトリで見つかったコーディングエージェント向けファイルが一覧表示され、Kody にそれらを使わせるかどうかを尋ねられます。オンにしない限りオフのままです。
- **あとから**：サイドバーで、**Code review** グループ上部のスコープピッカーで **Global** またはリポジトリを選択し、**Kody Rules** を開いて **Configuration** をクリックし、**Use coding-agent instructions in reviews** をオンにします。Global の値は、独自の値を設定していないすべてのリポジトリのデフォルトになります。

この設定は、コードレビュー設定（および `kodus-config.yml`）に `repoInstructionsEnabled` として保存されます。以前の `ideRulesSyncEnabled` はもう読み取られないため、そこに設定した値でこの機能が有効になることはありません。

## Kody が読むファイル

### Cursor
- `.cursorrules`
- `.cursor/rules/**/*.mdc`

### GitHub Copilot
- `.github/copilot-instructions.md`
- `.github/instructions/**/*.instructions.md`

### エージェント（agents.md 規約）
- `AGENTS.md`、`.agents.md`、`.agent.md`
- `.agents/rules/**`

### Claude
- `CLAUDE.md`

### Windsurf
- `.windsurfrules`

### Sourcegraph Cody
- `.sourcegraph/**/*.rule.md`

ツールの設定ファイル（`.claude/settings.json`、`.opencode.json`、`.aider.conf.yml`、`.aiderignore`）は認識されますが、コードを照らし合わせる指示を含まないため、読み込まれることはありません。

## レビューでの使われ方

- **変更をカバーするファイルだけ。** リポジトリのルートにあるファイルはすべてのファイルをカバーします。`services/billing/CLAUDE.md` のようなネストされたファイルは `services/billing/**` をカバーします。`globs:` を持つ（かつ `alwaysApply: true` ではない）Cursor ルールや、`applyTo:` を持つ Copilot ファイルは、宣言したファイルだけをカバーします。どちらも持たない Cursor ルールは、Cursor のエージェントが要求したときにだけ読み込まれるため、読み取りません。
- **プルリクエストのターゲットブランチから読み込みます。** プルリクエストは、そのブランチにすでにマージされている指示に照らしてチェックされます。プルリクエストで行った指示の変更は、マージ後に反映されます。
- **上限があります。** 1 回のレビューにつき最大 8 ファイル・64 KB まで、ルートのファイルが優先されます。長いファイルは切り詰められます。読み込まれなかったものはレビューのログに記録されます。
- **指摘には Repo Instruction のラベルが付きます。** Kody が指摘するのは、指示が変更されたファイルに適用され、かつそれに反する行がプルリクエストで追加または変更された場合だけです。コメントには指示が引用され、ファイル名が示されます。
- **Kody への指示としては扱いません。** これらのファイルは、差分と照らし合わせるためのリポジトリ内のテキストとして扱われます。レビュアーに何かを求める記述は無視され、バグ・セキュリティ・パフォーマンスの問題の判断が変わることもありません。

<Note>
Deep review モードはバグ・セキュリティ・パフォーマンスの各レビュアーを個別に実行し、コーディングエージェント向けの指示は読み込みません。
</Note>

## この変更以前にインポートされたルール

以前のバージョンの Kodus は、これらのファイルを Kody Rules に変換していました。それらのルールは残りますが **凍結** されます。ファイルが変更されても更新されず、Kody Rules ページでは **Agent file** のオリジンが付きます。**rules from coding-agent files** チップで一覧をそれらのルールに絞り込めるので、一時停止や削除をしたり、強制したい規約を `.kody/rules` に移したりできます。

オンボーディングで誰も選択しないままコーディングエージェント向けファイルや依存関係マニフェストからインポートされたルールは削除されました。各リポジトリにある同じファイルのコピーが、それぞれすべてのリポジトリに適用される別々のルールになっていたためです。Kody Rules ページには削除された件数が表示され、**Use coding-agent instructions in reviews** を有効にすると、各リポジトリのレビューで同じファイルが読み込まれます。削除されたルールを戻したい場合はサポートにお問い合わせください。

`@kody-sync` はもう何の効果もありません。Kody Rule ファイルは常に同期され、コーディングエージェント向けファイルがルールになることはないためです。`@kody-ignore` は引き続き Kody Rule ファイルを同期の対象から外します。

## セルフホストでの確認

ワーカーのログには、コーディングエージェント向けの指示を読み込んだレビューごとに grep しやすいマーカーが出力されます：

```bash
docker logs kodus_worker 2>&1 | grep "\[repo-instructions\]"
```

各行には、見つかった指示ファイルの数、読み込まれたファイル、バイト数、そして読み込まれなかったものがあるかどうかが表示されます。
