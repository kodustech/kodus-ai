**Code review → General**（ページタイトルは **General settings**）を開きます。レビューカテゴリと重大度しきい値は [What to review](/ja/how_to_use/code_review/configs/what_to_review) にあります。サマリー、メッセージ、Kody の語り口は **What Kody writes** にあります。

<Note>
  Kodus には、Global、Repository、Directory の3つの設定レベルがあります。仕組みについては <a href="/ja/how_to_use/code_review/configs/inheritance_overrides">設定の継承とオーバーライド</a> を参照してください。
</Note>

## 自動コードレビュー

**Automated code review** スイッチをオンにすると、Kody はプルリクエストが開かれたときにレビューします。デフォルトではオンです。オフの場合は、プルリクエストに `@kody start-review` とコメントしてレビューを開始します。

<Info>
  このスイッチが対象とするのは**最初のレビュー**です。以降のプッシュについては、下記のレビュー頻度を参照してください。
</Info>

### レビュー頻度

**Automated code review** がオンの場合に表示されます。最初のレビュー以降のレビューを Kody がどのように扱うかを決めます。

<Tabs>
  <Tab title="自動">
    新しいプッシュごとにレビューします。これがデフォルトです。
  </Tab>

  <Tab title="自動一時停止">
    プッシュが短時間に集中した場合に、レビューを一時停止します。**Time window (minutes)** の間に、Kody が **Pushes to trigger pause** 回プルリクエストをレビューすると、次のプッシュはレビューされず、`@kody start-review` とコメントするまでプルリクエストは一時停止のままになります。

    デフォルト: 15分間に3回のプッシュ。
  </Tab>

  <Tab title="手動">
    Kody は、プルリクエストが開かれたときの最初のプッシュをレビューします。以降のプッシュは、`@kody start-review` とコメントした場合にのみレビューされます。
  </Tab>
</Tabs>

### ドラフトのプルリクエストをレビューする

**Review draft pull requests** はデフォルトでオンのため、ドラフトもレビューされます。オフにすると、ドラフトは ready になるまでスキップされます。

## レビューモード

General には、有効になっているレビューモードとモデルが表示されます。モードや、リスク結果によって選択されるモードを変更したり、リポジトリやディレクトリのモデルを上書きしたりするには、**Configure routing** に進みます。[Routing](/ja/how_to_use/code_review/configs/routing) を参照してください。

リスク評価には、専用のページとスイッチがあります。[リスク評価](/ja/how_to_use/code_review/configs/risk)を参照してください。

## PR ワークフロー

**Automatic PR approval** — Kody は、問題のないレビューの後、または自分が残したすべてのコメントが解決された時点で PR を承認します。マージは行いません。承認ポリシーは、Kody が承認できる問題のない PR を定義し、有効なリスク評価はすべてのポリシーに適用されます。[自動承認](/ja/how_to_use/code_review/configs/auto_approve)を参照してください。

**対応プラットフォーム:** GitHub、GitLab、Bitbucket、Azure Repos、Forgejo

## レビューフィードバック

- **Request changes on critical issues**（`isRequestChangesActive`、デフォルトはオフ）— Kody が重大な問題を見つけると、プルリクエストのレビューを Request Changes に設定します。それらの指摘が解決されると、Kody は、承認しないプルリクエストであっても、リクエストを取り下げます。対応プラットフォーム: GitHub、Bitbucket、Azure Repos、Forgejo。接続済みのプラットフォームが GitLab のみの場合、このスイッチは表示されません。
- **Show status feedback**（デフォルトはオン）— レビューがスキップまたはブロックされたときに、Kody がリアクションまたはコメントを行います。
- **Committable suggestions**（Alpha、デフォルトはオン）— Kody は、コミットとして直接適用できるコードを提案できます。GitHub のみ。GitHub の接続がない場合、このスイッチは無効になります。

## レビュー範囲

Kody は、これらの設定に一致するファイルとプルリクエストをスキップします。`@kody start-review` で開始したレビューでは、**Ignore title keywords**、**Base Branches**、**Review draft pull requests** は無視されます。

### 無視するファイル

Kody がスキップするファイルの glob パターンです。パターンは大文字と小文字を区別し、ドットファイルにも一致します。フィールドにはいくつかのパターンが表示され、**Edit** で **Ignored files** ダイアログが開きます。新しいパターンごとに glob 構文が有効かどうかが確認され、**Test a file** で、パスが無視されるのか（どのパターンによるか）、レビューされるのかがわかります。**Apply** はフィールドを更新するだけです。**Save settings** をクリックするまで、何も保存されません。

デフォルトのリストは長く、`yarn.lock`、`package-lock.json`、`package.json`、`.env`、`**/*.json`、`**/*.xml`、`**/*.lock`、`**/*.min.*`、画像、フォント、アーカイブ、IDE や OS のファイル、および `**/build/**`、`**/bin/**`、`**/out/**`、`**/vendor/*`、`**/deploy/**`、`**/prod/**` などのフォルダーが含まれます。Kody がレビューを期待するファイルをスキップする場合は、リストに広すぎるパターンがないかを確認し、あれば削除してください。

変更されたファイルがすべて無視されていても、その中のいずれかをカスタムエージェントが明示的に対象にしていればレビューを実行できます。削除されたファイルは除外されます。メインレビューとカスタムエージェントを合わせてレビュー対象が 2,000 ファイルを超えると、Kody はレビューをスキップします。生成ファイルやベンダーのフォルダーは **Ignored files** で除外できます。

### 無視するタイトルのキーワード

タイトルにこれらのキーワードのいずれかが含まれるプルリクエストは、Kody がスキップします。照合は大文字と小文字を区別せず、各キーワードは最大100文字です。

### ベースブランチ

どのターゲットブランチに自動レビューを行うかを指定します。

<Info>
  **デフォルトの空は、リポジトリのデフォルトブランチのみを意味します。** 他のブランチをレビューするには、エントリを追加します。リストにエントリがある場合、Kody は、そのいずれかに一致するプルリクエストと、`!` で除外しない限りデフォルトブランチをレビューします。

  エントリは、`contains:` を除き、プルリクエストの**ターゲット**ブランチと照合されます。

  | エントリ | 効果 |
  | --- | --- |
  | `develop` | `develop` を対象とするプルリクエストをレビューします。 |
  | `release/*` | `release/` で始まる任意のブランチを対象とするプルリクエストをレビューします。`*` はスラッシュを含む任意の文字に一致します。 |
  | `*` | 任意のブランチを対象とするプルリクエストをレビューします。 |
  | `!staging` | `staging` を対象とするプルリクエストは一切レビューしません。除外は、他のすべての一致より優先されます。デフォルトブランチを対象外にするには `!main` を使用します。 |
  | `contains:hotfix` | ターゲットにかかわらず、**ソース**ブランチに `hotfix` を含むプルリクエストをレビューします。 |

  各エントリは最大100文字です。
</Info>

## その他の設定

- **Kody Language**（Global のみ）— Kody がレビューの返信で使用する言語。
- **Configure centralized config**（Global のみ、ページヘッダー）— レビュー設定を1つのリポジトリで管理します。[集中設定](/ja/how_to_use/code_review/configs/centralized_config)を参照してください。

## kodus-config.yml

### 設定の優先度

Web アプリの代わりに、リポジトリのルートにある `kodus-config.yml` ファイルでレビュー設定を管理できます。

<Warning>
  **オプトインするまで、このファイルは無視されます。** リポジトリで **Prefer kodus-config.yml settings** がオンになっていない限り、Kody は `kodus-config.yml` を読み取りません。ファイルをコミットしただけでは何も起こりません。

  サイドバーの **Code review** グループ上部にあるスコープピッカーでリポジトリを選択し、**Code review → General** を開いて、**Prefer kodus-config.yml settings** をオンにします。このスイッチはディレクトリスコープにも表示されますが、ファイルを読み取るかどうかを決めるのは、リポジトリの設定のみです。これは Web の設定であり、ファイルからオンにすることはできません。オンにすると、サイドバーのスコープピッカーの下に **kodus-config.yml applied**、**kodus-config.yml not found**、**kodus-config.yml unavailable** のいずれかが表示されます。
</Warning>

- Kody は、リポジトリのデフォルトブランチのルートからファイルを読み取ります。
- ファイルは、Global とリポジトリの Web 設定の上に適用されます。変更したいキーだけを記述してください。省略したキーは Web の値のままです。
- ネストされた設定は、キーごとにマージされます。`ignorePaths` のようなファイル内のリストは、Web のリストを置き換えます。
- ディレクトリスコープで上書きした設定は、リポジトリのファイル内の同じ設定よりも優先されます。[設定の継承とオーバーライド](/ja/how_to_use/code_review/configs/inheritance_overrides)を参照してください。
- 不明なトップレベルのキーは、エラーなしで破棄されます。設定が反映されないように見える場合は、下のサンプルとスペルを照合してください。
- `customAgents` と `knowledge` は、ファイルから読み取られません。レビューコメントにもその旨が表示されます。カスタムエージェントはアプリで設定してください。
- Kody Rules の設定と `customMessages` は、リポジトリ自身のファイルからは読み取られません。アプリで設定するか、同じファイルで指定できる[集中設定](/ja/how_to_use/code_review/configs/centralized_config)リポジトリで設定してください。

<Accordion title="kodus-config.yml のサンプル">
```yaml
version: 2.0

# general
automatedReviewActive: true
reviewCadence:
    type: 'automatic' # automatic | auto_pause | manual
    timeWindow: 15 # minutes, auto_pause only
    pushesToTrigger: 3 # auto_pause only
runOnDraft: true
reviewMode: balanced # balanced | heavy
riskAssessmentActive: false
riskCriteria: []
riskReviewRouting:
    noRisk: balanced
    riskFound: heavy
byokModel: '' # empty = inherit (directory -> repository -> the organization's main model)
pullRequestApprovalActive: false
approvalPolicies: []
approvalSensitivePaths: []
isRequestChangesActive: false # not available on GitLab
showStatusFeedback: true
enableCommittableSuggestions: true # GitHub only

# review scope
ignorePaths:
    - 'yarn.lock'
    - 'package-lock.json'
    - 'package.json'
    - '.env'
    - '**/*.json'
    # ...abbreviated: the shipped default lists about 1,100 patterns in total
ignoredTitleKeywords: []
baseBranches: [] # empty = the repository's default branch only

# linked repositories — Teams / Enterprise only, up to 3
linkedRepositories: []

# what to review
reviewOptions:
    bug: true
    performance: true
    security: true
    business_logic: true
repoInstructionsEnabled: false # check changes against CLAUDE.md / AGENTS.md / .cursor/rules
suggestionControl:
    severityLevelFilter: 'medium' # low | medium | high | critical
    applyFiltersToKodyRules: false
deterministicEvidence: # beta
    ciChecks: false
    tools:
        secrets: false
        dependencies: false
# businessLogic: see Business Logic Validation
# v2PromptOverrides: see Instructions & Personality

# what Kody writes
summary:
    generatePRSummary: true
    behaviourForExistingDescription: 'replace' # replace | concatenate | complement
    behaviourForNewCommits: 'none' # none | concatenate | replace
    customInstructions: ''
```
</Accordion>

<Note>
  デフォルト値の正典は、kodus-ai リポジトリの
  [`default-kodus-config.yml`](https://github.com/kodustech/kodus-ai/blob/main/default-kodus-config.yml)
  です。
</Note>
