サイドバーで **Code review → General**（ページタイトルは **General settings**）を開きます。レビューカテゴリと
重大度しきい値はもうここにはありません — **Code review → What to review** にあります。

## コア設定

<Note>
  Kodus には 3 つの設定レベルがあります：グローバル、リポジトリ、ディレクトリ。仕組みについては <a href="/ja/how_to_use/code_review/configs/inheritance_overrides">設定の継承とオーバーライド</a> を参照してください。
</Note>

### 設定の優先度

Web UI の代わりに、リポジトリルートの `kodus-config.yml` ファイルでレビュー設定を管理できます。

<Warning>
  **オプトインするまでこのファイルは無視されます。** デフォルトでは
  `kodusConfigFileOverridesWebPreferences` が `false` のため、Kody は `kodus-config.yml` を
  一切読み込みません — ファイルをコミットしただけでは何も起こりません。

  まず有効化してください：サイドバーの **Code review** グループ上部にあるスコープピッカーで
  リポジトリ（またはディレクトリ）を選択し、**Code review → General** を開いて **kodus Config
  File Overrides Web Preferences**（`kodusConfigFileOverridesWebPreferences`）を有効にします。この
  トグルはリポジトリとディレクトリのスコープにのみ存在します。それではじめてファイルが有効になります —
  その後、サイドバーのスコープピッカーの下に **kodus-config.yml applied**、**kodus-config.yml not found**、
  または **kodus-config.yml unavailable** のバッジが表示されます。
</Warning>

有効化すると、ファイルは Web 設定の上にマージされます。変更したいキーだけを書けばよく、
省略したものは Web 側の値がそのまま使われます。

<Note>
  **未知のキーは警告なく破棄されます。** 現在のスキーマに含まれないトップレベルのキーは、
  設定が適用される前に削除されます — エラーも警告も出ません。設定が効いていないように
  見える場合は、下のサンプルとスペルを照合してください。
</Note>

<Accordion title="kodus-config.yml のサンプル">
```yaml
version: 2.0

# general
automatedReviewActive: true
showStatusFeedback: true
kodusConfigFileOverridesWebPreferences: false
reviewCadence:
    type: 'automatic' # automatic | auto_pause | manual
    timeWindow: 15 # 分
    pushesToTrigger: 3
pullRequestApprovalActive: false
isRequestChangesActive: false # GitLab では利用できません
runOnDraft: true
ignorePaths:
    - 'yarn.lock'
    - 'package-lock.json'
    - 'package.json'
    - '.env'
    - '**/*.json'
    # ...省略：出荷時のデフォルトにはさらに数百のパターンが含まれます
ignoredTitleKeywords: []
baseBranches: []
enableCommittableSuggestions: true
byokModel: '' # 空 = 継承（ディレクトリ -> リポジトリ -> AI providers のメインモデル）

# linked repositories — Teams / Enterprise のみ。レビュー中にエージェントが参照できる関連リポジトリ。
# 推奨上限は 3、空 = 機能オフ。
linkedRepositories: []

# what to review：カテゴリ
reviewOptions:
    bug: true
    performance: true
    security: true
    business_logic: true

# what to review：決定的チェック（オプトイン、ベータ）
deterministicEvidence:
    ciChecks: false # 自分たちのパイプラインがすでに生成した CI 結果を読み取る
    tools: # 有効にしたツールでも、CI がすでに同等のものを実行している場合はスキップされる
        secrets: false # 変更されたファイルに対する認証情報スキャン
        dependencies: false # この PR が追加または更新する依存関係の既知の CVE

# what to review：重大度しきい値
suggestionControl:
    applyFiltersToKodyRules: false
    severityLevelFilter: 'medium' # low | medium | high | critical

# what Kody writes：PR サマリー
summary:
    generatePRSummary: true
    behaviourForNewCommits: 'none'
    behaviourForExistingDescription: 'replace'
    customInstructions: ''

# kody rules
ideRulesSyncEnabled: false
kodyRulesGeneratorEnabled: true
kodyLearningExcludedReviewers: []
kodyKnowledgeApproval:
    enabled: false

# what Kody writes：レビュー中のコメント + コメントの表示
customMessages:
    globalSettings:
        hideComments: false # GitHub のみ
        suggestionCopyPrompt: true # Bitbucket では利用できません
    errorReviewMessage:
        status: 'off' # off | active
        content: ''
    startReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: ''
    endReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: ''
```
</Accordion>

<Note>
  このサンプルは出荷時のデフォルトを反映しています。正典となるのは kodus-ai リポジトリの
  [`default-kodus-config.yml`](https://github.com/kodustech/kodus-ai/blob/main/default-kodus-config.yml)
  です。
</Note>

## レビュー動作

### 自動レビュー

Kody は PR が開かれたときに自動的にレビューするか、`@kody start-review` とコメントしたときのみレビューできます。
これは **Enable Automated Code Review** トグルです。

<Info>
  これは**初回レビュー**にのみ影響します。以降のコミットについては、下記のレビュー頻度を参照してください。
</Info>

#### レビュー頻度

**Enable Automated Code Review** がオンのときに、その下に表示されます。以降のコミットで Kody がレビューを
処理する方法：

<Tabs>
  <Tab title="自動">
    すべての新しいプッシュをレビュー。すべての変更に対して継続的なフィードバック。
  </Tab>
  
  <Tab title="自動一時停止">
    急速な連続プッシュ中にレビューを一時停止します（例：15 分以内に 3 回のプッシュ）。活発なコーディング中のスパムを防ぎます。
    
    デフォルト：3 回のプッシュ / 15 分（**Pushes to trigger pause** / **Time window (minutes)**）
  </Tab>
  
  <Tab title="手動">
    `@kody start-review` とコメントした場合のみフォローアップレビューを実行します。
  </Tab>
</Tabs>

### PR ワークフロー

#### PR の自動承認
**Enable Pull Request Approval** — 問題が見つからない場合、Kody は PR を承認します。

**対応プラットフォーム：** GitHub、GitLab、Bitbucket、Azure Repos、Forgejo

#### 変更のリクエスト
**Enable changing status of Review to 'Request Changes'** — クリティカルな問題が見つかった場合、Kody は
変更をリクエストします。

**対応プラットフォーム：** GitHub、Bitbucket、Azure Repos、Forgejo（接続済みのプラットフォームが GitLab のみの
場合、トグルは表示されません）

### スキップ条件

**Ignored files：** Kody がスキップするファイルの glob パターン（例：`**/*.js`）。フィールドにはいくつかの
パターンがチップとして表示されます。**Edit** をクリックすると **Ignored files** モーダルが開き、新しいパターンごとに
glob 構文が正しいかチェックされます。**Test a file** ボックスでは、あるパスが（どのパターンによって）無視されるのか、
レビューされるのかを確認できます。**Apply** はフィールドを更新するだけで、**Save settings** をクリックするまで
何も保存されません。デフォルト：`yarn.lock`、`package-lock.json`、`package.json`、`.env`、`**/*.json`、
およびビルド、バイナリ、IDE 関連ファイルの長いリスト。

**Ignore title keywords：** 特定のキーワードを含む PR をスキップします（大文字・小文字を区別しない、最大 100 文字）

**ベースブランチ：** *どの*ターゲットブランチをレビューするかを絞り込みます。

<Info>
  **空（デフォルト）はすべてのターゲットブランチをレビューする意味です** — `dev`/`release`/`master`
  といった組み込みのリストは存在しません。スコープを*狭めたい*ときだけエントリを追加してください。
  リストが空でなくなると、Kody はそれらのブランチ宛の PR だけをレビューします（リポジトリの
  デフォルトブランチは常に含まれます）。

  エントリは PR の**ターゲット**ブランチと照合され、専用の記法をサポートします：

  | エントリ | 一致するもの |
  | --- | --- |
  | `main` | ちょうど `main` 宛の PR |
  | `release/*` | `release/` 配下の任意のブランチ宛の PR（`*` は 1 階層のワイルドカード） |
  | `=main` | 完全一致。`main` と書くのと同じ |
  | `!staging` | `staging` 宛の PR を除外 |
  | `contains:hotfix` | 代わりに**ソース**ブランチと照合 — ヘッドブランチに `hotfix` を含む PR |

  複数のエントリが一致した場合は、より具体的なものが優先されます。各エントリは 100 文字以内で、
  使用できる文字は `a-z A-Z 0-9 / * - _ ! = :` のみ、`**` は使えません。
</Info>

**ドラフト PR：** **Enable Running on Draft Pull Requests**（`runOnDraft`）はデフォルトでオンなので、
ドラフトもレビューされます。オフにすると、PR が ready になるまでスキップされます。

### このページのその他の設定

- **Show Status Feedback** — レビューがスキップまたはブロックされたときに、Kody がステータスのフィードバック
  （絵文字リアクションまたはコメント）を表示します。
- **Enable committable suggestions**（Alpha、GitHub のみ）— コミットとして直接適用できるサジェスト。
- **Code review model**（リポジトリとディレクトリのスコープのみ。AI プロバイダーが設定されると表示）—
  このスコープでレビューに使用するモデル。デフォルトでは継承します（`byokModel`）。
- **Kody Language**（Global のみ）— Kody がコードレビューの返信で使用する言語。

## レビューカテゴリ（旧 Analysis Types）

Kody は 4 つのカテゴリでレビューします。カテゴリはもう **General** にはありません：
**Code review → What to review** の各スイッチで、または `kodus-config.yml` の `reviewOptions` で
個別にオン・オフを切り替えます。

- **Bug** — ロジックエラー、競合状態、null 参照、エッジケース、誤った挙動。
- **Security** — 脆弱性、インジェクション、認証の問題、データ露出、シークレット。
- **Performance** — N+1 クエリ、ホットパスでのアロケーション、キャッシュ不足、ブロッキング I/O。
- **Business Logic** — PR に紐づくビジネスルール・要件・受け入れ基準に対して実装を検証します。
  [ビジネスロジック検証](/ja/how_to_use/code_review/business_logic_validation) を参照してください。

<Note>
  Kody Rules はこれらのカテゴリの 1 つ**ではありません** — `reviewOptions` とは無関係に常に実行されます。
  [Kody Rules](/ja/how_to_use/code_review/configs/kody_rules) を参照してください。
</Note>
