BYOK（Bring Your Own Key）は、**すべてのプランで Kodus が LLM を使用するデフォルトの方法**です。Free、Teams、Enterprise のいずれでも同じです。自分のプロバイダーアカウントを接続し、使いたいモデルを追加して、各タスクを実行するモデルを選択します。トークンの料金はプロバイダーから直接請求され、キーは暗号化して保存されるため、平文で再表示されることはありません。

BYOK はセルフホストの Community でも使えます。**AI providers** で認証情報を管理できるのは [Owner](/ja/how_to_use/workspace_roles) です。Enterprise では、契約に基づいて Kodus がモデルを実行することもできます。

## BYOK の仕組み

BYOK は**プロバイダーファースト**です。プロバイダーを一度接続し、使いたいモデルをそれに追加して、Kody の各タスクをどのモデルで実行するかを選択します。接続は **AI providers** ページ（サイドバー → **AI providers**）で行い、このページには 2 つのタブがあります。タスクごとのモデルの選択は **Code review → Routing** で行い、ページヘッダーの **Configure routing** ボタンから開けます。

## プロバイダーを接続する

<Steps>
  <Step title="AI providers を開く">
    サイドバーで **AI providers**（[app.kodus.io/byok](https://app.kodus.io/byok)）を開きます。新しいワークスペースでは **Connect your first provider** が表示されます。
  </Step>

  <Step title="プロバイダーを選択する">
    プロバイダーのグリッドは 2 つに分かれています。

    - **Providers** — APIキーだけで接続できる標準のプロバイダー（OpenAI、Anthropic、Google、OpenRouter、Novita、Moonshot、Z.ai など）。
    - **Custom** — 独自のエンドポイントを指定したり、任意のモデルを実行したりするプロバイダー：**OpenAI-compatible**、**Anthropic-compatible**、**Google Vertex AI**、**Amazon Bedrock**、**Azure OpenAI**。カスタムエンドポイントには *Custom endpoint* のヒントが付いています。

    すでに接続済みのプロバイダーには **Connected · N models** と表示されます。
  </Step>

  <Step title="モデルを追加する">
    プロバイダーを選ぶと、そのモデル追加フォーム（**Add a … model**）が開きます。APIキーを一度貼り付けると（以降、そのプロバイダーに追加する各モデルで再利用されます）、モデルを選択します。

    - Kodus がプロバイダーのモデルを一覧表示できる場合は、ドロップダウンから選びます。目的のモデルがない場合は、**Type model manually** を選び、正確なモデル ID を入力します。
    - そうでない場合（カスタムエンドポイント、セルフホスト、またはプラットフォームキーが未設定の場合）は、正確なモデル ID を入力します。

    カスタムエンドポイント（OpenAI-compatible / Anthropic-compatible）では、先に **Base URL** も求められ、Azure OpenAI では **Resource endpoint** が求められます。**OpenAI** では、独自のプロキシやゲートウェイ向けに任意の **Base URL** が表示されます。空欄のままにすると OpenAI を直接呼び出します。ベース URL はエンドポイントのパスを含めずに貼り付けてください（`/chat/completions` は不要です）。`https://` を使用し、パブリックなアドレスに解決される必要があります。
  </Step>

  <Step title="Advanced settings を調整する（任意）">
    **Advanced (optional)** カードで **Advanced settings** を展開します。**Thinking / Reasoning**、**Temperature**、**Max output tokens**、**Max input tokens**、**Max concurrent requests** があります。デフォルト値はほとんどのプロバイダーで適切です。モデルごとに Kodus がロックまたは非表示にするフィールドについては、[Reasoning](/ja/how_to_use/byok/model_settings#reasoning-/-拡張思考) と [Temperature](/ja/how_to_use/byok/model_settings#temperature) を参照してください。
  </Step>

  <Step title="テストして保存する">
    **Test** をクリックして設定を確認するか、**Test & save** をクリックしてテストを実行し、成功した場合に保存します。キーは一度貼り付ければよいので、プロバイダーには好きなだけモデルを追加できます。
  </Step>
</Steps>

<Tip>
  **Add another provider** は、Providers タブからいつでも行えます。各プロバイダーは独自のキーを保持します。接続済みのプロバイダーでモデルを追加しても、キーを再度求められることはありません。
</Tip>

## 保存前にテストする

**Test** ボタンを使うには、先にモデルを選択しておく必要があります。選択したモデルに対して、レビューが行うのと同じ方法で組み立てた最小限の実リクエストを、キー、ベース URL、temperature、reasoning の設定を使って送信します。テストが成功すれば、その設定がそのまま動作することを意味します。失敗した場合は、誤ったモデル ID、制限されたキー、エンドポイントの問題など、プロバイダーのメッセージがその場で返されます。Google Vertex AI ではまずサービスアカウントを確認し、その後で同じリクエストを送信します。モデルを選択していない Amazon Bedrock では、認証情報のみを確認します。

Test は、設定したチューニングをモデル自身のルールに照らして検証し、モデルが無視する設定を保存する代わりに、具体的なメッセージを返します。

- モデルが無視する、または固定している temperature（[Temperature](/ja/how_to_use/byok/model_settings#temperature) を参照）。
- 常に reasoning を行い、無効にできないモデルで reasoning を **Off** にした場合。

テストは成功したものの、reasoning のオーバーライドや effort がリクエストのどのパラメーターにも反映されなかった場合は、その旨を伝える警告が結果に表示されます。

<Info>
  Test は実際のモデルを使用するため、**モデル ID のタイプミスは最初のレビューではなく Test の時点で検出されます**。レスポンスは `Model not found` で返されます。
</Info>

## 編集または削除する

**Providers** タブでは、**Edit model** でモデルの設定を、**Edit provider** でプロバイダーのキーを変更でき、**Remove model**（ゴミ箱アイコン）でモデルを削除できます。デフォルトまたはフォールバックのままになっているモデル、タスクに設定されているモデル、リポジトリやディレクトリで使用されているモデル、カスタムエージェントに固定されているモデルは削除できません。使用箇所が行に表示されるので、先にそれらを変更してください。最後のモデルを削除すると BYOK の接続が解除されます。環境変数で LLM が設定されている場合は Kodus がそれを使用し、設定されていない場合は、モデルを接続するまでレビューの実行が停止します。

## ルーティング：各タスクを実行するモデル

**Code review → Routing** を **Global** スコープで開きます（または **AI providers** の **Configure routing** から開きます）。**Models** カードで、組織のデフォルトを設定します。編集できるのは Owner のみです。ルーティングはフラットで、別のモデルを選択するまで、すべてのタスクがデフォルトを使用します。

- **Default model**：オーバーライドされない限り、すべてのタスクが使用する 1 つのモデルです。
- **Fallback model**：タスクのモデルが失敗したとき（無効または期限切れのキー、クレジット不足、アクセス拒否、プロバイダーのダウン。プロバイダー自身のリトライの後）に、Kody が呼び出しを 1 回だけ再実行する*別の*モデルです。設定しない場合、レビューは失敗します。
- **Risk assessment model**、**Balanced model**、**Heavy model**：[リスク評価](/ja/how_to_use/code_review/configs/risk)と各レビューモードで使用するモデルです。**Heavy model** は Teams と Enterprise で利用できます。いずれも、選択するまではデフォルトを使用します。
- **Other task models**（展開して表示）：**Kody Rules**、**PR Summary**、**Conversation**、**Business Rules**、**Custom Agents** は、それぞれ別のモデルを実行できます。たとえば、要約には安価なモデルを使えます。特定のタスクを実行できないモデルは、その行で無効化され、ツールチップが表示されます。

**Save settings** をクリックして保存するか、**Reset** をクリックして編集内容を破棄します。**Repository overrides** パネルには、個別のリポジトリ、ディレクトリ、カスタムエージェントに設定されたモデルが一覧表示されます。リポジトリやディレクトリのモデルは、**Routing** のスコープピッカーで設定します。[ルーティング](/ja/how_to_use/code_review/configs/routing)を参照してください。

<Note>
  接続済みのモデルが 1 つの場合、ルーティングはそのモデルに固定されます。ルーティングを意味のあるものにするには、2 つ目のモデルを接続してください。
</Note>

## サブスクリプションとコーディングプラン

一部のプロバイダーは、トークン従量課金の API アクセスの代わりに、またはそれに加えて、コーディングプランと呼ばれる定額のサブスクリプションを販売しています。Kodus は、他の API と同じ方法で、プランが提供するキーとエンドポイントを使って接続します。プロバイダーのウェブサイトやアプリでアカウントにサインインすることはありません。

プランをこの方法で利用できるかどうかはプロバイダー次第で、ルールはそれぞれ異なります。利用に頼る前に、次の点を確認してください。

- **利用規約を確認する。** プランによっては、プロバイダー自身のアプリからの利用のみを許可していたり、自動化された利用を制限していたりします。プロバイダーはいつでも変更でき、Kodus が代わりに確認することはできません。
- **制限を確認する。** プランでは、同時リクエスト数、リクエストのウィンドウ、月間の利用量に上限が設けられていることがよくあります。**Max concurrent requests** をそれに合わせて設定し、上限に達してもレビューが失敗しないよう、別のプロバイダーの **Fallback model** を追加してください。[同時実行数とレート制限](/ja/how_to_use/byok/model_settings#同時実行数とレート制限)を参照してください。
- **プラン専用のエンドポイントを使用する。** プランのキーは、プロバイダーのトークン従量課金の API ではなく、そのプランのエンドポイントでのみ動作することがよくあります。[Kimi と GLM](/ja/how_to_use/byok/providers#kimi（moonshot）と-glm（z-ai）を接続する) で違いを確認できます。

サブスクリプションプランの利用は自己責任です。プロバイダーがアクセスを制限または終了した場合、レビューは他のプロバイダー障害のときと同じように動作します。**Fallback model** を設定していればそちらに切り替わり、設定していなければ失敗します。

## Kodus credits

Kodus Cloud のワークスペースで **Kodus** プロバイダーのアルファ版を利用できる場合は、**AI providers** で **Kodus** を選ぶと、API キーなしでモデルを追加できます。**Kodus credits** で残高をチャージします。利用分はモデルに表示されたトークン単価で残高から差し引かれます。プラットフォーム手数料は支払い前にチャージ画面で確認できます。

**Configure routing** でそのモデルに割り当てるタスクを選びます。残高がなくなると、Kodus のモデルを使うレビューはチャージするまで一時停止します。独自のプロバイダーキーを使うモデルは引き続き利用できます。

## Advanced settings

各モデルのフォームには、任意の **Advanced settings** カードがあります。reasoning、temperature、出力と入力の上限、同時実行数を設定できます。デフォルト値はほとんどのプロバイダーに適しています。[モデル設定](/ja/how_to_use/byok/model_settings)を参照してください。必要になる前に知っておきたい設定が 2 つあります。

### Custom JSON override

Kodus にフィールドがないプロバイダーのオプションを使うには、**Thinking / Reasoning** で **Custom** を選択して JSON を貼り付けます。[Custom JSON override](/ja/how_to_use/byok/model_settings#custom-json-override)を参照してください。

### OpenRouter のプロバイダーを固定する

OpenRouter のモデルでは、**OpenRouter routing** で、そのモデルを提供する上流のプロバイダーを固定できます。[OpenRouter のプロバイダーを固定する](/ja/how_to_use/byok/providers#openrouter-のプロバイダーを固定する)を参照してください。

### ルーティング戦略

- デフォルトとフォールバックには**別のプロバイダー**を使用します（例：デフォルトは Anthropic、フォールバックは Google）。特定のプロバイダーの障害から保護できます。
- 同時実行数の上限が厳しいサブスクリプション（GLM Coding Plan の Lite/Pro、Kimi Code Plan）は、単独で使う構成には向きません。バーストする PR で処理が滞らないよう、トークン従量課金のフォールバックと組み合わせてください。
- 重いタスク（コードレビュー）は最も強力なモデルに、軽いタスク（要約、チャット）は **Code review → Routing** の **Other task models** でより安価なモデルにルーティングします。
