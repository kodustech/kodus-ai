## 概要

シングルサインオン（SSO）を使用すると、チームは SAML 2.0 を通じて、アイデンティティプロバイダーから Kodus にサインインできます。

Owner が **Organization → SSO** で SAML SSO を設定します。

## はじめに

<Steps>
    <Step title="SSO 設定にアクセス">
        サイドバーで **Organization → SSO**
        （[app.kodus.io/organization/sso](https://app.kodus.io/organization/sso)）を開きます。
        SSO は Enterprise プラン（およびトライアル中）で利用できます。その他のプランでは、ページにロックされたプレビューが表示されます。
    </Step>

    <Step title="IdP の設定を入力">
        **SAML SSO Configuration** で、**Enable SAML SSO** をオンにして設定を表示し、IdP の設定（**IDP Issuer**、**SSO URL**、**X.509 Certificate**）を入力します。これらは手動で入力するか、IdP の **Metadata URL (optional)**（その後 **Fetch**）またはメタデータ XML ファイル（**Upload Metadata XML File**）を提供することで入力できます。

        <Info>
            これらの値は通常、IdP のドキュメントまたは管理コンソールで確認できます。
        </Info>
    </Step>

    <Step title="IdP で Kodus を SP として設定">
        エンティティ ID（**Service Provider Entity ID**、デフォルトは `kodus-orchestrator`）と組織の **Callback URL**（どちらも SSO 設定ページに表示されます）を提供することで、IdP で Kodus を SP として設定します。

        名前 ID フォーマットがメールに設定されていることを確認してください。

        <Warning>
            IdP の SP 設定で署名証明書を無効にしてください。
        </Warning>
    </Step>

    <Step title="ドメインを検証">
        **Allowed Domains** にメールドメインを追加し（gmail.com などのパブリックドメインは使用できません）、それぞれで **Verify** をクリックします。**Verify Enterprise Domain** で、そのドメインのメールアドレスを入力すると検証リンクが届きます（セルフホストインスタンスでは即座に検証されます）。SSO を有効にするには、各ドメインが **Verified** と表示されている必要があります。
    </Step>

    <Step title="SSO をテストして有効化">
        **Test connection** をクリックし、IdP でのログインを完了します。SSO を有効として保存できるのは、テストが成功した後だけです。そのため、IdP の設定やドメインを変更した後は、もう一度テストを実行してください。テストが成功したら、**Enable SAML SSO** をオンにして **Save settings** をクリックします。
    </Step>

</Steps>

## オプション設定

### 属性マッピング

IdP から Kodus ユーザーへの以下の属性をマッピングして、ユーザーエクスペリエンスを向上させることができます。

-   名（First Name）、`firstName` にマッピング
-   姓（Last Name）、`lastName` にマッピング

## サインイン

サインインページでメールアドレスを入力します。そのドメインで SSO が有効になっている場合、Kodus はパスワードを求める代わりに **Continue with SSO** を表示し、IdP に移動します。

誰かが SSO で初めてサインインすると、Kodus はメール確認のステップなしで、**Contributor** ロールでその人のアカウントを組織内に作成します。オーナーは、後から **Organization → Subscription → Workspace members** でロールを変更できます。[ワークスペースロール](/ja/how_to_use/workspace_roles) を参照してください。
