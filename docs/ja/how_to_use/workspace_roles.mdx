<Note>
**ワークスペースメンバーと PR ライセンス**: これらは完全に別々のものであり、互いに影響しません。

- **ワークスペースメンバー**: Kodus の設定を行う管理者（無制限）
- **PR ライセンス**: Kody のレビューを受ける Git 組織の開発者（プランによる）
</Note>

## PR ライセンスについて

PR ライセンスは、直近数ヶ月に PR をオープンした開発者に基づいて、Git リポジトリから自動的に検出されます。

**開発者が表示されないのはなぜですか?** 開発者が PR ライセンスのカウントに表示されない場合、その開発者が PR をオープンしているリポジトリに Kody がインストールされていないことを意味します。

**例:** 設定を管理するワークスペース管理者が1人で、20人の開発者が自動レビューを受けることができます。すべてのプランには無制限の PR が含まれています — プランはどの開発者がレビューアクセスを取得するかを決定するだけです。

## 概要

Kodus ワークスペースは**ロールベースのアクセス制御（RBAC）**をサポートしており、組織内のユーザー権限とアクセスレベルを管理できます。各ワークスペースメンバーには、特定の権限と機能を持つ4つの異なるロールのいずれかを割り当てることができます。

## 利用可能なロール

各ロールはワークスペース内で異なるレベルのアクセスと機能を提供します:

### Owner（オーナー）

ワークスペースとすべてのリソースへの**完全な管理アクセス**。すべてのリポジトリのすべての設定を表示、編集、削除できます。



### Billing Manager（請求マネージャー）

請求/サブスクリプション管理へのアクセスと、ほとんどの設定への表示アクセスを持つ**財務・請求管理**アクセス。コードレビュー設定への編集アクセスはありません。

### Repository Admin（リポジトリ管理者）

**リポジトリ管理**アクセス。組織全体のすべての設定、プルリクエスト、Issue、Cockpit、プラグインを表示できます（読み取り専用）。さらに、自分に割り当てられたリポジトリのコードレビュー設定と Kody Rules を編集できます。

### Contributor（コントリビューター）

組織全体への**読み取り専用アクセス**。コントリビューターは、すべてのリポジトリの設定、Kody Rules、プルリクエスト、Issue を表示できます（リポジトリの割り当ては不要）が、何も編集することはできません。Cockpit、トークン使用量、請求、ユーザー管理は管理者専用のままです。

## ワークスペースメンバーの管理

ワークスペースのメンバーは **Organization → Subscription** の **Workspace members** タブで管理します — 別のメンバーページはありません。メンバーの招待、ロールの変更、削除ができるのは **Owner** のみです。

### 新しいメンバーの追加

1. サイドバーで **Organization → Subscription** を開き、**Workspace members** タブを選択
2. **Invite member** をクリック
3. **Workspace member invitation** でメンバーのメールアドレスを入力し、**Add to invite list** をクリック（複数人の場合は繰り返す）
4. **Send invites** をクリック
5. 招待されたメンバーは **Contributor** として参加します。ロールは後から変更してください（下記参照）

### ワークスペースメンバーの自動参加

一致するメールドメインを持つユーザーがワークスペースに自動的に参加できるように自動参加を有効にします。

**有効化の方法:**
1. **Organization → General**（[app.kodus.io/organization/general](https://app.kodus.io/organization/general)）に移動
2. **Auto Join** で **Enable Auto Join** をオンにし、ドメインを入力して保存
3. 現在は登録済みアカウントのメールドメインのみで機能
4. 異なるドメインが必要ですか? コミュニティでお問い合わせください

**仕組み:**
- メールドメインでサインアップしたユーザーは組織への参加を選択できます
- 参加を選択した後、メールを確認する必要があります
- 自動参加するすべてのユーザーは **Contributor** ロール（組織全体への読み取り専用アクセス）で入ります
- Owner として、編集権限が必要な場合にのみロールを調整します

### メンバーロールの変更

1. **Organization → Subscription → Workspace members** に移動
2. ロールを変更するメンバーを見つける
3. **Role** 列のセレクトを開く
4. 新しいロール（**Owner**、**Billing Manager**、**Repo Admin**、**Contributor**）を選択
5. 変更は即座に有効になります

**Repository Admin** の場合は、ロールの横にある **+** ボタンで編集できるリポジトリを割り当てます。**Assign repositories** が開きます。

### メンバーの削除

1. **Organization → Subscription → Workspace members** で削除するメンバーを見つける
2. その行の **Actions** メニュー（3点）を開く
3. **Delete** を選択
4. ダイアログで **Remove** をクリックして確認

同じメニューには、**Needs approval** と表示されたメンバー向けの **Approve** と、メンバーの招待リンクを再度共有するための **Copy invite link** もあります。

## セキュリティに関する考慮事項

1. **最小権限の原則**: 常に必要最小限の権限を持つロールを割り当てる
2. **定期的な監査**: メンバーのロールを定期的に確認して必要に応じて調整
3. **アクセスレビュー**: ワークスペースのアクセスと権限の四半期ごとのレビューを実施
4. **即時の取り消し**: メンバーが組織を離れたらすぐにアクセスを削除

## トラブルシューティング

<AccordionGroup>
  <Accordion title="ワークスペースに新しいメンバーを招待できません">
    **解決方法:**
    - Owner ロールがあることを確認 — メンバーを招待できるのは Owner のみです
    - ワークスペースがシステムの制限に達していないかを確認
    - アカウントに正しい権限があることを確認
  </Accordion>

  <Accordion title="メンバーがコードレビュー設定を編集できません">
    **解決方法:**
    - メンバーが特定のリポジトリに対して Repository Admin または Owner ロールを持っていることを確認
    - Repository Admin の場合は、そのリポジトリが割り当てられていることを確認（**Workspace members** の **Role** 列にある **Assign repositories**）
    - メンバーのロール割り当てが正しいことを確認
  </Accordion>

  <Accordion title="チームメンバーに請求情報が表示されません">
    **解決方法:**
    - メンバーが Owner または Billing Manager ロールを持っていることを確認
    - ワークスペースで請求機能が有効になっているかを確認
    - メンバーのアクセスが制限されていないことを確認
  </Accordion>

  <Accordion title="メンバーが Cockpit 機能にアクセスできません">
    **解決方法:**
    - メンバーが Repository Admin または Owner ロールを持っていることを確認（Cockpit は Contributor や Billing Manager には表示されません）
    - メンバーのロール割り当てが正しいことを確認
  </Accordion>

  <Accordion title="開発者が PR ライセンスに表示されません">
    **解決方法:**
    - この開発者が PR をオープンしているリポジトリに Kody がインストールされていることを確認
    - 開発者が直近数ヶ月に PR をオープンしているかを確認
    - PR ライセンスはワークスペースメンバーではなく Git アクティビティから来ることを覚えておく
    - リポジトリの Webhook が適切に設定されていることを確認
  </Accordion>
</AccordionGroup>
