<Note>
**ワークスペースメンバーと PR ライセンス**：これらは完全に別々のものであり、互いに影響しません。

- **ワークスペースメンバー**：ワークスペースに Kodus アカウントを持つユーザーです。各ユーザーのロールがアクセス権を決めます。すべてのプランで、メンバー数は無制限です。
- **PR ライセンス**：Kody のレビューを受ける Git 組織の開発者（プランによる）
</Note>

## PR ライセンスについて

**PR licenses** タブには、Kody がレビューするリポジトリでプルリクエストを開ける人が一覧表示されます。Git 組織のメンバーと、最近の PR の作成者が含まれ、ボットにはマークが付きます。ライセンスはそこで割り当てられ、シートの数はプランによって決まります。[ライセンスの自動割り当て](/ja/how_to_use/auto_license_assignment) を参照してください。

**開発者が表示されないのはなぜですか？** 一覧はコードプラットフォームから取得されます。**Refresh members** をクリックして再読み込みしてください。それでもその人が表示されない場合は、**Assign by git ID** を使って直接シートを割り当てます。コードプラットフォームが応答しない場合は、タブにその旨が表示され、シートの自動クリーンアップが一時停止します。

**例：** 設定を管理するワークスペース管理者が 1 人で、20 人の開発者が自動レビューを受けることができます。すべてのプランには無制限の PR が含まれています。有料プランでは、ライセンスによってどの開発者がレビューされるかが決まります。

## 概要

Kodus ワークスペースは **ロールベースのアクセス制御（RBAC）** をサポートしており、組織内のユーザー権限とアクセスレベルを管理できます。各ワークスペースメンバーには、特定の権限を持つ 4 つのロールのいずれかが割り当てられます。

## 利用可能なロール

各ロールは、ワークスペース内で異なるレベルのアクセスと機能を提供します。

### Owner（オーナー）

ワークスペースとすべてのリソースへの **完全な管理アクセス**。すべてのリポジトリのすべての設定を表示、編集、削除できます。



### Billing Manager（請求マネージャー）

**財務・請求管理** アクセス。プランと請求を管理し、開発者ライセンス、コードレビュー設定、Kody Rules、リポジトリ、プラグイン、トークン使用量、アクティビティログを表示できますが、編集はできません。プルリクエスト、Cockpit、CLI レビューにはアクセスできません。

### Repository Admin（リポジトリ管理者）

**リポジトリ管理** アクセス。組織全体のすべての設定、プルリクエスト、Issue、Cockpit、プラグイン、トークン使用量を表示でき（読み取り専用）、自分に割り当てられたリポジトリのコードレビュー設定、Kody Rules、Issue を編集できます。アプリでは **Repo Admin** と表示されます。

### Contributor（コントリビューター）

組織全体への **読み取り専用アクセス**。コントリビューターは、すべてのリポジトリの設定、Kody Rules、プルリクエスト、Issue を表示できます（リポジトリの割り当ては不要）が、何も編集することはできません。Cockpit、トークン使用量、請求、ユーザー管理は管理者専用のままです。

## ワークスペースメンバーの管理

ワークスペースのメンバーは **Organization → Subscription** の **Workspace members** タブで管理します。別のメンバーページはありません。メンバーの招待、ロールの変更、削除ができるのは **Owner** のみです。

### 新しいメンバーの追加

1. サイドバーで **Organization → Subscription** を開き、**Workspace members** タブを選択
2. **Invite member** をクリック
3. **Workspace member invitation** でメンバーのメールアドレスを入力し、**Add to invite list** をクリック（複数人の場合は繰り返す）
4. **Send invites** をクリック
5. 招待されたメンバーは **Contributor** として参加します。ロールは後から変更してください（下記参照）

### ワークスペースメンバーの自動参加

一致するメールドメインを持つユーザーがワークスペースに自動的に参加できるように、自動参加を有効にします。

**有効化の方法：**
1. **Organization → General**（[app.kodus.io/organization/general](https://app.kodus.io/organization/general)）に移動
2. **Auto Join** で **Enable Auto Join** をオンにし、ドメインを入力して保存
3. 現在は登録済みアカウントのメールドメインのみで機能
4. 異なるドメインが必要ですか？ コミュニティでお問い合わせください

**仕組み：**
- メールドメインでサインアップしたユーザーは、組織への参加を選択できます
- Kodus Cloud では、参加を選択した後、メールを確認する必要があります
- 自動参加するすべてのユーザーは **Contributor** ロール（組織全体への読み取り専用アクセス）で入ります
- Owner として、編集権限が必要な場合はロールを調整します

### メンバーロールの変更

1. **Organization → Subscription → Workspace members** に移動
2. ロールを変更するメンバーを見つける
3. **Role** 列のセレクトを開く
4. 新しいロール（**Owner**、**Billing Manager**、**Repo Admin**、**Contributor**）を選択
5. 変更は即座に有効になります

自分自身のロールは変更できません。ロールの変更とメンバーの削除は、組織の Owner に通知されます。

**Repository Admin** の場合は、ロールの横にある **+** ボタンで編集できるリポジトリを割り当てます。**Assign repositories** が開きます。

### メンバーの削除

1. **Organization → Subscription → Workspace members** で削除するメンバーを見つける
2. その行の **Actions** メニュー（3 点）を開く
3. **Delete** を選択
4. ダイアログで **Remove** をクリックして確認

同じメニューには、**Needs approval** と表示されたメンバー向けの **Approve** と、メンバーの招待リンクを再度共有するための **Copy invite link** もあります。

## セキュリティに関する考慮事項

1. **最小権限の原則**：常に必要最小限の権限を持つロールを割り当てる
2. **定期的な監査**：メンバーのロールを定期的に確認して必要に応じて調整
3. **アクセスレビュー**：ワークスペースのアクセスと権限の四半期ごとのレビューを実施
4. **即時の取り消し**：メンバーが組織を離れたらすぐにアクセスを削除

  <Accordion title="ワークスペースに新しいメンバーを招待できません">
    メンバーを招待できるのは Owner のみです。Owner であるにもかかわらず **Invite member** が無効になっている場合は、**Organization → Subscription → Workspace members** でロールを確認してください。
  </Accordion>

  <Accordion title="メンバーがコードレビュー設定を編集できません">
    - メンバーが Repo Admin または Owner であることを確認してください。Billing Manager と Contributor は設定を表示できますが、編集はできません。
    - Repo Admin の場合は、そのリポジトリが割り当てられていることを確認してください（**Workspace members** の **Role** 列にある **Assign repositories**）。
  </Accordion>

  <Accordion title="チームメンバーに請求情報が表示されません">
    **Organization → Subscription** は、Owner と Billing Manager にのみ表示されます。Repo Admin と Contributor には表示されません。
  </Accordion>

  <Accordion title="メンバーが Cockpit にアクセスできません">
    Cockpit は Repo Admin と Owner に表示され、Contributor や Billing Manager には表示されません。Cockpit には Teams または Enterprise プランも必要です。[プランとライセンス](/ja/how_to_use/pricing) を参照してください。
  </Accordion>

  <Accordion title="開発者が PR ライセンスに表示されません">
    - **PR licenses** タブで **Refresh members** をクリックし、その開発者が Git 組織に属しているか、Kody がレビューするリポジトリで最近 PR を開いていることを確認してください。
    - 一覧にない人にシートを割り当てるには、**Assign by git ID** を使ってください。
    - 覚えておいてください：PR ライセンスは Git プロバイダーから取得され、ワークスペースメンバーからではありません。
  </Accordion>
</AccordionGroup>
