---
title: "Kody Issues"
description: "Kody Issues 機能で未実装の提案を追跡・管理します。"
---

**Kody Issues** は、Pull Request のクローズ時に**実装されなかった** Kody の提案の最新リストを保持し、コードの変更に応じてそれらをクローズします。単独で動作し、**Auto-create issues** スイッチでオフにできます。

ライセンスのないセルフホスト環境を含むすべてのプランで、Owner、Repo Admin、Contributor は ⌘K のコマンドパレットから **Issues** を開けます。鍵アイコンと **Teams** タグが付いていても一覧を開けます。

[Cockpit にアクセスできる場合](/ja/how_to_use/cockpit/overview)は、**Issues** タブで一覧とオープン中の Issue 数を確認できます。

一覧には **Status**、**Severity**、**Category**、**Title**、**Repository**、**File**、**Age**、**#PR(s)** が表示されます。初期設定ではオープン中の Issue が表示されます。

Owners、Repo Admins、Contributors はすべてのリポジトリの Issue を閲覧できますが、Billing Managers はできません。Owners はすべての Issue を変更でき、Repo Admins は割り当てられたリポジトリの Issue のみ変更でき、Contributors は変更できません。

ターミナルで Issue を確認する場合は、[`kodus issues`](/ja/how_to_use/cli/commands#kodus-issues) の利用条件とフィルターを参照してください。

## Issue の作成方法

<Note>
  Issue は PR が**クローズ**されたときにのみ作成され、PR のオープン時やレビュー中には作成されません。GitLab と Azure Repos では、マージされた PR のみが対象です。
</Note>

- PR がクローズされると、Kody はその PR で行った提案のうち実装されなかったものを取り出し、それぞれについてリポジトリにリンクされた **Issue** を作成します。各 Issue には、元の説明、ファイル、重要度、カテゴリが保持されます。
- 同じファイルのオープン中の Issue がすでに同じ問題を扱っている場合、Kody は重複を作成せず、その Issue に新しい提案を追加します。**#PR(s)** には、関係したすべての PR が表示されます。
- これには、最小重要度に満たない、またはコメント数の上限を超えたために Kody が投稿しなかった提案も含まれます。誤りである、重複している、またはカテゴリがオフになっているという理由で Kody が破棄した提案は、Issue になりません。

<Warning>
  **Per PR** の Kody Rules は Issue を生成しません。ファイルレベルの提案のみが、追跡可能な Issue を作成します。
</Warning>

## Issue の解決方法

PR がクローズされるたびに、Kody はその PR が変更したファイル上のオープン中の Issue を、現在のコードと照らし合わせて確認します。

- コードにその問題がなくなっていれば、Issue は **Resolved** になります。
- ファイルが削除されていれば、Issue は **Dismissed** になります。

この処理は **Auto-create issues** がオフの場合でも実行されるため、既存の Issue はクローズされ続けます。

## Issue の操作

行をクリックすると Issue の詳細パネルが開き、リポジトリ、PR、ファイルへのリンク、説明、**Team feedback from PR reactions**（👍 / 👎 の数）が表示されます。**J** / **K** で Issue 間を移動でき、**Share** で Issue へのリンクをコピーできます。

### ステータス

- **Open**：対応が必要です。
- **Resolved**：問題がコードからなくなったときに Kody が設定します。
- **Dismissed**：関連がありません。提案がチームに当てはまらない場合は手動で設定します。ファイルが削除された場合は Kody も設定します。

ステータスは、詳細パネル上部のセレクターから変更します。

### 重要度

各 Issue には、提案の重要度から始まる重要度（`Critical`、`High`、`Medium`、`Low`）があります。チームの優先順位に合わせて、詳細パネルから変更できます。

### フィルター

リスト上部の **Filters**（ボタンには有効なフィルターの数が表示されます）を開くと、**Status**、**Severity**、**Category**、**Title**、**Repository**、**File path**、**PR numbers** で絞り込めます。**Set as default filters** は、このブラウザで Issues を開くたびにフィルターを適用し、**Reset to default filters** で元に戻せます。
