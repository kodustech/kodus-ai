ライセンスの自動割り当て機能は、組織内のデベロッパーライセンスの管理を簡素化します。各開発者にライセンスを手動で割り当てる代わりに、Kodus がアクティブなコントリビューターにライセンスを自動的に割り当てることができます。

シートを使う有料プランの組織と、ライセンスのあるセルフホスト環境で利用できます。Owner が **Subscription → PR licenses** で設定します。

## 仕組み

有料プランでは、Kodus はレビューしようとしている各プルリクエストの作成者を確認します。**Auto-assign licenses** がオンの場合、次のように動作します。

-   **最初の PR はシートなしでレビューされます。** Kodus は、作成者について記録している PR の件数を数えます。
-   **2 件目の PR からは、空きがあれば Kodus がライセンスを割り当て**、レビューが実行されます。
-   **作成者がライセンスを持たず、割り当てもできない場合**（空きシートがない、または **Auto-assign licenses** がオフの場合）、レビューはスキップされ、Kodus はプルリクエストにリアクションします。GitHub と Forgejo では 👎 の絵文字、GitLab では 🔒 の絵文字、Azure DevOps と Bitbucket では 👎 のコメントです。このリアクションが表示されるのは、**Code review → General** で **Show status feedback** がオンの場合のみです。

ライセンスが適用されるのは、シートのある有料プランのみです。Free プランとトライアルにはライセンスがありません。[プランとライセンス](/ja/how_to_use/pricing)を参照してください。

## PR 作成者フィルター

Kody がレビューする作成者を決める 2 つのフィルターがあります。**Repositories** ページの **PR author filters** タブで設定します。

-   **Exclude PR authors:** 指定した作成者が作成した PR を Kody はレビューしません。
-   **Only these PR authors:** 指定した作成者が作成した PR のみを Kody がレビューし、それ以外の作成者の PR はレビューしません。

どちらのフィルターも、そのユーザーをライセンスの自動割り当ての対象からも外します。

-   **レビューなし:** フィルターで除外された作成者のプルリクエストはレビューされません。ただし、その作成者がライセンスを保持している場合は、ライセンスがフィルターより優先されます。
-   **無言ではなくスキップ:** Kody はスキップを「User is ignored by configuration」として記録し、その PR を **Kody skipped** に表示します。**Show status feedback** がオフでない限り、PR に 👀 も付けます（Azure DevOps と Bitbucket では 👀 のコメント）。これらの作成者に対して、ライセンスなしのリアクション（👎 や 🔒）は付けません。

これは、ボット、サービスアカウント、またはコードレビューを必要としないチームメンバーに役立ちます。PR を作成するボットは、Git インテグレーションの作成時に除外リストへ追加されます。

## 設定

ライセンスの自動割り当てを有効化・設定するには、次の手順に従います。

1. サイドバーで **Organization → Subscription** を開きます。
2. **PR licenses** タブのままにします。
3. **Auto-assign licenses** をオンまたはオフにします。
    - **Release seats automatically**（同じカード）は、メンバーが Git 組織を離れてから数日後（デフォルトでは 7 日）にライセンスを解放します。
    - **Release N unused seats** は、Git 組織にいなくなった人が保持しているライセンスを一覧表示し、1 回の操作で解放します。
    - **Assign by git ID** は、一覧にいない人にシートを割り当てます。
    - 作成者をフィルターするには、**Repositories → PR author filters** を使用します（[PR 作成者フィルター](#pr-作成者フィルター)を参照）。

2 つのトグルが表示されるのは、有効な有料プランまたはライセンス済みのセルフホストインスタンスがある場合のみで、シートを管理できるメンバー（Owner）にのみ表示されます。

GitLab では、シートを持つユーザーがメンバー一覧にいない場合、Kodus は接続済みプロジェクトで最近マージリクエストを作成したかを確認します。確認できた作成者のシートは維持されます。プロバイダーが確認を完了できない場合も、Kodus はシートを維持します。 この GitLab の確認処理は、セルフホスト版 2.2.11 より後に追加されました。
