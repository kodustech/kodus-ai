## PR サイクルタイムとは

PR サイクルタイムは、プルリクエストがオープンのままである期間、つまりオープンされてからクローズされるまでの時間を測定します。プロセスのレビューとマージのスピードを反映します。

Cockpit では、**Productivity** タブの **PR Cycle Time (p75)** カードと **PR Cycle Time** チャートです。

## 計算方法

```
PR Cycle Time = (PR Closed Time) - (PR Opened Time)
```

- 起点は最初のコミットではなく、PR のオープン日です。リベースされたブランチには古いコミットが含まれることがあり、数値が膨らんでしまうためです。PR がオープンされる前の時間については、[リードタイム内訳](/ja/how_to_use/cockpit/metrics/lead_time_breakdown)を参照してください。
- 選択した日付範囲内にクローズされた PR が対象で、マージされたものと、マージされずにクローズされたものの両方を含みます。
- クローズ後の時間（デプロイ、ユーザーによる採用）は数えられません。

カードには 75 パーセンタイル（P75）が表示されます。PR の 4 分の 3 は、この値より速くクローズされています。そのため、極端に長い外れ値に値が引っ張られることはありません。チャートには、週ごとの P75 が時間単位でプロットされます。

## カードの読み方

カードには、時間と分で表した P75、レベルのバッジ、同じ長さの前の期間の値と変化率が表示されます。フッターには、選択した範囲にかかわらず「Last 2 weeks was …」と表示されますが、その数値は前の期間のものです。バッジにカーソルを合わせると、レベルを確認できます。

| P75 サイクルタイム | レベル |
| --- | --- |
| 48 時間未満 | Elite |
| 48 から 84 時間 | High |
| 84 から 160 時間 | Fair |
| 160 時間超 | Need focus |

## 重要な理由

サイクルタイムが長い場合は、バッチサイズが大きい、レビュープロセスが長い、またはワークフローにボトルネックがあることを示している可能性があります。

## 改善方法

- 大きな変更を、より小さな PR（200〜400 行）に分割する
- レビューに対する明確な期待とガイドラインを設定する
- レビュー前に問題を検出するために、自動チェックを使用する
- レビューの作業負荷をチーム全体に分散する
- 開発中に早めにフィードバックを得る
