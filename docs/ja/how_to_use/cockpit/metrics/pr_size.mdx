## PR サイズとは

PR サイズは、プルリクエストで変更された行数の平均です。チームが作業をどのように分解しているかを示し、大きな PR はレビューが遅くなるサインであることが少なくありません。

Cockpit では、**Productivity** タブの **PR Size** カードです。

## 計算方法

```
PR Size = (Total lines changed in the PRs) ÷ (Number of PRs)
```

- 選択した日付範囲内にクローズされた PR が対象で、マージされたものと、マージされずにクローズされたものの両方を含みます。
- 変更された行とは、各 PR で追加および削除された行です。サイズが記録されていない PR は 0 行として数えられます。

たとえば、変更行数が 50、100、150 の 3 つの PR がある場合、平均 PR サイズは 100 行です。

## カードの読み方

カードには、平均、レベルのバッジ、同じ長さの前の期間の値と変化率（低いほど良好）が表示されます。フッターには、選択した範囲にかかわらず「Last 2 weeks was …」と表示されますが、その数値は前の期間のものです。バッジにカーソルを合わせると、レベルを確認できます。

| 変更行数 | レベル |
| --- | --- |
| 250 未満 | Elite |
| 250 から 400 | High |
| 400 から 600 | Fair |
| 600 超 | Need focus |

<Note>
  カードのタイトルは **PR Size (p75)** と表示されますが、値は上記のとおり平均です。
</Note>

## 重要な理由

- **レビューの質**：小さな PR のほうが、徹底的にレビューしやすい
- **デプロイの速度**：小さな変更のほうが、より頻繁にデプロイできる
- **リスク管理**：大きな変更ほど、バグのリスクが高い

## 改善方法

- 段階的なロールアウトのためにフィーチャーフラグを使用する
- ユーザーストーリーを、より小さく焦点を絞ったタスクに分割する
- PR のサイズに明確な上限を設ける（200〜400 行を推奨）
- 技術的なレイヤーではなく、垂直スライスで構築する
