## リードタイム内訳とは

リードタイム内訳は、PR の最初のコミットからクローズまでの時間を、コーディング時間、ピックアップ時間、レビュー時間の 3 つのフェーズに分解します。ワークフローのどこで遅くなっているかが分かります。

Cockpit では、**Productivity** タブの **Lead Time Breakdown** チャートです。週ごとに 1 本の積み上げバーで、**Coding Time**、**Pickup Time**、**Review Time** を時間単位で表示します。チャートの下の名前をクリックすると、そのフェーズの表示と非表示を切り替えられます。

## 計算方法

```
Coding Time = (Last Commit Time) - (First Commit Time)
Pickup Time = (PR Opened Time) - (Last Commit Time)
Review Time = (PR Closed Time) - (PR Opened Time)
```

- **Coding Time**：PR の最初のコミットから最後のコミットまで。PR のオープン後にプッシュされたコミットも含みます。
- **Pickup Time**：最後のコミットから PR がオープンされるまで。オープン後に新しいコミットが追加された PR では、負の値になります。
- **Review Time**：PR がオープンされてからクローズされるまで（マージされたかどうかは問いません）。

各週について、各フェーズは、その週にクローズされた PR の 75 パーセンタイル（P75）です。これにより、極端に長い外れ値に値が引っ張られることはありません。あるフェーズの値がちょうどゼロの PR（たとえば、コミットが 1 つだけの PR のコーディング時間）は、そのフェーズの P75 から除外されます。PR がオープンされる 30 日前までに行われたコミットのみが数えられます。リベースされたブランチ上の古いコミットは、通常は別の作業に属するためです。コミットデータのない PR は除外されます。

最初のコミットより前の時間（計画、設計）と、クローズ後の時間（デプロイ）は数えられません。

## 重要な理由

時間がどこに費やされているかを理解することで、プロセスの適切な部分を最適化できます。

- **Coding Time**：開発効率を示す
- **Pickup Time**：コードの完成からレビュー依頼までの間にあるワークフローのボトルネックを明らかにする
- **Review Time**：レビュープロセスの有効性を示す

## 改善方法

### コーディング時間の削減
- 作業を始める前に要件を明確にする
- 大きな機能を、管理しやすい部分に分割する
- 複雑な問題はペアで取り組む

### ピックアップ時間の削減
- コードが完成したらすぐに PR をオープンする
- PR の作成とセットアップを自動化する
- コードがレビューの準備ができたタイミングを定義する

### レビュー時間の削減
- レビュアーに明確な期待を設定する
- レビュー前に問題を検出するために、自動チェックを使用する
- レビューの負荷をチーム全体に分散する
- レビューコメントに迅速に対応する
- PR を小さく保つ
