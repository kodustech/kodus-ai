## バグ比率とは

バグ比率は、クローズされたプルリクエストのうち、バグ修正が占める割合です。デリバリーのどれだけが、機能の構築ではなく問題の修正に費やされているかを示します。

Cockpit では、**Productivity** タブの **Bug Ratio** カードです。DORA の変更失敗率ではありません。失敗したデプロイではなく、バグ修正の PR を数えます。

## 計算方法

バックグラウンドジョブが AI モデルに、各プルリクエストを**タイトルのみから** **Bug Fix**、**Feature**、**Refactor**、**Test** のいずれかに分類させます。PR の説明、ラベル、diff は使用されず、設定する項目もありません。

```
Bug Ratio = (PRs classified as Bug Fix) ÷ (PRs closed in the range) × 100
```

範囲は Cockpit 上部で選択した日付範囲で、クローズされた PR とは、マージされたもの、またはマージされずにクローズされたものを指します。まだ分類されていない PR は、合計には含まれますが、バグ修正としては数えられません。たとえば、15 件の PR のうち 3 件がバグ修正に分類された場合、バグ比率は 20% です。

選択した範囲と前の期間の両方で比率が 0% の場合、カードには 0% の代わりに **Once we have enough data, your metrics will appear here.** と表示されます。

## カードの読み方

カードには、パーセンテージ、レベルのバッジ、同じ長さの前の期間の値と変化率（低いほど良好）が表示されます。フッターには、選択した範囲にかかわらず「Last 2 weeks was …」と表示されますが、その数値は前の期間のものです。バッジにカーソルを合わせると、レベルを確認できます。

| バグ比率 | レベル |
| --- | --- |
| 5% 未満 | Elite |
| 5% から 10% | High |
| 10% から 20% | Fair |
| 20% 超 | Need focus |

## PR タイトルが重要な理由

読み取られるのはタイトルだけなので、内容がわかるタイトルのほうが、より正確な比率になります。

| 良いバグ修正のタイトル | 曖昧なタイトル |
| --- | --- |
| "Fix: User login fails with invalid credentials" | "Fix stuff" |
| "Resolve issue: API returns 500 error for large requests" | "Update code" |
| "Patch: Fix null pointer exception in user service" | "Improve performance" |

## 改善方法

- ユニット、統合、エンドツーエンドの各レベルでテストを増やす
- 本番前にリンターや静的解析ツールを使用する
- 大きな機能を、テスト可能な小さな部分に分割する
- より安全なデプロイのためにフィーチャーフラグを使用する
- 再発を防ぐためにポストインシデントレビューを実施する
