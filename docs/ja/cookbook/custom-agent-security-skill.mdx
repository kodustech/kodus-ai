## なぜスキルか

チームはすでに、コーディングアシスタント向けのエージェントスキルとしてセキュリティルールを管理しているかもしれません。カスタムエージェントはコードレビューでも同じスキルに従えます。変更が必要とするときにスキルを開き、参照ファイルを読み、各指摘が適用するルールを引用します。プルリクエストのターゲットブランチでスキルが変更されると、エージェントは設定を変えなくても新しいバージョンに従います。

例は、すべてのクエリを呼び出し元のワークスペースにスコープしなければならないマルチテナントのスケジューリング API です。

カスタムエージェントはベータ版で、Teams プランと Enterprise プラン、およびトライアル期間中に利用できます。セルフホストの Kodus では `BETA_FEATURES=true` も必要です。

## ステップ1 — リポジトリのスキル

```markdown .claude/skills/tenant-isolation/SKILL.md
---
name: tenant-isolation
description: Rules that keep one workspace's data out of another's. Use when changing endpoints, queries or background jobs.
---

# Tenant isolation

- Every query on a tenant table filters by `workspaceId` taken from the authenticated session, never from the request body or query string.
- Every new endpoint declares `@RequireWorkspaceRole(...)`; an endpoint without it is public.
- Background jobs receive `workspaceId` in their payload and pass it to every repository call.
- Logs never include tokens, passwords or full email addresses.

For the list of tenant tables, see references/tenant-tables.md.
```

```markdown .claude/skills/tenant-isolation/references/tenant-tables.md
# Tenant tables

bookings, calendars, invoices, members, resources
```

`name` には小文字、数字、ハイフンを使います（フォルダー名と異なる `name` はフォルダー名として読まれます）。`description` は必須です。

## ステップ2 — エージェントとしてインポートする

<Steps>
  <Step title="リポジトリの設定を開く">
    スコープピッカーでリポジトリを選び、**What to review → Custom agents → New agent** を開きます。
  </Step>
  <Step title="リポジトリからインポートする">
    タブにはデフォルトブランチで見つかったスキルが一覧表示されます。**tenant-isolation** をクリックします。
  </Step>
  <Step title="結果を確認する">
    エージェントはオフの状態で作成され、名前は **Tenant isolation reviewer**、スキルがリンクされ、次の instructions が設定されます。

    ```text
    Review the change against the team's "tenant-isolation" skill: load it, follow its rules and references, and report where the change departs from them. Cite the rule you apply.
    ```
  </Step>
</Steps>

## ステップ3 — instructions を磨く

スキルへの参照は残し、指摘にどんな証拠が必要かを追加します。

```text Instructions
Review the change against the team's "tenant-isolation" skill: load it, follow its rules and references, and report where the change departs from them. Cite the rule you apply.

Trace where workspaceId comes from in every query or repository call the change adds or edits. A finding must show the line where the value enters (session, body, query string, job payload) and the line where it is used.

Ignore tests and seed scripts. Do not report general security issues the skill does not cover; Kody's own review handles those.
```

| フィールド | 値 |
| --- | --- |
| **Files** | `src/api/**`, `src/jobs/**`, `src/repositories/**` |
| **Except** | `**/*.test.ts`, `src/db/seeds/**` |

## ステップ4 — 任意：プラグイン

課題管理ツールがプラグインとしてインストールされている場合は、**Tools → Plugins** でオンにします。提供されるのは読み取りツールだけです。プルリクエストの説明にチケットへのリンクがあれば、エージェントはそれを読み、変更がチケットの要求に沿っているかを確認できます。

## ステップ5 — コメント

| フィールド | 値 | 理由 |
| --- | --- | --- |
| **Format** | Inline comments | |
| **Minimum severity** | High | テナント間の漏えいと認証の欠落だけを対象にし、堅牢化のアイデアは対象外にします。 |
| **Suggested fix** | When confident | |

**Save settings** をクリックします。

## ステップ6 — 試してみる

エンドポイントを追加するプルリクエストで **Try it** を実行します。次を確認します。

- **Skills opened** に `.claude/skills/tenant-isolation` が表示されます。エージェントが必要とした場合は `references/tenant-tables.md` も表示されます。
- 残った指摘はスキルのルールを引用します。

```markdown
**Rule** (`.claude/skills/tenant-isolation/SKILL.md`):
> Every new endpoint declares `@RequireWorkspaceRole(...)`; an endpoint without it is public.
```

- 破棄された指摘には理由が表示されます。スキルが扱わない一般的なセキュリティ上の指摘は、エージェントの対象外として破棄されます。ここではそれが望ましい動作です。

エージェントをオンにします。あとで、オープン中のプルリクエストでセカンドオピニオンが欲しいときは、`@kody -v tenant-isolation-reviewer` とコメントします。

## チェックリスト

- [ ] `SKILL.md` に `name` と `description` がある
- [ ] 参照ファイルがスキルのフォルダー内にある
- [ ] Instructions に、指摘にどんな証拠が必要かが書かれている
- [ ] Minimum severity が、エージェントにどれだけ発言させたいかに合っている
- [ ] 既知のギャップを含むプルリクエストで試した

検出と予算の詳細は [Skills & docs](/ja/how_to_use/code_review/custom_agents_knowledge_and_tools#skills-&-docs) を参照してください。
