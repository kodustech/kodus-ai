## なぜカスタムプラグインか

カスタムプラグインを使うと、Kody はプルリクエストに回答する際に、ナレッジベース、インシデントダッシュボード、ポリシーエンジンなどの社内システムを読み取れます。レビュアーがスクリーンショットや古いスニペットをコメントに貼り付ける必要がなくなります。

<Callout icon="globe">
  Kodus がサポートするのは**リモート MCP サーバーのみ**です。サーバーは Kodus のインフラから到達可能でなければなりません。`localhost` やデスクトップの MCP エンドポイントは使えません。
</Callout>

## プラグイン情報を準備する

Plugins ページを開く前に、次の情報を集めておきます。

| フィールド | 重要な理由 |
| ----- | -------------- |
| **URL** | MCP エンドポイント。例：`https://acme-internal-tools.com/mcp` |
| **Protocol** | **HTTP** または **SSE**。 |
| **Authorization** | **None**、**Bearer Token**、**Basic Auth**、**API Key**（および設定先のヘッダー）、または **OAuth 2.0**（クライアント ID、または動的クライアント登録）。 |
| **Description and logo** | 任意。チームメンバーがプラグインを見分けやすくなります。 |

試せるリモート MCP サーバーをお探しですか？

- [Smithery.ai](https://smithery.ai/) は、デプロイ可能な MCP サービスをキュレーションしています。
- [Awesome Remote MCP Servers](https://github.com/sylviangth/awesome-remote-mcp-servers) は、コミュニティが管理するエンドポイントを一覧にしています。

## Kodus にプラグインをインストールする

<Frame caption="Plugins → Add Custom Plugin カード → Add Plugin でこのフォームが開きます">
  <img src="/images/custom-plugin.png" alt="Add Custom Plugin form" />
</Frame>

<Steps>
  <Step title="フォームを開く">
    サイドバーで **Plugins** を開きます。**Add Custom Plugin** カードで **Add Plugin** をクリックします。
  </Step>
  <Step title="入力する">
    ```text
    Plugin Name: Descriptive label (for example "Security Runbooks MCP")
    Description: What data it exposes (optional)
    Logo URL: Optional
    URL: https://your-domain.com/mcp
    Protocol: HTTP or SSE
    Authorization: None, Bearer Token, Basic Auth, API Key or OAuth 2.0
    Custom Headers: Any extra header your server needs (optional)
    ```

    **Create Plugin** をクリックします。
  </Step>
  <Step title="ツールを選んでインストールする">
    プラグインが開きます。OAuth 2.0 の場合は、まず **Authenticate with** プラグインをクリックします。**Selected tools** で、Kody に必要なツールだけを残し、**Install plugin** をクリックします。インストール済みのプラグインは、カードに **Installed** と表示されます。
  </Step>
</Steps>

**Selected tools** が 0 of 0 と表示される場合、Kodus はサーバーのツールを一覧取得できていません。プラグインを開いて **Edit Plugin** をクリックし、URL、プロトコル、認可を確認してください。

<Warning>
  Kody は、選択したどのツールでも呼び出せます。組織が信頼するエンドポイントだけをインストールし、Kody に必要なツールだけを選択してください。
</Warning>

## 接続を確認する

1. Kody が有効なリポジトリで、プルリクエストを開きます。
2. `@kody` に続けて、そのプラグインにしか答えられない質問をコメントします。

   ```
   @kody can you fetch the deployment checklist from our MCP and confirm whether feature flags are required?
   ```

3. Kody の返信を確認します。プラグインが返したデータが含まれているはずです。含まれていない場合は、**Plugins** ページでそのプラグインを開き、URL、プロトコル、認可を確認してください。

<Info>
  サーバーを構築せずに流れを試すには、`https://docs.kodus.io/mcp` をカスタムプラグインとして追加します。プロトコルは **HTTP**、認可は **None** です。
</Info>

## カスタムエージェントで使う

カスタムエージェントは、エージェントのページの **Tools → Plugins** でオンにすると、インストール済みのプラグインから読み取れるようになります。提供されるのは読み取りツールだけです。[Skills, docs and tools](/ja/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp) を参照してください。
