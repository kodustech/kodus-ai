Kodus は既存の IDE ルールファイルを自動的に同期・インポートし、チームが確立したコーディング標準と設定で Kody のコードレビューを強化できます。

## ルールファイル検出とは？

ルールファイル検出は、リポジトリ内の人気の AI コーディングツールとアシスタントからの設定ファイルを自動的に検出・インポートします。これにより、手動セットアップなしで Kody が既存のコーディング標準を理解して尊重できます。

## サポートされているルールファイル

Kodus は以下のルールファイルパターンを自動的に検出・インポートします：

### Cursor
- `.cursorrules` - メイン Cursor ルールファイル（レガシー）
- `.cursor/rules/**/*.mdc` - サブディレクトリの Cursor ルール

### GitHub Copilot
- `.github/copilot-instructions.md` - Copilot の指示
- `.github/instructions/**/*.instructions.md` - 詳細な指示ファイル

### Agentic（agents.md 規約）
- `AGENTS.md` - エージェント向けガイダンスの事実上の標準ファイル
- `.agents.md` / `.agent.md` - ドットファイルの派生形

### Claude
- `CLAUDE.md` - Claude 固有のルール
- `.claude/settings.json` - Claude の設定

### Windsurf
- `.windsurfrules` - Windsurf IDE のルール

### Sourcegraph Cody
- `.sourcegraph/**/*.rule.md` - Cody のルールファイル

### OpenCode
- `.opencode.json` - OpenCode の設定

### Aider
- `.aider.conf.yml` - Aider の設定
- `.aiderignore` - Aider の無視パターン

### 汎用/内部ルール
- `.rules/**/*` - 汎用ルールディレクトリ
- `.kody/rules/**` と `rules/**/*.md` - Kody 固有のルール（[リポジトリルール](/how_to_use/ja/code_review/configs/repository_rules) を参照 — LLM による書き換えなしでそのままインポートされます）
- `docs/coding-standards/**/*` - ドキュメントベースのコーディング標準

### 検出の詳細

- **ネストされたファイルも検出されます。** 上記のすべてのパターンは、リポジトリのルート**およびあらゆるサブディレクトリ**で照合されます。`services/billing/CLAUDE.md` はインポートされ、自動的に `services/billing/**` にスコープされます — ディレクトリごとのガイダンスファイル（モノレポでよくある慣習）がそのまま機能します。
- **大文字・小文字は区別しません。** `claude.md` と `CLAUDE.md` は同じものとして扱われます。
- **`@file` 参照はたどられます。** ルールファイルが標準の `@` 記法で別ファイルを参照している場合（例：`CLAUDE.md` 内の `@AGENTS.md`）、参照先の内容が取得されインポート時に含まれます（1 階層まで、1 ファイルあたり最大 5 参照、参照ファイルあたり 100KB）。
- **1 つのルールに複数のグロブを指定できます。** `app/**/*.rb,lib/**/*.rb` のようなパス（または [リポジトリルール](/how_to_use/ja/code_review/configs/repository_rules) のフロントマターにおける `path: []` のリスト）は、**いずれか**のグロブに一致するファイルにルールを適用します。

## 仕組み

### 初期セットアップ
1. **自動同期を有効にする**：設定で「リポジトリからルールを自動同期」オプションをトグルします
2. **初回同期モーダル**：初回同期を行うかどうかを確認するモーダルが表示されます
3. **リポジトリスキャン**：確認すると、Kodus はサポートされているルールファイルのためにリポジトリ全体をスキャンします
4. **ルール生成**：LLM が見つかったファイルを処理し、対応する Kody ルールを自動的に作成します

### 継続的な同期
- **自動更新**：プルリクエストがクローズされると自動的に同期が行われます
- **ファイルの変更が検出される**：
  - **新しいルールファイル** → 新しい Kody ルールを作成
  - **変更されたルールファイル** → 既存の Kody ルールを更新
  - **削除されたルールファイル** → 対応する Kody ルールを削除

### 手動同期（トグル無効時）

自動同期を有効にせずに個別のルールファイルを同期できます：

1. ルールファイルの任意の場所に `@kody-sync` を追加します
2. 変更をコミットします
3. Kody はその特定のファイルのみを同期します

これにより、すべてのファイルの自動同期を有効にせずにルールを選択的に同期できます。

### ファイルを除外する（`@kody-ignore`）

ルール／ガイダンスファイルをリポジトリに残したまま、Kody が Kody Rules に変換しないようにするには、ファイル内のどこかに `@kody-ignore` を追加します：

1. ルールファイルのどこかに `@kody-ignore` を追加（大文字・小文字は区別しません）
2. 変更をコミット

次回の同期で Kody はそのファイルを**スキップ**し、**そこから作成された Kody Rules も削除**します。あとで `@kody-ignore` マーカーを外す（または `@kody-sync` を追加する）と、ルールは自動的に戻ります。`CLAUDE.md` や `AGENTS.md` のような社内スタイル文書を、レビューで強制されるルールにせずリポジトリに置いておきたい場合に使います。

<Warning>
IDE ルールファイルから作成された Kody ルールを手動で編集した場合、対応するファイルが変更されて次回同期されると、変更が上書きされます。
</Warning>

## 同期とルール評価の確認（セルフホスト）

セルフホストのデプロイでは、API のログに grep しやすいマーカーが出力されます：

- `[kody-rules-sync]` — 実行ごとの同期サマリー：どのファイルがインポート・スキップ（理由付き）・削除されたか。
- `[kody-rules-eval]` — レビュー中のファイル単位の評価トレース：レビュー対象ファイルごとに、どのルール（uuid + タイトル）がプロンプトに選ばれたか。

```bash
docker logs kodus_api 2>&1 | grep "kody-rules-sync"
docker logs kodus_api 2>&1 | grep "kody-rules-eval"
```

UI 上では有効なのに、期待するファイルの `[kody-rules-eval]` に一度も現れないルールがある場合は、その **Path** グロブを確認してください — ルールはパスに一致するファイルでしか実行されません。

## ルールの上限

**有効なライセンスなし**で稼働しているセルフホストインスタンス（Community Edition）は、1 回のレビューで最大 **10 ルール**（古い順）までしか評価しません。ライセンス済みのセルフホストとクラウドにはこの上限はありません。ライセンスのないインスタンスで 11 個目以降のルールが発火しない場合は、この上限が原因です。
