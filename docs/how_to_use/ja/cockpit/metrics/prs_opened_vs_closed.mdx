## オープン vs クローズの PR 数とは

このチャートは、同じ週に**オープンされた** PR 数と**クローズされた** PR 数を並べて表示します。
速度系のメトリクスでは分からないことを教えてくれます — チームは自分たちのスループットに
追いつけているのか、それともマージより速く仕事が積み上がっているのか。

## 算出方法

選択期間の各週について、次を数えます：

- **オープン** — その週に作成された PR。
- **クローズ** — その週にクローズされた PR（マージされたもの、それ以外の理由で閉じられたものを含む）。

両者は独立に数えられます。ある週にオープンされ 3 週間後にクローズされた PR は、1 週目の
「オープン」バーと 3 週目の「クローズ」バーの両方に現れます。これは意図的で、バックログを
可視化するための仕様です。

## 読み方

- **毎週クローズ ≈ オープン** — 定常状態。引き受けた分をチームが消化できています。
- **オープンが継続してクローズを上回る** — バックログが増えています。ボトルネックは通常、
  コードを書く能力ではなくレビューの capacity です。
- **クローズがオープンを大きく上回るスパイク** — たいていは棚卸しです。誰かが放置された PR を
  まとめて閉じた形。生産性の向上と読む前に確認してください。
- **両方が同時に落ち込む** — 多くは暦の影響（休暇、フリーズ、インシデント）で、行動の変化では
  ありません。

<Tip>
  [PR Cycle Time](/how_to_use/ja/cockpit/metrics/lead_time_for_changes) と併せて見てください。
  ここでの差の拡大とサイクルタイムの上昇が重なるときは、ボトルネックが開発ではなくレビューに
  あるという最も明確なサインです。
</Tip>

## 表示場所

Cockpit → **Productivity** タブの詳細チャートセクション。

<Note>
  このチャートは組織全体で非表示にできます。表示されない場合は
  [Cockpit の設定](/how_to_use/ja/cockpit/configuration) を確認してください。
</Note>
