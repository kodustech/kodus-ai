description: "把一个已连接的代码库变成组织级 Kody Rules 的来源,让同一套架构与编码标准在代码审查时应用到所有代码库。"
---

全局规则源让你把 Kodus 指向一个或多个已连接的代码库,并把其中的规则文件导入为**全局** Kody Rules。与[代码库规则](/how_to_use/zh/code_review/configs/repository_rules)(仅在其所在代码库生效)不同,从全局源导入的规则会在代码审查时应用到**所有**代码库。

当团队把架构与编码标准放在一个专门的 "standards" 代码库中,并希望这些标准在各处都被执行、又不想把规则文件复制到每个项目时,就用它。

## 工作原理

- 你选择若干已连接的代码库作为**源**。
- Kodus 使用与[规则文件检测](/how_to_use/zh/code_review/configs/rules_file_detection)相同的模式扫描每个源代码库(`CLAUDE.md`、`AGENTS.md`、`.cursor/rules/**`、`.kody/rules/**` 等)。
- 每个被发现的规则文件都会导入到**全局作用域**,并标记它来自哪个源代码库。
- 在任何代码库的审查过程中,这些全局规则会与该代码库自身的规则一起应用(遵循[继承规则](/how_to_use/zh/code_review/configs/rules_inheritance))。

<Info>
只有已在你的 git 设置中连接的代码库才能作为全局源。这样可以为已连接代码库保持单一可信来源,并通过下文描述的 Pull Request 触发器确保导入的规则保持最新。
</Info>

## 设置

1. 打开 **Settings → Code Review → Kody Rules**,切换到 **global** 视图。
2. 在 **Configuration** 标签页中找到 **Global rule sources**。
3. 点击代码库选择器,选择一个或多个已连接的代码库。
4. 点击 **Import selected**。

导入在后台运行。完成后,导入的规则会出现在你的全局 Kody Rules 列表中,每条都标注了其源代码库。

<Tip>
你可以选择任意数量的源代码库。Kodus 会导入在每个代码库中找到的规则文件。
</Tip>

## 保持规则最新

导入的规则会自动更新,也可按需更新:

- **合并时** —— 当源代码库中有 Pull Request 被合并时,其规则文件会被重新扫描,全局规则随之更新。未变更的文件会被跳过,因此开销很小。
- **Resync now** —— 使用 **Resync now** 按钮按需重新扫描所有已配置的源。这也涵盖直接推送到源代码库默认分支的改动。

<Note>
未经 Pull Request、**直接**推送到源代码库默认分支的改动不会被自动检测。直接推送后请使用 **Resync now** 来同步。
</Note>

## 移除一个源

把某个代码库从源列表中移除,会**删除从它导入的全局规则** —— 这些规则将不再在代码审查中生效。移除生效前会要求你确认。来自其他源的规则,以及你手工编写的规则,都不会受到影响。

## 源代码库不会被审查

仅作为全局规则来源使用的代码库,会被视为配置代码库而非代码本体。Kodus 会**跳过**在全局规则源中打开的 Pull Request 的代码审查,与[集中式配置](/how_to_use/zh/code_review/configs/kody_rules)代码库的处理方式相同。

## 套餐可用性

能否使用全局规则源取决于你的套餐:

| 套餐 | 可用性 |
|------|--------|
| **Free** | 不可用。 |
| **Trial** | 所有源代码库合计最多导入 **5 条全局规则**。只会导入最先找到的 5 条;达到上限后,除非你删除一些或升级,否则不会再导入更多规则。 |
| **付费**(云端)和**已授权的自托管** | 无限制。 |

<Info>
在 Trial 套餐下导入时,Kodus 会在你选择的代码库中导入**最先找到的 5 条规则**(按代码库文件顺序)。界面上的计数器会显示 5 条中已使用了多少,导入前的确认对话框会说明还会新增多少条。
</Info>
