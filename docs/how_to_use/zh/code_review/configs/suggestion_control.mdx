---
title: "审查过滤器"
description: "控制 Kody 在你的 PR 中发布多少反馈。"
---

审查过滤器决定 Kody 的哪些发现**真正会被发布**。你可以在
**Settings → Code Review → 对应代码库 → Review filters** 中找到它们,并且可以在全局、代码库或
目录级别设置 —— 参见
[配置继承与覆盖](/how_to_use/zh/code_review/configs/inheritance_overrides)。

## 最低严重性级别

Kody 会为每条建议分配严重性,只发布达到或高于你所选级别的建议。默认值为 **Medium**。

| 级别 | 涵盖内容 |
| --- | --- |
| **Low / All** | 提升代码质量的细微改进 —— 小幅优化、风格改进、细节打磨。 |
| **Medium**(默认) | 推荐但不紧急的中等改进:最佳实践,预防未来的技术债。 |
| **High** | 应在近期处理的重要问题 —— 关键的质量改进、潜在风险、实质性的技术问题。 |
| **Critical** | 需要立即处理、可能严重影响稳定性、安全性或功能的问题。 |

<Tip>
  大型 PR 上噪音过多,通常是严重性的问题,而不是数量的问题。在尝试其他手段之前先调到
  **High** —— 你会保留所有真正的 bug,只丢掉吹毛求疵的部分。参见
  [如何减少代码审查噪音](/knowledge_base/zh/how-to-reduce-code-review-noise)。
</Tip>

## 对 Kody Rules 应用过滤器

一个开关,**默认关闭**。

- **关闭** —— [Kody Rules](/how_to_use/zh/code_review/configs/kody_rules) 的发现会**绕过**严重性
  过滤器。团队自己编写的规则,无论被判定为何种严重性,都始终会被报告。
- **开启** —— Kody Rules 与其他建议一样,经过相同的严重性过滤器。

除非你的规则产生的噪音多于信号,否则请保持关闭。Kody Rule 的意义正在于:团队已经认定这件事很重要。

<Note>
  在 `kodus-config.yml` 中,这两项设置位于 `suggestionControl` 之下:

  ```yaml
  suggestionControl:
      severityLevelFilter: 'medium' # low | medium | high | critical
      applyFiltersToKodyRules: false
  ```

  请记住,只有在你启用 `kodusConfigFileOverridesWebPreferences` 之后,该文件才会被读取 ——
  参见[通用设置](/how_to_use/zh/code_review/configs/general)。
</Note>

## 减少噪音的其他方式

审查过滤器是一把钝刀。当你需要更有针对性的手段时:

- **Ignore paths** —— 完全跳过生成代码、锁文件和 vendored 目录。
  参见[通用设置](/how_to_use/zh/code_review/configs/general)。
- **分析类型** —— 在用不上的代码库中,直接关闭整个类别(例如 `performance`)。
- **目录级配置** —— 在 monorepo 中按文件夹应用更严格或更宽松的过滤器。
  参见[目录级配置](/how_to_use/zh/code_review/configs/directory_level)。
- **Kody Rules** —— 把团队真正在意的东西固化下来,让信号来自你们的标准,而不是泛泛的建议。
