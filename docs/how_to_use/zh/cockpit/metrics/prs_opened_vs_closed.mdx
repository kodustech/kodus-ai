## 什么是开启 vs 关闭的 PR 数

这张图把两个每周计数并排展示:同一周内有多少 pull request 被**开启**、多少被**关闭**。它回答了
所有速度类指标都回答不了的问题 —— 团队跟得上自己的吞吐量吗,还是工作积压得比合并更快?

## 我们如何计算

对所选周期内的每一周,我们统计:

- **开启** —— 该周创建的 pull request。
- **关闭** —— 该周被关闭的 pull request(合并或以其他方式关闭)。

两者独立计数:某个 PR 在某周开启、三周后关闭,会同时出现在第一周的"开启"柱和第三周的"关闭"柱上。
这是刻意为之 —— 正是它让积压变得可见。

## 如何解读

- **每周关闭 ≈ 开启** —— 稳态。团队消化得了自己承接的工作。
- **开启持续高于关闭** —— 积压在增长。瓶颈通常是审查能力,而不是写代码的能力。
- **关闭远高于开启的尖峰** —— 通常是一次清理:有人批量关闭了陈旧的 PR。在把它当作生产力提升
  之前,先确认一下。
- **两者同时骤降** —— 多半是日历因素(假期、封版、故障),而不是行为变化。

<Tip>
  与 [PR Cycle Time](/how_to_use/zh/cockpit/metrics/lead_time_for_changes) 一起看。这里的差距
  扩大,同时 cycle time 上升,是瓶颈在审查而非开发的最明确信号。
</Tip>
