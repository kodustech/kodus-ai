Os filtros de revisão decidem **quais** achados do Kody são efetivamente publicados. Você os
encontra em **Settings → Code Review → o repositório → Review filters**, e podem ser definidos
nos níveis global, de repositório ou de diretório — veja
[Herança e Sobrescrita de Configuração](/how_to_use/pt-br/code_review/configs/inheritance_overrides).

## Severidade mínima

O Kody atribui uma severidade a cada sugestão e publica somente as que estão no nível escolhido
ou acima dele. O padrão é **Medium**.

| Nível | O que cobre |
| --- | --- |
| **Low / All** | Melhorias pequenas de qualidade de código — otimizações menores, ajustes de estilo, refinamentos sutis. |
| **Medium** (padrão) | Melhorias moderadas, recomendadas mas não críticas: boas práticas e prevenção de dívida técnica futura. |
| **High** | Problemas relevantes que devem ser tratados no curto prazo — melhorias importantes de qualidade, riscos potenciais, questões técnicas substanciais. |
| **Critical** | Problemas que exigem atenção imediata e podem afetar seriamente estabilidade, segurança ou funcionamento. |

<Tip>
  Barulho demais num PR grande costuma ser problema de severidade, não de volume. Suba para
  **High** antes de tentar qualquer outra coisa — você mantém todo bug real e perde os
  nitpicks. Veja [Como reduzir o ruído na revisão](/knowledge_base/pt-br/how-to-reduce-code-review-noise).
</Tip>

## Aplicar filtros às Kody Rules

Um toggle, **desligado por padrão**.

- **Desligado** — os achados das [Kody Rules](/how_to_use/pt-br/code_review/configs/kody_rules)
  **ignoram** o filtro de severidade. Uma regra escrita pelo seu time é sempre reportada,
  independentemente da severidade atribuída.
- **Ligado** — as Kody Rules passam pelo mesmo filtro de severidade que as demais sugestões.

Deixe desligado, a menos que suas regras estejam gerando mais ruído do que sinal. O sentido de
uma Kody Rule é justamente o time já ter decidido que aquilo importa.

<Note>
  No `kodus-config.yml`, essas duas configurações ficam sob `suggestionControl`:

  ```yaml
  suggestionControl:
      severityLevelFilter: 'medium' # low | medium | high | critical
      applyFiltersToKodyRules: false
  ```

  Lembre-se de que o arquivo só é lido depois que você habilita
  `kodusConfigFileOverridesWebPreferences` — veja
  [Geral](/how_to_use/pt-br/code_review/configs/general).
</Note>

## Outras formas de cortar ruído

Filtros de revisão são um instrumento grosseiro. Quando precisar de algo mais direcionado:

- **Ignore paths** — pule código gerado, lockfiles e diretórios vendored por completo.
  Veja [Geral](/how_to_use/pt-br/code_review/configs/general).
- **Tipos de análise** — desligue uma categoria inteira (ex.: `performance`) nos repositórios
  em que ela não ajuda.
- **Config por diretório** — aplique filtros mais rígidos ou mais frouxos por pasta num
  monorepo. Veja [Configuração por Diretório](/how_to_use/pt-br/code_review/configs/directory_level).
- **Kody Rules** — codifique o que seu time realmente valoriza, para o sinal vir dos seus
  padrões em vez de conselhos genéricos.
