当您保存仓库选择时，Kodus 通常会自动创建 webhook。这需要仓库的管理员权限：在 Bitbucket Cloud 上，API 令牌还需要 `read:webhook:bitbucket` 和 `write:webhook:bitbucket` 范围；在 Bitbucket Data Center 上，则需要 **Repository admin** 权限。如果自动创建没有发生，**Repositories** 页面会列出该仓库及原因，您可以手动设置 webhook：

<Note>
  Webhook URL 必须能到达 Webhooks 服务（端口 3332）。仅当反向代理将 `/.../webhook` 路径转发到 webhooks 服务时，才能使用 API 域名。
</Note>

## Bitbucket Cloud

1. 导航到您的 Bitbucket 仓库
2. 单击左侧边栏中的 "Repository settings"
3. 选择 "Webhooks"
4. 单击 "Add webhook"
5. 是时候配置您的 webhook 了：

   - **Title**：Kodus Code Review
   - **URL**：您在 `.env` 文件中 `GLOBAL_BITBUCKET_CODE_MANAGEMENT_WEBHOOK` 下填写的 URL（以 `/bitbucket/webhook` 结尾）
   - **Status**：Active
   - **SSL/TLS**：勾选 Enable SSL verification
   - **Triggers**：选择这些事件：
        - Pull Request
            - Created
            - Updated
            - Merged
            - Declined
            - Comment created

6. 单击 "Save"

## Bitbucket Data Center

Bitbucket Data Center 的支持处于 alpha 阶段。打开仓库，进入 **Repository settings** > **Webhooks**，并创建一个 webhook，设置如下：

- **URL**：与上面相同的 `GLOBAL_BITBUCKET_CODE_MANAGEMENT_WEBHOOK` 值
- **Events**：pull request 事件 `pr:opened`、`pr:modified`、`pr:comment:added`、`pr:merged` 和 `pr:declined`

<Note>
  Kodus 只消费 pull request 事件：在 Cloud 上为 `created`、`updated`、`merged`、`declined` 和 `comment created`，在 Data Center 上为上面列出的五个事件。Repository、Issue 和构建状态触发器在到达后即被丢弃，因此不勾选它们可以减少 webhook 流量。Data Center 上的自动注册还会订阅 `pr:reviewer:updated`，Kodus 会接收并忽略它。
</Note>

### 向已打开的 pull request 推送

在 Data Center 上，向已打开的 pull request 推送新提交会以 `pr:from_ref_updated` 的形式到达。Kodus 不订阅它并会将其丢弃，因此推送不会启动审查。当标题、描述、目标分支或草稿状态发生变化时，会触发 `pr:modified`。除非最新提交对 Kodus 来说是新的，或者 pull request 退出草稿状态，否则 Kodus 会忽略它。要审查新提交，请在 pull request 上评论 `@kody start-review`。

在 Cloud 上，Kodus 以相同的方式处理 `pullrequest:updated`：仅当最新提交对 Kodus 来说是新的，或者 pull request 退出草稿状态时，才会启动审查。
