---
title: 创建 Webhook
description: "当自动注册未发生时,手动创建 Bitbucket webhook,并只勾选 Kodus 实际消费的 pull request 触发器。"
icon: webhook
---

Kodus 通常会自动创建 webhook。如果没有发生，请按照以下步骤手动设置：

<Note>
  Webhook URL 必须指向 Webhooks 服务（端口 3332）。仅当反向代理将 `/.../webhook` 路径转发到 Webhooks 服务时，才能使用 API 域名。
</Note>

1. 导航到您的 Bitbucket 仓库
2. 单击左侧边栏中的"仓库设置"
3. 选择"Webhooks"
4. 单击"添加 webhook"
5. 是时候配置您的 webhook 了：

   - **标题**：Kodus 代码审查
   - **URL**：输入您想要接收通知的 URL，即您在 `.env` 文件中的 `GLOBAL_BITBUCKET_CODE_MANAGEMENT_WEBHOOK` 下放置的 URL
   - **状态**：活动
   - **SSL/TLS**：勾选启用 SSL 验证
   - **触发器**：选择这些事件：
        - 拉取请求(Pull Request)
            - 已创建(Created)
            - 已更新(Updated)
            - 已合并(Merged)
            - 已拒绝(Declined)
            - 评论已创建(Comment created)

6. 单击"保存"

就是这样！您已成功设置 webhook 以在 Bitbucket 仓库中进行代码审查。

<Note>
  Kodus 只消费 Pull Request 事件 —— `created`、`updated`、`merged`、`declined` 和
  `comment created`。仓库、工单和构建状态触发器在到达后即被丢弃,不勾选它们
  可以减少 webhook 流量。

  在 Bitbucket Data Center 上,对应的事件是 `pr:opened`、`pr:modified`、
  `pr:reviewer:updated`、`pr:comment:added`、`pr:merged` 和 `pr:declined`。
</Note>
