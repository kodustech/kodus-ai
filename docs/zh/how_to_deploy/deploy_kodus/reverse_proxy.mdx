<Info>
如果负载均衡器或其他代理已经将流量路由到 Kodus，请跳过本页。
</Info>

要让你的 Kodus 实例可以被外部系统访问（Code Review webhook 和公开访问都需要），你需要用 Nginx 配置反向代理。它路由三个服务：Web 应用（3000 端口）、API（3001 端口）和 webhook 服务（3332 端口）。安装程序会在主机上发布这三个端口。

下面是适用于两个子域名的 Nginx 配置示例：

```nginx
# Server block for the Kodus Web Application
server {
    listen 80;
    server_name kodus-web.yourdomain.com; # Replace with your actual web app domain

    location / {
        proxy_pass http://localhost:3000; # Points to the Kodus Web App container
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        proxy_buffer_size 16k;
        proxy_buffers 8 16k;
        proxy_busy_buffers_size 32k;
    }
}

# Server block for the Kodus API
server {
    listen 80;
    server_name kodus-api.yourdomain.com; # Replace with your actual API domain

    client_max_body_size 50m;

    location ~ ^/(github|gitlab|bitbucket|azure-repos|forgejo)/webhook {
        proxy_pass http://localhost:3332; # Points to the Kodus Webhooks service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    location / {
        proxy_pass http://localhost:3001; # Points to the Kodus API service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

<Note>
  Webhook 由单独的服务处理（3332 端口）。如果你的 webhook URL 使用 API 域名，则需要 `location ~ ^/(github|gitlab|bitbucket|azure-repos|forgejo)/webhook` 块。当 `API_MCP_SERVER_ENABLED=true` 时，同一个 API 域名还会提供 `/mcp`。
</Note>

### 可选：专用 Webhook 子域名

如果你更希望为 webhook 使用单独的域名（例如 `kodus-webhooks.yourdomain.com`），请添加一个指向 webhook 服务的 server 块：

```nginx
server {
    listen 80;
    server_name kodus-webhooks.yourdomain.com;

    location / {
        proxy_pass http://localhost:3332; # Webhooks service
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

将此配置保存到 `/etc/nginx/sites-available/kodus`（或你选择的名称，例如，如果愿意，可将 `kodus-web` 和 `kodus-api` 保存为单独的文件），并创建符号链接以启用它：

```bash
sudo ln -s /etc/nginx/sites-available/kodus /etc/nginx/sites-enabled/
sudo nginx -t  # Test the configuration
sudo systemctl reload nginx  # Apply the changes
```

<Info>
  **让 `.env` 与公开 URL 保持一致。** 代理启动后，在 `.env` 中设置以下内容，并再次运行 `./scripts/install.sh` 以重新创建容器：

  - `NEXTAUTH_URL`、`API_FRONTEND_URL` 和 `API_USER_INVITE_BASE_URL`：Web 应用的公开 `https://` URL。
  - webhook URL（例如 `API_GITHUB_CODE_MANAGEMENT_WEBHOOK`）：能够访问 **webhook 服务**的 `https://` URL。仅当 `/.../webhook` 路由到 `3332` 端口时才使用 API 域名，否则请使用专用的 webhook 域名，例如 `https://kodus-webhooks.yourdomain.com/github/webhook`。
  - `API_URL`，仅在使用 SSO 时：公开的 API URL，例如 `https://kodus-api.yourdomain.com`。

  `WEB_HOSTNAME_API` 和 `WEB_PORT_API` 不指向代理。Web 应用的服务器通过 Docker 网络调用 API，因此请保持默认值（`localhost` 和 `3001`）。设置了 `WEB_PORT_API` 时，Web 应用会调用 `http://<WEB_HOSTNAME_API>:<WEB_PORT_API>`，因此使用 `443` 端口的公开 HTTPS 主机会失败。

  错误的 webhook URL 不会报错：仓库可以连接，但审查永远不会开始。
</Info>

### 启用 SSL（推荐）

对于生产部署，我们强烈建议使用 Let's Encrypt 设置 SSL：

```bash
# Install Certbot for Let's Encrypt
sudo apt-get update
sudo apt-get install certbot python3-certbot-nginx

# Obtain and install certificates (add -d for the webhooks domain if you use one)
sudo certbot --nginx -d kodus-web.yourdomain.com -d kodus-api.yourdomain.com # Replace with your actual domains
```

这会自动配置你的 Nginx 设置，为这些域名使用 HTTPS 并重定向 HTTP 流量。
