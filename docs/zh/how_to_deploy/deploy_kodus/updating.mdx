## Docker Compose

请在 `kodus-installer` 目录下运行以下步骤。

升级前，请备份 PostgreSQL、MongoDB 和 `.env` 文件。将当前的 `API_CRYPTO_KEY` 与备份一同保存，以便恢复后读取加密凭据。

<Steps>
  <Step title="更新安装器">
    ```bash
    git pull
    ```

    这样可以让 `docker-compose.yml`、`.env.example` 和必需变量列表与版本保持同步。将 `.env.example` 与您的 `.env` 进行比较，并添加您缺少的所有变量。
  </Step>
  <Step title="设置版本">
    在 `.env` 中，将 `IMAGE_TAG` 设置为您想要的版本，例如 `IMAGE_TAG=2.2.11`。各版本在 [kodus-ai releases 页面](https://github.com/kodustech/kodus-ai/releases)中以 _Self-Hosted Release_ 列出。如果没有设置 `IMAGE_TAG`，安装器会使用 `latest`，而 Docker 只有在您明确要求时才会重新拉取它。
  </Step>
  <Step title="拉取镜像并重新创建容器">
    ```bash
    ./scripts/validate-env.sh
    docker compose pull
    ./scripts/install.sh
    ```

    `api` 容器在启动时会运行数据库迁移。
  </Step>
  <Step title="检查结果">
    ```bash
    ./scripts/doctor.sh
    ```
  </Step>
</Steps>

<Warning>
  请勿在已有数据的安装上运行 `./scripts/generate-secrets.sh`。它会替换 `.env` 中的所有密钥，包括数据库密码和 `API_CRYPTO_KEY`。
</Warning>

您的数据存放在 Docker 卷中：`pgdata`（PostgreSQL）、`mongodbdata`（MongoDB）、`rabbitmq-data-prod`（RabbitMQ）和 `log_volume`。除 `rabbitmq-data-prod` 外，Docker 会为其余卷加上 Compose 项目名称前缀；`docker volume ls` 会显示它们。`docker compose down` 会保留这些卷，而 `docker compose down -v` 会删除它们。升级前请备份 PostgreSQL 和 MongoDB；迁移无法回退。

如果您使用 analytics worker，请在升级后使用 `docker compose --profile analytics up -d worker-analytics` 再次启动它。

## Kubernetes

Chart 版本会固定 Kodus 的发布版本。要升级到新版本，请升级 chart 或设置 `imageTag`；迁移任务会在 pod 滚动更新之前运行。参阅 [Kubernetes & OpenShift](/zh/how_to_deploy/deploy_kodus/kubernetes#升级)。
