为了带着正确的上下文审查 PR，Kodus 会把整个仓库解析为
**AST 图**（节点 + 边），并用它来获取 cross-file
上下文、验证建议并为 agent 提供输入。解析器在
**沙箱**中运行，因此它可以 `git clone`、安装依赖，并在与 API 进程隔离的环境中
执行 CLI。

同一个沙箱还通过已检出的仓库，为审查 agent 提供它们的文件工具（搜索、读取文件、
列出目录），无论是在审查中还是在 `@kody`
对话中。

本页说明你可以选择的沙箱模式、AST
图是什么，以及缓存如何让 PR 级审查保持快速。

## AST 图如何工作

Kodus 使用 [`@kodus/kodus-graph`](https://www.npmjs.com/package/@kodus/kodus-graph)，
这是一个遍历仓库并输出 JSON 图（函数、类、
文件、导入、调用）的 CLI。该 CLI **已预装在 Kodus 镜像中**
（包括 `kodus-ai-worker`），因此在 `local` 模式下无需额外的设置步骤。

生命周期：

1. **当你选择一个仓库时**（在设置期间，或之后在 UI 中添加仓库时）
   — Kodus 会将一个 `AstGraphBuild` 作业入队，它针对默认分支运行
   `kodus-graph parse --all`，将结果持久化到 Postgres（`ast_graph_*` 表），
   并将该仓库标记为已索引。这在后台进行 — 你不必等它
   完成就可以打开 PR。
2. **当 PR 合并到默认分支时** — webhook 处理程序
   会将一次增量重建入队，只重新解析变更的文件，
   并把差异合并到缓存的图中。变更超过
   500 个文件的合并会改为触发完整重建。
3. **每次 PR 审查时** — Kodus 加载缓存的图，只解析
   该 PR 涉及的文件，并为 agent 提供聚焦的子图。
   这是热路径；它从不重新解析整个仓库。

缓存是让大型仓库审查变得可行的关键：首次构建
在仓库接入时运行一次，此后每个 PR 都从 Postgres 读取。

## 沙箱模式

沙箱由 `.env` 中的 `SANDBOX_PROVIDER` 选择：

| 模式 | 作用 | 权衡 |
|---|---|---|
| **`local`** _（安装程序默认值）_ | 在 `worker` 容器内部运行 `kodus-graph`。Bun 和 CLI 已预装。 | 没有外部依赖。与 worker 容器共享 CPU 和内存。 |
| **`e2b`** | 每个作业启动一个远程 [E2B](https://e2b.dev) 沙箱。需要 `API_E2B_KEY`。 | 强隔离，可扩展到超大仓库。**付费的第三方服务。** |
| **`auto`** | 设置了 `API_E2B_KEY` 时使用 `e2b`，否则使用 `local`。 | 未设置 `SANDBOX_PROVIDER` 时得到的行为。 |
| **`null`** | 没有沙箱。 | 审查只能看到 diff：没有 cross-file 上下文，也没有代码图。 |

### 选择模式

- **刚开始使用，希望它“开箱即用”** → `local`。这是
  安装程序的默认值，不需要任何外部账号。
- **仓库非常大，或者你想要严格隔离** →
  `e2b`。在 [e2b.dev](https://e2b.dev) 注册，设置 `API_E2B_KEY`，并切换
  `SANDBOX_PROVIDER=e2b`。

设置了 `SANDBOX_PROVIDER=e2b` 却没有 `API_E2B_KEY` 时，审查会没有沙箱：
没有 cross-file 上下文，也没有代码图。当 `SANDBOX_PROVIDER=local` 时
只设置 `API_E2B_KEY`，仍会使用本地沙箱。

将 `SANDBOX_PROVIDER` 设为 `null` 即可关闭沙箱。沙箱关闭时，`./scripts/doctor.sh` 会报告警告。如果 `./scripts/validate-env.sh` 拒绝 `null`，请检查安装器的 `.env.example` 中列出的允许值。较早的安装器配置架构列出的是 `none`，worker 会将它视为 `auto`。

## 迁移现有的自托管安装

如果你是从早于 AST 图的版本升级而来，你
**已选择的仓库**还没有图 — 构建只会在**新**选择仓库时
自动触发。要为它们建立索引，请运行
安装程序附带的回填脚本：

```bash
# From the kodus-installer directory, with the stack running:
./scripts/backfill-ast-graph.sh
```

它会遍历实例中的每个团队，并为每个图状态为未设置、`pending` 或
`failed` 的已选仓库，将一个 `AstGraphBuild`
作业入队。构建在后台运行 — 你可以在它们完成期间继续使用 Kodus。

该脚本是**幂等的**：重新运行会跳过已经
`ready` 的仓库，从不重复入队 `building` 作业，并且你可以随时
停止和恢复。

常用标志：

```bash
./scripts/backfill-ast-graph.sh --org <id>          # restrict to one org
./scripts/backfill-ast-graph.sh --org <id> --team <id>  # one team only
./scripts/backfill-ast-graph.sh --force             # also rebuild ready graphs
./scripts/backfill-ast-graph.sh --limit 50          # cap jobs per team (default: 10)
./scripts/backfill-ast-graph.sh --dry-run           # list teams, enqueue nothing
```

你可以在 worker 日志中查看进度：

```bash
docker compose logs -f worker | grep -i ast-graph
```

## 配置

```bash
# Default for self-hosted — runs in the worker container.
SANDBOX_PROVIDER=local

# Or use E2B (paid) for stronger isolation.
SANDBOX_PROVIDER=e2b
API_E2B_KEY=your-e2b-api-key
```

在 [e2b.dev](https://e2b.dev) 注册 E2B，在控制台中生成 API 密钥，
然后把它放入 `.env` 并再次运行 `./scripts/install.sh`。

在 `local` 模式下，worker 克隆仓库的时间预算为 120 秒。克隆
超大 monorepo 时速度较慢，可能会超出这个预算，此时审查会
在没有沙箱的情况下运行。请以毫秒为单位提高该预算：

```bash
API_SANDBOX_CLONE_TIMEOUT_MS=300000
```

## 什么在哪里运行

```mermaid
flowchart LR
    pr[PR webhook] --> worker[worker]
    worker -->|local mode| sandbox_local[kodus-graph CLI<br/>inside worker container]
    worker -.->|e2b mode| sandbox_e2b[E2B remote sandbox<br/>kodus-graph runs there]
    sandbox_local --> graph[(Postgres • ast_graph_*)]
    sandbox_e2b --> graph
    graph --> agent[code-review agent]
```

## 资源规划

`local` 沙箱在 `worker` 容器内部运行 `git clone` 和 `kodus-graph parse`，
因此 worker 的内存限制同样适用于它们。Helm
chart 为 worker 设置了 `1536Mi` 的限制。如果 worker 在构建图时
因内存被杀死，请在 `services.worker.resources` 下提高该限制，或者
使用 `e2b` 在主机之外进行解析。

## 故障排除

**审查不包含 cross-file 上下文（`local` 模式）：**

在 worker 日志中检查克隆或 `kodus-graph` 解析错误：

```bash
docker compose logs -f worker | grep -iE "sandbox|kodus-graph"
```

worker 需要网络访问你的 Git 提供商才能克隆。`./scripts/doctor.sh` 会对所选仓库运行只读的
`git ls-remote`，并报告失败。

**`e2b` 作业挂起或无法启动：**

确认 `API_E2B_KEY` 已设置且有效：

```bash
docker compose exec worker sh -c 'if [ -n "$API_E2B_KEY" ]; then echo "API_E2B_KEY is set"; else echo "API_E2B_KEY is missing"; fi'
```

E2B 控制台会显示实时会话和配额使用情况。
