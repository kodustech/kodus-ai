<Note>
  本指南用于本地开发目的。对于生产部署，请参阅[部署 Kodus](/zh/how_to_deploy/deploy_kodus/generic_vm) 指南。
</Note>

<Note>
  `.env.example` 是与 Kodus Cloud 共用的模板，因此全新的 `.env` 默认带有
  `API_CLOUD_MODE=true` 和 `SANDBOX_PROVIDER=e2b`。要以自托管实例的方式运行，
  请在启动服务之前，在 `.env` 中设置 `API_CLOUD_MODE=false` 和
  `SANDBOX_PROVIDER=local`。当 `API_CLOUD_MODE=false` 时，到 `telemetry.kodus.io`
  的每日匿名心跳默认启用。如果您不希望本地实验出现在集群中，请设置
  `KODUS_TELEMETRY_DISABLED=true`。有关发送内容和检查方式，请参阅
  [匿名遥测](/zh/how_to_deploy/deploy_kodus/telemetry)。
</Note>

## 先决条件

- Node.js（固定版本请参阅 `.nvmrc`）
- pnpm
- Docker
- OpenSSL
- LLM API 密钥

<Note>
  kodus-ai 是一个 pnpm 工作区 — `pnpm-lock.yaml` 是仓库中唯一的锁文件。本地开发不支持 npm 和 yarn。
</Note>

## 运行项目

<Tabs>
  <Tab title="自动设置（推荐）">
      要进行快速自动设置，请使用我们的设置脚本：

      ```bash
      git clone https://github.com/kodustech/kodus-ai.git
      cd kodus-ai
      pnpm run setup
      ```

      <Warning>
        请使用 `pnpm run setup`，而不是 `pnpm setup` — 后者是 pnpm 自带的用于配置其主目录的命令，不会运行项目脚本。
      </Warning>

      此脚本将自动：
      - 检查所有必需的依赖项（Node.js、pnpm、Docker、OpenSSL）
      - 安装项目依赖项
      - 根据 `.env.example` 创建 `.env` 文件
      - 生成安全密钥
      - 创建 `kodus-backend-services` 和 `shared-network` Docker 网络
      - 打印后续步骤

      然后[连接模型](#连接模型)并启动服务：

      ```bash
      pnpm run docker:start
      ```

      **带外部集成（webhook 等）：**
      ```bash
      pnpm run docker:start
      pnpm run tunnel  # Creates public endpoint for external services
      ```

      <Info>
        数据库迁移和种子数据会在容器启动时**自动**执行 — 开发用 compose 文件将 `RUN_MIGRATIONS` 和
        `RUN_SEEDS` 默认设为 `true`。您无需单独执行这一步。

        如果您把它们设为 `false` 以自行管理，请在宿主机上运行 `pnpm run migration:run` 和
        `pnpm run seed`。
      </Info>

      一切运行后，在浏览器中打开 [http://localhost:3000](http://localhost:3000)。
  </Tab>
  <Tab title="手动设置">
      如果您更喜欢手动配置所有内容：

      ### 1. 克隆仓库

      ```bash
      git clone https://github.com/kodustech/kodus-ai.git
      cd kodus-ai
      ```

      ### 2. 安装依赖项

      ```bash
      pnpm install
      ```

      ### 3. 配置环境变量

      ```bash
      cp .env.example .env
      ```

      ### 4. 生成安全密钥

      为 `.env` 中的密钥生成安全的值：

      ```bash
      # JWT secrets and the NextAuth secret
      openssl rand -base64 32

      # Encryption key and code management secret
      openssl rand -hex 32

      # Webhook token (URL-safe)
      openssl rand -base64 32 | tr -d '=' | tr '/+' '_-'
      ```

      设置以下变量：
      - `API_JWT_SECRET`（使用 `openssl rand -base64 32`）
      - `API_JWT_REFRESH_SECRET`（使用 `openssl rand -base64 32`）
      - `API_CRYPTO_KEY`（使用 `openssl rand -hex 32`）
      - `CODE_MANAGEMENT_SECRET`（使用 `openssl rand -hex 32`）
      - `CODE_MANAGEMENT_WEBHOOK_TOKEN`（使用 `openssl rand -base64 32 | tr -d '=' | tr '/+' '_-'`）
      - `WEB_NEXTAUTH_SECRET` 和 `NEXTAUTH_SECRET`，两者取相同的值（使用 `openssl rand -base64 32`）

      ### 5. 设置 Docker 网络

      创建所需的 Docker 网络：

      ```bash
      docker network create kodus-backend-services || true
      docker network create shared-network || true
      ```

      ### 6. 连接模型

      请按照下面的[连接模型](#连接模型)操作。

      ### 7. 启动开发环境

      使用 Docker 启动服务：

      ```bash
      pnpm run docker:start
      ```

      此命令启动：

      - Kodus API
      - Worker（异步任务）
      - Webhooks 服务
      - Kodus Web 应用程序
      - PostgreSQL 数据库
      - MongoDB 数据库
      - RabbitMQ

      如需同时为外部服务创建公共端点：
      ```bash
      pnpm run tunnel
      ```

      ### 8. 首次设置

      无需操作 — API 容器会在启动时运行迁移和种子数据，因为
      `docker-compose.dev.yml` 将 `RUN_MIGRATIONS` 和 `RUN_SEEDS` 默认设为 `true`。

      <Accordion title="手动运行迁移">
        如果您在 `.env` 中设置了 `RUN_MIGRATIONS=false` / `RUN_SEEDS=false`（例如想自己控制），
        请在宿主机上运行：

        ```bash
        pnpm run migration:run   # OLTP database
        pnpm run seed            # initial data
        ```

        其他数据存储有各自的命令：

        ```bash
        pnpm run analytics:migration:run     # analytics warehouse
        pnpm run mcp-manager:migration:run   # MCP manager
        pnpm run mongo:migrate               # MongoDB
        ```
      </Accordion>

      ### 9. 服务端点

      访问服务：

      - Web UI：`http://localhost:3000`
      - API：`http://localhost:3001`
      - Webhooks：`http://localhost:3332`
      - RabbitMQ 管理界面：`http://localhost:15672`
      - PostgreSQL：`localhost:5432`，MongoDB：`localhost:27017`
      - API 调试端口：`9229`

## 连接模型

Kodus 需要一个模型来执行审查。请在启动服务之前选择一种方式：

- **在应用中。** 登录后，打开侧边栏中的 **AI providers**，并使用您的密钥连接提供商。参阅 [BYOK](/zh/how_to_use/byok)。
- **在 `.env` 中。** 整个实例使用一个模型：

  ```env
  API_LLM_PROVIDER=openai                  # openai, openai_compatible, anthropic, anthropic_compatible, google_gemini or google_vertex
  API_LLM_PROVIDER_MODEL="your-model-id"
  API_LLM_API_KEY="your-api-key"
  # API_LLM_BASE_URL="https://your-provider.example.com/v1"   # required for the *_compatible providers
  ```

  有关各提供商的要求，请参阅 [LLM Provider Configuration](/zh/how_to_deploy/deploy_kodus/generic_vm#llm-提供商配置)。在 **AI providers** 页面连接的模型会覆盖 `.env` 中的模型。

## 可选服务

`pnpm run docker:start` 不会启动 MCP Manager 或 analytics worker。可通过 `KODUS_DEV_EXTRAS` 添加它们：

```bash
KODUS_DEV_EXTRAS=mcp pnpm run docker:start          # MCP Manager (also set API_MCP_SERVER_ENABLED=true)
KODUS_DEV_EXTRAS=analytics pnpm run docker:start    # analytics worker
KODUS_DEV_EXTRAS=mcp,analytics pnpm run docker:start
```

## 开发工作流程

### 基本本地开发

1. **启动服务**：`pnpm run docker:start`（迁移和种子数据会自动运行）
2. **打开应用**：访问 `http://localhost:3000`
3. **健康检查**：`pnpm run dev:health-check`

### 带外部集成的开发

如果您需要测试与外部服务的集成（如 Git webhook）：

1. **启动服务**：`pnpm run docker:start`
2. **创建隧道**：`pnpm run tunnel`（创建公共端点）
3. **更新 webhook URL**：隧道命令会自动更新您的 `.env`
4. **配置 Git 提供商**：在 Git 提供商的 webhook 设置中使用隧道 URL
5. **测试集成**：触发 webhook 并监控日志

<Info>
  **隧道优势：**
  - 在本地测试真实的 webhook 集成
  - 调试外部服务通信
  - 与团队成员共享您的开发环境
  - 测试移动应用或其他外部客户端
</Info>

## 故障排除

### 快速健康检查

```bash
pnpm run dev:health-check
```

此健康检查验证：
- **服务**：API、worker、webhooks、web、PostgreSQL、MongoDB 和 RabbitMQ 容器
- **端口可用性**：Web（3000）、API（3001）、PostgreSQL（5432）、MongoDB（27017）、RabbitMQ（5672）
- **数据库设置**：迁移和种子数据
- **API 端点**：`/health/simple`、`/health` 和基本连接


### 手动验证

1. **检查 Web UI**：在浏览器中访问 `http://localhost:3000`
2. **检查 API 健康**：访问 `http://localhost:3001/health`
3. **检查 RabbitMQ**：访问 `http://localhost:15672`（默认凭据：`dev`/`devpass`，来自 `.env` 中的 `RABBITMQ_DEFAULT_USER` 和 `RABBITMQ_DEFAULT_PASS`）
4. **验证数据库连接**：检查日志以查看成功的数据库连接
5. **测试 webhook 端点**：您的 Git 提供商 webhook 应指向 `http://localhost:3332/[provider]/webhook`（或在反向代理将 `/.../webhook` 转发到 webhooks 服务时指向您的 API 域名）


### 设置脚本问题

如果自动设置脚本（`pnpm run setup`）失败：

**缺少依赖项：**
```bash
# Check if all required tools are installed
node --version
pnpm --version
docker --version
openssl version
```

**Docker 权限问题：**
```bash
# Add your user to the docker group (Linux)
sudo usermod -aG docker $USER
# Then log out and log back in
```

**网络创建错误：**
```bash
# Check if networks already exist
docker network ls | grep -E "kodus|shared"
# Remove conflicting networks if needed
docker network rm kodus-backend-services shared-network
```

### 常见问题

**端口冲突：**
- 确保端口 3000（Web）、3001（API）、3332（Webhooks）、5432（PostgreSQL）、27017（MongoDB）和 5672/15672（RabbitMQ）可用
- 在启动 Kodus 之前停止使用这些端口的其他服务

**环境变量未加载：**
- 验证项目根目录中存在 `.env` 文件
- 检查变量赋值中是否没有尾随空格
- 确保所有必需的安全密钥都已正确生成

**健康检查失败：**
- 运行 `pnpm run dev:health-check` 以获取详细诊断
- 检查容器是否完全启动（在 `pnpm run docker:start` 后等待 1-2 分钟）
- 验证数据库迁移和种子数据是否已加载
- 使用 `pnpm run docker:logs` 检查 API 日志以查找启动错误

**API 无响应：**
- 容器启动后 API 需要时间才能完全初始化
- 检查迁移和种子数据是否已加载
- 验证 `.env` 文件是否包含所有必需的变量
- 运行健康检查以查看哪些特定组件失败

**审查不运行：**
- 没有连接模型。打开 **AI providers**，或在 `.env` 中设置 `API_LLM_PROVIDER_MODEL` 和密钥。

**审查没有跨文件上下文：**
- `SANDBOX_PROVIDER=e2b` 且没有 `API_E2B_KEY` 时，审查会在没有沙箱的情况下运行。请设置 `SANDBOX_PROVIDER=local`。

**外部服务的 webhook 问题：**
- 使用 `pnpm run tunnel` 为外部 webhook 创建公共端点
- 更新 Git 提供商的 webhook URL 以使用隧道 URL
- 测试 webhook 集成时确保隧道正在运行
- 检查隧道日志以查找连接问题
