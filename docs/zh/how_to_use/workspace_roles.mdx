<Note>
**工作区成员 vs. PR 许可证**:这些是完全独立的,不会相互影响。

- **工作区成员**：在工作区中拥有 Kodus 账号的人员。每人的角色决定其访问权限，所有套餐均允许不限数量的成员。
- **PR 许可证**:来自您的 Git 组织并获得 Kody 审查的开发人员(基于您的套餐)
</Note>

## 了解 PR 许可证

**PR licenses** 标签页列出可以在 Kody 审查的代码库中打开拉取请求的人员:您 Git 组织的成员,加上近期的 PR 作者,机器人会被标记。许可证在那里分配给他们,而您的套餐决定有多少席位。请参阅[自动许可证分配](/zh/how_to_use/auto_license_assignment)。

**为什么开发人员没有显示?** 该列表来自您的代码平台。点击 **Refresh members** 重新加载。如果该人员仍未列出,请使用 **Assign by git ID** 直接为其分配席位。如果您的代码平台没有响应,该标签页会说明,并且自动席位清理会暂停。

**示例:**您可以有 1 个工作区管理员管理设置,而 20 个开发人员获得自动审查。所有套餐都包括无限的 PR;在付费套餐上,由许可证决定哪些开发人员会被审查。

## 概述

Kodus 工作区支持**基于角色的访问控制(RBAC)**,允许您管理组织内的用户权限和访问级别。每个工作区成员拥有四个角色之一,每个角色都有特定的权限。

## 可用角色

每个角色在工作区内提供不同级别的访问和功能:

### 所有者

对工作区及其所有资源的**完全管理访问权限**。可以查看、编辑和删除所有代码库的所有配置。

### 计费管理员

**财务和计费管理**访问权限。管理套餐和计费,并且可以查看开发者许可证、代码审查设置、Kody Rules、代码库、插件、token 用量和活动日志,但无法编辑它们。无法访问拉取请求、Cockpit 或 CLI 审查。

### 代码库管理员

**代码库管理**访问权限。可以查看整个组织的所有配置、拉取请求、工单、Cockpit、插件和 token 用量(只读),并且可以编辑分配给他们的代码库的代码审查配置、Kody Rules 和工单。在应用中显示为 **Repo Admin**。

### 贡献者

对整个组织的**只读访问权限**。贡献者可以查看所有代码库的配置、Kody Rules、拉取请求和工单(无需分配代码库),但无法编辑任何内容。Cockpit、token 用量、计费和用户管理仍仅限管理员。

## 管理工作区成员

工作区成员在 **Organization → Subscription** 的 **Workspace members** 标签页中管理——没有单独的成员页面。只有**所有者**可以邀请成员、更改角色或删除成员。

### 添加新成员

1. 在侧边栏中打开 **Organization → Subscription**,然后选择 **Workspace members** 标签页
2. 点击 **Invite member**
3. 在 **Workspace member invitation** 中,输入成员的电子邮件并点击 **Add to invite list**(如需邀请更多人,请重复此操作)
4. 点击 **Send invites**
5. 受邀成员以 **Contributor** 身份加入;之后可更改其角色(见下文)

### 工作区成员的自动加入

启用自动加入以允许具有匹配电子邮件域的用户自动加入您的工作区。

**如何启用:**
1. 转到 **Organization → General**([app.kodus.io/organization/general](https://app.kodus.io/organization/general))
2. 在 **Auto Join** 下,打开 **Enable Auto Join**,输入您的域名并保存
3. 目前仅适用于您注册的账户电子邮件域
4. 需要不同的域?在社区中联系我们

**工作原理:**
- 使用您的电子邮件域注册的用户可以选择加入您的组织
- 在 Kodus Cloud 上,他们必须在选择加入后确认电子邮件
- 所有自动加入的用户作为 **Contributor** 角色进入(对整个组织的只读访问权限)
- 作为所有者,如果他们需要编辑权限,请调整他们的角色

### 更改成员角色

1. 转到 **Organization → Subscription → Workspace members**
2. 找到您要更改角色的成员
3. 打开其 **Role** 列中的选择框
4. 选择新角色(**Owner**、**Billing Manager**、**Repo Admin** 或 **Contributor**)
5. 更改立即生效

您无法更改自己的角色。角色更改和成员删除会通知组织的所有者。

对于**代码库管理员**,请使用其角色旁边的 **+** 按钮分配他们可以编辑的代码库,该按钮会打开 **Assign repositories**。

### 删除成员

1. 在 **Organization → Subscription → Workspace members** 中,找到要删除的成员
2. 打开其所在行的 **Actions** 菜单(三个点)
3. 选择 **Delete**
4. 在对话框中点击 **Remove** 确认

同一菜单中还有 **Approve**(用于标记为 **Needs approval** 的成员)和 **Copy invite link**(用于再次分享成员的邀请链接)。

## 安全考虑

1. **最小权限原则**:始终分配具有最小必要权限的角色
2. **定期审核**:定期审查成员角色并根据需要进行调整
3. **访问审查**:每季度进行工作区访问和权限审查
4. **立即撤销**:成员离开组织时立即删除访问权限

## 故障排除

<AccordionGroup>
  <Accordion title="我无法邀请新成员到工作区">
    只有所有者可以邀请成员。如果您是所有者但 **Invite member** 被禁用,请在 **Organization → Subscription → Workspace members** 下检查您的角色。
  </Accordion>

  <Accordion title="成员无法编辑代码审查配置">
    - 确认该成员是代码库管理员或所有者。计费管理员和贡献者可以查看设置,但无法编辑。
    - 对于代码库管理员,检查该代码库是否已分配给他们(**Workspace members** 的 **Role** 列中的 **Assign repositories**)。
  </Accordion>

  <Accordion title="团队成员无法看到计费信息">
    **Organization → Subscription** 只对所有者和计费管理员可见。代码库管理员和贡献者看不到它。
  </Accordion>

  <Accordion title="成员无法访问 Cockpit">
    Cockpit 对代码库管理员和所有者可见,对贡献者和计费管理员不可见。Cockpit 还需要 Teams 或 Enterprise 套餐;请参阅[套餐与许可证](/zh/how_to_use/pricing)。
  </Accordion>

  <Accordion title="开发人员没有出现在 PR 许可证中">
    - 点击 **PR licenses** 标签页上的 **Refresh members**,并检查该开发人员是否属于您的 Git 组织,或最近是否在 Kody 审查的代码库中打开过 PR。
    - 使用 **Assign by git ID** 为未列出的人员分配席位。
    - 请记住:PR 许可证来自您的 Git 提供方,而不是工作区成员。
  </Accordion>
</AccordionGroup>
