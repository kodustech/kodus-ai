## 什么是开发者的 PR

开发者的 PR 统计每位团队成员**已关闭**的 pull request 数量，按周分组。它侧重于已完成的工作，让您可以了解产出以及其在团队中的分布情况。

在 Cockpit 中，它是 **Productivity** 标签页上的 **PRs Merged By Developer** 图表：每周一个堆叠条形，每位开发者一种颜色。将鼠标悬停在条形上可查看每位开发者的计数。

## 我们如何计算

```
Weekly PRs per Developer = COUNT(closed PRs) per developer per week
```

- PR 按其**关闭**的那一周计入，无论是已合并还是未合并即关闭。尽管图表的名称如此，Cockpit 并不区分两者。
- 开发者是 PR 作者在您的 Git 提供商上的用户名。
- 每周从周一开始。
- 打开的和草稿 PR、没有关闭日期的 PR，以及没有作者的 PR 不会被计入。

## 开发者活动与开发者的 PR

| | 开发者活动 | 开发者的 PR |
| --- | --- | --- |
| **统计对象** | 已打开的 PR | 已关闭的 PR |
| **日期依据** | 打开日期 | 关闭日期 |
| **状态筛选** | 无 | 仅已关闭的 PR |
| **呈现方式** | 表格，每周一列 | 每周的堆叠条形 |

## 需要牢记的背景

- 提交的 PR 较少但较大的开发者，可能同样高效。请将该图表与 [PR 大小](/zh/how_to_use/cockpit/metrics/pr_size)对照阅读。
- 产出会随工作类型、角色和项目阶段而变化。
- 参与审查或结对完成的工作在此处不可见。
