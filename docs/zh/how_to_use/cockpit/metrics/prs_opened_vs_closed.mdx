## 什么是开启 vs 关闭的 PR 数

这张图把两个每周计数并排展示：同一周内有多少 pull request 被**打开**、多少被**关闭**。它显示团队是否跟得上自己打开的工作，还是 pull request 积压得比关闭得更快。

## 我们如何计算

对于所选日期范围内的每一周：

- **Opened**：该周打开的 pull request，无论其当前状态如何。对于在其仓库连接之前就已打开、且不在连接时导入的 PR 之列的 PR，该日期是 Kodus 首次记录它的日期。
- **Closed**：该周关闭的 pull request，无论是已合并还是未合并即关闭。

两者独立计数：某个 PR 在某周打开、三周后关闭，会计入第一周的 **Opened** 柱和第四周的 **Closed** 柱。这正是让积压变得可见的原因。

## 如何解读

- **Closed 与 Opened 接近，周复一周**：稳态。团队关闭了它打开的内容。
- **Opened 连续数周高于 Closed**：积压在增长。
- **Closed 远高于 Opened**：通常是一批陈旧的 PR 被一次性关闭。在将其解读为生产力提升之前，请先确认。
- **两者同时下降**：通常是假期、封版或故障。

<Tip>
  请与 [PR 周期时间](/zh/how_to_use/cockpit/metrics/lead_time_for_changes)对照阅读。这里的差距扩大，同时周期时间上升，表明审查是瓶颈。
</Tip>

## 在哪里查看

Cockpit → **Productivity** 标签页，在详细图表区。每周从周一开始，您可以点击图表下方的名称来隐藏 **Opened** 或 **Closed**。

<Note>
  该图表可以对整个组织隐藏。如果您看不到它，请查看
  **Organization → Cockpit visibility**。参见 [Cockpit 配置](/zh/how_to_use/cockpit/configuration)。
</Note>
