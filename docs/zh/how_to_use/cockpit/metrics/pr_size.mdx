## 什么是 PR 大小

PR 大小是您的 pull request 中更改行数的平均值。它显示您的团队如何拆分工作，而大型 PR 往往是审查缓慢的迹象。

在 Cockpit 中，它是 **Productivity** 标签页上的 **PR Size** 卡片。

## 我们如何计算

```
PR Size = (Total lines changed in the PRs) ÷ (Number of PRs)
```

- 它涵盖在所选日期范围内关闭的 PR，无论是已合并还是未合并即关闭。
- 更改的行数是每个 PR 中添加和删除的行数。没有记录大小的 PR 按 0 行计算。

例如，如果您有 3 个 PR，分别更改了 50、100 和 150 行，则您的平均 PR 大小为 100 行。

## 读懂卡片

卡片显示平均值、一个级别徽章，以及相同长度的上一周期的值和百分比变化（越低越好）。无论选择了哪个范围，页脚都显示 "Last 2 weeks was …"；该数字对应的是上一周期。将鼠标悬停在徽章上可查看各级别：

| 更改行数 | 级别 |
| --- | --- |
| 少于 250 | Elite |
| 250 到 400 | High |
| 400 到 600 | Fair |
| 多于 600 | Need focus |

<Note>
  卡片标题显示为 **PR Size (p75)**，但其值是平均值，如上所述。
</Note>

## 为什么重要

- **审查质量**：较小的 PR 更容易彻底审查
- **部署速度**：较小的更改可以更频繁地部署
- **风险管理**：大型更改引入 bug 的风险更大

## 如何改进

- 使用功能标志进行增量发布
- 将用户故事分解为更小、更集中的任务
- 设置清晰的 PR 大小限制（推荐 200-400 行）
- 构建垂直切片而不是技术层
