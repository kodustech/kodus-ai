## 什么是 PR 周期时间

PR 周期时间衡量 pull request 保持打开状态的时长：从其被打开到被关闭。它反映了您的流程的审查与合并速度。

在 Cockpit 中，它是 **Productivity** 标签页上的 **PR Cycle Time (p75)** 卡片和 **PR Cycle Time** 图表。

## 我们如何计算

```
PR Cycle Time = (PR Closed Time) - (PR Opened Time)
```

- 它从 PR 的打开日期开始，而不是其第一次提交，因为变基后的分支可能带有会使数值虚高的旧提交。关于 PR 打开之前的时间，请参阅[交付时间细分](/zh/how_to_use/cockpit/metrics/lead_time_breakdown)。
- 它涵盖在所选日期范围内关闭的 PR，无论是已合并还是未合并即关闭。
- 关闭之后的时间（部署、用户采用）不会被计入。

卡片显示第 75 百分位数（P75）：四分之三的 PR 关闭得比这更快，因此异常长的离群值不会扭曲它。图表以小时为单位绘制每周的 P75。

## 读懂卡片

卡片以小时和分钟显示 P75、一个级别徽章，以及相同长度的上一周期的值和百分比变化。无论选择了哪个范围，页脚都显示 "Last 2 weeks was …"；该数字对应的是上一周期。将鼠标悬停在徽章上可查看各级别：

| P75 周期时间 | 级别 |
| --- | --- |
| 少于 48 小时 | Elite |
| 48 到 84 小时 | High |
| 84 到 160 小时 | Fair |
| 多于 160 小时 | Need focus |

## 为什么重要

较高的周期时间可能表明批量过大、审查过程冗长，或工作流中存在瓶颈。

## 如何改进

- 将大型更改分解为更小的 PR（200-400 行）
- 设定清晰的审查期望和指南
- 使用自动化检查在审查前捕获问题
- 在团队中分配审查工作负载
- 在开发过程中获得早期反馈
