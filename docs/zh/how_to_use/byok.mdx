BYOK(自带密钥)是 **Kodus 在所有套餐中使用 LLM 的默认方式**:免费版、团队版和企业版都一样。您连接自己的提供商账号、添加想要的模型,并为每个任务选择运行哪个模型。您的提供商直接向您收取 token 费用,您的密钥以加密方式存储,也不会以明文形式回显。

自托管 Community 也支持 BYOK。只有 [Owner](/zh/how_to_use/workspace_roles) 可以在 **AI providers** 中管理凭据。Enterprise 客户也可以按合同使用由 Kodus 管理的模型。

## BYOK 如何工作

BYOK 是**提供商优先**的:您连接一次提供商,把想要的模型添加到该提供商上,然后选择这些模型中的哪一个运行 Kody 的各个任务。连接位于 **AI providers** 页面(侧边栏 → **AI providers**),它有两个选项卡。按任务选择模型位于 **Code review → Routing**,页面顶部的 **Configure routing** 按钮会打开它。

## 连接提供商

<Steps>
  <Step title="打开 AI providers">
    在侧边栏中打开 **AI providers**([app.kodus.io/byok](https://app.kodus.io/byok))。在全新的工作区中,您会看到 **Connect your first provider**。
  </Step>

  <Step title="选择一个提供商">
    提供商网格分为两部分:

    - **Providers** — 只需一个 API 密钥即可连接的一等提供商(OpenAI、Anthropic、Google、OpenRouter、Novita、Moonshot、Z.ai……)。
    - **Custom** — 指向您自己端点或运行任意模型的提供商:**OpenAI-compatible**、**Anthropic-compatible**、**Google Vertex AI**、**Amazon Bedrock** 和 **Azure OpenAI**。自定义端点带有 *Custom endpoint* 提示。

    已经连接的提供商会显示 **Connected · N models**。
  </Step>

  <Step title="添加模型">
    选择一个提供商会打开它的添加模型表单(**Add a … model**)。粘贴一次 API 密钥(之后添加到该提供商的每个模型都会复用它),然后选择模型:

    - 如果 Kodus 能列出该提供商的模型，请从下拉菜单中选择。列表中找不到所需模型时，选择 **Type model manually** 并输入准确的模型 ID。
    - 否则(自定义端点、自托管,或未配置平台密钥时),请输入精确的模型 ID。

    自定义端点(OpenAI-compatible / Anthropic-compatible)还会先要求填写一个 **Base URL**,Azure OpenAI 则要求填写 **Resource endpoint**。**OpenAI** 会显示一个可选的 **Base URL**,用于您自己的代理或网关;留空则直接调用 OpenAI。粘贴不含端点路径的 base URL(不要带 `/chat/completions`)。它必须使用 `https://` 并解析到公网地址。
  </Step>

  <Step title="调整高级设置(可选)">
    在 **Advanced (optional)** 卡片中展开 **Advanced settings**:**Thinking / Reasoning**、**Temperature**、**Max output tokens**、**Max input tokens** 和 **Max concurrent requests**。对大多数提供商来说默认值都是合理的 — 关于 Kodus 针对每个模型锁定或隐藏的字段,请参见[推理](/zh/how_to_use/byok/model_settings#reasoning-/-extended-thinking)和[温度](/zh/how_to_use/byok/model_settings#temperature)。
  </Step>

  <Step title="测试并保存">
    点击 **Test** 检查配置,或点击 **Test & save** 运行测试并在成功后保存。您可以往该提供商上添加任意数量的模型;密钥只需粘贴一次。
  </Step>
</Steps>

<Tip>
  您可以随时从 Providers 选项卡 **Add another provider**。每个提供商保留自己的密钥;在已连接的提供商上启用更多模型时永远不会再次索要密钥。
</Tip>

## 保存前先测试

**Test** 按钮需要先选择一个模型。它会向该模型发送一个最小的真实请求,构建方式与审查相同,使用您的密钥、base URL、温度和推理设置。测试通过意味着这套配置确实可用;测试失败则会当场返回提供商的消息:模型 ID 错误、密钥受限或端点问题。Google Vertex AI 会先检查服务账号,再发出同样的请求。未选择模型的 Amazon Bedrock 只检查凭证。

Test 还会根据模型自身的规则检查您的调优,并返回具体消息,而不是保存一个模型会忽略的设置:

- 模型忽略或固定的温度(参见[温度](/zh/how_to_use/byok/model_settings#temperature))。
- 在始终推理且无法禁用的模型上将推理设为 **Off**。

当测试通过,但推理覆盖或强度没有对应到请求的任何参数时,结果会附带一条警告说明这一点。

<Info>
  由于 Test 使用真实模型,**模型 ID 中的拼写错误会在 Test 时被捕获**,而不是在您的第一次审查时:响应会返回 `Model not found`。
</Info>

## 编辑或移除

在 **Providers** 选项卡上,**Edit model** 更改模型的设置,**Edit provider** 更改提供商的密钥,**Remove model**(垃圾桶图标)移除模型。仍是默认模型或备用模型、已为某个任务设置、被某个仓库或目录使用,或固定在某个自定义 agent 上的模型无法移除。该行会列出它的使用位置,请先更改这些位置。移除最后一个模型会断开 BYOK:如果有通过环境变量设置的 LLM,Kodus 会使用它;否则在您连接模型之前,审查会停止运行。

## 路由:哪个模型运行哪个任务

在 **Global** 范围打开 **Code review → Routing**(或在 **AI providers** 上点击 **Configure routing**)。**Models** 卡片为您的组织设置默认值。只有 Owner 可以编辑;路由是扁平的,因此每个任务都使用默认模型,直到您为它选择另一个模型。

- **Default model**:每个任务都使用的那一个模型,除非被覆盖。
- **Fallback model**:当任务的模型失败时(密钥无效或过期、没有额度、访问被拒绝,或提供商宕机(在其自身重试之后)),Kody 会在一个*不同的*模型上重新运行该调用一次。没有备用模型时,审查会失败。
- **Risk assessment model**、**Balanced model** 和 **Heavy model**:用于[风险评估](/zh/how_to_use/code_review/configs/risk)和各个审查模式的模型。**Heavy model** 在团队版和企业版上可用。在您选择之前,它们都使用默认模型。
- **Other task models**(展开它):**Kody Rules**、**PR Summary**、**Conversation**、**Business Rules** 和 **Custom Agents** 都可以各自运行不同的模型,例如为摘要使用更便宜的模型。无法完成某个任务的模型会在该行中被禁用,并带有提示。

点击 **Save settings** 保存,或点击 **Reset** 放弃您的修改。**Repository overrides** 面板列出为单个仓库、目录和自定义 agent 设置的模型。您可以用 **Routing** 上的范围选择器设置仓库或目录的模型;参见[路由](/zh/how_to_use/code_review/configs/routing)。

<Note>
  只连接了一个模型时,路由固定为该模型。连接第二个模型,路由才有意义。
</Note>

## 订阅与编码套餐

一些提供商会出售固定费率订阅(通常称为编码套餐),替代按 token 付费的 API 访问,或与之并行。Kodus 连接订阅的方式与连接任何 API 相同:使用该套餐给您的密钥和端点。它从不使用您在提供商网站或应用上的账号登录。

套餐能否以这种方式使用由提供商决定,各家有各自的规则。依赖某个套餐之前:

- **查看其条款。** 有些套餐只允许在提供商自己的应用中使用,或限制自动化使用。提供商可以随时更改这一点,Kodus 无法替您检查。
- **查看其限制。** 套餐通常会限制并发请求数、请求窗口或月度用量。请相应设置 **Max concurrent requests**,并在另一个提供商上添加 **Fallback model**,这样触及上限时审查不会失败。参见[并发与速率限制](/zh/how_to_use/byok/model_settings#并发与速率限制)。
- **使用套餐自己的端点。** 套餐的密钥通常只能用于该套餐的端点,而不能用于提供商按 token 付费的 API。[Kimi 与 GLM](/zh/how_to_use/byok/providers#连接-kimi-moonshot-和-glm-z-ai) 展示了两者的区别。

使用订阅套餐的风险由您自行承担。如果提供商限制或终止访问,审查的表现与其他任何提供商故障相同:如果您设置了 **Fallback model**,则切换到它;如果没有设置,则失败。

## Kodus credits

如果你的 Kodus Cloud 工作区有权使用 **Kodus** 提供商的 Alpha 版本，请在 **AI providers** 中选择 **Kodus**，即可添加模型，无需 API 密钥。在 **Kodus credits** 中充值。用量按模型所示的每 token 单价从余额中扣除。付款前可以在充值页面看到平台费用。

在 **Configure routing** 中选择要交给该模型的任务。如果余额用完，分配给 Kodus 模型的审查会暂停，直到你充值。使用你自己的提供商密钥的模型可以继续运行。

## 高级设置

每个模型的表单都有一个可选的 **Advanced settings** 卡片:推理、温度、输出和输入限制以及并发。默认值适合大多数提供商;参见[模型设置](/zh/how_to_use/byok/model_settings)。有两项设置值得在需要之前先了解。

### 自定义 JSON 覆盖

对于 Kodus 没有对应字段的提供商选项,请在 **Thinking / Reasoning** 中选择 **Custom** 并粘贴 JSON。参见[自定义 JSON 覆盖](/zh/how_to_use/byok/model_settings#自定义-json-覆盖)。

### 固定 OpenRouter 提供商

在 OpenRouter 模型上,**OpenRouter routing** 可固定由哪些上游提供商为其提供服务。参见[固定 OpenRouter 提供商](/zh/how_to_use/byok/providers#固定-openrouter-提供商)。

### 路由策略

- 为默认模型和备用模型使用**不同的提供商**(例如默认用 Anthropic,备用用 Google)。这可以防范特定提供商的故障。
- 并发限制很严的订阅(GLM Coding Plan Lite/Pro、Kimi Code Plan)单独使用并不是好的配置 — 请搭配一个按 token 付费的备用模型,这样突发的 PR 不会被饿死。
- 将繁重的任务(代码审查)路由到您最强的模型,将轻量的任务(摘要、聊天)路由到 **Code review → Routing** 上 **Other task models** 下更便宜的模型。
