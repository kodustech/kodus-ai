---

本指南让您在 5 分钟内完成从零到一次完整审查的流程。

<Steps>
  <Step title="安装">
    <Tabs>
      <Tab title="技能安装器（推荐）">
        安装或更新 CLI，然后将 Kodus 技能安装到在您机器上找到的 AI 代理中（Claude Code、Cursor、Codex 等 — 参见 [AI 代理](/zh/how_to_use/cli/ai_agents)）。

        macOS 和 Linux：

        ```bash
        curl -fsSL https://review-skill.com/install | bash
        ```

        Windows PowerShell：

        ```powershell
        powershell -NoProfile -ExecutionPolicy Bypass -Command "$tmp = Join-Path $env:TEMP 'kodus-install.ps1'; Invoke-WebRequest https://review-skill.com/install.ps1 -OutFile $tmp; & $tmp"
        ```
      </Tab>
      <Tab title="npm">
        ```bash
        npm install -g @kodus/cli
        ```

        `pnpm add -g @kodus/cli`、`yarn global add @kodus/cli` 和 `bun add -g @kodus/cli` 的效果相同。
      </Tab>
      <Tab title="npx（无需安装）">
        ```bash
        npx @kodus/cli review
        ```
      </Tab>
    </Tabs>

    <Note>需要 Node.js 22.19.0 或更高版本。</Note>

    验证安装：

    ```bash
    kodus --version
    kodus status
    ```
  </Step>

  <Step title="认证">
    根据您的使用场景选择。您也可以跳过认证，直接运行 `kodus review` — 试用模式有每小时次数限制。

    <Tabs>
      <Tab title="独立开发者">
        使用个人账户登录：

        ```bash
        kodus auth login
        ```

        CLI 会在浏览器中打开 **Authorize Kodus CLI** 页面，并在浏览器未打开时打印其 URL。核对 **Device**、**Mode** 和 **Expires** 信息，点击 **Authorize CLI**，然后返回终端。

        如果您在该浏览器中尚未登录 Kodus，会先进入登录页面，登录后进入仪表板。请再次打开终端中的 URL 以到达 **Authorize CLI**。CLI 最多等待 10 分钟。

        在没有浏览器的机器上（SSH 会话、CI 或非交互式终端），CLI 会改为打印一个 URL 和一个代码。页面上没有输入代码的字段。请在任意设备上打开该 URL，并把代码作为 `code` 参数添加进去（`https://app.kodus.io/cli/authorize?code=ABCD-EFGH`），然后点击 **Authorize CLI**。代码 10 分钟后过期。添加 `--device-code` 可在任意机器上使用此流程。

        您的登录信息保存在 `~/.kodus/credentials.json`，并自动刷新。
      </Tab>
      <Tab title="团队（共享密钥）">
        组织 Owner 在侧边栏的 **Organization → CLI keys**（<a href="https://app.kodus.io/organization/cli-keys" target="_blank">app.kodus.io/organization/cli-keys</a>）下生成团队密钥。

        在运行 CLI 的 shell 中，将密钥设置为环境变量 `KODUS_TEAM_KEY`。运行 `kodus status`，确认 CLI 已识别该密钥。

        <Warning>请在显示密钥时保存 — 之后将无法再次查看。</Warning>
      </Tab>
      <Tab title="AI 代理">
        对于 AI 编码代理（Claude Code、Cursor、Codex），推荐使用团队密钥 — 无需个人登录，无交互提示。设置一次即可：

        ```bash
        export KODUS_TEAM_KEY=kodus_xxxxx
        ```

        将其添加到您的 shell 配置文件，使代理每次运行都能读取。
      </Tab>
      <Tab title="CI/CD">
        使用团队密钥。将其存为 secret，并以 `KODUS_TEAM_KEY` 暴露给作业：

        ```bash
        export KODUS_TEAM_KEY=kodus_xxxxx
        ```

        GitHub Actions、GitLab CI 及通用流水线示例参见 [自托管配置](/zh/how_to_use/cli/self_hosted#ci/cd-集成)。
      </Tab>
    </Tabs>

    <Info>
      **自托管 Kodus？** 在认证前先指向您的 API：

      ```bash
      export KODUS_API_URL=https://kodus-api.yourcompany.com
      ```

      除 `localhost` 外必须使用 HTTPS。
    </Info>

    确认认证状态：

    ```bash
    kodus auth status
    ```
  </Step>

  <Step title="运行第一次审查">
    在包含未提交变更的任意 git 仓库中：

    ```bash
    kodus review
    ```

    CLI 会分析您的工作目录差异并打印摘要。在 macOS 和 Linux 的交互式终端中，审查结果会在 Hunk diff 查看器中打开，紧挨着代码。在 Windows 上，或使用 `--no-hunk` 时，您可以逐文件浏览列表、预览建议的修复并应用。

    常见变体：

    ```bash
    kodus review --staged             # Only staged files
    kodus review --branch main        # Compare current branch against main
    kodus review --commit abc123      # Analyze a single commit
    kodus review --fix                # Apply every fixable issue (asks to confirm)
    kodus review --prompt-only        # Compact output for AI agents
    kodus review --fail-on error      # Exit 1 on error-or-worse issues (CI-friendly)
    ```

    <Tip>
      使用登录或团队密钥时，工作目录审查（默认）和 `--staged` 会将变更文件的内容连同 diff 一起发送。`--branch`、`--commit` 和 `--fast` 只发送 diff，因为后端可以自行读取这些提交。这就是它们在超大分支上表现良好的原因。试用审查始终只发送 diff。
    </Tip>

    <Note>
      只审查已跟踪的变更。对新文件执行 `git add` 以将其纳入审查。
    </Note>
  </Step>

  <Step title="选择下一步">
    根据您的目标：

    <CardGroup cols={2}>
      <Card title="每次推送自动审查" icon="shield-check" href="/zh/how_to_use/cli/commands#kodus-hook">
        使用 `kodus hook install` 安装 pre-push 钩子。它会审查您推送的分支，并在出现严重问题时阻止推送。
      </Card>
      <Card title="在 CI 中运行审查" icon="infinity" href="/zh/how_to_use/cli/self_hosted#ci/cd-集成">
        GitHub Actions、GitLab CI 及通用流水线示例。
      </Card>
      <Card title="接入 AI 代理" icon="robot" href="/zh/how_to_use/cli/ai_agents">
        将 `--prompt-only` 接入 Claude Code、Cursor 或 Codex，实现自主修复循环。
      </Card>
      <Card title="配置仓库" icon="sliders" href="/zh/how_to_use/cli/commands#kodus-config-remote">
        从 CLI 读取和修改审查设置。
      </Card>
    </CardGroup>
  </Step>
</Steps>

## 环境变量

这些环境变量用于配置所有命令下的 CLI 行为。

| 变量 | 描述 |
| ---- | ---- |
| `KODUS_API_URL` | API 端点（默认：`https://api.kodus.io`） |
| `KODUS_APP_URL` | `kodus config remote open` 指向的 Web 应用 URL（默认：`https://app.kodus.io`） |
| `KODUS_TEAM_KEY` | 团队共享访问和 AI 代理的团队密钥 |
| `KODUS_TOKEN` | 登录访问令牌，按原样使用，不会刷新。优先级高于所有其他凭据。CI 请使用团队密钥 |
| `KODUS_GITHUB_PAT` | 用于对私有仓库进行试用审查的 GitHub 令牌。也会读取 `GITHUB_TOKEN` 和 `GH_TOKEN` |
| `KODUS_SKIP_HOOK` | 设置为任意值以跳过单次 `git push` 的 pre-push 钩子 |
| `KODUS_REQUEST_TIMEOUT_MIN` | 每次 API 请求的超时时间（分钟，默认：`60`） |
| `KODUS_DISABLE_UPDATE_CHECK` | 设置为 `1` 以关闭更新提示 |
| `CF_ACCESS_CLIENT_ID` | Cloudflare Access 客户端 ID（用于 Zero Trust 后的 API） |
| `CF_ACCESS_CLIENT_SECRET` | Cloudflare Access 客户端密钥 |

关于自托管配置和 Cloudflare Access，请参考 [自托管配置](/zh/how_to_use/cli/self_hosted)。
