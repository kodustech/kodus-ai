---
title: "自托管配置"
description: "将 Kodus CLI 连接到您的自托管 Kodus 实例。"
---

如果您在自己的基础设施上运行 Kodus，CLI 的使用方式完全相同 — 只需将其指向您的 API。

## 连接到您的实例

<Steps>
  <Step title="设置 API URL">
    告诉 CLI 您的 Kodus API 地址。选择一种方式：

    <Tabs>
      <Tab title="环境变量（推荐）">
        ```bash
        export KODUS_API_URL=https://kodus-api.yourcompany.com
        ```

        将其添加到 shell 配置文件（`~/.bashrc`、`~/.zshrc` 等）以永久生效：

        ```bash
        echo 'export KODUS_API_URL=https://kodus-api.yourcompany.com' >> ~/.zshrc
        source ~/.zshrc
        ```
      </Tab>
      <Tab title="配置文件">
        创建或编辑 `~/.kodus/config.json`：

        ```json
        {
          "apiUrl": "https://kodus-api.yourcompany.com",
          "teamKey": "kodus_xxxxx",
          "teamName": "Your Team",
          "organizationName": "Your Org"
        }
        ```

        运行 `kodus auth team-key` 时 CLI 会自动创建此文件，并保留其中已有的 `apiUrl`。您也可以手动创建。

        <Warning>
          `kodus auth login` 和 `kodus auth logout` 可能删除此文件，包括 API URL 和 Cloudflare Access 设置。请设置环境变量 `KODUS_API_URL`。如果您的 API 使用 Cloudflare Access，请同时设置 `CF_ACCESS_CLIENT_ID` 和 `CF_ACCESS_CLIENT_SECRET`。
        </Warning>
      </Tab>
      <Tab title="内联（一次性）">
        ```bash
        KODUS_API_URL=https://kodus-api.yourcompany.com kodus review
        ```
      </Tab>
    </Tabs>

    <Warning>
      **必须使用 HTTPS。** 出于安全考虑，CLI 会拒绝非 HTTPS URL。唯一的例外是 `localhost` 和 `127.0.0.1`（用于本地开发）。
    </Warning>

    **优先级：** `KODUS_API_URL` 环境变量 > `~/.kodus/config.json` 中的 apiUrl > 默认值（`https://api.kodus.io`）。
  </Step>

  <Step title="认证">
    <Tabs>
      <Tab title="团队密钥（推荐）">
        在自托管的 Kodus Web 应用中打开 **Organization → CLI keys**，生成团队密钥。在运行 CLI 的 shell 中，将密钥设置为环境变量 `KODUS_TEAM_KEY`。

        <Tip>团队密钥非常适合共享环境和 AI 代理配置 — 无需个人登录。</Tip>
      </Tab>
      <Tab title="个人登录">
        ```bash
        kodus auth login
        ```

        CLI 会打开您自托管 Web 应用的 **Authorize Kodus CLI** 页面。使用在您的实例上注册的账户登录（登录后会进入仪表板，请再次打开 CLI 打印的 URL），然后点击 **Authorize CLI**。在没有浏览器的机器上，请在私用终端中运行 `kodus auth login --device-code`。CLI 会显示实例的授权网址和一次性代码。在浏览器地址栏中，将一次性代码作为 `code` 查询参数加入网址，然后点击 **Authorize CLI**。请勿将代码或含代码的完整链接写入日志或发到共享频道。

        您的登录信息以受限权限（600）存储在 `~/.kodus/credentials.json` 中。

        <Info>
          该页面的地址来自 Kodus API 的 `API_FRONTEND_URL` 设置。它必须是您的 Web 应用的 URL，否则登录页面会在错误的主机上打开。
        </Info>

        CI 中使用密文变量 `KODUS_TEAM_KEY` 保存团队密钥。
      </Tab>
    </Tabs>
  </Step>

  <Step title="验证连接">
    ```bash
    kodus status
    ```

    `kodus status` 显示本地检测到的认证方式。要检查 API URL，请在调用 API 的命令中添加 `--verbose`。例如，使用允许配置仓库的团队密钥时，可以运行：

    ```bash
    kodus config remote list --verbose
    ```
  </Step>
</Steps>

## Cloudflare Access（零信任）

如果您的自托管 API 位于 [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/applications/) 之后，CLI 支持服务令牌认证。

<Tabs>
  <Tab title="环境变量">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export CF_ACCESS_CLIENT_ID=your-client-id.access
    export CF_ACCESS_CLIENT_SECRET=your-client-secret
    ```
  </Tab>
  <Tab title="配置文件">
    ```json
    {
      "apiUrl": "https://kodus-api.yourcompany.com",
      "teamKey": "kodus_xxxxx",
      "cfAccessClientId": "your-client-id.access",
      "cfAccessClientSecret": "your-client-secret"
    }
    ```
  </Tab>
</Tabs>

当客户端 ID 和密钥都已设置时，CLI 会在每个 API 请求中发送 `CF-Access-Client-Id` 和 `CF-Access-Client-Secret` 头。优先级：环境变量 > 配置文件。

## 配置文件参考

CLI 将配置存储在 `~/.kodus/config.json` 中：

```json
{
  "apiUrl": "https://kodus-api.yourcompany.com",
  "teamKey": "kodus_xxxxx",
  "teamName": "Engineering",
  "organizationName": "Acme Corp",
  "cfAccessClientId": "your-client-id.access",
  "cfAccessClientSecret": "your-client-secret"
}
```

| 字段 | 必需 | 描述 |
|------|------|------|
| `apiUrl` | 否 | 自托管 API URL。可被 `KODUS_API_URL` 环境变量覆盖。 |
| `teamKey` | 否 | 团队 API 密钥（以 `kodus_` 开头）。可被 `KODUS_TEAM_KEY` 环境变量覆盖。 |
| `teamName` | 否 | 团队显示名称。 |
| `organizationName` | 否 | 组织显示名称。 |
| `cfAccessClientId` | 否 | Cloudflare Access 客户端 ID。可被 `CF_ACCESS_CLIENT_ID` 环境变量覆盖。 |
| `cfAccessClientSecret` | 否 | Cloudflare Access 客户端密钥。可被 `CF_ACCESS_CLIENT_SECRET` 环境变量覆盖。 |

<Info>
  配置文件以 `0600` 权限创建（仅所有者可读写）。目录 `~/.kodus/` 以 `0700` 权限创建。
</Info>

## 环境变量汇总

| 变量 | 描述 |
|------|------|
| `KODUS_API_URL` | 自托管 API 端点（需要 HTTPS，localhost 除外） |
| `KODUS_APP_URL` | 您的 Web 应用的 URL，`kodus config remote open` 会指向它（默认 `https://app.kodus.io`） |
| `KODUS_TEAM_KEY` | 团队共享访问密钥 |
| `KODUS_TOKEN` | 登录访问令牌，按原样使用，不会刷新。优先级高于所有其他凭据。CI 请使用团队密钥 |
| `CF_ACCESS_CLIENT_ID` | Cloudflare Access 客户端 ID |
| `CF_ACCESS_CLIENT_SECRET` | Cloudflare Access 客户端密钥 |
| `KODUS_REQUEST_TIMEOUT_MIN` | 每次 API 请求的超时时间（分钟，默认 `60`） |
| `KODUS_DISABLE_UPDATE_CHECK` | 设置为 `1` 以关闭更新提示 |

## CI/CD 集成

在 CI/CD 流水线中使用自托管实例时，将 API URL 和团队密钥设置为环境变量。全新检出的代码没有未提交的变更，因此请用 `--branch` 将分支与其基础分支对比审查。基础分支必须存在于检出结果中，因此请获取完整历史。

<Tabs>
  <Tab title="GitHub Actions">
    ```yaml
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0
    - name: Kodus Review
      env:
        KODUS_API_URL: ${{ secrets.KODUS_API_URL }}
        KODUS_TEAM_KEY: ${{ secrets.KODUS_TEAM_KEY }}
      run: npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
  <Tab title="GitLab CI">
    ```yaml
    kodus-review:
      variables:
        GIT_DEPTH: "0"
      script:
        - git fetch origin main
        - npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```

    在项目设置中将 `KODUS_API_URL` 和 `KODUS_TEAM_KEY` 添加为 CI/CD 变量。
  </Tab>
  <Tab title="通用">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export KODUS_TEAM_KEY=kodus_xxxxx
    npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
</Tabs>

<Tip>
  使用 `--fail-on error` 或 `--fail-on critical` 在发现超过严重级别阈值的问题时使流水线失败。Pull Request 由 Git 集成审查，因此无需流水线作业。
</Tip>

## 在团队中分发

向团队分享 [CLI 安装说明](/zh/how_to_use/cli/getting_started)和自托管 API 的 URL。每个人可在 shell 配置文件中设置 `KODUS_API_URL`，或在 `~/.kodus/config.json` 中设置 `apiUrl`。通过密钥管理工具分发团队密钥，并在使用 CLI 前将密钥设置为 `KODUS_TEAM_KEY`。

## 故障排除

<AccordionGroup>
  <Accordion title="安全错误：API URL 必须使用 HTTPS 协议">
    CLI 要求所有非 localhost URL 使用 HTTPS。随后它会回退到默认的 `https://api.kodus.io`，因此在认证之前请先阅读该提示。确保您的自托管实例有有效的 TLS 证书。如果是本地测试，请使用 `http://localhost:<port>`。
  </Accordion>

  <Accordion title="连接被拒绝或超时">
    - 验证 URL 可达：`curl -I https://kodus-api.yourcompany.com`
    - 检查防火墙或 VPN 是否阻止了连接
    - 如果在 Cloudflare Access 之后，确保已设置 `CF_ACCESS_CLIENT_ID` 和 `CF_ACCESS_CLIENT_SECRET`
    - 使用 `--verbose` 查看正在使用的确切 URL
  </Accordion>

  <Accordion title="认证失败 (401)">
    - 运行 `kodus status` 检查当前认证状态
    - 如果使用团队密钥，在自托管 Web 应用的 **Organization → CLI keys** 下确认其仍为 **Active**
    - 如果使用个人登录，CLI 会自动刷新登录；如果刷新失败，请再次运行 `kodus auth login`
    - 确保 `KODUS_API_URL` 指向正确的实例
  </Accordion>

  <Accordion title="API 返回无效响应（期望 JSON，收到 HTML）">
    这通常意味着 URL 命中的是反向代理、负载均衡器或 Cloudflare Access 页面，而不是实际的 API。请检查：
    - URL 路径是否正确（没有多余的 `/api` 等）
    - 如果适用，是否已配置 Cloudflare Access 凭据
    - 反向代理是否正确转发请求
  </Accordion>

  <Accordion title="设备限制已达上限">
    您的自托管实例可能对每个组织强制执行设备限制。Web 应用中没有可供清理的设备列表，因此请联系管理员提高限制（API 的 `CLI_DEVICE_LIMIT` 设置；默认值 `0` 表示不限制）。
  </Accordion>
</AccordionGroup>
