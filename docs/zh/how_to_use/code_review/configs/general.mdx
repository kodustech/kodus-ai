打开 **Code review → General**（页面标题为 **General settings**）。审查类别和严重级别阈值位于 [What to review](/zh/how_to_use/code_review/configs/what_to_review)。摘要、消息和 Kody 的语气位于 **What Kody writes**。

<Note>
  Kodus 有三个配置级别：Global、Repository 和 Directory。了解它们如何工作，请参阅<a href="/zh/how_to_use/code_review/configs/inheritance_overrides">配置继承与覆盖</a>。
</Note>

## Automated code review

**Automated code review** 开关让 Kody 在拉取请求打开时进行审查。默认开启。关闭后，请在拉取请求上评论 `@kody start-review` 来启动审查。

<Info>
  该开关控制的是**初始审查**。对于后续推送，请参阅下面的 Review Cadence。
</Info>

### Review Cadence

在 **Automated code review** 开启时显示。它决定 Kody 如何处理首次审查之后的审查：

<Tabs>
  <Tab title="Automatic">
    审查每次新推送。这是默认值。
  </Tab>

  <Tab title="Auto-pause">
    推送密集到来时暂停审查。当 Kody 在 **Time window (minutes)** 内对某个拉取请求审查了 **Pushes to trigger pause** 次之后，下一次推送不会被审查，该拉取请求保持暂停，直到你评论 `@kody start-review`。

    默认值：15 分钟内 3 次推送。
  </Tab>

  <Tab title="Manual">
    拉取请求打开时，Kody 审查第一次推送。之后的推送仅在你评论 `@kody start-review` 时才会审查。
  </Tab>
</Tabs>

### Review draft pull requests

**Review draft pull requests** 默认开启，因此草稿也会被审查。关闭它可跳过草稿，直到它们被标记为 ready。

## Review mode

General 页面会显示当前生效的审查模式和模型。点击 **Configure routing** 可以更改模式，或由风险结果选择的模式，并为某个仓库或目录覆盖模型。参见 [Routing](/zh/how_to_use/code_review/configs/routing)。

风险评估有自己的页面和开关。参见[风险评估](/zh/how_to_use/code_review/configs/risk)。

## PR workflow

**Automatic PR approval** — Kody 会在审查结果干净后，或在它留下的所有评论都已解决后批准 PR。它从不合并 PR。批准策略定义 Kody 可以批准哪些干净的 PR，启用的风险评估适用于每个策略。参见[自动批准](/zh/how_to_use/code_review/configs/auto_approve)。

**平台：** GitHub、GitLab、Bitbucket、Azure Repos、Forgejo

## Review feedback

- **Request changes on critical issues**（`isRequestChangesActive`，默认关闭）— 当 Kody 发现严重问题时，会把拉取请求的审查状态设为 Request Changes。一旦这些发现被解决，Kody 就会撤回该请求，即使是在它不批准的拉取请求上。平台：GitHub、Bitbucket、Azure Repos、Forgejo。当 GitLab 是你唯一连接的平台时，该开关会被隐藏。
- **Show status feedback**（默认开启）— 当审查被跳过或被阻止时，Kody 会用表情回应或评论进行反馈。
- **Committable suggestions**（Alpha，默认开启）— Kody 可以给出能够直接作为提交应用的代码建议。仅限 GitHub；没有 GitHub 连接时该开关会被禁用。

## Review scope

Kody 会跳过匹配这些设置的文件和拉取请求。使用 `@kody start-review` 启动的审查会忽略 **Ignore title keywords**、**Base Branches** 和 **Review draft pull requests**。

### Ignored files

Kody 跳过的文件的 glob 模式。模式区分大小写，并匹配点文件。该字段会显示部分模式；点击 **Edit** 打开 **Ignored files** 对话框。每个新模式都会校验 glob 语法是否有效，**Test a file** 会告诉你某个路径会被忽略（以及由哪个模式忽略）还是会被审查。**Apply** 只会更新该字段。在你点击 **Save settings** 之前不会保存任何内容。

默认列表很长：`yarn.lock`、`package-lock.json`、`package.json`、`.env`、`**/*.json`、`**/*.xml`、`**/*.lock`、`**/*.min.*`、图片、字体和压缩包、IDE 和操作系统文件，以及 `**/build/**`、`**/bin/**`、`**/out/**`、`**/vendor/*`、`**/deploy/**` 和 `**/prod/**` 等文件夹。如果 Kody 跳过了你期望它审查的文件，请检查列表中是否有范围过宽的模式并将其删除。

即使所有更改文件都已忽略，只要自定义智能体明确包含其中一个文件，审查仍可运行。已删除的文件会被排除。如果主审查和自定义智能体合计有超过 2,000 个可审查文件，Kody 会跳过这次审查。使用 **Ignored files** 排除生成目录或第三方目录。

### Ignore title keywords

Kody 会跳过标题包含这些关键字中任意一个的拉取请求。匹配不区分大小写，每个关键字最长 100 个字符。

### Base Branches

哪些目标分支会被自动审查。

<Info>
  **留空（默认值）表示仅审查仓库的默认分支。** 添加条目即可审查其他分支。一旦列表有了条目，Kody 会审查匹配其中任一条目的拉取请求，以及默认分支，除非你用 `!` 将其排除。

  除 `contains:` 外，条目都会与拉取请求的**目标**分支进行匹配：

  | 条目 | 效果 |
  | --- | --- |
  | `develop` | 审查目标为 `develop` 的拉取请求。 |
  | `release/*` | 审查目标为任何以 `release/` 开头的分支的拉取请求。`*` 匹配任意字符，包括斜杠。 |
  | `*` | 审查目标为任意分支的拉取请求。 |
  | `!staging` | 从不审查目标为 `staging` 的拉取请求。排除优先于所有其他匹配。使用 `!main` 可让默认分支不被审查。 |
  | `contains:hotfix` | 审查**源**分支包含 `hotfix` 的拉取请求，无论目标是什么。 |

  每个条目最长 100 个字符。
</Info>

## Other settings

- **Kody Language**（仅 Global）— Kody 在审查回复中使用的语言。
- **Configure centralized config**（仅 Global，位于页面标题栏）— 将审查设置保存在一个仓库中。参见[集中式配置](/zh/how_to_use/code_review/configs/centralized_config)。

## kodus-config.yml

### Config Priority

你可以把审查设置放在仓库根目录的 `kodus-config.yml` 文件中，而不使用网页应用。

<Warning>
  **在你主动开启之前，该文件会被忽略。** 除非仓库开启了 **Prefer kodus-config.yml settings**，否则 Kody 从不读取 `kodus-config.yml`。仅仅提交文件不会产生任何效果。

  在侧边栏 **Code review** 分组顶部的作用域选择器中选择该仓库，打开 **Code review → General**，并开启 **Prefer kodus-config.yml settings**。该开关也会出现在目录作用域，但只有仓库的设置决定是否读取该文件。它是网页设置：无法在文件中开启。之后侧边栏会在作用域选择器下方显示 **kodus-config.yml applied**、**kodus-config.yml not found** 或 **kodus-config.yml unavailable**。
</Warning>

- Kody 从仓库默认分支的根目录读取该文件。
- 该文件会叠加在 Global 和仓库的网页设置之上。只需声明你想要修改的键；未声明的键保留其网页中的值。
- 嵌套设置按键逐个合并。文件中的列表（例如 `ignorePaths`）会替换网页中的列表。
- 在目录作用域上覆盖的设置，优先于仓库文件中的同一设置。参见[配置继承与覆盖](/zh/how_to_use/code_review/configs/inheritance_overrides)。
- 未知的顶层键会被丢弃且不报错。如果某项设置看起来没有生效，请对照下面的示例检查拼写。
- `customAgents` 和 `knowledge` 不会从该文件读取。审查评论会说明这一点；请在应用中配置自定义代理。
- Kody Rules 设置和 `customMessages` 不会从仓库自己的文件读取。请在应用中设置，或在[集中式配置](/zh/how_to_use/code_review/configs/centralized_config)仓库中设置，那里的同类文件可以携带它们。

<Accordion title="示例 kodus-config.yml">
```yaml
version: 2.0

# general
automatedReviewActive: true
reviewCadence:
    type: 'automatic' # automatic | auto_pause | manual
    timeWindow: 15 # minutes, auto_pause only
    pushesToTrigger: 3 # auto_pause only
runOnDraft: true
reviewMode: balanced # balanced | heavy
riskAssessmentActive: false
riskCriteria: []
riskReviewRouting:
    noRisk: balanced
    riskFound: heavy
byokModel: '' # empty = inherit (directory -> repository -> the organization's main model)
pullRequestApprovalActive: false
approvalPolicies: []
approvalSensitivePaths: []
isRequestChangesActive: false # not available on GitLab
showStatusFeedback: true
enableCommittableSuggestions: true # GitHub only

# review scope
ignorePaths:
    - 'yarn.lock'
    - 'package-lock.json'
    - 'package.json'
    - '.env'
    - '**/*.json'
    # ...abbreviated: the shipped default lists about 1,100 patterns in total
ignoredTitleKeywords: []
baseBranches: [] # empty = the repository's default branch only

# linked repositories — Teams / Enterprise only, up to 3
linkedRepositories: []

# what to review
reviewOptions:
    bug: true
    performance: true
    security: true
    business_logic: true
repoInstructionsEnabled: false # check changes against CLAUDE.md / AGENTS.md / .cursor/rules
suggestionControl:
    severityLevelFilter: 'medium' # low | medium | high | critical
    applyFiltersToKodyRules: false
deterministicEvidence: # beta
    ciChecks: false
    tools:
        secrets: false
        dependencies: false
# businessLogic: see Business Logic Validation
# v2PromptOverrides: see Instructions & Personality

# what Kody writes
summary:
    generatePRSummary: true
    behaviourForExistingDescription: 'replace' # replace | concatenate | complement
    behaviourForNewCommits: 'none' # none | concatenate | replace
    customInstructions: ''
```
</Accordion>

<Note>
  默认值的权威来源是 kodus-ai 仓库中的
  [`default-kodus-config.yml`](https://github.com/kodustech/kodus-ai/blob/main/default-kodus-config.yml)。
</Note>
