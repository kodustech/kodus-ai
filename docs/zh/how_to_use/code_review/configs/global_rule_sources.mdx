全局规则源让你把 Kodus 指向一个或多个已连接的代码库，并把其中的规则文件导入为**全局** Kody Rules。与[代码库规则](/zh/how_to_use/code_review/configs/repository_rules)（仅在其所在代码库生效）不同，从全局源导入的规则会在代码审查时应用到**所有**代码库。

当团队把架构与编码标准放在一个专门的 "standards" 代码库中，并希望这些标准在各处都被执行、又不想把规则文件复制到每个项目时，就用它。

## 工作原理

- 你选择若干已连接的代码库作为**源**。
- Kodus 扫描每个源代码库默认分支中的规则文件，位置和模板与[代码库规则](/zh/how_to_use/code_review/configs/repository_rules)相同（`.kody/rules/`、`rules/**/*.md` 等）。
- 每个规则文件都会成为一条全局规则，显示在全局 **Kody Rules** 页面上，并标明它来自哪个文件。
- 在任何代码库的代码审查过程中，这些全局规则会与该代码库自身的规则一起应用，并遵循[继承规则](/zh/how_to_use/code_review/configs/rules_inheritance)。
- 为编码代理编写的指令（`CLAUDE.md`、`AGENTS.md`、`.cursor/rules/**`）不会被导入。此前从它们导入的全局规则会被保留，但已冻结；请参阅[编码代理指令](/zh/how_to_use/code_review/configs/rules_file_detection)。

<Info>
只有已在 **Repositories** 页面上连接的代码库才能作为源，这样导入的规则才能通过下文描述的 Pull Request 触发器保持最新。
</Info>

## 设置

1. 在侧边栏 **Code review** 分组顶部的作用域选择器中选择 **Global**，然后打开 **Kody Rules**。
2. 点击 **Configuration** 打开侧边面板，找到 **Global rule sources**。
3. 点击代码库选择器，选择一个或多个已连接的代码库。
4. 点击 **Import selected**。

导入在后台运行。完成后，导入的规则会出现在你的全局 Kody Rules 列表中。你已选择但尚未导入的代码库会显示 **Not imported yet**。

## 保持规则最新

- **合并时：** 当源代码库中有 Pull Request 被合并时，其规则文件会被重新扫描，全局规则随之更新。未变更的文件会被跳过。
- **Resync now：** 按需重新扫描所有源。直接推送到源代码库默认分支的改动不会被自动检测，请在这种推送之后使用它。

## 移除一个源

把某个代码库从列表中移除，会**删除从它导入的全局规则**，这些规则将不再在代码审查中生效。移除前会要求你确认。来自其他源的规则，以及你手工编写的规则，都不会受到影响。

## 源代码库不会被审查

用作全局规则来源的代码库会被视为配置代码库，而非代码本体。Kodus 会**跳过**在其中打开的 Pull Request 的代码审查，与[集中式配置](/zh/how_to_use/code_review/configs/centralized_config)代码库的处理方式相同。

## 套餐可用性

| 套餐 | 可用性 |
|------|--------|
| **Free**、没有有效许可证密钥的自托管，或已取消或已过期的套餐 | 不可用。 |
| **Trial** | 所有源代码库合计最多 **5 条全局规则**。只会导入最先找到的 5 条；达到上限后，除非你删除一些或升级，否则不会再导入更多规则。 |
| **付费**（云端）和**已授权的自托管** | 无限制。 |

在 Trial 套餐下，计数器会显示 5 条中已使用了多少，导入前的确认对话框会说明还会新增多少条。
