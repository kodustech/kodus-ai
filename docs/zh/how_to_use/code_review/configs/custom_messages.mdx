---
title: "自定义消息"
description: "编辑 Kody 在审查开始、结束或失败时发布的评论，以及其评论在拉取请求上的显示方式。"
---

打开 **Code review → What Kody writes**。这些消息位于 **Comments during the review** 部分，每条消息一个标签页：**Review starts**、**Review ends** 和 **Review fails**。每个标签页都有一个 **Message** 输入框和一个 **Reset to…** 菜单。该菜单在仓库和目录范围提供 **Inherited message**，在 Global 范围提供 **Default message**。

消息可以在 Global、Repository 和 Directory 范围设置。

## 消息如何显示

审查开始时，Kody 会发布开始消息。审查结束时，它会把同一条评论编辑为结束消息。建议作为审查评论发布在两者之间。

- **开始和结束都已发布：** 一条评论，先显示开始消息，审查完成后显示结束消息。
- **本次运行未发布开始消息：** 结束消息会在审查之后作为新评论发布。
- **结束消息设为 Never：** 开始评论保持原样，审查失败后也是如此。此时 😕 表情回应是失败的唯一迹象。
- **审查失败：** Kody 会发布其默认的错误评论，而不是您的结束消息，您的 **Review fails** 文本显示在其下方。

在 GitHub 上，新的审查开始时，Kody 会折叠上一次审查的评论。

## Post this message

在 **Review starts** 和 **Review ends** 上，**Post this message** 选择框用于设置该消息何时发布。每条消息都有各自的设置。

- **On every push**（`every_push`，默认）— 每次审查运行时都发布：拉取请求打开时，以及每次触发审查的推送之后。
- **Only when the PR opens**（`only_when_opened`）— 仅发布一次，在首次审查运行时。
- **Never**（`off`）— 不发布。文本会保留，**Message** 输入框和 **Add context** 会被禁用。Kody 仍会运行审查并发布建议。

消息只会在审查运行时发布。审查节奏为 **Manual** 且 **Automated code review** 开启时，首次审查在拉取请求打开时运行；之后的推送不会发布任何内容，直到有人评论 `@kody start-review`。

## Add context

**Message** 旁边的 **Add context** 菜单会插入一个标记，Kody 会将其替换为来自拉取请求的真实数据。

| 菜单项 | 标记 | 添加的内容 |
| --- | --- | --- |
| **Changed files** | `@changedFiles` | 一个可折叠的变更文件表格，包含状态、新增和删除。 |
| **Changes summary** | `@changeSummary` | 文件、新增行、删除行和变更的总计。 |
| **Review options** | `@reviewOptions` | 哪些审查类别已开启或关闭。 |
| **Review cadence** | `@reviewCadence` | 后续审查的工作方式：自动、带限制的自动暂停，或手动。 |
| **Review scope** | `@reviewScope` | 本次审查使用了哪个层级：全局、仓库还是目录。 |
| **Agent Prompt** | `@agentPrompt` | 本次审查的所有建议合并为一个提示词，可粘贴到编码代理中，位于一个可折叠的 **Open Agent Prompt** 块中。 |

`@agentPrompt` 仅在 **Review ends** 上提供，因为它的内容只有在审查之后才存在。

## Review fails 消息

在 **Review fails** 标签页中填写文本，会把它追加到审查失败时 Kody 发布的评论下方，例如未配置 AI 提供商，或提供商拒绝了请求时。用它把人引导到内部负责人或 runbook。

这条消息没有开关：文本本身就是开关。留空（默认）则保持 Kody 的标准错误评论不变。

## 评论可见性

**Comment visibility** 部分有两项设置。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| **Post as hidden comment**（`hideComments`） | 关闭 | 承载 **Review starts** 和 **Review ends** 消息的评论会以折叠的已过时状态发布，使拉取请求对话保持简短。行内建议和 PR 级评论不会被折叠。仅限 GitHub；未连接 GitHub 时该开关会被隐藏。 |
| **Add a copyable prompt to each suggestion**（`suggestionCopyPrompt`） | 开启 | 每条建议都附带一个提示词，开发者可以粘贴到 AI 助手中来应用修复。在 Bitbucket 上，提示词会作为同一讨论串中的回复发布；关闭该设置后，Bitbucket 评论不显示修复。 |

## YAML

消息以 `customMessages` 存储在[集中式配置](/zh/how_to_use/code_review/configs/centralized_config)仓库的 `kodus-config.yml` 文件中。被审查仓库根目录下的 `kodus-config.yml` 不会更改它们；请使用应用。

```yaml
customMessages:
    startReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: |
            Review started. @changedFiles
    endReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: |
            Review finished. @changeSummary
    errorReviewMessage:
        status: 'active' # off | active; a review reads only content
        content: |
            Reviews failing? Ping #platform-eng.
    globalSettings:
        hideComments: false
        suggestionCopyPrompt: true
```
