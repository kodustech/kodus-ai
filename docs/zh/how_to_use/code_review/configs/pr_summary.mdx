---
title: "PR 摘要"
description: "让 Kody 撰写拉取请求描述,并选择对已有描述和新提交的处理方式。"
---

Kody 可以撰写一段说明拉取请求改动内容的描述。打开 **Code review → What Kody writes**;相关设置位于 **PR summary** 部分。这些设置可以在全局、代码库和目录范围内配置。

页面中的预览(**Show preview** / **Hide preview**)会展示摘要在示例拉取请求上的呈现效果。

## 撰写摘要

开启 **Write a summary on every pull request**。该选项默认开启。关闭后,Kody 不会撰写摘要,下面的选项也会被禁用。

Kody 使用 [General](/zh/how_to_use/code_review/configs/general) 中 **Kody Language** 所设置的语言撰写摘要。

## 当 PR 已有描述时

选择 Kody 如何处理作者已写好的描述:

- **Replace**(默认)—— 从头撰写一份新描述。
- **Concatenate** —— 将摘要追加到现有描述的末尾。
- **Complement** —— 阅读现有描述,并撰写一份仅突出新增或相关内容的描述。

Replace 和 Complement 会把旧描述中关联任务的行(例如 `Closes #12`、`AB#12` 或任务跟踪器链接)保留在新描述的顶部。Concatenate 则保留整段描述不变。

Kody 的文本位于两个隐藏的注释标记之间,因此重新运行时会更新该区块,而不是叠加一个新的区块。

## 当有新提交时

选择在拉取请求打开后又推送了提交时,如何处理 Kody 的摘要:

- **Do nothing**(默认)—— 摘要保持不变。
- **Concatenate new summary** —— 将新提交的摘要追加到 Kody 现有的区块中。
- **Replace Kody's summary** —— 用整个拉取请求的摘要替换 Kody 的区块。

只有 Kody 的区块会改变。作者撰写的文本会保留。

## 摘要说明

可选的 **Summary instructions** 字段用于告诉 Kody 摘要应关注或省略哪些内容。**Examples** 标签会添加现成的说明。

- "关注安全更改和性能影响"
- "简洁地总结,突出显示修改的公共 API"

说明中也可以引用审查的发现,例如提及最高严重性。说明可以引用代码库中的文件,请参阅[外部引用](/zh/how_to_use/code_review/configs/custom_prompts#外部引用)。

**Try on a real PR** 会在你的某个拉取请求上运行当前设置。该功能在摘要已开启且你有权读取拉取请求时可用。预览在任何审查之前运行,因此不会显示审查发现。

<Note>
  如果拉取请求非常大,无法在几轮内放进模型的上下文,Kody 会跳过摘要。
</Note>

超出提供方限制的描述会被截断并附上截断说明:Azure DevOps 为 4,000 个字符,Bitbucket 为 32,768 个,GitHub 为 65,536 个。在 Azure DevOps 上,Kody 会让摘要保持简短,为已有描述留出空间。

## YAML

```yaml
summary:
    generatePRSummary: true
    behaviourForExistingDescription: 'replace' # replace | concatenate | complement
    behaviourForNewCommits: 'none' # none | concatenate | replace
    customInstructions: ''
```

只有开启 **Prefer kodus-config.yml settings** 后才会读取该文件。请参阅 [General](/zh/how_to_use/code_review/configs/general#config-priority)。
