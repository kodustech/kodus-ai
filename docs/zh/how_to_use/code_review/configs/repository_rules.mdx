<Info>
代码库规则始终保持同步:无需开启任何设置。它们是代码库中唯一会变成 Kody Rules 的文件。为编码代理编写的指令(`CLAUDE.md`、`AGENTS.md`、`.cursor/rules`)会单独处理,请参阅<a href="/zh/how_to_use/code_review/configs/rules_file_detection">编码代理指令</a>。
</Info>

## 工作原理

将符合下方模板的 markdown 文件放入代码库。Kody 会把它导入为一条规则,规则随文件变化:编辑文件,规则随之改变;删除文件,规则随之移除。

文件会被**逐字**导入,不经过 LLM 转换。frontmatter 按原样读取,markdown 正文会原封不动地成为规则的指令,Bad 和 Good 示例则从正文中导入。每个文件生成一条规则。

- **自动:** 每个已连接的代码库中的规则文件都会被同步。
- **合并时:** 当新增、修改、重命名或删除某个规则文件的拉取请求被合并时,对应的规则会被创建、更新或移除。[集中式配置](/zh/how_to_use/code_review/configs/centralized_config)代码库中的拉取请求不会被同步。
- **立即导入:** 对于代码库中已有的文件,打开该代码库的 **Code review → Kody Rules → Configuration**,点击 **Import rule files now**。它会读取默认分支上的所有规则文件。
- **在应用中:** 同步的规则显示在该代码库的 **Kody Rules** 页面上,来源标记为 **Auto-sync**,并以文件路径作为其来源。

新规则会直接启用;如果开启了 **Kody knowledge approval**,则进入 **Pending review**。

文件是唯一的事实来源。每次同步时,规则的文本、路径、严重性和状态都会被文件中的内容替换,因此请修改文件,而不是在应用中修改规则。在应用中暂停的规则,会在其文件下一次同步时重新启用。

## 文件位置

将规则文件放在以下位置之一,可位于代码库根目录或任意子目录:

- `.kody/rules/`
- `rules/**/*.md`
- `.rules/` 和 `docs/coding-standards/`(仅限遵循模板的文件)

规则的适用范围取决于其 `path`,而不是文件所在的位置。位于 `services/billing/.kody/rules/` 中且没有 `path` 的规则,仍然适用于每个文件。

## 规则模板

````markdown
---
title: "<rule name>"
scope: "file"            # "file" or "pull-request"
path: []                 # list of globs. example: ["**/*.ts", "apps/web/**"]
severity_min: "high"     # "low", "medium", "high", "critical"
enabled: true            # optional
---

## Instructions
Describe what to review and how to decide. Be direct and objective.
- Focus on security, performance and public contract impacts.
- Give team preferences or patterns when applicable.
- If it's a PR rule, explain what to consider in the changeset.

## Examples

### Bad example
```lang
// paste here a short counter-example that violates the rule
```

### Good example
```lang
// paste here a short example that follows the rule
```
````

### 字段

只有非空的 `title` 和非空的正文是必填的。缺少其中任意一项的文件会被跳过。

| 字段 | 说明 | 取值 | 默认值 |
|-------|-------------|--------|---------|
| `title` | 在应用中显示的规则名称 | 任意字符串 | 必填 |
| `scope` | **Per file** 或 **Per PR** | `"file"` 或 `"pull-request"` | `"file"` |
| `path` | 规则适用的文件;只要匹配**任意一个** glob,规则就会在该文件上运行。`pull-request` 规则不使用该字段 | 一个 glob 或 glob 列表 | `**/*`(所有文件) |
| `severity_min` | 规则的严重性 | `"low"`、`"medium"`、`"high"`、`"critical"` | `"medium"` |
| `enabled` | `false` 会跳过该文件。已从该文件导入的规则不会被移除 | boolean | `true` |

<Note>
  `severity` 会被当作 `severity_min` 的别名接受。四个级别之外的取值会回退为 `"medium"`,而 `"pull-request"` 以外的 `scope` 都按 `"file"` 处理。其他 frontmatter 键会被忽略。
</Note>

Bad 和 Good 示例来自标题中包含 "bad" 或 "good" 的小节(例如 `### Bad example`);该标题下的每个围栏代码块都会成为一个示例。

## 示例规则

### 文件级规则

````markdown
---
title: "Avoid console.log in production code"
scope: "file"
path: ["src/**/*.ts", "src/**/*.tsx"]
severity_min: "medium"
---

## Instructions
Check for console.log statements in production TypeScript/JavaScript files.
- Console logs should not appear in production code
- Use proper logging libraries instead
- Allow console.log only in development utilities

## Examples

### Bad example
```typescript
function processUser(user: User) {
  console.log('Processing user:', user.id);
  return user.process();
}
```

### Good example
```typescript
import { logger } from './logger';

function processUser(user: User) {
  logger.info('Processing user:', user.id);
  return user.process();
}
```
````

### 拉取请求级规则

````markdown
---
title: "New API endpoints must have tests"
scope: "pull-request"
severity_min: "high"
---

## Instructions
When new API endpoints are added, ensure corresponding tests are included in the PR.
- Check for new route definitions in controllers
- Verify test files exist for new endpoints
- Ensure both positive and negative test cases

## Examples

### Bad example
Added new endpoint `/api/users/profile` but no test file included in the PR.

### Good example
Added new endpoint `/api/users/profile` with corresponding test file `tests/api/users/profile.test.ts` that covers success and error cases.
````

## 文件停止同步的情形

- **文件不符合模板。** 缺少 frontmatter、`title` 或正文的文件会被跳过。如果已从该文件导入过规则,规则会保留其最后的文本和状态,规则的侧边面板会警告其文件不再同步。当文件重新可以解析时,该警告会消失。
- **让文件不参与同步。** 在文件的前 10 行或后 10 行中添加 `@kody-ignore`。下次同步时,其对应的规则会被移除。
- **停止导入文件。** `enabled: false` 会停止导入该文件。它不会移除或暂停已存在的规则;如需如此,请删除文件或使用 `@kody-ignore`。

## 自托管日志

在自托管部署中,请在日志中搜索以下标记:

- `[kody-rules-sync]`:每次同步的汇总,包含被导入、被跳过(含原因)和被移除的文件。
- `[kody-rules-eval]`:审查期间,哪些规则(uuid 和标题)被选入已更改的文件。

如果某条规则在应用中显示为启用,却从未在你预期文件的 `[kody-rules-eval]` 中出现,请检查它的 **Path**:规则只会在匹配其路径的文件上运行。

## 规则数量上限

Free 套餐和未获许可的自托管实例最多运行 10 条启用的规则,包括来自文件的规则。请参阅[规则数量上限](/zh/how_to_use/code_review/configs/kody_rules#规则限制)。
