## Kody 无响应或无评论

请先查看 PR 上的反应。👀 表示 Kody 跳过了审查,😕 表示审查失败,🎉 表示审查已完成(干净的审查不会发布内联评论)。在 GitHub(GitHub App)和 Forgejo 上,**Kody Code Review** 检查会显示跳过的原因。[Kody 何时跳过](/zh/how_to_use/code_review/flow#kody-何时跳过)列出了每个原因及其解决方法。

### 自动审查未启动时

1. 确认仓库已在 **Repositories** 中选中，或已纳入 **Review every repository** 的范围。
2. 确认 Git 平台是否已投递 PR 事件。[排查 webhook 投递](/zh/knowledge_base/how-to-fix-webhook-issues)。
3. 在仓库作用域中打开 **Code review → General**，检查 **Automated code review**。如果仓库使用 [kodus-config.yml](/zh/how_to_use/code_review/configs/general#kodus-config-yml)，检查文件中的 `automatedReviewActive`。
4. 要立即请求审查，请在 PR 上评论 `@kody start-review`。如果仍被跳过，[查看记录的原因](/zh/how_to_use/code_review/flow#kody-何时跳过)。

### 审查已完成但没有建议

确保至少开启了一个类别(Bug、Performance、Security、Business Logic),以便 Kody 提供建议,并检查 **Minimum severity to post**。两者都位于 **Code review → What to review** 中([打开](https://app.kodus.io/settings/code-review/global/review-scope))。

## 推送后审查停止

评论 `@kody start-review` 可恢复暂停的 PR，也可在 **Manual** 模式下请求审查。要在每次推送后自动审查，请选择 **Automatic**。[审查节奏](/zh/how_to_use/code_review/flow#审查节奏)介绍了各模式的行为。

## 令牌问题

确认令牌仍然有效、可以访问仓库，并具备相应 Git 平台要求的权限。

[GitHub](/zh/how_to_use/code_review/general_config/github_pat) · [GitLab](/zh/how_to_use/code_review/general_config/gitlab_pat) · [Bitbucket](/zh/how_to_use/code_review/general_config/bitbucket_pat) · [Azure DevOps](/zh/how_to_use/code_review/general_config/azure_devops_pat) · [Forgejo](/zh/how_to_use/code_review/general_config/forgejo_pat)

## 全局与代码库设置

在 **Code review** 的作用域选择器中检查仓库或目录的设置。参阅[设置继承规则](/zh/how_to_use/code_review/configs/inheritance_overrides)，找到覆盖配置的作用域。

只有在该代码库的 **Code review → General** 中开启 **Prefer kodus-config.yml settings** 时，`kodus-config.yml` 才会生效。范围选择器下方的徽章会显示该文件是已应用、未找到还是不可用。

## Kody 提示它已在审查此 PR

当同一个 PR 上已有审查在运行时发送的审查命令(`@kody review`、`@kody -v …`)会等待,并在当前审查结束后开始。如果在 Kody 停止等待时(最多约 25 分钟)该审查仍在运行,Kody 会评论 "Kody is already reviewing this PR",并且不会启动该命令。请等待审查结束后再次请求。

## 合并队列在等待 Kody Code Review 时移除 PR

在 GitHub 上,当 `Kody Code Review` 是必需检查且 PR 进入合并队列时,Kody 会在队列所测试的提交上报告该 PR 最近一次完成的审查结果。不会运行新的审查。这需要通过 GitHub App 连接 Kody;使用个人访问令牌时,Kody 不会发布检查。

该检查表示 Kody 审查过该 PR,而不是 PR 没有问题。即使仍有未处理的关键建议,它也会通过;在 PR 上,它只有在审查本身无法运行时才会失败。要求该检查能保证审查已经发生;它不会因为 Kody 的发现而阻止合并。

如果 PR 的最新提交在进入队列时没有已完成的 Kody 审查(例如管理员绕过了必需检查),检查会立即失败并显示 **No finished Kody review**,队列会移除该 PR。请在 PR 上评论 `@kody start-review`,等待审查完成,然后再次将其加入队列。**Could not carry Kody's review** 表示 GitHub 没有返回审查结果;请再次将 PR 加入队列。
