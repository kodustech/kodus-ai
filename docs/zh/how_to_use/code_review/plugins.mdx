插件是连接到您工作区的远程模型上下文协议(MCP)服务器:任务跟踪工具、wiki、错误监控。Kody 从中读取内容,只有在您要求时才会对其执行操作。

| 位置 | 会发生什么 |
| --- | --- |
| 提及 `@kody` 的评论 | Kody 调用已安装的插件,并在同一线程中回复。只有当您的评论要求时,它才会更改内容,例如移动工单或编辑规则。 |
| [业务逻辑验证](/zh/how_to_use/code_review/business_logic_validation) | Kody 从您的任务跟踪工具中读取拉取请求所引用的任务。 |
| [自定义智能体](/zh/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp) | 智能体从您为其开启的插件中读取内容。仅限读取类工具。 |

## Plugins 页面

在侧边栏中打开 **Plugins**。只有所有者可以安装或更改插件;计费管理员、代码库管理员和贡献者可以查看。每张卡片显示一个插件,连接后会显示 **Installed**、**Default** 或 **Locked**。在自托管安装上,该页面需要 [MCP Manager](/zh/how_to_deploy/deploy_kodus/mcp_manager)。

| 插件 | Kody 可以读取什么 | 登录方式 |
| --- | --- | --- |
| **Git Issues** | 您代码库的任务跟踪器(GitHub、GitLab、Bitbucket 或 Forgejo)中的 issue,通过您的 Git 连接读取 | 无 |
| **Linear** | Issue、项目和 cycle | OAuth 或 API key |
| **Atlassian Rovo** | Jira 和 Confluence | OAuth 或 API token |
| **Notion** | 页面、数据库和文档 | OAuth |
| **Sentry** | 项目、issue 和事件 | OAuth |
| **Fireflies** | 会议转录、摘要和待办事项 | API key |
| **Kodus Docs** | Kodus 文档 | 无 |
| **Exa Search** | 网页和代码搜索 | 无 |
| **Kodus OSV** | 软件包的已知漏洞 | 无 |

**Kodus MCP** 在每个工作区中都已连接(**Default**)。它从您的 Git 提供方读取代码库、拉取请求、提交、文件和 diff,并管理 Kody Rules、memory 和 Kody issue。它始终开启,且不计入下文所述的 Free 套餐限制。

## 安装插件

<Steps>
  <Step title="打开插件">
    点击它的卡片。
  </Step>
  <Step title="连接它">
    需要登录的插件会先要求登录:点击 **Authenticate with** 该插件(OAuth),或填写字段并点击 **Connect**(API key 或 token)。连接后即完成安装。Kody 默认使用插件标记为只读的工具;如果插件没有标记任何工具,则使用所有工具。

    无需登录的插件会直接进入 **Selected tools**。选择 Kody 可以使用的工具,然后点击 **Install plugin**。
  </Step>
  <Step title="之后更改工具">
    打开已安装的插件,更改 **Selected tools** 并点击 **Update Tools**。**Reset Authentication** 会断开连接。
  </Step>
</Steps>

名称暗示破坏性操作(delete、remove、archive)的工具会带有警告标记,并且默认不选中。若要在选中其中之一的情况下安装,请在底部的复选框中确认。Kody 可以使用您选中的任何工具,因此只选择它需要的工具。

<Note>
  在 Free 套餐(以及未获得许可的自托管版本)中,Kody 一次最多运行 3 个已安装的插件,最早安装的优先。Plugins 页面上的横幅会列出被跳过的插件,它们的卡片显示 **Locked**。当您的代码提供方是 Azure Repos 或 Bitbucket Data Center(它们没有原生的问题跟踪器)时,无法安装 **Git Issues**。
</Note>

## 自定义插件

当目录无法覆盖某个工具时,可以添加您自己的 MCP 服务器。该服务器必须能从 Kodus 访问:是远程 HTTP 或 SSE 端点,而不是 `localhost`。

<Steps>
  <Step title="添加">
    在 **Add Custom Plugin** 卡片上,点击 **Add Plugin**。
  </Step>
  <Step title="填写表单">
    | 字段 | 说明 |
    | --- | --- |
    | **Plugin Name** | 必填。 |
    | **Description**、**Logo URL** | 可选。帮助团队成员在目录中识别它。 |
    | **URL** | MCP 端点。 |
    | **Protocol** | **HTTP** 或 **SSE**。 |
    | **Authorization** | **None**、**Bearer Token**、**Basic Auth**、**API Key**(带请求头名称)或 **OAuth 2.0**。OAuth 2.0 使用 **Use Dynamic Client Registration**,或者使用 **Client ID**、可选的 **Client Secret** 和可选的 **Scopes**。 |
    | **Custom Headers** | 额外的请求头,通过 **Add Header** 添加。授权设置的请求头会被授权覆盖。 |

    点击 **Create Plugin**。
  </Step>
  <Step title="安装">
    插件会打开。使用 OAuth 2.0 时,请先点击 **Authenticate with** 该插件。然后在 **Selected tools** 下选择它的工具,并点击 **Install plugin**。如果列表为空,请检查 URL、协议和授权。
  </Step>
</Steps>

打开自定义插件可以 **Edit Plugin** 或 **Delete Plugin**。完整的演练请参阅[安装自定义 MCP 插件](/zh/cookbook/custom-plugin-install)。

## 在回复中使用插件

<img src="https://kodus.io/wp-content/uploads/2025/10/comment-mcp.gif" alt="在建议中使用插件的示例" />

在建议或拉取请求的评论中提及 Kody。Kody 会调用它需要的插件,并在同一线程中回复。

- `@kody, update this kody rule to ignore test files`
- `@kody, move this task https://jira.com/task-123 to DONE`

## 验证业务逻辑

`@kody -v business-logic` 会将拉取请求与它所引用的任务进行比较,任务通过您的任务跟踪插件读取。
