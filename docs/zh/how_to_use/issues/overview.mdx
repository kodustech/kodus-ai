title: "Kody 工单"

---

**Kody Issues**(Kody 工单)会维护一份实时列表,记录 Kody 提出的、在其拉取请求关闭时**未被实施**的建议,并随着代码变化将它们关闭。它独立运行;可通过 **Auto-create issues** 开关将其关闭。

在所有套餐中，包括无许可证的自托管环境，Owner、Repo Admin 和 Contributor 都可以从 ⌘K 命令面板打开 **Issues**。即使该入口带有挂锁图标和 **Teams** 标签，也能打开列表。

拥有 [Cockpit 访问权限](/zh/how_to_use/cockpit/overview)时，可从 **Issues** 标签页打开列表并查看未关闭的工单数量。

列表显示 **Status**、**Severity**、**Category**、**Title**、**Repository**、**File**、**Age** 和 **#PR(s)**。默认显示未关闭的工单。

Owners、Repo Admins 和 Contributors 可以读取所有代码库的工单;Billing Managers 不能。Owners 可以更改任何工单,Repo Admins 只能更改其被分配的代码库中的工单,Contributors 则不能更改任何工单。

要在终端查看工单，请参阅 [`kodus issues`](/zh/how_to_use/cli/commands#kodus-issues) 的可用性和筛选选项。

## 工单如何创建

<Note>
  工单仅在 PR **关闭**时创建,不是在它们打开或审查期间。在 GitLab 和 Azure Repos 上,只有已合并的 PR 才算数。
</Note>

- 当 PR 关闭时,Kody 会取出它在该 PR 上提出的未被实施的建议,并为每条建议创建一个链接到代码库的**工单**。每个工单都保留原始说明、文件、严重性和类别。
- 如果同一文件上已有一个打开的工单涵盖了相同的问题,Kody 会把新建议加入该工单,而不是创建重复的工单。**#PR(s)** 列出所有贡献过的 PR。
- 这包括 Kody 因低于最低严重性或超过评论数量上限而未发布的建议。被 Kody 因错误、重复或类别已关闭而丢弃的建议不会成为工单。

<Warning>
  **Per PR** 类型的 Kody Rules 不会生成工单。只有文件级建议才会创建可跟踪的工单。
</Warning>

## 工单如何解决

每次 PR 关闭时,Kody 都会将该 PR 所更改文件上的打开工单与当前代码进行核对:

- 如果代码中已不再存在该问题,工单变为 **Resolved**。
- 如果文件已被删除,工单变为 **Dismissed**。

即使 **Auto-create issues** 处于关闭状态,这一过程也会运行,因此现有工单会继续被关闭。

## 处理工单

点击某一行即可打开该工单的详情面板,其中包含代码库、PR 和文件链接、描述,以及 **Team feedback from PR reactions**(👍 / 👎 数量)。使用 **J** / **K** 在工单之间切换,**Share** 会复制该工单的链接。

### 状态

- **Open**:需要关注。
- **Resolved**:当问题已从代码中消失时由 Kody 设置。
- **Dismissed**:不相关。当某条建议不适用于您的团队时手动设置;文件被删除时 Kody 也会设置该状态。

从详情面板顶部的选择器更改状态。

### 严重性

每个工单都有一个严重性(`Critical`、`High`、`Medium`、`Low`),初始值来自建议本身的严重性。可在详情面板中更改,以匹配您团队的优先级。

### 过滤器

打开列表顶部的 **Filters**(该按钮会显示当前生效的过滤器数量),可按 **Status**、**Severity**、**Category**、**Title**、**Repository**、**File path** 和 **PR numbers** 过滤。**Set as default filters** 会在此浏览器中每次打开 Issues 时应用您的过滤器;**Reset to default filters** 可将其恢复。
