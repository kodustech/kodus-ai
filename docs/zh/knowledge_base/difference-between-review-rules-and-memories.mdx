---
title: "审查规则和记忆有什么区别"
description: "了解何时使用审查规则与记忆,以获得最佳代码审查效果。"
---

在 Kody Rules 的界面里,你实际上是在配置两种不同的东西。理解它们各自的用途,会让代码审查更有效。

一个实用的判断方式是:

- **记忆**用来教会 Kody 你的代码库是如何工作的,这样后续的审查和建议会更贴合上下文。
- **审查规则**用来告诉 Kody,当 PR 不符合你的标准时应该标记什么。

## 审查规则

审查规则是在代码审查期间运行的**检查**。每条规则应用于文件的 diff 或整个 PR,当更改违反规则时,Kody 会报告一条建议。

**最适用于:**
- 架构边界("领域层不得导入基础设施")
- 代码模式("避免在循环条件中使用 `==`")
- PR 要求("每个服务文件必须有测试")
- 对 PR 本身的要求,例如其描述或大小

**工作原理:**
- 按文件或按 PR 运行(由规则的 **Execution mode** 决定)
- 仅在代码审查期间运行
- 可以通过 `@file:path/to/file` 指向代码库中的文件
- 产生带有严重性级别的建议
- 可以限制到特定路径,也可以从规则库添加

## 记忆

记忆是 Kody 在代码审查和与 Kody 的对话中使用的**持久上下文指令**。它们代表 Kody 应该持续携带的关于您的代码库、约定和偏好的背景知识。

**最适用于:**
- 代码库上下文("这个仓库会镜像第三方 API,因此某些外部字段会刻意保持 snake_case")
- 建议偏好("在这个仓库里给 JS 工具建议时,优先原生方法而不是 Lodash")
- 迁移上下文("billing 模块正处于迁移中,所以更适合渐进式修改,而不是大范围重构")
- 架构上下文("这个服务采用六边形架构,并把 adapter 放在边界层")

**工作原理:**
- 作为高优先级上下文添加到代码审查和对话中
- 通过让 Kody 基于仓库特定的上下文来改善未来的建议
- 通过对话(`@kody remember: ...`)创建,或在 **Code review → Kody Rules** 的 **Memories** 选项卡上点击 **New memory** 手动创建
- 范围限定为目录、代码库或组织级别
- Kody 在保存新记忆之前会检查现有记忆,并跳过重复项或更新现有记忆

## 何时使用哪个

| 场景 | 使用 |
|------|------|
| 检查每个服务是否有测试文件 | 审查规则 |
| "这个仓库会镜像外部 API,因此某些响应字段会刻意保持 snake_case" | 记忆 |
| PR 描述必须遵循模板 | 审查规则 |
| "在这个服务里,测试通常放在实现文件旁边,而不是统一的测试目录" | 记忆 |
| 标记违反架构层的导入 | 审查规则 |
| "认证模块正处于迁移中,因此更适合渐进式修改,而不是大范围重构" | 记忆 |

## 可以相互转换吗?

不能直接转换 — 应用中没有转换操作。待审记忆显示在 **Code review → Kody Rules** 的 **Pending review** 部分,您可以在那里 **Approve** 或 **Discard** 它们。如果某条记忆需要更结构化的执行(带有文件路径和严重性级别),请在 **Review Rules** 选项卡上点击 **New rule** 创建一条审查规则,然后删除或丢弃该记忆。

更多详情,请参阅 [Kody Rules](/zh/how_to_use/code_review/configs/kody_rules)。
