---
title: "如何创建自定义代码审查规则"
description: "定义适合团队架构、模式和编码偏好的规则,在每个 PR 上进行检查。"
---

每个团队都有通用 linter 无法覆盖的约定:架构边界、命名模式、测试要求或业务特定约束。自定义代码审查规则让您将这些约定编码为 Kody 在每个拉取请求上运行的检查。

## 在 Kodus 中创建规则

1. 在侧边栏 **Code review** 分组顶部的范围选择器中选择 **Global**(或某个代码库/目录),然后打开 **Kody Rules**
2. 在 **Review Rules** 选项卡上,点击 **New rule**
3. 配置:
   - **Rule name**:规则检查的内容(例如,"Service files must have tests")
   - **Execution mode**:**Per file**(检查每个变更的文件,行内评论)或 **Per PR**(检查整个 PR,发布一条 PR 评论)
   - **Path**:将 Per file 规则限制到特定文件的 glob 模式(例如,`src/services/**/*.ts`);Per PR 规则不使用此项
   - **Instructions**:要检查什么以及如何判断
   - **Severity**:Critical、High(默认)、Medium 或 Low

在 **Advanced settings** 下,您可以添加 **Bad example** 和 **Good example**,帮助 Kody 区分违规代码和合规代码。

## 什么有助于规则生效

- **要具体。** 指明模式、路径以及什么算作违规。
- **指向您的标准。** 通过路径提及某个文件,例如 `@file:docs/architecture.md`,Kody 在判断规则时会读取它。该文件从拉取请求的目标分支读取。
- **选择正确的模式。** 对于在单个文件中就能看出的内容使用 Per file,对于关于整个拉取请求的要求(其描述、大小,或相关文件是否一起更改)使用 Per PR。

### 示例:执行命名约定

您可以创建文件级规则,例如:

- **Rule name**:"React components must use PascalCase file names"
- **Path**:`src/components/**/*.tsx`
- **Severity**:High
- **Instructions**:"Flag any component file that doesn't follow PascalCase naming."

### 示例:架构边界规则

```
Name: Domain layer must not depend on infrastructure
Execution mode: Per PR
Instructions: Flag any import added in src/domain/ that
points to src/infrastructure/. The allowed dependencies are
described in @file:docs/architecture.md.
```

### 示例:测试覆盖规则

```
Name: Every service change needs a test change
Execution mode: Per PR
Instructions: For each file modified in src/services/, check that the
PR also changes a matching test file under test/services/.
```

## 更多添加规则的方式

- **规则库**:在 Kody Rules 页面上点击 **Discovery**,添加现成的规则和规则包
- **代码库规则**:在代码库的 `.kody/rules` 中,每个 markdown 文件保存一条规则
- **自动生成**:Kody 根据审查者过去的评论起草规则
- **在审查线程中**:让 Kody 创建或更改规则,例如 `@kody update this rule to ignore test files`

要让 Kody 根据 `CLAUDE.md`、`AGENTS.md` 或 Cursor 和 Copilot 指令检查拉取请求,请参阅[编码代理指令](/zh/how_to_use/code_review/configs/rules_file_detection)。

完整参考,请参阅 [Kody Rules](/zh/how_to_use/code_review/configs/kody_rules)。
