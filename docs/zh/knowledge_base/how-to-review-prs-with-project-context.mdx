title: "如何使用项目特定上下文审查 PR"
description: "让 Kody 访问您的项目文档、手册和架构指南,以获得更相关的代码审查。"
---

通用代码审查发现通用问题。要获得真正与项目相关的反馈,Kody 需要理解您的具体上下文 — 架构决策、约定和业务规则。

## 提供上下文的方式

### 记忆

通过对话教 Kody 您的约定:

```
@kody remember: this project uses hexagonal architecture.
Domain layer must never depend on infrastructure.
```

记忆持久保存,并应用于所有未来的审查。

### 规则中的文件引用

直接在规则中引用您自己的文档:

```
Instructions: Validate that new endpoints follow the patterns
in @file:docs/api-conventions.md and use the base classes
defined in @file:src/shared/base-controller.ts.
```

### 类别说明

添加 Kody 在每次审查中包含的项目特定说明:

1. 在侧边栏中打开 **Code review → What to review**
2. 编辑 **Bug**、**Performance** 或 **Security** 类别的 **Instructions**,加入架构描述、团队指南或领域知识等上下文
3. Kody 在每次代码审查分析中包含此内容

如需更改 Kody 表述建议的方式(语气、长度),请使用 **Code review → What Kody writes** 中的 **Kody's personality**。

### 任务跟踪器

在 **Plugins** 中连接 Linear、Jira(**Atlassian Rovo**)、Notion 或 Git Issues。当 PR 引用某个任务时,Kody 会根据该任务的需求和验收标准检查 PR。参见[业务逻辑验证](/zh/how_to_use/code_review/business_logic_validation)。

### 插件

您安装的插件也是当您在 PR 评论中提及 Kody 时它可以使用的工具,也是您可以为[自定义代理](/zh/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp)开启的工具。将您自己的 MCP 服务器添加为自定义插件,即可引入其他工具。

## 示例工作流

1. 通过**记忆**定义架构规则:`@kody remember: we follow CQRS pattern in this service`
2. 创建引用文档的**审查规则**:`@file:docs/architecture.md`
3. 连接您的任务跟踪器,使 Kody 根据任务需求验证 PR
4. 在 **What to review** 中添加类别 **Instructions**,提供领域特定知识

更多详情,请参阅[类别说明](/zh/how_to_use/code_review/configs/custom_prompts)和[插件](/zh/how_to_use/code_review/plugins)。
