手动代码审查会造成瓶颈。审查者需要切换上下文,PR 排队等待,反馈质量参差不齐。AI 驱动的代码审查在每个 PR 上即时运行,在人工审查者查看代码之前就能发现问题。

## Kodus 如何自动化代码审查

连接后,Kodus 自动审查每个拉取请求。它分析代码的安全漏洞、性能问题、错误处理、可维护性以及您的自定义规则,然后直接在 PR 中发布评论。

### 支持的平台

- **GitHub** — 通过 GitHub App(或个人访问令牌)
- **GitLab** — 通过 OAuth(或个人访问令牌)
- **Bitbucket** — 通过 API 令牌
- **Azure DevOps**(Azure Repos)— 通过个人访问令牌
- **Forgejo** — 通过个人访问令牌

### 分析内容

默认情况下,Kodus 检查您可以在 **Code review → What to review** 中开启或关闭的类别,以及您自己的规则:
- 安全问题(SQL 注入、XSS、硬编码密钥)
- 性能问题(N+1 查询、缺少索引)
- 潜在 bug(空指针、资源泄漏、错误处理缺口)
- 业务逻辑合规性(根据关联任务需求验证)
- 您的自定义 Kody Rules(用于代码风格和团队约定)

### 审查节奏选项

在 **Code review → General** 的 **Automated code review** → **Review Cadence** 下设置审查节奏。

| 模式 | 行为 |
|------|------|
| **Automatic** | 审查每次推送,提供持续反馈 |
| **Auto-pause** | 在一连串审查之后暂停某个 PR(默认:15 分钟内 3 次)以避免噪音 |
| **Manual** | 在 PR 打开时审查一次,之后仅在您评论 `@kody start-review` 时审查 |

您也可以在任何 PR 上使用 `@kody start-review` 按需运行审查。所有命令以及审查被跳过的原因,请参见[代码审查流程](/zh/how_to_use/code_review/flow)。

### 审查之后会发生什么

Kody 还可以批准没有问题的 PR(参见[自动批准](/zh/how_to_use/code_review/configs/auto_approve)),并在出现严重问题时请求更改(参见[审查策略](/zh/how_to_use/code_review/policy))。两者默认均为关闭。Kodus 从不合并 PR。

## 开始使用

1. 在 [kodus.io](https://kodus.io) 创建工作区或[自托管 Kodus](/zh/how_to_deploy/deploy_kodus/generic_vm)
2. 连接您的 Git 提供商(GitHub、GitLab、Bitbucket、Azure DevOps 或 Forgejo)
3. 选择要监控的代码库
4. 打开一个 PR — Kodus 自动审查
