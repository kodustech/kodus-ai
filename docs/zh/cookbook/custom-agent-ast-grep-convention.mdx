## 为什么选择 ast-grep

有些约定是结构性的：“永远不要在这里调用这个函数”“始终传入这个选项”。模型可以发现它们，但也可能漏掉，或者凭空想象出一个。[ast-grep](https://ast-grep.github.io) 规则匹配的是语法树，所以一次匹配就是证明。引用了运行时已匹配规则的发现会跳过模型检查，直接发布。

示例是一个只有一条约定的结账服务：**金额是由 `Money` 辅助类处理的整数分，绝不使用浮点数。**

自定义 agent 处于 beta 阶段，适用于 Teams 和 Enterprise 套餐以及试用期间。自托管 Kodus 还需要 `BETA_FEATURES=true`。

## 步骤 1 — 在仓库中编写规则

在默认分支上提交一个规则文件。Kodus 从每个 pull request 的目标分支读取它，因此 pull request 无法放宽用来检查它自己的规则。

```yaml rules/money.yml
id: no-parsefloat-amount
language: typescript
message: Parse amounts with Money.parse; parseFloat turns cents into a float.
severity: error
rule:
  pattern: parseFloat($A)
---
id: no-tofixed-amount
language: typescript
message: Format amounts with Money.format; toFixed formats a float, not an amount.
severity: error
rule:
  pattern: $A.toFixed($N)
```

每条规则的 `message` 就是评论中作为该规则引用的内容，因此请为阅读 pull request 的人来写。

对于模式无法覆盖的情况，也把理由在文档中写一次：

```markdown docs/money.md
# Money

Amounts are integers in cents, wrapped in `Money`. Never store, add or compare an amount as a float.
Convert at the edges only: `Money.parse` on input, `Money.format` on output.
```

## 步骤 2 — 创建 agent

**New agent → Templates → Blank**，然后：

```text Name
Money handling
```

```text Instructions
Enforce the money convention in checkout and billing code: amounts are integer cents in Money, never floats.

First run the team's ast-grep rules on the changed files. Report every match as its own finding on the matched line, citing its rule.

Beyond the rules, flag arithmetic or comparison on amounts held as plain numbers only when docs/money.md states the rule; quote it.

Ignore tests and amounts that are not money (percentages, durations, counts).
```

| 字段 | 值 |
| --- | --- |
| **Files** | `src/checkout/**`, `src/billing/**` |
| **Except** | `**/*.test.ts` |
| **Skills & docs** | `docs/money.md`（**Add skill or doc → Add by path**） |

## 步骤 3 — 指向规则

在 **Tools → Advanced → Structural search (ast-grep rules)** 下，用单行输入路径：

```text
rules/money.yml
```

提示会列出它找到的规则：`2 rules in rules/money.yml: no-parsefloat-amount, no-tofixed-amount`。你也可以直接粘贴 YAML 而不是路径；此时规则存放在 agent 中，而不是仓库里。

## 步骤 4 — 评论

| 字段 | 值 |
| --- | --- |
| **Format** | Inline comments |
| **Minimum severity** | Team minimum |
| **Suggested fix** | When confident |

点击 **Save settings**。

## 步骤 5 — 试一试

在一个给价格添加了 `parseFloat` 的 pull request 上运行 **Try it**。该发现会被**保留**，其评论会引用规则：

```markdown
**Rule** (`ast-grep:no-parsefloat-amount`):
> Parse amounts with Money.parse; parseFloat turns cents into a float.
```

agent 根据 `docs/money.md` 提出的发现会引用该文档，如果引用内容不在目标分支上的文档中，该发现会被丢弃。

如果 **Warnings** 提示沙箱中未安装 ast-grep，说明 agent 是在没有规则的情况下运行的。

## 检查清单

- [ ] 规则文件已提交到默认分支
- [ ] 每条规则都有 `id`、`rule` 和可读的 `message`
- [ ] 字段提示列出了每一条规则
- [ ] glob 只覆盖该约定适用的代码
- [ ] 已在含有已知违规的 pull request 上试过

字段详情请参阅 [ast-grep 规则](/zh/how_to_use/code_review/custom_agents_knowledge_and_tools#ast-grep-rules)。
