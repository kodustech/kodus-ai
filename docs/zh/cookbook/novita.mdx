## Novita 工作原理

Novita 是一个无服务器推理平台,通过 **OpenAI 兼容**的 API 托管开源模型,例如 DeepSeek、Kimi、GLM、MiniMax 和 Qwen。Kodus 提供专用的 **Novita** 提供商,因此您只需要一个 API 密钥。

## 推荐模型

<Info>
  请在 [Novita 的模型列表](https://novita.ai/models/llm)查看当前的模型和定价。`https://api.novita.ai/openai/v1/models` 处的列表是公开的,显示每个模型的上下文大小和功能。
</Info>

Novita 的模型 ID 是 `org/model` 字符串,大多为小写。以下模型在 Novita 的目录中列出了函数调用和结构化输出支持:

| 模型 ID | 上下文窗口 |
| -------- | -------------- |
| `deepseek/deepseek-v4-pro` | 约 1M tokens |
| `moonshotai/kimi-k3` | 约 1M tokens |
| `zai-org/glm-5.3` | 约 1M tokens |
| `minimax/minimax-m3` | 约 1M tokens |
| `qwen/qwen3.8-27b` | 约 1M tokens |

## 创建 API 密钥

<Warning>创建 API 密钥需要 Novita 账号。</Warning>

1. 在 Novita 控制台中打开 [**Key Management**](https://novita.ai/settings/key-management)。
2. 选择 **Create API Key** 并为其命名,例如 `kodus`。
3. 选择有效期:**Permanent**、90 天、30 天或 24 小时。之后无法更改,且 Novita 会拒绝已过期的密钥。
4. 复制密钥。Novita 只会完整显示一次。

## 在 Kodus 中配置 Novita

### 方式 1 — AI providers 页面(推荐)

此流程在 Kodus Cloud 和自托管实例上相同。

<Steps>
  <Step title="打开 AI providers 并选择 Novita">
    在侧边栏中打开 **AI providers**(Cloud 上为 [app.kodus.io/byok](https://app.kodus.io/byok),自托管实例上为 `/byok`)。在 **Providers** 选项卡上,点击 **Novita** 磁贴。它位于 **Connect your first provider** 下方;如果已连接过提供商,则位于 **Add another provider** 之后。
  </Step>

  <Step title="粘贴 API 密钥并选择模型">
    将 Novita 密钥粘贴到 **API key** 卡片的 **Key** 字段中。**Base URL (optional)** 留空:此时 Kodus 会调用 `https://api.novita.ai/v3/openai`。在 **Model** 卡片中,从列表中选择一个模型,或选择 **Type model manually**。
  </Step>

  <Step title="Test & save">
    点击 **Test & save**。Kodus 会向模型发送一个单 token 请求,成功后保存配置。
  </Step>
</Steps>

然后打开 **Code review → Routing**(**AI providers** 页面上的 **Configure routing** 按钮会打开它)。在 **Models** 卡片中,将 Novita 模型设置为 **Default model**,并将另一个已连接提供商(如 OpenAI 或 Anthropic)的模型设置为 **Fallback model**,这样当 Novita 不可用时审查仍能继续。点击 **Save settings**。

### 方式 2 — 自托管(环境变量)

自托管实例可在 `.env` 中选择 OpenAI 兼容提供商，并使用与内置 Novita 提供商相同的基础 URL。

```env
API_LLM_PROVIDER=openai_compatible
API_LLM_PROVIDER_MODEL="deepseek/deepseek-v4-pro"
API_LLM_BASE_URL="https://api.novita.ai/v3/openai"
API_LLM_API_KEY="your-novita-api-key"
```

按照安装指南[应用模型配置变更](/zh/how_to_deploy/deploy_kodus/generic_vm#应用模型配置变更)。

## 故障排查

<AccordionGroup>
  <Accordion title="API 密钥问题">
    - 在 [Novita 控制台](https://novita.ai/settings/key-management)中验证您的 API 密钥是否正确且处于活动状态
    - 检查您的 Novita 账户中是否有足够的额度
    - 确保 `.env` 值中没有尾随空格或引号
  </Accordion>

  <Accordion title="模型未找到">
    - 模型 ID 是 `org/model` 字符串,少数包含大写字母。请从 Novita 的模型列表复制精确的 ID
    - 检查该模型是否仍在 `https://api.novita.ai/openai/v1/models` 的列表中
  </Accordion>

  <Accordion title="连接错误">
    - 验证您的服务器是否有互联网访问权限以访问 `api.novita.ai`
    - 检查是否有任何防火墙限制
    - 查看 API 和 worker 日志获取具体的上游错误
  </Accordion>
</AccordionGroup>
