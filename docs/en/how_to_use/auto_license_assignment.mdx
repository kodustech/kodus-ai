---
title: "Auto License Assignment"
description: "Let Kodus assign developer licenses automatically to active contributors instead of managing every seat by hand."
---

The Auto License Assignment feature simplifies the management of developer licenses within your organization. Instead of manually assigning licenses to each developer, Kodus can automatically assign a license to active contributors.

Organizations with a paid plan that uses seats, including licensed self-hosted deployments. Owners manage this setting in **Subscription → PR licenses**.

## How it Works

On a paid plan, Kodus checks the author of each pull request it is about to review. With **Auto-assign licenses** on:

-   **Their first PR is reviewed without a seat.** Kodus counts the PRs it has recorded for the author.
-   **From their second PR, Kodus assigns a license** if one is available, and the review proceeds.
-   **If the author has no license and none can be assigned**, because no seat is free or **Auto-assign licenses** is off, the review is skipped and Kodus reacts to the pull request with a thumbs down emoji (👎) on GitHub and Forgejo, a padlock emoji (🔒) on GitLab, or a 👎 comment on Azure DevOps and Bitbucket. The reaction only appears when **Show status feedback** is on in **Code review → General**.

Licenses only apply on a paid plan with seats. The Free plan and the trial have none; see [Plans and Licenses](/en/how_to_use/pricing).

## PR author filters

Two filters decide which authors Kody reviews at all. They are set on the **Repositories** page, **PR author filters** tab:

-   **Exclude PR authors:** Kody won't review PRs opened by the authors you list.
-   **Only these PR authors:** Kody reviews PRs opened by the authors you list, and no one else.

Both filters also keep the person out of automatic license assignment.

-   **No Reviews:** Pull requests from a filtered-out author are not reviewed, unless that author holds a license, which overrides the filter.
-   **Skipped, not silent:** Kody records the skip as "User is ignored by configuration" and lists the PR under **Kody skipped**. Unless **Show status feedback** is off, it also marks the PR with 👀 (a 👀 comment on Azure DevOps and Bitbucket). It never adds the no-license reaction (👎 or 🔒) for these authors.

This is useful for bots, service accounts, or team members who do not need code reviews. Bots that author PRs are added to the excluded list when the Git integration is created.

## Configuration

To enable and configure Auto License Assignment:

1. In the sidebar, open **Organization → Subscription**.
2. Stay on the **PR licenses** tab.
3. Turn **Auto-assign licenses** on or off.
    - **Release seats automatically** (same card) frees a license a few days (7 by default) after a member leaves your git organization.
    - **Release N unused seats** lists the licenses held by people who are no longer in your git organization, and frees them in one step.
    - **Assign by git ID** seats someone who isn't in the list.
    - To filter authors, use **Repositories → PR author filters** (see [PR author filters](#pr-author-filters)).

The two toggles appear only with an active paid plan or a licensed self-hosted instance, and only to members who can manage seats (Owners).

On GitLab, the license list checks recent merge request authors on connected projects when a seat holder is missing from the member list. An author found in that check keeps their seat. If the provider can’t complete the check, Kodus keeps seats in place. This GitLab check was added after self-hosted 2.2.11.
