A plugin is a remote Model Context Protocol (MCP) server connected to your workspace: a ticket tracker, a wiki, an error monitor. Kody reads from it, and acts on it only when you ask.

| Where | What happens |
| --- | --- |
| A comment that mentions `@kody` | Kody calls an installed plugin and answers in the same thread. It changes something, such as moving a ticket or editing a rule, only when your comment asks for it. |
| [Business logic validation](/en/how_to_use/code_review/business_logic_validation) | Kody reads the task a pull request references from your tracker. |
| [Custom agents](/en/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp) | An agent reads from the plugins you turn on for it. Read tools only. |

## Plugins page

Open **Plugins** in the sidebar. Only Owners can install or change plugins; Billing Managers, Repo Admins and Contributors can view them. Each card shows a plugin and, once connected, **Installed**, **Default** or **Locked**. On a self-hosted install the page needs the [MCP Manager](/en/how_to_deploy/deploy_kodus/mcp_manager).

| Plugin | What Kody can read | Sign-in |
| --- | --- | --- |
| **Git Issues** | Issues of your repository's tracker (GitHub, GitLab, Bitbucket or Forgejo), through your Git connection | None |
| **Linear** | Issues, projects and cycles | OAuth or API key |
| **Atlassian Rovo** | Jira and Confluence | OAuth or API token |
| **Notion** | Pages, databases and docs | OAuth |
| **Sentry** | Projects, issues and events | OAuth |
| **Fireflies** | Meeting transcripts, summaries and action items | API key |
| **Kodus Docs** | The Kodus documentation | None |
| **Exa Search** | Web and code search | None |
| **Kodus OSV** | Known vulnerabilities of packages | None |

**Kodus MCP** is connected in every workspace (**Default**). It reads repositories, pull requests, commits, files and diffs from your Git provider, and manages Kody Rules, memories and Kody issues. It is always on and doesn't count toward the Free plan limit below.

## Install a plugin

<Steps>
  <Step title="Open the plugin">
    Click its card.
  </Step>
  <Step title="Connect it">
    A plugin with a sign-in asks for it first: click **Authenticate with** the plugin (OAuth), or fill in the fields and click **Connect** (API key or token). It is installed as soon as it connects. Kody starts with the tools the plugin marks read-only, or with every tool when it marks none.

    A plugin without a sign-in goes straight to **Selected tools**. Choose the tools Kody may use and click **Install plugin**.
  </Step>
  <Step title="Change the tools later">
    Open an installed plugin, change **Selected tools** and click **Update Tools**. **Reset Authentication** disconnects it.
  </Step>
</Steps>

Tools whose names suggest a destructive action (delete, remove, archive) are marked with a warning and start unselected. To install with one selected, confirm it in the checkbox at the bottom. Kody can use any tool you select, so select only what it needs.

<Note>
  On the Free plan (and unlicensed self-hosted), Kody runs up to 3 installed plugins at a time, the oldest first. A banner on the Plugins page names the ones it skips, and their cards show **Locked**. **Git Issues** can't be installed when your code provider is Azure Repos or Bitbucket Data Center, which have no native issue tracker.
</Note>

## Custom plugins

Add your own MCP server when the catalog doesn't cover a tool. The server must be reachable from Kodus: a remote HTTP or SSE endpoint, not `localhost`.

<Steps>
  <Step title="Add it">
    On the **Add Custom Plugin** card, click **Add Plugin**.
  </Step>
  <Step title="Fill in the form">
    | Field | Notes |
    | --- | --- |
    | **Plugin Name** | Required. |
    | **Description**, **Logo URL** | Optional. They help teammates recognize it in the catalog. |
    | **URL** | The MCP endpoint. |
    | **Protocol** | **HTTP** or **SSE**. |
    | **Authorization** | **None**, **Bearer Token**, **Basic Auth**, **API Key** (with the header name) or **OAuth 2.0**. OAuth 2.0 uses **Use Dynamic Client Registration**, or a **Client ID**, an optional **Client Secret** and optional **Scopes**. |
    | **Custom Headers** | Extra headers, added with **Add Header**. A header the authorization sets is overridden by it. |

    Click **Create Plugin**.
  </Step>
  <Step title="Install it">
    The plugin opens. With OAuth 2.0, click **Authenticate with** the plugin first. Then choose its tools under **Selected tools** and click **Install plugin**. If the list is empty, check the URL, protocol and authorization.
  </Step>
</Steps>

Open a custom plugin to **Edit Plugin** or **Delete Plugin**. See [Install custom MCP plugins](/en/cookbook/custom-plugin-install) for a full walkthrough.

## Use plugins in a reply

<img src="https://kodus.io/wp-content/uploads/2025/10/comment-mcp.gif" alt="Example of using a plugin in a suggestion" />

Mention Kody in a comment on a suggestion or on the pull request. Kody calls the plugin it needs and replies in the same thread.

- `@kody, update this kody rule to ignore test files`
- `@kody, move this task https://jira.com/task-123 to DONE`
