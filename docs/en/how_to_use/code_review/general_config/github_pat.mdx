## Introduction to FGPAT

To enable Kody to perform automatic Code Reviews, you need to generate a Fine-Grained Personal Access Token (FGPAT) in GitHub. This token allows Kody to securely access your repositories and perform code analysis in a controlled manner.

## Check Fine-Grained Access Permissions

By default, a Fine-Grained PAT may not have access to your organization’s content. Ensure access by following these steps:

![title](/images/fgpat.png)

1. You must be the organization owner.
1. Go to your organization's settings in GitHub:
   - You can use this URL replacing with your org name: <small>https://github.com/organizations/YOUR_ORG_NAME/settings/personal-access-tokens</small>.
1. In the left sidebar, under **Personal access tokens**, click **Settings**. On the **Fine-grained tokens** tab, select **Allow access via personal access tokens** and click **Save**.

## Generating the FGPAT (Fine-Grained Personal Access Token)

Follow these steps to set up the token correctly:

1. **Access GitHub and go to your profile settings**:

   - [Click here to access the profile settings page](https://github.com/settings/profile).

2. **Navigate to `Developer Settings`**:

   - In the left sidebar, scroll down to find `Developer Settings` and click on it.

3. **Go to `Personal Access Tokens`**:

   - Still in the left sidebar, under `Developer Settings`, select `Personal Access Tokens`.
   - Then, click on [Fine-grained Tokens](https://github.com/settings/tokens?type=beta).

4. **Generate a new token**:

   - Click the `Generate new token` button.

5. **Set up the new token with the following specifications**:

   - **Token Name**: Choose an easily identifiable name, such as `kody_code_review`.
   - **Expiration Date**: If possible, select a long expiration date, preferably at least 180 days.
   - **Resource Owner**: Ensure the organization is set as the token owner, as the team’s repositories are under the organization.
   - **Repository Access**: Select **All repositories** to allow the token access to all repositories.
   - **Permissions**: Configure the following permissions:
   - **Repository**:
     - **Commit statuses**: Read permission.
     - **Contents**: Read and write permission.
     - **Issues**: Read permission.
     - **Metadata**: Read permission.
     - **Pull requests**: Read and write permission.
     - **Webhooks**: Read and write permission.
   - **Organization**:
     - **Members**: Read permission.

   Kody does not use **Actions** or **Deployments**; leave them at **No access**.

6. **Finalize and save the token**:
   - After setting up the permissions, click on `Generate token`.
   - Make sure to copy the generated token and store it securely, as you’ll need it to configure Kody.

## Adding the Token to Kody

After generating the token, paste it into Kodus:

- **During onboarding**: on **Connect your Git tool**, pick the **Github** tab and click **Connect via token**.
- **Later**: in the sidebar, open **Repositories**, click **Github** under **Connect a provider**, switch to the **Token** tab, paste the token and click **Validate and save**.
- **Replacing a token**: on **Repositories**, click **Reset** on the **Github** card, choose **Just reset the integration**, then connect again with the new token as described above.

With a token, reviews are published under your GitHub profile instead of Kody's, and GitHub Checks / PR status aren't available.

## GitHub Enterprise Server (Beta)

To connect GitHub Enterprise Server with a token, your Cloud workspace needs access to this beta. On self-hosted Kodus, set `BETA_FEATURES=true`.

1. Create the token on your GitHub Enterprise Server instance.
2. In the **Github** token dialog, turn on **Self-hosted** and enter your **GitHub Enterprise URL**, for example `https://github.your-company.com`. It must start with `http://` or `https://`.
3. Paste the token and click **Validate and save**.

Kodus calls the instance's API at `<GitHub Enterprise URL>/api/v3`. If the token or the URL is wrong, the dialog says **Invalid Token or GitHub Enterprise URL**.
