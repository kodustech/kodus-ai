---
title: "Custom Messages"
description: "Edit the comments Kody posts when a review starts, ends or fails, and how its comments appear on the pull request."
---

Open **Code review → What Kody writes**. The messages are in the **Comments during the review** section, with one tab per message: **Review starts**, **Review ends** and **Review fails**. Each tab has a **Message** box and a **Reset to…** menu. The menu offers **Inherited message** at repository and directory scope, and **Default message** at Global.

Messages can be set at Global, Repository and Directory scope.

## How the messages appear

Kody posts the start message when a review begins. When the review ends, it edits that same comment into the end message. Suggestions are posted as review comments in between.

- **Start and end both posted:** one comment, showing the start message first and the end message once the review finishes.
- **Start not posted this run:** the end message is posted as a new comment after the review.
- **End set to Never:** the start comment stays as it is, also after a failed review. The 😕 reaction is then the only sign of the failure.
- **Review fails:** Kody posts its default error comment instead of your end message, with your **Review fails** text below it.

On GitHub, when a new review starts, Kody collapses the comment from the previous review.

## Post this message

On **Review starts** and **Review ends**, the **Post this message** select sets when that message is posted. Each message has its own setting.

- **On every push** (`every_push`, default) — posted on every review run: when the pull request opens and after each push that triggers a review.
- **Only when the PR opens** (`only_when_opened`) — posted once, on the first review run.
- **Never** (`off`) — not posted. The text is kept, and the **Message** box and **Add context** are disabled. Kody still runs the review and posts suggestions.

Messages are posted only when a review runs. With a **Manual** review cadence and **Automated code review** on, the first review runs when the pull request opens; later pushes post nothing until someone comments `@kody start-review`.

## Add context

The **Add context** menu next to **Message** inserts a token that Kody replaces with real data from the pull request.

| Menu item | Token | What it adds |
| --- | --- | --- |
| **Changed files** | `@changedFiles` | A collapsible table of the changed files, with status, additions and deletions. |
| **Changes summary** | `@changeSummary` | Totals for files, lines added, lines removed and changes. |
| **Review options** | `@reviewOptions` | Which review categories are on or off. |
| **Review cadence** | `@reviewCadence` | How follow-up reviews work: automatic, auto-pause with its limits, or manual. |
| **Review scope** | `@reviewScope` | Which level, global, repository or directory, was used for this review. |
| **Agent Prompt** | `@agentPrompt` | Every suggestion from the review as one prompt to paste into a coding agent, in a collapsible **Open Agent Prompt** block. |

`@agentPrompt` is offered on **Review ends** only, because its content exists only after the review.

## Review fails message

Write text on the **Review fails** tab to append it below the comment Kody posts when a review fails, for example when no AI provider is configured or the provider rejected the request. Use it to point people at an internal owner or runbook.

There is no switch for this message: the text is the switch. Empty (the default) keeps Kody's standard error comment as it is.

## Comment visibility

The **Comment visibility** section has two settings.

| Setting | Default | What it does |
| --- | --- | --- |
| **Post as hidden comment** (`hideComments`) | Off | The comment that carries the **Review starts** and **Review ends** messages is posted collapsed, as outdated, so the pull request conversation stays short. Inline suggestions and PR-level comments are not collapsed. GitHub only; the switch is hidden when GitHub is not connected. |
| **Add a copyable prompt to each suggestion** (`suggestionCopyPrompt`) | On | Each suggestion carries a prompt the developer can paste into an AI assistant to apply the fix. On Bitbucket the prompt is posted as a reply in the same thread; with the setting off, Bitbucket comments show no fix. |

## YAML

Messages are stored as `customMessages` in `kodus-config.yml` files of a [centralized config](/en/how_to_use/code_review/configs/centralized_config) repository. A `kodus-config.yml` at the root of a reviewed repository does not change them; use the app.

```yaml
customMessages:
    startReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: |
            Review started. @changedFiles
    endReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: |
            Review finished. @changeSummary
    errorReviewMessage:
        status: 'active' # off | active; a review reads only content
        content: |
            Reviews failing? Ping #platform-eng.
    globalSettings:
        hideComments: false
        suggestionCopyPrompt: true
```
