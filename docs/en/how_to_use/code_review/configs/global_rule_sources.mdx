Global Rule Sources let you point Kodus at one or more connected repositories and import their rule files as **global** Kody Rules. Unlike [Repository Rules](/en/how_to_use/code_review/configs/repository_rules), which apply only to the repository they live in, rules imported from a global source apply to **every** repository during code review.

Use this when a team keeps its architecture and coding standards in a dedicated "standards" repository and wants them enforced everywhere, without copying rule files into each project.

## How it works

- You select connected repositories to act as **sources**.
- Kodus scans each source repository's default branch for rule files, in the same locations and with the same template as [Repository Rules](/en/how_to_use/code_review/configs/repository_rules) (`.kody/rules/`, `rules/**/*.md`, and so on).
- Each rule file becomes a global rule, shown on the global **Kody Rules** page with the file it came from.
- During code review of any repository, these global rules apply alongside that repository's own rules, subject to [inheritance](/en/how_to_use/code_review/configs/rules_inheritance).
- Instructions written for coding agents (`CLAUDE.md`, `AGENTS.md`, `.cursor/rules/**`) are not imported. Global rules imported from them in the past are kept but frozen; see [Coding-Agent Instructions](/en/how_to_use/code_review/configs/rules_file_detection).

<Info>
Only repositories already connected on the **Repositories** page can be sources, so imported rules stay up to date through the pull request trigger described below.
</Info>

## Setup

1. In the sidebar, pick **Global** in the scope picker at the top of the **Code review** group, then open **Kody Rules**.
2. Click **Configuration** to open the side sheet, and find **Global rule sources**.
3. Click the repository picker and select one or more connected repositories.
4. Click **Import selected**.

Importing runs in the background. When it finishes, the imported rules appear in your global Kody Rules list. A repository you picked but have not imported yet shows **Not imported yet**.

## Keeping rules up to date

- **On merge:** when a pull request is merged in a source repository, its rule files are re-scanned and the global rules are updated. Unchanged files are skipped.
- **Resync now:** re-scans every source on demand. Use it after a push straight to a source repository's default branch, which is not detected automatically.

## Removing a source

Removing a repository from the list **deletes the global rules imported from it**, so they stop applying during code review. You are asked to confirm first. Rules from your other sources, and rules you wrote by hand, are not affected.

## Source repositories are not reviewed

A repository used as a source of global rules is treated as a configuration repository, not a codebase. Kodus **skips code review** on pull requests opened in it, the same way it does for a [centralized configuration](/en/how_to_use/code_review/configs/centralized_config) repository.

## Plan availability

| Plan | Access |
|------|--------|
| **Free**, self-hosted without a valid license key, or a canceled or expired plan | Not available. |
| **Trial** | Up to **5 global rules in total**, across all source repositories. Only the first 5 rules found are imported; once the limit is reached, nothing more is imported until you remove some or upgrade. |
| **Paid** (cloud) and **licensed self-hosted** | Unlimited. |

On the Trial plan, a counter shows how many of the 5 rules are used, and a confirmation dialog says how many more will be added before you import.
