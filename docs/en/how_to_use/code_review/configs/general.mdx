Open **Code review → General** (page title **General settings**). Review categories and the severity threshold are on [What to review](/en/how_to_use/code_review/configs/what_to_review). Summaries, messages and Kody's voice are on **What Kody writes**.

<Note>
  Kodus has three config levels: Global, Repository, and Directory. Learn how they work in <a href="/en/how_to_use/code_review/configs/inheritance_overrides">Config Inheritance & Overrides</a>.
</Note>

## Automated code review

The **Automated code review** switch makes Kody review pull requests when they open. It is on by default. With it off, start a review by commenting `@kody start-review` on the pull request.

<Info>
  This switch covers the **initial review**. For later pushes, see Review Cadence below.
</Info>

### Review Cadence

Shown when **Automated code review** is on. It decides how Kody handles reviews after the first one:

<Tabs>
  <Tab title="Automatic">
    Review every new push. This is the default.
  </Tab>

  <Tab title="Auto-pause">
    Pause reviews when pushes arrive in a burst. Once Kody has reviewed a pull request **Pushes to trigger pause** times within **Time window (minutes)**, the next push is not reviewed and the pull request stays paused until you comment `@kody start-review`.

    Defaults: 3 pushes in 15 minutes.
  </Tab>

  <Tab title="Manual">
    Kody reviews the first push when the pull request opens. Later pushes are reviewed only when you comment `@kody start-review`.
  </Tab>
</Tabs>

### Review draft pull requests

**Review draft pull requests** is on by default, so drafts get reviewed. Turn it off to skip them until they are marked ready.

## Review mode

General shows the review modes and models in effect. Follow **Configure routing** to change the mode, or the modes chosen by the risk result, and to override the model for a repository or directory. See [Routing](/en/how_to_use/code_review/configs/routing).

Risk assessment has its own page and switch. See [Risk assessment](/en/how_to_use/code_review/configs/risk).

## PR workflow

**Automatic PR approval** — Kody approves a PR after a clean review, or once every comment it left is resolved. It never merges. Approval policies define which clean PRs Kody may approve, and active risk assessment applies to every policy. See [Auto-approve](/en/how_to_use/code_review/configs/auto_approve).

**Platforms:** GitHub, GitLab, Bitbucket, Azure Repos, Forgejo

## Review feedback

- **Request changes on critical issues** (`isRequestChangesActive`, off by default) — when Kody finds a critical issue, it sets the pull request review to Request Changes. Kody takes the request back once those findings are resolved, even on a pull request it does not approve. Platforms: GitHub, Bitbucket, Azure Repos, Forgejo. The switch is hidden when GitLab is your only connected platform.
- **Show status feedback** (on by default) — Kody reacts or comments when a review is skipped or blocked.
- **Committable suggestions** (Alpha, on by default) — Kody can suggest code you apply directly as a commit. GitHub only; the switch is disabled without a GitHub connection.

## Review scope

Kody skips files and pull requests that match these settings. Reviews started with `@kody start-review` ignore **Ignore title keywords**, **Base Branches** and **Review draft pull requests**.

### Ignored files

Glob patterns for files Kody skips. Patterns are case-sensitive and match dotfiles. The field shows a few patterns; **Edit** opens the **Ignored files** dialog. Each new pattern is checked for valid glob syntax, and **Test a file** tells you whether a path would be ignored, and by which pattern, or reviewed. **Apply** only updates the field. Nothing is saved until you click **Save settings**.

The default list is long: `yarn.lock`, `package-lock.json`, `package.json`, `.env`, `**/*.json`, `**/*.xml`, `**/*.lock`, `**/*.min.*`, images, fonts and archives, IDE and OS files, and folders such as `**/build/**`, `**/bin/**`, `**/out/**`, `**/vendor/*`, `**/deploy/**` and `**/prod/**`. If Kody skips files you expect it to review, check the list for a broad pattern and remove it.

When all changed files are ignored, a review can still run for a custom agent that explicitly includes one of those files. Deleted files are excluded. Kody skips a review when more than 2,000 files remain for the main review and custom agents combined. Use **Ignored files** to exclude generated or vendored folders.

### Ignore title keywords

Kody skips pull requests whose title contains any of these keywords. Matching is case-insensitive, and each keyword can be up to 100 characters.

### Base Branches

Which target branches get automatic reviews.

<Info>
  **Empty, the default, means only the repository's default branch.** Add entries to review other branches. Once the list has entries, Kody reviews pull requests that match one of them, plus the default branch unless you exclude it with `!`.

  Entries are matched against the pull request's **target** branch, except `contains:`:

  | Entry | Effect |
  | --- | --- |
  | `develop` | Reviews pull requests targeting `develop`. |
  | `release/*` | Reviews pull requests targeting any branch that starts with `release/`. `*` matches any characters, slashes included. |
  | `*` | Reviews pull requests targeting any branch. |
  | `!staging` | Never reviews pull requests targeting `staging`. An exclusion wins over every other match. Use `!main` to opt the default branch out. |
  | `contains:hotfix` | Reviews pull requests whose **source** branch contains `hotfix`, whatever the target. |

  Each entry can be up to 100 characters.
</Info>

## kodus-config.yml

### Config Priority

You can keep review settings in a `kodus-config.yml` file at the root of a repository instead of the web app.

<Warning>
  **The file is ignored until you opt in.** Kody never reads `kodus-config.yml` unless **Prefer kodus-config.yml settings** is on for the repository. Committing the file alone does nothing.

  Pick the repository in the scope picker at the top of the **Code review** group, open **Code review → General**, and turn on **Prefer kodus-config.yml settings**. The switch also appears at directory scope, but only the repository's setting decides whether the file is read. It is a web setting: it cannot be turned on from the file. The sidebar then shows **kodus-config.yml applied**, **kodus-config.yml not found** or **kodus-config.yml unavailable** under the scope picker.
</Warning>

- Kody reads the file from the root of the repository's default branch.
- The file is applied on top of Global and the repository's web settings. Declare only the keys you want to change; omitted keys keep their web value.
- Nested settings merge key by key. A list in the file, such as `ignorePaths`, replaces the list from the web.
- A setting overridden on a directory scope takes precedence over the same setting in the repository's file. See [Config Inheritance & Overrides](/en/how_to_use/code_review/configs/inheritance_overrides).
- Unknown top-level keys are dropped without an error. If a setting seems to have no effect, check the spelling against the sample below.
- `customAgents` and `knowledge` are not read from the file. The review comment says so; configure custom agents in the app.
- Kody Rules settings and `customMessages` are not read from a repository's own file. Set them in the app, or in a [centralized config](/en/how_to_use/code_review/configs/centralized_config) repository, where the same files can carry them.

<Accordion title="Sample kodus-config.yml">
```yaml
version: 2.0

# general
automatedReviewActive: true
reviewCadence:
    type: 'automatic' # automatic | auto_pause | manual
    timeWindow: 15 # minutes, auto_pause only
    pushesToTrigger: 3 # auto_pause only
runOnDraft: true
reviewMode: balanced # balanced | heavy
riskAssessmentActive: false
riskCriteria: []
riskReviewRouting:
    noRisk: balanced
    riskFound: heavy
byokModel: '' # empty = inherit (directory -> repository -> the organization's main model)
pullRequestApprovalActive: false
approvalPolicies: []
approvalSensitivePaths: []
isRequestChangesActive: false # not available on GitLab
showStatusFeedback: true
enableCommittableSuggestions: true # GitHub only

# review scope
ignorePaths:
    - 'yarn.lock'
    - 'package-lock.json'
    - 'package.json'
    - '.env'
    - '**/*.json'
    # ...abbreviated: the shipped default lists about 1,100 patterns in total
ignoredTitleKeywords: []
baseBranches: [] # empty = the repository's default branch only

# linked repositories — Teams / Enterprise only, up to 3
linkedRepositories: []

# what to review
reviewOptions:
    bug: true
    performance: true
    security: true
    business_logic: true
repoInstructionsEnabled: false # check changes against CLAUDE.md / AGENTS.md / .cursor/rules
suggestionControl:
    severityLevelFilter: 'medium' # low | medium | high | critical
    applyFiltersToKodyRules: false
deterministicEvidence: # beta
    ciChecks: false
    tools:
        secrets: false
        dependencies: false
# businessLogic: see Business Logic Validation
# v2PromptOverrides: see Instructions & Personality

# what Kody writes
summary:
    generatePRSummary: true
    behaviourForExistingDescription: 'replace' # replace | concatenate | complement
    behaviourForNewCommits: 'none' # none | concatenate | replace
    customInstructions: ''
```
</Accordion>
