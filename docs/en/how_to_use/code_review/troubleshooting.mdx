## No Response or No Comments from Kody

Start with the reaction on the PR. 👀 means Kody skipped the review, 😕 means it failed, and 🎉 means it finished (a clean review posts no inline comments). On GitHub (GitHub App) and Forgejo, the **Kody Code Review** check shows the reason for a skip. [When Kody skips](/en/how_to_use/code_review/flow#when-kody-skips) lists every reason and its fix.

### If an automatic review never starts

1. Confirm the repository is selected in **Repositories** or covered by **Review every repository**.
2. Check whether the Git provider delivered the PR event. [Diagnose webhook delivery](/en/knowledge_base/how-to-fix-webhook-issues).
3. Open **Code review → General** at repository scope and check **Automated code review**. If this repository uses [kodus-config.yml](/en/how_to_use/code_review/configs/general#kodus-config-yml), check `automatedReviewActive` there.
4. To request a review now, comment `@kody start-review` on the PR. [Check the recorded skip reason](/en/how_to_use/code_review/flow#when-kody-skips) if Kody still skips it.

### The review finished with no suggestions

Ensure at least one category (Bug, Performance, Security, Business Logic) is turned on for Kody to provide suggestions, and check the **Minimum severity to post**. Both live in **Code review → What to review** ([open](https://app.kodus.io/settings/code-review/global/review-scope)).

## Reviews stopped after a push

Comment `@kody start-review` to resume a paused PR or request a review in **Manual** mode. To review every new push automatically, choose **Automatic**. See [Review cadence](/en/how_to_use/code_review/flow#review-cadence) for how each mode works.

## Token Issues

Check whether the token is active, can access the repository and has the permissions listed for your provider.

[GitHub](/en/how_to_use/code_review/general_config/github_pat) · [GitLab](/en/how_to_use/code_review/general_config/gitlab_pat) · [Bitbucket](/en/how_to_use/code_review/general_config/bitbucket_pat) · [Azure DevOps](/en/how_to_use/code_review/general_config/azure_devops_pat) · [Forgejo](/en/how_to_use/code_review/general_config/forgejo_pat)

## Global vs. Repository Settings

Check the effective repository or directory settings with the scope picker under **Code review**. See [how settings inherit](/en/how_to_use/code_review/configs/inheritance_overrides) to find the override.

`kodus-config.yml` only applies when **Prefer kodus-config.yml settings** is on in **Code review → General** for that repository. A badge under the scope picker shows whether the file was applied, not found or unavailable.

## Kody says it is already reviewing this PR

A review command (`@kody review`, `@kody -v …`) sent while another review runs on the same PR waits and starts when the current review finishes. If that review is still running when Kody stops waiting (about 25 minutes at most), Kody comments "Kody is already reviewing this PR" and does not start the command. Wait for the review to finish, then ask again.

## Merge queue removes PRs while waiting for Kody Code Review

On GitHub, when `Kody Code Review` is a required check and a PR enters the merge queue, Kody reports the PR's last finished review result on the commit the queue tests. No new review runs. This needs Kody connected through the GitHub App; with a personal access token Kody posts no checks.

The check means Kody reviewed the PR, not that the PR is free of issues. It passes even with critical suggestions still open, and on the PR it fails only when the review itself could not run. Requiring it guarantees a review happened; it does not block a merge on Kody's findings.

If the PR's latest commit has no finished Kody review when it enters the queue (for example because an admin bypassed the required check), the check fails at once with **No finished Kody review** and the queue removes the PR. Comment `@kody start-review` on the PR, let the review finish, then add it to the queue again. **Could not carry Kody's review** means GitHub did not return the review result; add the PR to the queue again.
