## What is PR Size

PR Size is the average number of lines changed in your pull requests. It shows how your team breaks down work, and large PRs are often a sign of slow reviews.

In the Cockpit, it's the **PR Size** card on the **Productivity** tab.

## How We Calculate It

```
PR Size = (Total lines changed in the PRs) ÷ (Number of PRs)
```

- It covers PRs closed in the selected date range, merged or closed without merging.
- Lines changed are the lines added and deleted in each PR. A PR with no recorded size counts as 0 lines.

For example, if you have 3 PRs with 50, 100, and 150 lines changed, your average PR size is 100 lines.

## Reading the card

The card shows the average, a level badge, and the value for the previous period of the same length with the percentage change (lower is better). The footer reads "Last 2 weeks was …" whatever range is selected; the number is for the previous period. Hover the badge to see the levels:

| Lines changed | Level |
| --- | --- |
| Less than 250 | Elite |
| 250 to 400 | High |
| 400 to 600 | Fair |
| More than 600 | Need focus |

<Note>
  The card title reads **PR Size (p75)**, but the value is the average, as described above.
</Note>

## Why It Matters

- **Review Quality**: smaller PRs are easier to review thoroughly
- **Deployment Speed**: smaller changes can be deployed more often
- **Risk Management**: large changes carry more risk of bugs

## How to Improve

- Use feature flags for incremental rollout
- Break user stories into smaller, focused tasks
- Set clear PR size limits (200-400 lines recommended)
- Build vertical slices instead of technical layers
