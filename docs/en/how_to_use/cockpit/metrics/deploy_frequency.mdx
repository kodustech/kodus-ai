## What is Deploy Frequency

Deploy Frequency is the average number of pull requests your team closes per week. Cockpit doesn't read deployments from your CI/CD, so it uses closed pull requests as a stand-in for how often code reaches production.

In the Cockpit, it's the **Deploy Frequency** card on the **Productivity** tab.

## How We Calculate It

```
Deploy Frequency = (PRs closed in the range) ÷ (weeks in the range)
```

- The range is the date range selected at the top of the Cockpit. Its length in weeks is rounded up, with a minimum of one week.
- Every closed PR counts, whatever its base branch, and a PR closed without merging counts the same as a merged one.

For example, if 12 PRs close in a 4-week range, Deploy Frequency is 3 per week.

If your team deploys on a different rhythm than it closes PRs (for example, release trains or deploys from feature branches), read this number as PR throughput, not deployments.

## Reading the card

The card shows the average per week, a level badge, and the value for the previous period of the same length with the percentage change. The footer reads "Last 2 weeks was …" whatever range is selected; the number is for the previous period. Hover the badge to see the levels:

| PRs closed per week | Level |
| --- | --- |
| More than 5 | Elite |
| 2 to 5 | High |
| 1 to 2 | Fair |
| Less than 1 | Need focus |

## How to Improve

- Break large changes into smaller PRs
- Implement CI/CD pipelines for automated deployments
- Use feature flags to deploy without exposing features
- Set up monitoring and quick rollback
