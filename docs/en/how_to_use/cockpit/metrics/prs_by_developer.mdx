## What is PRs by Developer

PRs by Developer counts the pull requests each team member had **closed**, grouped by week. It focuses on finished work, so you can see output and how it is spread across the team.

In the Cockpit, it's the **PRs Merged By Developer** chart on the **Productivity** tab: one stacked bar per week, with one color per developer. Hover a bar to see each developer's count.

## How We Calculate It

```
Weekly PRs per Developer = COUNT(closed PRs) per developer per week
```

- A PR counts in the week it **closed**, merged or closed without merging. Despite the chart's name, Cockpit doesn't tell the two apart.
- The developer is the PR author's username on your Git provider.
- Weeks start on Monday.
- Open and draft PRs, PRs without a close date, and PRs without an author are not counted.

## Developer Activity vs. PRs by Developer

| | Developer Activity | PRs by Developer |
| --- | --- | --- |
| **Counts** | PRs opened | PRs closed |
| **Date basis** | Opened date | Close date |
| **Status filter** | None | Closed PRs only |
| **Shown as** | Table, one column per week | Stacked bars per week |

## Context to Keep in Mind

- A developer with fewer but larger PRs may be just as productive. Read the chart next to [PR Size](/en/how_to_use/cockpit/metrics/pr_size).
- Output varies with the kind of work, the role and the phase of the project.
- Work reviewed or paired on isn't visible here.
