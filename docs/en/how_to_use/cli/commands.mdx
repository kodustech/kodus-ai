## Global Flags

These flags are available on all commands:

| Flag              | Short | Default    | Description                                                                 |
| ----------------- | ----- | ---------- | --------------------------------------------------------------------------- |
| `--format <fmt>`  | `-f`  | `terminal` | Output format: `terminal`, `json`, `markdown`                               |
| `--output <file>` | `-o`  | —          | Save output to a file                                                       |
| `--verbose`       | `-v`  | `false`    | Verbose output, on stderr                                                   |
| `--quiet`         | `-q`  | `false`    | Quiet mode (errors only)                                                    |
| `--agent`         | —     | `false`    | Agent mode: deterministic JSON output for scripts and agents                |
| `--version`       | `-V`  | —          | Print the CLI version                                                       |

`--format` applies to `review`, `pr`, and `trace`. `--agent` works on `review`, `pr`, `schema`, `hook install`, `hook uninstall`, `trace status`, `trace disable`, and `trace <path>`; it prints one JSON envelope with `ok`, `command`, `data`, `error`, and `meta`. The other commands that print structured data take `--json`.

With `--fail-on`, a `kodus review --agent` that trips the gate prints a second envelope after the first, with `ok: false` and `error.code` `INTERNAL_ERROR`. Read the exit code, or read the first envelope only.

Results go to stdout. Spinners, progress, and errors go to stderr. With `--fail-on`, a review that trips the gate also prints a line to stdout after the result, so `kodus review --format json --fail-on error > review.json` is not valid JSON. Use `--output review.json`, which keeps the file clean.

## `kodus review`

Analyzes your changes for bugs, security vulnerabilities, performance problems, and style violations. A review uses your team's Kody Rules and code review settings.

### Usage

```bash
kodus review                          # Review working tree changes (interactive)
kodus review [files...]               # Review specific files
kodus review --staged                 # Review staged files only
kodus review --branch main            # Compare against a branch
kodus review --commit abc123          # Analyze a specific commit
kodus review --fix                    # Apply all fixable issues
kodus review --prompt-only            # Output optimized for AI agents
```

With no scope flag, `kodus review` reviews tracked changes in your working tree, staged and unstaged. If you pass more than one scope, files win over `--branch`, `--branch` over `--commit`, and `--commit` over `--staged`. See [Diff Modes](/en/how_to_use/cli/concepts#diff-modes).

### Flags

| Flag                   | Short | Description                                                 |
| ---------------------- | ----- | ----------------------------------------------------------- |
| `--staged`             | `-s`  | Analyze only staged files                                   |
| `--commit <sha>`       | `-c`  | Analyze the diff of a specific commit                       |
| `--branch <name>`      | `-b`  | Compare the current branch against `<name>`                 |
| `--rules-only`         | —     | Review using only configured rules (no general suggestions) |
| `--fast`               | —     | Fast mode: quicker analysis with lighter checks             |
| `--focus <text>`       | —     | Steer the review at a specific area — see [Steer a Review](/en/how_to_use/code_review/review_directive) |
| `--heavy`              | —     | Heavy mode: specialist reviewers run next to the main review for higher recall (more tokens), whatever review mode is set. Needs a signed-in team on the Teams or Enterprise plan — see [Heavy mode](/en/how_to_use/code_review/review_directive#heavy-mode) |
| `--balanced`           | —     | Balanced mode: the main review alone, on a repository set to Heavy — see [Heavy mode](/en/how_to_use/code_review/review_directive#heavy-mode) |
| `--interactive`        | `-i`  | Use the interactive list to navigate and apply fixes. Cannot be combined with `--prompt-only` or `--fix` |
| `--fix`                | —     | Apply all fixable issues, after one confirmation            |
| `--prompt-only`        | —     | Output optimized for AI agents                              |
| `--fail-on <severity>` | —     | Exit with code 1 if an issue is at or above `info`, `warning`, `error`, or `critical` |
| `--context <file>`     | —     | Custom context file to include in the review                |
| `--fields <csv>`       | —     | Select response fields, e.g. `summary,issues.file`. Needs `--format json` or `--agent` |
| `--github-pat <token>` | —     | GitHub token (`read:repo`) used to clone private repos. Trial users only. Also read from `KODUS_GITHUB_PAT`, `GITHUB_TOKEN`, or `GH_TOKEN`. Held in memory only, never persisted |
| `--no-hunk`            | —     | Skip the Hunk viewer and use the interactive list (interactive terminals only) |

### Review Modes

<Tabs>
  <Tab title="Interactive (Default)">
    In a terminal on macOS and Linux, the findings open in the Hunk diff viewer, next to the code. On Windows, with `--no-hunk`, or with `--interactive`, you get a list instead: browse files with issue counts, preview suggested fixes, apply them one by one, or copy a fix prompt for an AI agent.

    ```bash
    kodus review
    ```

  </Tab>
  <Tab title="Auto-fix">
    Applies all fixable issues at once after a confirmation prompt.

    ```bash
    kodus review --fix
    ```

  </Tab>
  <Tab title="AI Agent">
    Minimal, structured output designed for Claude Code, Cursor, or Windsurf. It starts with `REVIEW_ANALYSIS_COMPLETE` and ends with `END_REVIEW`, and prints `NO_ISSUES_FOUND` when the review is clean. Enables autonomous review-fix loops.

    ```bash
    kodus review --prompt-only
    ```

  </Tab>
</Tabs>

### Notes

- A review that runs differently than you asked, for example `--heavy` on a plan without it, prints a notice. With `--agent` or `--format json`, the notice is in the result's `notices`.
- If your credentials are rejected (a revoked team key or an expired session), `kodus review` runs as a trial review and says so.

## `kodus diff`

Open the current changeset in the Hunk terminal diff viewer.

```bash
kodus diff
```

This is a thin wrapper around `hunk diff`. Every argument you pass is forwarded to it unchanged, so any flag Hunk supports works here too. It is not available on Windows.

<Note>
  Useful for looking at a changeset before running `kodus review` on it. The same viewer backs the interactive review. Pass `--no-hunk` to `kodus review` if you prefer the list.
</Note>

## `kodus pr suggestions`

Fetch the suggestions Kody made on a pull request. Needs a login or a team key.

### Usage

```bash
kodus pr suggestions --pr-url https://github.com/org/repo/pull/42
kodus pr suggestions --pr-number 42 --repo-id <id>
kodus pr suggestions --pr-number 42 --repo-id <id> --severity critical,high
kodus pr suggestions --pr-number 42 --repo-id <id> --format json
kodus pr suggestions --pr-number 42 --repo-id <id> --format markdown
```

Find a repository id with `kodus config remote list --json`.

### Flags

| Flag                   | Description                                                      |
| ---------------------- | ---------------------------------------------------------------- |
| `--pr-url <url>`       | Pull request URL                                                 |
| `--pr-number <number>` | Pull request number (requires `--repo-id`)                       |
| `--repo-id <id>`       | Repository ID for the pull request                               |
| `--severity <list>`    | Comma-separated severities: `info`, `warning`, `error`, `critical`, `high`, `medium`, `low` |
| `--category <list>`    | Comma-separated categories, from the [Issue Categories](#issue-categories) below |
| `--fields <csv>`       | Select response fields, e.g. `summary,issues.file`. Needs `--format json` or `--agent` |

Provide `--pr-url`, or `--pr-number` together with `--repo-id`. `--prompt-only` is not available here.

## `kodus pr reviews`

Show every review Kody ran on a pull request, newest first: when, the status, how many suggestions were sent and filtered, the reviewed commit, and the reason when a run failed. Needs a login.

### Usage

```bash
kodus pr reviews 42
kodus pr reviews 42 --repo org/repo
kodus pr reviews 42 --repo-id <id> --limit 50 --json
```

### Flags

| Flag             | Description                                                                |
| ---------------- | -------------------------------------------------------------------------- |
| `--repo <repo>`  | Repository as `owner/repo` or name. Defaults to the origin of this checkout |
| `--repo-id <id>` | Repository ID. Wins over `--repo`                                          |
| `--team <team>`  | Team name or id, when your organization has more than one team             |
| `--limit <n>`    | Most recent runs to return, from 1 to 100 (default 20)                     |
| `--json`         | Output the runs as JSON                                                    |

## `kodus pr business-validation`

Validate a local diff against the business rules and acceptance criteria of a task. Useful before merging to confirm the implementation matches the task. Needs a login or a team key. Nothing is posted to a pull request.

### Usage

```bash
kodus pr business-validation --task-url https://linear.app/team/issue/KC-1441
kodus pr business-validation --task-id KC-1441 --staged
kodus pr business-validation --task-id KC-1441 --branch main
kodus pr business-validation --task-id KC-1441 --commit abc123
kodus pr business-validation --task-id KC-1441 src/billing/invoice.ts
kodus pr business-validation --task-id KC-1441 --dry-run
```

With `--format json` or `--agent`, it prints the verdict as structured data. See [Business Logic Validation](/en/how_to_use/code_review/business_logic_validation#from-the-cli).

### Flags

| Flag                 | Short | Description                                                        |
| -------------------- | ----- | ------------------------------------------------------------------ |
| `--task-url <url>`   | —     | Task URL. Use it or `--task-id`, not both                          |
| `--task-id <id>`     | —     | Task ID or issue key (e.g. `KC-1441`)                              |
| `--staged`           | `-s`  | Use only staged changes                                            |
| `--commit <sha>`     | `-c`  | Use diff from a specific commit                                    |
| `--branch <name>`    | `-b`  | Compare current branch against a base branch                       |
| `--dry-run`          | —     | Print the payload without calling the API                          |

Pass at most one scope: files, `--staged`, `--branch`, or `--commit`. With none, it uses your working tree changes.

## `kodus auth`

Manage authentication with the Kodus API.

### `auth login`

```bash
kodus auth login                              # Browser login
kodus auth login --device-code                # Code login, for SSH and headless machines
kodus auth login --legacy -e user@mail.com
```

Login opens the **Authorize Kodus CLI** page in your browser and prints its URL; click **Authorize CLI** there to finish. If you aren't signed in to Kodus in that browser, you land on the dashboard after signing in: open the URL again.

For a private SSH session or a machine without a browser, use `--device-code` and follow the [sign-in steps](/en/how_to_use/cli/getting_started). Both flows wait up to 10 minutes. For CI, use `KODUS_TEAM_KEY` as a secret.

On a self-hosted instance, the page is on the host set by the API's `API_FRONTEND_URL`.

| Flag                    | Short | Description                                                          |
| ----------------------- | ----- | -------------------------------------------------------------------- |
| `--device-code`         | —     | Use the code flow even when a browser is available                   |
| `--legacy`              | —     | Sign in with email and password. Deprecated; kept for scripts        |
| `--email <email>`       | `-e`  | Account email (implies `--legacy`)                                   |
| `--password <password>` | `-p`  | Account password (implies `--legacy`)                                |

### `auth logout`

```bash
kodus auth logout
```

Removes the stored login and deletes `~/.kodus/config.json`: the team key, and a saved API URL or Cloudflare Access settings.

### `auth status`

```bash
kodus auth status
```

Shows how you are signed in. With a login: your email, whether the token is valid, and your organization id. With a team key saved by `kodus auth team-key`: the organization and team. In trial mode: reviews used, the limit, and when it resets. It reads stored credentials only: with `KODUS_TEAM_KEY` or `KODUS_TOKEN` set in the environment and nothing stored, it says "No credentials found". Use `kodus status` for those.

### `auth token`

This command appears in the CLI help, and relies on a CI token endpoint absent from the current API. For CI/CD, use a team key in the `KODUS_TEAM_KEY` secret. See [CI/CD integration](/en/how_to_use/cli/self_hosted).

### `auth team-key`

Stores a shared team key in `~/.kodus/config.json`. The command requires `--key`, verifies the key with the API, registers the device, and replaces any stored login.

For routine use, set `KODUS_TEAM_KEY` in the CLI environment. The CLI reads it directly. Team keys start with `kodus_`.

### `auth team-status`

```bash
kodus auth team-status
```

Shows the organization and team of the stored team key.

## `kodus hook`

Manage a pre-push Git hook that reviews your commits before they leave your machine.

### `hook install`

```bash
kodus hook install                    # Default: fail-on critical, fast mode enabled
kodus hook install --fail-on error    # Block pushes on error severity
kodus hook install --no-fast          # Disable fast mode
kodus hook install --force            # Overwrite existing hook
kodus hook install --dry-run          # Show what would be written
```

| Flag                   | Default    | Description                                       |
| ---------------------- | ---------- | ------------------------------------------------- |
| `--fail-on <severity>` | `critical` | Minimum severity to block push (`info`, `warning`, `error`, `critical`) |
| `--fast` / `--no-fast` | `true`     | Enable/disable fast mode                          |
| `--force`              | —          | Overwrite an existing hook without prompting      |
| `--dry-run`            | —          | Print planned changes without writing files       |

On `git push`, the hook runs this for the branch you push:

```bash
kodus review --branch <remote>/<branch> --fast --fail-on <severity> --format terminal --quiet
```

That reviews the commits the remote doesn't have yet. `--fast` is left out with `--no-fast`.

- The push is blocked (exit code 1) when a finding reaches the `--fail-on` severity, and also when the review fails, for example when the API can't be reached.
- In an interactive terminal on macOS and Linux, the findings open in the Hunk viewer before the push continues, even when there are none. Quit the viewer to go on.
- Without an interactive terminal (an IDE, a Git GUI), the viewer can't open and any finding blocks the push. See [Troubleshooting](/en/how_to_use/cli/troubleshooting).
- It reviews only the branch you have checked out, and skips new branches, branch deletions, and `git push origin HEAD`. Push the branch by name.
- With a login or team key it reviews like any other `kodus review`; without one, it runs a trial review. The trial limit (2 reviews per hour) applies, and when it is reached the push goes through.
- If `kodus` is not installed, it prints a warning and lets the push through.

### `hook uninstall`

```bash
kodus hook uninstall
```

Removes the pre-push hook installed by Kodus. Add `--dry-run` to preview. A hook that Kodus did not install is left alone.

### `hook status`

```bash
kodus hook status
```

Shows whether the hook is installed, its fail-on severity, fast mode setting, and path.

### Skipping the Hook

```bash
KODUS_SKIP_HOOK=1 git push
```

## `kodus config remote`

Read and change code review settings stored in Kodus: global, per repository, and per directory.

<Note>`kodus config repo` still works as an alias of `kodus config remote`.</Note>

Which commands work depends on how you are signed in. With a login, `show` and `set` reach every setting at every level, and `unset`, `model`, `messages`, `language`, and `skills` are available. `keys` needs no sign-in. With a team key, `show` and `set` cover six settings of one repository, and `add`, `setup`, and `open` need a team key. The key must have **Allow repository configuration via CLI** turned on (**Organization → CLI keys**, **Configure** on the key; off by default). See [Authentication Modes](/en/how_to_use/cli/concepts#authentication-modes).

The `[repository]` argument takes `.` for the current repository, `owner/repo`, a repository id, or `global`. Always pass it when the command also takes a key or value.

### Usage

```bash
kodus config remote list                                # Repositories added to Kodus
kodus config remote show .                              # Settings, with the level each value comes from
kodus config remote show . --directory packages/api     # Settings of one directory
kodus config remote keys                                # Every setting you can change
kodus config remote set . suggestionControl.severityLevelFilter high
kodus config remote set global runOnDraft true
kodus config remote unset . runOnDraft                  # Inherit from the level above again
kodus config remote add-ignore-file . "**/*.generated.ts"
kodus config remote add-base-branch . "release/*"
kodus config remote add-ignore-title . "WIP"
kodus config remote add .                               # Add the current repo to Kodus (team key)
kodus config remote setup .                             # Guided setup (team key)
```

`kodus config -r [repository]` is a shortcut for `kodus config remote add [repository]`.

### Subcommands

| Subcommand                                                  | Description                                                                              |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `add [repository]`                                          | Add a repository to Kodus. `--no-prompt` skips the setup prompt                          |
| `list`                                                      | List the repositories added to Kodus. `--team`, `--json`                                 |
| `show [repository]`                                         | Show settings and the level each value comes from. `--no-file-overlay` skips reading `kodus-config.yml` |
| `set [repository] <key> <value>`                            | Set one setting. `--create-directory` gives `--directory` its own settings if it has none |
| `unset [repository] <key>`                                  | Drop a level's own value so it inherits again                                            |
| `keys`                                                      | List the settable keys with their type, allowed values, and page                         |
| `setup [repository]`                                        | Guided setup wizard. `--yes` applies the current answers without prompts                 |
| `open [repository]`                                         | Open the web app. `--section` is one of `general`, `review-categories`, `custom-prompts`, `suggestion-control`, `pr-summary`, `kody-rules`, `custom-messages`, `business-rules` |
| `add-pattern [repository] <field> <pattern>`                | Add a pattern to a list. Fields: `ignore-files`, `base-branches`, `ignore-titles`        |
| `remove-pattern [repository] <field> <pattern>`             | Remove a pattern from a list                                                             |
| `add-ignore-file`, `remove-ignore-file [repository] <pattern>`   | Shortcuts for the `ignore-files` list                                               |
| `add-base-branch`, `remove-base-branch [repository] <pattern>`   | Shortcuts for the `base-branches` list                                              |
| `add-ignore-title`, `remove-ignore-title [repository] <pattern>` | Shortcuts for the `ignore-titles` list                                              |
| `model list`, `model set [repository] <modelId>`, `model unset [repository]`, `model test <modelId>` | Choose the review model among the BYOK models your organization configured. `set` takes `--force` for an id not in the list |
| `messages show`, `set`, `unset`, `fields`                   | Read and change the custom messages Kody posts when a review starts, ends, or fails      |
| `language show`, `set <language>`, `list`                   | Read and change the team's review language, by code (`pt-BR`) or name                    |
| `skills list`, `discover`, `add`, `remove`, `link`, `unlink` | Manage the skills and docs the main review and custom agents follow                      |

Commands that take a scope accept `--team <team>` (needed when your organization has more than one team) and `--directory <path>`. Most also take `--json`.

With a team key, `set` accepts `review.enabled`, `review.autoApprove`, `review.requestChanges.minSeverity`, `patterns.ignoreFiles`, `patterns.baseBranches`, and `patterns.ignoreTitles`. Those names work when you are logged in too.

When [Centralized Config](#kodus-config-centralized) is on, a change is proposed as a pull request and the command prints its link.

## `kodus config centralized`

Manage centralized configuration from the CLI. Needs a team key with **Allow repository configuration via CLI** turned on.

### Usage

```bash
kodus config centralized status
kodus config centralized init [owner/repo] --sync-option <pr|manual>
kodus config centralized sync
kodus config centralized disable
kodus config centralized download --out ./centralized-config.zip
```

### Subcommands

| Subcommand              | Description                                                                   |
| ----------------------- | ----------------------------------------------------------------------------- |
| `status`                | Show whether centralized config is enabled and the selected source repository |
| `init [repository]`     | Enable centralized config for a selected repository                           |
| `sync`                  | Run centralized config sync on demand                                         |
| `disable`               | Disable centralized config and clear selected repository                      |
| `download --out <path>` | Download centralized config ZIP bundle                                        |

### Flags

| Flag                           | Applies To                  | Description                       |
| ------------------------------ | --------------------------- | --------------------------------- |
| `--sync-option <pr or manual>` | `init`                      | Sync strategy. Default is `pr`    |
| `--out <path>`                 | `download`                  | Required output path for ZIP file |
| `--json`                       | all centralized subcommands | Output structured JSON            |

For a complete walkthrough, see the [Centralized Config guide](/en/how_to_use/code_review/configs/centralized_config#cli).

## `kodus rules`

Create, update, view, pause, resume, and delete Kody Rules — structured rules that Kodus applies during review.

With a team key, the key needs **Allow Kody Rules management via CLI** turned on (**Organization → CLI keys**, **Configure** on the key; off by default). With a login, the permissions of your role in the web app apply. `pause`, `resume`, and `delete` need a login.

### Usage

```bash
kodus rules view                                         # View all rules for your team
kodus rules view --repo-id <id>                          # Filter by repository
kodus rules view --uuid <rule-uuid>                      # Fetch a single rule
kodus rules create --title "No console.log" --rule "Avoid leaving console.log in committed code" --severity high
kodus rules update --uuid <rule-uuid> --severity critical
kodus rules pause --uuid <rule-uuid>
kodus rules resume --uuid <rule-uuid>
kodus rules delete --uuid <rule-uuid>
```

### Subcommands

| Subcommand | Description                                              |
| ---------- | -------------------------------------------------------- |
| `create`   | Create a new Kody Rule                                   |
| `update`   | Update an existing rule                                  |
| `view`     | View Kody Rules                                          |
| `pause`    | Keep rules in the list but stop enforcing them in reviews |
| `resume`   | Enforce paused rules again                               |
| `delete`   | Delete rules                                             |

### `rules create` Flags

| Flag                    | Default     | Description                                       |
| ----------------------- | ----------- | ------------------------------------------------- |
| `--title <title>`       | —           | Rule title (required)                             |
| `--rule <rule>`         | —           | Rule content/description (required)               |
| `--repo-id <id>`        | `global`    | Repository ID (or `global` to apply to all repos) |
| `--severity <severity>` | `medium`    | `low`, `medium`, `high`, `critical`               |
| `--scope <scope>`       | `file`      | `file` or `pull-request`                          |
| `--path <glob>`         | `**/*`      | Glob pattern for file targeting                   |
| `--team <team>`         | —           | Team name or id, when your organization has more than one (login only) |
| `--json`                | `false`     | Output created rule as JSON                       |

### `rules update` Flags

| Flag                    | Description                                     |
| ----------------------- | ----------------------------------------------- |
| `--uuid <uuid>`         | Rule UUID to update (required)                  |
| `--repo-id <id>`        | Updated repository ID                           |
| `--title <title>`       | Updated title                                   |
| `--rule <rule>`         | Updated content/description                     |
| `--severity <severity>` | Updated severity                                |
| `--scope <scope>`       | Updated scope                                   |
| `--path <glob>`         | Updated glob pattern                            |
| `--team <team>`         | Team name or id (login only)                    |
| `--json`                | Output updated rule as JSON                     |

Pass at least one field to change.

### `rules view` Flags

| Flag             | Description                    |
| ---------------- | ------------------------------ |
| `--uuid <uuid>`  | Fetch a single rule by UUID    |
| `--repo-id <id>` | Filter rules by repository ID  |
| `--team <team>`  | Team name or id (login only)   |
| `--json`         | Output rules as JSON           |

### `rules pause`, `resume`, and `delete` Flags

| Flag            | Description                                                         |
| --------------- | ------------------------------------------------------------------- |
| `--uuid <uuid>` | Rule UUID (required). Repeat the flag or separate several with commas |
| `--team <team>` | Team name or id, when your organization has more than one           |
| `--json`        | Output the result as JSON                                           |

A rule that keeps its status, for example because your plan allows no more active rules, is listed and the command exits with code 1.

When [Centralized Config](#kodus-config-centralized) is on, `create`, `update`, `pause`, `resume`, and `delete` open a pull request and print its link instead of changing the rule.

## `kodus agents`

List, create, edit, turn on and off, delete, and try [custom agents](/en/how_to_use/code_review/custom_agents).

Sign in to a workspace with [custom agent access](/en/how_to_use/code_review/custom_agents). To create or change agents, use an Owner account or a Repo Admin account for an assigned repository.

### Usage

```bash
kodus agents list
kodus agents show "Billing guard"
kodus agents create --name "Billing guard" --instructions "Flag invoice totals computed with floating point" --include "src/billing/**"
kodus agents try "Billing guard" --repo org/repo --pr https://github.com/org/repo/pull/42
kodus agents enable "Billing guard"
```

An agent is named by its id, its name, or its `@kody -v` command.

### Subcommands

| Subcommand       | Description                                                                              |
| ---------------- | ---------------------------------------------------------------------------------------- |
| `list`           | List the agents a review runs at this level                                              |
| `show <agent>`   | Show one agent with its full configuration                                               |
| `create`         | Create an agent. It starts turned off: try it, then turn it on. `--enable` turns it on right away |
| `update <agent>` | Change an agent. Only the fields you pass change                                         |
| `enable <agent>` | Turn an agent on: reviews run it                                                         |
| `disable <agent>`| Turn an agent off: reviews don't run it                                                  |
| `delete <agent>` | Delete an agent. Its findings stay on past pull requests                                 |
| `try <agent>`    | Run an agent on one pull request without posting. Needs `--pr <url>` and `--repo`. Agent fields you pass change only this run |

### Level flags

Every subcommand takes these:

| Flag                    | Default  | Description                                                     |
| ----------------------- | -------- | --------------------------------------------------------------- |
| `--team <name or id>`   | —        | Team, when your organization has more than one                  |
| `--repo <repository>`   | `global` | Repository id or name, or `global` for the agents every repository gets |
| `--directory <path or id>` | —     | A directory of `--repo` with its own settings                   |
| `--json`                | —        | Output as JSON                                                  |

### Agent field flags

`create`, `update`, and `try` take these. `create` also takes `--template <id>` (`architecture`, `e2e-coverage`, `regression-hallucination`, `security`, or `blank`).

| Flag                        | Description                                                       |
| --------------------------- | ----------------------------------------------------------------- |
| `--name <name>`             | Agent name (also its `@kody -v` command)                          |
| `--instructions <text>`     | What the agent reviews and how                                    |
| `--from-file <file>`        | Read agent fields from a `.json` file, or the instructions from any other file |
| `--include <glob>`          | Run only on changed files matching the glob. Repeatable           |
| `--exclude <glob>`          | Skip changed files matching the glob. Repeatable                  |
| `--color <hex>`             | Tag color of its comments                                         |
| `--comment-format <format>` | `inline` or `single-comment`                                      |
| `--min-severity <severity>` | Lowest severity it posts: `low`, `medium`, `high`, `critical`, or `none` |
| `--max-comments <n>`        | Most comments it posts per review                                 |
| `--suggested-fix <mode>`    | `when-confident` or `never`                                       |
| `--writing <text>`          | How its comments are written                                      |
| `--model <modelId>`         | BYOK model id it runs on. An empty value uses the routing table   |
| `--ast-grep <yaml or path>` | ast-grep rule YAML, or the repository path of a rule file         |
| `--ast-grep-file <file>`    | Read the ast-grep rule YAML from a local file                     |
| `--skill <path>`            | Link a skill folder of the repository. Repeatable                 |
| `--doc <path>`              | Link a doc file of the repository. Repeatable                     |
| `--unlink <path>`           | Unlink a skill or doc. Repeatable                                 |

When [Centralized Config](#kodus-config-centralized) is on, changes open a pull request and print its link.

## `kodus skills`

Inspect and install the Kodus skills bundled with the CLI into the AI agents on your machine.

### Usage

```bash
kodus skills list                                        # List bundled skills
kodus skills install                                     # Install into detected agents
kodus skills install --dry-run                           # Preview changes
kodus skills resync                                      # Refresh installed skills
kodus skills uninstall                                   # Remove installed skills
```

### Subcommands

| Subcommand  | Description                                                                              |
| ----------- | ---------------------------------------------------------------------------------------- |
| `list`      | List the skills bundled with this CLI version (also what `kodus skills` alone prints)    |
| `install`   | Install the skills into every agent the CLI detects, in the current directory and your home folder, creating the skills folder if needed |
| `sync`      | Update the skills in agents that already have them                                       |
| `resync`    | Same as `sync`                                                                           |
| `uninstall` | Remove the skills the CLI installed                                                      |

### Flags

| Flag        | Applies To                               | Description                                    |
| ----------- | ---------------------------------------- | ---------------------------------------------- |
| `--dry-run` | `install`, `sync`, `resync`, `uninstall` | Show planned changes without writing files     |

The CLI detects an agent by its config folder. [AI Agents](/en/how_to_use/cli/ai_agents) lists the agents and the skills.

<Tip>For a full machine bootstrap, prefer the installer (`curl -fsSL https://review-skill.com/install | bash`). `kodus skills` covers refreshing and cleanup.</Tip>

## Severity Levels

Issues are categorized by severity, from most to least critical:

| Level      | Description                                                      |
| ---------- | ---------------------------------------------------------------- |
| `critical` | Major security or stability issues requiring immediate attention |
| `error`    | Significant bugs or problems                                     |
| `warning`  | Potential issues worth addressing                                |
| `info`     | Suggestions and best practices                                   |

## Issue Categories

| Category                 | Description                            |
| ------------------------ | -------------------------------------- |
| `security_vulnerability` | Security-related issues                |
| `bug`                    | Potential bugs                         |
| `performance`            | Performance optimization opportunities |
| `code_quality`           | Code quality improvements              |
| `best_practices`         | Best practice violations               |
| `complexity`             | Code complexity issues                 |
| `maintainability`        | Maintainability concerns               |
| `style`                  | Code style issues                      |
| `documentation`          | Documentation gaps (accepted by `--category` on `kodus pr suggestions`) |
