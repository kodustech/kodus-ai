title: "Self-Hosted Setup"
description: "Connect the Kodus CLI to your self-hosted Kodus instance."
---

If you're running Kodus on your own infrastructure, the CLI works the same way — you just need to point it to your API.

## Connect to Your Instance

<Steps>
  <Step title="Set the API URL">
    Tell the CLI where your Kodus API lives. Pick one method:

    <Tabs>
      <Tab title="Environment Variable (Recommended)">
        ```bash
        export KODUS_API_URL=https://kodus-api.yourcompany.com
        ```

        Add this to your shell profile (`~/.bashrc`, `~/.zshrc`, etc.) to make it permanent:

        ```bash
        echo 'export KODUS_API_URL=https://kodus-api.yourcompany.com' >> ~/.zshrc
        source ~/.zshrc
        ```
      </Tab>
      <Tab title="Config File">
        Create or edit `~/.kodus/config.json`:

        ```json
        {
          "apiUrl": "https://kodus-api.yourcompany.com",
          "teamKey": "kodus_xxxxx",
          "teamName": "Your Team",
          "organizationName": "Your Org"
        }
        ```

        The CLI creates this file automatically when you run `kodus auth team-key`, and keeps an `apiUrl` that is already in it. You can also create it manually.

        <Warning>
          `kodus auth login` and `kodus auth logout` can delete this file, including the API URL and Cloudflare Access settings. Set `KODUS_API_URL` in your environment. If your API uses Cloudflare Access, also set `CF_ACCESS_CLIENT_ID` and `CF_ACCESS_CLIENT_SECRET`.
        </Warning>
      </Tab>
      <Tab title="Inline (One-off)">
        ```bash
        KODUS_API_URL=https://kodus-api.yourcompany.com kodus review
        ```
      </Tab>
    </Tabs>

    <Warning>
      **HTTPS is required.** The CLI rejects non-HTTPS URLs for security. The only exception is `localhost` and `127.0.0.1` for local development.
    </Warning>

    **Priority order:** `KODUS_API_URL` env var > `~/.kodus/config.json` apiUrl > default (`https://api.kodus.io`).
  </Step>

  <Step title="Authenticate">
    <Tabs>
      <Tab title="Team Key (Recommended)">
        Generate a team key in your self-hosted Kodus web app under **Organization → CLI keys**. Set it as `KODUS_TEAM_KEY` in the shell where you run the CLI.

        <Tip>Team keys are ideal for shared environments and AI agent setups — no individual login required.</Tip>
      </Tab>
      <Tab title="Personal Login">
        ```bash
        kodus auth login
        ```

        The CLI opens the **Authorize Kodus CLI** page of your self-hosted web app. Sign in with the account registered on your instance (after signing in you land on the dashboard, so open the URL the CLI printed again), then click **Authorize CLI**. On a machine without a browser, run `kodus auth login --device-code` in a private terminal. The CLI shows the authorization URL for your instance and a one-time code. In your browser's address bar, add the code as the `code` query parameter and click **Authorize CLI**. Keep the code and the full link out of logs and shared messages.

        Your login is stored in `~/.kodus/credentials.json` with restricted permissions (600).

        <Info>
          The address of that page comes from the `API_FRONTEND_URL` setting of your Kodus API. It must be your web app's URL, or the login page opens on the wrong host.
        </Info>

        For CI, store a team key as the `KODUS_TEAM_KEY` secret.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Verify the Connection">
    ```bash
    kodus status
    ```

    `kodus status` shows the authentication mode detected locally. To check the API URL, add `--verbose` to a command that calls the API. For example, with a team key that allows repository configuration, run:

    ```bash
    kodus config remote list --verbose
    ```
  </Step>
</Steps>

## Cloudflare Access (Zero Trust)

If your self-hosted API is behind [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/applications/), the CLI supports service token authentication.

<Tabs>
  <Tab title="Environment Variables">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export CF_ACCESS_CLIENT_ID=your-client-id.access
    export CF_ACCESS_CLIENT_SECRET=your-client-secret
    ```
  </Tab>
  <Tab title="Config File">
    ```json
    {
      "apiUrl": "https://kodus-api.yourcompany.com",
      "teamKey": "kodus_xxxxx",
      "cfAccessClientId": "your-client-id.access",
      "cfAccessClientSecret": "your-client-secret"
    }
    ```
  </Tab>
</Tabs>

When both the client ID and the secret are set, the CLI sends `CF-Access-Client-Id` and `CF-Access-Client-Secret` headers on every API request. Priority: env vars > config file.

## Config File Reference

The CLI stores configuration in `~/.kodus/config.json`:

```json
{
  "apiUrl": "https://kodus-api.yourcompany.com",
  "teamKey": "kodus_xxxxx",
  "teamName": "Engineering",
  "organizationName": "Acme Corp",
  "cfAccessClientId": "your-client-id.access",
  "cfAccessClientSecret": "your-client-secret"
}
```

| Field | Required | Description |
|-------|----------|-------------|
| `apiUrl` | No | Your self-hosted API URL. Overridden by `KODUS_API_URL` env var. |
| `teamKey` | No | Team API key (starts with `kodus_`). Overridden by `KODUS_TEAM_KEY` env var. |
| `teamName` | No | Display name for the team. |
| `organizationName` | No | Display name for the organization. |
| `cfAccessClientId` | No | Cloudflare Access client ID. Overridden by `CF_ACCESS_CLIENT_ID` env var. |
| `cfAccessClientSecret` | No | Cloudflare Access client secret. Overridden by `CF_ACCESS_CLIENT_SECRET` env var. |

<Info>
  The config file is created with `0600` permissions (owner read/write only). The directory `~/.kodus/` is created with `0700` permissions.
</Info>

## Environment Variables Summary

| Variable | Description |
|----------|-------------|
| `KODUS_API_URL` | Self-hosted API endpoint (HTTPS required, except localhost) |
| `KODUS_APP_URL` | Your web app's URL, which `kodus config remote open` points to (default `https://app.kodus.io`) |
| `KODUS_TEAM_KEY` | Team key for shared access |
| `KODUS_TOKEN` | A login access token, used as is and not refreshed. Takes priority over every other credential. For CI, use a team key |
| `CF_ACCESS_CLIENT_ID` | Cloudflare Access client ID |
| `CF_ACCESS_CLIENT_SECRET` | Cloudflare Access client secret |
| `KODUS_REQUEST_TIMEOUT_MIN` | Timeout of each API request in minutes (default `60`) |
| `KODUS_DISABLE_UPDATE_CHECK` | Set to `1` to turn off the update notice |

## CI/CD Integration

For self-hosted instances in CI/CD pipelines, set the API URL and a team key as environment variables. A fresh checkout has no uncommitted changes, so review the branch against its base with `--branch`. The base branch must be available in the checkout, so fetch the full history.

<Tabs>
  <Tab title="GitHub Actions">
    ```yaml
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0
    - name: Kodus Review
      env:
        KODUS_API_URL: ${{ secrets.KODUS_API_URL }}
        KODUS_TEAM_KEY: ${{ secrets.KODUS_TEAM_KEY }}
      run: npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
  <Tab title="GitLab CI">
    ```yaml
    kodus-review:
      variables:
        GIT_DEPTH: "0"
      script:
        - git fetch origin main
        - npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```

    Add `KODUS_API_URL` and `KODUS_TEAM_KEY` as CI/CD variables in the project settings.
  </Tab>
  <Tab title="Generic">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export KODUS_TEAM_KEY=kodus_xxxxx
    npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
</Tabs>

<Tip>
  Use `--fail-on error` or `--fail-on critical` to fail the pipeline when issues above a severity threshold are found. Pull requests are reviewed by the Git integration, so they need no pipeline job.
</Tip>

## Distributing to Your Team

Share the [CLI installation instructions](/en/how_to_use/cli/getting_started) and your self-hosted API URL with your team. Each teammate sets `KODUS_API_URL` in their shell profile or `apiUrl` in `~/.kodus/config.json`. Provide the team key through your secret manager and set it as `KODUS_TEAM_KEY` before using the CLI.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Security Error: API URL must use HTTPS protocol">
    The CLI requires HTTPS for all non-localhost URLs. It then falls back to the default `https://api.kodus.io`, so read the message before you authenticate. Make sure your self-hosted instance has a valid TLS certificate. If you're testing locally, use `http://localhost:<port>` instead.
  </Accordion>

  <Accordion title="Connection refused or timeout">
    - Verify the URL is reachable: `curl -I https://kodus-api.yourcompany.com`
    - Check if a firewall or VPN is blocking the connection
    - If behind Cloudflare Access, ensure `CF_ACCESS_CLIENT_ID` and `CF_ACCESS_CLIENT_SECRET` are set
    - Use `--verbose` to see the exact URL being used
  </Accordion>

  <Accordion title="Authentication failed (401)">
    - Run `kodus status` to check your current auth state
    - If using a team key, verify it's still **Active** under **Organization → CLI keys** in your self-hosted web app
    - If using personal login, the CLI refreshes your login automatically; if the refresh fails, run `kodus auth login` again
    - Make sure `KODUS_API_URL` points to the correct instance
  </Accordion>

  <Accordion title="API returned invalid response (expected JSON, got HTML)">
    This usually means the URL is hitting a reverse proxy, load balancer, or Cloudflare Access page instead of the actual API. Check:
    - The URL path is correct (no trailing `/api` or similar)
    - Cloudflare Access credentials are configured if applicable
    - The reverse proxy is forwarding requests correctly
  </Accordion>

  <Accordion title="Device limit reached">
    Your self-hosted instance may enforce device limits per organization. The web app has no device list to clean up, so contact your admin to increase the limit (the API's `CLI_DEVICE_LIMIT` setting; `0`, the default, means no limit).
  </Accordion>
</AccordionGroup>
