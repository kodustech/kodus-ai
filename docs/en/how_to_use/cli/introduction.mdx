Kodus CLI reviews your code changes directly from the terminal, before they reach a pull request. Point it at your working tree, staged diff, branch, or commit. It applies your team's Kody Rules and code review settings.

Connect the CLI to [Kodus Cloud](/en/how_to_use/cli/getting_started) or a [self-hosted instance](/en/how_to_use/cli/self_hosted). Basic reviews have a limited trial without signing in. Workspace commands require a login or a team key, depending on the command.

## Who it's for

- **Solo developers** running a pre-commit check before pushing.
- **Teams** wanting a shared review ruleset across every clone, IDE, and CI job — without each developer signing in.
- **AI coding agents** (Claude Code, Cursor, Codex, Windsurf, and others) running review-fix loops with structured output.
- **CI/CD pipelines** failing builds on issues above a severity threshold.

## What it looks like

Running `kodus review` on a change lists its findings with severity, location, and a suggested fix. In an interactive terminal on macOS and Linux, the findings open in the Hunk diff viewer, next to the code.

<img src="/images/kodus_cli_review.jpg" alt="AI code review in your CLI"/>

With `--prompt-only`, the same review becomes compact, structured text for an AI agent to parse and act on. With `--fail-on`, the exit code tells a script whether to stop.

## Limits

|                  | Trial (no account)                                               | Signed in or team key                                             |
| ---------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| Rate limit       | 2 reviews per hour, for each user, device, and repository folder | 1,000 requests per hour, per team                                 |
| Sent to Kodus    | The diff only                                                    | The diff, plus the changed files in a working-tree or staged review |
| Diff             | 20 million characters                                            | 20 million characters                                             |
| Files per review | —                                                                | 500                                                               |
| Diff per file    | —                                                                | 500,000 characters                                                |
| Content per file | —                                                                | 2,000,000 characters                                              |
| Request size     | 25 MB                                                            | 24 MB                                                             |

The trial hour is a rolling window. No file or line limit applies to a trial review. For a signed-in team, the 1,000 requests count reviews, business validation checks, and [Kodus Trace](/en/how_to_use/cli/trace) session events.

With a login or team key, a file over the per-file limits is skipped with a warning. `--branch`, `--commit`, and `--fast` send the diff alone, which keeps large reviews under the request limit.

In trial mode, `kodus auth status` shows your usage and when it resets.

## CLI vs Kodus Web

The CLI and the Kodus web app share Kody Rules and code review settings. Use the CLI when you want a review **before the PR exists** — on a local branch, a staged diff, or inside an agent loop. Use the web app for PR reviews, Cockpit, and team-level configuration.

A CLI review applies your team's Kody Rules. When your git remote matches a repository added to Kodus, it also applies that repository's rules, its review mode, and its repository instructions (`CLAUDE.md`, `AGENTS.md`). With no match, only the rules that apply to every repository run. A trial review has no team: it runs with default settings and no Kody Rules.

Reviews run from the CLI show up in the web app under **Reviews → CLI**. A review run with a team key is labelled **Team · &lt;key name&gt;**, and one run with a login is labelled **Personal**.
