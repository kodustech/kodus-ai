**Kody Issues** keeps a live list of the suggestions Kody made that were **not implemented** when their pull request closed, and closes them as the code changes. It works on its own; turn it off with the **Auto-create issues** switch.

On any plan, including unlicensed self-hosted, Owners, Repo Admins and Contributors can open **Issues** from the ⌘K command palette. The entry also opens the list when it shows a padlock and a **Teams** tag.

With [Cockpit access](/en/how_to_use/cockpit/overview), use the **Issues** tab to open the list and see the open-issue count.

The list shows **Status**, **Severity**, **Category**, **Title**, **Repository**, **File**, **Age**, and **#PR(s)**. It starts with open issues.

Owners, Repo Admins and Contributors can read issues across all repositories; Billing Managers can't. Owners can change any issue, Repo Admins only those in their assigned repositories, and Contributors none.

To list issues in the terminal, see [`kodus issues`](/en/how_to_use/cli/commands#kodus-issues) for availability and filters.

## How issues are created

<Note>
  Issues are only created when PRs are **closed**, not when they're opened or
  during review. On GitLab and Azure Repos, only a merged PR counts.
</Note>

- When a PR is closed, Kody takes the suggestions it made on that PR that were not implemented and creates an **Issue** for each, linked to the repository. Each issue keeps the original explanation, the file, and the severity and category.
- If an open issue on the same file already covers the same problem, Kody adds the new suggestion to it instead of creating a duplicate. **#PR(s)** lists every PR that contributed.
- This includes suggestions Kody didn't post because they were below the minimum severity or over a comment limit. Suggestions Kody discarded as wrong, as repeats, or because their category is turned off don't become issues.

<Warning>
  **Per PR** Kody Rules do not generate issues. Only file-level suggestions create trackable issues.
</Warning>

## How issues are resolved

Each time a PR closes, Kody checks the open issues on the files that PR changed against the current code:

- If the code no longer has the problem, the issue becomes **Resolved**.
- If the file was deleted, the issue becomes **Dismissed**.

This also runs with **Auto-create issues** off, so existing issues keep closing.

## Working with issues

Click a row to open the issue's detail panel, with the repository, PR and file links, the description, and **Team feedback from PR reactions** (the 👍 / 👎 count). Step through issues with **J** / **K**, and **Share** copies a link to the issue.

### Status

- **Open**: needs attention.
- **Resolved**: set by Kody when the problem is gone from the code.
- **Dismissed**: not relevant. Set it by hand when a suggestion doesn't apply to your team; Kody also sets it when the file is deleted.

Change the status from the selector at the top of the detail panel.

### Severity

Each issue has a severity (`Critical`, `High`, `Medium`, `Low`) that starts from the suggestion's. Change it from the detail panel to match your team's priorities.

### Filters

Open **Filters** at the top of the list (the button shows how many are active) to filter by **Status**, **Severity**, **Category**, **Title**, **Repository**, **File path** and **PR numbers**. **Set as default filters** applies your filters each time you open Issues in this browser; **Reset to default filters** brings them back.
