<Note>
  This guide is for local development purposes. For production deployment,
  please refer to the [Deploy Kodus](/en/how_to_deploy/deploy_kodus/generic_vm)
  guide.
</Note>

<Note>
  `.env.example` is the template shared with Kodus Cloud, so a fresh `.env` ships
  `API_CLOUD_MODE=true` and `SANDBOX_PROVIDER=e2b`. To run the way a
  self-hosted instance does, set `API_CLOUD_MODE=false` and
  `SANDBOX_PROVIDER=local` in `.env` before you start the services. With
  `API_CLOUD_MODE=false` the daily anonymous heartbeat to `telemetry.kodus.io`
  is enabled by default. If you don't want your local experiments showing up
  in the fleet, set `KODUS_TELEMETRY_DISABLED=true`. See
  [Anonymous Telemetry](/en/how_to_deploy/deploy_kodus/telemetry) for what is
  sent and how to inspect it.
</Note>

## Prerequisites

- Node.js (see `.nvmrc` for the pinned version)
- pnpm
- Docker
- OpenSSL
- An LLM API key

<Note>
  kodus-ai is a pnpm workspace — `pnpm-lock.yaml` is the only lockfile in the repo. npm and yarn
  are not supported for local development.
</Note>

## Running the project

<Tabs>
  <Tab title="Automated Setup (Recommended)">
      For a quick and automated setup, use our setup script:

      ```bash
      git clone https://github.com/kodustech/kodus-ai.git
      cd kodus-ai
      pnpm run setup
      ```

      <Warning>
        Use `pnpm run setup`, not `pnpm setup` — the latter is pnpm's own built-in command for
        configuring its home directory and will not run the project script.
      </Warning>

      This script will automatically:
      - Check all required dependencies (Node.js, pnpm, Docker, OpenSSL)
      - Install project dependencies
      - Create the `.env` file from `.env.example`
      - Generate the security keys
      - Create the `kodus-backend-services` and `shared-network` Docker networks
      - Print the next steps

      Then [connect a model](#connect-a-model) and start the services:

      ```bash
      pnpm run docker:start
      ```

      **With external integrations (webhooks, etc.):**
      ```bash
      pnpm run docker:start
      pnpm run tunnel  # Creates public endpoint for external services
      ```

      <Info>
        Database migrations and seeds run **automatically** on container boot — the dev compose
        file defaults `RUN_MIGRATIONS` and `RUN_SEEDS` to `true`. You don't need a separate step.

        If you set them to `false` to manage them yourself, run `pnpm run migration:run` and
        `pnpm run seed` from the host.
      </Info>

      Once everything is running, open **http://localhost:3000** in your browser.
  </Tab>
  <Tab title="Manual Setup">
      If you prefer to configure everything manually:

      ### 1. Clone the repository

      ```bash
      git clone https://github.com/kodustech/kodus-ai.git
      cd kodus-ai
      ```

      ### 2. Install dependencies

      ```bash
      pnpm install
      ```

      ### 3. Configure environment variables

      ```bash
      cp .env.example .env
      ```

      ### 4. Generate security keys

      Generate secure values for the secrets in `.env`:

      ```bash
      # JWT secrets and the NextAuth secret
      openssl rand -base64 32

      # Encryption key and code management secret
      openssl rand -hex 32

      # Webhook token (URL-safe)
      openssl rand -base64 32 | tr -d '=' | tr '/+' '_-'
      ```

      Set these variables:
      - `API_JWT_SECRET` (use `openssl rand -base64 32`)
      - `API_JWT_REFRESH_SECRET` (use `openssl rand -base64 32`)
      - `API_CRYPTO_KEY` (use `openssl rand -hex 32`)
      - `CODE_MANAGEMENT_SECRET` (use `openssl rand -hex 32`)
      - `CODE_MANAGEMENT_WEBHOOK_TOKEN` (use `openssl rand -base64 32 | tr -d '=' | tr '/+' '_-'`)
      - `WEB_NEXTAUTH_SECRET` and `NEXTAUTH_SECRET`, with the same value (use `openssl rand -base64 32`)

      ### 5. Set up Docker networks

      Create the required Docker networks:

      ```bash
      docker network create kodus-backend-services || true
      docker network create shared-network || true
      ```

      ### 6. Connect a model

      Follow [Connect a model](#connect-a-model) below.

      ### 7. Start the development environment

      Launch the services using Docker:

      ```bash
      pnpm run docker:start
      ```

      This command starts:

      - Kodus API
      - Worker (async jobs)
      - Webhooks service
      - Kodus Web Application
      - PostgreSQL database
      - MongoDB database
      - RabbitMQ

      To also create a public endpoint for external services:
      ```bash
      pnpm run tunnel
      ```

      ### 8. First-time setup

      Nothing to do — the API container runs migrations and seeds on boot, because
      `docker-compose.dev.yml` defaults `RUN_MIGRATIONS` and `RUN_SEEDS` to `true`.

      <Accordion title="Running migrations manually">
        If you set `RUN_MIGRATIONS=false` / `RUN_SEEDS=false` in your `.env` (for example to
        control them yourself), run them from the host with:

        ```bash
        pnpm run migration:run   # OLTP database
        pnpm run seed            # initial data
        ```

        There are separate commands for the other datastores:

        ```bash
        pnpm run analytics:migration:run     # analytics warehouse
        pnpm run mcp-manager:migration:run   # MCP manager
        pnpm run mongo:migrate               # MongoDB
        ```
      </Accordion>

      ### 9. Service endpoints

      Access the services at:

      - Web UI: `http://localhost:3000`
      - API: `http://localhost:3001`
      - Webhooks: `http://localhost:3332`
      - RabbitMQ Management: `http://localhost:15672`
      - PostgreSQL: `localhost:5432`, MongoDB: `localhost:27017`
      - API debug port: `9229`

  </Tab>
</Tabs>

## Connect a model

Kodus needs a model to run reviews. Pick one way before you start the services:

- **In the app.** After you sign in, open **AI providers** in the sidebar and connect a provider with your key. See [BYOK](/en/how_to_use/byok).
- **In `.env`.** One model for the whole instance:

  ```env
  API_LLM_PROVIDER=openai                  # openai, openai_compatible, anthropic, anthropic_compatible, google_gemini or google_vertex
  API_LLM_PROVIDER_MODEL="your-model-id"
  API_LLM_API_KEY="your-api-key"
  # API_LLM_BASE_URL="https://your-provider.example.com/v1"   # required for the *_compatible providers
  ```

  See [LLM Provider Configuration](/en/how_to_deploy/deploy_kodus/generic_vm#llm-provider-configuration) for what each provider needs. A model connected on the **AI providers** page overrides the one in `.env`.

## Optional services

`pnpm run docker:start` does not start the MCP Manager or the analytics worker. Add them with `KODUS_DEV_EXTRAS`:

```bash
KODUS_DEV_EXTRAS=mcp pnpm run docker:start          # MCP Manager (also set API_MCP_SERVER_ENABLED=true)
KODUS_DEV_EXTRAS=analytics pnpm run docker:start    # analytics worker
KODUS_DEV_EXTRAS=mcp,analytics pnpm run docker:start
```

## Development workflow

### Basic Local Development

1. **Start services**: `pnpm run docker:start` (migrations and seeds run automatically)
2. **Open the app**: Visit `http://localhost:3000`
3. **Health check**: `pnpm run dev:health-check`

### Development with External Integrations

If you need to test integrations with external services (like Git webhooks):

1. **Start services**: `pnpm run docker:start`
2. **Create tunnel**: `pnpm run tunnel` (creates public endpoint)
3. **Update webhook URLs**: The tunnel command updates your `.env` automatically
4. **Configure Git provider**: Use the tunnel URL in your Git provider webhook settings
5. **Test integration**: Trigger webhooks and monitor logs

<Info>
  **Tunnel Benefits:**
  - Test real webhook integrations locally
  - Debug external service communications
  - Share your development environment with team members
  - Test mobile apps or other external clients
</Info>

## Troubleshooting

### Quick Health Check

```bash
pnpm run dev:health-check
```

This health check validates:
- **Services**: the API, worker, webhooks, web, PostgreSQL, MongoDB and RabbitMQ containers
- **Port availability**: Web (3000), API (3001), PostgreSQL (5432), MongoDB (27017), RabbitMQ (5672)
- **Database setup**: migrations and seed data
- **API endpoints**: `/health/simple`, `/health` and basic connectivity


### Manual Verification

1. **Check Web UI**: Visit `http://localhost:3000` in your browser
2. **Check API health**: Visit `http://localhost:3001/health`
3. **Check RabbitMQ**: Visit `http://localhost:15672` (default credentials: `dev`/`devpass`, from `RABBITMQ_DEFAULT_USER` and `RABBITMQ_DEFAULT_PASS` in `.env`)
4. **Verify database connections**: Check the logs for successful database connections
5. **Test webhook endpoints**: Your Git provider webhooks should point to `http://localhost:3332/[provider]/webhook` (or to your API domain if a reverse proxy routes `/.../webhook` to the webhooks service)


### Setup Script Issues

If the automated setup script (`pnpm run setup`) fails:

**Missing dependencies:**
```bash
# Check if all required tools are installed
node --version
pnpm --version
docker --version
openssl version
```

**Permission issues with Docker:**
```bash
# Add your user to the docker group (Linux)
sudo usermod -aG docker $USER
# Then log out and log back in
```

**Network creation errors:**
```bash
# Check if networks already exist
docker network ls | grep -E "kodus|shared"
# Remove conflicting networks if needed
docker network rm kodus-backend-services shared-network
```

### Common Issues

**Port conflicts:**
- Ensure ports 3000 (Web), 3001 (API), 3332 (Webhooks), 5432 (PostgreSQL), 27017 (MongoDB), and 5672/15672 (RabbitMQ) are available
- Stop other services using these ports before starting Kodus

**Environment variables not loading:**
- Verify your `.env` file exists in the project root
- Check that there are no trailing spaces in variable assignments
- Ensure all required security keys were generated properly

**Health check failures:**
- Run `pnpm run dev:health-check` to get detailed diagnostics
- Check if containers are fully started (wait 1-2 minutes after `pnpm run docker:start`)
- Verify database migrations and seed data are loaded
- Check API logs with `pnpm run docker:logs` for startup errors

**API not responding:**
- The API takes time to fully initialize after container startup
- Check if migrations and seed data are loaded
- Verify the `.env` file has all required variables
- Run health check to see which specific components are failing

**Reviews don't run:**
- No model is connected. Open **AI providers**, or set `API_LLM_PROVIDER_MODEL` and a key in `.env`.

**Reviews have no cross-file context:**
- `SANDBOX_PROVIDER=e2b` with no `API_E2B_KEY` runs reviews without a sandbox. Set `SANDBOX_PROVIDER=local`.

**Webhook issues with external services:**
- Use `pnpm run tunnel` to create a public endpoint for external webhooks
- Update your Git provider webhook URLs to use the tunnel URL
- Ensure the tunnel is running when testing webhook integrations
- Check tunnel logs for connection issues
