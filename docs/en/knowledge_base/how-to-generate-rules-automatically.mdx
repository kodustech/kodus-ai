---
title: "How to generate code review rules automatically"
description: "Let Kody read your reviewers' past comments and draft rules from the standards they keep repeating."
---

Writing code review rules from scratch can be tedious. Kodus can read the comments your team left on closed pull requests and draft rules from the patterns it finds.

## How it works

1. Pick **Global** or a repository in the scope picker at the top of the **Code review** group in the sidebar, open **Kody Rules**, and click **Configuration**
2. Turn on **Generate from past reviews**
3. Kody reads the last 3 months of closed PRs in the repository, looking at your reviewers' comments (not bots, and not Kody's own). Turned on for a repository, this starts right away; turned on at **Global**, repositories are picked up by the next weekly run
4. It drafts rules for the standards that come up repeatedly, listed on the Kody Rules page with the origin **Kody-generated**

Optionally, use the reviewer picker under the toggle to leave out developers whose comments Kody should not learn from.

## What happens next

- By default, generated rules are active right away and checked during code reviews
- To review them first, turn on **Kody knowledge approval** in the same **Configuration** sheet: new rules then wait in the **Pending review** section until you **Approve** or **Discard** them
- Edit, pause, or delete any generated rule like any other Kody Rule

## Continuous learning

After the first pass, Kodus reads the last week of reviewer comments **every week** and drafts new rules from them.

## Requirements

- Reviewer comments on closed pull requests in the repository. There is no minimum amount of history
- On the cloud, outside the trial, your own model key ([BYOK](/en/how_to_use/byok)); self-hosted instances use the deployment's model

For details, see [Automatic Rules Generation](/en/how_to_use/code_review/learning/kody_rules_generation).
