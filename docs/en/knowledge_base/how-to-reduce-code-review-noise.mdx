---
title: "How to reduce code review noise and false positives"
description: "Fine-tune your AI code review to surface only the most relevant suggestions and avoid alert fatigue."
---

Too many low-priority suggestions can make developers ignore code review feedback entirely. The key is to tune the review so it surfaces what matters and stays quiet on what doesn't.

## Severity threshold

Kodus filters which findings actually get posted:

- **Minimum severity to post** — only post suggestions at or above a threshold (default: Medium). Kody still finds lower-severity issues; it just does not comment on them.
- **Apply the threshold to Kody Rules** — off by default, so your team's own rules always surface

Configure these in the sidebar under **Code review → What to review**, or in `kodus-config.yml`:

```yaml
suggestionControl:
  severityLevelFilter: medium   # low | medium | high | critical
  applyFiltersToKodyRules: false
```

The `kodus-config.yml` snippets on this page only take effect when **Prefer kodus-config.yml settings** is on for the repository (**Code review → General**, at repository scope). Kody reads the file at the repository root on the default branch. See [Config Priority](/en/how_to_use/code_review/configs/general#config-priority).

## Ignore files and paths

Skip files that generate noise (lock files, generated code, configs). Add them under **Ignored files** in **Code review → General**, or in `kodus-config.yml`:

```yaml
ignorePaths:
  - yarn.lock
  - package-lock.json
  - "**/*.generated.ts"
  - dist/**
```

A list in the file replaces the list set in the app, default patterns included. Copy the defaults you want to keep into it.

## Skip PRs by title

Skip PRs that don't need review (releases, version bumps). Add keywords under **Ignore title keywords** in **Code review → General**, or in `kodus-config.yml`:

```yaml
ignoredTitleKeywords:
  - "release"
  - "bump version"
  - "chore"
```

## Toggle analysis categories

Disable entire review categories you don't need with the **Bug**, **Performance**, **Security**, and **Business Logic** switches in **Code review → What to review**, or in `kodus-config.yml`:

```yaml
reviewOptions:
  bug: true
  security: true
  performance: false        # disable if too noisy
  business_logic: false     # disable if not relevant
```

## Review cadence

Use **Auto-pause** (**Code review → General** → **Automated code review** → **Review Cadence**) to prevent spam during active development. Kodus pauses a PR after a burst of reviews (default: 3 reviews in 15 minutes) until someone comments `@kody start-review`.

## Start and end messages

Kody posts a message when a review starts and another when it ends. In **Code review → What Kody writes → Comments during the review**, use **Post this message** to post each one only when the PR opens, or never. See [Custom messages](/en/how_to_use/code_review/configs/custom_messages).

## Business Logic comments

When a PR meets its task, Kody posts a one-line comment. Turn off **Comment when every requirement is met** in the **Business Logic** settings to hear only about gaps. See [Business Logic Validation](/en/how_to_use/code_review/business_logic_validation).

For details, see [General Configuration](/en/how_to_use/code_review/configs/general) and [Severity threshold](/en/how_to_use/code_review/configs/suggestion_control).
