---
title: "Why is my AI code review not triggering"
description: "Common reasons and fixes when Kodus doesn't automatically review your pull requests."
---

If Kodus isn't reviewing your PRs, check these common causes:

## 1. Automated review is disabled

Verify that automated reviews are enabled:
- Go to **Code review → General**
- Check that **Enable Automated Code Review** is turned on
- Or verify in `kodus-config.yml`:

```yaml
automatedReviewActive: true
```

## 2. Webhook is not configured

Kodus needs webhooks to know when a PR is opened or updated:
- Go to your Git provider's webhook settings
- Verify the Kodus webhook URL is registered and active
- Check for failed delivery attempts

## 3. PR title matches an ignored keyword

If the PR title contains an ignored keyword, Kodus skips the review:

```yaml
ignoredTitleKeywords:
  - "release"
  - "WIP"
```

Check **Ignore title keywords** in **Code review → General** (or `ignoredTitleKeywords` in `kodus-config.yml`).

## 4. Base branch is not monitored

By default, Kodus reviews PRs targeting the default branch. If your PR targets a different branch, add it under **Base Branches** in **Code review → General**, or to `baseBranches` in `kodus-config.yml`:

```yaml
baseBranches:
  - develop
  - staging
```

## 5. Review cadence is set to manual

If **Review Cadence** (in **Code review → General**, under **Enable Automated Code Review**) is set to **Manual**, Kodus only reviews when you comment `@kody start-review`.

## 6. Auto-pause is active

If you've pushed multiple times quickly, auto-pause may have kicked in and Kody posted an "Auto-paused" comment on the PR. The PR stays paused until you comment `@kody start-review`.

## Still not working?

Try commenting `@kody start-review` on the PR to trigger a manual review. If that doesn't work, check the [Troubleshooting guide](/en/how_to_use/code_review/troubleshooting).
