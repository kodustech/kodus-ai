## How to connect

1. In the sidebar, open **Plugins** (installing a plugin needs the Owner role)
2. Click the **Linear** tile
3. Click **Authenticate with** the plugin and authorize access to your Linear workspace (OAuth), or enter a Linear API key and click **Connect**
4. The plugin is installed as soon as it connects, with its read-only tools selected. To change them later, open it, edit **Selected tools** and click **Update Tools**

Keep these tools selected, because Kody reads issues with them: `get_issue`, `get_team`, `list_teams`, `list_issues` and `get_document`. A tool you turn off cannot be used.

## What it enables

### Automatic business logic validation

Reference the Linear issue in the PR title, branch name or description. With **Business Logic** on in **Code review → What to review** (the default), Kody checks the PR on the first review. Kody reads the issue, its parent, sub-issues and attached documents.

### On-demand validation

Paste any Linear URL, or an issue key, in a PR comment:

```
@kody -v business-logic https://linear.app/your-team/issue/TEAM-123
```

## What you get

Kody posts one **Kody · Business Logic** comment with the requirements it checked and the code behind each result. A re-check updates that comment. See [Business Logic Validation](/en/how_to_use/code_review/business_logic_validation) for result states and re-check options.

## Tips

- Write clear acceptance criteria in your Linear issues for the most thorough validation.
- A requirement delivered by a sub-issue shows as **CHECK MANUALLY**, never as missing.

## Plugin tools in conversations

Kody can use the plugin when you mention it in a PR comment. It can also be turned on for a [custom agent](/en/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp).
