---
title: "How to check code against Google Docs specs"
description: "Validate your pull request implementation against specifications written in Google Docs."
---

Product specs and requirements often live in Google Docs. Google Docs is not a built-in task source for Business Logic Validation, which reads tasks from Linear, Jira, Notion, Git Issues or a custom plugin. A Google Docs link in the command is not read.

Two ways to check a PR against a spec from a Google Doc:

## Paste the requirements in the command

Copy the requirements from the document and comment on your PR:

```
@kody -v business-logic
## Requirements
1. Users with role "admin" can delete any comment
2. Users can only edit their own comments within 24 hours
3. Deleted comments show "[removed]" placeholder
```

Kody checks the PR against the text you wrote. No tracker is needed, but the text must be at least 40 characters. The result is one comment on the PR, **Kody · Business Logic**, with each requirement marked **MET**, **PARTIAL**, **MISSING**, **CHECK MANUALLY** or **NOT IN TASK**.

## Keep the requirements in a task

Copy the requirements into the description of a task in your tracker, under a heading such as `Acceptance criteria`, and name the task in the PR title, branch or description. Kody then checks every PR that references the task, without a command. If the criteria sit under a heading or in a custom field, set **Requirements → Where acceptance criteria live** in the Business Logic settings. A Notion page works as a task: put its URL in the PR.

## Tips

- Keep specs structured, with clear sections and numbered requirements.
- Break large documents into sections and check them one at a time for more focused feedback.
- After you fix a gap, comment `@kody -v business-logic` again. The same comment is updated.

For details, see [Business Logic Validation](/en/how_to_use/code_review/business_logic_validation).
