## How Z.AI works

Z.AI (developed by Zhipu AI) serves the GLM family of models. It's one of the few major providers offering a **flat-rate subscription** for API access: the **GLM Coding Plan** bundles model usage at a fixed monthly price, with rate limits applied over 5-hour and weekly windows instead of per-token billing.

For higher-volume or variable workloads, Z.AI also offers pay-per-token access to the same models on its standard Developer API.

Both paths expose an OpenAI-compatible endpoint, so Kodus can talk to them via the **OpenAI-compatible** provider. Kodus also has a dedicated **Z.ai** provider, which connects over Z.AI's Anthropic-compatible endpoint (`https://api.z.ai/api/anthropic`).

## Plans at a glance

<Info>
  Pricing and quotas change regularly. Always confirm current numbers at [z.ai/subscribe](https://z.ai/subscribe) and [docs.z.ai](https://docs.z.ai/devpack/overview) before choosing a tier.
</Info>

### GLM Coding Plan (subscription)

| Tier | Price (monthly equivalent) | Approximate API-value equivalent | Concurrency |
| ---- | -------------------------- | -------------------------------- | ----------- |
| **Lite** | ~$18/mo (billed quarterly) | ~15× the monthly fee | ~1 concurrent |
| **Pro**  | ~$30/mo (billed quarterly) | ~20× the monthly fee | ~1 concurrent |
| **Max**  | ~$80/mo (billed quarterly) | ~30× the monthly fee | up to 30 concurrent |

- Quotas reset on a rolling **5-hour** window and a **weekly** window — plan around the ceiling, not a monthly cap.
- Coverage includes GLM-5.1, GLM-5-Turbo, GLM-5, GLM-4.5, and GLM-4.5-Air.
- Coding Plan endpoints: `https://api.z.ai/api/anthropic` (Anthropic-compatible — the one the **Z.ai** provider in Kodus uses) and `https://api.z.ai/api/coding/paas/v4` (OpenAI-compatible). The standard `/api/paas/v4/` endpoint does not draw from the Coding Plan.

### Pay-per-token Developer API

| Model | Pricing (1M input / output tokens) | Context Window |
| ----- | ---------------------------------- | -------------- |
| **GLM-5.1** `recommended` | $0.95 / $3.15 | ~200k tokens |
| **GLM-5**      | $0.72 / $2.30 | ~131k tokens |
| **GLM-4.5**    | $0.60 / $2.20 | ~128k tokens |
| **GLM-4.5-Air** | lower tier, optimized for routing | ~128k tokens |

Standard endpoint: `https://api.z.ai/api/paas/v4/` (OpenAI-compatible).

## Creating an API Key

<Warning>A Z.AI account is required to create an API key.</Warning>

<Tabs>
  <Tab title="Coding Plan subscriber">
    1. Sign in at [z.ai](https://z.ai).
    2. Purchase a **GLM Coding Plan** tier at [z.ai/subscribe](https://z.ai/subscribe).
    3. Open the key management page for your subscription and create a Coding Plan key.
    4. Copy the key — you will not be able to see it again.

    <Note>
      Coding Plan keys are tied to the Coding Plan endpoints (`/api/anthropic` and `/api/coding/paas/v4`). They **will return 401** if sent against the standard `/api/paas/v4/` endpoint.
    </Note>
  </Tab>

  <Tab title="Developer API (pay-per-token)">
    1. Sign in at [z.ai](https://z.ai).
    2. Open the **API Keys** section at [z.ai/manage-apikey/apikey-list](https://z.ai/manage-apikey/apikey-list).
    3. Click **Create API Key**, give it a descriptive name (e.g. `kodus-prod`), and copy the key.

    <Note>
      Developer API keys are tied to the `/api/paas/v4/` endpoint.
    </Note>
  </Tab>
</Tabs>

## Configure Z.AI in Kodus

The primary flow is the **AI providers** page on Kodus Cloud. Self-hosted users who prefer fixing the provider at the process level can use environment variables instead.

### Option 1 — Z.ai provider on Kodus Cloud (recommended)

<Steps>
  <Step title="Open AI providers and pick Z.ai">
    In the sidebar, open **AI providers** ([app.kodus.io/byok](https://app.kodus.io/byok)). On the **Providers** tab, click the **Z.ai** tile (under **Connect your first provider**, or **Add another provider** if you already connected one).
  </Step>

  <Step title="Paste your API key and enter the model">
    Paste your Z.AI key in the **API key** card, then type the model ID (e.g. `glm-5.1`) in **Model**. Kodus fills in the `https://api.z.ai/api/anthropic` endpoint for you — the Anthropic-compatible endpoint Z.AI documents for the GLM Coding Plan — so this tile has no plan selector and no base URL field. To use a specific OpenAI-compatible endpoint instead, use Option 2 below.
  </Step>

  <Step title="Set concurrency (Coding Plan)">
    Kodus does not pre-fill concurrency. On Coding Plan Lite/Pro, open **Advanced (optional)** and set **Max concurrent requests** to `1`; raise it up to 30 if you're on Max.
  </Step>

  <Step title="Test & save">
    Click **Test & save**. Kodus tests the connection and saves the config on success. 401 means the key doesn't match the endpoint.
  </Step>
</Steps>

### Tuning reasoning (optional)

**Thinking / Reasoning** is under **Advanced (optional)**. For GLM, any level other than Off emits `thinking: { type: "enabled" }`, which is fine for most workloads. Two cases to override:

- **Force a specific token budget** — switch **Thinking / Reasoning** to **Custom** and paste:

  ```json
  {
    "thinking": { "type": "enabled", "budget_tokens": 20000 }
  }
  ```

- **Disable thinking** — for fastest/cheapest reviews on small PRs:

  ```json
  {
    "thinking": { "type": "disabled" }
  }
  ```

<Note>
  No namespace wrapping needed — Kodus wraps the options under the active provider's namespace before sending. See the [main BYOK doc → Custom JSON override](/en/how_to_use/byok#custom-json-override) for details.
</Note>

### Tuning concurrency

- **Coding Plan Lite / Pro**: set **Max concurrent requests** to `1`. Going higher returns `429 Too much concurrency`.
- **Coding Plan Max**: raise to `5` first, up to `30` if you don't see 429s. Max tier allows up to 30 concurrent.
- **Developer API**: start empty (no cap). Drop to `5` if you see rate-limit errors, then tune up.

<Note>
  On the **Routing** tab, set GLM 5.1 as **Model for all tasks** and an OpenAI or Anthropic model as **Fallback (optional)** so that reviews keep running when your Coding Plan 5-hour window is exhausted. Kodus fails over automatically.
</Note>

### Option 2 — OpenAI-compatible endpoint

To connect through one of Z.AI's OpenAI-compatible endpoints, open **AI providers**, pick **OpenAI-compatible** under **Custom** on the **Providers** tab, and fill:

| Field | Value |
| --- | --- |
| **Base URL** | `https://api.z.ai/api/coding/paas/v4` (Coding Plan)<br />`https://api.z.ai/api/paas/v4/` (Developer API) |
| **Model** | `glm-5.1`, `glm-5`, `glm-5-turbo`, `glm-4.5`, `glm-4.5-air` |
| **API key** | your Z.AI key (matching the base URL above) |
| **Max concurrent requests** (under **Advanced (optional)**) | `1` on Lite/Pro Coding Plan; up to `30` on Max; leave empty on Developer API |

### Option 3 — Self-hosted (environment variables)

If you run Kodus in Fixed Mode (single global provider, no per-org BYOK), configure Z.AI in the `.env` of your API + worker containers:

```env
# Z.AI configuration (Fixed Mode)
API_LLM_PROVIDER_MODEL="glm-5.1"                                  # any GLM model you have access to
API_OPENAI_FORCE_BASE_URL="https://api.z.ai/api/coding/paas/v4"   # use /api/paas/v4/ for pay-per-token
API_OPEN_AI_API_KEY="your-z-ai-api-key"
```

<Note>
  This path is only needed for self-hosted Kodus installs that deliberately disable BYOK. If BYOK is enabled on your self-hosted instance, prefer **Option 1** — the **AI providers** page works the same as on Cloud.
</Note>

Restart the API and worker containers after editing `.env`, then verify the integration:

```bash
docker-compose logs api worker | grep -iE "z\.ai|glm"
```

For the full self-hosted setup (domains, security keys, database, webhooks, reverse proxy), follow the [generic VM deployment guide](https://docs.kodus.io/en/how_to_deploy/deploy_kodus/generic_vm) and only swap the LLM block for the one above.

## Choosing between the Coding Plan and pay-per-token

- Pick the **Coding Plan** when you have a predictable team of reviewers and want a flat monthly cost. The 5-hour and weekly quotas translate to roughly 15–30× the subscription fee in equivalent API spend.
- Pick **pay-per-token** when your traffic is bursty, when you need occasional access to the largest context windows, or when you want cost to scale linearly with PR volume.
- **Pair them**: in **Routing**, use the Coding Plan as **Model for all tasks** and a Developer API key (or an entirely different provider) as **Fallback (optional)** to cover bursts that exhaust your subscription window.

## Troubleshooting

<AccordionGroup>
  <Accordion title="401 after Test — key doesn't match endpoint">
    - Coding Plan keys work on `/api/anthropic` and `/api/coding/paas/v4`, not on `/api/paas/v4/`. Developer API keys use `/api/paas/v4/`.
    - The **Z.ai** tile always uses `https://api.z.ai/api/anthropic`. If your key is only valid on another endpoint, connect it through **OpenAI-compatible** with that **Base URL**.
    - With **OpenAI-compatible**, confirm the **Base URL** matches the key origin.
  </Accordion>

  <Accordion title="'Too much concurrency' at review time">
    - Lite and Pro Coding Plan tiers typically allow only **1 concurrent request**. Set **Max concurrent requests** to `1`; raise it only on Max.
    - Lower **Max concurrent requests** in Advanced settings if you're still hitting 429s.
  </Accordion>

  <Accordion title="Quota exhausted on the Coding Plan">
    - Quotas are enforced on a **5-hour rolling window** and a **weekly window**. Hitting one of them returns HTTP 429.
    - Check remaining quota in the Z.AI console.
    - Options: wait for the next window, upgrade to a higher tier, or have a Developer API key configured as the **Fallback (optional)** model in **Routing** to cover the gap.
  </Accordion>

  <Accordion title="Model not found">
    - Verify the model ID matches Z.AI's catalog (`glm-5.1`, `glm-5-turbo`, `glm-5`, `glm-4.5`, `glm-4.5-air`).
    - The Coding Plan currently covers only the GLM family — non-GLM model names will be rejected.
  </Accordion>

  <Accordion title="Connection errors (timeout, DNS)">
    - Confirm your server can reach `api.z.ai`.
    - Check the API and worker logs for the exact upstream error.
    - If you are in a region with restricted outbound traffic, route requests through a reverse proxy your infra allows.
  </Accordion>
</AccordionGroup>
