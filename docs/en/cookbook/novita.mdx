## How Novita works

Novita is a serverless inference platform that hosts open-source models, such as DeepSeek, Kimi, GLM, MiniMax and Qwen, behind an **OpenAI-compatible** API. Kodus has a dedicated **Novita** provider, so you only need an API key.

## Recommended Models

<Info>
  See [Novita's model list](https://novita.ai/models/llm) for current models and pricing. The list at `https://api.novita.ai/openai/v1/models` is public and shows each model's context size and features.
</Info>

Novita model IDs are `org/model` strings, mostly lowercase. These list function calling and structured outputs in Novita's catalog:

| Model ID | Context Window |
| -------- | -------------- |
| `deepseek/deepseek-v4-pro` | ~1M tokens |
| `moonshotai/kimi-k3` | ~1M tokens |
| `zai-org/glm-5.3` | ~1M tokens |
| `minimax/minimax-m3` | ~1M tokens |
| `qwen/qwen3.8-27b` | ~1M tokens |

## Creating API Key

<Warning>A Novita account is required to create an API key.</Warning>

1. Open [**Key Management**](https://novita.ai/settings/key-management) in the Novita console.
2. Select **Create API Key** and name it, for example `kodus`.
3. Choose an expiration: **Permanent**, 90 days, 30 days or 24 hours. You cannot change it later, and Novita rejects an expired key.
4. Copy the key. Novita shows it in full only once.

## Configure Novita in Kodus

### Option 1 — AI providers page (recommended)

This flow is the same on Kodus Cloud and on a self-hosted instance.

<Steps>
  <Step title="Open AI providers and pick Novita">
    In the sidebar, open **AI providers** ([app.kodus.io/byok](https://app.kodus.io/byok) on Cloud, `/byok` on your own instance). On the **Providers** tab, click the **Novita** tile. It is under **Connect your first provider**, or after **Add another provider** if you already connected one.
  </Step>

  <Step title="Paste your API key and pick the model">
    Paste your Novita key in the **Key** field of the **API key** card. Leave **Base URL (optional)** empty: Kodus then calls `https://api.novita.ai/v3/openai`. In the **Model** card, pick a model from the list, or choose **Type model manually**.
  </Step>

  <Step title="Test & save">
    Click **Test & save**. Kodus sends a one-token request to the model and saves the config on success.
  </Step>
</Steps>

Then open **Code review → Routing** (the **Configure routing** button on the **AI providers** page opens it). In the **Models** card, set the Novita model as **Default model** and a model from another connected provider, such as OpenAI or Anthropic, as **Fallback model**, so reviews keep running if Novita is unavailable. Click **Save settings**.

### Option 2 — Self-hosted (environment variables)

To give a self-hosted instance one model through `.env`, use the OpenAI-compatible provider:

```env
API_LLM_PROVIDER=openai_compatible
API_LLM_PROVIDER_MODEL="deepseek/deepseek-v4-pro"
API_LLM_BASE_URL="https://api.novita.ai/openai"
API_LLM_API_KEY="your-novita-api-key"
```

Follow the installation guide to [apply the model change](/en/how_to_deploy/deploy_kodus/generic_vm#apply-a-model-change).

## Troubleshooting

<AccordionGroup>
  <Accordion title="API Key Issues">
    - Verify your API key is correct and active in [Novita's console](https://novita.ai/settings/key-management)
    - Check if you have sufficient credits in your Novita account
    - Make sure there are no trailing spaces or quotes in the `.env` value
  </Accordion>

  <Accordion title="Model Not Found">
    - Model IDs are `org/model` strings, and a few contain capitals. Copy the exact ID from Novita's model list
    - Check that the model is still in the list at `https://api.novita.ai/openai/v1/models`
  </Accordion>

  <Accordion title="Connection Errors">
    - Verify your server has internet access to reach `api.novita.ai`
    - Check if there are any firewall restrictions
    - Review the API and worker logs for the exact upstream error
  </Accordion>
</AccordionGroup>
