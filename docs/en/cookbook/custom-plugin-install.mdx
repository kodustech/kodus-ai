## Why custom plugins

A custom plugin lets Kody read your internal systems, such as a knowledge base, an incident dashboard or a policy engine, while it answers on a pull request. Reviewers stop pasting screenshots and stale snippets into comments.

<Callout icon="globe">
  Kodus supports **remote MCP servers only**. The server must be reachable from Kodus' infrastructure: no `localhost`, no desktop MCP endpoints.
</Callout>

## Prepare your plugin info

Gather these details before opening the Plugins page:

| Field | Why it matters |
| ----- | -------------- |
| **URL** | The MCP endpoint, for example `https://acme-internal-tools.com/mcp`. |
| **Protocol** | **HTTP** or **SSE**. |
| **Authorization** | **None**, **Bearer Token**, **Basic Auth**, **API Key** (and the header it goes in) or **OAuth 2.0** (a client ID, or dynamic client registration). |
| **Description and logo** | Optional. They help teammates recognize the plugin. |

Looking for remote MCP servers to try?

- [Smithery.ai](https://smithery.ai/) curates deployable MCP services.
- [Awesome Remote MCP Servers](https://github.com/sylviangth/awesome-remote-mcp-servers) lists community-maintained endpoints.

## Install the plugin in Kodus

<Frame caption="Plugins → Add Custom Plugin card → Add Plugin opens this form">
  <img src="/images/custom-plugin.png" alt="Add Custom Plugin form" />
</Frame>

<Steps>
  <Step title="Open the form">
    In the sidebar, open **Plugins**. On the **Add Custom Plugin** card, click **Add Plugin**.
  </Step>
  <Step title="Fill it in">
    ```text
    Plugin Name: Descriptive label (for example "Security Runbooks MCP")
    Description: What data it exposes (optional)
    Logo URL: Optional
    URL: https://your-domain.com/mcp
    Protocol: HTTP or SSE
    Authorization: None, Bearer Token, Basic Auth, API Key or OAuth 2.0
    Custom Headers: Any extra header your server needs (optional)
    ```

    Click **Create Plugin**.
  </Step>
  <Step title="Choose its tools and install">
    The plugin opens. With OAuth 2.0, click **Authenticate with** the plugin first. Under **Selected tools**, keep only the tools Kody needs, then click **Install plugin**. An installed plugin shows **Installed** on its card.
  </Step>
</Steps>

If **Selected tools** shows 0 of 0, Kodus could not list the server's tools. Open the plugin, click **Edit Plugin**, and check the URL, protocol and authorization.

<Warning>
  Kody can call any tool you select. Install only endpoints your organization trusts, and select only the tools Kody needs.
</Warning>

## Verify the connection

1. Open a pull request in a repository where Kody is enabled.
2. Comment with `@kody` and a question only the plugin can answer:

   ```
   @kody can you fetch the deployment checklist from our MCP and confirm whether feature flags are required?
   ```

3. Check Kody's reply. It should include data your plugin returned. If it doesn't, open the plugin on the **Plugins** page and check its URL, protocol and authorization.

<Info>
  To rehearse the flow without building a server, add `https://docs.kodus.io/mcp` as a custom plugin: protocol **HTTP**, authorization **None**.
</Info>

## Use it in a custom agent

A custom agent reads from an installed plugin when you turn it on under **Tools → Plugins** on the agent's page. Only read tools are offered. See [Skills, docs and tools](/en/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp).

## Quick checklist

- [ ] The server is reachable from Kodus over HTTP or SSE.
- [ ] Its authorization works with the method you chose.
- [ ] **Selected tools** lists tools, and only the ones Kody needs are selected.
- [ ] The plugin shows **Installed**.
- [ ] A test comment on a pull request returned data from the plugin.
- [ ] Someone owns monitoring and updating the integration.
