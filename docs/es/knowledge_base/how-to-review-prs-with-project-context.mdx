---
title: "Cómo revisar PRs con contexto específico del proyecto"
description: "Proporciona a Kody acceso a los documentos, manuales y guías de arquitectura de tu proyecto para revisiones de código más relevantes."
---

La revisión de código genérica detecta problemas genéricos. Para obtener feedback que sea realmente relevante para tu proyecto, Kody necesita entender tu contexto específico — decisiones de arquitectura, convenciones y reglas de negocio.

## Formas de proporcionar contexto

### Memorias

Enseña a Kody tus convenciones a través de la conversación:

```
@kody remember: this project uses hexagonal architecture.
Domain layer must never depend on infrastructure.
```

Las Memorias persisten y se aplican en todas las revisiones futuras.

### Referencias a archivos en reglas

Referencia tu propia documentación directamente en las reglas:

```
Instructions: Validate that new endpoints follow the patterns
in @file:docs/api-conventions.md and use the base classes
defined in @file:src/shared/base-controller.ts.
```

### Instrucciones de categoría

Agrega instrucciones específicas del proyecto que Kody incluye en cada revisión:

1. En la barra lateral, abre **Code review → What to review**
2. Edita las **Instructions** de la categoría **Bug**, **Performance** o **Security** con contexto como descripciones de arquitectura, pautas del equipo o conocimiento del dominio
3. Kody lo incluye en cada análisis de revisión de código

Para cambiar cómo Kody redacta sus sugerencias (tono, extensión), usa **Kody's personality** en **Code review → What Kody writes**.

### Trackers de tareas

Conecta Linear, Jira (**Atlassian Rovo**), Notion o Git Issues en **Plugins**. Cuando un PR referencia una tarea, Kody verifica el PR contra los requisitos y criterios de aceptación de la tarea. Consulta [Validación de Lógica de Negocio](/es/how_to_use/code_review/business_logic_validation).

### Plugins

Los plugins que instalas también son herramientas que Kody puede usar cuando lo mencionas en un comentario de PR, y herramientas que puedes activar para un [agente personalizado](/es/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp). Agrega tu propio servidor MCP como plugin personalizado para incorporar otras herramientas.

## Flujo de trabajo de ejemplo

1. Define reglas de arquitectura mediante **Memories**: `@kody remember: we follow CQRS pattern in this service`
2. Crea **Review Rules** que referencien tus documentos: `@file:docs/architecture.md`
3. Conecta tu tracker de tareas para que Kody valide los PRs contra los requisitos de las tareas
4. Agrega **Instructions** de categoría en **What to review** para conocimiento específico del dominio

Para más detalles, consulta [Instrucciones de categoría](/es/how_to_use/code_review/configs/custom_prompts) y [Plugins](/es/how_to_use/code_review/plugins).
