---
title: "Cómo reducir el ruido y los falsos positivos en la revisión de código"
description: "Ajusta tu revisión de código con IA para mostrar solo las sugerencias más relevantes y evitar la fatiga por alertas."
---

Demasiadas sugerencias de baja prioridad pueden hacer que los desarrolladores ignoren por completo el feedback de las revisiones de código. La clave está en ajustar la revisión para que muestre lo que importa y permanezca en silencio en lo que no.

## Umbral de severidad

Kodus filtra qué hallazgos se publican realmente:

- **Minimum severity to post** — publica solo sugerencias en o por encima de un umbral (por defecto: Medium). Kody sigue encontrando los problemas de menor severidad; simplemente no los comenta.
- **Apply the threshold to Kody Rules** — desactivado por defecto, para que las reglas propias de tu equipo siempre aparezcan

Configúralos en la barra lateral en **Code review → What to review**, o en `kodus-config.yml`:

```yaml
suggestionControl:
  severityLevelFilter: medium   # low | medium | high | critical
  applyFiltersToKodyRules: false
```

Los fragmentos de `kodus-config.yml` de esta página solo tienen efecto cuando **Prefer kodus-config.yml settings** está activado para el repositorio (**Code review → General**, en el alcance de repositorio). Kody lee el archivo en la raíz del repositorio, en la rama por defecto. Consulta [Prioridad de configuración](/es/how_to_use/code_review/configs/general#prioridad-de-configuración).

## Ignorar archivos y rutas

Omite archivos que generan ruido (archivos de bloqueo, código generado, configuraciones). Agrégalos en **Ignored files** en **Code review → General**, o en `kodus-config.yml`:

```yaml
ignorePaths:
  - yarn.lock
  - package-lock.json
  - "**/*.generated.ts"
  - dist/**
```

Una lista en el archivo reemplaza la lista definida en la app, incluidos los patrones por defecto. Copia en ella los valores por defecto que quieras conservar.

## Omitir PRs por título

Omite PRs que no necesitan revisión (versiones, actualizaciones de versión). Agrega palabras clave en **Ignore title keywords** en **Code review → General**, o en `kodus-config.yml`:

```yaml
ignoredTitleKeywords:
  - "release"
  - "bump version"
  - "chore"
```

## Alternar categorías de análisis

Desactiva categorías de revisión completas que no necesitas con los interruptores **Bug**, **Performance**, **Security** y **Business Logic** en **Code review → What to review**, o en `kodus-config.yml`:

```yaml
reviewOptions:
  bug: true
  security: true
  performance: false        # disable if too noisy
  business_logic: false     # disable if not relevant
```

## Cadencia de revisión

Usa **Auto-pause** (**Code review → General** → **Automated code review** → **Review Cadence**) para evitar spam durante el desarrollo activo. Kodus pausa un PR después de una ráfaga de revisiones (por defecto: 3 revisiones en 15 minutos) hasta que alguien comenta `@kody start-review`.

## Mensajes de inicio y de fin

Kody publica un mensaje cuando empieza una revisión y otro cuando termina. En **Code review → What Kody writes → Comments during the review**, usa **Post this message** para publicar cada uno solo cuando se abre el PR, o nunca. Consulta [Mensajes personalizados](/es/how_to_use/code_review/configs/custom_messages).

## Comentarios de Business Logic

Cuando un PR cumple su tarea, Kody publica un comentario de una línea. Desactiva **Comment when every requirement is met** en los ajustes de **Business Logic** para enterarte solo de las brechas. Consulta [Validación de Lógica de Negocio](/es/how_to_use/code_review/business_logic_validation).

Para más detalles, consulta [Configuración General](/es/how_to_use/code_review/configs/general) y [Umbral de severidad](/es/how_to_use/code_review/configs/suggestion_control).
