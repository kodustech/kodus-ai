title: "Cómo enseñarle a la IA las convenciones de codificación de tu equipo"
description: "Usa Memorias para que Kody aprenda tus preferencias de codificación, decisiones de arquitectura y convenciones del equipo a través de una conversación natural."
---

Cada equipo tiene contexto no escrito — preferencias tecnológicas, convenciones de nomenclatura, decisiones de arquitectura, detalles de migración. En lugar de documentarlo todo desde el principio, puedes enseñárselo a Kody mediante una conversación natural para que las futuras revisiones sean más relevantes y desaparezcan las sugerencias repetitivas de poco valor.

## Cómo funciona

Cuando le pides a Kody en un comentario de PR que recuerde algo, lo guarda como una **Memoria**. Cuando solo expones contexto del código o una preferencia del equipo, Kody ofrece guardarlo y lo guarda cuando le dices que sí. Las Memorias se usan luego como contexto de alta prioridad en futuras revisiones de código y conversaciones.

### Enseñanza explícita

Dile directamente a Kody que recuerde algo:

```
@kody remember: this repo mirrors a third-party API, so some payload fields intentionally stay snake_case.
```

```
@kody please remember: this service follows hexagonal architecture and keeps adapters at the edge.
```

### Exponer una convención

Expón una convención, o explica por qué una sugerencia no aplica, y Kody ofrece guardarla como memoria. Responde `@kody yes` para guardarla. Por ejemplo:

```
@kody this repo mirrors a third-party API, so some payload fields intentionally stay snake_case.
```

```
@kody in this service, tests usually live next to the implementation files rather than in a central test folder.
```

```
@kody the billing module is mid-migration, so prefer incremental fixes over broad refactors.
```

## Qué no guardará Kody

Kody es selectiva respecto a lo que se convierte en memoria:

- Instrucciones temporales ("arregla esto ahora", "omite esto por hoy")
- Preguntas ("¿cuál es el plazo?")
- Conversaciones de depuración ("veo un error")
- Declaraciones vagas sin información accionable
- Solicitudes con alcance a un solo PR o tarea

## Alcances de memoria

Cada memoria se aplica en un nivel específico:

| Alcance | Ejemplo |
|---------|---------|
| **Directorio** | "En `src/components/ui`, usar siempre nuestros tokens del sistema de diseño" |
| **Repositorio** | "Este repositorio usa arquitectura hexagonal" |
| **Organización** | "Todos los repositorios usan ESLint flat config" |

## Flujo de aprobación

Si quieres revisar las memorias que Kody crea antes de que entren en vigor, abre **Code review → Kody Rules**, haz clic en **Configuration** y activa **Kody knowledge approval**. Las memorias nuevas (y las reglas generadas por Kody) esperarán entonces en la sección **Pending review** hasta que las apruebes (**Approve**) o descartes (**Discard**). Las memorias que escribes con **New memory** están activas de inmediato.

## Gestionar memorias

Ve a **Code review → Kody Rules** → pestaña **Memories** para ver, editar o eliminar memorias. También puedes crear memorias manualmente con **New memory**.

Para más detalles, consulta [Kody Rules — Memorias](/es/how_to_use/code_review/configs/kody_rules#memorias).
