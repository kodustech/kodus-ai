Si quieres ejecutar Kody con una GitHub App, necesitas crear una. Esta app permite que Kody interactúe con tus repositorios, gestione pull requests y reciba webhooks.

<Note>Si quieres habilitar "Iniciar sesión con GitHub" para los usuarios de la plataforma, ese es un proceso separado de OAuth App y no interfiere con los permisos de la GitHub App. Esta guía se centra en la integración funcional. Consulta <a href="/es/how_to_deploy/platforms/github/github_oauth">OAuth App de GitHub</a>.</Note>

## Requisitos previos

Ten listos los dominios de tu aplicación:

- **WEB_DOMAIN**: URL de tu frontend (ej., `https://app.yourdomain.com` o `http://localhost:3000`). Define `NEXTAUTH_URL` y `API_FRONTEND_URL` en tu `.env` con la misma URL.
- **WEBHOOK_DOMAIN**: URL pública que llega al servicio de webhooks (ej., `https://kodus-webhooks.yourdomain.com`). El dominio de tu API solo funciona si su proxy inverso enruta `/github/webhook` a ese servicio.

## Paso 1: Crear la GitHub App

1. En GitHub, ve a **Settings** > **Developer Settings** > **GitHub Apps**
2. Haz clic en **New GitHub App**
3. Completa la información básica (Name, Homepage URL) según tu preferencia

## Paso 2: Configurar las URLs de callback y configuración

Este paso es fundamental para garantizar que la instalación y la redirección funcionen correctamente. Completa los campos a continuación, reemplazando `WEB_DOMAIN` con tu URL real:

- **Callback URL**:
  ```
  WEB_DOMAIN/api/auth/callback/github
  ```
  Esta URL se utiliza para completar el flujo de autorización.
  Mantén **Allow wildcard matching** marcado en ella: cuando alguien conecta la app, GitHub confirma que tiene acceso a la instalación y lo devuelve a `WEB_DOMAIN/api/auth/callback/github/installation`, un subdirectorio de esta URL. Si desactivas el wildcard matching, agrega esa URL como segunda Callback URL. Kodus construye esa URL de retorno a partir de `API_FRONTEND_URL`, o de `NEXTAUTH_URL` cuando `API_FRONTEND_URL` está vacío, por lo que debe coincidir con tu URL web. El `.env.example` del instalador define `API_FRONTEND_URL=http://localhost:3000`; cámbialo.

- **Setup URL**:
  ```
  WEB_DOMAIN/setup/github
  ```

- Marca la opción: **Redirect on update**
  Esto garantiza que, tras instalar la app, los usuarios sean redirigidos de regreso a Kodus para completar la configuración.

## Paso 3: Configurar el webhook

El webhook notifica a Kodus sobre los eventos en tus pull requests.

<Note>
  Los webhooks son gestionados por un servicio separado (puerto 3332). Si usas el dominio de la API aquí, asegúrate de que tu proxy inverso enrute `/github/webhook` al servicio de webhooks. De lo contrario, usa un dominio dedicado para webhooks.
</Note>

- **Webhook URL**:
  ```
  WEBHOOK_DOMAIN/github/webhook
  ```

- Asegúrate de que la opción **Active** esté marcada
- Deja **Secret** vacío

## Paso 4: Definir los permisos y suscribirse a los eventos

En **Repository permissions**, define:

| Permission | Access |
| --- | --- |
| Contents | Read-only |
| Pull requests | Read and write |
| Issues | Read and write |
| Checks | Read and write |
| Commit statuses | Read-only |
| Metadata | Read-only |

En **Organization permissions**, define **Members** como **Read-only**. Kody lo usa para listar los miembros de la organización, por ejemplo en los filtros de autor de PR en **Repositories**.

El acceso de escritura a Contents solo es necesario para funciones que hacen commit de archivos del repositorio; para leer código basta con solo lectura. Commit statuses es de solo lectura para usar los resultados de tu CI como evidencia de la revisión; sin él, Kody solo ve los check runs. Instala la app en los repositorios deseados y aprueba los permisos nuevos solicitados en las instalaciones existentes.

En **Subscribe to events**, selecciona:

- **Pull request**
- **Pull request review comment**
- **Issue comment**
- **Push**
- **Repository** (opcional): permite que Kody configure un repositorio creado después de instalar la app con acceso a todos los repositorios en cuanto GitHub lo reporta, cuando [Revisar todos los repositorios](/es/how_to_use/code_review/configs/review_all_repositories) está activado.

Kody ignora los demás eventos. GitHub igual recibe un `200` por ellos.

### Merge queue

Kody solo actúa sobre un **Push** a una rama de merge queue (`gh-readonly-queue/...`) e ignora cualquier otro push. La merge queue de GitHub prueba cada PR en cola en esa rama. En ese push, Kody copia el último resultado terminado de `Kody Code Review` del PR al commit de la cola, de modo que el check puede seguir siendo obligatorio con una merge queue. No se ejecuta ninguna revisión nueva y no se necesita ningún permiso más allá de **Checks**. Si el PR no tiene una revisión de Kody terminada, el check falla y la cola elimina el PR; consulta [Solución de problemas](/es/how_to_use/code_review/troubleshooting).

## Paso 5: Recopilar las credenciales y agregarlas al .env

Ahora necesitas obtener las credenciales generadas por GitHub y agregarlas a las variables de entorno de Kodus.

### App ID

En la parte superior de la página "About" de tu app, copia el **App ID**.

Agrega a tu `.env`:
```
API_GITHUB_APP_ID=your_app_id_here
```

### Client ID

En la misma página, copia el **Client ID**.

Agrega a tu `.env`:
```
GLOBAL_GITHUB_CLIENT_ID=your_client_id_here
```

### Client Secret

Ve a la sección **Client secrets** y haz clic en **Generate a new client secret**.

Copia el valor generado.

Agrega a tu `.env`:
```
API_GITHUB_CLIENT_SECRET=your_client_secret_here
```

### Private Key

Desplázate hasta el final de la página y haz clic en **Generate a private key**.

Esto descargará un archivo `.pem`. Abre este archivo con un editor de texto y copia todo el contenido.

Agrega a tu `.env`:
```
API_GITHUB_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY----- ..."
```

Kodus acepta la clave con sus saltos de línea, o en una sola línea con `\n` entre las líneas.

### Installation URL

Abre tu GitHub App y haz clic en **Install App**. Copia la URL de la barra de direcciones del navegador (tiene el formato `https://github.com/apps/<app-slug>/installations/new`).

Agrega a tu `.env`:
```
WEB_GITHUB_INSTALL_URL="https://github.com/apps/your-app/installations/new"
```

## Resumen de variables de entorno

Al finalizar, tu archivo de configuración debe contener:

```bash
API_GITHUB_APP_ID=123456
GLOBAL_GITHUB_CLIENT_ID=Iv1.example123
API_GITHUB_CLIENT_SECRET=example_secret_123
API_GITHUB_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY----- ..."
WEB_GITHUB_INSTALL_URL="https://github.com/apps/your-app/installations/new"
```

Haz clic en **Save Changes** en GitHub y reinicia tu aplicación Kodus para aplicar los cambios.

## Verificar la conexión

La URL del webhook debe llegar al servicio de webhooks, no a la página de inicio de sesión del frontend. Una respuesta `200` o `307` por sí sola no prueba que la entrega sea correcta; consulta [Cómo solucionar problemas de webhooks](/es/knowledge_base/how-to-fix-webhook-issues) para ver una solicitud que sí lo prueba.

Mantén **Redirect on update** activado. Después de instalar o cambiar el acceso a repositorios, completa el recorrido del navegador de regreso a Kodus a través de la **Setup URL**. Un `ping` exitoso o un evento `installation` ignorado no crea la integración de Kodus.

En Kodus, abre **Repositories** en la barra lateral y confirma que el repositorio esperado aparezca en la lista. Luego abre un pull request de prueba y revisa tanto la respuesta de entrega de GitHub como los logs de webhooks y del worker de Kodus.

Si falta la conexión:

- La persona que conecta debe poder ver la instalación en GitHub, por ejemplo un propietario de la organización. De lo contrario, Kodus rechaza el vínculo.
- Una instalación se vincula a una sola organización de Kodus. Conectarla a una segunda se rechaza.
- Inicia y termina la conexión en el mismo navegador dentro de 10 minutos. Después de eso, la autorización de GitHub caduca y debes empezar de nuevo.
- Revisa el acceso a repositorios de la instalación, los permisos aprobados, la Setup URL, la Callback URL y el enrutamiento del proxy.

[Referencia de registro en GitHub](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app).
