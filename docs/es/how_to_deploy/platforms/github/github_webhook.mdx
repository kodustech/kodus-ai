---
title: Crear un webhook
description: "Crea manualmente el webhook de GitHub para una integración con token cuando el registro automático no ocurrió, y selecciona los tres eventos que Kodus consume."
icon: webhook
---

Con un personal access token, Kodus crea el webhook en cada repositorio cuando guardas la selección de repositorios. Para eso necesita acceso de lectura y escritura a los webhooks del repositorio: `admin:repo_hook` en un token clásico, o **Webhooks: Read and write** en un token fine-grained. Si el token no lo tiene, **Repositories** muestra el repositorio con el motivo, y puedes crear el webhook manualmente como se indica a continuación.

Con la GitHub App no hay un webhook por repositorio: los eventos provienen del webhook propio de la App. Consulta [Crear una GitHub App](/es/how_to_deploy/platforms/github/github_app).

<Note>
  Las URLs de webhook deben llegar al servicio de Webhooks (puerto 3332). Usar el dominio de la API solo funciona si tu proxy inverso enruta las rutas `/.../webhook` al servicio de webhooks.
</Note>

1. Ve a tu repositorio de GitHub
2. Haz clic en "Settings"
3. Busca "Webhooks" en la barra lateral izquierda
4. Haz clic en "Add webhook"
5. Configura tu webhook:

   - **Payload URL**: Ingresa la URL de tu archivo `.env`: `API_GITHUB_CODE_MANAGEMENT_WEBHOOK` (termina en `/github/webhook`)
   - **Content type**: `application/json`
   - **Secret**: Dejar en blanco
   - **SSL verification**: Enable SSL verification
   - **Which events would you like to trigger this webhook?**: Let me select individual events
   - Marca estas casillas:
     - Issue comments
     - Pull request review comments
     - Pull requests

6. Haz clic en "Add webhook"

Has configurado correctamente un webhook para las revisiones de código en tu repositorio de GitHub.

<Note>
  Estos son los únicos eventos que usa una integración con token. Kodus ignora los demás, como pushes, pull request reviews y review threads, por lo que seleccionarlos solo agrega tráfico.
</Note>
