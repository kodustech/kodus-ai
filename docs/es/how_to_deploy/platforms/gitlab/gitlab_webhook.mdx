---
title: Crear un webhook
description: "Crea manualmente el webhook de GitLab cuando el registro automático no ocurrió, y selecciona los eventos que Kodus consume."
icon: webhook
---

Kodus normalmente crea el webhook automáticamente cuando guardas la selección de repositorios. Para eso necesita el rol **Maintainer** u **Owner** en el proyecto. Si no ocurrió, **Repositories** muestra el proyecto con el motivo, y puedes configurar el webhook manualmente:

<Note>
  Las URLs de webhook deben llegar al servicio de Webhooks (puerto 3332). Usar el dominio de la API solo funciona si tu proxy inverso enruta las rutas `/.../webhook` al servicio de webhooks.
</Note>

1. Navega a tu proyecto de GitLab
2. Ve a "Settings" > "Webhooks"
3. Configura tu webhook:

   - **URL**: Ingresa la URL de tu archivo `.env`: `API_GITLAB_CODE_MANAGEMENT_WEBHOOK` (termina en `/gitlab/webhook`)
   - **Check Show full URL**
   - **Name**: (opcional) Kodus Code Review
   - **Description**: (opcional) Kodus Code Review Webhook
   - **Secret token**: Dejar en blanco
   - **SSL verification**: Enable SSL verification
   - **Trigger**: Selecciona los siguientes eventos:
     - Comments
     - Merge request events

4. Haz clic en "Add webhook"

Has configurado correctamente un webhook para las revisiones de código en tu proyecto de GitLab.

<Note>
  Kodus solo consume eventos de comentario y de merge request. Los eventos de issue se descartan al llegar.
</Note>
