---
title: Crear un webhook
description: "Crea manualmente el webhook de Forgejo cuando el registro automático no ocurrió, y selecciona los eventos que Kodus consume."
icon: webhook
---

<Note>
  El soporte para Forgejo es mantenido por la comunidad.
</Note>

Kodus normalmente crea el webhook automáticamente cuando guardas la selección de repositorios. Para eso necesita acceso de administrador al repositorio y el scope `write:repository` en el token. Si no ocurrió, **Repositories** muestra el repositorio con el motivo, y puedes configurar el webhook manualmente:

<Note>
  Las URLs de webhook deben llegar al servicio de Webhooks (puerto 3332). Usar el dominio de la API solo funciona si tu proxy inverso enruta las rutas `/.../webhook` al servicio de webhooks.
</Note>

1. Navega a tu repositorio en Forgejo
2. Abre la pestaña **Settings** del repositorio
3. Selecciona **Webhooks**
4. Haz clic en **Add webhook** → **Forgejo**
5. Configura tu webhook:

   - **Target URL**: Ingresa la URL que configuraste en `API_FORGEJO_CODE_MANAGEMENT_WEBHOOK` en tu archivo `.env` (termina en `/forgejo/webhook`)
   - **HTTP method**: POST
   - **POST content type**: `application/json`
   - **Trigger on**: **Custom events**, y luego selecciona:
        - Repository events: **Push**
        - Pull request events: **Modification**, **Synchronized** y **Comments**
   - **Active**: Marca

6. Haz clic en **Add webhook**

¡Listo! Has configurado exitosamente un webhook para las revisiones de código en tu repositorio de Forgejo.

<Note>
  Forgejo entrega los comentarios de pull request como `issue_comment`, y Kodus actúa sobre las entregas `pull_request`, `push` e `issue_comment`. De los eventos de pull request, actúa sobre `opened`, `synchronized`, `reopened` y `closed`; **Synchronized** es lo que entrega los nuevos commits de un pull request.

  Los eventos de push importan específicamente en Forgejo: son los únicos que llevan el head
  anterior y el actual de la rama, que es como Kodus detecta los force-push y asocia una rama con
  sus pull requests abiertos. Los eventos de issue se descartan al llegar.
</Note>
