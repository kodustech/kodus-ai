Dos ajustes definen qué reporta Kody y cómo se lee. Ambos se pueden definir en los alcances Global, Repository y Directory.

| Ajuste | Dónde | Qué controla |
| --- | --- | --- |
| **Instructions** | **Code review → What to review**, en las filas Bug, Performance y Security | Qué busca Kody en esa categoría. |
| **Personality instructions** | **Code review → What Kody writes**, en **Kody's personality** | El tono y la longitud de cada sugerencia. |

## Instrucciones de categoría

Cada fila **Bug**, **Performance** y **Security** activada en [Qué revisar](/es/how_to_use/code_review/configs/what_to_review) tiene un botón **Instructions** que abre un editor (*What counts as a bug issue*, y así sucesivamente).

- El editor muestra el texto predeterminado de Kody. El chip dice **Kody's default** hasta que lo cambias, y entonces **Custom**.
- **Reset to default** restaura el texto predeterminado. Borrar el texto hace lo mismo.
- El límite es de 2000 caracteres.
- El botón se oculta mientras la categoría está desactivada. Business Logic no tiene instrucciones aquí.

Kody añade tu texto a sus directrices para esa categoría. Nombra tu stack y los patrones que te importan:

```text
Focus on SQL injection and missing authorization checks in our API
handlers. Treat unvalidated user input reaching a query as a finding.
```

## Instrucciones de personalidad

El editor **Personality instructions** en **Kody's personality** (límite de 2000 caracteres, **Reset to default** disponible) define cómo suena Kody en cada sugerencia. Se aplica además de las instrucciones de cada categoría.

- El valor predeterminado de Kody limita cada sugerencia a dos frases cortas: el impacto y qué cambiar. Cuando escribes las tuyas, ese tope deja de aplicarse, así que indica qué extensión quieres que tengan las sugerencias.
- Algunas reglas se mantienen sea lo que sea que escribas: Kody no repite el título de la sugerencia, no pone bloques de código en el texto porque la corrección se muestra por separado, y no añade números de línea.
- Se aplica a toda sugerencia excepto a los hallazgos deterministas de escáneres. Las instrucciones de redacción propias de un agente personalizado la reemplazan para los hallazgos de ese agente.

```text
Be direct. State the impact in one sentence, then the change to make.
Write in the second person and skip pleasantries.
```

## Referencias Externas

Las instrucciones de categoría, las instrucciones de personalidad y las [instrucciones de resumen](/es/how_to_use/code_review/configs/pr_summary) pueden apuntar a archivos. Tras guardar, Kody detecta las referencias y lee esos archivos en revisiones posteriores. Un indicador de estado bajo el editor muestra cuándo termina el procesamiento.

- `@file:path/to/file.ts` — un archivo del repositorio que se está revisando. Añade `#L10-L50` para un rango de líneas.
- `@file:repo-name:path/to/file.ts` — un archivo de otro repositorio.

También se detectan menciones como "follow the guidelines in CONTRIBUTING.md". Usa rutas precisas para que Kody encuentre el archivo correcto.

## Configurarlas en `kodus-config.yml`

Los mismos campos están disponibles bajo `v2PromptOverrides`:

```yaml
v2PromptOverrides:
    generation:
        main: |
            Tone and length for every suggestion.
    categories:
        descriptions:
            bug: |
                What Kody should look for in the Bug category.
            performance: |
                What Kody should look for in the Performance category.
            security: |
                What Kody should look for in the Security category.
```

El archivo acepta un grupo más que ninguna página de la aplicación edita: la rúbrica de severidad que Kody usa para clasificar un hallazgo.

```yaml
v2PromptOverrides:
    severity:
        flags:
            critical: |
                What counts as critical.
            high: |
                What counts as high.
            medium: |
                What counts as medium.
            low: |
                What counts as low.
```

<Warning>
  Esto cambia cómo Kody *clasifica* los hallazgos, no solo cómo los redacta. Una rúbrica mala puede silenciar o inflar severidades de forma discreta en todas las revisiones. Parte de los valores predeterminados de
  [`default-kodus-config.yml`](https://github.com/kodustech/kodus-ai/blob/main/default-kodus-config.yml)
  en lugar de escribir una rúbrica desde cero.
</Warning>

<Note>
  `default-kodus-config.yml` también contiene un grupo `v2PromptOverrides.level`. Se acepta pero se ignora; solo `categories.descriptions`, `severity.flags` y `generation.main` llegan a la revisión.
</Note>

El archivo solo se lee cuando **Prefer kodus-config.yml settings** está activado. Consulta [General](/es/how_to_use/code_review/configs/general#prioridad-de-configuración).

## Consejos

- **Sé específico para tu contexto.** "Focus on null dereferences in our Java services and unclosed connections in the DAO layer" funciona mejor que "look for bugs".
- **Mantén las categorías separadas.** No repitas la misma instrucción en Bug, Security y Performance.
- **Describe el patrón, no un solo ejemplo.** Un ejemplo, como una concatenación de cadenas exacta, puede reducir lo que Kody señala a esa forma.
- **Empieza con un solo ajuste.** Ejecuta los valores predeterminados durante una semana, anota los falsos positivos o las omisiones, y cambia solo la instrucción relacionada con ellos.

## Preguntas Frecuentes

<AccordionGroup>
  <Accordion title="¿Se aplican a todos los repositorios?">
    Definidas en Global, se aplican a todo repositorio que no tenga su propio valor. Un repositorio o directorio puede sobrescribirlas.
  </Accordion>

  <Accordion title="¿Qué pasa con los pull requests existentes cuando las cambio?">
    Los cambios afectan solo a las revisiones nuevas. Comenta `@kody review --force` para revisar todo un pull request existente con el nuevo texto. Sin `--force`, un comando de revisión cubre solo los commits desde la última revisión.
  </Accordion>

  <Accordion title="Las revisiones son demasiado ruidosas. ¿Qué debo cambiar?">
    Sube **Minimum severity to post** en What to review (consulta [Umbral de Severidad](/es/how_to_use/code_review/configs/suggestion_control)), y luego haz más específicas las instrucciones de categoría.
  </Accordion>

  <Accordion title="Kody pasa por alto un problema que debería detectar.">
    Comprueba que la categoría esté activada y que la severidad del hallazgo no esté por debajo de tu umbral. Usa **Reset to default** para ver si tu instrucción redujo demasiado la revisión.
  </Accordion>

  <Accordion title="¿Cuál es la diferencia entre las instrucciones de categoría y las de personalidad?">
    Las instrucciones de categoría controlan qué analiza Kody en cada categoría. Las instrucciones de personalidad controlan cómo se redacta cada hallazgo. Puedes cambiarlas de forma independiente.
  </Accordion>
</AccordionGroup>
