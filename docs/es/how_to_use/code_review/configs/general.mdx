Abre **Code review → General** (título de la página **General settings**). Las categorías de revisión y el umbral de severidad están en [Qué revisar](/es/how_to_use/code_review/configs/what_to_review). Los resúmenes, los mensajes y la voz de Kody están en **What Kody writes**.

<Note>
  Kodus tiene tres niveles de configuración: Global, Repositorio y Directorio. Aprende cómo funcionan en <a href="/es/how_to_use/code_review/configs/inheritance_overrides">Herencia y Overrides de Configuración</a>.
</Note>

## Revisión automatizada

El interruptor **Automated code review** hace que Kody revise los pull requests cuando se abren. Está activado por defecto. Con él desactivado, inicia una revisión comentando `@kody start-review` en el pull request.

<Info>
  Este interruptor cubre la **revisión inicial**. Para pushes posteriores, consulta Cadencia de Revisión a continuación.
</Info>

### Cadencia de Revisión

Se muestra cuando **Automated code review** está activado. Decide cómo gestiona Kody las revisiones posteriores a la primera:

<Tabs>
  <Tab title="Automática">
    Revisa cada nuevo push. Este es el valor predeterminado.
  </Tab>

  <Tab title="Auto-pausa">
    Pausa las revisiones cuando los pushes llegan en ráfaga. Una vez que Kody ha revisado un pull request **Pushes to trigger pause** veces dentro de **Time window (minutes)**, el siguiente push no se revisa y el pull request permanece en pausa hasta que comentes `@kody start-review`.

    Valores predeterminados: 3 pushes en 15 minutos.
  </Tab>

  <Tab title="Manual">
    Kody revisa el primer push cuando se abre el pull request. Los pushes posteriores se revisan solo cuando comentas `@kody start-review`.
  </Tab>
</Tabs>

### Revisar pull requests en borrador

**Review draft pull requests** está activado por defecto, así que los borradores se revisan. Desactívalo para omitirlos hasta que se marquen como listos.

## Modo de revisión

General muestra los modos de revisión y los modelos en vigor. Sigue **Configure routing** para cambiar el modo, o los modos elegidos según el resultado del riesgo, y para sobrescribir el modelo de un repositorio o directorio. Consulta [Routing](/es/how_to_use/code_review/configs/routing).

La evaluación de riesgo tiene su propia página e interruptor. Consulta [Evaluación de riesgo](/es/how_to_use/code_review/configs/risk).

## Flujo de trabajo del PR

**Automatic PR approval** — Kody aprueba un PR después de una revisión limpia, o cuando se resuelven todos los comentarios que dejó. Nunca hace merge. Las políticas de aprobación definen qué PRs limpios puede aprobar Kody, y la evaluación de riesgo activa se aplica a todas las políticas. Consulta [Auto-aprobación](/es/how_to_use/code_review/configs/auto_approve).

**Plataformas:** GitHub, GitLab, Bitbucket, Azure Repos, Forgejo

## Feedback de la revisión

- **Request changes on critical issues** (`isRequestChangesActive`, desactivado por defecto) — cuando Kody encuentra un problema crítico, establece la revisión del pull request en Request Changes. Kody retira la solicitud cuando esos hallazgos se resuelven, incluso en un pull request que no aprueba. Plataformas: GitHub, Bitbucket, Azure Repos, Forgejo. El interruptor se oculta cuando GitLab es tu única plataforma conectada.
- **Show status feedback** (activado por defecto) — Kody reacciona o comenta cuando una revisión se omite o se bloquea.
- **Committable suggestions** (Alpha, activado por defecto) — Kody puede sugerir código que aplicas directamente como un commit. Solo GitHub; el interruptor está deshabilitado sin una conexión con GitHub.

## Alcance de la revisión

Kody omite los archivos y pull requests que coinciden con estos ajustes. Las revisiones iniciadas con `@kody start-review` ignoran **Ignore title keywords**, **Base Branches** y **Review draft pull requests**.

### Archivos ignorados

Patrones glob de los archivos que Kody omite. Los patrones distinguen mayúsculas de minúsculas y coinciden con los dotfiles. El campo muestra algunos patrones; **Edit** abre el diálogo **Ignored files**. Se comprueba que cada patrón nuevo tenga una sintaxis glob válida, y **Test a file** te indica si una ruta se ignoraría, y por qué patrón, o se revisaría. **Apply** solo actualiza el campo. No se guarda nada hasta que haces clic en **Save settings**.

La lista predeterminada es larga: `yarn.lock`, `package-lock.json`, `package.json`, `.env`, `**/*.json`, `**/*.xml`, `**/*.lock`, `**/*.min.*`, imágenes, fuentes y archivos comprimidos, archivos de IDE y del sistema operativo, y carpetas como `**/build/**`, `**/bin/**`, `**/out/**`, `**/vendor/*`, `**/deploy/**` y `**/prod/**`. Si Kody omite archivos que esperas que revise, busca en la lista un patrón demasiado amplio y elimínalo.

Cuando se ignoran todos los archivos modificados, la revisión aún puede ejecutarse si un agente personalizado incluye explícitamente uno de ellos. Los archivos eliminados quedan excluidos. Kody omite la revisión cuando quedan más de 2.000 archivos revisables entre la revisión principal y los agentes personalizados. Usa **Ignored files** para excluir carpetas generadas o de terceros.

### Ignore title keywords

Kody omite los pull requests cuyo título contiene alguna de estas palabras clave. La comparación no distingue mayúsculas de minúsculas, y cada palabra clave puede tener hasta 100 caracteres.

### Base Branches

Qué ramas de destino reciben revisiones automáticas.

<Info>
  **Vacío, el valor predeterminado, significa solo la rama predeterminada del repositorio.** Añade entradas para revisar otras ramas. Una vez que la lista tiene entradas, Kody revisa los pull requests que coinciden con alguna de ellas, más la rama predeterminada salvo que la excluyas con `!`.

  Las entradas se comparan con la rama de **destino** del pull request, excepto `contains:`:

  | Entrada | Efecto |
  | --- | --- |
  | `develop` | Revisa los pull requests dirigidos a `develop`. |
  | `release/*` | Revisa los pull requests dirigidos a cualquier rama que empiece por `release/`. `*` coincide con cualquier carácter, barras incluidas. |
  | `*` | Revisa los pull requests dirigidos a cualquier rama. |
  | `!staging` | Nunca revisa los pull requests dirigidos a `staging`. Una exclusión gana sobre cualquier otra coincidencia. Usa `!main` para excluir la rama predeterminada. |
  | `contains:hotfix` | Revisa los pull requests cuya rama de **origen** contiene `hotfix`, sea cual sea el destino. |

  Cada entrada puede tener hasta 100 caracteres.
</Info>

## Otros ajustes

- **Kody Language** (solo Global) — el idioma que Kody usa en las respuestas de revisión.
- **Configure centralized config** (solo Global, en el encabezado de la página) — mantiene la configuración de revisión en un único repositorio. Consulta [Configuración Centralizada](/es/how_to_use/code_review/configs/centralized_config).

## kodus-config.yml

### Prioridad de Configuración

Puedes mantener la configuración de revisión en un archivo `kodus-config.yml` en la raíz de un repositorio en lugar de la aplicación web.

<Warning>
  **El archivo se ignora hasta que lo habilites.** Kody nunca lee `kodus-config.yml` a menos que **Prefer kodus-config.yml settings** esté activado para el repositorio. Hacer commit del archivo por sí solo no hace nada.

  Elige el repositorio en el selector de alcance en la parte superior del grupo **Code review**, abre **Code review → General** y activa **Prefer kodus-config.yml settings**. El interruptor también aparece en el alcance de directorio, pero solo el ajuste del repositorio decide si se lee el archivo. Es un ajuste web: no se puede activar desde el archivo. La barra lateral muestra entonces **kodus-config.yml applied**, **kodus-config.yml not found** o **kodus-config.yml unavailable** bajo el selector de alcance.
</Warning>

- Kody lee el archivo desde la raíz de la rama predeterminada del repositorio.
- El archivo se aplica sobre los ajustes Global y los ajustes web del repositorio. Declara solo las claves que quieras cambiar; las claves omitidas conservan su valor web.
- Los ajustes anidados se fusionan clave por clave. Una lista en el archivo, como `ignorePaths`, reemplaza la lista de la web.
- Un ajuste sobrescrito en un alcance de directorio tiene prioridad sobre el mismo ajuste en el archivo del repositorio. Consulta [Herencia y Overrides de Configuración](/es/how_to_use/code_review/configs/inheritance_overrides).
- Las claves de primer nivel desconocidas se descartan sin error. Si un ajuste parece no tener efecto, revisa la ortografía contra el ejemplo de abajo.
- `customAgents` y `knowledge` no se leen del archivo. El comentario de la revisión lo indica; configura los agentes personalizados en la aplicación.
- Los ajustes de Kody Rules y `customMessages` no se leen del archivo propio de un repositorio. Defínelos en la aplicación, o en un repositorio de [configuración centralizada](/es/how_to_use/code_review/configs/centralized_config), donde los mismos archivos pueden incluirlos.

<Accordion title="Ejemplo de kodus-config.yml">
```yaml
version: 2.0

# general
automatedReviewActive: true
reviewCadence:
    type: 'automatic' # automatic | auto_pause | manual
    timeWindow: 15 # minutes, auto_pause only
    pushesToTrigger: 3 # auto_pause only
runOnDraft: true
reviewMode: balanced # balanced | heavy
riskAssessmentActive: false
riskCriteria: []
riskReviewRouting:
    noRisk: balanced
    riskFound: heavy
byokModel: '' # empty = inherit (directory -> repository -> the organization's main model)
pullRequestApprovalActive: false
approvalPolicies: []
approvalSensitivePaths: []
isRequestChangesActive: false # not available on GitLab
showStatusFeedback: true
enableCommittableSuggestions: true # GitHub only

# review scope
ignorePaths:
    - 'yarn.lock'
    - 'package-lock.json'
    - 'package.json'
    - '.env'
    - '**/*.json'
    # ...abbreviated: the shipped default lists about 1,100 patterns in total
ignoredTitleKeywords: []
baseBranches: [] # empty = the repository's default branch only

# linked repositories — Teams / Enterprise only, up to 3
linkedRepositories: []

# what to review
reviewOptions:
    bug: true
    performance: true
    security: true
    business_logic: true
repoInstructionsEnabled: false # check changes against CLAUDE.md / AGENTS.md / .cursor/rules
suggestionControl:
    severityLevelFilter: 'medium' # low | medium | high | critical
    applyFiltersToKodyRules: false
deterministicEvidence: # beta
    ciChecks: false
    tools:
        secrets: false
        dependencies: false
# businessLogic: see Business Logic Validation
# v2PromptOverrides: see Instructions & Personality

# what Kody writes
summary:
    generatePRSummary: true
    behaviourForExistingDescription: 'replace' # replace | concatenate | complement
    behaviourForNewCommits: 'none' # none | concatenate | replace
    customInstructions: ''
```
</Accordion>

<Note>
  La fuente canónica de los valores predeterminados es
  [`default-kodus-config.yml`](https://github.com/kodustech/kodus-ai/blob/main/default-kodus-config.yml)
  en el repositorio kodus-ai.
</Note>
