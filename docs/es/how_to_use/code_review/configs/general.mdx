En la barra lateral, abre **Code review → General** (título de la página **General settings**). Las categorías
de revisión y el umbral de severidad ya no están aquí — viven en **Code review → What to review**.

## Configuración Principal

<Note>
  Kodus tiene tres niveles de configuración: Global, Repositorio y Directorio. Aprende cómo funcionan en <a href="/es/how_to_use/code_review/configs/inheritance_overrides">Herencia y Overrides de Configuración</a>.
</Note>

### Prioridad de Configuración

Puedes mantener la configuración de revisión en un archivo `kodus-config.yml` en la raíz de tu
repositorio en lugar de usar la interfaz web.

<Warning>
  **El archivo se ignora hasta que lo habilites.** Por defecto,
  `kodusConfigFileOverridesWebPreferences` es `false`, lo que significa que Kody nunca lee
  `kodus-config.yml` — hacer commit del archivo por sí solo no hace nada.

  Actívalo primero: elige el repositorio (o directorio) en el selector de alcance en la parte
  superior del grupo **Code review** de la barra lateral, abre **Code review → General** y habilita
  **kodus Config File Overrides Web Preferences** (`kodusConfigFileOverridesWebPreferences`). El
  interruptor solo existe en el alcance de repositorio y de directorio. Solo entonces el archivo
  surte efecto — la barra lateral muestra entonces un distintivo **kodus-config.yml applied**,
  **kodus-config.yml not found** o **kodus-config.yml unavailable** bajo el selector de alcance.
</Warning>

Una vez habilitado, el archivo se fusiona sobre tus ajustes web, así que solo necesitas declarar
las claves que quieras cambiar — todo lo que omitas conserva su valor de la web.

<Note>
  **Las claves desconocidas se descartan en silencio.** Cualquier clave de primer nivel que no
  forme parte del esquema actual se elimina antes de aplicar la configuración — sin error ni
  advertencia. Si un ajuste parece no tener efecto, revisa la ortografía contra el ejemplo de
  abajo.
</Note>

<Accordion title="Ejemplo de kodus-config.yml">
```yaml
version: 2.0

# general
automatedReviewActive: true
showStatusFeedback: true
kodusConfigFileOverridesWebPreferences: false
reviewCadence:
    type: 'automatic' # automatic | auto_pause | manual
    timeWindow: 15 # minutos
    pushesToTrigger: 3
pullRequestApprovalActive: false
isRequestChangesActive: false # no disponible en GitLab
runOnDraft: true
ignorePaths:
    - 'yarn.lock'
    - 'package-lock.json'
    - 'package.json'
    - '.env'
    - '**/*.json'
    # ...abreviado: el valor por defecto que se entrega incluye varios cientos de patrones más
ignoredTitleKeywords: []
baseBranches: []
enableCommittableSuggestions: true
byokModel: '' # vacío = hereda (directorio -> repositorio -> el modelo principal en AI providers)

# repositorios vinculados — solo Teams / Enterprise. Repositorios hermanos que el agente puede consultar en la revisión.
# Límite recomendado de 3; vacío = función desactivada.
linkedRepositories: []

# qué revisar: categorías
reviewOptions:
    bug: true
    performance: true
    security: true
    business_logic: true

# qué revisar: verificaciones deterministas (opcionales, beta)
deterministicEvidence:
    ciChecks: false # lee los resultados de CI que tu propio pipeline ya produjo
    tools: # una herramienta habilitada se omite igualmente si tu CI ya ejecuta una equivalente
        secrets: false # escaneo de credenciales en los archivos modificados
        dependencies: false # CVEs conocidos en dependencias que este PR añade o actualiza

# qué revisar: umbral de severidad
suggestionControl:
    applyFiltersToKodyRules: false
    severityLevelFilter: 'medium' # low | medium | high | critical

# qué escribe Kody: resumen del PR
summary:
    generatePRSummary: true
    behaviourForNewCommits: 'none'
    behaviourForExistingDescription: 'replace'
    customInstructions: ''

# kody rules
ideRulesSyncEnabled: false
kodyRulesGeneratorEnabled: true
kodyLearningExcludedReviewers: []
kodyKnowledgeApproval:
    enabled: false

# qué escribe Kody: comentarios durante la revisión + visibilidad de comentarios
customMessages:
    globalSettings:
        hideComments: false # solo GitHub
        suggestionCopyPrompt: true # no disponible en Bitbucket
    errorReviewMessage:
        status: 'off' # off | active
        content: ''
    startReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: ''
    endReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: ''
```
</Accordion>

<Note>
  Este ejemplo refleja los valores por defecto que se entregan. La fuente canónica es
  [`default-kodus-config.yml`](https://github.com/kodustech/kodus-ai/blob/main/default-kodus-config.yml)
  en el repositorio kodus-ai.
</Note>

## Comportamiento de la Revisión

### Revisión Automatizada

Kody puede revisar los PRs automáticamente cuando se abren, o solo cuando comentas `@kody start-review`.
Este es el interruptor **Enable Automated Code Review**.

<Info>
  Esto afecta solo la **revisión inicial**. Para commits posteriores, consulta Cadencia de Revisión a continuación.
</Info>

#### Cadencia de Revisión

Se muestra bajo **Enable Automated Code Review** cuando está activado. Cómo Kody gestiona las
revisiones en commits posteriores:

<Tabs>
  <Tab title="Automática">
    Revisa cada nuevo push. Feedback continuo sobre todos los cambios.
  </Tab>
  
  <Tab title="Auto-pausa">
    Pausa las revisiones durante pushes consecutivos rápidos (p. ej., 3 pushes en 15 minutos). Previene el spam durante la codificación activa.
    
    Valores predeterminados: 3 pushes / 15 minutos (**Pushes to trigger pause** / **Time window (minutes)**)
  </Tab>
  
  <Tab title="Manual">
    Solo ejecuta revisiones de seguimiento cuando comentas `@kody start-review`.
  </Tab>
</Tabs>

### Flujo de Trabajo del PR

#### Auto-aprobar PRs
**Enable Pull Request Approval** — Kody aprueba los PRs cuando no se encuentran problemas.

**Plataformas:** GitHub, GitLab, Bitbucket, Azure Repos, Forgejo

#### Solicitar Cambios
**Enable changing status of Review to 'Request Changes'** — Kody solicita cambios cuando
encuentra problemas críticos.

**Plataformas:** GitHub, Bitbucket, Azure Repos, Forgejo (el interruptor se oculta cuando GitLab es
tu única plataforma conectada)

### Condiciones de Omisión

**Ignored files:** Patrones glob (p. ej., `**/*.js`) para los archivos que Kody omite. El campo
muestra algunos patrones como chips; haz clic en **Edit** para abrir el modal **Ignored files**,
donde se valida la sintaxis glob de cada patrón nuevo y la caja **Test a file** te indica si una
ruta se ignoraría (y por qué patrón) o se revisaría. **Apply** solo actualiza el campo — no se
guarda nada hasta que haces clic en **Save settings**. Predeterminados: `yarn.lock`,
`package-lock.json`, `package.json`, `.env`, `**/*.json`, más una larga lista de archivos de build,
binarios y de IDE.

**Ignore title keywords:** Omite PRs con palabras clave específicas (sin distinción entre mayúsculas y minúsculas, máx. 100 caracteres)

**Ramas Base:** Restringe *qué* ramas de destino se revisan.

<Info>
  **Vacío (el valor por defecto) significa que se revisa cualquier rama de destino** — no existe
  una lista integrada de `dev`/`release`/`master`. Añade entradas solo cuando quieras *acotar* el
  alcance: con la lista no vacía, Kody revisa únicamente los PRs dirigidos a esas ramas (la rama
  por defecto de tu repositorio siempre se incluye).

  Las entradas se comparan con la rama de **destino** del PR y admiten una sintaxis propia:

  | Entrada | Coincide con |
  | --- | --- |
  | `main` | PRs dirigidos exactamente a `main` |
  | `release/*` | PRs dirigidos a cualquier rama bajo `release/` (`*` es comodín de un nivel) |
  | `=main` | Coincidencia exacta, igual que escribir `main` |
  | `!staging` | Excluye PRs dirigidos a `staging` |
  | `contains:hotfix` | Compara con la rama de **origen** — cualquier PR cuya rama de origen contenga `hotfix` |

  Cuando varias entradas coinciden, gana la más específica. Cada entrada está limitada a 100
  caracteres, solo puede usar `a-z A-Z 0-9 / * - _ ! = :`, y `**` no está permitido.
</Info>

**PRs en borrador:** **Enable Running on Draft Pull Requests** (`runOnDraft`) está activado por
defecto, así que los borradores se revisan. Desactívalo para omitirlos hasta que el PR se marque
como listo.

### Otros ajustes en esta página

- **Show Status Feedback** — Kody muestra feedback de estado (reacción con emoji o comentario)
  cuando una revisión se omite o se bloquea.
- **Enable committable suggestions** (Alpha, solo GitHub) — sugerencias que se pueden aplicar
  directamente como commits.
- **Code review model** (solo en alcance de repositorio y directorio, visible una vez configurado
  un proveedor de IA) — el modelo con el que revisa este alcance; por defecto se hereda
  (`byokModel`).
- **Kody Language** (solo Global) — el idioma que Kody usa en las respuestas de code review.

## Categorías de revisión (antes Tipos de Análisis)

Kody revisa en cuatro categorías. Las categorías ya no están en **General**: activa o desactiva
cada una con su interruptor en **Code review → What to review**, o mediante `reviewOptions` en
`kodus-config.yml`.

- **Bug** — errores de lógica, condiciones de carrera, desreferencias nulas, casos límite y comportamiento incorrecto.
- **Security** — vulnerabilidades, inyección, problemas de autenticación, exposición de datos y secretos.
- **Performance** — consultas N+1, asignaciones en el hot path, falta de caché y E/S bloqueante.
- **Business Logic** — valida la implementación contra reglas de negocio, requisitos y criterios
  de aceptación vinculados al PR. Consulta
  [Validación de Lógica de Negocio](/es/how_to_use/code_review/business_logic_validation).

<Note>
  Kody Rules **no** es una de estas categorías — siempre se ejecutan, con independencia de
  `reviewOptions`. Consulta [Kody Rules](/es/how_to_use/code_review/configs/kody_rules).
</Note>
