## Descripción General

Personaliza los mensajes que Kody envía al comienzo y al final de las revisiones de código. Esta función te permite adaptar el estilo de comunicación y agregar contexto o instrucciones específicas para tu equipo.

## Comportamiento Predeterminado

Cuando no has personalizado ningún mensaje, Kody funciona de la siguiente manera:

1. **Mensaje Inicial**: Kody envía un mensaje estándar de inicio de revisión
2. **Sugerencias**: Kody proporciona todas las sugerencias de revisión de código
3. **Mensaje Final**: Kody actualiza el mensaje inicial con un resumen de la revisión

## Comportamiento con Mensajes Personalizados

Una vez que editas el mensaje de inicio o de fin de revisión por primera vez, el comportamiento de Kody cambia a:

1. **Mensaje Inicial**: Kody envía tu mensaje de inicio de revisión personalizado
2. **Sugerencias**: Kody proporciona todas las sugerencias de revisión de código
3. **Mensaje Final**: Kody envía tu mensaje de fin de revisión personalizado (sin actualizar el mensaje inicial)

Esto crea una línea de tiempo completa: **Mensaje Inicial → Sugerencias → Mensaje Final**

## Opciones de Configuración de Mensajes

### Comportamiento del Mensaje

Usa el menú desplegable **Comportamiento del mensaje** para decidir cuándo Kody debe publicar tus mensajes
de inicio y fin personalizados:

- **Importante:** Los mensajes solo se envían cuando realmente se ejecuta una revisión.  
  Si tu cadencia de revisión es **Manual**, los mensajes se publican solo cuando alguien ejecuta `@kody start-review`.

- **En cada push**: Kody publica el mensaje de inicio cuando se abre el pull request y
  repite el par inicio/fin después de cada nuevo push **que active una revisión**.
  Esto ocurre automáticamente solo cuando la cadencia es **Automática** o **Auto-pausa**.
- **Solo al abrir**: Kody envía los mensajes de inicio y fin solo una vez, justo
  después de la primera ejecución de revisión. Si la cadencia es **Manual**, la primera ejecución de revisión es
  cuando llamas a `@kody start-review`. Los pushes futuros solo agregan sugerencias de revisión
  más la reacción habitual para que los autores sepan que la revisión volvió a ejecutarse.
- **Desactivado**: Los mensajes personalizados están deshabilitados. Kody aún ejecuta la revisión y publica
  sugerencias, pero no se envían mensajes de inicio ni de fin.

Cuando el comportamiento es `En cada push` o `Solo al abrir`, Kody usa las
plantillas que hayas completado. Si solo personalizas el mensaje de inicio, solo ese
mensaje se envía; lo mismo aplica para el mensaje de fin. Esto mantiene la línea de tiempo familiar de
**Mensaje Inicial → Sugerencias → Mensaje Final** siempre que el comportamiento permita
publicar mensajes.

**Ejemplo (cadencia Manual)**  
PR abierto → sin mensaje aún  
`@kody start-review` → mensaje de inicio → sugerencias → mensaje de fin

## Contexto Dinámico

Puedes enriquecer tus mensajes personalizados con contexto dinámico usando el botón **Agregar Contexto**. Esto te permite incluir:

### changedFiles

Un resumen de los archivos modificados, mostrando adiciones y eliminaciones por archivo. Proporciona un desglose detallado de lo que se modificó en el pull request.

### changeSummary

Un resumen exhaustivo de todos los cambios en el pull request, ofreciendo una visión general del alcance completo de las modificaciones.

### reviewOptions

Un reflejo de la configuración de revisión del equipo, mostrando qué tipos de análisis están habilitados o deshabilitados para la revisión.

### reviewCadence

Proporciona la política exacta de revisiones de seguimiento para que los autores sepan qué sucede después
de la primera revisión automatizada:

- **Automática**: Kody revisa cada push tan pronto como llega.
- **Auto-pausa**: Kody revisa los pushes automáticamente, pero si detecta una
  "ráfaga de pushes" (por ejemplo, 3 pushes en 15 minutos, según tus
  umbrales) pausa las revisiones de seguimiento hasta que las reanudes. El contexto de cadencia
  incluye los límites de pushes y tiempo para que el equipo sepa cuándo puede
  activarse la pausa.
- **Manual**: Kody espera a que alguien ejecute `@kody start-review` antes de hacer
  otra revisión.

### reviewScope

Muestra qué nivel de configuración —global, repositorio o directorio— se usó para
revisar este pull request, para que los autores sepan qué ajustes se aplicaron.

### agentPrompt

<Note>
  **Solo en el mensaje de fin de revisión.** Agrupa las sugerencias de los
  comentarios de línea de la revisión, que no existen hasta que la revisión se
  ejecuta, por lo que no se ofrece en el mensaje de inicio.
</Note>

Agrupa todas las sugerencias de la revisión en un único bloque de prompt para
copiar y pegar (mostrado como un desplegable **Open Agent Prompt**). Pégalo en tu
agente de código para aplicar todas las correcciones de la revisión de una vez.

<Info>
  Estas variables de contexto se completarán automáticamente con los datos reales
  de tu pull request cuando Kody envíe el mensaje.
</Info>

<Note>
  En `kodus-config.yml` estos tokens se escriben con prefijo `@` — `@changedFiles`,
  `@changeSummary`, `@reviewOptions`, `@reviewCadence`, `@reviewScope`, `@agentPrompt` —
  en cualquier posición dentro del `content` del mensaje. El botón **Add Context** inserta
  los mismos tokens por ti en la interfaz web.
</Note>

## Mensaje de error

Aparte del par inicio/fin, puedes añadir tu propio texto al comentario que Kody publica cuando
una revisión **falla** — por ejemplo cuando no hay proveedor BYOK configurado, o el proveedor
rechazó la petición.

- **Off** (por defecto) — Kody publica su mensaje de error estándar sin cambios.
- **Active** — tu texto se añade debajo del mensaje de error estándar.

Úsalo para dirigir a la gente al responsable interno o al runbook, en lugar de dejarles un fallo
genérico:

```yaml
customMessages:
    errorReviewMessage:
        status: 'active' # off | active
        content: |
            ¿Fallan las revisiones? Escribe a #platform-eng — la clave de la API de Kodus es nuestra.
```

Dejar `content` vacío mantiene el mensaje de error por defecto sin cambios.

## Ajustes globales

Dos toggles que aplican a todos los comentarios de Kody, no solo a los mensajes personalizados:

| Ajuste | Por defecto | Qué hace |
| --- | --- | --- |
| `hideComments` | `false` | Publica cada mensaje de revisión como comentario oculto/minimizado. Se muestra en la interfaz como **Post as hidden comment**. **Solo GitHub** — el toggle se oculta en otras plataformas. |
| `suggestionCopyPrompt` | `true` | Añade a las sugerencias la opción de copiar como prompt, para pegarlas en un agente de código. **No disponible en Bitbucket.** |

```yaml
customMessages:
    globalSettings:
        hideComments: false # solo GitHub
        suggestionCopyPrompt: true # no disponible en Bitbucket
```
