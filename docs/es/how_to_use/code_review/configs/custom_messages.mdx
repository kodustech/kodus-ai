title: "Mensajes Personalizados"
description: "Edita los comentarios que Kody publica cuando una revisión empieza, termina o falla, y cómo aparecen sus comentarios en el pull request."
---

Abre **Code review → What Kody writes**. Los mensajes están en la sección **Comments during the review**, con una pestaña por mensaje: **Review starts**, **Review ends** y **Review fails**. Cada pestaña tiene una caja **Message** y un menú **Reset to…**. El menú ofrece **Inherited message** en el alcance de repositorio y de directorio, y **Default message** en Global.

Los mensajes se pueden definir en los alcances Global, Repository y Directory.

## Cómo aparecen los mensajes

Kody publica el mensaje de inicio cuando empieza una revisión. Cuando la revisión termina, edita ese mismo comentario para convertirlo en el mensaje de fin. Las sugerencias se publican como comentarios de revisión entre ambos.

- **Inicio y fin publicados:** un solo comentario, que muestra primero el mensaje de inicio y el mensaje de fin cuando la revisión termina.
- **Inicio no publicado en esta ejecución:** el mensaje de fin se publica como un comentario nuevo tras la revisión.
- **Fin en Never:** el comentario de inicio se queda como está, también tras una revisión fallida. La reacción 😕 es entonces la única señal del fallo.
- **La revisión falla:** Kody publica su comentario de error predeterminado en lugar de tu mensaje de fin, con el texto de **Review fails** debajo.

En GitHub, cuando empieza una nueva revisión, Kody colapsa el comentario de la revisión anterior.

## Post this message

En **Review starts** y **Review ends**, el selector **Post this message** define cuándo se publica ese mensaje. Cada mensaje tiene su propio ajuste.

- **On every push** (`every_push`, predeterminado) — se publica en cada ejecución de revisión: cuando se abre el pull request y después de cada push que activa una revisión.
- **Only when the PR opens** (`only_when_opened`) — se publica una sola vez, en la primera ejecución de revisión.
- **Never** (`off`) — no se publica. El texto se conserva, y la caja **Message** y **Add context** quedan deshabilitados. Kody sigue ejecutando la revisión y publicando sugerencias.

Los mensajes se publican solo cuando se ejecuta una revisión. Con una cadencia de revisión **Manual** y **Automated code review** activado, la primera revisión se ejecuta cuando se abre el pull request; los pushes posteriores no publican nada hasta que alguien comenta `@kody start-review`.

## Add context

El menú **Add context** junto a **Message** inserta un token que Kody reemplaza con datos reales del pull request.

| Elemento del menú | Token | Qué añade |
| --- | --- | --- |
| **Changed files** | `@changedFiles` | Una tabla colapsable de los archivos modificados, con estado, adiciones y eliminaciones. |
| **Changes summary** | `@changeSummary` | Totales de archivos, líneas añadidas, líneas eliminadas y cambios. |
| **Review options** | `@reviewOptions` | Qué categorías de revisión están activadas o desactivadas. |
| **Review cadence** | `@reviewCadence` | Cómo funcionan las revisiones de seguimiento: automática, auto-pausa con sus límites, o manual. |
| **Review scope** | `@reviewScope` | Qué nivel, global, de repositorio o de directorio, se usó para esta revisión. |
| **Agent Prompt** | `@agentPrompt` | Todas las sugerencias de la revisión como un único prompt para pegar en un agente de programación, en un bloque colapsable **Open Agent Prompt**. |

`@agentPrompt` se ofrece solo en **Review ends**, porque su contenido existe únicamente después de la revisión.

## Mensaje Review fails

Escribe texto en la pestaña **Review fails** para añadirlo debajo del comentario que Kody publica cuando una revisión falla, por ejemplo cuando no hay ningún proveedor de IA configurado o el proveedor rechazó la solicitud. Úsalo para dirigir a la gente a un responsable interno o a un runbook.

No hay un interruptor para este mensaje: el propio texto es el interruptor. Vacío (el valor predeterminado) mantiene el comentario de error estándar de Kody tal como está.

## Visibilidad de comentarios

La sección **Comment visibility** tiene dos ajustes.

| Ajuste | Predeterminado | Qué hace |
| --- | --- | --- |
| **Post as hidden comment** (`hideComments`) | Desactivado | El comentario que contiene los mensajes **Review starts** y **Review ends** se publica colapsado, como obsoleto, para que la conversación del pull request se mantenga corta. Las sugerencias en línea y los comentarios a nivel de PR no se colapsan. Solo GitHub; el interruptor se oculta cuando GitHub no está conectado. |
| **Add a copyable prompt to each suggestion** (`suggestionCopyPrompt`) | Activado | Cada sugerencia incluye un prompt que el desarrollador puede pegar en un asistente de IA para aplicar la corrección. En Bitbucket el prompt se publica como respuesta en el mismo hilo; con el ajuste desactivado, los comentarios de Bitbucket no muestran la corrección. |

## YAML

Los mensajes se almacenan como `customMessages` en los archivos `kodus-config.yml` de un repositorio de [configuración centralizada](/es/how_to_use/code_review/configs/centralized_config). Un `kodus-config.yml` en la raíz de un repositorio revisado no los cambia; usa la aplicación.

```yaml
customMessages:
    startReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: |
            Review started. @changedFiles
    endReviewMessage:
        status: 'every_push' # every_push | only_when_opened | off
        content: |
            Review finished. @changeSummary
    errorReviewMessage:
        status: 'active' # off | active; a review reads only content
        content: |
            Reviews failing? Ping #platform-eng.
    globalSettings:
        hideComments: false
        suggestionCopyPrompt: true
```
