## Qué reglas aplica una revisión

Cada revisión aplica las reglas activas de tres ámbitos: **Global → Repositorio → Directorio**.

- Las reglas **Global** se aplican a todos los repositorios.
- Las reglas de **Repositorio** se aplican a todos los pull requests de ese repositorio.
- Las reglas de **Directorio** se aplican cuando el pull request se revisa con los ajustes de ese ámbito de directorio, lo que ocurre cuando toca exactamente un ámbito de directorio. Las reglas de los demás ámbitos de directorio del repositorio no se aplican.
- Un pull request que no toca ningún ámbito de directorio, o que toca dos o más, se revisa con los ajustes del repositorio. En ese caso, las reglas de **todos** los ámbitos de directorio del repositorio también se aplican, a todos los archivos del pull request.

Una regla escrita en un ámbito padre siempre la heredan los ámbitos que están por debajo. Una regla que aparece en dos ámbitos con instrucciones idénticas se ejecuta una sola vez.

<Note>
  El interruptor **Inheritable** y **Override and disable for this scope** cambian cómo se listan las reglas en la página **Kody Rules**. No cambian qué reglas aplica una revisión. Consulta más abajo.
</Note>

## En la aplicación

En la página **Kody Rules**, las reglas heredadas de ámbitos superiores se listan junto a las reglas propias del ámbito, marcadas con el ámbito del que provienen. Allí son de solo lectura: abre la regla y usa **View**, o ve al ámbito donde se creó para editarla. **Filters → View** muestra u oculta **Inherited from Global**, **Inherited from Repository** y **Disabled Rules**.

### Inheritable

En una regla de cualquier ámbito, abre **Advanced settings** en el diálogo de la regla y desactiva **Inheritable** (activado por defecto).

- La regla deja de listarse como heredada en los ámbitos que están por debajo.
- Una revisión sigue aplicándola en todos los ámbitos, como se describió arriba.

### Override and disable for this scope

En un ámbito de repositorio o de directorio, abre una regla heredada (**View**) y activa **Override and disable for this scope**.

- La regla aparece como **Disabled** en ese ámbito, y se oculta cuando **Disabled Rules** está desmarcado en **Filters → View**.
- No aparece como deshabilitada en los ámbitos inferiores, que conservan su propio ajuste.
- Una revisión sigue aplicando la regla.

Para que una regla deje de aplicarse, pausala o elimínala en el ámbito donde se creó.

## Configuración centralizada

Un archivo de regla en un repositorio de [configuración centralizada](/es/how_to_use/code_review/configs/centralized_config) puede llevar los mismos ajustes:

```yaml
inheritance:
  inheritable: true
  exclude: []   # repository or directory IDs
  include: []   # repository or directory IDs
```

`inheritable` y `exclude` se comportan como se describió arriba. `include` no tiene control en la aplicación ni efecto en una revisión; una regla con una lista `include` no vacía no se muestra en la lista de heredadas.
