Kody evalúa el PR completo. El [modo de revisión](/es/how_to_use/code_review/configs/routing) y los agentes condicionados por el riesgo usan el resultado para decidir cómo revisar. Con la [aprobación automática](/es/how_to_use/code_review/configs/auto_approve) activada, el resultado también puede impedir la aprobación.

## Activa la evaluación de riesgo

1. Abre **Code review → Risk assessment**.
2. Activa **Risk assessment** y haz clic en **Save settings**.

La evaluación de riesgo está desactivada por defecto. Puede ejecutarse con la aprobación automática desactivada.

## Resultados

- **Risk found:** el PR cae dentro de al menos una [regla de riesgo](#reglas-de-riesgo) activada. Los agentes condicionados por riesgo pueden ejecutarse, Routing usa su modo de riesgo encontrado y la aprobación automática se bloquea. El comentario de aprobación nombra las reglas.
- **No risk found:** Routing usa su modo sin riesgo. La aprobación sigue necesitando una revisión limpia y una política que coincida.
- **Unavailable:** Routing usa el modo de revisión predeterminado configurado. La aprobación automática se bloquea, y los agentes que requieren riesgo confirmado no se ejecutan automáticamente. El comentario de aprobación indica el motivo, por ejemplo cuando el proveedor Git no devolvió el diff de un archivo de código.

Con la evaluación desactivada, Routing usa un único modo configurado para todos los PRs. Los agentes condicionales no se ejecutan sin riesgo confirmado; los comandos manuales explícitos de agentes omiten esa condición.

Una evaluación cubre un head, un título y una descripción de PR. Un nuevo commit mantiene en espera la aprobación automática hasta su revisión. Cuando solo cambian el título, la descripción o los ajustes de riesgo, Kody vuelve a evaluar los mismos commits antes de decidir sobre la aprobación.

## Vista previa en un PR

**Preview on a PR** abre un panel lateral. Elige un repositorio conectado y un número de PR para probar las reglas actuales, incluidas las ediciones sin guardar. Usa el modelo de evaluación de riesgo configurado y no publica un comentario ni aprueba el PR.

## Reglas de riesgo

Kody encuentra riesgo cuando un PR cae dentro de una regla activada. Kodus incluye estas reglas, todas activadas:

- `kodus-security` **Security and permissions:** autenticación, autorización, permisos, aislamiento entre tenants, validación de entradas o cualquier verificación que proteja datos o acciones, incluido un nuevo endpoint, handler o job que lea o modifique datos sin la protección que tienen sus vecinos.
- `kodus-money` **Money, billing and licensing:** pagos, precios, cargos, créditos, facturas, suscripciones o licencias.
- `kodus-data` **Stored data and migrations:** migraciones de datos o de esquema, eliminar o reescribir datos almacenados, o la forma de los datos persistidos y las consultas que los leen o escriben.
- `kodus-infrastructure` **Secrets and infrastructure:** secretos, credenciales, infraestructura, red o el entorno de ejecución.
- `kodus-ci-build` **CI, build, release and dependencies:** configuración de CI, build, release o despliegue, o la versión de una dependencia o herramienta.
- `kodus-shared-contract` **Shared contracts and public interfaces:** aquello de lo que dependen otro código, usuarios o integraciones, como los resultados de una API pública, una función de biblioteca o una CLI.
- `kodus-concurrency` **Concurrency, retries, queues and caching.**
- `kodus-ai-behavior` **Production prompts and model behavior:** los prompts, la elección de modelo o los ajustes de modelo con los que se ejecuta una funcionalidad en producción.
- `kodus-broad-change` **Broad or mixed changes:** una reescritura amplia de rutas centrales, o un PR que mezcla varios cambios con consecuencias.

Puedes desactivar una regla de Kodus o editar su nombre, sus instrucciones o sus filtros de archivos. Tus ediciones reemplazan la versión de Kodus hasta que haces clic en **Reset**; lo que no cambies sigue las actualizaciones de Kodus. Agrega tus propias reglas para dar contexto del equipo, como las consecuencias de cambiar permisos de cuentas o eliminar datos de clientes.

Una regla tiene un nombre, instrucciones, un interruptor y patrones de archivos incluidos/excluidos opcionales. Los ajustes guardan hasta 50 entradas, contando tus reglas y las reglas de Kodus que cambiaste. Un nombre admite hasta 120 caracteres y las instrucciones hasta 4.000; en un archivo, cada `id` debe ser único. Una regla con filtros de archivos se aplica solo a los cambios en los archivos que coinciden; Kody sigue evaluando el resto del PR con las demás reglas. Cuando ninguna regla activada se aplica a los archivos modificados, Kody no encuentra riesgo sin llamar al modelo, así que una revisión limpia puede aprobar.

Las instrucciones de riesgo guardadas antes de que existieran las reglas de riesgo aparecen como **Team context**. Kody las lee como contexto y no como una regla: pueden decir que un cambio necesita a una persona o que no la necesita. Cuando piden a una persona, el comentario de aprobación nombra **Team context**.

La evaluación lee el diff, el título y la descripción del PR, y el historial de correcciones de bugs de las áreas modificadas. Un historial ausente es información desconocida, no evidencia de seguridad.

## YAML

Activa **Prefer kodus-config.yml settings** en **Code review → General** (ámbito de repositorio) antes de usar los archivos de configuración del repositorio.

```yaml
riskAssessmentActive: true
riskCriteria:
  - id: kodus-shared-contract # A Kodus rule, turned off
    enabled: false
  - id: kodus-ci-build # A Kodus rule, limited to release workflows
    enabled: true
    includedFiles:
      - '.github/workflows/release*.yml'
  - id: access-control
    name: Access control
    enabled: true
    instructions: 'Check whether permission changes expose data across accounts. Distinguish them from equivalent refactors.'
    includedFiles:
      - 'src/access/**'
    excludedFiles:
      - '**/*.test.ts'
```

Una regla de Kodus se lista por su `id`, solo con lo que cambias. Una entrada cuyo `id` no coincide con ninguna regla de Kodus necesita un nombre e instrucciones. `riskCriteria: []` aplica las reglas de Kodus tal como vienen. Un repositorio o directorio que define `riskCriteria` reemplaza la lista que hereda, así que enumera ahí todos los cambios que necesita, incluidas las reglas propias de la organización. `kodus config remote risk-rules .` lista las reglas vigentes, con sus ids. Para detener la evaluación, define `riskAssessmentActive: false`.

Una configuración que nunca definió **Risk assessment** mantiene su comportamiento de riesgo de aprobación existente hasta que cambies este ajuste. Activar o desactivar la aprobación automática no cambia el interruptor **Risk assessment**.
