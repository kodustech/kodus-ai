title: "Resumen de PR"
description: "Haz que Kody escriba la descripción del pull request y elige qué ocurre con una descripción existente y con los nuevos commits."
---

Kody puede escribir una descripción de lo que cambia un pull request. Abre **Code review → What Kody writes**; los ajustes están en la sección **PR summary**. Se pueden definir en el ámbito Global, de Repositorio y de Directorio.

La vista previa de la página (**Show preview** / **Hide preview**) muestra cómo queda el resumen en un pull request de ejemplo.

## Escribir un resumen

Activa **Write a summary on every pull request**. Está activado por defecto. Si lo desactivas, Kody no escribe ningún resumen y las opciones de abajo quedan deshabilitadas.

Kody escribe el resumen en el idioma definido en **Kody Language**, dentro de [General](/es/how_to_use/code_review/configs/general).

## Cuando el PR ya tiene una descripción

Elige qué hace Kody con una descripción escrita por el autor:

- **Replace** (predeterminado) — escribe una descripción nueva desde cero.
- **Concatenate** — agrega el resumen al final de la descripción existente.
- **Complement** — lee la descripción existente y escribe una que destaca solo lo que es nuevo o relevante.

Replace y Complement mantienen al inicio de la nueva descripción las líneas de la anterior que enlazan una tarea, como `Closes #12`, `AB#12` o un enlace a un tracker. Concatenate deja toda la descripción en su lugar.

El texto de Kody queda entre dos marcadores de comentario ocultos, de modo que una nueva ejecución actualiza ese bloque en vez de apilar uno nuevo.

## Cuando llegan nuevos commits

Elige qué ocurre con el resumen de Kody cuando se envían commits después de abrir el pull request:

- **Do nothing** (predeterminado) — el resumen se queda como está.
- **Concatenate new summary** — se agrega al bloque existente de Kody un resumen de los nuevos commits.
- **Replace Kody's summary** — el bloque de Kody se reemplaza por un resumen de todo el pull request.

Solo cambia el bloque de Kody. El texto escrito por el autor se mantiene.

## Instrucciones del resumen

El campo opcional **Summary instructions** le indica a Kody en qué debe enfocarse el resumen o qué debe dejar fuera. Los chips de **Examples** agregan líneas listas para usar.

- "Focus on security changes and performance impacts"
- "Summarize concisely, highlighting modified public APIs"

Las instrucciones también pueden referirse a lo que encontró la revisión, por ejemplo para mencionar la severidad más alta. Las instrucciones pueden referenciar archivos del repositorio; consulta [External References](/es/how_to_use/code_review/configs/custom_prompts#referencias-externas).

**Try on a real PR** ejecuta los ajustes actuales sobre uno de tus pull requests. Está disponible cuando el resumen está activado y puedes leer pull requests. La vista previa se ejecuta antes de cualquier revisión, por lo que no muestra hallazgos de la revisión.

<Note>
  En un pull request muy grande que no cabe en el contexto del modelo en unas pocas pasadas, Kody omite el resumen.
</Note>

Una descripción que supera el límite del proveedor se corta con una nota de truncamiento: 4.000 caracteres en Azure DevOps, 32.768 en Bitbucket y 65.536 en GitHub. En Azure DevOps, Kody mantiene su resumen corto para dejar espacio a la descripción existente.

## YAML

```yaml
summary:
    generatePRSummary: true
    behaviourForExistingDescription: 'replace' # replace | concatenate | complement
    behaviourForNewCommits: 'none' # none | concatenate | replace
    customInstructions: ''
```

El archivo solo se lee cuando **Prefer kodus-config.yml settings** está activado. Consulta [General](/es/how_to_use/code_review/configs/general#prioridad-de-configuración).
