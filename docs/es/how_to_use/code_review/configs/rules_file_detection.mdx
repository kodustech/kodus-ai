Archivos como `CLAUDE.md`, `AGENTS.md`, `.cursor/rules` y `.github/copilot-instructions.md` les dicen a los agentes de código cómo trabaja tu equipo. No son política de revisión, así que Kodus nunca los convierte en Kody Rules. Cuando activas esta opción, Kody lee los que cubren los archivos que cambia un pull request y señala los cambios que incumplen lo que dicen.

Para que una convención sea una regla de revisión obligatoria, escríbela como una [Regla del Repositorio](/es/how_to_use/code_review/configs/repository_rules) en `.kody/rules`.

## Cómo activarlo

- **Durante el onboarding**, el paso **Teach Kody how your team builds software** muestra los archivos para agentes de código encontrados en cada repositorio seleccionado y pregunta si Kody debe usarlos. Está desactivado a menos que lo actives.
- **Más adelante**, elige **Global** o un repositorio en el selector de alcance en la parte superior del grupo **Code review**, abre **Kody Rules**, haz clic en **Configuration** y activa **Use coding-agent instructions in reviews**. El valor global es el predeterminado para todos los repositorios que no definan el suyo.

La opción se guarda como `ideRulesSyncEnabled` en la configuración de revisión de código (y en `kodus-config.yml`).

## Archivos que lee Kody

### Cursor
- `.cursorrules`
- `.cursor/rules/**/*.mdc`

### GitHub Copilot
- `.github/copilot-instructions.md`
- `.github/instructions/**/*.instructions.md`

### Agentes (convención agents.md)
- `AGENTS.md`, `.agents.md`, `.agent.md`
- `.agents/rules/**`

### Claude
- `CLAUDE.md`

### Windsurf
- `.windsurfrules`

### Sourcegraph Cody
- `.sourcegraph/**/*.rule.md`

Los archivos de configuración de herramientas (`.claude/settings.json`, `.opencode.json`, `.aider.conf.yml`, `.aiderignore`) se reconocen pero nunca se leen, porque no contienen instrucciones contra las que revisar el código.

## Cómo los usa una revisión

- **Solo los archivos que cubren el cambio.** Un archivo en la raíz del repositorio cubre todos los archivos. Un archivo anidado como `services/billing/CLAUDE.md` cubre `services/billing/**`. Una regla de Cursor con `globs:` (y sin `alwaysApply: true`) o un archivo de Copilot con `applyTo:` cubre solo los archivos que declara.
- **Se leen desde la rama de destino del pull request.** Un pull request se revisa con las instrucciones ya fusionadas en ella; los cambios que haga en las instrucciones solo cuentan después de fusionarse.
- **Con límites.** Como máximo 8 archivos y 64 KB por revisión, primero los archivos de la raíz; un archivo más largo se recorta. La revisión registra en el log lo que quedó fuera.
- **Los hallazgos llevan la etiqueta Repo Instruction.** Kody reporta uno solo cuando la instrucción aplica al archivo modificado y la línea que la incumple fue agregada o modificada por el pull request. El comentario cita la instrucción y nombra el archivo.
- **Nunca son instrucciones para Kody.** Los archivos se tratan como texto del repositorio contra el que se revisa el diff. Cualquier cosa que le pidan al revisor se ignora, y nunca cambian cómo se evalúan los bugs ni los problemas de seguridad o rendimiento.

<Note>
El modo de revisión profunda ejecuta revisores separados de bugs, seguridad y rendimiento, y no lee las instrucciones para agentes de código.
</Note>

## Reglas importadas antes de este cambio

Las versiones anteriores de Kodus convertían estos archivos en Kody Rules. Esas reglas se conservan pero quedan **congeladas**: ya no se actualizan cuando cambia el archivo y llevan el origen **Agent file** en la página de Kody Rules. El chip **rules from coding-agent files** filtra la lista para mostrar solo esas reglas, así puedes pausarlas o eliminarlas, o mover a `.kody/rules` las convenciones que quieras que se apliquen.

Las reglas que el onboarding importó desde archivos para agentes de código o manifiestos de dependencias sin que nadie las eligiera se movieron a **Pending review**. Aprueba las que quieras conservar.

`@kody-sync` ya no hace nada: los archivos de Kody Rules siempre se sincronizan y los archivos para agentes de código nunca se convierten en reglas. `@kody-ignore` sigue excluyendo un archivo de Kody Rule de la sincronización.

## Verificarlo en self-hosted

Los logs del worker llevan un marcador grep-able en cada revisión que lee instrucciones para agentes de código:

```bash
docker logs kodus_worker 2>&1 | grep "\[repo-instructions\]"
```

Cada línea muestra cuántos archivos de instrucciones se encontraron, cuáles se leyeron, cuántos bytes y si algo quedó fuera.
