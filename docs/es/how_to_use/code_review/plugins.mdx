Un plugin es un servidor remoto de Model Context Protocol (MCP) conectado a tu workspace: un gestor de tickets, una wiki, un monitor de errores. Kody lee de él, y actúa sobre él solo cuando se lo pides.

| Dónde | Qué ocurre |
| --- | --- |
| Un comentario que menciona a `@kody` | Kody llama a un plugin instalado y responde en el mismo hilo. Cambia algo, como mover un ticket o editar una regla, solo cuando tu comentario lo pide. |
| [Validación de lógica de negocio](/es/how_to_use/code_review/business_logic_validation) | Kody lee de tu gestor de tareas la tarea que referencia un pull request. |
| [Agentes personalizados](/es/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp) | Un agente lee de los plugins que activas para él. Solo herramientas de lectura. |

## Página de Plugins

Abre **Plugins** en la barra lateral. Solo los Owners pueden instalar o cambiar plugins; los Billing Managers, Repo Admins y Contributors pueden verlos. Cada tarjeta muestra un plugin y, una vez conectado, **Installed**, **Default** o **Locked**. En una instalación self-hosted, la página necesita el [MCP Manager](/es/how_to_deploy/deploy_kodus/mcp_manager).

| Plugin | Qué puede leer Kody | Inicio de sesión |
| --- | --- | --- |
| **Git Issues** | Los issues del tracker de tu repositorio (GitHub, GitLab, Bitbucket o Forgejo), a través de tu conexión de Git | Ninguno |
| **Linear** | Issues, proyectos y ciclos | OAuth o API key |
| **Atlassian Rovo** | Jira y Confluence | OAuth o API token |
| **Notion** | Páginas, bases de datos y docs | OAuth |
| **Sentry** | Proyectos, issues y eventos | OAuth |
| **Fireflies** | Transcripciones de reuniones, resúmenes y action items | API key |
| **Kodus Docs** | La documentación de Kodus | Ninguno |
| **Exa Search** | Búsqueda web y de código | Ninguno |
| **Kodus OSV** | Vulnerabilidades conocidas de paquetes | Ninguno |

**Kodus MCP** está conectado en todos los workspaces (**Default**). Lee repositorios, pull requests, commits, archivos y diffs de tu proveedor de Git, y gestiona Kody Rules, memorias e issues de Kody. Siempre está activo y no cuenta para el límite del plan Free que se describe más abajo.

## Instalar un plugin

<Steps>
  <Step title="Abre el plugin">
    Haz clic en su tarjeta.
  </Step>
  <Step title="Conéctalo">
    Un plugin con inicio de sesión lo pide primero: haz clic en **Authenticate with** el plugin (OAuth), o completa los campos y haz clic en **Connect** (API key o token). Se instala en cuanto se conecta. Kody empieza con las herramientas que el plugin marca como de solo lectura, o con todas las herramientas cuando no marca ninguna.

    Un plugin sin inicio de sesión va directo a **Selected tools**. Elige las herramientas que Kody puede usar y haz clic en **Install plugin**.
  </Step>
  <Step title="Cambia las herramientas más adelante">
    Abre un plugin instalado, cambia **Selected tools** y haz clic en **Update Tools**. **Reset Authentication** lo desconecta.
  </Step>
</Steps>

Las herramientas cuyos nombres sugieren una acción destructiva (delete, remove, archive) se marcan con una advertencia y empiezan sin seleccionar. Para instalar con una seleccionada, confírmalo en la casilla al final. Kody puede usar cualquier herramienta que selecciones, así que selecciona solo lo que necesita.

<Note>
  En el plan Free (y en self-hosted sin licencia), Kody ejecuta hasta 3 plugins instalados a la vez, los más antiguos primero. Un banner en la página Plugins nombra los que omite, y sus tarjetas muestran **Locked**. **Git Issues** no se puede instalar cuando tu proveedor de código es Azure Repos o Bitbucket Data Center, que no tienen un issue tracker nativo.
</Note>

## Plugins personalizados

Agrega tu propio servidor MCP cuando el catálogo no cubra una herramienta. El servidor debe ser accesible desde Kodus: un endpoint HTTP o SSE remoto, no `localhost`.

<Steps>
  <Step title="Agrégalo">
    En la tarjeta **Add Custom Plugin**, haz clic en **Add Plugin**.
  </Step>
  <Step title="Completa el formulario">
    | Campo | Notas |
    | --- | --- |
    | **Plugin Name** | Obligatorio. |
    | **Description**, **Logo URL** | Opcionales. Ayudan a tus compañeros a reconocerlo en el catálogo. |
    | **URL** | El endpoint MCP. |
    | **Protocol** | **HTTP** o **SSE**. |
    | **Authorization** | **None**, **Bearer Token**, **Basic Auth**, **API Key** (con el nombre del header) u **OAuth 2.0**. OAuth 2.0 usa **Use Dynamic Client Registration**, o un **Client ID**, un **Client Secret** opcional y **Scopes** opcionales. |
    | **Custom Headers** | Headers adicionales, agregados con **Add Header**. Un header que define la autorización queda sobrescrito por ella. |

    Haz clic en **Create Plugin**.
  </Step>
  <Step title="Instálalo">
    Se abre el plugin. Con OAuth 2.0, haz clic primero en **Authenticate with** el plugin. Luego elige sus herramientas en **Selected tools** y haz clic en **Install plugin**. Si la lista está vacía, revisa la URL, el protocolo y la autorización.
  </Step>
</Steps>

Abre un plugin personalizado para **Edit Plugin** o **Delete Plugin**. Consulta [Instalar plugins MCP personalizados](/es/cookbook/custom-plugin-install) para una guía completa paso a paso.

## Usar plugins en una respuesta

<img src="https://kodus.io/wp-content/uploads/2025/10/comment-mcp.gif" alt="Ejemplo de uso de un plugin en una sugerencia" />

Menciona a Kody en un comentario sobre una sugerencia o sobre el pull request. Kody llama al plugin que necesita y responde en el mismo hilo.

- `@kody, update this kody rule to ignore test files`
- `@kody, move this task https://jira.com/task-123 to DONE`

## Validar lógica de negocio

`@kody -v business-logic` compara un pull request con la tarea que referencia, leída a través del plugin de tu gestor de tareas.
