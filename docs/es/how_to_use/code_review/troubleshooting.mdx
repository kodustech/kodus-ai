## Sin respuesta o sin comentarios de Kody

Empieza por la reacción en el PR. 👀 significa que Kody omitió la revisión, 😕 significa que falló y 🎉 significa que terminó (una revisión limpia no publica comentarios en línea). En GitHub (GitHub App) y Forgejo, el check **Kody Code Review** muestra el motivo de una omisión. [Cuándo omite Kody](/es/how_to_use/code_review/flow#cuándo-omite-kody) lista todos los motivos y su solución.

### Cuando no arranca una revisión automática

1. Comprueba que el repositorio esté seleccionado en **Repositories** o incluido en **Review every repository**.
2. Comprueba si el proveedor Git entregó el evento del PR. [Diagnostica la entrega del webhook](/es/knowledge_base/how-to-fix-webhook-issues).
3. Abre **Code review → General** en el alcance del repositorio y comprueba **Automated code review**. Si ese repositorio usa [kodus-config.yml](/es/how_to_use/code_review/configs/general#kodus-config-yml), comprueba `automatedReviewActive` en el archivo.
4. Para solicitar una revisión ahora, comenta `@kody start-review` en el PR. Si Kody todavía la omite, [consulta el motivo registrado](/es/how_to_use/code_review/flow#cuándo-omite-kody).

### La revisión terminó sin sugerencias

Asegúrate de que al menos una categoría (Bug, Performance, Security, Business Logic) esté activada para que Kody dé sugerencias, y revisa el **Minimum severity to post**. Ambos están en **Code review → What to review** ([abrir](https://app.kodus.io/settings/code-review/global/review-scope)).

## Las revisiones se detuvieron tras un push

Comenta `@kody start-review` para reanudar un PR pausado o pedir una revisión en modo **Manual**. Para revisar automáticamente cada nuevo push, elige **Automatic**. Consulta [Cadencia de revisión](/es/how_to_use/code_review/flow#cadencia-de-revisión) para ver cómo funciona cada modo.

## Problemas con el token

Comprueba que el token esté activo, que pueda acceder al repositorio y que tenga los permisos indicados para tu proveedor.

[GitHub](/es/how_to_use/code_review/general_config/github_pat) · [GitLab](/es/how_to_use/code_review/general_config/gitlab_pat) · [Bitbucket](/es/how_to_use/code_review/general_config/bitbucket_pat) · [Azure DevOps](/es/how_to_use/code_review/general_config/azure_devops_pat) · [Forgejo](/es/how_to_use/code_review/general_config/forgejo_pat)

## Ajustes Global vs. de Repositorio

Comprueba los ajustes del repositorio o directorio en el selector de alcance de **Code review**. Consulta [cómo se heredan los ajustes](/es/how_to_use/code_review/configs/inheritance_overrides) para encontrar qué nivel los cambió.

`kodus-config.yml` solo se aplica cuando **Prefer kodus-config.yml settings** está activado en **Code review → General** para ese repositorio. Una insignia bajo el selector de ámbito muestra si el archivo se aplicó, no se encontró o no está disponible.

## Kody dice que ya está revisando este PR

Un comando de revisión (`@kody review`, `@kody -v …`) enviado mientras otra revisión se ejecuta en el mismo PR espera y empieza cuando termina la revisión actual. Si esa revisión sigue en curso cuando Kody deja de esperar (unos 25 minutos como máximo), Kody comenta "Kody is already reviewing this PR" y no inicia el comando. Espera a que la revisión termine y vuelve a pedirlo.

## La merge queue elimina PRs mientras espera Kody Code Review

En GitHub, cuando `Kody Code Review` es un check requerido y un PR entra en la merge queue, Kody informa el último resultado de revisión terminada del PR en el commit que prueba la cola. No se ejecuta ninguna revisión nueva. Esto requiere que Kody esté conectada mediante la GitHub App; con un personal access token, Kody no publica checks.

El check significa que Kody revisó el PR, no que el PR esté libre de problemas. Pasa incluso con sugerencias críticas aún abiertas, y en el PR solo falla cuando la revisión misma no pudo ejecutarse. Exigirlo garantiza que hubo una revisión; no bloquea un merge por los hallazgos de Kody.

Si el último commit del PR no tiene una revisión de Kody terminada cuando entra en la cola (por ejemplo, porque un admin omitió el check requerido), el check falla de inmediato con **No finished Kody review** y la cola elimina el PR. Comenta `@kody start-review` en el PR, deja que la revisión termine y vuelve a agregarlo a la cola. **Could not carry Kody's review** significa que GitHub no devolvió el resultado de la revisión; vuelve a agregar el PR a la cola.
