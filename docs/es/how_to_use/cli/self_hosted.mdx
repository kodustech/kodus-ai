---
title: "Configuración Self-Hosted"
description: "Conecta el CLI de Kodus a tu instancia auto-alojada de Kodus."
---

Si estás ejecutando Kodus en tu propia infraestructura, el CLI funciona de la misma manera: solo necesitas apuntarlo a tu API.

## Conectar a Tu Instancia

<Steps>
  <Step title="Establecer la URL de la API">
    Indica al CLI dónde vive tu API de Kodus. Elige un método:

    <Tabs>
      <Tab title="Variable de Entorno (Recomendado)">
        ```bash
        export KODUS_API_URL=https://kodus-api.yourcompany.com
        ```

        Agrega esto a tu perfil de shell (`~/.bashrc`, `~/.zshrc`, etc.) para que sea permanente:

        ```bash
        echo 'export KODUS_API_URL=https://kodus-api.yourcompany.com' >> ~/.zshrc
        source ~/.zshrc
        ```
      </Tab>
      <Tab title="Archivo de Configuración">
        Crea o edita `~/.kodus/config.json`:

        ```json
        {
          "apiUrl": "https://kodus-api.yourcompany.com",
          "teamKey": "kodus_xxxxx",
          "teamName": "Your Team",
          "organizationName": "Your Org"
        }
        ```

        El CLI crea este archivo automáticamente cuando ejecutas `kodus auth team-key` y conserva un `apiUrl` que ya esté en él. También puedes crearlo manualmente.

        <Warning>
          `kodus auth login` y `kodus auth logout` pueden eliminar este archivo, incluida la URL de la API y la configuración de Cloudflare Access. Define `KODUS_API_URL` en el entorno. Si tu API usa Cloudflare Access, define también `CF_ACCESS_CLIENT_ID` y `CF_ACCESS_CLIENT_SECRET`.
        </Warning>
      </Tab>
      <Tab title="En Línea (Uso Puntual)">
        ```bash
        KODUS_API_URL=https://kodus-api.yourcompany.com kodus review
        ```
      </Tab>
    </Tabs>

    <Warning>
      **Se requiere HTTPS.** El CLI rechaza las URLs no-HTTPS por seguridad. La única excepción es `localhost` y `127.0.0.1` para el desarrollo local.
    </Warning>

    **Orden de prioridad:** variable de entorno `KODUS_API_URL` > `apiUrl` en `~/.kodus/config.json` > predeterminado (`https://api.kodus.io`).
  </Step>

  <Step title="Autenticarse">
    <Tabs>
      <Tab title="Clave de Equipo (Recomendado)">
        Genera una clave de equipo en **Organization → CLI keys** de tu app autohospedada de Kodus. Define la clave como variable de entorno `KODUS_TEAM_KEY` en la terminal donde ejecutas el CLI.

        <Tip>Las claves de equipo son ideales para entornos compartidos y configuraciones de agentes de IA: no se requiere inicio de sesión individual.</Tip>
      </Tab>
      <Tab title="Inicio de Sesión Personal">
        ```bash
        kodus auth login
        ```

        El CLI abre la página **Authorize Kodus CLI** de tu aplicación web auto-alojada. Inicia sesión con la cuenta registrada en tu instancia (tras iniciar sesión llegas al dashboard, así que abre de nuevo la URL que imprimió el CLI) y luego haz clic en **Authorize CLI**. En una máquina sin navegador, ejecuta `kodus auth login --device-code` en una terminal privada. El CLI muestra la URL de autorización de tu instancia y un código de un solo uso. En la barra de direcciones del navegador, añade el código como parámetro `code` y haz clic en **Authorize CLI**. Mantén el código y el enlace completo fuera de los registros y los mensajes compartidos.

        Tu inicio de sesión se almacena en `~/.kodus/credentials.json` con permisos restringidos (600).

        <Info>
          La dirección de esa página proviene de la configuración `API_FRONTEND_URL` de tu API de Kodus. Debe ser la URL de tu aplicación web, o la página de inicio de sesión se abre en el host equivocado.
        </Info>

        Para CI, guarda una clave de equipo como secreto `KODUS_TEAM_KEY`.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Verificar la Conexión">
    ```bash
    kodus status
    ```

    `kodus status` muestra el modo de autenticación detectado localmente. Para comprobar la URL de la API, añade `--verbose` a un comando que llame a la API. Por ejemplo, con una clave de equipo que permita configurar repositorios, ejecuta:

    ```bash
    kodus config remote list --verbose
    ```
  </Step>
</Steps>

## Cloudflare Access (Zero Trust)

Si tu API auto-alojada está detrás de [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/applications/), el CLI admite la autenticación con token de servicio.

<Tabs>
  <Tab title="Variables de Entorno">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export CF_ACCESS_CLIENT_ID=your-client-id.access
    export CF_ACCESS_CLIENT_SECRET=your-client-secret
    ```
  </Tab>
  <Tab title="Archivo de Configuración">
    ```json
    {
      "apiUrl": "https://kodus-api.yourcompany.com",
      "teamKey": "kodus_xxxxx",
      "cfAccessClientId": "your-client-id.access",
      "cfAccessClientSecret": "your-client-secret"
    }
    ```
  </Tab>
</Tabs>

Cuando están configurados tanto el ID de cliente como el secreto, el CLI envía los encabezados `CF-Access-Client-Id` y `CF-Access-Client-Secret` en cada solicitud a la API. Prioridad: variables de entorno > archivo de configuración.

## Referencia del Archivo de Configuración

El CLI almacena la configuración en `~/.kodus/config.json`:

```json
{
  "apiUrl": "https://kodus-api.yourcompany.com",
  "teamKey": "kodus_xxxxx",
  "teamName": "Engineering",
  "organizationName": "Acme Corp",
  "cfAccessClientId": "your-client-id.access",
  "cfAccessClientSecret": "your-client-secret"
}
```

| Campo | Requerido | Descripción |
|-------|-----------|-------------|
| `apiUrl` | No | Tu URL de API auto-alojada. Anulada por la variable de entorno `KODUS_API_URL`. |
| `teamKey` | No | Clave de API del equipo (comienza con `kodus_`). Anulada por la variable de entorno `KODUS_TEAM_KEY`. |
| `teamName` | No | Nombre de visualización del equipo. |
| `organizationName` | No | Nombre de visualización de la organización. |
| `cfAccessClientId` | No | ID de cliente de Cloudflare Access. Anulado por la variable de entorno `CF_ACCESS_CLIENT_ID`. |
| `cfAccessClientSecret` | No | Secreto de cliente de Cloudflare Access. Anulado por la variable de entorno `CF_ACCESS_CLIENT_SECRET`. |

<Info>
  El archivo de configuración se crea con permisos `0600` (solo lectura/escritura del propietario). El directorio `~/.kodus/` se crea con permisos `0700`.
</Info>

## Resumen de Variables de Entorno

| Variable | Descripción |
|----------|-------------|
| `KODUS_API_URL` | Endpoint de la API auto-alojada (se requiere HTTPS, excepto localhost) |
| `KODUS_APP_URL` | URL de tu aplicación web, a la que apunta `kodus config remote open` (predeterminado `https://app.kodus.io`) |
| `KODUS_TEAM_KEY` | Clave de equipo para acceso compartido |
| `KODUS_TOKEN` | Un token de acceso de inicio de sesión, usado tal cual y sin actualizarse. Tiene prioridad sobre cualquier otra credencial. Para CI, usa una clave de equipo |
| `CF_ACCESS_CLIENT_ID` | ID de cliente de Cloudflare Access |
| `CF_ACCESS_CLIENT_SECRET` | Secreto de cliente de Cloudflare Access |
| `KODUS_REQUEST_TIMEOUT_MIN` | Tiempo de espera de cada solicitud a la API en minutos (predeterminado `60`) |
| `KODUS_DISABLE_UPDATE_CHECK` | Establécelo en `1` para desactivar el aviso de actualización |

## Integración con CI/CD

Para instancias auto-alojadas en pipelines de CI/CD, establece la URL de la API y una clave de equipo como variables de entorno. Un checkout nuevo no tiene cambios sin confirmar, así que revisa la rama contra su base con `--branch`. La rama base debe estar disponible en el checkout, así que obtén el historial completo.

<Tabs>
  <Tab title="GitHub Actions">
    ```yaml
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0
    - name: Kodus Review
      env:
        KODUS_API_URL: ${{ secrets.KODUS_API_URL }}
        KODUS_TEAM_KEY: ${{ secrets.KODUS_TEAM_KEY }}
      run: npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
  <Tab title="GitLab CI">
    ```yaml
    kodus-review:
      variables:
        GIT_DEPTH: "0"
      script:
        - git fetch origin main
        - npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```

    Añade `KODUS_API_URL` y `KODUS_TEAM_KEY` como variables de CI/CD en la configuración del proyecto.
  </Tab>
  <Tab title="Genérico">
    ```bash
    export KODUS_API_URL=https://kodus-api.yourcompany.com
    export KODUS_TEAM_KEY=kodus_xxxxx
    npx @kodus/cli review --branch origin/main --format json --fail-on error
    ```
  </Tab>
</Tabs>

<Tip>
  Usa `--fail-on error` o `--fail-on critical` para que el pipeline falle cuando se encuentren problemas por encima de un umbral de severidad. Los pull requests los revisa la integración con Git, así que no necesitan un job en el pipeline.
</Tip>

## Distribución a Tu Equipo

Comparte con tu equipo las [instrucciones de instalación del CLI](/es/how_to_use/cli/getting_started) y la URL de tu API autohospedada. Cada persona configura `KODUS_API_URL` en su perfil de la terminal o `apiUrl` en `~/.kodus/config.json`. Distribuye la clave de equipo mediante tu gestor de secretos y defínela como `KODUS_TEAM_KEY` antes de usar el CLI.

## Solución de Problemas

<AccordionGroup>
  <Accordion title="Security Error: API URL must use HTTPS protocol">
    El CLI requiere HTTPS para todas las URLs que no sean localhost. Después vuelve a la URL predeterminada `https://api.kodus.io`, así que lee el mensaje antes de autenticarte. Asegúrate de que tu instancia auto-alojada tenga un certificado TLS válido. Si estás probando localmente, usa `http://localhost:<port>` en su lugar.
  </Accordion>

  <Accordion title="Conexión rechazada o tiempo de espera agotado">
    - Verifica que la URL sea accesible: `curl -I https://kodus-api.yourcompany.com`
    - Comprueba si un firewall o VPN está bloqueando la conexión
    - Si está detrás de Cloudflare Access, asegúrate de que `CF_ACCESS_CLIENT_ID` y `CF_ACCESS_CLIENT_SECRET` estén configurados
    - Usa `--verbose` para ver la URL exacta que se está usando
  </Accordion>

  <Accordion title="Autenticación fallida (401)">
    - Ejecuta `kodus status` para verificar tu estado de autenticación actual
    - Si usas una clave de equipo, verifica que siga **Active** en **Organization → CLI keys** de tu aplicación web auto-alojada
    - Si usas inicio de sesión personal, el CLI actualiza tu sesión automáticamente; si la actualización falla, ejecuta `kodus auth login` de nuevo
    - Asegúrate de que `KODUS_API_URL` apunte a la instancia correcta
  </Accordion>

  <Accordion title="API returned invalid response (expected JSON, got HTML)">
    Esto generalmente significa que la URL está llegando a un proxy inverso, balanceador de carga o página de Cloudflare Access en lugar de la API real. Comprueba:
    - La ruta de la URL es correcta (sin `/api` u otro sufijo adicional)
    - Las credenciales de Cloudflare Access están configuradas si corresponde
    - El proxy inverso está reenviando las solicitudes correctamente
  </Accordion>

  <Accordion title="Límite de dispositivos alcanzado">
    Tu instancia auto-alojada puede aplicar límites de dispositivos por organización. La aplicación web no tiene una lista de dispositivos para limpiar, así que contacta a tu administrador para aumentar el límite (la configuración `CLI_DEVICE_LIMIT` de la API; `0`, el valor por defecto, significa sin límite).
  </Accordion>
</AccordionGroup>
