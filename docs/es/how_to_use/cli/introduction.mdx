El CLI de Kodus revisa tus cambios de código directamente desde la terminal, antes de que lleguen a un pull request. Apúntalo a tu árbol de trabajo, diff preparado, rama o commit. Aplica las Kody Rules y la configuración de revisión de código de tu equipo.

Conecta la CLI a [Kodus Cloud](/es/how_to_use/cli/getting_started) o a una [instancia autoalojada](/es/how_to_use/cli/self_hosted). Puedes probar revisiones básicas sin iniciar sesión, con un límite de uso. Los comandos del workspace requieren iniciar sesión o usar una clave de equipo, según el comando.

## Para quién es

- **Desarrolladores individuales** ejecutando una verificación previa al commit antes de enviar.
- **Equipos** que quieren un conjunto de reglas de revisión compartidas en cada clon, IDE y trabajo de CI, sin que cada desarrollador tenga que iniciar sesión.
- **Agentes de programación de IA** (Claude Code, Cursor, Codex, Windsurf y otros) ejecutando bucles de revisión y corrección con salida estructurada.
- **Pipelines de CI/CD** que fallan compilaciones con problemas por encima de un umbral de severidad.

## Cómo se ve

Ejecutar `kodus review` sobre un cambio lista sus hallazgos con severidad, ubicación y una corrección sugerida. En una terminal interactiva de macOS y Linux, los hallazgos se abren en el visor de diff Hunk, junto al código.

<img src="/images/kodus_cli_review.jpg" alt="Revisión de código con IA en tu CLI"/>

Con `--prompt-only`, la misma revisión se convierte en texto compacto y estructurado para que un agente de IA lo analice y actúe sobre él. Con `--fail-on`, el código de salida le indica a un script si debe detenerse.

## Límites

|                  | Prueba (sin cuenta)                                              | Sesión iniciada o clave de equipo                                 |
| ---------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| Límite de uso    | 2 revisiones por hora, por cada usuario, dispositivo y carpeta de repositorio | 1000 solicitudes por hora, por equipo                |
| Enviado a Kodus  | Solo el diff                                                     | El diff, más los archivos modificados en una revisión del árbol de trabajo o preparada |
| Diff             | 20 millones de caracteres                                        | 20 millones de caracteres                                         |
| Archivos por revisión | —                                                           | 500                                                               |
| Diff por archivo | —                                                                | 500 000 caracteres                                                |
| Contenido por archivo | —                                                           | 2 000 000 de caracteres                                           |
| Tamaño de la solicitud | 25 MB                                                      | 24 MB                                                             |

La hora de la prueba es una ventana móvil. A una revisión de prueba no se le aplica ningún límite de archivos ni de líneas. Para un equipo con sesión iniciada, las 1000 solicitudes cuentan revisiones, verificaciones de validación de negocio y eventos de sesión de [Kodus Trace](/es/how_to_use/cli/trace).

Con un inicio de sesión o una clave de equipo, un archivo que supere los límites por archivo se omite con una advertencia. `--branch`, `--commit` y `--fast` envían solo el diff, lo que mantiene las revisiones grandes por debajo del límite de la solicitud.

En modo de prueba, `kodus auth status` muestra tu uso y cuándo se restablece.

## CLI vs Kodus Web

El CLI y la aplicación web de Kodus comparten las Kody Rules y la configuración de revisión de código. Usa el CLI cuando quieras una revisión **antes de que exista el PR**: en una rama local, un diff preparado o dentro de un bucle de agente. Usa la aplicación web para revisiones de PR, Cockpit y configuración a nivel de equipo.

Una revisión del CLI aplica las Kody Rules de tu equipo. Cuando tu remoto de git coincide con un repositorio añadido a Kodus, también aplica las reglas de ese repositorio, su modo de revisión y sus instrucciones de repositorio (`CLAUDE.md`, `AGENTS.md`). Si no hay coincidencia, solo se ejecutan las reglas que se aplican a todos los repositorios. Una revisión de prueba no tiene equipo: se ejecuta con la configuración predeterminada y sin Kody Rules.

Las revisiones ejecutadas desde el CLI aparecen en la aplicación web en **Reviews → CLI**. Una revisión ejecutada con una clave de equipo se etiqueta como **Team · &lt;key name&gt;**, y una ejecutada con un inicio de sesión se etiqueta como **Personal**.
