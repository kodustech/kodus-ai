---
title: "Agentes de IA"
description: "Integra el CLI de Kodus con agentes de programación de IA para bucles autónomos de revisión y corrección."
---

El CLI incluye un modo de salida mínimo y estructurado (`--prompt-only`) para que los agentes de programación de IA lo analicen y actúen sobre él. Combinado con una clave de equipo, permite que un agente revise sus propios cambios, corrija lo que la revisión encuentra y vuelva a revisar, sin ninguna persona en el bucle. El CLI también instala skills de Kodus en los agentes de tu máquina, para que un agente sepa qué comando ejecutar.

## Agentes compatibles

`kodus skills install` encuentra un agente por su carpeta de configuración, en el directorio actual y en tu carpeta personal, y escribe allí los skills de Kodus. Detecta:

| Agente        | Carpeta de configuración                           |
| ------------- | -------------------------------------------------- |
| Claude Code   | `.claude`, `~/.claude`, `~/.config/claude`         |
| Cursor        | `.cursor`, `~/.cursor`                             |
| Codex         | `.codex`, `~/.codex`                               |
| Windsurf      | `.windsurf`, `~/.codeium/windsurf`                 |
| Gemini        | `.gemini`                                          |
| Antigravity   | `.agent`, `~/.gemini/antigravity`                  |
| OpenCode      | `.opencode`, `~/.config/opencode`                  |
| Kiro          | `.kiro`, `~/.kiro`                                 |
| Goose         | `.goose`, `~/.config/goose`                        |
| Roo Code      | `.roo`, `~/.roo`                                   |
| Kilo Code     | `.kilocode`, `~/.kilocode`                         |
| Droid         | `.factory`, `~/.factory`                           |
| AiderDesk     | `.aider-desk`, `~/.aider-desk`                     |
| Otros agentes | `.agents`, `~/.agents`, `~/.config/agents`         |

Para cualquier otro agente que pueda ejecutar comandos de shell y leer texto, `kodus review --prompt-only` funciona sin un skill.

## Configuración más rápida

Instala el CLI junto con los skills de una sola vez:

```bash
curl -fsSL https://review-skill.com/install | bash
```

El instalador agrega el CLI e instala los skills incluidos en cada agente que detecta. Define `KODUS_TEAM_KEY` en el entorno donde se ejecuta tu agente. En una instancia autohospedada, define también `KODUS_API_URL`. Para agregar o actualizar los skills más tarde, ejecuta `kodus skills install` o `kodus skills resync`.

## Los skills

| Skill                             | Qué puede hacer el agente con él                                                   |
| --------------------------------- | ---------------------------------------------------------------------------------- |
| `kodus-review`                    | Revisar los cambios locales con `kodus review --prompt-only` y corregir lo que encuentra |
| `kodus-pr-suggestions-resolver`   | Obtener las sugerencias de un pull request, aplicar las que tengan sentido y leer su historial de revisión |
| `kodus-business-rules-validation` | Verificar los cambios locales contra los criterios de aceptación de una tarea      |
| `kodus-kody-rules`                | Ver, crear, actualizar, pausar, reanudar y eliminar Kody Rules                     |
| `kodus-review-settings`           | Mostrar y cambiar la configuración de revisión de código y el modelo de revisión   |
| `kodus-custom-agents`             | Listar, crear, editar, activar o desactivar, eliminar y probar agentes personalizados |
| `kodus-cockpit-usage`             | Leer las métricas de Cockpit y el uso de tokens                                    |
| `kodus-centralized-config`        | Verificar, habilitar, sincronizar y descargar la configuración centralizada        |
| `kodus-trace`                     | Leer las decisiones registradas para el código que está por cambiar                |

Los skills que cambian reglas, configuraciones o agentes necesitan un inicio de sesión, o una clave de equipo que lo permita. Consulta [Modos de autenticación](/es/how_to_use/cli/concepts#modos-de-autenticación).

## El bucle de revisión y corrección

<Steps>
  <Step title="El agente ejecuta la revisión">
    ```bash
    kodus review --prompt-only
    ```

    El CLI devuelve problemas estructurados con rutas de archivos, números de línea, severidades y correcciones sugeridas, en un formato de texto compacto para un LLM. La salida empieza con `REVIEW_ANALYSIS_COMPLETE` y termina con `END_REVIEW`.
  </Step>
  <Step title="El agente aplica correcciones">
    El agente lee la salida, decide qué correcciones aplicar y edita los archivos. Un falso positivo omitido está bien; el agente debe decir por qué.
  </Step>
  <Step title="El agente vuelve a ejecutar la revisión">
    ```bash
    kodus review --prompt-only --fail-on error
    ```

    Con `--fail-on error`, el comando termina con código 1 mientras quede un problema de nivel error o superior. Cuando la revisión sale limpia, imprime `NO_ISSUES_FOUND`, termina con código 0 y el agente avanza.
  </Step>
  <Step title="El agente confirma y envía los cambios">
    Una vez que la revisión está limpia, el agente confirma y envía los cambios. Opcionalmente, instala el hook pre-push (`kodus hook install`) como red de seguridad en los envíos manuales.
  </Step>
</Steps>

<Note>
  `--fix` pide una confirmación en la terminal, así que un agente sin supervisión debe aplicar las correcciones por sí mismo.
</Note>

## Autenticación con clave de equipo para agentes

Las claves de equipo son muy recomendables para los agentes: sin registro individual, sin inicio de sesión interactivo, rotación sencilla, seguimiento por dispositivo.

```bash
export KODUS_TEAM_KEY=kodus_xxxxx
kodus review --prompt-only
```

Genera una clave en **Organization → CLI keys** (<a href="https://app.kodus.io/organization/cli-keys" target="_blank">app.kodus.io/organization/cli-keys</a>) y distribuye a tu equipo el comando de instalación que se muestra junto con la nueva clave.

<Warning>Guarda la clave cuando se muestre: no se volverá a mostrar.</Warning>

## Flags de salida que importan

| Flag             | Uso                                                                 |
| ---------------- | ------------------------------------------------------------------- |
| `--prompt-only`  | Salida estructurada compacta para analizar. Úsalo en el bucle de revisión. Solo `kodus review` |
| `--agent`        | Un solo sobre JSON (`ok`, `command`, `data`, `error`, `meta`). No todos los comandos lo admiten: consulta [Global Flags](/es/how_to_use/cli/commands#flags-globales) |
| `--format json`  | Carga útil JSON completa para `review` y `pr`                       |
| `--fail-on`      | Control del código de salida: 1 cuando un problema alcanza la severidad |
| `--fields <csv>` | Reduce la carga útil JSON (p. ej., `summary,issues.file,issues.severity`) para mantener pequeño el contexto de un agente. Requiere `--format json` o `--agent` |

Otros comandos aceptan `--json`. `kodus schema` imprime cada comando y flag como JSON, para un agente que necesite comprobar qué existe.

## Ejemplo: bucle de Claude Code con validación de negocio

```bash
# In a Claude Code session, the agent can run:
kodus review --prompt-only --fail-on error                      # general review
kodus pr business-validation --task-id KC-1441 --format json    # check against the task
kodus review --prompt-only --fail-on error                      # re-run after fixes
git commit -am "fix: KC-1441 address review findings"
```

Con los skills instalados, el agente sabe cuándo ejecutar cada uno de estos.

## Capturar lo que decide el agente

`kodus trace enable` agrega hooks para Claude Code, Cursor y Codex que registran cada sesión, de modo que las razones detrás de los cambios de un agente se conservan y pueden leerse de vuelta por ruta. Consulta [Kodus Trace](/es/how_to_use/cli/trace).
