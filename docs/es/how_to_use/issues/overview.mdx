---
title: "Kody Issues"
description: "Rastrea y gestiona las sugerencias no implementadas con la función Kody Issues."
---

**Kody Issues** mantiene una lista en vivo de las sugerencias que Kody hizo y que **no se implementaron** cuando se cerró su pull request, y las cierra a medida que el código cambia. Funciona por sí solo; desactívalo con el interruptor **Auto-create issues**.

En cualquier plan, incluidas las instalaciones autoalojadas sin licencia, los Owners, Repo Admins y Contributors pueden abrir **Issues** desde la paleta de comandos ⌘K. La entrada abre la lista incluso si muestra un candado y una etiqueta **Teams**.

Con [acceso a Cockpit](/es/how_to_use/cockpit/overview), abre la pestaña **Issues** para ver la lista y el número de issues abiertos.

La lista muestra **Status**, **Severity**, **Category**, **Title**, **Repository**, **File**, **Age** y **#PR(s)**. Por defecto, muestra los issues abiertos.

Los Owners, Repo Admins y Contributors pueden leer los issues de todos los repositorios; los Billing Managers no. Los Owners pueden modificar cualquier issue, los Repo Admins solo los de sus repositorios asignados y los Contributors ninguno.

Para consultar los issues en la terminal, revisa la disponibilidad y los filtros de [`kodus issues`](/es/how_to_use/cli/commands#kodus-issues).

## Cómo se crean los issues

<Note>
  Los issues solo se crean cuando los PRs se **cierran**, no cuando se abren ni
  durante la revisión. En GitLab y Azure Repos, solo cuenta un PR mergeado.
</Note>

- Cuando se cierra un PR, Kody toma las sugerencias que hizo en ese PR y que no se implementaron, y crea un **Issue** por cada una, vinculado al repositorio. Cada issue conserva la explicación original, el archivo, y la severidad y la categoría.
- Si un issue abierto en el mismo archivo ya cubre el mismo problema, Kody le agrega la nueva sugerencia en lugar de crear un duplicado. **#PR(s)** lista todos los PRs que contribuyeron.
- Esto incluye las sugerencias que Kody no publicó porque estaban por debajo de la severidad mínima o por encima de un límite de comentarios. Las sugerencias que Kody descartó por incorrectas, por repetidas o porque su categoría está desactivada no se convierten en issues.

<Warning>
  Las Kody Rules de tipo **Per PR** no generan issues. Solo las sugerencias a nivel de archivo crean issues rastreables.
</Warning>

## Cómo se resuelven los issues

Cada vez que se cierra un PR, Kody compara con el código actual los issues abiertos de los archivos que ese PR modificó:

- Si el código ya no tiene el problema, el issue pasa a **Resolved**.
- Si el archivo fue eliminado, el issue pasa a **Dismissed**.

Esto también se ejecuta con **Auto-create issues** desactivado, así que los issues existentes siguen cerrándose.

## Trabajar con los issues

Haz clic en una fila para abrir el panel de detalle del issue, con los enlaces al repositorio, al PR y al archivo, la descripción y **Team feedback from PR reactions** (el conteo de 👍 / 👎). Recorre los issues con **J** / **K**, y **Share** copia un enlace al issue.

### Status

- **Open**: requiere atención.
- **Resolved**: lo define Kody cuando el problema ya no está en el código.
- **Dismissed**: no es relevante. Defínelo a mano cuando una sugerencia no aplica a tu equipo; Kody también lo define cuando el archivo se elimina.

Cambia el estado desde el selector en la parte superior del panel de detalle.

### Severity

Cada issue tiene una severidad (`Critical`, `High`, `Medium`, `Low`) que parte de la de la sugerencia. Cámbiala desde el panel de detalle para que coincida con las prioridades de tu equipo.

### Filters

Abre **Filters** en la parte superior de la lista (el botón muestra cuántos están activos) para filtrar por **Status**, **Severity**, **Category**, **Title**, **Repository**, **File path** y **PR numbers**. **Set as default filters** aplica tus filtros cada vez que abres Issues en este navegador; **Reset to default filters** los restablece.
