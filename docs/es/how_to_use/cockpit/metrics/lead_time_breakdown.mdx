## Qué es el Desglose del Lead Time

El Desglose del Lead Time (Lead Time Breakdown) divide el tiempo desde el primer commit de un PR hasta su cierre en tres fases: tiempo de codificación, tiempo de recogida y tiempo de revisión. Muestra dónde se ralentiza tu flujo de trabajo.

En el Cockpit, es el gráfico **Lead Time Breakdown** de la pestaña **Productivity**: una barra apilada por semana, con **Coding Time**, **Pickup Time** y **Review Time** en horas. Haz clic en un nombre debajo del gráfico para ocultar o mostrar esa fase.

## Cómo lo Calculamos

```
Coding Time = (Last Commit Time) - (First Commit Time)
Pickup Time = (PR Opened Time) - (Last Commit Time)
Review Time = (PR Closed Time) - (PR Opened Time)
```

- **Coding Time**: desde el primer hasta el último commit del PR, incluidos los commits enviados después de abrir el PR.
- **Pickup Time**: desde el último commit hasta que se abre el PR. Es negativo para un PR que recibió nuevos commits después de abrirse.
- **Review Time**: desde que se abre el PR hasta que se cierra, mergeado o no.

Para cada semana, cada fase es el percentil 75 (P75) de los PRs cerrados esa semana, de modo que los valores atípicos inusualmente largos no la distorsionen. Un PR cuyo valor para una fase es exactamente cero, como el tiempo de codificación de un PR de un solo commit, se excluye del P75 de esa fase. Solo cuentan los commits hechos hasta 30 días antes de que se abriera el PR, porque los commits más antiguos en una rama con rebase suelen pertenecer a otro trabajo. Un PR sin datos de commits se excluye.

No se cuenta el tiempo antes del primer commit (planificación, diseño) ni después del cierre (despliegue).

## Por qué Importa

Comprender dónde se invierte el tiempo te ayuda a optimizar la parte correcta de tu proceso:

- **Coding Time**: muestra la eficiencia del desarrollo
- **Pickup Time**: revela cuellos de botella del flujo de trabajo entre terminar el código y pedir la revisión
- **Review Time**: indica la efectividad del proceso de revisión

## Cómo Mejorar

### Reducir el Coding Time
- Aclarar los requisitos antes de empezar el trabajo
- Dividir las funcionalidades grandes en partes manejables
- Trabajar en pareja en los problemas complejos

### Reducir el Pickup Time
- Abrir el PR justo después de terminar el código
- Automatizar la creación y la configuración del PR
- Definir cuándo el código está listo para revisión

### Reducir el Review Time
- Establecer expectativas claras para los revisores
- Usar verificaciones automatizadas para detectar problemas antes de la revisión
- Distribuir la carga de revisión en el equipo
- Responder con prontitud a los comentarios de revisión
- Mantener los PRs pequeños
