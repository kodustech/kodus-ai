## Qué es la Proporción de Bugs

La Proporción de Bugs (Bug Ratio) es el porcentaje de pull requests cerrados que son correcciones de bugs. Muestra qué parte de tu entrega se dedica a corregir problemas en lugar de construir funcionalidades.

En el Cockpit, es la tarjeta **Bug Ratio** de la pestaña **Productivity**. No es la change failure rate de DORA: cuenta PRs de corrección de bugs, no despliegues fallidos.

## Cómo la Calculamos

Un job en segundo plano le pide a un modelo de IA que clasifique cada pull request **solo a partir de su título** como **Bug Fix**, **Feature**, **Refactor** o **Test**. No se usan la descripción del PR, las etiquetas ni el diff, y no hay nada que configurar.

```
Bug Ratio = (PRs classified as Bug Fix) ÷ (PRs closed in the range) × 100
```

El rango es el rango de fechas seleccionado en la parte superior del Cockpit, y un PR cerrado es uno mergeado o cerrado sin merge. Un PR que aún no se ha clasificado cuenta en el total pero no como corrección de bug. Por ejemplo, si 3 de 15 PRs se clasifican como correcciones de bugs, tu Bug Ratio es del 20%.

Cuando la proporción es 0% tanto en el rango seleccionado como en el período anterior, la tarjeta muestra **Once we have enough data, your metrics will appear here.** en lugar de 0%.

## Cómo leer la tarjeta

La tarjeta muestra el porcentaje, una insignia de nivel y el valor del período anterior de la misma duración con el cambio porcentual (cuanto más bajo, mejor). El pie dice "Last 2 weeks was …" sin importar qué rango esté seleccionado; el número corresponde al período anterior. Pasa el cursor sobre la insignia para ver los niveles:

| Bug Ratio | Nivel |
| --- | --- |
| Menos del 5% | Elite |
| 5% a 10% | High |
| 10% a 20% | Fair |
| Más del 20% | Need focus |

## Por qué importan los títulos de los PRs

Como solo se lee el título, un título descriptivo da una proporción más precisa.

| Buenos títulos de corrección de bugs | Títulos vagos |
| --- | --- |
| "Fix: User login fails with invalid credentials" | "Fix stuff" |
| "Resolve issue: API returns 500 error for large requests" | "Update code" |
| "Patch: Fix null pointer exception in user service" | "Improve performance" |

## Cómo Mejorar

- Probar más a nivel unitario, de integración y de extremo a extremo
- Usar linters y analizadores estáticos antes de producción
- Dividir las funcionalidades grandes en partes más pequeñas y comprobables
- Usar feature flags para despliegues más seguros
- Realizar revisiones post-incidente para prevenir la recurrencia
