## Por qué son importantes los plugins personalizados

Un plugin personalizado permite que Kody lea tus sistemas internos, como una base de conocimiento, un panel de incidentes o un motor de políticas, mientras responde en un pull request. Los revisores dejan de pegar capturas de pantalla y fragmentos desactualizados en los comentarios.

<Callout icon="globe">
  Kodus admite **únicamente servidores MCP remotos**. El servidor debe ser accesible desde la infraestructura de Kodus: sin `localhost`, sin endpoints MCP de escritorio.
</Callout>

## Prepara la información de tu plugin

Reúne estos datos antes de abrir la página de Plugins:

| Campo | Por qué importa |
| ----- | --------------- |
| **URL** | El endpoint MCP, por ejemplo `https://acme-internal-tools.com/mcp`. |
| **Protocol** | **HTTP** o **SSE**. |
| **Authorization** | **None**, **Bearer Token**, **Basic Auth**, **API Key** (y el header en el que va) u **OAuth 2.0** (un client ID, o dynamic client registration). |
| **Descripción y logo** | Opcional. Ayudan a tus compañeros a reconocer el plugin. |

¿Buscas servidores MCP remotos para probar?

- [Smithery.ai](https://smithery.ai/) reúne servicios MCP desplegables.
- [Awesome Remote MCP Servers](https://github.com/sylviangth/awesome-remote-mcp-servers) lista endpoints mantenidos por la comunidad.

## Instala el plugin en Kodus

<Frame caption="Plugins → tarjeta Add Custom Plugin → Add Plugin abre este formulario">
  <img src="/images/custom-plugin.png" alt="Add Custom Plugin form" />
</Frame>

<Steps>
  <Step title="Abre el formulario">
    En la barra lateral, abre **Plugins**. En la tarjeta **Add Custom Plugin**, haz clic en **Add Plugin**.
  </Step>
  <Step title="Complétalo">
    ```text
    Plugin Name: Descriptive label (for example "Security Runbooks MCP")
    Description: What data it exposes (optional)
    Logo URL: Optional
    URL: https://your-domain.com/mcp
    Protocol: HTTP or SSE
    Authorization: None, Bearer Token, Basic Auth, API Key or OAuth 2.0
    Custom Headers: Any extra header your server needs (optional)
    ```

    Haz clic en **Create Plugin**.
  </Step>
  <Step title="Elige sus herramientas e instálalo">
    Se abre el plugin. Con OAuth 2.0, haz clic primero en **Authenticate with** el plugin. En **Selected tools**, conserva solo las herramientas que Kody necesita y luego haz clic en **Install plugin**. Un plugin instalado muestra **Installed** en su tarjeta.
  </Step>
</Steps>

Si **Selected tools** muestra 0 of 0, Kodus no pudo listar las herramientas del servidor. Abre el plugin, haz clic en **Edit Plugin** y revisa la URL, el protocolo y la autorización.

<Warning>
  Kody puede llamar a cualquier herramienta que selecciones. Instala solo endpoints en los que tu organización confíe y selecciona solo las herramientas que Kody necesita.
</Warning>

## Verifica la conexión

1. Abre un pull request en un repositorio donde Kody esté habilitado.
2. Comenta con `@kody` y una pregunta que solo el plugin pueda responder:

   ```
   @kody can you fetch the deployment checklist from our MCP and confirm whether feature flags are required?
   ```

3. Revisa la respuesta de Kody. Debería incluir datos devueltos por tu plugin. Si no es así, abre el plugin en la página **Plugins** y revisa su URL, protocolo y autorización.

<Info>
  Para ensayar el flujo sin construir un servidor, agrega `https://docs.kodus.io/mcp` como plugin personalizado: protocolo **HTTP**, autorización **None**.
</Info>

## Úsalo en un agente personalizado

Un agente personalizado lee de un plugin instalado cuando lo activas en **Tools → Plugins** en la página del agente. Solo se ofrecen herramientas de lectura. Consulta [Skills, docs y herramientas](/es/how_to_use/code_review/custom_agents_knowledge_and_tools#plugins-mcp).

## Lista de verificación rápida

- [ ] El servidor es accesible desde Kodus por HTTP o SSE.
- [ ] Su autorización funciona con el método que elegiste.
- [ ] **Selected tools** lista herramientas, y solo están seleccionadas las que Kody necesita.
- [ ] El plugin muestra **Installed**.
- [ ] Un comentario de prueba en un pull request devolvió datos del plugin.
- [ ] Alguien es responsable de monitorear y actualizar la integración.
