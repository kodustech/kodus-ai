# apps/runtime/src/e2e

Test and dev code: scripts and fixtures that drive a whole Run against a local stack. Nothing here runs in production; production code never imports it ([layering](../../AGENTS.md#layering)).

## Owns
- `trigger.ts`: `pnpm run runtime:e2e`. Publishes a `RuntimeRunRequested` the way the product's outbox relay would, against `docker-compose.runtime.yml`, and follows the Run to its verdict.
- `fixtures.ts` `shopRunRequest`: the synthetic toy-shop PR, its tokens sealed with the dev key. Most worker, admission and Run specs build their requests from it (and a few in `libs/runtime`).
- `product-target.ts` `recordProductTarget`, `productPgConfig`: writes the Run's publish target into the product Postgres, as `RuntimeRunEnqueuer` does, so "Run again" and publication find it.
- `run-stream-reader.ts` `readRunStreamForE2e`: reads a Run's stream from Postgres or the file store.
- `evidence-bucket.ts`: creates the S3 evidence bucket and its lifecycle rule (README "Evidence").
- `integrated-worker.ts`: the real production worker module with a loopback DBOS inspection listener, for a harness that drives the worker end to end.

## Rules and limits
- These files read the process environment directly; they are test code for `config-boundary.spec.ts` (`testing/source-scan.ts` `isTestCode`).
- Fixtures carry no customer data.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/e2e` (`product-target.spec.ts`). The scripts themselves run against a stack: `pnpm run runtime:up`, then `pnpm run runtime:e2e`.
