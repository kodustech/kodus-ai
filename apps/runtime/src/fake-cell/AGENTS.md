# apps/runtime/src/fake-cell

Test and dev code: a cell written in TypeScript that speaks the real hub protocol over WebSocket and runs the in-memory environment driver behind it. It stands in for the Go cell (`apps/runtime-cell`) in the isolated local stack and in the contract tests. Production code never imports it ([layering](../../AGENTS.md#layering)).

## Owns
- `fake-cell.ts` `FakeCell`: connects out to the hub, answers frames through `decodeFrame`, deduplicates steps by stepId and command hash as the real cell must.
- `main.ts`: the `runtime-fake-cell` process of `docker-compose.runtime.yml`; reconnects with backoff and jitter.
- `scenarios.ts` `SCENARIOS`, `SHOP_IMAGE`: synthetic environments (a toy shop whose PR turns the empty-cart 400 into a 500). Many worker Run specs use them.

## Rules and limits
- The one production-module import is `scenarios.ts`, loaded lazily by `fakeEnvironments` in `worker/runtime-worker.module.ts` behind `RUNTIME_ENV_DRIVER=fake`, which the production image refuses.
- `libs/mcp-server/tests/fixtures/runtime-env.fixture.ts` also uses `FakeCell`, as test code.
- No customer data in scenarios.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/fake-cell`: `hub-cell.contract.spec.ts` runs a whole Run through the real hub and this cell on real frames (regression verdict, egress blocked, permit kept until release).
