# apps/runtime/src/shared/evidence

The evidence object store of a Run: where each step's output and the cells' artifacts live, under the key `{orgId}/{runId}/{side}/{stepId}/{type}`. It runs in the runtime-worker (writes, takes uploads, presigns) and its local adapter is also read by the worker's evidence server. Two adapters of one port, chosen by `RUNTIME_EVIDENCE_STORE`; the flows are in [README.md "Evidence"](../../../README.md#evidence).

## Owns
- The port: `file-evidence-store.ts` `EvidenceStore` (`put`, `get`, optional `takeUpload`), `TakenUpload`, and `canonicalEvidenceKey` (the exact five-part key or `InvalidEvidenceKeyError`).
- The local volume adapter: `file-evidence-store.ts` `FileEvidenceStore` (one file per key, 0600 under 0700 directories, a metadata sidecar) and its retention `sweep` (`EVIDENCE_RETENTION_DAYS`).
- The S3 adapter: `s3-evidence-store.ts` `S3EvidenceStore`, also the `EvidencePresigner` of grants and reads; `takeUpload` checks a cell's staging object (type, size, ETag) and commits it, or a redacted text, to the evidence key.
- The S3 calls: `s3-object-client.ts` `S3ObjectClient` (`head`, `get`, `put`, `copy`, `delete`, and `createBucket`, `putEvidenceLifecycle` for setup) signed with SigV4 over `fetch`, no SDK; `S3RequestError` names the operation and status only.

## Does not own
- Signing grants and the HTTP server cells PUT to: `apps/runtime/src/worker/evidence/`.
- Which refs a step keeps and the canary check of an upload: `apps/runtime/src/worker/run/run-evidence.ts`.
- SigV4 and the S3 config loader: `libs/runtime/contracts/sigv4.ts`, `evidence-s3.ts`. The key format: `libs/runtime/contracts/evidence.ts` `evidenceKey`.
- Reads for the browser: the API, with signed URLs.

## Rules and limits
- A key is always rebuilt from its parts (`evidenceKey`), so a path from elsewhere never reaches the disk or the bucket.
- Only the worker writes the evidence key; a cell's PUT after the take changes nothing. An object stored redacted carries a marker so a retried take still reports the leak.
- An oversized staging object is deleted unread. Errors and logs never carry a URL, a signature or a credential.
- The file store lives on one worker's disk: one replica only. S3 retention is the bucket's lifecycle rule, not a sweep.
- A sweep that cannot read its directory fails instead of reporting nothing past retention.

## Where new code goes
- A new evidence type: its kind and byte ceiling in `libs/runtime/contracts/evidence.ts` first, then here only if the store must treat it differently.
- A new S3 call: `S3ObjectClient`, with the AWS-example check in `libs/runtime/contracts/sigv4.spec.ts` if signing changes.

## Tests
- Unit: `API_NODE_ENV=test npx jest apps/runtime/src/shared/evidence` (S3 against an in-memory fake behind `fetch` that re-signs each call; `InMemoryEvidenceStore` in `testing.ts`).
- MinIO: `RUNTIME_IT_S3_ENDPOINT=http://localhost:9000 API_NODE_ENV=test npx jest apps/runtime/src/shared/evidence/s3-evidence-store.integration.spec.ts`.
