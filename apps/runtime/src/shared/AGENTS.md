# apps/runtime/src/shared

What the runtime-hub, the runtime-worker and the preview edge share, by concern. The root holds the few files every process needs at boot or on every call: the one config loader, the ids every side derives the same way, and the errors that cross the hub/worker boundary. It is a library of the control plane, not a process: it never imports `hub/` or `worker/` ([layering](../../AGENTS.md#layering)).

## Owns
- Configuration, read once and validated at boot: `config.ts` `loadRuntimeConfig` (hub), `loadWorkerConfig` (worker, adds `SetupConfig` through `loadSetupConfig`), `loadPreviewEdgeConfig` (edge); `assertSafeForProduction` refuses the dev switches in the production image; `workflowReleaseOf` names the DBOS application version per planner host; the DI tokens `RUNTIME_CONFIG`, `RUNTIME_PG_POOL`, `COMMAND_STORE`, `RUNTIME_RUN_PROJECTION_STORE`.
- Claim ids: `claim-id.ts` `claimIdFor` (org + idempotency key), `isSetupChildSuffix` (which `setup:<key>:<suffix>` claims belong to a setup's admission ticket).
- Errors the worker reads from the hub: `errors.ts` `CellUnavailableError` (a lost round, never a failed Run by itself), `HubUnreachableError`, `MemberCleanupPendingError`, `HubRefused` (a structured 409).
- `request-listener.ts` `requestListener`: a plain Node HTTP handler whose rejection ends the request (500, or a cut socket) instead of the process.
- Subfolders:
  - `admission/`: durable admission requests, the per-PR fences, the physical cell reservation (Postgres side).
  - `evidence/`: the evidence store port and its file and S3 adapters.
  - `identity/`: peer certificate identity and the internal routes' `WorkerAuthGuard`.
  - `observability/`: the JSON logger, spans, OTel setup and the process resource.
  - `persistence/`: schema and migrations, advisory locks, the command, preview and snapshot stores, the cell directory.

## Does not own
- Domain rules (protocol, gate, run state, sealed secrets, derived-id hashing): `libs/runtime` (`contracts/derive-id.ts` for `nulJoinedHex`).
- The claim's state and its store: `apps/runtime/src/hub/hub-store.ts`.

## Rules and limits
- Process environment: only `config.ts` reads it, plus the standard `OTEL_*` in `observability/` ([layering](../../AGENTS.md#layering)); `config-boundary.spec.ts` lists every allowed reader across the Runtime and fails on a new one.
- Test doubles stay out of production code; `testing-boundary.spec.ts` enforces it. Its one allowed exception is `config.ts` importing `../testing/dev-seal-key`, so a production worker refuses the dev seal key.
- Derived ids are stored across releases: `derived-ids.golden.spec.ts` pins claim, step, setup, lesson, preview, admission and workspace ids. Changing one strands stored rows and DBOS checkpoints.
- No TypeScript module may share its path with a `.json` file: ts-node would load the JSON (`module-resolution.spec.ts`).

## Where new code goes
- A new setting: a field of `RuntimeConfig`, `WorkerConfig` or `PreviewEdgeConfig` with its validation in the loader, a case in `config.spec.ts`, and a row in the README's config table.
- A new shared file: the subfolder of its concern, never the root.
- A new id derived from an org or key: keep the org in it, and add its value to `derived-ids.golden.spec.ts`.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/shared` (unit; the integration specs of the subfolders need `RUNTIME_IT_DATABASE_URL`).
