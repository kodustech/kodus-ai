# apps/runtime/src/shared/admission

Admission of Runs and setups before they take a cell: the durable admission requests (opt-in, `RUNTIME_DURABLE_ADMISSION`), the per-PR fences that decide which Run of a PR is current, and the Postgres side of a physical cell reservation (slots and the org's debit). Both the runtime-worker (admission workflows, command handlers) and the runtime-hub (ticket service) use it; it holds contracts and stores, no workflow.

## Owns
- The contract: `admission-contract.ts` `AdmissionStore` (accept, approve, take, defer, reserve, ticket, dispatch, start, finish, cleanup, due), `PhysicalAdmissionClient` (the worker's reservation port), the closed `AdmissionState` and `AdmissionReason` sets, `ADMISSION_WAIT_MS`, `ADMISSION_APPROVAL_MS`, `ADMISSION_BYTE_LIMITS`.
- The transitions, once for both stores: `admission-store.ts` `AdmissionStoreBase` (payload schema, dedupe by `canonicalAdmissionPayloadHash`, waiting and backlog bounds, fenced leases, shared Run/setup execution limits, a setup at most one per org). `PgAdmissionStore` (`pg-admission-store.ts`) supplies its transaction and reads on `runtime_admission_requests`.
- PR fences: `pr-admission-store.ts` `PgPrAdmissionStore` (`register`, `current`, `cancel`, `canCancel` over `runtime_pr_fences`, `runtime_pr_run_generations`, `runtime_pr_cancel_generations`), token `PR_ADMISSION_STORE`.
- Physical reservation: `physical-admission-directory.ts` `PgPhysicalAdmissionDirectory` (`reserve` a pair's slots on one cell under the org's advisory lock, `matches`, `pin`, `release`, `retarget`), on `runtime_cell_reservations` and `runtime_cell_sessions.free_slots`.

## Does not own
- The admission workflows and their maintenance: `apps/runtime/src/worker/dbos/admission-coordinator.ts`, `run-engine.service.ts`.
- The hub's ticket and its memory book (RAM granted per cell): `apps/runtime/src/hub/claims/ticket.service.ts`, `cell-memory.ts`.
- The worker's HTTP client of the reservation: `apps/runtime/src/worker/env/physical-admission-client.ts`.
- Cell choice without durable admission: `../persistence/cell-directory.ts`.

## Rules and limits
- Every write is tenant scoped and fenced by generation and `ticketOwnerToken`; an old worker lease is refused after takeover, the physical identity stays the same.
- No store transaction reaches the hub, the broker or DBOS. The quota is decided under one global advisory key (`admission_quota`); PR fences under the PR lock, reusing its connection through `LockScopedPg`.
- Payloads hold only sealed tokens: plaintext is refused, never stored or echoed ([secrets](../../../AGENTS.md#secrets)). `due` returns references, never payloads.
- A permit is freed only after cleanup is confirmed (`finishExecution`, `acknowledgeTicketCleanup`); expiry or cancellation alone keeps it.
- A cancel before accept is a tombstone: a later accept answers `cancelled`.
- A request's `isolation` minimum is never placed lower: `reserve` takes only cells whose hello isolation satisfies it and refuses `isolation_unavailable` (not retryable) when cells are there and none does; the hub's ticket service checks the cell again. Every Run and setup claim of the worker asks the deployment's `RUNTIME_ISOLATION_MINIMUM` when it names none (`HubEnvironmentClient`; `kernel` in the production image).
- Cleanup failures cross into logs only as `AdmissionCleanupFailureReason`, never remote text.

## Where new code goes
- A new transition: `AdmissionStoreBase`, so `InMemoryAdmissionStore` (`testing.ts`) and `PgAdmissionStore` share it, with a case in `admission-store.spec.ts` and `pg-admission-store.integration.spec.ts`.
- A new column: a migration in `../persistence/runtime-schema.ts`, and the payload hash stays pinned in `../derived-ids.golden.spec.ts`.

## Tests
- Unit: `API_NODE_ENV=test npx jest apps/runtime/src/shared/admission`.
- Postgres: `RUNTIME_IT_DATABASE_URL=postgres://… API_NODE_ENV=test npx jest apps/runtime/src/shared/admission --runInBand` (concurrent writers, cross-tenant isolation, epoch fencing, retention).
