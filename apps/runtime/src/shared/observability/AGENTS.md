# apps/runtime/src/shared/observability

Logs, spans and metrics plumbing for the three control-plane processes (runtime-hub, runtime-worker, preview edge). Each process calls `setupRuntimeOtel` before Nest starts and logs through `RuntimeLogger`. The metric set, the attribute taxonomy and the redaction rules are domain code in `libs/runtime/telemetry`; this module wires them.

## Owns
- `logger.ts` `RuntimeLogger`: one JSON object per line (`service`, `level`, `context`, `msg`, the active `traceId`/`spanId`); Nest's loggers write through it. `silentLogger` for tests.
- `diagnostic-fields.ts` `diagnosticFields`: a log line's fields made bounded JSON (string, node and byte budgets), older names written under their taxonomy key, sensitive keys and raw errors dropped, strings scrubbed.
- `tracing.ts` `inSpan` (a span around a call; a failure is recorded as a safe category, never its message) and `contextFromHeaders` (the W3C parent of a hub request).
- `otel.ts` `setupRuntimeOtel`: W3C propagation, OTLP or console traces behind `RedactingSpanExporter`, Prometheus metrics on the configured port.
- `resource.ts` `runtimeResource`, `parseResourceAttributes`: the process's `service.*` resource, with `OTEL_RESOURCE_ATTRIBUTES` and `OTEL_SERVICE_NAME` as the specification orders them.

## Does not own
- Metric names, labels and the taxonomy: `libs/runtime/telemetry` (`taxonomy.json`, `RuntimeMetrics`). The hub's own metrics: `apps/runtime/src/hub/hub-types.ts` `HubMetrics`.
- Secret scrubbing and the span exporter's filter: `libs/runtime/telemetry/telemetry-guard.ts`, `redacting-span-exporter.ts`.
- Alert rules and dashboards: `apps/runtime/observability/` (checked by `observability-as-code.spec.ts` here).

## Rules and limits
- `otel.ts` and `resource.ts` are the only files of the control plane besides `config.ts` that read the process environment, and only `OTEL_*` ([layering](../../../AGENTS.md#layering)).
- What may be logged and used as a label: [logs and metrics](../../../AGENTS.md#logs-and-metrics). The logger never throws: a getter, a cycle, a bigint, a revoked proxy or a broken sink is dropped, not raised.
- `@opentelemetry/resources` is deliberately not a dependency; the `Resource` type is taken from the SDK's config type (`resource.ts`).
- A flush that fails on shutdown never holds the exit.

## Where new code goes
- A new metric or log field name: the taxonomy in `libs/runtime/telemetry` first; an alert or panel that reads it, in `apps/runtime/observability/` with its runbook entry.
- A new process: a `RuntimeProcessIdentity` passed to `setupRuntimeOtel` from its `main.ts`.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/shared/observability` (no services). `telemetry-redaction.spec.ts` and `tracing.privacy.spec.ts` check that no secret or exception content leaves in logs, spans or metric labels; alert rules themselves run under `scripts/runtime/test-alert-rules.sh`.
