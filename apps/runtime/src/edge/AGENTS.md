# apps/runtime/src/edge

The preview edge, its own process (`runtime-preview-edge`, Docker target of the same name): it serves `*.<RUNTIME_PREVIEW_DOMAIN>` to browsers and proxies each request as an HTTP/2 stream over the tunnel a preview claim's cell dialed ([docs/runtime/preview-urls.md](../../../../docs/runtime/preview-urls.md)). It is the composition root and the adapter for that flow; it never talks to the hub or the worker, only to the Runtime Postgres and the cells' tunnels.

## Owns
- Boot: `main.ts` `bootstrap` (`loadPreviewEdgeConfig`), `edge-app.ts` `startPreviewEdge` (the browser listener, plain behind a TLS-terminating balancer or TLS here; the tunnel listener, always mTLS against the cell CA), `serveTunnels`.
- `preview-edge.ts` `PreviewEdge`:
  - `authorizeTunnel`: a cell certificate (OU=cell, the pinned serial) and a one-time ticket the hub issued to that same cell, spent whatever the certificate says.
  - `attachTunnel`: the tunnel as an HTTP/2 client session; a newer tunnel of the cell replaces the older; the holder row is kept by `startHeartbeat` every 30 s.
  - `handle`: the host's preview row and the viewer's session; revalidation after `RUNTIME_PREVIEW_SESSION_REVALIDATE_MINUTES`; the sleeping, starting, blocked and ended pages; a wake request; forwarding once to the replica that holds the tunnel (`PREVIEW_FORWARDED_HEADER`); `proxy`.
  - `/__kodus/session`: a GET shows the grant as a prompt; only a same-origin POST (`sameOriginPost`) spends the grant and sets the host-only cookie.
- `edge-pages.ts`: the edge's own HTML pages (`notFoundPage`, `startingPage`, `endedPage`, `reopenPage`, `blockedPage`, `confirmPage`).

## Does not own
- Preview rows, sessions, tickets, holders and the audit: `shared/persistence/preview-store.ts` `PgPreviewStore`.
- Grants, host labels and the cookie format: `libs/runtime/contracts/preview` (the API signs grants with the private key).
- Starting, waking and stopping previews: the runtime-worker (`worker/preview`). Issuing tunnel tickets and routes: `hub/claims/claim-preview.service.ts`.
- Settings: `shared/config.ts` `loadPreviewEdgeConfig`.

## Rules and limits
- Logs, metrics and audit rows carry no path, query, header value, cookie or grant: requests are counted by outcome only.
- The app never gets the edge's cookie, the viewer's address or a client `X-Forwarded-*`; the edge adds `frame-ancestors`, HSTS and noindex, and drops an app cookie that sets `Domain`.
- A viewer outside the org and an unknown host get the same 404: nothing says whether a preview exists.
- A grant is single-use and short-lived; a cross-site redirect to it opens nothing.
- The tunnel listener is never behind a TLS-terminating balancer. The grant key must be Ed25519 or the edge refuses to start.
- A holder row older than `HOLDER_FRESH_MS` (90 s) is never forwarded to.

## Where new code goes
- A new edge page: `edge-pages.ts`, with no third-party resource and the nonce script only.
- A new preview state the browser sees: `PreviewEdge` serve logic and the state in `libs/runtime/contracts/preview`.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/edge` (`InMemoryPreviewStore`, HTTP/2 tunnels in process).
- `preview-edge.go-tunnel.integration.spec.ts`: the Go cell's tunnel; opt-in with `RUNTIME_IT_GO_CELL=1` (`testing/go-cell.ts` `goCellEnabled`), then `go`, `docker` and `openssl` are required.
