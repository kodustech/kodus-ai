# apps/runtime/src/fleet/providers/boat

boat (boat.dev) as a host provider (docs/runtime/host-providers.md §9.2): one boat sandbox per Run host, created `from` the environment's saved snapshot with `noEnv`, `snapshots: false`, `monitoring: false`, `failFast`, a dead-man `ttlSeconds`, the installation, pool and host labels, and the bootstrap file in `files`. Saved snapshots for the environment template.

## Owns
- `boat-provider.ts` `BoatHostProvider`: create (with `Idempotency-Key`), get, list by label (cursor pages), extend (`PATCH ttlSeconds`), delete (with `X-Ascii-Confirm-Delete`), `GET /limits`, and `images` (saved snapshots).
- `boat-errors.ts` `mapBoatError`: boat's error codes to `ProviderError`.
- `testing.ts` `RecordedBoat`: the API as documented, **recorded from docs, not from the live API**.

## Does not own
- When a host is made, extended or destroyed: `../../per-run-host.ts`. The key: `shared/config.ts` (`RUNTIME_BOAT_API_KEY`).

## Rules and limits
- Plain `fetch`, no SDK. Never `exec`, `prompt`, `host`, `desktop`, `fork` or boat environments.
- Never logs or returns the key, a token, or a boat message; errors carry boat's code, the status and the wait.
- `destroy` reads the host first and leaves any host without this installation's label.
- A host is created only `from` a template; `snapshots: false` and `noEnv: true` are fixed by the class schema.
- Plans (17/11): the trial has no `large`, no saved snapshots, 2 at once and a 2-hour auto-stop; the $20 plan has 100 at once, 12/60/200 starts per minute/hour/day and 10 saved snapshots.

## Where new code goes
- A boat call: `boat-provider.ts`, its documented shape in `testing.ts`, a case in `boat-provider.spec.ts`.
- A boat error code: `boat-errors.ts` `BY_CODE` and the table in `boat-provider.spec.ts`.

## Tests
- `boat-provider.spec.ts` (conformance and errors on recorded responses); `boat-provider.live.spec.ts` only with `RUNTIME_BOAT_LIVE_TEST=1` and a key.
