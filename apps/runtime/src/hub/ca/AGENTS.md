# apps/runtime/src/hub/ca

The runtime-hub's internal CA: it signs the cells' short client certificates and reads their CSRs, with a hand-written DER writer and reader over node `crypto` (no X.509 library in `node_modules`). A pure helper module of the hub: `hub/enrollment` calls it to issue, `hub/runtime-hub.module.ts` loads the CA material, specs and the TS fake cell use it to make keys and CSRs.

## Owns
- `x509.ts` `parseCsr`: a PKCS#10 CSR read and its self-signature checked; returns the public key.
- `x509.ts` `issueClientCert`: CN = the cell id (or worker), OU = role, `clientAuth` only, valid for the given hours, a 16-byte random serial; the result is verified against the CA before it is handed out.
- `x509.ts` `createCa` (an ephemeral CA, only in test-only plaintext mode or specs), `createCsr` (fake cell and specs), `pemToDer`, `normalizeSerial` (one spelling of a serial for pins).

## Does not own
- When a certificate is issued, renewed, pinned or revoked: `hub/enrollment/cell-identity.service.ts`.
- Reading a peer certificate's CN/OU: `shared/identity/tls-identity.ts` `peerIdentity` (re-exported here).
- The Go cell's own key and CSR: `apps/runtime-cell`.

## Rules and limits
- ECDSA P-256 with SHA-256 only; any other key is refused.
- A CSR that is cut or truncated is refused without reading past its buffer.
- Callers never pass the parser's error to a cell: enrollment answers one generic `invalid_csr`.
- The hub refuses to start without `RUNTIME_TLS_CA` and `RUNTIME_TLS_CA_KEY` outside plaintext test mode (`runtime-hub.module.ts` `hubCa`). The DER code is not replaced by a library yet ([README](../../../README.md) "runtime-hub").

## Where new code goes
- A new certificate field or extension: `issueClientCert`, with a case in `x509.spec.ts` that reads the result with node's `X509Certificate`.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/hub/ca` (pure).
