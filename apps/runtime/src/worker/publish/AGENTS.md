# apps/runtime/src/worker/publish

How a Run hands its result to the product: one AMQP adapter of the `PublishRequester` port (`worker/run/ports.ts`) that publishes `RuntimePublishRequested` on `workflow.exchange` with the routing key `workflow.jobs.created.RUNTIME_PUBLISH`. It runs in the runtime-worker, inside the Run's publish steps; the product worker (`libs/runtime-publish`) posts the comment and the check (ADR-052).

## Owns
- `amqp-publish-requester.ts` `AmqpPublishRequester.request`: validates the message with `RuntimePublishRequestedSchema`, wraps it in the Runtime envelope (`runtimeEnvelope`, `workflowType` `RUNTIME_PUBLISH`), uses the publication key as `messageId`, and resolves only on the broker's confirm.
- `PUBLISH_CONFIRM_TIMEOUT_MS` (10 s): no confirm in time fails the step instead of hanging it.

## Does not own
- What is published and when (progress phases, report, check, replies): `worker/run/run-orchestrator.ts`, `worker/run/report.ts`, `worker/run/comment.ts`.
- Retrying a failed publish step: `worker/dbos/run-engine.service.ts` `PUBLISH_STEP_RETRY`.
- Rendering, the target and the Git calls: `libs/runtime-publish` ([README](../../../../../libs/runtime-publish/README.md)).

## Rules and limits
- The message carries structured fields only and never names a target; the publisher reads the target from its own store.
- The step that calls this is checkpointed only after the broker holds the message. A broker that answers `false` fails the step.
- The Runtime's broker user may publish on `workflow.exchange` only with this routing key ([libs/runtime-publish/README.md](../../../../../libs/runtime-publish/README.md) "Broker and database users").
- A retried step republishes the same key; the product's publication keys make it idempotent.

## Where new code goes
- A new field the product shows: `libs/runtime/run/run-messages.ts` (the schema) and the publisher's renderer, not here.

## Tests
- `worker/commands/commands.spec.ts` `AmqpPublishRequester` (confirm, deadline, refusal, structured report only): `API_NODE_ENV=test npx jest apps/runtime/src/worker/commands/commands.spec.ts`.
