# apps/runtime/src/worker/maintenance

The hang detector: once per maintenance tick, it reads every item that is not final (Runs, setups, claims, admissions, cell sessions, DBOS workflows), applies the bounds of `libs/runtime/health/stuck.ts` and reports what crossed them. It runs in the runtime-worker, on the replica that holds the maintenance lock, called last by `RunEngineService.maintenanceTick` (`worker/dbos`). It is described in [docs/runtime/observability.md](../../../../../docs/runtime/observability.md) part 4.

## Owns
- `stuck-detector.ts` `StuckDetector.pass`: one pass; a `runtime.stuck` log line the first time an item crosses its bound, `runtime.stuck.detected`, and the gauges of the last pass (stuck items, open claims, admission queue). `lastPass` keeps the last pass in memory (the API reads its own; tests use this).
- `StuckSource` and its production reader `PgStuckSource`: bounded reads of the Runtime Postgres (owner role) and DBOS's public status API.

## Does not own
- The bounds themselves: `libs/runtime/health/stuck.ts`.
- Acting on a stuck item: the sweep and the reaper in `worker/dbos/run-engine.service.ts` (`sweep`, `RunDependenciesFactory.reap`).
- Taking the maintenance lock and the 15 s schedule: `RunEngineService.maintenanceTick`.

## Rules and limits
- It never stops, releases or retries anything. What it sees is what the sweep and the reap missed.
- A source that fails is "not read" for that pass, never zero; the other sources are still reported.
- An item is reported once while it stays in its state; one that leaves and comes back is reported again.
- A replica that stops running passes reports 0, so alerts take the max over replicas.
- Log fields are ids, the state and numbers only ([apps/runtime/AGENTS.md](../../../AGENTS.md) "Logs and metrics").

## Where new code goes
- A new kind of item to watch: a read on `StuckSource` and `PgStuckSource` (bounded), its bound in `libs/runtime/health/stuck.ts`, its case in `stuck-detector.spec.ts`; `stuck-bounds.spec.ts` checks the bounds against the worker's and the hub's own constants.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/worker/maintenance` (no services).
