# apps/runtime/src/worker/intent

The Run's intent phase: for each finding the gate produced, whether the change looks unintended or uncertain, and the repository test a model `intended` points at. It runs in the runtime-worker, inside the Run workflow after the replay (`worker/run/run-orchestrator.ts`), as durable steps. It can only downgrade a finding's intent; it never changes a verdict, removes a finding or leads to success.

## Owns
- The classifier: `intent-classifier.ts` `IntentClassifier.classify` (one `runtime.intent` turn through the `LlmGateway`, apart from the agent and without its exploration), the answer held to its contract by `decide` (never `intended`: a model `intended` with a backing test is `uncertain` naming the test), and `downgrade` (unintended → uncertain → intended, never back).
- Which test a model `intended` may name: `intentEvidence` (a test that existed on base, not added or changed by the PR, ran and passed on both sides, and exercises the finding's entry point). It never clears a finding: the PR's machine runs it and the PR's code decides its exit code, and a pre-existing test passing on both sides is also what a regression the tests do not cover looks like (s1-security-crosscut S1-02). Only the diff (`libs/runtime/gate` `decideIntendedChange`) makes a finding `intended`.
- Classifying a Run's findings: `classifyIntents`, `INTENT_CONCURRENCY` (4) at a time, one step per finding (`intent:<i>:<probeId>`), started in index order. A finding the diff already explains arrives intended (`libs/runtime/gate` `decideIntendedChange`) and spends no turn.
- Running the tests the planner named: `test-runs.ts` `runPlannedTests` (a command outside the planned-test shape, `libs/runtime/contracts` `plannedTestCommandProblem`, never runs; reset to the side's pinned image or round snapshot, exec with `TEST_TIMEOUT_MS`, exit 0 = pass; one cast grant per side and step, read back for canaries).

## Does not own
- The verdict and the finding itself: `libs/runtime/gate`, `libs/runtime/run` `decideRunVerdict`.
- Which tests to run: the planner (`worker/agent`). When this phase runs: `worker/run`.
- Canary redaction and the leak error: `worker/canary`. Grant signing: `worker/run/run-evidence.ts`.

## Rules and limits
- Tests are internal evidence: they never decide a verdict, they only feed this classifier.
- An LLM error, a spent budget or an answer outside the three intents leaves the finding `uncertain`; only what the caller marks with `rethrow` (the canary detector) stops the Run.
- `pr_destabilizes_machine` is never intended.
- Only the outcome and the cast's ref are checkpointed; a test's output never leaves its step. A canary in a cast is redacted in the store and halts the Run.
- Step ids are the workflow's contract ([apps/runtime/AGENTS.md](../../../AGENTS.md) "Workflow code (DBOS)").

## Where new code goes
- A new kind of evidence for `intended`: `intentEvidence`, with a case in `intent-classifier.spec.ts` showing it cannot be faked by the PR.
- A change to the intent values: `libs/runtime/run` (`ProbeVerdict['intent']`) first.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/worker/intent` (recorded gateway, fake environment, no services).
