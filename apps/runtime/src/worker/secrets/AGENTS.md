# apps/runtime/src/worker/secrets

The runtime-worker's one way to open a sealed token: a `SecretOpener` port and its AES-256-GCM implementation over `libs/runtime/run/sealed-secret.ts`, keyed by `RUNTIME_SECRET_SEAL_KEY`. It runs in the runtime-worker; the adapters that call the hub or the product open tokens through it, inside the one call that sends them.

## Owns
- `sealed-tokens.ts` `SecretOpener` (`SECRET_OPENER`) and `SealedSecretOpener.open`: a sealed value, opened for what it is bound to (a runId, or a setup's key).
- `SealedSecretOpener.seal` and `sealedForInput`: a setup token that arrives plain (an older producer) is sealed at ingress, before DBOS stores it (`EnvironmentSetupRequestedHandler`, `worker/commands`).
- `setupTokenBinding`: a setup's tokens are bound to the setup command's `key` (a setup has no Run).

## Does not own
- The seal format and the binding check: `libs/runtime/run/sealed-secret.ts`. Sealing a Run's tokens: the product.
- Loading and validating the key: `shared/config.ts` (`loadWorkerConfig`).
- The calls that open tokens: `worker/env/hub-environment-runtime.ts` (repo tokens, in the acquire) and `worker/agent` (`http-llm-gateway.ts`, `http-model-turn.ts`, `http-run-plan.ts`, `worker-plan-client.ts`, `http-recipe-author.ts`, `http-setup-repo-tokens.ts`).

## Rules and limits
- Workflow inputs, step outputs and logs hold sealed values only; the plain value is never returned, stored or logged ([apps/runtime/AGENTS.md](../../../AGENTS.md) "Secrets").
- A token opened for another binding fails: a Run's token cannot be used for another Run, nor a setup's for another setup.
- An empty or absent token stays absent; `sealedForInput` never seals an empty string.

## Where new code goes
- A new token the worker opens: sealed by its producer and bound to the Run or the setup key; opened through `SecretOpener` in the adapter's call, and listed in the README's "Sealed tokens" section.

## Tests
- Through its callers: `worker/agent/http-*.spec.ts`, `worker/env/hub-environment-runtime.spec.ts`, `worker/setup/environment-setup.service.spec.ts` (`API_NODE_ENV=test npx jest apps/runtime/src/worker`).
