# apps/runtime/src/worker/evidence

The runtime-worker's evidence server for the file store: its own origin and port, serving one exact evidence key for a URL the API signed, and taking a cell's upload of one artifact with a grant the worker signed. It runs in the runtime-worker as a Nest lifecycle service; with the S3 store it does nothing (cells and browsers use presigned URLs, the bucket's lifecycle rule keeps retention). The two stores are compared in [README "Evidence"](../../../README.md#evidence).

## Owns
- Starting and stopping: `evidence.service.ts` `RuntimeEvidenceService` (file store only: the hourly 30-day sweep, and the server when `RUNTIME_EVIDENCE_PORT` and `RUNTIME_EVIDENCE_SIGNING_SECRET` are both set; uploads on).
- Reads: `evidence-server.ts` `evidenceRequestHandler` GET serves a signed, unexpired URL for its exact key (`verifyEvidenceSignature`), always as an attachment with a sandbox CSP; only screenshots and videos may be embedded by another origin.
- Uploads: PUT with an upload grant (`verifyUploadGrant`): the exact key, the declared content type the grant binds, at most the grant's bytes, before it expires, once (`UsedNonces` remembers nonces until expiry; an object already stored is never replaced).

## Does not own
- The stores: `shared/evidence` (`FileEvidenceStore`, `S3EvidenceStore`, `canonicalEvidenceKey`).
- Signing upload grants and writing step output, and reading uploads back for canaries: `worker/run/run-evidence.ts`.
- Signing read URLs: the API (`GET /runtime/runs/:id/evidence/:stepId`). Key, type and signature rules: `libs/runtime/contracts/evidence.ts`.

## Rules and limits
- No cookie, no session, no Kodus origin: HTML or JS from a PR never runs with any Kodus origin's rights. Every refusal is a 4xx without detail; a store failure is logged without the key.
- The declared content type must match exactly (no parameters, no sniffing); a stored type outside the evidence types is served as bytes.
- When the grant-nonce memory is full, uploads are refused rather than forgetting a live nonce.
- The file store lives on one worker's disk: one replica only. More replicas need `RUNTIME_EVIDENCE_STORE=s3`.

## Where new code goes
- A new evidence type: `libs/runtime/contracts/evidence.ts` (type, content type, byte ceiling), then the cell's upload and the Run page.
- Anything served to browsers beyond one signed key does not go here.

## Tests
- `API_NODE_ENV=test npx jest apps/runtime/src/worker/evidence` (a temporary directory, a real listener): signed reads, uploads with grants, the 30-day sweep, the dev route.
