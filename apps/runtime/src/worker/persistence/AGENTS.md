# apps/runtime/src/worker/persistence

The runtime-worker's read-only view of the hub's tables: which claims a Run holds, what their egress and the cell reported, and which claims the reaper must end. It runs in the runtime-worker and is a Postgres adapter of the `RunClaims` port (`worker/run/ports.ts`) and of `HardExpiredClaims` (`worker/dbos/run-deps.factory.ts`).

## Owns
- `pg-run-claims.ts` `PgRunClaims`:
  - `forRun`: the unreleased claims of a Run and their side.
  - `egressBlocked`, `securityViolations`: the egress events and the `security_violation` blockers the hub recorded for a set of claims, read by the Run between steps.
  - `hardExpiryOf`: a claim's hard expiry, by org and claim, so a restored claim is not trusted past it.
  - `hardExpired`: up to 100 unreleased claims past their hard expiry, oldest first (the reaper's input).
  - `replicasOfEnvironment`: the hub replicas holding a live bound claim of an environment (or of any environment of the org, for the org list), where `HubEgressPolicyPusher` sends an approved host.

## Does not own
- Writing claims, egress events or blockers: the hub (`hub/hub-store.ts`). Releasing a claim: `HubClaimReleaser` (`worker/env/hub-environment-runtime.ts`).
- The Run projection and setups: `libs/runtime/run/adapters`. Commands, locks and the cell directory: `shared/persistence`.

## Rules and limits
- No writes, ever: the hub is the only writer of `runtime_claims` ([apps/runtime/AGENTS.md](../../../AGENTS.md) "Claims").
- Tenant scope ([apps/runtime/AGENTS.md](../../../AGENTS.md) "Tenant scope"): `hardExpiryOf` and `replicasOfEnvironment` filter by org. Gap: `forRun`, `egressBlocked` and `securityViolations` take a run id or claim ids without `organizationId`; their callers pass ids of their own Run only.
- `hardExpired` reads across orgs by design (the reaper) and returns each claim's org, which the release then carries.

## Where new code goes
- A new read of a hub table: a method here, on the port in `worker/run/ports.ts` (and its in-memory double in `worker/run/testing.ts`), with the org in the query.

## Tests
- No spec of its own; the Run specs use the in-memory double (`worker/run/testing.ts`). `hub/pg-hub-store.integration.spec.ts` reads through it against real Postgres (`RUNTIME_IT_DATABASE_URL`).
