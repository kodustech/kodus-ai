# apps/runtime/src/testing

Test and dev code: helpers that specs across the Runtime share. Production code never imports it, with one exception the boundary spec allows ([layering](../../AGENTS.md#layering)).

## Owns
- `dev-seal-key.ts` `devSealKey`, `DEV_SECRET_SEAL_KEY_HEX`: the seal key of the local stacks and the specs. `shared/config.ts` imports it only so a production worker refuses it (the allowed exception in `shared/testing-boundary.spec.ts`).
- `isolated-database.ts`: a leased database per integration suite on the `RUNTIME_IT_DATABASE_URL` server, emptied on each lease instead of dropped. Used by the Postgres suites of `apps/runtime`, `libs/runtime` and `libs/runtime-publish`.
- `go-cell.ts` `goCellEnabled`, `buildGoCell`: the opt-in (`RUNTIME_IT_GO_CELL`) and build of the real Go cell for `hub/go-cell-hub.integration.spec.ts` and `edge/preview-edge.go-tunnel.integration.spec.ts`; opted in, a missing tool fails the suite.
- `setup-service.ts` `testSetupService`: an `EnvironmentSetupService` with an instant ready check and no capacity wait, plus `clockFrom`, for the `worker/setup` specs.
- `source-scan.ts` `sources`, `isTestCode`: the Runtime sources and what counts as test code, for the config and testing boundary specs.

## Rules and limits
- A new in-memory double goes in a `testing.ts` next to its port, not here; this folder holds helpers shared across modules.
