# Changing the cell

The cell runs code nobody trusts. Read `README.md` first for the package map and a claim's life. The root `AGENTS.md` writing rules apply to comments, PRs and issues here too.

Each module (a directory with source files) has its own `AGENTS.md`: what it owns, what it does not, its rules, where new code goes, and a generated map of what it imports and what imports it ([module-docs.md](../../docs/runtime/module-docs.md)). The system map, with where new code goes across the Runtime, is [architecture.md](../../docs/runtime/architecture.md). After adding, moving or re-importing a module, run `node scripts/runtime/module-docs.mjs --write`.

## Package boundaries

- Dependency direction:
  - `cmd/*` wires;
  - `internal/agent` orchestrates;
  - the ports (`driver`, `transport`, `hubclient`, `policy/control`) sit under it;
  - `protocol`, `redact`, `clock`, `metrics`, `telemetry` and `lifecycle` are leaves.

  A driver never imports `agent`. The data plane (`egress`, `resolver`, `injector`, `observer`) never imports the control side.
- The same roles as the product's hexagonal libs, in Go's idiom: `agent` is the application, the ports are the interfaces it is given (`driver`, `transport`, `hubclient`, `policy/control`), `drivers/*` are adapters, `cmd/*` is the composition root. A rule that needs no backend and no claim state is a pure package (`recipe`, `netguard`, `machinetrust`, `buildmirror`, `buildfingerprint`, `bakecatalog`, `agent/checkout`, `agent/admission`, `agent/provenance`): an adapter calls it, it never lives inside one. What only one driver needs but stands on its own is a subpackage of that driver (`drivers/dockergvisor/buildstate`, `buildcache`, `registry`), with its own tests and its own lock; the driver holds it as a field and hands it what it reads of the driver (ports, funcs). Sibling subpackages never import each other: the driver composes them. A driver never imports another driver (`TestADriverNeverImportsAnotherDriver`): code two drivers share is a package outside `drivers/`, as `dockercli` (the docker binary) and `composecmd` are.
- The agent is a router over its parts: a part with state of its own is a package with its own lock (`agent/claims`, `outbox`, `pool`, `admission`, `provenance`), and a part without state takes a narrow view of the claim, never the claim (`agent/evidence`), given what it needs at construction. `Agent.mu` guards the hub session only. A new concern is a new part, not another field and method on `Agent`.
- A claim's preparation is a list of steps on one `preparation` (`agent/prepare.go`), and a project's boot on docker-gvisor a list of steps on one `projectBoot` (`drivers/dockergvisor/up.go`). A new stage is a new step in that list, in its place in the order, not more lines in another step.
- Two drivers run machines on a Linux host, sharing packages, not one layer over two backends: `drivers/dockergvisor` runs gVisor containers (`isolation/gvisor`) on the host's Docker (`placement/docker`), and `drivers/microvm` runs Firecracker microVMs (`isolation/firecracker`, the microvm backend) on `placement/hostnet`. `isolation.Backend` is the port both backends implement; docker-gvisor holds its gVisor backend directly and has no firecracker branch. Claims, egress wiring, the build path, the registry, data copies and the sandbox pool stay in each driver. A backend or a placement never imports the agent, the hub client or a driver; a new backend is a new package under `isolation/`, never another branch inside a driver.
- `driver.MachineDriver` is the core every driver keeps, composed of small interfaces (`Describer`, `ClaimNetworker`, `MachineCreator`, `MachineKeeper`). A package that needs part of a driver asks for that part, in an interface of its own (`lease.Machines`, `pool.Machines`), never for the whole driver. A driver's own Docker port is split the same way (`drivers/dockergvisor/docker.go`), each method required: a Docker that lacks one does not compile, it never degrades at run time.
- The microVM path is `drivers/microvm` over `placement/hostnet` (a bridge per claim, a tap per machine, one nftables ruleset) and `isolation/firecracker` (jailer, reflink root, vsock). What runs inside a machine (`guest`, `guestinit`, `vsock`) and what builds its image (`rootfs`, `kit`) import nothing of the control side.
- `internal/preview` is the preview tunnel (docs/runtime/preview-urls.md §4.2): the routes the hub declared, the WebSocket the cell dials to the edge and the HTTP/2 server on it. The agent hands it a route with its upstream (the claim's observer `/v1/preview` proxy); it never imports the agent, the hub client, a driver or the data plane, and the observer never imports it. A stream reaches an app only through a live route of a ready preview claim, and only its http expose entry.
- The docker compose command line (argv per verb, shell quoting for a guest line) and how its output reads are `internal/composecmd`, one place for every driver: dockercli runs its argv on the host, microvm joins it with `DockerLine` for the guest agent, and both read service logs through `composecmd.ServiceLogs`. It never imports a driver. A new compose verb or flag goes there, never as a string in a driver.
- `internal/archrules` tests these boundaries on the import graph. A new boundary is a new rule there, in the same change as its line here.
- `cmd/*/main.go` only wires. A function in it that is more than glue belongs in a package with a test.
- Only `main` exits: it calls `run() error` and exits with `lifecycle.ExitCode` (a setting it refuses is a `lifecycle.Usage` error, exit 2), so every defer runs. No `os.Exit`, `log.Fatal` or exiting `must` anywhere else.
- Every goroutine has an owner that waits for it, with a deadline. A process's servers and loops run in a `lifecycle.Group` (`lifecycle.Run`, `lifecycle.ServeHTTP`, `resolver.ListenAndServe`); on SIGTERM or SIGINT they stop taking work and get the process's grace to end. The cell stops its agent, its sweep (`sweepExpired`, the one loop over `Parts.Sweeper`) and its loops, then closes its driver (`cmd/cell/serve.go`). A driver's work that outlives the call that started it (docker-gvisor's disk reclaim and remote cache pushes) runs in the driver's own group under the driver's lifetime, never on `context.Background()`, and `Shutdown(deadline)` lets it finish, then ends it at the deadline. A request's own goroutines are joined before it returns.
- A driver the cell runs is one entry of `drivers` (`cmd/cell/drivers.go`), keyed by its package's `Kind`: its gate, its settings check, its observer modes and its `Open` (`wire.go`). `selectDriver` resolves `-driver auto` and docker-gvisor's `-isolation-backend` (firecracker is the `microvm` entry) before it checks anything. A flag only some drivers read is in `flagOwners`, and the cell refuses it, set on the command line or in the config file, on any other driver. A new driver is a new entry and a new driver flag a line in `flagOwners`, never another `switch` on the driver's name. The config file sets any registered flag by its name (`applyFile`, `cmd/cell/config.go`), so a new flag needs no file field.
- What a driver can do beyond the core is one place: `driver.Parts` (`Baker`, `Resetter`, `Composer`, `Recipes`, `Pooler`, `Sandboxes`, `Snapshots`, `Sessions`, `Memory`, `Diagnoser`, `Sweeper` and the rest), a nil field being a capability it does not have. Each driver returns its own (`Driver.Parts()`), `cmd/cell` assigns them once to `agent.Config.Parts`, and `driver.Observed` hands every part back. A capability is never a flag next to its part (hello's `snapshotMemory` is `Parts.SnapshotsMemory()`, a bake `Parts.Bakes()`), never a method every driver stubs with `ErrUnsupported`, and never found by type assertion: a wrapper hides it. `archrules` (`TestNoCapabilityIsDiscoveredByTypeAssertion`) fails on a new assertion to an interface of the module. The cell's capabilities that are not the driver's are explicit fields of `agent.Config` (`Keys`, `Manifests`, `Secrets`, `DeniedEgress`, `Alerts`), and the reaper's orphan pass is `reaper.Reaper.Orphans`.
- A claim's mutable state lives in `agent/claims` behind the claim's lock. Read it through its methods, never by copying fields across goroutines.
- `Agent.Handle` runs on the WebSocket read loop: it validates and answers at once. Work that needs I/O before the answer goes through `hubclient.Later`; anything else goes through `goTracked`.
- Test fakes live in `internal/testing/` or in `_test.go` files. `driver/fake` is selectable only with `-dev`.

## Protocol

- Every protocol change starts in `libs/runtime/protocol` (zod). Then dump the schema and run `go generate ./internal/protocol`.
- Never edit `internal/protocol/types_gen.go`, `internal/protocol/constants_gen.go` or `schema/protocol.schema.json` by hand. A protocol constant (hello feature, bound, pattern, reserved name) comes from `constants_gen.go`, never a literal copied from TS.
- A zod refinement the JSON Schema cannot carry is mirrored in `internal/protocol/codec.go` or `strictjson.go`, with the same error code.
- Every new rule gets a fixture in `libs/runtime/protocol/fixtures` (new files only). It must pass both `go test ./internal/protocol/` and `API_NODE_ENV=test npx jest libs/runtime/protocol`.
- Parse date-time fields with `protocol.ParseTime` and write them with `protocol.FormatTime`. Never use `time.Parse(time.RFC3339, ...)` on a frame field.

## Untrusted input

- Every value from the hub, the checkout, the VM or the observer is untrusted, even after the schema accepted it.
- Ids become names and paths only after `claims.ValidID` or `driver.ValidateClaimID`. Build paths with `claims.WorkDir`, never by joining an id.
- The cell writes into a checkout only through `internal/checkoutfs` or an `os.Root`. A plain `os.WriteFile` into a checkout is a bug.
- A compose file from a checkout reaches gVisor only after `compose/sandbox.Apply`, and is checked again with `VerifyCanonical` before it starts.
- A claim of several repositories is `claim/ws/<alias>` (`checkout.PlanWorkspace`); its host paths resolve inside `ws/` only (`driver.UpRequest.WorkspaceRoot`, `sandbox.Options.Root`), and every one of its download tokens is revoked and redacted, the ones it never fetched too.
- `exec.cwd` stays inside the workspace (`agent/handle.go`). Repo URLs come from `gitsource`, built from validated parts.
- Nothing from the observer chooses a result's step, executor or image (`agent/steps.go`).
- `local-docker` reports isolation `none`. It must never run code you did not write, and never be enabled outside a developer's machine. Do not weaken its gate (`localdocker.Gate`) or the agent's isolation check (`agent.New`).
- Claim frames leave the cell only through `agent.deliver`, or `agent.deliverOnce` for a frame a newer one replaces (`claim.progress`: one try, on `goTracked`); both redact with `redactOutbound`. Never send a body around them, and never redact one on its own path.
- A ceiling only goes down: `kodus:hard-expires` is written once (`driver.MachineSpec.AllTags`) and the reaper honors it whatever renews. It is read only through `driver.Ceiling`, `driver.Expired` and `driver.ClampToCeiling`, on the tags the driver read from its backend, never a caller's ref; a missing or bad ceiling is already past. A driver's sweep (`driver.Sweeper`) and the reaper end a machine at its ceiling alone; `kodus:expires` is the lease manager's (`driver.LeaseLapsed`).
- A data snapshot belongs to one machine and dies with it. Nothing that must differ per round or per Run is made before the snapshot, and when pool machines are handed to claims, a snapshot never moves with a machine to another claim.
- A host denial lives in `netguard.DenyList`, which the proxy and the resolver both ask, never in one of them. Its zero value must keep refusing the Kodus list. Both read the operator's entries through `netguard.RegisterDenyFlags` and report `DenyList.Fingerprint` on each push answer (`control.Server.DenyFingerprint`); the agent's push fails when two differ (`control.ErrDenyListsDiffer`).
- A driver touches only this cell's machines and networks. `List` never returns another cell's, whatever the selector names. `Destroy`, `SetExpiry` and `ReleaseClaim` refuse another cell's with `driver.ErrNotOwned` after reading the owner from the backend, never from the caller's ref. What a driver does not offer is a nil part; a part that cannot do one kind of request (a sandbox with the cell's trust where `Capabilities.SandboxCellTrust` is false) fails with `driver.ErrUnsupported`.
- A bake takes only what a clean setup claim produced, and only through the pin the agent takes before it acks `image.bake`. Nothing from a PR claim is ever named `kodus-bake/...`: a PR's code never reaches a baked image or a pool. Reuse goes one way: a claim may take its environment's baked image when the fingerprint matches, never the reverse. A copy of an org's data (bake or restore) runs under the driver's runtime with no network. The build cache follows the same rule: everything reads the environment's, only a setup's workload (`MachineSpec.Setup`) writes. A setup that seeds the cache (`seedsCache`, the default branch's) promotes each build's cache when that build ends, so a setup that fails later still leaves the next one a warm build; a bake promotes only what a build left unpromoted (`promoteCache`). The build cache off the cell (`remotecache`, `cache_remote.go`) keeps the rule: only a seeding setup pushes, the cell moves the files (the builder never holds the store's credential or route), each org's caches live under its own repository prefix, and every pulled blob is checked against its digest before a build reads it. Shared bakes (`share.go`, `-gvisor-bake-share`) keep it too: only a bake pushes, after every blob of the image is checked for the setup claim's secret values; a claim pulls only by the digest the hub recorded, never a setup.
- A Run's canaries (the `canaries` of `claim.acquire`) are planted only in a Run's workload: the config slot in the services' env, the npmrc slot as the decoy file at `sandbox.DecoyTarget`; never in a setup's, which a bake may keep. They never go into a label, a tag, a log or a frame, and the cell does not redact them: the worker checks for them.
- The cell CA reaches a machine only for a claim with org secrets, or on a cell that inspects egress (`-egress-inspect`, `Config.InspectEgress`): `CellTrust` in that claim's `driver.UpRequest` and `driver.SandboxRequest`, never on a blank pool sandbox, and on a sandbox only from a driver whose `Capabilities.SandboxCellTrust` is true (one without refuses it with `driver.ErrUnsupported`). Only a machine its claim's own boot gave the CA is an inspect source (`ClaimInfo.CellTrusted`, `policy.ClaimPolicy.InspectSources`), and the image builder when the driver gives its RUN steps the bundle (the cell's own builder with the trust files, `ClaimNetwork.SourcesTrustCellCA`, `policy.Spec.BuildTrusted`); from any other (a pool machine) TLS to an inspected host stays SNI passthrough, counted by `kodus_egress_inspect_bypassed_total`. A builder that is not trusted reaches over TLS only its passthrough hosts (`policy.BuildRefuses`), and gets no secrets. Its files and variables are `machinetrust`'s; a compose file never mounts under `/etc/kodus`, and the cell's variables replace the file's and the recipe's.
- A recipe's env configures the app; it never changes what runs. A new rule of that kind goes in `recipe` (`isControlEnv`), so every cell enforces it, not in one driver. The names and prefixes it refuses are `libs/runtime/protocol/recipe-control-env.json`, which the worker reads too; `internal/recipe/recipe-control-env.json` is its byte copy (a test fails when they differ), so a new name goes in the libs file and is copied over.

## Tests

- Every driver passes `drivertest.Run` (`internal/driver/drivertest`) on a backend that keeps state: an in-memory cluster, daemon or account in its `_test.go`. A subject gives the driver's own `Parts`; with no `Parts.Sweeper` the suite runs the reaper. A driver that boots compose projects or code sandboxes also passes `drivertest.RunRequests`, which checks each field of `driver.UpRequest` and `driver.SandboxRequest` by what its backend shows. A rule every driver must keep goes in the suite, not in one driver's tests.
- What `Up` and `CreateSandbox` must honor is a field of their request (`driver.UpRequest`, `driver.SandboxRequest`), never a `context.Value`: ctx carries cancellation and the trace only.
- Every bug fix starts with a test that fails on the old code; say in the test's comment what it used to do.
- Run before pushing: `golangci-lint fmt`, `golangci-lint run ./...` and `GOOS=linux golangci-lint run ./...` (v2.15.0, config in `.golangci.yml`), `go vet ./...`, `GOOS=linux go vet ./...` and `go test -race -count=1 ./...`. A `//nolint` names its linter and carries a one-line reason, and only for a confirmed false positive.
- Time-based logic takes a `clock.Clock` (or a `now` func). Tests use `clock.Fake`, never real sleeps for retries or expiries.
- Unit tests of the agent use `newHarness` (`internal/agent/harness_test.go`). A part a test runs on its own (the sandbox pool: `h.runPool`) is stopped and joined in `t.Cleanup` before the test's directories go. End-to-end flows use `test/integration` against `testing/hubstub`.
- Anything that touches real Docker stays behind the `dockersmoke` build tag.

## Names, errors, logs

- Log events are `noun.verb[.outcome]` (`claim.acquire`, `step.result`, `hub.nack.sent`, `claim.renew.failed`). Log through the claim's logger (`claims.Claim.Log`), which carries cell, claim and run.
- Logs are structured (`log/slog`, JSON in production) through `telemetry.NewHandler`, which writes the taxonomy's field names (`claim` becomes `kodus.runtime.claim.id`, `libs/runtime/telemetry/taxonomy.json`), the active span's `traceId`/`spanId`, and no secret-shaped text. Name the phase (`claim.phase` with `phase` and `ms`). Mark what an operator must act on with `"alarm", true`.
- Never log, return in an error, or send a token, a key, a credential or a command's raw output. Output goes through `redact`; error text sent to the hub is clipped with `redact.Clip`.
- Errors carry their package (`gitsource: ...`) and wrap with `%w`. A prepare failure is `blockerErr(kind, signature, err)`: the signature is a stable snake_case name, the kind a protocol `BlockerKind`.
- Metrics are `cell_<subject>_<unit>` and counters end in `_total`. Label values come from a fixed set (kind, outcome, code), never from a host or an id.
- Exported names say what they do: `FetchExtractRevoke`, `HasLiveLease`, `Admit`. A function that records state is not called `Check`.
