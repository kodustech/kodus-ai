# apps/runtime-cell/internal/dockerignore

Decides which entries of a build context a `.dockerignore` leaves out, the way BuildKit does when it sends the context: a self-contained reimplementation of the frontend's parser and the file sync's matcher, slash-separated, for a Linux builder. A pure package; its one caller is `internal/buildfingerprint`, which hashes only what can reach a build.

## Owns
- `matcher.go` `Parse` (the file as the frontend reads it), `Compile`, `New`, `Matcher.Matches`.
- `walk.go` `Matcher.Walk`, `Walk.Visit`: a walk that skips a directory only when no later `!` pattern can bring an entry back (`prunable`).
- `pattern.go`: one pattern compiled as patternmatcher does, quirks included.

## Rules and limits
- Where this package and BuildKit could disagree, it keeps the entry in (`TestDisagreementKeepsTheEntry`): a caller may trust what it excludes never reaches a build, not that everything it keeps does.
- Files BuildKit refuses are refused here too (`TestBuildKitRefusesTheseFiles`).

## Where new code goes
- A BuildKit behavior it does not model yet: a case in `dockerignore_test.go` first (`TestPatternmatcherQuirks`, `TestDocumentedExamples`), then the rule.

## Tests
- `go test ./internal/dockerignore` (pure).
