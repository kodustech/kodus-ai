# apps/runtime-cell/internal/preflight

`cell preflight`'s checks: the host against what the cell assumes at run time, before it is installed or updated ([self-hosted.md](../../../../docs/runtime/self-hosted.md), "Host preflight"). One `Result` per check (`ok`, `warn`, `fail`, the reason and the fix), a text or JSON `Report`, exit 1 when a check failed.

## Owns
- `preflight.go`: `Result`, `Report` (`WriteText`, `WriteJSON`, `ExitCode`).
- `checks.go`: the checks and their stable names (`Name*`): `CheckGVisor` (Docker, its API, compose, runsc, claim limits, the data root, the disks), `CheckIdentity` (the cell certificate on this host's clock), `Memory`, `HostPolicy`, `Clock`, `MicroVM` (a fix for each line `firecracker.Missing` names), `FreeDisk`, `Loaded`, `Settings`.
- `network.go`: the `-network` checks and `RunNetwork` (all at once, a timeout each, one bound for the run, a hung check reported at its `Below` status): `CheckHub` (DNS, TCP, TLS 1.3 with the cell's certificate against the hub CA, then `GET /health`; no hello), `CheckImage` (on the host, or its manifest readable; no layer pulled), `CheckEgressContainer`, `CheckRegistry` (the store's own `Check`, `GET /v2/`), `CheckGit` (`GET` with no token, no redirect followed).
- `host.go` `FreeBytes` (the nearest directory that exists), `clock_*.go` `KernelClockSynced` (adjtimex, read only).

## Does not own
- Parsing the cell's settings, resolving the driver and wiring the real probes: `cmd/cell` (`preflight.go` `runPreflight`).
- The rules a driver enforces at start: the driver's own functions, passed in by `cmd/cell` (`dockergvisor.ValidateClaimLimitDaemon`, `ValidateClaimLimitEndpoint`, `microvm.Prerequisites`). This package picks no driver.
- Running preflight before a swap: `internal/cellupdate` (`StagedPreflight`).

## Rules and limits
- A check exists only for something the cell already needs: its comment names the runtime code that depends on it. A `fail` is what the cell refuses at start or what breaks every claim; a `warn` is what it starts with but runs worse.
- Checks read the host. The one write is the microVM cell's own reflink probe in its state directory (`firecracker.Missing`).
- The network checks only read too: no hello to the hub, no pull, no push, no token sent to a Git host. Each is a `fail` when every claim needs what it reaches (the hub, the Git API, the holder and observer images, the egress container) and a `warn` when only some claims or speed do (the other images, the registries).
- A refusal of a driver's rule that no named finding explains still fails, with the driver's words: preflight never passes what the cell refuses.
- Names are stable: docs and scripts grep them.

## Where new code goes
- A new requirement of a driver: its check here, with a test on a fake host, and the call in `cmd/cell/preflight.go`.
- A new line in `firecracker.Missing`: its fix in `microVMFixes` (`TestEveryMicroVMPrerequisiteTheBackendNamesHasItsOwnFix` fails until it has one).

## Tests
- `go test ./internal/preflight` (a fake Docker, fake disks and clocks, `testpki` certificates, `httptest` TLS servers on loopback for the hub and the Git API; no Docker, no root, no network off the host).
