# apps/runtime-cell/internal/rootfs

An OCI image to a microVM's root file system ([`docs/runtime/isolation-architecture.md`](../../../../docs/runtime/isolation-architecture.md) C3): the image's layers flattened as the OCI spec applies them, the guest agent added as the machine's init with its profile, and an ext4 image made from the result. Build tooling: `cmd/kody-kit rootfs` runs it where the microVM kit is built, never inside the cell.

## Owns
- Reading an image: `oci.go` `OpenLayout` (an OCI layout as a directory or a tar, what `docker save` and `buildx --output type=oci` write), `Layout.Layers` for one platform, each layer checked against its digest.
- Flattening tar to tar: `flatten.go` `Flatten` (whiteouts, opaque directories, hard links after their targets), `Options`, `Layer`, `GuestPath`.
- The ext4 step: `ext4.go` `MakeExt4` (`mkfs.ext4 -d` over the same tar), `CheckMkfs` (`MinE2fsprogs` 1.47.1), `SizeMB`, `Ext4`.
- The whole build: `build.go` `Build`, `TarLayer`, `List`.

## Does not own
- The guest agent's init, its profiles and its path: `internal/guestinit`.
- The kit's manifest and its verification by digest: `internal/kit`, `microvm-kit/`.
- Cloning the root per machine: `internal/isolation/firecracker`.

## Rules and limits
- Ownership and modes travel in tar headers, so nothing needs root.
- A layer path that would climb out of the root or break the tree is refused; a layer that is not its digest fails the build.
- A sandbox profile's root has no set-id bit, device node or FIFO: no way to become root in a code sandbox.
- zstd layers are refused (rebuild with gzip). Reproducible: what the builder adds is stamped with `Options.ModTime`.
- It imports nothing of the control side ([`../../AGENTS.md`](../../AGENTS.md) "Package boundaries").

## Tests
- `go test ./internal/rootfs`. The ext4 tests skip without `mkfs.ext4` (e2fsprogs 1.47.1 or later) and `debugfs`.
