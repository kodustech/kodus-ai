# apps/runtime-cell/internal/placement/docker

The docker Placement: machines are containers in the host's Docker and a claim's network is an internal bridge in a /24 of the cell's pool. The docker-gvisor driver holds it (`internal/drivers/dockergvisor`); it reaches Docker through `dockercli`.

## Owns
- `docker.go` `Placement` over the `Networks` interface (`dockercli.CLI` implements it): `CreateNetwork` (internal network, starts at the slot the claim id points to, moves on while Docker says the subnet is taken), `AttachEgress`, `DetachEgress`, `RemoveNetwork`, `NetworkLabels`.
- `ClaimSlot`: a slot's /24 and its upper half (Docker's dynamic range); `DefaultPool`.

## Does not own
- Running containers and gVisor: `internal/isolation/gvisor`, `internal/dockercli`.
- The order of a claim's network steps: `internal/drivers/dockergvisor/network.go`.

## Rules and limits
- A claim network is `internal` (no route out). It is removed only once the egress has left it.
- Dynamic addresses (the holder, the egress) only from the upper half; services take fixed ones in the lower half.
- `DefaultPool` repeats `netguard.DefaultClaimSubnets` and `hostnet.DefaultPool`: change all three together.

## Tests
- `go test ./internal/placement/docker` (an in-memory `Networks`).
