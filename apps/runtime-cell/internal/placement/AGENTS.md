# apps/runtime-cell/internal/placement

The Placement port ([`docs/runtime/isolation-architecture.md`](../../../../docs/runtime/isolation-architecture.md) C3): where a cell's machines live and how a claim's network is made, joined to the cell's egress and removed, under any isolation backend. The interface the two Linux drivers hold; `placement/docker` and `placement/hostnet` implement it.

## Owns
- `placement.go` `Placement` (`CreateNetwork`, `AttachEgress`, `DetachEgress`, `RemoveNetwork`, `NetworkLabels`) and `NetworkSpec` (name, key, labels, pool).

## Does not own
- Docker networks: `internal/placement/docker`. Bridges, taps and nftables: `internal/placement/hostnet`.
- The machines themselves: `internal/isolation` and its backends.

## Rules and limits
- A claim's network has no route out: the cell's egress joins it and is the only way out.
- A network takes a /24 of the pool; dynamic addresses come only from its upper half, the lower half is for fixed ones.
- A placement never imports the agent, the hub client or a driver ([`../../AGENTS.md`](../../AGENTS.md) "Package boundaries").

## Where new code goes
- A new placement: a subpackage implementing `Placement`, with tests of its own; a driver composes it.
- Something every placement must do: a method here, implemented by both subpackages in the same change.

## Tests
- No tests of its own: each implementation tests the contract.
