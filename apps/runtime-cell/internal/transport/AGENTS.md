# apps/runtime-cell/internal/transport

How the cell agent runs a command on a machine and uploads a checkout to it: the `Transport` port the agent is given, and its three implementations. `cmd/cell/wire.go` picks one per driver: `SSH` for aws-ec2, `Compose` for a driver that boots the checkout itself (docker-gvisor, microvm), `Local` for the fake cell and local-docker.

## Owns
- `transport.go` `Transport` (`Exec`, `Upload`), `Local` (each machine a directory under `Root`; commands run on the host, no isolation).
- `ssh.go` `SSH` (runs `kody-exec` on the VM over its private address, the request on stdin as JSON; `Upload`, `SetKeys`, `Forget`, `ClaimSecrets`, `PrepareClaim`) and `ClaimKeys` (`NewClaimKeys`, `UserData`, `AuthorizedKey`, `RedactionValues`).
- `compose.go` `Compose` (nothing to upload; exec goes to the driver, which runs it in the project's sandbox), `WorkspaceRel`, `Workspace`, `ErrNoExec`.

## Does not own
- The command runner on the machine: `internal/kodyexec` (`cmd/kody-exec`). What runs a command inside a gVisor or microVM project: the driver's `Exec`.
- Validating `exec.cwd` against the workspace before it gets here: `internal/agent/handle.go`.

## Rules and limits
- SSH keys are per claim, kept only in memory; the agent pins the VM's host key (`ssh.FixedHostKey`, ed25519 only), never trusts on first use. The client private key never leaves the cell, and the claim's private keys are handed to the redactor (S-51).
- Nothing from the hub is parsed by a shell on the cell side: the command line is fixed.
- An upload destination is a plain relative path; an upload that fails leaves no writer, and ends with its context.
- `Local` runs code on the host with no isolation: only for the fake cell and local-docker ([`../../AGENTS.md`](../../AGENTS.md) "Untrusted input").

## Where new code goes
- A new way to reach a machine: an implementation of `Transport` here, chosen in `cmd/cell/wire.go` for its driver.

## Tests
- `go test ./internal/transport` (an in-process SSH server with pinned keys).
