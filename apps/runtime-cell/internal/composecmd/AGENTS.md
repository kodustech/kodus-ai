# apps/runtime-cell/internal/composecmd

The docker compose command line every driver runs, as argv without the docker binary, and how its output reads. A pure package of the cell process: `dockercli` runs the argv on the host's docker, `drivers/microvm` joins it into one shell line for the guest agent (`DockerLine`), and `drivers/dockergvisor` and `drivers/localdocker` read service logs through it.

## Owns
- The argv per verb: `composecmd.go` `Project` (`Args`, `UpPrebuilt`, `UpBuild`, `BuildWith`, `UpBuilt`, `Exec`), `Ps`, `LogsWindow`, `Down`.
- Shell quoting for a guest line: `ShellQuote`, `ShellJoin`, `DockerLine`.
- Reading output: `parse.go` `ParseComposePs` (`ServiceState`), `ParseTimestampedLogs` (`TimedLine`).
- Service logs over any runner: `service_logs.go` `ServiceLogs` on a `LogRunner`, into `driver.ServiceLogLine`.

## Does not own
- Running a command: `internal/dockercli` on the host, the guest agent in a VM. Which compose file runs: `internal/compose`, `internal/compose/sandbox`.

## Rules and limits
- Nothing here runs a command, and it never imports a driver ([`apps/runtime-cell/AGENTS.md`](../../AGENTS.md) "Package boundaries").
- A joined line reaches the program word for word (`TestAJoinedCommandLineReachesTheProgramWordForWord`).

## Where new code goes
- A new compose verb or flag: a function here with its case in `TestEachVerbIsTheComposeCommandLineTheDriversRun`, never a string in a driver.

## Tests
- `go test ./internal/composecmd` (pure).
