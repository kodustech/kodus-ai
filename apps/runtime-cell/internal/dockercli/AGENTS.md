# apps/runtime-cell/internal/dockercli

The one adapter to the `docker` binary on the cell's host. `drivers/dockergvisor` (and its `registry`), the dev-only `drivers/localdocker`, `isolation/gvisor`, `placement/docker` and `cmd/reaper` reach Docker only through `CLI`. It runs in the cell process; it knows no claim, only the containers, networks, volumes and images a caller names.

## Owns
- Running the binary: `dockercli.go` `CLI`, `ExecCommand`, `ExecCommandWith`, `MinimalEnv` (only `passEnv` reaches docker), bounded stdout, `ExitError` with a redacted tail of stderr; `daemon_says.go` (`NoSuchImage`, `NoSuchContainer`, `NotConnected`, `PoolOverlap`).
- Holders and sandboxes: `dockercli.go` `HolderSpec`, `RunHolder` (runtime, claim network, no capability, read-only root, the cell's resolver, `ValidDiskSize`); `sandbox.go` `SandboxSpec`, `SandboxArgs`, `RunSandbox`, `ExecStream` (the guest agent's stream over docker exec).
- Builds: `dockercli.go` `BuildRun`, `RunBuild` (rootless BuildKit in a container on the claim network, plain progress, the cell trust bundle and secrets by id when asked); `builder_log.go` `ReadBuilderLog`; `registry.go` `BuildPush`, `BuiltDigest`, `RunRegistry`, `PullImage` (by digest only).
- Loading a built image: `image_tarball.go` `LoadImage`, `CheckImageTarball` (exactly the one image asked for, bounded size and entries).
- Compose verbs over `composecmd` argv: `ComposeProject`, `ComposeUp`, `ComposeBuild`, `ComposeExec`, `ComposeLogs`, `ComposePs` and the rest; `Exec`, `ExecArgs` for a `kodyexec.Request` in a container.
- Networks, volumes and labels: `NetworkCreate`, `NetworkConnect`, `Volumes`, `VolumeRemove`, `List`, `Inspect`, `LabelsOf` (every container's id, names and the labels asked for in one `docker ps`, each value printed through the template's `json`, so a label cannot forge a field; what the driver's ownership check reads); tag/label spelling `LabelFromTag`, `TagFromLabel`, `CeilingTags`.
- Image metadata, local only: `image_labels.go` `ImageLabels`, `image_config.go` `ImageConfig` (env, entrypoint, command; bounded).
- Data copies under the runtime with no network: `copy_helper.go` `CopyVolumeBound`, `CopyVolumeGeneration` (generation markers never read through a link), `CopyVolumeIn`.
- Host resources: `cgroup.go` `ValidateCgroupParent`, `CgroupInfo`, `DaemonEndpoint`; `iobound.go` `IOBound` (blkio and tc on the host veth, `ShapeNetwork`), `DataRootDisk`.

## Does not own
- The compose command lines and how their output reads: `internal/composecmd`.
- Which compose file is allowed: `internal/compose/sandbox`. What a driver does with these calls: `internal/drivers/*`.

## Rules and limits
- A command never inherits the cell's environment unless the caller hands one: compose would interpolate `${VAR}` from it (`TestCommandsDoNotSeeTheCellsEnvironment`).
- Output read into memory is bounded (`maxStdout`); an error carries only a redacted tail of stderr (`redact`, `TestErrorsCarryARedactedTailOfStderr`).
- What a build leaves is untrusted: a tarball naming another image is refused before `docker load`, and a built digest is parsed as untrusted text.
- A failed or cancelled copy is not proof its helper stopped: `CopyVolumeBound` removes it by name and returns `driver.ErrResourceCleanupPending` when it cannot confirm.
- `output.go` `WithOutput` is the one `context.Value`: the tee of a boot's stderr lines to `UpRequest.Output`, inside the adapter; no input travels that way ([`AGENTS.md`](../../AGENTS.md) "Tests").

## Where new code goes
- A new docker call: a method on `CLI` here, with an argv test through a recording `CommandRunner`. A compose verb or flag goes in `composecmd` first.
- A docker fact only one driver needs still goes here; the driver's own Docker port (`drivers/dockergvisor/docker.go`) lists the methods it uses.

## Tests
- `go test ./internal/dockercli`: argv and parsing against recorded runs, no Docker.
- Real Docker: `go test -tags dockersmoke -run TestSmokeSandbox ./internal/dockercli/` (needs a sandbox image; see `sandbox_smoke_test.go`).
