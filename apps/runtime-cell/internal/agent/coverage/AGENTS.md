# apps/runtime-cell/internal/agent/coverage

The answer to `claim.exercised` (feature `exercisedLines`): which of a PR's changed lines a Run claim's Node services ran during the probes. A stateless part of the agent, in the cell process; it sees a claim only as `coverage.Claim` (logger, workload, instrumented services, coverage directory, checkout), built by the agent's `exercised.go`.

## Owns
- `coverage.go` `Prepare`: the claim's coverage directory (`claim/coverage`, writable by any uid of its services), capped through a `Capper`, and the flush preload (`claim/coverage-preload.cjs`, `compose.PreloadSource`), beside the checkout and removed with the claim; `Release` takes the cap off first.
- `cap.go` `Capper`, `DirBytes` (65 MiB, just above `exercised.MaxCoverageBytes`), `DirFiles` (256), `FakeCap` for tests. `tmpfs_linux.go` `Tmpfs`: a tmpfs with `size`, `nr_inodes`, `mode=1777`, `nosuid,nodev,noexec` mounted over the directory, refused unless the cell shares the init process's mount namespace (Docker resolves bind sources there); `Recover` unmounts what a stopped cell left under `<workdir>/claims`. Other hosts cap nothing.
- `Counter.Count`: the flush through `driver.CoverageFlusher`, the wait on `clock.Clock` until the coverage files stop growing (at most `MaxWait`, 3 s), `exercised.Answer` over the checkout (`checkoutfs.Read`, 16 MiB a file), and the step result's `exercised`. One mapping at a time on the cell (`Counter`'s slot), for at most `MaxMeasure` (30 s): a count whose step ends waiting, or that runs past it, answers `coverage_too_large`. Coverage no V8 writes (`exercised.ErrUntrusted`) answers every JS file measured with 0 run and logs `claim.exercised.untrusted` with an alarm.

## Does not own
- Which claims are instrumented and the frame's admission: the agent (`exercised.go`, `collectsCoverage`, `admitStep`). The env the services get: `compose.AddNodeCoverage`; the mounts: `compose/sandbox` (`Options.Coverage`), set by the driver from `driver.UpRequest.Coverage`.
- Reading V8 coverage and source maps, and the bounds on what is read: `internal/exercised`.

## Rules and limits
- A directory that cannot be capped is never handed to the services: `Prepare` returns `ErrUncapped` and the agent boots the claim uninstrumented. The services write it as a bind, outside their `storage_opt` cap.
- `Count` never fails: no flusher is `unsupported_driver`, a failed flush, no instrumented service or a panic leave every file unknown. Logs carry counts only, never a path, a service name or a command's output.
- Only counts leave the claim; the coverage files stay in its directory.

## Tests
- `go test ./internal/agent/coverage`; the agent's `exercised_test.go` covers the frame end to end on `newHarness`.
