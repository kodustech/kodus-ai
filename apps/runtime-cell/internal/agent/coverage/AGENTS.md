# apps/runtime-cell/internal/agent/coverage

The answer to `claim.exercised` (feature `exercisedLines`): which of a PR's changed lines a Run claim's Node services ran during the probes. A stateless part of the agent, in the cell process; it sees a claim only as `coverage.Claim` (logger, workload, instrumented services, coverage directory, checkout), built by the agent's `exercised.go`.

## Owns
- `coverage.go` `Prepare`: the claim's coverage directory (`claim/coverage`, writable by any uid of its services) and the flush preload (`claim/coverage-preload.cjs`, `compose.PreloadSource`), beside the checkout and removed with the claim.
- `Counter.Count`: the flush through `driver.CoverageFlusher`, the wait on `clock.Clock` until the coverage files stop growing (at most `MaxWait`, 3 s), `exercised.Answer` over the checkout (`checkoutfs.Read`, 16 MiB a file), and the step result's `exercised`.

## Does not own
- Which claims are instrumented and the frame's admission: the agent (`exercised.go`, `collectsCoverage`, `admitStep`). The env the services get: `compose.AddNodeCoverage`; the mounts: `compose/sandbox` (`Options.Coverage`), set by the driver from `driver.UpRequest.Coverage`.
- Reading V8 coverage and source maps, and the bounds on what is read: `internal/exercised`.

## Rules and limits
- `Count` never fails: no flusher is `unsupported_driver`, a failed flush, no instrumented service or a panic leave every file unknown. Logs carry counts only, never a path, a service name or a command's output.
- Only counts leave the claim; the coverage files stay in its directory.

## Tests
- `go test ./internal/agent/coverage`; the agent's `exercised_test.go` covers the frame end to end on `newHarness`.
