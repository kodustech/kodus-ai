# apps/runtime-cell/internal/agent/pool

The cell's warm pool (S-52): `pool.target` asks the cell to keep `size` clean machines ready for an environment, made from the environment's bake. A part of the agent with its own lock, in the cell process. It makes machines through the driver's `driver.Pooler` and knows no claim: the agent asks for a machine and adopts what it hands out.

## Owns
- `pool.go` `Manager`: `SetTarget` (record and fill or drain), `FollowBake` (replace the pool's machines with the new image's), `Refill`, `RefillAll` (housekeeping retries a failed fill), `Take` and `Has` (same org, environment, image and size, a ceiling no earlier than the claim's), `Discard`, `Ready`, `Environments`, `Target`.
- `ClaimSize`: the machine size a `pool.target` asks.
- The pool's own view of the driver: `Machines` (`Destroy`, `ReleaseClaim`), never the whole driver.

## Does not own
- Whether a claim may start from the pool (provenance, taint, the bake it asks): `internal/agent` `pool_claims.go`, `internal/agent/provenance`.
- How a pool machine is made: the driver's `Pooler`.

## Rules and limits
- A pool machine is used once and destroyed on release like any other; it never goes back.
- A setup claim never starts from a pool machine (`Request.Setup`): it holds the previous bake's data.
- A `nil` `Pooler` is a cell with no pool: targets are recorded, nothing is made or handed out. Nothing is made while `Accepting` is false.
- Background fills run through `Config.Go`, which the cell joins at shutdown.

## Tests
- `go test ./internal/agent/pool` (fake clock); the agent's harness runs it on its own with `h.runPool` (`internal/agent/harness_test.go`).
