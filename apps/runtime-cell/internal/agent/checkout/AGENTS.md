# apps/runtime-cell/internal/agent/checkout

What the cell reads from and writes into a claim's checkout before anything boots. A pure package called by the agent's preparation (`internal/agent/prepare.go`, the code step) in the cell process: it has no claim state and returns plain errors, which the agent turns into blockers.

## Owns
- `recipe.go` `ApplyRecipe`: the default branch's recipe replaces the checkout's `.kodus/workspace.yaml` (a PR's edit never changes how its own code boots); content null removes the checkout's copy; no recipe in the claim (an older hub) leaves it.
- `authored_files.go` `WriteAuthoredFiles`: Kody's authored build files under `.kodus/`, created exclusively; a file already there fails the claim unless it has the same bytes.
- What the checkout pins for the mirror: `gopins.go` `GoSumPins` (`go.sum`, `go.work.sum`), `imagepins.go` `DockerfileImagePins` (Docker Hub images of every Dockerfile's `FROM`).
- A claim of several repositories: `workspace.go` `PlanWorkspace`, `Workspace`, `Member` (`claim/ws/<alias>`, the primary first, at most `MaxWorkspaceRepositories`).

## Does not own
- The recipe's format and rules: `internal/recipe`. The authored file rules: `internal/protocol` (`CheckAuthoredFiles`, `AuthoredFilePath`).
- Fetching each member: `internal/agent` `workspace.go` and `internal/tarball`. Writing the cell's other files into a checkout: `internal/checkoutfs`.

## Rules and limits
- A Run's checkout is the PR's. `.kodus` must be a real directory this cell owns, opened with `O_NOFOLLOW`; every open is relative to it; the recipe replaces the entry at its path by an atomic rename of a file created beside it, never by writing through it. See [`apps/runtime-cell/AGENTS.md`](../../../AGENTS.md) "Untrusted input".
- Pins read regular files only (no symlink followed), skip `node_modules` (and `vendor` for Dockerfiles), and past their bounds (500 `go.sum` files, 32 MB) refuse the checkout rather than half pin it.
- An authored file error names the path and a fixed reason, never repository text: the product's card shows it.

## Where new code goes
- Anything new the cell reads or writes in a checkout before the boot: a file here with its test of planted links and FIFOs, called from a step of `prepare.go`.

## Tests
- `go test ./internal/agent/checkout` (temporary directories; links, FIFOs and same-bytes cases).
