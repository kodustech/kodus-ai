# apps/runtime-cell/internal/recipe

The environment recipe, `.kodus/workspace.yaml`: how a checkout boots, in the format Runo reads, and the rules every cell enforces on it. The product sends the default branch's recipe in `claim.acquire`; the agent writes it into the checkout over the PR's copy (`internal/agent/checkout`), and the drivers and `internal/compose` read it from there. A pure rule package: what one driver supports is that driver's business.

## Owns
- The format and its parse: `recipe.go` `Recipe`, `Services`, `Compose`, `ExposedPort`, `Data`, `Seed`, `Parse` (bounded by `yamlbound` first, known fields only, Runo's short forms normalized), `Load` (resolved inside the checkout), `Path`.
- Boot questions: `HealthTimeout` (capped at `MaxHealthTimeout`), `PublicHTTP`, `SeedsData`, `ResetStrategy`, `HasBootSteps`, `Unapplied` (keys no cell acts on: `flags`, `llm`, `ui`).
- The rules every cell enforces: `validate.go` `validate` (paths inside the repo, no secrets in `services.compose.env` except Kodus test values, no control env names: `isControlEnv` over the embedded `recipe-control-env.json`).
- Other repositories beside this one: `needs.go` `DeclaredNeeds`, `Need`, `AliasOf`, `NeedsConflict`, `MaxNeeds`.
- Declared local fakes: `fakes.go` `FakeServices`, `RequirePinnedFakes`. Resources and egress hosts: `resources.go` `SizeRequirement`, `EgressRequirements`. Named validations: `validation.go` `ValidationChecks`. The `suite:` block (the repository's own e2e suite, which the worker runs; the cell only holds the same verdicts and does not list it as unapplied): `suite.go` `checkSuite`.

## Does not own
- Laying the recipe over the checkout and the authored files: `internal/agent/checkout`.
- Reading and adapting the compose project: `internal/compose`, `internal/compose/sandbox`.
- The product's copy of the rules and the recipe's JSON Schema: `libs/runtime/protocol/recipe.ts`.

## Rules and limits
- A recipe's env configures the app, never changes what runs ([`../../AGENTS.md`](../../AGENTS.md) "Untrusted input"). `recipe-control-env.json` is a byte copy of `libs/runtime/protocol/recipe-control-env.json` (`TestControlEnvListIsTheWorkersCopy`).
- Runo's services mode (a service with `image` or `run`) is refused: a cell boots a compose project.
- A recipe linked out of the checkout is refused, never read. A recipe over `yamlbound`'s bounds, or an alias bomb, is refused before parsing.
- Fake images must be pinned by digest at execution (`RequirePinnedFakes`). `ResourceSize.DiskGB` is parsed but must be refused until a backend can enforce it.
- The worker holds the same verdicts: `TestRecipeContract` reads `libs/runtime/protocol/fixtures/recipes/verdicts.json`.

## Where new code goes
- A new recipe key: `Recipe` here and `libs/runtime/protocol/recipe.ts`, with a case in the recipe fixtures. A key no cell acts on yet goes in `Unapplied`.
- A new control env name: `libs/runtime/protocol/recipe-control-env.json`, copied here.

## Tests
- `go test ./internal/recipe` (pure; reads the libs fixtures from the repository).
