# apps/runtime-cell/internal/claimlimits

One cgroup v2 budget (memory, CPU, pids) for the whole container subtree of a claim on a docker-gvisor cell: the aggregate ceiling every service, builder and holder of that claim runs under. It runs in the cell process; `cmd/cell` opens it (`claim_limits.go` `configureClaimLimits`, `-gvisor-claim-limits`, `-gvisor-claim-limit-backend`) and `drivers/dockergvisor` holds it as `Config.ClaimLimits`.

## Owns
- The port: `limits.go` `Limits`, `Manager` (`Ensure`, `Verify`, `Remove`), `systemd.go` `Lifecycle` (adds `Resizer`, `PruneEmpty`, `RequireEmpty`, `Close`), `ErrUnavailable`.
- Lowering a ready claim's memory: `resize.go` `Resizer` (`Lower`, `Usage`), `Usage.WorkingSetBytes` (memory.current less the file cache that is not shmem). The cgroupfs backend writes memory.max; the systemd one sets `MemoryMax` over D-Bus. Both read the result back.
- The cgroupfs backend: `limits.go` `FS` over a dedicated, operator-delegated root; `fs_linux.go` `New` (directory descriptors, `O_NOFOLLOW`, bounded reads, a lock on the root).
- The systemd backend: `systemd.go` `Systemd`, one slice per claim under the cell's root slice (`RootSliceName`), over one D-Bus connection (`systemd_linux.go` `NewSystemd`); `systemd_properties.go` the exact unit properties it writes and reads back.
- Which parent a container may name: `ValidateParent` (cgroupfs path), `ValidateDockerParent` (that or a generated slice name), used by `dockercli` and `compose/sandbox` before any docker call.

## Does not own
- The size of a claim's budget and when it is made or removed: `drivers/dockergvisor/claim_limits.go`.
- The per-container limits compose forces: `internal/compose/sandbox`. The microVM path, whose limits are the VM's own: `isolation/firecracker`.

## Rules and limits
- Fail closed: a budget is returned only after it is written and read back whole; a mismatch, a foreign unit or a changed ceiling refuses before any change (`TestReadbackMismatchRefusesParent`, `TestSystemdRefusesChangedCeilingsAndForeignUnitsBeforeMutation`).
- `Ensure` never changes an existing budget (`TestEnsureNeverChangesExistingBudget`). Only `Lower` changes one: its memory, only down (`TestLowerNeverRaisesTheCeiling`). A launch after a `Lower` names the lowered ceiling. The systemd slice's description hashes the CPU and pids ceilings, not memory, because a running unit's description cannot change with its `MemoryMax`. Only empty groups this manager owns are removed.
- Keys are generated identities, never a path from a checkout, a hub frame or a Docker label.
- It never creates or delegates its root or touches ancestors: the operator delegates it first. At startup the cell prunes, then requires an empty managed tree before admitting a claim.
- Pids counts host tasks (the gVisor Sentry included), not guest processes. The Docker daemon, image loads and the cell's own processing stay outside the budget.
- Off Linux, `New` and `NewSystemd` return `ErrUnavailable`.

## Where new code goes
- A new resource in the budget: a field of `Limits`, its file in `Limits.values` and its property in `systemd_properties.go`, each read back.

## Tests
- `go test ./internal/claimlimits`: both backends on modelled filesystems and buses; the Linux descriptor rules run on Linux.
- On a Linux host with a delegated cgroup: `go test -tags dockersmoke ./internal/claimlimits` (`kernel_smoke_test.go`; `TestKernelLowerReclaimsFileCacheWithoutKilling` lowers memory.max below memory.current and checks that the kernel drops cache with no `oom_kill`). A transient delegated unit works as the root: `systemd-run --wait --pipe -p Delegate=yes` running a script that moves itself into a leaf and passes a sibling as `KODY_CGROUP_TEST_ROOT`; `test/fixtures/systemdproof` is an explicitly invoked fixture: two runsc scopes sharing one systemd claim budget.
