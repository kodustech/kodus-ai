# apps/runtime-cell/internal/checkoutfs

The way the cell writes, removes and reads its own files in a checkout. The checkout is the PR's code, so any name in it may be a symlink the PR planted; every path step here resolves inside the checkout (`os.Root`). A leaf used by the drivers in the cell process.

## Owns
- `checkoutfs.go` `Replace`: what the checkout had under the name (file, directory link or symlink) is removed, then a new regular file is created exclusively.
- `Remove`: deletes a name without following a symlink out of the checkout.
- `Read`: at most `limit` bytes, `ErrTooLarge` past it; a symlink to a file outside the checkout is refused, never read.

## Does not own
- Which files the cell writes (the compose file, the recipe, Kody's build files): the drivers and `internal/agent/checkout`.
- The rule that every write into a checkout goes through here or an `os.Root`: [package rules](../../AGENTS.md), "Untrusted input".

## Rules and limits
- Callers today are `internal/drivers/dockergvisor` and `internal/drivers/localdocker`; other modules that touch a checkout open their own `os.Root`.

## Tests
- `go test ./internal/checkoutfs`: a planted symlink, paths outside the checkout, the read bound.
