# apps/runtime-cell/internal/gitsource

Where the cell gets a claim's code from: the forge API that serves the tarball at a SHA, and the call that revokes the claim's download token once the code is in. It runs in the cell process; `cmd/cell` builds it from its configured API base and hands it to the agent.

## Owns
- `github.go` `GitHub.TarballURL`: `GET /repos/{owner}/{repo}/tarball/{sha}`, refused unless the claim names this API base, an owner/repo of plain segments and a full commit SHA.
- `GitHub.Revoke`: `DELETE /installation/token` with the token itself; a 401 means it is already gone. A personal access token (`ghp_`, `github_pat_`) is never sent: a `-dev` cell keeps it (`KeepPersonalTokens`), any other cell refuses it (`ErrPersonalToken`), so the claim fails.

## Does not own
- Downloading and extracting the tarball, and revoking on every path: `internal/tarball` and `internal/agent`.
- Minting the token: the product side, which sends it in `claim.acquire`.

## Rules and limits
- Repo URLs come only from here, built from validated parts on the one configured API ([package rules](../../AGENTS.md), "Untrusted input").
- Only GitHub (and GitHub Enterprise's `/api/v3`) is implemented.

## Where new code goes
- Another forge: a new type next to `GitHub` with the same two methods and its own validation tests.

## Tests
- `go test ./internal/gitsource` (`httptest`). `test/integration` and `test/fcregress` use it end to end.
