# apps/runtime-cell/internal/guestinit

What the guest agent does as a microVM's first process (C4, [isolation-architecture.md](../../../../docs/runtime/isolation-architecture.md)): read the machine's profile baked into the image and the boot values on the kernel command line, mount what the machine needs, start Docker in an environment machine, run the guest agent's server on vsock under the profile's user, reap orphans, and serve the cell's snapshot steps. It runs inside the machine as PID 1 (`cmd/kody-guest`); the cell side imports its types to write the command line and talk to its control port.

## Owns
- The rules as plain data, tested without a VM: `guestinit.go` `Profile` (`SandboxProfile`, `EnvironmentProfile`, `ProfileByName`), `Boot` with `Cmdline` and `ParseCmdline`, `Profile.Mounts`, `Resolv`, `ServerArgs`, `DockerdArgs`.
- Carrying them out: `init.go` `Setup` over a `Kernel`; `init_linux.go` `Run` (Linux only; `ErrNotLinux` elsewhere).
- Snapshot steps on `ControlPort` (1023, privileged) from `HostCID` only: `control.go` `ControlOp` (`prepare`, `thaw`, `rebirth`), `Rebirth.Validate`, bounded `ReadControl`/`WriteControl`; `clone.go` `Clone.Handle` (freeze the workload cgroup, remove `SeedFiles`, reseed the RNG, set the clock, take new names and address, thaw).
- The wall clock: `clocksync.go` `SyncClock` follows the host through the KVM PTP clock (`PTPDevice`), stepping past a threshold and slewing below it.

## Does not own
- The guest agent's server and its ops: `internal/guest`. The vsock listener: `internal/vsock`.
- Baking the profile into an image: `internal/rootfs`. Taking and restoring snapshots: `internal/isolation/firecracker`, `internal/isolation/vmsnap`.

## Rules and limits
- A profile comes from the image the cell built, never from the workload; an unknown profile, or an unknown or repeated command-line parameter, is refused.
- A sandbox serves as uid 1000 with `no_new_privs`, a read-only root, and writes only to bounded memory it owns; an environment keeps Docker and its workspace on its data disk, formatted only once.
- A sandbox template with any workload process running is never snapshotted; nothing of the workload runs before a rebirth is complete, and a failed rebirth leaves it frozen.
- It imports nothing of the control side ([package rules](../../AGENTS.md), "Package boundaries").

## Where new code goes
- A new mount or boot value: `Profile.Mounts` or `Boot` (with `Cmdline` and `ParseCmdline` both), and a case in `guestinit_test.go`.
- A new snapshot step: a `ControlOp`, its handling in `Clone.Handle`, the cell side in `internal/isolation/firecracker`.

## Tests
- `go test ./internal/guestinit` (fake `Kernel`, `CloneKernel` and `HostClock`). On a KVM host: `test/fcregress`.
