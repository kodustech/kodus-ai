# apps/runtime-cell/internal/kit

The microVM kit ([isolation-architecture.md](../../../../docs/runtime/isolation-architecture.md), "Is the self-hosted image different?"): firecracker and the jailer, the pinned guest kernel and the base root file systems, as one signed OCI artifact the cell pulls by digest. This package is its manifest and its verification. A pure package: the cell loads a kit when it opens the microVM driver (`internal/drivers/microvm`, `internal/isolation/firecracker`), and the release tooling makes one (`cmd/kody-kit`).

## Owns
- `kit.go` `Load`: refuses a kit whose manifest is not the pinned digest, a file whose bytes are not the manifest's (named in the `Error`), a path that leaves the kit, and a kit of another architecture.
- `Manifest`, `Manifest.Validate`, `SchemaVersion`; `Kit.Path`, `Kit.NestedDocker` (the environment base has Docker).
- `Make` and `Layout`: write the manifest of a kit laid out on disk and return the digest the cell pins.

## Does not own
- Building a root file system from an OCI image: `internal/rootfs`.
- What the kit's files do at run time: `internal/isolation/firecracker` (the VMM, the jailer), `internal/guestinit` (init).
- The kit's build scripts and published artifact: `microvm-kit/`.

## Rules and limits
- What boots a machine is exactly what was signed: nothing in a kit is used before `Load` verified it by digest.
- The environment base is optional; a kit without it serves sandboxes only.
- It imports nothing of the control side ([package rules](../../AGENTS.md), "Package boundaries").

## Where new code goes
- A new file in the kit: `Layout`, `Manifest`, `Validate`, and a case in `kit_test.go`; a new `SchemaVersion` when old kits no longer read.

## Tests
- `go test ./internal/kit` (a kit laid out in a temporary directory).
