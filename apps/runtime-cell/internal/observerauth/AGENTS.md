# apps/runtime-cell/internal/observerauth

The observer's claim-local SQL account: a random login and password per claim database, its SCRAM verifier, and the fixed script that provisions it in the app's PostgreSQL. A pure package with no driver, guest, product, filesystem or network dependency; the docker-gvisor driver creates and provisions the account, and the observer connects with it.

## Owns
- `credential.go` `Credential` (service, port, database, `kody_observer_<hex>` user, 32-byte password), `Validate`, `NewCredential`, `SCRAMVerifier`.
- `provision.go` `ProvisionSQL`: one transaction that creates or checks the role (no superuser, no inherit, connection limit), grants read on a supported plain schema and sets its expiry.

## Does not own
- Running the script in the claim's database: `internal/drivers/dockergvisor/observer_sql.go`.
- Connecting and the query subset: `internal/observer` (`managed_postgres.go`, `managed_sql.go`).

## Rules and limits
- A credential is private cell-to-observer configuration, never a hub frame or a Run field. It prints as redacted in every format.
- The plaintext password never enters the script: only the validated verifier does; names are validated before substitution and quoted with `format(%I)`.
- A richer schema (views, routines, row-level security) is refused rather than promised side-effect free.

## Tests
- `go test ./internal/observerauth` (pure). `postgres_smoke_test.go` is behind the `dockersmoke` build tag and needs a real PostgreSQL (`KODY_SQL_TEST_ADDRESS`, `KODY_SQL_TEST_ADMIN_PASSWORD`).
