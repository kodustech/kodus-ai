# apps/runtime-cell/internal/buildfingerprint

The identity of one image build as the cell can see it: a hash of the context BuildKit would send, the Dockerfile and its ignore file, the target, the args and the builder image. A pure package called by `internal/drivers/dockergvisor`, which compares fingerprints to decide whether a claim may take its environment's baked image.

## Owns
- `fingerprint.go` `Of`: walks a `sandbox.Build`'s context and hashes every entry (path, type, mode, content or link target); `ErrNone` when the build cannot be fingerprinted (past `maxFingerprintFiles` or `maxFingerprintBytes`, unreadable).
- `ignore.go` `contextExclusions`: the entries BuildKit will never send, read from `<Dockerfile>.dockerignore` or the context's `.dockerignore` through `internal/dockerignore`.
- `fingerprintVersion`: bumped whenever what the fingerprint covers changes, so an image baked under old rules is never taken for a new build.

## Does not own
- Whether a match is used, and the reuse direction (setup to claim, never the reverse): the driver and the [package rules](../../AGENTS.md), "Untrusted input".
- The ignore file's syntax: `internal/dockerignore`.

## Rules and limits
- The context is the PR's checkout: nothing is followed (a symlink hashes its target string), only regular files are opened, without following and without blocking, so a planted FIFO or device cannot hang the cell.
- In any doubt about what the ignore file leaves out, it leaves out nothing: a wrong guess costs a rebuild, never a stale image. The Dockerfile and ignore file are always covered, and are read only as regular files reached through real directories (`readDefinition`).
- A base image that moved upstream under the same tag is the one input it cannot see.

## Where new code goes
- A new input of a build's result: `Of`, a new `fingerprintVersion`, and a case in `TestFingerprintFollowsEveryInputOfTheBuild`.

## Tests
- `go test ./internal/buildfingerprint` (temporary directories).
