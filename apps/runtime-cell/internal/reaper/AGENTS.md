# apps/runtime-cell/internal/reaper

The reaper's pass and loop: it destroys this cell's machines past `kodus:hard-expires`, even while the hub and the cell keep renewing (ADR-056, S-08), then runs the driver's orphan pass. It runs in its own process (`cmd/reaper`: once per tick on a timer or scheduler, or in a loop), with a credential that can only list and destroy this cell's machines; `drivertest` runs it against drivers that have no sweep of their own.

## Owns
- `reaper.go` `Reaper` (`Run`, `Loop`), `Report`.
- The narrow views of a driver it uses: `MachineReaper` (`List`, `Destroy`, nothing else) and `OrphanReaper` (`ReapOrphans`).
- Its metrics: `cell_reaper_terminated_total` (above zero means the sweep and the dead-man switch both failed: it alerts) and `cell_reaper_pass_failures_total`.

## Does not own
- The ceiling's tags and how they read: `internal/driver` (`Expired`, `Ceiling`, `TagCell`).
- What an orphan is for a driver: the driver's own pass (`internal/drivers/microvm/reaper.go`, docker-gvisor's).
- Lease expiry (`kodus:expires`): the lease manager (`internal/lease`).
- Where and how often it runs: `cmd/reaper`.

## Rules and limits
- It ends a machine at its ceiling alone; a machine nobody can date is already past it ([`../../AGENTS.md`](../../AGENTS.md) "Untrusted input").
- It lists only by this cell's tag (`driver.TagCell`) and never asks the agent or the hub.
- A pass that fails on one machine goes on with the others and returns every error joined.

## Where new code goes
- A new kind of leftover a driver can find: the driver's `ReapOrphans`, not here.

## Tests
- `go test ./internal/reaper` (an in-memory driver, a fixed `Now`).
