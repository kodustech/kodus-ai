# apps/runtime-cell/internal/compose/sandbox

The compose allowlist of a cell whose services run on a shared host (S-10): the PR's compose file is checked and rewritten before any container starts, then what compose will really run is checked again. A pure rule package of the cell process; `drivers/dockergvisor` and `drivers/microvm` apply it on every boot, the agent and `buildfingerprint` read its build sections.

## Owns
- `sandbox.go` `Apply`: every key on an allowlist (a new compose feature is closed by default), every host path inside the checkout through real directories (`ResolveInside`, `ResolveWithin` for a workspace's `Root`), no interpolation outside the shell fields, none of the cell's `HostEnv` names; then it forces runsc, no new privileges, pids/memory/CPU limits, the trusted cgroup parent, the claim's network, read-only binds, no published ports, the log bound and disk cap, the resolver, the decoy, a Run's coverage mounts (`Coverage`: the claim's directory writable at `CoverageTarget` and the preload read-only, on the instrumented services only; the one writable bind) and the trust files (`Options`). Refusals are listed all at once (`RefusedError`, `Violation`).
- `canonical.go` `VerifyCanonical`: the same invariants on `docker compose config --format json`, so a YAML trick the first reader did not model cannot pass.
- Capabilities: every service drops ALL and gets back `ServiceCaps` only.
- Builds: `build.go` `Builds` (a build section inside the checkout only; no remote context, ssh, cache export or network mode), `build_secrets.go` `DockerfileSecretIDs` and the org secrets a build asks for. A build section gives way to the image the cell built (`Options.Built`); any other is refused.
- Names and addresses: `names.go` `ServiceAddresses` (fixed by name in the claim's subnet), `ServiceMAC`, `ResolvTarget`, `DecoyTarget`, `CoverageTarget`, `CoveragePreloadTarget`; `health.go` the fast start probe (`Options.HealthStartInterval`).

## Does not own
- Reading and adapting a project for side-by-side runs: `internal/compose`.
- The trust files and their variables: `internal/machinetrust`. Building the images: the drivers.

## Rules and limits
- Every compose file from a checkout passes `Apply` and `VerifyCanonical` before it starts ([`apps/runtime-cell/AGENTS.md`](../../../AGENTS.md) "Untrusted input").
- `PATH`, `HOME` and every `DOCKER_`, `COMPOSE_` and `XDG_` name are refused in `environment`, `command`, `entrypoint` and `healthcheck` whatever `HostEnv` holds; `$$` is the container's.
- A compose file never mounts under the cell's trust directory, nor over name resolution.

## Where new code goes
- A newly allowed compose key: its entry in the allowlist in `sandbox.go`, the same check in `canonical.go`, and a test of each.
- A new thing the cell forces on every service: a field of `Options`, its rewrite in `rewriteService`, its check in `verifyService`.

## Tests
- `go test ./internal/compose/sandbox` (pure). Each forced field has an `Apply` test and a `VerifyCanonical` test.
