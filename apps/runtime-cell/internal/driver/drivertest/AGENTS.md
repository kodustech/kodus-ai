# apps/runtime-cell/internal/driver/drivertest

Test code: the `MachineDriver` conformance suite every driver passes. It is imported only from `_test.go` files (each driver's own tests, `internal/driver/fake`, `test/gvisoregress`) and never ships in a binary.

## Owns
- `drivertest.go` `Run`: two tiers. The contract tier needs nothing from the backend (capabilities declared, bad claim ids and specs refused, reserved tags stamped); the lifecycle tier (`Subject.Lifecycle`) creates, lists, renews and destroys on a backend that keeps state, checks that foreign machines and networks are refused with `driver.ErrNotOwned`, and that machines past their ceiling or without one are swept (by `Subject.Parts.Sweeper`, else by `internal/reaper`).
- `requests.go` `RunRequests`: each field of `driver.UpRequest` and `driver.SandboxRequest` (cell trust, canaries, build secrets, output, workspace root) checked by what the backend shows (`Booted`).

## Rules and limits
- How drivers use the suite is in [`apps/runtime-cell/AGENTS.md`](../../../AGENTS.md) "Tests".
- `Now` is the suite's fixed clock; every spec expires relative to it.

## Where new code goes
- A rule every driver must keep: a check here, run from `Run` or `RunRequests`, never in one driver's tests.
- A new request field: a `upHonors...`/`sandboxHonors...` check in `requests.go` and, when the backend must show it, a field of `Booted`.

## Tests
- It runs through its users: `go test ./internal/drivers/... ./internal/driver/...`.
