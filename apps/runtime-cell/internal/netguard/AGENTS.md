# apps/runtime-cell/internal/netguard

The network rules every piece of the cell's data plane applies the same way: which addresses a connection may go to, the hosts no approval reaches, the Kodus recommended list, and the DNS answers the cell resolver handed out, so the proxy checks a connection against what the machine was actually told. A pure rule package, called by the egress proxy, the resolver, the injector and the agent; `cmd/cell`, `cmd/egress`, `cmd/resolver` and `cmd/injector` read its flags.

## Owns
- Destinations: `addr.go` `RefusedDestination` (link-local, multicast, unspecified always; loopback, private, CGNAT and other special ranges unless inside the cell's own networks), `ParseInternalCIDRs` and `CheckInternalCIDRs`, `DefaultClaimSubnets`.
- The deny list: `deny.go` `DenyList` (`NewDenyList`, `ParseDenyList`, `Denies`), `OnKodusDenyList`, `OwnedHosts`.
- The operator's entries: `operator.go` `RegisterDenyFlags` (`-deny-hosts`, `-owned-hosts`), `DenyFlags.List`, `DenyList.Fingerprint`.
- The lists shared with the API: `lists.go` reads the embedded `egress-lists.json` (deny patterns, `Recommended`, `RecommendedInspectRules`, `RecommendedBuildPassthrough`, `MirrorBuildArgNames`, `MatchesPattern`).
- Answers: `answers.go` `Answers` (`Record`, `Handed`, `ForgetClaim`), per claim, expiring with their TTL.

## Does not own
- The claim's allowlist, inspect rules and secrets: `internal/policy`.
- Refusing a policy push when the proxy and the resolver report different fingerprints: `internal/policy/control` (`ErrDenyListsDiffer`).
- Proxying and resolving: `internal/egress`, `internal/resolver`.

## Rules and limits
- The deny list applies over any allowlist, recipe or admin approval. Its zero value is the Kodus list alone, so an unconfigured component still refuses it; only exact owned hosts and the cell's own names (`policy.AppHost`, `policy.MirrorHost`) pass. See [`../../AGENTS.md`](../../AGENTS.md) "Untrusted input".
- `egress-lists.json` is a byte copy of `libs/runtime/protocol/egress-lists.json`; `TestEgressListsAreTheAPIsCopy` fails when they differ.
- An internal network may not overlap the claim pool: every claim could reach another claim's services. The cell refuses it at startup.
- An operator entry the list cannot express exactly is refused (`TestDenyListRefusesWhatItCannotSayExactly`). The fingerprint covers the operator's entries and owned hosts, not the Kodus list, so two binary versions can run side by side.

## Where new code goes
- A new denied or recommended host: `libs/runtime/protocol/egress-lists.json`, then copy it here byte for byte. A host that only one cell's operator denies is a `-deny-hosts` value, not a code change.
- A new address class to refuse: `RefusedDestination`, with a case in `TestRefusedDestination`.

## Tests
- `go test ./internal/netguard` (pure; reads the libs JSON from the repository).
