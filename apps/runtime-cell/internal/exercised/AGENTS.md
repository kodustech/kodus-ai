# apps/runtime-cell/internal/exercised

Counts which of a PR's changed lines its Node services ran during the probes (feature `exercisedLines`, `claim.exercised` in `libs/runtime/protocol/messages.ts`), from the V8 coverage they wrote under `NODE_V8_COVERAGE`. A leaf: it reads a directory and returns line counts per file; the coverage itself never leaves the claim.

## Owns
- `collect.go` `Answer`: the `coverage-*.json` files of a dir (regular files only, no link followed, `MaxCoverageFiles`, `MaxCoverageBytes` all together), each read in two passes: the `source-map-cache` first, then the result script by script with a token decoder, so a script that maps to no changed file is scanned and dropped, never decoded or painted. A file that is not JSON (written while read) is skipped; JSON of another shape is `ErrUntrusted`. The error says why the answer is no count: `ErrCoverageTooLarge` (the bounds, `MaxPaint`, or the context ended: every JS file `coverage_too_large`) or `ErrUntrusted`.
- `measure.go` `Measure`: a character counts by its innermost range; a script line ran when a non-blank character on it ran (plain JS, the text read from the checkout, refused as `unmapped_source` when the script is not exactly as long as it: another repository's service can run a file with the same path); a source mapped line ran when a segment mapping to it starts on a character that ran (`source-map-cache` of the coverage, `lineLengths` for the generated offsets); a line no segment maps to did not. A map counts for a changed file only when it is a map of the checkout's file: its `sourcesContent`, when carried, is the checkout's text, and no segment maps past the file's last line (else `unmapped_source`). The shape is checked before anything is painted. Coverage files are unioned (each `v8.takeCoverage` resets the counters). A file nothing maps to is `not_loaded_unproven`, or measured at 0 when another file of the request mapped. Script URLs match repository paths by the longest `/`+path suffix.
- The budget: `MaxPaint` range units for one answer, every script of every file together (past it `ErrBudget`, `coverage_too_large`), and the context, checked between scripts and while painting.
- The trust rule: the coverage is written by the PR's own processes. A coverage file counts only when a process the cell's preload started wrote it (its pid has a `started-<pid>-<ms>` marker, `StartMarkerPrefix`); another is skipped, so it can only lower the count. A range V8 never writes (negative, reversed, a block outside its own function's range), line lengths that do not add up to the script's own length, or a file of another shape is `ErrUntrusted`, answered by `Untrusted`: every JS file measured with 0 of its lines run, so it holds a green Run back. Coverage shaped like V8's that claims lines ran which did not cannot be told apart inside the claim: the count is advisory against a hostile PR ([docs/runtime/exercised-lines.md](../../../../docs/runtime/exercised-lines.md), section 11).
- `sourcemap.go` `decodeMappings`: Source Map v3 VLQ, bounded at `maxSegments`.
- `bench_test.go`: the cost of a large and of a hostile coverage file, with the numbers before and after the budget.

## Rules and limits
- The reason codes are `EXERCISED_UNKNOWN_REASONS` (protocol); a new one starts there.
- Not read: an adjacent `.map` or an inline `sourceMappingURL` the cache lacks (Node fills `source-map-cache` when `NODE_V8_COVERAGE` is set).

## Tests
- `go test -race ./internal/exercised/` (`trust_test.go`: forged shapes, maps of another version, the budget, the context): testdata holds a plain JS file and a TS file transpiled with `typescript.transpileModule` (its `.js` and `.js.map`), each with a hand-written coverage JSON where one function ran and one did not.
