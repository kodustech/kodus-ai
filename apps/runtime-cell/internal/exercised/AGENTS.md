# apps/runtime-cell/internal/exercised

Counts which of a PR's changed lines its Node services ran during the probes (feature `exercisedLines`, `claim.exercised` in `libs/runtime/protocol/messages.ts`), from the V8 coverage they wrote under `NODE_V8_COVERAGE`. A leaf: it reads a directory and returns line counts per file; the coverage itself never leaves the claim.

## Owns
- `collect.go` `Collect` (the `coverage-*.json` files of a dir: regular files only, no link followed, `MaxCoverageFiles`, `MaxCoverageBytes` all together), `Answer` (a request to results; coverage past the bound is `coverage_too_large`).
- `measure.go` `Measure`: a character counts by its innermost range; a script line ran when a non-blank character on it ran (plain JS, the text read from the checkout, refused as `unmapped_source` when the script is longer than it); a source mapped line ran when a segment mapping to it starts on a character that ran (`source-map-cache` of the coverage, `lineLengths` for the generated offsets); a line no segment maps to did not. Coverage files are unioned (each `v8.takeCoverage` resets the counters). A file nothing maps to is `not_loaded_unproven`, or measured at 0 when another file of the request mapped. Script URLs match repository paths by the longest `/`+path suffix.
- `sourcemap.go` `decodeMappings`: Source Map v3 VLQ, bounded at `maxSegments`.

## Rules and limits
- The reason codes are `EXERCISED_UNKNOWN_REASONS` (protocol); a new one starts there.
- Not read: an adjacent `.map` or an inline `sourceMappingURL` the cache lacks (Node fills `source-map-cache` when `NODE_V8_COVERAGE` is set).

## Tests
- `go test -race ./internal/exercised/`: testdata holds a plain JS file and a TS file transpiled with `typescript.transpileModule` (its `.js` and `.js.map`), each with a hand-written coverage JSON where one function ran and one did not.
