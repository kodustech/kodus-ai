# apps/runtime-cell/internal/buildmirror

What an image build gets from the cell's read-only mirror, whichever driver runs it: the build args that send each package manager to the mirror and BuildKit's registry configuration that pulls docker.io images through it. A pure package in the cell process; `internal/drivers/dockergvisor` and `internal/dockercli` hand both to the builder container, `internal/drivers/microvm` writes them into the VM's compose file and BuildKit configuration, and `cmd/cell` builds the `Mirror` from its flags.

## Owns
- `buildmirror.go` `At`: the mirror served at a base URL, its Go proxy, npm registry, PyPI index and registry under the paths `cmd/egress` serves them at; an empty base is no mirror.
- `Mirror.Args`: a build's args with the mirror's addresses added under the names `netguard.MirrorBuildArgNames` gives.
- `RegistryConfig`: the `buildkitd.toml` part that pulls docker.io through the registry mirror over plain HTTP on the claim's network.

## Does not own
- The list of build-arg names: `internal/netguard` (`MirrorBuildArgNames`).
- Serving the mirror: `cmd/egress`.

## Rules and limits
- The project's own value of an arg wins; an index the project set itself keeps its own trusted host.
- A Dockerfile reaches a registry through the mirror only when it declares the ARG; the mirror is read-only.

## Where new code goes
- A new ecosystem: a field of `Mirror`, its path in `At`, its names in `netguard.MirrorBuildArgNames`, and a case in `buildmirror_test.go`.

## Tests
- `go test ./internal/buildmirror` (pure).
