# apps/runtime-cell/internal/drivers/dockergvisor/buildcache

docker-gvisor's exported BuildKit cache, kept per environment and service as generations, so promoting a finished build's cache never changes files under a running build. A subpackage the driver holds as a field (`driver.go` `caches`); it holds directories and a clock and knows no Docker. It runs in the cell process.

## Owns
- `generations.go` `Generations`: `<dir>/gen-<id>` holds one generation, the symlink `<dir>/current` names the one builds read.
- `Acquire` (a build's read-only hold on the current generation), `Promote` (a new generation and an atomic swap of the link), `Drop` (an environment's cache goes, unless a build reads it), `Current` (what is kept, for the driver's accounting).
- `Sweep`: removes what was retired into the trash; the bytes go here, never on a build's path.

## Does not own
- Who may promote (only a seeding setup, and a bake for what a build left unpromoted): the driver (`cache.go`, `build.go`). The rule is in [`../../../../AGENTS.md`](../../../../AGENTS.md) "Untrusted input".
- BuildKit's own state per environment: `../buildstate`. The cache off the cell: `../remotecache`.

## Rules and limits
- A generation goes only once no build holds it; retiring it is a rename into the trash under the lock, O(1).
- Generation names come from the clock (`clock.Clock`), so tests drive them with `clock.Fake`.

## Tests
- `go test ./internal/drivers/dockergvisor/buildcache` (temporary directories, no Docker).
