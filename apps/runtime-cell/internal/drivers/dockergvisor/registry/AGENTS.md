# apps/runtime-cell/internal/drivers/dockergvisor/registry

docker-gvisor's registry image transfer (`-gvisor-image-transfer registry`): BuildKit pushes a build's image to a registry container the cell runs for that one build, and the host's Docker pulls it by the digest the build reported, so only what changed moves. A subpackage the driver builds in `registry.go` `newRegistries` and uses from `build.go`; it runs in the cell process. The security model is the package doc in `registry.go`: read it before changing anything here.

## Owns
- `registry.go` `Registries` (`New`, `Config`, `Clear`): the cell's registries and the count of builds on each environment's seed storage.
- `Registries.Start`: one registry container per build, on the claim's network (at the address the driver gives it: one pair of addresses per build running together on a claim) and the cell's internal registry network; seed storage for a seeding build, storage of its own (with the seed's sealed blobs linked in) for any other; `ErrUnseeded` when there is no seed to link.
- `Registry.Push` (BuildKit's push target), `Registry.Pull` (by digest only, bounded by the image bound, over a loopback port the cell forwards), `Registry.Stop`, `Discard`, `Pushed`.
- Storage accounting: `TreeBytes`, `MaxStorageEntries`, `EntriesError`; the seed wiped past `Config.KeepBytes` with no build holding it.

## Does not own
- Choosing tarball or registry and falling back to a tarball on `ErrUnseeded`: the driver (`../registry.go`, `../build.go`).
- The docker commands: `internal/dockercli` (`RegistrySpec`), through this package's `Docker` interface. Host directory ownership: the driver's `HostDirs`.

## Rules and limits
- The builder is untrusted: whatever it reaches, the pull request reaches. A registry is reachable only by its claim's builder and the cell, has no way out, and is removed once its image is pulled.
- A pull request's storage never sees another pull request's blobs, and nothing it writes outlives its build; a seed blob swapped for a link is never handed to a pull request.
- The digest is read from the build's metadata file as untrusted (a regular file, bounded, one sha256 digest); the image is pulled by digest, never by tag.
- The registry runs under the cell's runtime as the builder's uid, with no capability, no new privileges and a read-only root.

## Tests
- `go test ./internal/drivers/dockergvisor/registry` (races between a seed wipe or link and a build, with test hooks). The transfer end to end, on a fake Docker: `registry_test.go` in the parent package.
