# apps/runtime-cell/internal/drivers/awsec2

The cell's driver for EC2 VMs (`-driver aws-ec2`): an adapter of the `internal/driver` port, one VM per claim side plus an observer VM, with per-claim security groups and disks under the org's KMS key. It runs in the cell process (`cmd/cell` `wireAWS`, exec over SSH) and, cut down to list and destroy, in the reaper (`cmd/reaper`). It is written against `EC2API`, the subset of the SDK it calls, so nothing here reaches AWS unless a real client is passed in.

## Owns
- Construction and the checked settings: `driver.go` `New`, `Config` (launch template, subnets, the cell's fixed groups, the observer image, `OrgKey`).
- A claim's network: `driver.go` `PrepareClaim` (two groups: the workload takes SSH from the cell agent and expose ports from its observer, the observer its API port from the cell agent; egress only to the proxy and resolver ports, `toEgressGroup`), `ReleaseClaim` (deletes groups that reference each other).
- Machines: `driver.go` `Create` (launch template, org KMS key, tags, ceiling), `List`, `SetExpiry`, `InstanceType`; `lifecycle.go` `Suspend`, `Resume`, `Destroy`, bounded waits (`poll`, `waitRunning`), cleanup of a launch whose response was lost (`cleanupLaunchByToken`, by `launchToken`).
- Disk reset: `reset.go` `Reset`, a replace-root-volume task from the machine's original root (`tagOriginalRootVolume`, recorded once by `recordOriginalRoot`). Its only `driver.Parts` entry is `Resetter`.
- The reaper's view: `driver.go` `Reaper`, `NewForReaper` (List and Destroy only).
- The IAM policies the code assumes: `iam/cell-role.json`, `iam/reaper-role.json`, checked by `iam_test.go`.

## Does not own
- Exec and upload into the VM: `internal/transport` (SSH), given by `cmd/cell/wire.go`.
- A compose-volume reset: the agent runs it over the transport (`ErrComposeResetInCell`).
- Bakes and a warm pool: not implemented on this driver (no `Baker` or `Pooler` in `Parts`).
- The order of a claim's stages and its egress policy: `internal/agent`.

## Rules and limits
- The ownership, ceiling and listing rules of [`../../../AGENTS.md`](../../../AGENTS.md) "Untrusted input" apply; here the owner and org are read from the instance's tags (`owned`, `actualOwned`, `checkScope`), never the caller's ref.
- A disk is encrypted only with the claim's org key; another org's key fails with `ErrWrongOrgKey`.
- `Create` refuses a spec without a ceiling, a group that is not the claim's, and a caller-supplied original-root tag.
- Every API call and wait is bounded by `OperationTimeout` or `CleanupTimeout`, independent of the caller; a failed `PrepareClaim` or `Create` removes what it made, and a cleanup it cannot confirm is reported.
- A reset takes only this machine's original root and waits for the task; a failed, missing or foreign task is never success.
- Arch is `x86_64` only; hibernation only with `Config.Hibernate` and never for an observer.

## Where new code goes
- A new EC2 call: add it to `EC2API`, to the mock in `mock_test.go`, and to `iam/cell-role.json` (or the reaper's), with a case in `iam_test.go`.
- A new setting: `Config`, read from the `-aws-config` file in `cmd/cell/wire.go` (`flagOwners` owns `aws-config`).

## Tests
- `go test ./internal/drivers/awsec2`: an in-memory EC2 mock (`mock_test.go`), `drivertest.Run` in `conformance_test.go`, and the IAM policy checks. No AWS account needed.
