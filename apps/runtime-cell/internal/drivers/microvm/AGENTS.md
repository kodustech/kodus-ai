# apps/runtime-cell/internal/drivers/microvm

The cell's driver for Firecracker microVMs (`-isolation-backend firecracker`): an adapter of the `internal/driver` port that the agent calls for every machine of a claim. It composes the host-network placement (`internal/placement/hostnet`) with the Firecracker backend (`internal/isolation/firecracker`) and keeps the driver's own rules on top. It runs in the cell process; what runs inside each VM is `internal/guest` and `internal/guestinit`.

## Owns
- Machines and claim networks: `microvm.go` `Create`, `Destroy`, `List`, `PrepareClaim`, `ReleaseClaim`, tags, ceilings and ownership checks.
- An environment's boot inside its VM: `env.go` `Upload` (the checkout, as base64 chunks through the guest agent), `Up` (the cell's compose file, `docker compose` in the VM).
- Builds of a claim that trusts the cell CA: `build.go` `vmBuilder` starts the kit's buildkitd in the VM and compose builds through it; `systemTrust` adds the cell CA to the VM's own trust store.
- The observer VM and its targets (`env_run.go` `DialObserver`, `Targets`), recipe steps (`RunRecipe`), resets (`Reset`, `ResetToSnapshot`).
- Templates and snapshots: `env_run.go` `PinBakeSource`, `Bake`; `microvm.go` `SnapshotMachine`, `CreateFrom`; taints that keep a machine out of a snapshot (`Taint`).
- An environment's data disk sized from its setup's peak (`disk_need.go`), memory accounting (`memory.go`), the sweep and the reaper's view (`reaper.go`), diagnosis (`diagnose.go`, `health.go`, `service_logs.go`).
- Opening the stack from the cell's flags: `open.go` `Open` (kit verified, host checked, egress ports).

## Does not own
- The VMM, jailer, disks, snapshots on disk: `internal/isolation/firecracker`.
- Bridges, taps, nftables: `internal/placement/hostnet`.
- What runs in the VM: `internal/guest` (the agent), `internal/guestinit` (init, dockerd's start), the kit (`microvm-kit/`).
- The compose command lines: `internal/composecmd`. The mirror's build args: `internal/buildmirror`.
- The order of a claim's stages and the egress policy: `internal/agent`.

## Rules and limits
- The guest agent writes only under `/workspace`; anything the cell needs elsewhere in the VM is copied there by a command (`vmBuilder.script`).
- A machine holding a Run's canaries or a build's org secrets is tainted before compose runs, so it never becomes a template (S-28, `Up`).
- A claim that trusts the cell CA builds only with the cell's buildkitd: a kit with the stock one fails the boot (exit 97).
- The VM is one egress source: its builds, its dockerd and its services all leave from its address, so a trusted claim's VM must trust the cell CA as a whole (`systemTrust`).
- Data disks are admitted at the ceiling (`-firecracker-data-gb`) until a setup measured the environment's need.
- Upload is slow for large repositories (base64 over vsock): about 30–43 s for a 174 MB checkout.

## Where new code goes
- Something every environment VM runs before compose: a line of `upCommand` in `build.go`, with a test in `env_test.go` that uses the real guest agent on a host directory (`envDriver`, `trustingDriver`).
- A new flag of this driver: `cmd/cell/microvm.go` (`microvmSettings`), owned by the `firecracker-` prefix in `flagOwners`.
- Something the backend must do (a VMM call, a disk operation): `internal/isolation/firecracker`, reached through the `Backend` interface.

## Tests
- `go test ./internal/drivers/microvm` runs anywhere: a memory backend and the real guest agent on a temporary directory, with fake `docker`, `buildkitd` and `buildctl` on its PATH.
- On a KVM host, as root: `test/fcregress` (`KODY_E2E_FIRECRACKER=1` and a kit), including `TestFirecrackerABuildOfATrustingClaimReachesAHostTheCellInspects` and the kodus-ai Run (`KODY_E2E_KODUSAI_*`).
