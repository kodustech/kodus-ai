# apps/runtime-cell/internal/drivers/localdocker

A dev-only driver (`-driver local-docker`): an adapter of the `internal/driver` port that runs a claim's environment (the checkout's compose project, or one container built from its Dockerfile) on the developer's own Docker daemon, with no isolation. It exists to run a real app on a laptop against a local hub. It runs in the cell process (`cmd/cell/wire.go` `wireLocalDocker`), with the observer in-process. The package doc in `driver.go` maps its files.

## Owns
- The dev gate and construction: `driver.go` `Gate`, `New` (refuses without both `-dev-insecure-local-docker` and `KODY_RUNTIME_DEV=1`, prints `Warning`, needs a reachable daemon).
- Machines: `machines.go` `Create`, `Suspend`, `Resume`, `Destroy`, `List`, `SetExpiry`, `Sweep`; Docker labels carry the tags, `kodus:expires` and published ports live in the state file (`state.go`).
- A claim's network as a name only: `claims.go` `PrepareClaim`, `ReleaseClaim`.
- What a checkout boots: `boot_plan.go` `newBootPlan` (recipe, adapted compose, `ComposeFile`, `EnvFile`), `recipe_support.go` (what of a recipe it runs, ignores or refuses; declared fakes as private services).
- Boot and reset, phase by phase: `boot.go` `Boot`, `Reset`; `seed.go` (migrate, seed, bounded SQL file); `health.go` (the recipe's health check); `snapshot.go` (named-volume snapshots for the `snapshot` reset); `boot_report.go` `LastBoot`, `BootTiming`.
- The upload that boots: `transport.go` `Transport` (a `transport.Local` whose `Upload` brings the project up).
- What the agent and the observer read: `claim_view.go` `Manifest`, `Targets`, `machines.go` `HostAddress`; the failure bundle: `diagnose.go` `Diagnose`.
- Its Docker port and adapter: `docker.go` `Docker`, `SnapshotDocker`, `DiagnosticDocker`; `docker_cli.go` `CLI` over `internal/dockercli`.

## Does not own
- The docker binary and compose's argv and output: `internal/dockercli`, `internal/composecmd`.
- Reading a compose project and the recipe format: `internal/compose`, `internal/recipe`.
- Bakes and pools: none (`Parts` is `Resetter`, `BootTimes`, `Diagnoser`, `Sweeper`); the environment is built from the checkout at every boot.

## Rules and limits
- Isolation is `none`: [`../../../AGENTS.md`](../../../AGENTS.md) "Untrusted input" says what that forbids. Never weaken `Gate` or make the driver selectable without it.
- A boot refuses labels the checkout forged, services the recipe does not name, and a seed file that leaves the checkout through a symlink.
- It refuses what it cannot provide the same way the agent does (a seeded SQL observer: `readonly_refusal_test.go`), never with a warning.
- A declared fake never publishes a host port and is recreated on every reset.
- A snapshot is taken once, after the first ready boot, with the services stopped; a failed copy or restore falls back to recreate (README "Resetting between rounds (local-docker)").

## Where new code goes
- A recipe key it now supports: `recipe_support.go` (remove it from what is ignored or refused) and the phase in `boot.go`, with a case in `recipe_test.go`.
- A new Docker call: `docker.go` (the narrowest interface that needs it), `docker_cli.go`, and the fake in `fakes_test.go`.

## Tests
- `go test ./internal/drivers/localdocker`: a fake Docker (`fakes_test.go`) and `drivertest.Run` (`conformance_test.go`).
- Real Docker, behind `dockersmoke`: `KODY_RUNTIME_DEV=1 go test -tags dockersmoke -run 'SmokeRealDocker|SmokeRecipe' ./internal/drivers/localdocker/` (fixture `testdata/recipe-app`); `SmokeCheckout` boots a real checkout.
