# apps/runtime-cell/internal/yamlbound

Bounds on the YAML a pull request hands the cell before the cell parses it in its own process: the compose files and the recipe. yaml.v3 turns its input into a node tree about a hundred times its size and expands an alias once per use, so an unbounded file is the cell's memory, outside any claim's cgroup. A pure package called by `internal/recipe`, `internal/compose` and `internal/compose/sandbox`.

## Owns
- `yamlbound.go` `ReadFile` (inside an `os.Root`, a regular file only, at most `MaxFileBytes`), `Parse` (a node tree within the bounds), `Check` (the bounds alone), `ErrTooLarge`.
- The bounds: `MaxFileBytes` (1 MiB; a Dockerfile is held to the same in `internal/agent/checkout/imagepins.go`) and `MaxNodes` (100 000, aliases counted as what they expand to).

## Rules and limits
- Every YAML file from a checkout or a claim goes through this package before it is decoded into maps. A FIFO or device is refused and never waited on; an anchor that contains itself is refused.

## Where new code goes
- A new YAML file the cell reads from a checkout: read and check it here first, never with `os.ReadFile` and a bare `yaml.Unmarshal`.

## Tests
- `go test ./internal/yamlbound` (pure).
