# apps/runtime-cell/internal/injector

The only piece of the cell that holds a test credential or an org secret's value (Inc. 5, [sandbox.md](../../../../docs/runtime/sandbox.md) "Secrets: OpenBao"). The egress proxy sends it the credentialed hosts and the inspected hosts from machines that trust the cell CA, with the address it validated in a PROXY v1 line; the injector ends the machine's TLS with a leaf of the cell CA, checks and rewrites the request, and goes to exactly that address over its own verified TLS. Data plane: it runs in the injector process (`cmd/injector`).

## Owns
- A connection: `injector.go` `Injector.Serve`, `handle` (PROXY v1 only from `TrustedProxies`), `leaf` (the cell CA's leaf for the host), `proxyWithCredential`, `relay` (responses masked as they stream, cut past `MaxResponse`); `inspect.go` `proxyInspected` (reads of the inspected tier, cut only past `MaxInspectedResponse`, 16 GiB by default, `-max-inspected-response-gb`).
- Org secrets as placeholders: `placeholders.go` `proxyWithSecrets` (a placeholder becomes the value only on a host the admin allowed it for); the store `openbao_secrets.go` `OpenBaoSecrets`, `AppRoleToken`.
- The inspected tier: `inspect.go` `proxyInspected` (only a GET or HEAD under the rule's paths, no body, no credential), `refuseInspected` (a fixed code, never the request).
- The request target: `request_target.go` `upstreamURL` (https to the validated host with the request's path and query only); reflected credential header names: `response_headers.go`.
- Per-claim concurrency: `request_slots.go`.
- The cell vault of per-claim credentials: `vault.go` (`Binding`, `SecretVersion`, `ManagedVault`, `RefusingVault`), `vault_store.go` `EncryptedVault`, `OpenConfiguredVault`, `vault_records.go` (`Bind`, `Credential`, revocations), external versions read from OpenBao (`external_versions.go`, `openbao_reader.go` `OpenBaoReader`), bindings authorized only by a signed live policy (`policy_claim_authorizer.go`).
- Alerts (S-28, S-29, S-50) served on the control port and read by the agent: `Alert`, `alert_client.go` `AlertClient`; `metrics.go`.

## Does not own
- Which hosts reach it and the destination check before it: `internal/egress`. The policy and its signature: `internal/policy`, `internal/policy/control`.
- The signed management port that writes the vault: `internal/injector/management`, its CLI `internal/injector/admincli`.
- Writing org secrets to OpenBao: the product API's write-only role.

## Rules and limits
- It never resolves a name and never takes a proxy from its environment: the credential goes to the address the proxy validated, checked again against `InternalCIDRs`.
- A value never goes back to the machine or through the proxy: a request carrying the credential, a real secret value or a bait out is refused and raises an alert; a request target other than the TLS name never leaves with the credential.
- Secret types print as `{redacted}` (`String`, `GoString`, `LogValue`, `Format`); errors and logs carry closed codes, never provider details.
- The vault fails closed: an uncertain revocation stays denied after a restart; a caller cannot supply a binding's authority, scope or TTL.
- The data plane never imports the control side ([package rules](../../AGENTS.md), "Package boundaries").

## Where new code goes
- A new refusal of a request: the file of its tier (`placeholders.go`, `inspect.go`, `request_target.go`), a closed refusal code, and a test that the value never reaches the machine.

## Tests
- `go test ./internal/injector` (`testpki`, `testopenbao`, in-process upstreams). `openbao_integration_test.go` runs a real OpenBao when `KODY_OPENBAO_TEST_BINARY` names one; `openbao_container_smoke_test.go` is behind the `dockersmoke` tag.
