# apps/runtime-cell/cmd/resolver

The standalone resolver binary: the only DNS of the machines and the observer. It answers a claim's exact allowlist and NXDOMAIN for the rest, logs every query by claim, and takes signed policies on an mTLS control port. Run standalone, its answer record stays in this process; to share it with the proxy, run the resolver inside `cmd/egress` (`-dns-listen`).

## Owns
- Wiring: `main.go` `newResolverPlane` (`policy.Store`, `resolver.QueryLog`, `resolver.Server`, `control.Server` with the deny list's fingerprint), `run` (DNS on udp and tcp, a 30 s sweep, the control mux with `GET /v1/queries`).

## Does not own
- Answers, rate limits, the query log: `internal/resolver`. The deny list and internal ranges: `internal/netguard`. Policies: `internal/policy`, `internal/policy/control`.

## Rules and limits
- The data plane never imports the control side; the deny list is shared with the proxy ([`apps/runtime-cell/AGENTS.md`](../../AGENTS.md) "Untrusted input").
- `-internal-cidrs` may not overlap `-claim-subnets` (`netguard.ParseInternalCIDRs`).
- `GET /v1/queries` answers only the pinned agent; with no pin, nobody.

## Tests
- `go test ./cmd/resolver` (`TestTheStandaloneResolverDeniesTheOperatorListAndReportsIt`).
