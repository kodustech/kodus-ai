# apps/runtime-cell/cmd/kody-guest

The guest agent binary, which runs inside a machine ([architecture.md](../../../../docs/runtime/architecture.md), "Inside a machine"). It has three modes, chosen in `main.go` `main`:
- As PID 1 of a microVM it is the init: `guestinit.Run` sets the machine up and starts it again as the `-vsock` server.
- `kody-guest observer -vsock PORT` is a claim's observer in an observer microVM (`observersrv.Run` on vsock).
- Otherwise it serves the cell's `sandbox.op` frames (`guest.Serve`) on exactly one of `-stdio`, `-listen` (a unix socket) or `-vsock`.

## Owns
- The accept loop: `main.go` `run` (one stream per connection, at most `maxStreams`, every stream joined within `streamsGrace` before the root closes).
- The mounted cell CA as the commands' trust variables (`guest.MountedTrustEnv`), present only where the cell mounted it.

## Does not own
- File operations, exec and the frame protocol: `internal/guest`. Init, profiles, mounts and dockerd: `internal/guestinit`. The vsock listener: `internal/vsock`. The observer: `internal/observer/observersrv`.

## Rules and limits
- Every file operation stays under `-root` (default `/workspace`, `guest.OpenRoot`).
- Nothing before `guestinit.Run` may read `/proc` or rely on `PATH`; PID 1 returning ends the machine, so it prints why first.
- It imports nothing of the control side ([`apps/runtime-cell/AGENTS.md`](../../AGENTS.md) "Package boundaries").
- It exits with its own codes (`os.Exit(1)`, `2` for bad flags), not `lifecycle.ExitCode`.

## Tests
- None here; `go test ./internal/guest ./internal/guestinit`, and the microVM driver's tests run the real guest agent on a host directory (`internal/drivers/microvm`).
