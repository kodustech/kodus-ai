# apps/runtime-cell/cmd/reaper

The reaper binary: destroys this cell's machines past `kodus:hard-expires`, with its own credentials, whether the cell agent is alive or not. It runs once per tick (`-once`: an EventBridge schedule on AWS, a systemd timer on a docker-gvisor host), as a Kubernetes CronJob, or loops every `-every`.

## Owns
- Picking the reaper's driver: `main.go` `newDriver` (`awsec2.NewForReaper`, `k8ssandbox.NewForReaper`, `dockergvisor.NewForReaper`, `microvm.NewForReaper`), each list-and-destroy only; docker-gvisor and microvm also give an orphan pass.
- The cell id: `-cell-id`, or the CN of `-cell-cert` (`cellIDFromCert`).

## Does not own
- The pass itself (ceilings, orphans, the report): `internal/reaper`. Ceilings: `internal/driver` (`Ceiling`, `Expired`).

## Rules and limits
- No fake driver: a reaper over memory reaps nothing and would look healthy (`TestNoFakeReaper`).
- No cell id or an unknown `-driver` is `lifecycle.Usage` (exit 2).
- k8s-sandbox needs `-k8s-namespace`: its Role reaches that namespace only. With `-k8s-env-namespace` (a cell that runs environment Runs) it also ends a reaped machine's objects in the environment namespace and runs the orphan pass there (`k8ssandbox.NewForReaperWithEnv`, `ReapOrphans`).
- The ceiling and ownership rules are in [`apps/runtime-cell/AGENTS.md`](../../AGENTS.md) "Untrusted input".

## Where new code goes
- A driver's reaper: a `NewForReaper` in that driver's package and a case in `newDriver`, with a test that the kind has a reaper.

## Tests
- `go test ./cmd/reaper`.
