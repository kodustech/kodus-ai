# libs/runtime/planner/import-graph

Reverse reachability over a static JS/TS import graph (docs §9.8): a changed file with no route of its own maps to the routes of the files that import it, directly or through others. Part of the test planner's core ([`../AGENTS.md`](../AGENTS.md)); `planTests` calls it for the diff's unmapped files before its first prompt (`ReachedBy`).

## Owns
- The walk: `reach.ts` `routesReaching`, nearest files first, to `IMPORT_GRAPH_LIMITS` reads and time; `ImportGraphCache` keeps what was read per commit for the next round; `importGraphReadsOf` takes a budget.
- Specifier resolution: `resolve.ts` `resolveSpecifier` (relative paths, tsconfig/jsconfig `paths` and `baseUrl` via `aliasesOf` and `parseJsonc`, workspace packages via `packageOf`).
- Routes a file declares by convention: `routes.ts` `routesOf` (Next.js app and pages routers, Remix, Nest controllers and GraphQL resolvers, Express/Koa/Hono, Fastify, a router-named receiver as fallback), within `ROUTE_LIMITS`.

## Does not own
- Routes a changed file declares itself: `libs/runtime/entry-points/extract.ts` (`routes.ts` uses its `extractEntryPoints`).
- Reading files: the planner's `RepoReader`.

## Rules and limits
- Nothing of the repository runs: imports are listed by TypeScript's pre-processor, config files are read as data, a specifier that names no file of the tree resolves to nothing.
- File content is untrusted: cut and normalized (`normalizedSource`) before any pattern runs, and every pattern is bounded.
- A `ReachedRoute` is the route as its file declares it, before any mount prefix, with the import `hops` from the changed file; the planner still has to read the prefix.

## Where new code goes
- A new framework convention: `routes.ts`, with a case in `routes.spec.ts` and, if the diff's own file should map too, in `entry-points/extract.ts`.
- A new resolution rule: `resolve.ts` and `resolve.spec.ts`.

## Tests
- `node node_modules/jest/bin/jest.js --runInBand libs/runtime/planner/import-graph` (pure, in-memory readers).
