# libs/runtime/api/domain

The domain layer of the product's Runtime API: the ports every use case depends on, their injection tokens, and the pure rules the product decides by (when a Run starts, what it may spend, what an admin may set). No Nest and no driver. Use cases in `../application/` call it; adapters in `../infrastructure/` implement its ports; `apps/runtime` imports a few files (`runtime-commands`, `run-cost`, `run-token`, `ports`, `external-findings`) and the web imports its types.

## Owns
- Ports and tokens: `ports.ts` (Runtime readers, product stores, `RuntimeGitPort`, the repo token issuer, LLM provider and usage store, team and org repositories, clock, config) and the ports of an area in its file: `env-tools.ts`, `external-findings.ts`, `previews.ts`, `pull-request-runs.ts`, `secrets.ts`, `setup-calls.ts`, `model-turn.ts`, `webhook-reconciler.ts`.
- When a Run starts: `trigger-rules.ts` `decideRun`, `parseTriggerRules`, `compileGlob` (linear, no backtracking); forks: `fork-policy.ts` `decideForkRun`, `forkRunMaxTokens`.
- What a Run may spend: `budget.ts` `planLlmCall`, `decideBudget` (per Run, per PR, per org per day); the Run token: `run-token.ts` `signRunToken`, `verifyRunToken`, and the setup token `signSetupToken`, `verifySetupToken`.
- Admin settings bounded by the plan: `pool.ts` (`effectivePoolSize`, `parsePoolPolicy`, `desiredPoolSize`), `machine-size-plan.ts` `effectiveMachineSize`, `egress.ts` `normalizeEgressHost`, `deniedBy` (the Kodus denylist wins over an approval).
- Costs and usage: `run-cost.ts` `estimateRunCost`, `run-cost-summary.ts`, `llm-spend.ts`, `machine-minutes-today.ts`, `usage-report.ts` `buildUsageReport`, `usageReportCsv`; the Health screen: `runtime-health.ts` `buildRuntimeHealth`, and its Speed card: `runtime-speed.ts` `buildRuntimeSpeed` (nearest-rank p50/p95).
- Derived Run ids: `deterministic-id.ts` `deterministicUuid`.

## Does not own
- Shared vocabulary and commands: `libs/runtime/contracts` (`cell-token.ts` and `runtime-commands.ts` here are re-exports kept for older callers).
- Calling ports and checking access: `../application/`. Implementing them: `../infrastructure/`.

## Rules and limits
- Pure ([`AGENTS.md`](../../AGENTS.md) "Dependency direction"): zod, `crypto`, `net`, type imports from `@libs/agent-harness` and `@libs/llm`, and `PlatformType` from `@libs/core`; never Nest, TypeORM, `pg` or an adapter.
- Every port is org-scoped: each `get`, `list` and write takes `organizationId`.
- A port is named `…Reader` (read-only), `…Store` (writes) or `…Port` (external system); its token is `RUNTIME_<NAME>`.
- Errors that cross layers live here (`InvalidPoolSizeError`, `MachineSizeAbovePlanError`, `InvalidRunTokenError`, …); the use case maps them to HTTP.
- An unknown answer from the platform denies; facts come from `RuntimeGitPort`, never the webhook payload.

## Where new code goes
- A new port: its interface and token here, then its adapter and the binding in `../runtime-api.module.ts`.
- A new rule a use case decides by: a pure function here with its spec in `../__tests__/`; a rule `apps/runtime` also needs goes to `libs/runtime/contracts`.

## Tests
- `API_NODE_ENV=test npx jest libs/runtime/api/__tests__/domain.spec.ts libs/runtime/api/__tests__/trigger-rules.spec.ts` and the area's spec in `../__tests__/` (pure).
