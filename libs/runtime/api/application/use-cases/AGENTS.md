# libs/runtime/api/application/use-cases

One use case per route of the product's Runtime API, in the application layer. A controller in `apps/api/src/controllers/runtime/` imports its use case by path and calls one method; the PR trigger and the session sweep are also called by the product worker's consumer and crons. Each use case checks access, reads through ports, and writes product tables or an outbox command; none writes Runtime state.

## Owns
By area (files named without `.use-case(s).ts`):
- **e2e suite**: `suite.use-cases.ts` (`GetRuntimeRunSuiteUseCase` the Run page's tab, any reader of the org; `RetryRuntimeRunSuiteUseCase` "Re-run failed", gated like "Run again"; `GetRuntimeRunSuiteArtifactUseCase` a 5-minute URL for a file the suite run stored, the key found server side; `GetRuntimeEnvironmentSuiteUseCase` Settings; `ResumeSuiteSelectionUseCase` Manage on the environment). Settings go through `update-environment-settings` (`suiteCi` is the product's column, `suiteSelection` is a command to the Runtime).
- **Runs**: `get-run` (with `probeRequestsOf`, stuck state from `libs/runtime/health`), `list-runs`, `read-run-stream`, `get-run-evidence` (URLs of at most 5 minutes), `get-run-reproduction`, `run-again`, `approve-fork-run`, `finding-feedback`, `finding-intent` (a learning mark; never changes the Run or the PR), `kept-checks` (keep a regression's recorded probe, list, remove; docs/runtime/kept-checks.md).
- **Pull requests**: `pull-request-trigger` (a PR event or `@kody runtime` comment becomes a Run or not, every fact from the Git API), `pull-request-runs` (a page of PRs in one read), `request-pull-request-run`, `pull-request-session-sweep` (the fallback for a lost PR close), `simulate` ("Try it").
- **Environments**: `environments.use-cases.ts` (re-exports, keeps the old path), `environment-view`, `environment-blockers`, `list-environments`, `get-environment`, `list-environment-blockers`, `create-environment`, `request-environment-setup`, `update-environment-settings` (pool size and machine size under the plan), `environment-repositories` (multi-repo membership), `apply-blocker-fix`, `propose-inferred-recipe`, `lessons`.
- **Egress**: `approve-egress`, `egress-access` (revoke, the org list and settings).
- **Settings and reports**: `settings` (mode, rules, who can ask, machine minutes), `runtime-health`, `usage-report` (and its CSV), `preview-settings`.
- **Org operations**: `stop-runtime` (stop and clear), `cells` (registration tokens, cells, revoke), `secrets` (OpenBao values, write-only), `purge-organization` (every Runtime datum of one org: its secrets, its product rows, then the worker's command; [architecture.md](../../../../../docs/runtime/architecture.md) "Data lifecycle"), `env-audit`, `set-team-key-repositories`.
- **Previews**: `previews` `RuntimePreviewsService` (access and single-use grants; the worker owns the records).
- **Worker routes** (`/internal/runtime/*`, a Run or setup token, never a user): `llm-gateway`, `model-turn-gateway` (canary check on every prompt), `test-planner`, `planner-source`, `recipe-author`, `setup-repo-tokens`.

## Does not own
- Response shapes: `libs/runtime/contracts/views/` (re-exported from the old paths here). Shared services: `../`. Rules and ports: `../../domain/`.
- Authentication of the route: the controller's guards (`RuntimeReaderAuthGuard`, the oncall guard, `PolicyGuard`); the use case still checks the object.

## Rules and limits
- Object-level checks on every route: load the object, then org, team and repo; another tenant's object answers 404 (`RuntimeRunAccessService`, `AuthorizationService`).
- A decision that changes Runtime state is a command through the outbox (`runtimeCommandOutboxMessage`), never a write to a Runtime table.
- Worker routes accept only their token (`runtimeWorkerScope`, `verifyRunToken`, `openSetupToken`) and recheck the live Run, its org and attempt on every call; a setup call asked again returns its receipt instead of running twice.
- `runtime-health.use-case.ts` takes its port (`RUNTIME_HEALTH_READER`) from `infrastructure/pg-runtime-health.reader.ts`, and `pull-request-session-sweep.use-case.ts` declares `PullRequestSessionsReader` itself; ports belong in `../../domain/`.

## Where new code goes
- A new route: a file here, listed in `../../runtime-api.module.ts` `useCases`, its controller method, its view in `contracts/views/` if it answers one, its spec in `../../__tests__/`.

## Tests
- `API_NODE_ENV=test npx jest libs/runtime/api/__tests__` (unit, with `fixtures.ts` and the real RBAC); `apps/api/src/controllers/runtime/__tests__/runtime.controllers.spec.ts` for the routes.
