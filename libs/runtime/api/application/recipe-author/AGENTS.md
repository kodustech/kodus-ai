# libs/runtime/api/application/recipe-author

Kody's recipe author: an agent on the product's harness, with the org's BYOK (ADR-057), that writes `.kodus/workspace.yaml` (and the Dockerfiles and compose files next to it) for a repository that has no recipe and none Kodus could infer. Application layer, run in the product API when a setup's recipe step calls `POST /internal/runtime/recipe-author` (`../use-cases/recipe-author.use-case.ts`). Its output is untrusted until the cell boots it.

## Owns
- The agent: `recipe-author.agent.ts` `authorRecipe`, its tools (`find_files` with `globMatcher`, `submit_recipe`), `RECIPE_AUTHOR_LIMITS`, the instructions and previous-attempt feedback.
- What it knows before reading: `repository-facts.ts` `repositoryFacts`, `factsBlock`, `workspaceFactsBlock` (no model).
- Context size options (off by default): `recipe-author-context.ts` (`ClearStaleReadsPolicy`, prefetch).
- Rules a written recipe must pass beyond a repository's: `authored-recipe-policy.ts` `checkAuthoredRecipe`. Rules for its files: `authored-files-policy.ts` (`checkAuthoredDockerfile`, `checkNodeBuild`, compose checks), `authored-compose-sanitiser.ts` `sanitiseAuthoredCompose`, `authored-dockerfile-mirror.ts` `declareMirrorBuildArgs`.
- Readers: `git-repo-reader.ts` `GitRepoReader` (over `RuntimeGitPort`, `GIT_READ_MAX_BYTES`), `workspace-repo-reader.ts` `WorkspaceRepoReader` (every repository of a multi-repo workspace, each at its commit), `repo-reader.ts` (re-export of `libs/runtime/planner/repo-reader`, kept as an entry point).

## Does not own
- The route, receipts, lease and budget of a call: `../use-cases/recipe-author.use-case.ts`. Retrying, booting and repairing: the runtime-worker's setup workflow (`apps/runtime/src/worker/setup/`).
- The recipe schema and the rules every recipe passes: `libs/runtime/protocol/recipe.ts`. Bounds both sides share: `libs/runtime/contracts/authored-files.ts`, `contracts/recipe-author.ts`.
- The version recorded on an authored recipe: `libs/runtime/run/recipe-author-version.ts`.

## Rules and limits
- What the model read can be steered by a PR or a README, so a written recipe gets no field a team recipe could not have and its files pass stricter rules than the cell's; the cell still checks and sandboxes them.
- Kodus rewrites only Kody's own files under `.kodus/`, and says each change back to the model.
- Reads are bounded (`READ_LIMITS`) and pass `modelView` (secret files and assignments masked, token patterns redacted) before the model sees them; nothing of the repository runs here.
- A change to the instructions that should reach environments with a recipe already booted adds a revision in `run/recipe-author-version.ts`. It is part of the agent harness: carry eval evidence (`experiments/kody-runtime/recipe-agent`, root `AGENTS.md`).

## Where new code goes
- A new check on written files: `authored-files-policy.ts` (or `authored-recipe-policy.ts` for the recipe), with a spec next to it.
- A new fact: `repository-facts.ts`.

## Tests
- `API_NODE_ENV=test npx jest libs/runtime/api/application/recipe-author` (specs next to the code, a scripted runner and in-memory readers).
