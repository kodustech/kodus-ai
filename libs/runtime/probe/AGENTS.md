# libs/runtime/probe

The typed probes the Run's agent writes and the results the observer returns (ADR-053). A pure domain library of zod schemas: the cell protocol carries them (`protocol/messages.ts` `probe.run`), the gate compares their results, and the planner and the API's external findings validate against them. See [`libs/runtime/README.md`](../README.md) "probe".

## Owns
- The probe kinds and their bounds: `probe.schema.ts` `HttpProbeSchema`, `SqlProbeSchema`, `BrowserProbeSchema` (`BrowserStepSchema`, `BROWSER_STEP_KINDS`), `InternalProbeSchema`, joined in `ProbeSpecSchema` and `ProbeSchema` (with `compare`, `CompareFieldSchema`).
- Which kinds decide a verdict: `probe.schema.ts` `decidesVerdict` (http, sql and browser, all on the observer; shell never).
- The observer's answer: `ProbeResultSchema`, `ProbeEvidenceSchema`, `BrowserStepOutcomeSchema`, `PixelDiffSchema`, `EvidenceRefSchema`.
- What a probe exercised, for people to read: `exercised.ts` `exercisedOf`, `browserStepTargetOf` (from the typed spec only, redacted, at most `MAX_EXERCISED` characters).

## Does not own
- The compare floor of each kind (`effectiveCompare`) and field normalization: `libs/runtime/gate/probe-fields.ts`.
- Coverage of an entry point: `libs/runtime/entry-points/coverage.ts`, from the observer's request log. `exercisedOf` names, it never covers.
- Control-plane expectations (`assertions`): `libs/runtime/contracts/probe-assertions.ts`; they never enter the wire probe.

## Rules and limits
- Every object is strict. Paths never start with `//` or hold a backslash; header names are RFC 9110 tokens, values hold no CR or LF.
- The SQL check is a first filter only (one SELECT/WITH/EXPLAIN/SHOW statement); the guard is the observer's READ ONLY transaction. Its Go copy is `protocol.CheckReadOnlySQL`, held to it by the shared fixtures.
- Browser steps are a closed list: no evaluate, no script (S-31).
- A change here is a protocol change: follow [`AGENTS.md`](../AGENTS.md) "Protocol changes" (dump, `go generate`, fixtures).

## Where new code goes
- A new probe kind or field: `probe.schema.ts`, then the gate's floor in `gate/probe-fields.ts`, the observer in `apps/runtime-cell/internal/observer`, and a fixture in `protocol/fixtures`.

## Tests
- `node node_modules/jest/bin/jest.js --runInBand libs/runtime/probe libs/runtime/protocol` (pure).
