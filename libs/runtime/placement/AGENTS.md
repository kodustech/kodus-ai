# libs/runtime/placement

Which pools may take a claim, and in which order (docs/runtime/host-providers.md §6.2). A pure domain library: the worker's cell directory and its physical-admission path read the pool rows and call `candidatePools` inside the reservation.

## Owns
- `candidate-pools.ts` `candidatePools`: the pools an org may use (its own, and Kodus pools whose admission list names it), minus cordoned and not-scalable ones, minus perRun pools for anything but a Run, minus pools whose isolation label does not satisfy the claim; own first, then weight, then id.
- `boundKeyOfRun`: the key a perRun host's cell is bound to (`run:<org>/<runId>`).
- `PoolView`, `PlacementAsk`, `Placement`.

## Does not own
- Reading pools (`apps/runtime/src/shared/persistence/host-pools.ts`), reserving a cell and recording demand (`apps/runtime/src/shared/persistence/cell-directory.ts`, `apps/runtime/src/shared/admission/physical-admission-directory.ts`).
- Making hosts: runtime-fleet acts on the demand rows.

## Rules and limits
- Pure: no I/O. Placement never calls a provider.
- null means "no restriction": when no pool a controller drives admits the claim, placement is what it was before pools. Static-only installs, self-hosted and hybrid orgs never see a change.
- The bound key carries the org, so two orgs never share a perRun host.

## Where new code goes
- A new rule on which pool may take a claim: `candidatePools`, with a row in `candidate-pools.spec.ts`.
- Org preferences (residency, own-only): a field of `PlacementAsk`, copied into the Run request at trigger time.

## Tests
- `node node_modules/jest/bin/jest.js libs/runtime/placement`; the SQL side in `apps/runtime/src/shared/persistence/cell-directory-pools.integration.spec.ts`.
