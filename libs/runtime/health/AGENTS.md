# libs/runtime/health

The hang detector's rule (docs/runtime/observability.md part 4): for every state that is not final, the longest the code lets a Run, a setup, a claim, a sandbox, an admission request, a DBOS workflow or a cell stay in it. A pure domain library: callers hand it the rows they read and get back the items past their bound. The runtime-worker's maintenance pass (`apps/runtime/src/worker/maintenance/stuck-detector.ts`) and the API's Health screen, Run page and Environment Health use it.

## Owns
- The bounds table: `stuck.ts` `STUCK_BOUNDS`, `STUCK_GRACE_MS`, `SETUP_CEILING_MS`, `SETUP_NO_PROGRESS_MS`, built from `RUNTIME_LIMITS` and the claim ceilings of `libs/runtime/environment`.
- One detector per subject: `stuckRuns`, `stuckSetups` (including the setup queue as a whole), `stuckClaims`, `stuckAdmissions`, `stuckWorkflows`, `stuckCells`, each returning `StuckItem` (ids only).

## Does not own
- Reading the rows: `apps/runtime/src/worker/maintenance/stuck-detector.ts` and `libs/runtime/api/infrastructure/pg-runtime-health.reader.ts`.
- Acting on a stuck item: nothing does. Ending a Run past its limit and releasing a claim past its ceiling are the worker's and the hub's own loops.
- The metric and its labels: `libs/runtime/telemetry/catalog.ts` `STUCK_STATES`, `STUCK_SUBJECTS`.

## Rules and limits
- Pure, and report only: a stuck item becomes an event, a metric and a line on a screen, never a stop.
- `RUNTIME_LIMITS` repeats limits that live in `apps/runtime` (a lib cannot import an app); `apps/runtime/src/worker/maintenance/stuck-bounds.spec.ts` keeps them equal.
- A final state is never stuck. Every state it reports is named in the telemetry taxonomy, so the label is never `other`.

## Where new code goes
- A new bound or state: a row of `STUCK_BOUNDS`, its value in `RUNTIME_LIMITS` (and in `stuck-bounds.spec.ts` when it comes from the app), the state in `telemetry/catalog.ts` `STUCK_STATES`, the table in docs/runtime/observability.md.

## Tests
- `node node_modules/jest/bin/jest.js --runInBand libs/runtime/health` (pure), and `apps/runtime/src/worker/maintenance/stuck-bounds.spec.ts`.
