# libs/runtime/run/adapters

The Postgres side of the Runtime's own stores and the pieces every Postgres store shares. Adapters of the ports in `../run-projection.ts` and `../run-stream.ts`: the runtime-worker and the hub write through them; the product API and worker read through them with the read-only role; the publisher and the API's TypeORM stores reuse `pg-document.ts`.

## Owns
- The Run projection: `pg-run-projection.store.ts` `PgRunProjectionStore` (`runtime.runtime_runs`; `RUN_COLUMNS`, the live-Run unique index `ONE_LIVE_RUN_PER_ENVIRONMENT_SHA`, `checkReadOptions`).
- The latest setup of each environment: `pg-environment-setup.store.ts` `PgEnvironmentSetupReads` (what the API gets) and `PgEnvironmentSetupStore` (the worker).
- The Run stream: `pg-run-stream.store.ts` `PgRunStreamStore` (`runtime.runtime_run_events`, keyed appends written once, events bounded by `RUN_STREAM_EVENT_MAX_BYTES`; rows go after 30 days by `runtime-schema.ts` `applyRetention`); `file-run-stream.store.ts` `FileRunStreamStore` (a local directory, for dev and self-hosted).
- Shared parts: `pg-document.ts` `DocumentTable` (typed columns plus one jsonb rest; column names only from the spec), `pg-sql.ts` `PgSql` and `SqlQuery` (read-only transactions, a server-side timeout per query), `advisory-lock.ts` `lockKey`, `lockCall`, `withTransaction`.

## Does not own
- The tables, indexes and their versions: `apps/runtime/src/shared/persistence/runtime-schema.ts`. Grants of the read-only role: `scripts/runtime/runtime-reader-grants.sql`.
- The API's one read pool: `libs/runtime/api/infrastructure/runtime-read-db.ts`. Lessons: `libs/runtime/blockers/pg-lesson.store.ts`.

## Rules and limits
- Every read and write takes `organizationId` and filters on it in SQL ([`AGENTS.md`](../../AGENTS.md) "Facts and state"). A bounded projection read names a timeout between 1 and 5000 ms (`checkReadOptions`); lists stop at `MAX_RUN_LIST_LIMIT`.
- Only the runtime-worker writes the projection and setups; only the hub appends to the stream. The API is handed reader types, never a store with `upsert`.
- A stream append takes a transaction advisory lock per org and Run before allocating its sequence, so a later event never commits ahead of an earlier one of the same stream.
- An advisory-lock namespace's key scheme never changes once shipped (`advisory-lock.spec.ts` and its integration spec pin them); a new lock adds a namespace.
- A query on a new field needs a typed column, an index in a new `runtime-schema.ts` version and a limit.

## Where new code goes
- A new Runtime store: a `DocumentTable` spec and a reads class apart from the writing class, its table in `runtime-schema.ts`, the grant for the reader role, and an integration spec here.

## Tests
- Unit: `node node_modules/jest/bin/jest.js --runInBand libs/runtime/run/adapters`.
- Postgres: `RUNTIME_IT_DATABASE_URL=<disposable server> API_NODE_ENV=test npx jest libs/runtime/run/adapters` (each spec leases its own database; skipped without the URL or with `SKIP_INTEGRATION=true`).
