# libs/runtime/contracts/views

The response shapes of the product's /runtime routes, types only. The API's use cases build them, and the web (`apps/web/src/lib/services/runtime/contracts.ts`) imports them with `import type`, so a field the API renames or drops breaks the web typecheck instead of drifting.

## Owns
- `environments.ts`: GET /runtime/environments, /environments/:id and its blockers (`RuntimeEnvironmentView`, `RuntimeBlockerGroupView`, `RuntimeMembershipBlockerGroupView`, `RuntimeLearnView`, …), built in `api/application/use-cases/environment-view.ts`.
- `run.ts`: GET /runtime/runs/:id (`RuntimeRunDetail`, `FindingFeedbackView`, `FindingIntentView`, `ProbeRequestView`), built in `get-run.use-case.ts`.
- `kept-checks.ts`: GET/POST /runtime/kept-checks (`RuntimeKeptChecksView`, `RuntimeKeptCheckView`, `RuntimeKeepCheckView`), built in `kept-checks.use-cases.ts`.
- `suite.ts`: GET /runtime/runs/:id/suite (`RuntimeSuiteRunView`: the verdict's fields, the failed tests by whose fault they are, the shards, how the specs were chosen), GET /runtime/environments/:id/suite (`RuntimeEnvironmentSuiteView`) and the usage report's `RuntimeSuiteUsage`, built in `api/domain/suite-view.ts`. It declares `RuntimeSuiteSelectionView` itself instead of importing the Runtime's report type, which would pull the selection rules into the web build.
- `lessons.ts` (`RuntimeLessonView`), `settings.ts` (`RuntimeSettingsView`, `RuntimeRepositorySettingsView`), `cells.ts` (`CellRegistrationTokenView`).

## Does not own
- Building a view, and access checks: the use cases in `libs/runtime/api/application/use-cases/`, which re-export these types from their old paths.
- The web's tolerant reading of an older API: `apps/web/src/lib/services/runtime/contracts.ts`.

## Rules and limits
- Types only, and every import here is `import type`: the web's isolated build does not copy these files' dependencies.
- A view names ids and fields the caller may see; it never carries a token, a secret value or raw repository text.
- These types depend on `api/domain`, `blockers`, `run` and `libs/runtime-publish/domain`; a view never adds a value import.

## Where new code goes
- A new response view: a file here, the use case that builds it, and the web type derived from it.

## Tests
- No runtime code. `npx tsc --noEmit -p tsconfig.json` and the web typecheck catch a broken shape; the use cases' specs in `libs/runtime/api/__tests__` check the values.
