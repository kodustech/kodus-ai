# libs/runtime/contracts

The shared vocabulary and the product↔Runtime contracts, defined once and imported by every side: the API and the product worker, the runtime-worker, the hub, the preview edge, the web (types only) and the protocol's Go constants. Pure schemas, constants and signing helpers. See [`libs/runtime/README.md`](../README.md) "contracts".

## Owns
- Vocabulary: `enums.ts` (expose kinds, blocker kinds, verdicts, finding kinds and intents, VM health, sides, claim states and `assertClaimTransition`, consumers, triggers, check conclusions, cell owners, recipe paths, fork policies).
- Commands that change Runtime state: `runtime-commands.ts` schemas, `runtimeCommandRoute` (Run lane or control lane), `runtimeCommandOutboxMessage`.
- Internal HTTP contracts between the worker and the product: `run-plan.ts` (`checkPlanSubmission`), `planner-source.ts`, `model-turn.ts`, `recipe-author.ts`, `setup-repo-tokens.ts`, `env-session.ts` (signed requests), `sandbox.ts`, `preview.ts` (grants, cookies, tunnel tickets, settings), `external-findings.ts`.
- Evidence: `evidence.ts` keys, signed URLs and upload grants; `evidence-s3.ts` and `sigv4.ts` for an S3-compatible store.
- Kept checks (docs/runtime/kept-checks.md): `kept-check.ts`, the check a Run receives (`KeptCheckSchema`, `keptCheckProbe`), its outcomes and stale reasons, and the limits (`MAX_KEPT_CHECKS_PER_REPOSITORY`, `KEPT_CHECKS_BUDGET_MS`, `KEPT_CHECK_RESULTS_RETENTION_DAYS`).
- Shared bounds and shapes: `limits.ts`, `env-int.ts`, `machine-size.ts`, `isolation.ts`, `workspace.ts`, `authored-files.ts`, `browser-exploration.ts`, `probe-assertions.ts`, `recipe-validation.ts`, `egress.ts`, `trace-context.ts`.
- Derived ids and digests that never change once shipped: `derive-id.ts` (pinned by `apps/runtime/src/shared/derived-ids.golden.spec.ts`).
- Cell registration tokens: `cell-token.ts`; refusal of public dev secrets in production: `production-secrets.ts` `assertProductionSecret`.
- Response views of the product's /runtime routes: `views/` ([its AGENTS.md](views/AGENTS.md)).

## Does not own
- The cell protocol's bodies: `libs/runtime/protocol`. Probe schemas: `libs/runtime/probe`. Outbox messages of a Run: `libs/runtime/run/run-messages.ts`.
- Where the API writes a command (`runtime-run-enqueuer.service.ts`, the use cases) and where the worker applies it (`apps/runtime/src/worker/commands`).

## Rules and limits
- Pure ([`AGENTS.md`](../AGENTS.md) "Dependency direction"); `crypto` only. It still imports `probe`, `protocol` (`strict-json`, `sandbox`, `messages`), `run` (`run-messages`, `sealed-secret`, `environment-setup`), `gate` (a type) and `entry-points` (a type), so a new import from those must not close a cycle.
- A command carries no plain token: the schemas require sealed ones.
- Shared vocabulary is added in `enums.ts` and derived elsewhere, never redeclared.
- The evidence key is built on the server from the authorized Run; only the step id, side and type come from outside, each from a closed set. An env_upload's `input` objects are keyed the same way under the env session's id (the worker draws their step ids). Read URLs last at most 5 minutes, upload grants at most 15.
- `testing.ts` (`InMemoryCellTokenStore`) is a test double: not in the barrel, never imported by production code.
- `runtime-commands.ts`'s header comment still says every command goes on the runtime_run queue; `runtimeCommandRoute` sends all but setups to the control queue.

## Where new code goes
- A new command: its schema and name in `runtime-commands.ts`, its route, the worker's handler, and the README "Queues" note if its lane is new.
- A new response view: `views/`, never next to its use case.
- A constant the Go cell needs: export it here and render it in `protocol/scripts/go-constants.ts`.

## Tests
- `node node_modules/jest/bin/jest.js --runInBand libs/runtime/contracts` (pure; `sigv4.spec.ts` uses the AWS examples).
