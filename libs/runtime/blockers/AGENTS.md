# libs/runtime/blockers

What blocked an environment and what fixes it (docs §4, ADR-015, ADR-018): the deterministic classifier that turns what the cell and the worker saw into a typed card, the lessons that remember a fix that worked, the one LLM step of the learn loop, and the one-field recipe edit a fix applies. Domain rules, used by the runtime-worker's setup and Run workflows (`apps/runtime/src/worker/setup/`, `worker/run/report.ts`), the API's Environment Health and Health screen, and the web's labels.

## Owns
- The classifier: `catalog.ts` `classifyBlocker`, `classifyBlockerWithRule`, `BLOCKER_RULES` (the order is the policy), the card types (`ClassifiedBlocker`, `BlockerFixView`, `FixAction`, `RecipeChange`). The rules themselves: `rules/` ([its AGENTS.md](rules/AGENTS.md)).
- Lessons: `lessons.ts` `deriveLessons` (born only from a clean boot right after a blocked one, with a change a catalog fix names), `lessonsFor`, `lessonIdFor`.
- The learn loop's LLM step: `hypothesis.ts` `HypothesisSchema`, `parseHypothesisAnswer`, `MAX_HYPOTHESES_PER_BLOCKER`; the model picks one typed change among candidates computed from the evidence.
- The recipe edit: `recipe-edit.ts` `applyRecipeChange`, `lineDiff` (one field under `services.compose`, every other byte kept, refused if loading both versions shows any other difference).
- Lessons in the Runtime Postgres: `pg-lesson.store.ts` `PgLessonReads` (the API, read-only role) and `PgLessonStore` (the runtime-worker).

## Does not own
- Blocker kinds and `SECURITY_VIOLATION_SIGNATURE`: `libs/runtime/contracts/enums.ts`.
- Running the learn loop, boots and lesson writes: `apps/runtime/src/worker/setup/` (`learn-loop.ts`, `lesson.store.ts`).
- Grouping cards for a screen: `libs/runtime/api/application/use-cases/environment-blockers.ts`.

## Rules and limits
- Deterministic rules only; an unknown stays unknown and ends at `fallbackRule`, which always reads.
- A title or fix is a template filled with checked identifiers (an env name, a host, a service, a port), never repository text (S-23).
- The LLM only chooses: no shape carries a value, a command, an `egress.allow` or a setup step, and every choice must be among the computed candidates (S-20, S-40). An env var's value is the catalog's `testValueFor`, never the model's.
- Every YAML load uses `protocol/yaml-limits.ts` `UNTRUSTED_YAML`.
- `pg-lesson.store.ts` is a Postgres adapter inside a domain module; it takes a `SqlQuery`, never a pool of its own.

## Where new code goes
- A new card: a rule in `rules/`, its place in `BLOCKER_RULES`, a pinned case in `__tests__/classify-blocker.pinned.spec.ts`, and its signature in `telemetry/catalog.ts` if it is set whole.
- A new kind of fix the learn loop may try: `FixAction`, a `HypothesisSchema` shape with its candidate check, and `applyRecipeChange` if it edits the recipe.

## Tests
- `node node_modules/jest/bin/jest.js --runInBand libs/runtime/blockers` (pure; fixtures in `__tests__/fixtures`).
- The lesson store: `libs/runtime/run/adapters/pg-environment-setup-and-lessons.integration.spec.ts`, with `RUNTIME_IT_DATABASE_URL`.
