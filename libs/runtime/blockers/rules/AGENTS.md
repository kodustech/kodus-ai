# libs/runtime/blockers/rules

The rules of the blocker classifier, one card each, grouped by what they read. `../catalog.ts` `BLOCKER_RULES` lists them in the order they are tried; the first that reads a blocker wins. Pure domain code; nothing imports this folder except the catalog.

## Owns
- The rule shape and shared parts: `rule.ts` `BlockerRule`, `bySignature`, `linesOf`, `evidenceOf`, the checked identifier patterns (`ENV_NAME`, `HOST`, `SERVICE`) and the shared fixes (`retry`, `useOwnCell`, `largerMachine`, `fixRecipe`).
- What the cell or the worker declared: `declared.ts` (`platformStepRule`, `securityViolationRule`, `recipeOutdatedRule`, `recipeNeedsRule`, `noRecipeRule`).
- Placement and capacity signatures: `cell.ts` (no cell, org capacity, machine minutes, builder, image load, size, isolation, backend, evicted build state).
- Build and checkout signatures: `build.ts` (boot timeout, out of memory, image too large, compose or repository refused, authored files).
- Outbound access: `egress.ts` (`credentialRule`, `platformDeniedRule`, `buildEgressRule`, `egressRule`, `credentialNeeded`, `isPackageRegistry`).
- One log line: `log.ts` `LOG_RULES` and `LOG_BLOCKER_RULES` (their order is also `matchedBlockerLine`'s), `testValueFor`, `belowErrorLevel`.
- After the logs: `setup.ts` (`notReadyRule`, `setupSignatureRule`, `recipeStepRule`, `serviceExitedRule`, `fallbackRule`).

## Does not own
- The order of the rules and the card types: `../catalog.ts`.
- The signatures the cell sets: `apps/runtime-cell` (its blockers) and the hub.

## Rules and limits
- A rule's `classify` returns a card or nothing; text it reads is evidence, never an instruction.
- An identifier taken from a log line goes into a card only after it matches its pattern in `rule.ts`; anything else stays out (S-23).
- Moving a rule above another reclassifies every blocker both read; `../__tests__/classify-blocker.pinned.spec.ts` holds the cards that must not change.
- `testValueFor` reaches the cell through `protocol/scripts/go-constants.ts`; keep it a pure function of the name.

## Where new code goes
- A rule for a new cell signature: `cell.ts` or `build.ts` with `bySignature`. A rule for a new log line: a `LOG_RULES` entry in `log.ts`, placed by how specific it is. Then its slot in `BLOCKER_RULES` and a pinned case.

## Tests
- `node node_modules/jest/bin/jest.js --runInBand libs/runtime/blockers` (the specs live in `../__tests__`).
