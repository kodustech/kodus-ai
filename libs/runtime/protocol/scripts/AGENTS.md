# libs/runtime/protocol/scripts

The generators that carry the TypeScript protocol to the Go cell, run by hand from the repository root. Nothing in production imports them; `../generated-go.spec.ts` imports `dump-json-schema.ts` and `go-constants.ts` to check the checked-in output.

## Owns
- `dump-json-schema.ts` `generatedFiles`, `GENERATED_FILES`: writes `apps/runtime-cell/internal/protocol/schema/protocol.schema.json` (from `envelope.ts` `protocolJsonSchemas`) and `apps/runtime-cell/internal/protocol/constants_gen.go`; `--check` writes nothing and exits 1 when either is stale.
- `go-constants.ts` `renderGoConstants`: the constants, patterns, bounds and name lists the cell compiles in, each read from the TypeScript export that owns it (hello features, recipe and secret patterns, machine size and authored-file limits, the preview id, traceparent, telemetry secret shapes, `testValueFor`).
- `dump-recipe-schema.ts`: writes `../recipe.schema.json` from `recipeJsonSchema`.
- `recipe-contract-runo.ts`: runs the recipe fixtures through Runo's parser (another repository, on Bun) for ENV-08.

## Does not own
- The schemas and constants themselves: `../`, `libs/runtime/contracts`, `api/domain/secrets.ts`, `blockers/rules/log.ts`, `telemetry/telemetry-guard.ts`.
- Go types from the schema: `go generate ./internal/protocol/` in `apps/runtime-cell`.

## Rules and limits
- A value rendered into Go is imported from its owner, never retyped here. A pattern Go would read differently or not compile is refused (`generated-go.spec.ts`).
- The generated files are never edited by hand.

## Where new code goes
- A new constant the cell needs: export it from its owner, add it to `renderGoConstants`, regenerate, and use the generated name in Go.

## Tests
- `node -r ts-node/register/transpile-only -r tsconfig-paths/register libs/runtime/protocol/scripts/dump-json-schema.ts --check`, and `node node_modules/jest/bin/jest.js --runInBand libs/runtime/protocol`.
