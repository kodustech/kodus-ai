# libs/runtime/entry-points

What a diff can change at runtime and what a probe actually reached, decided by parsers and never by a model (docs §9.8, ADR-044, S-32). A pure domain library run in the runtime-worker's Run workflow (`apps/runtime/src/worker/run/run-orchestrator.ts`) and by the planner's import graph. See [`libs/runtime/README.md`](../README.md) "entry-points".

## Owns
- The entry points of a diff: `extract.ts` `extractEntryPoints` (`http_route`, `job`, `cli`, `dependency_surface`, `unmapped`), `routesServedBy`, `changedLines`, the truncation marker `DIFF_TRUNCATED_MARKER_PATH`.
- Which handlers a changed line outside every handler reaches: `helper-reach.ts` `helperReach`. Route tables of Remix and React Router: `route-table.ts` `routeTableRoutes`.
- Coverage from the observer's request log: `coverage.ts` `routeShapeOf`, `requestMatchesEntryPoint`, `coveredEntryPoint`.
- A diff with nothing to test: `no-effect.ts` `noRuntimeEffectOf`, `noEffectReason`, `codeChangedLines` (comments and layout only, documentation; JS/TS through the TypeScript parser, small lexers for Go and Python).
- The link from a finding to the code: `diff-ref.ts` `diffRefOf`, `firstAddedLine`.
- The changed lines the cell measures: `executable-lines.ts` `executableChangedLines` (added code rows of JS/TS files, new-side numbers; no comments, blank lines, tests or documentation; at most `MAX_EXERCISED_FILES` files and `MAX_EXERCISED_LINES_PER_FILE` lines each).

## Does not own
- Routes of files the diff does not touch but that import a changed one: `libs/runtime/planner/import-graph`.
- The probe's label (`exercised`): `libs/runtime/probe/exercised.ts`.
- What a missing verdict does to the Run: `libs/runtime/run/run-state.ts` `decideRunVerdict`.

## Rules and limits
- Pure; imports the `typescript` package as a parser only. Nothing of the repository is executed.
- Anything the extractor cannot map is `unmapped`, which keeps the Run partly tested. A truncated diff becomes `unmapped:diff-truncated`, which no probe settles ([`AGENTS.md`](../AGENTS.md) "The gate fails closed").
- Coverage comes from requests the observer sent on both sides, never from the agent's label.
- `added: true` only for a route an added line declares and no removed line declares.
- `noRuntimeEffectOf` is certain or answers `undefined`: an unknown language, a missing head, a base it cannot rebuild or a side that does not parse goes the usual way.

## Where new code goes
- A new framework's routes: `extract.ts` (and `route-table.ts` for a route-table file), with a case in `extract.spec.ts`; the same convention in `planner/import-graph/routes.ts` when files that import it should reach it.
- A new language for no-effect: its lexer in `no-effect.ts`, with `parsedLanguage`.

## Tests
- `node node_modules/jest/bin/jest.js --runInBand libs/runtime/entry-points` (pure).
