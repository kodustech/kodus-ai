# libs/runtime-publish/domain

The publisher's rules, ports and wording: where a Run publishes, when a delivery may publish, which comment and check it writes, what the PR reads, and what the Run page says about it. Pure functions and interfaces with their DI tokens, used by `application/` in the product worker and by `libs/runtime/api` in the API (Run target at enqueue, Run page, skipped-trigger reply).

## Owns
- The Run target: `run-target.ts` `RunTarget`, `runTargetOf` (from the `RuntimeRunRequested` the product enqueues), `sameRunTarget`, `RunTargetConflictError`, the `RunTargetStore` port.
- Publications and their claims: `runtime-publication.ts` `RuntimePublication`, `canClaim`, `refusalState`, `hasVerdict`, `CHECK_STATUS_RANK`, `PUBLICATION_LEASE_MS`, the `PublicationStore`, `PublicationReader` and `PublicationRedriveStore` ports.
- One comment per PR and environment: `pull-request-comment-slot.ts` `PullRequestCommentSlotStore`, `COMMENT_SLOT_LEASE_MS`; `publish-environment.ts` `publishEnvironmentOf`, `checkNameOf`, `commentMarkerOf`.
- The redrive policy: `publication-redrive.ts` `isFinalPublication`, `storableRequestOf` (256 KiB, check summary dropped first), `nextRedriveStep`, `hasFallback`, `REDRIVE_AFTER_MS`, `MAX_REDRIVE_ATTEMPTS`, `REDRIVE_BATCH`; `runtime-publication.ts` `isStaleForRedrive`.
- What reaches the PR: `render-runtime-comment.ts` (`renderProgressComment`, `renderReportComment`, `renderCheckOutput`, `renderBareCheckOutput`, `renderSuggestionReply`, `renderUndeliveredReportComment`, `renderUndeliveredCheckOutput`, `partlyTestedReasons`, `code`, `runtimeLinks`, `RUNTIME_COMMENT_MARKER`); `render-skipped-trigger.ts` `renderSkippedTriggerReply`, `skippedTriggerReplyKey`, `skippedTriggerMarker`.
- What the Run page says was published: `run-publication-view.ts` `runPublicationViewOf`.
- What the publisher needs from the product: `runtime-publish.ports.ts` (repository resolver, code management, checks, comment author, suggestion resolver, metrics, preview offer, `CHECKS_PLATFORMS`, `KODY_RUNTIME_CHECK_NAME`); `pull-request-observation-gate.ts` `RuntimePullRequestGate`.

## Does not own
- Running a delivery (target check, claim, slot, platform calls): `application/`.
- SQL, the broker and the product services behind the ports: `infrastructure/` and `RuntimePublishModule`.
- The verdict and the report's fields: `libs/runtime/run`; the verdict labels of the web: `apps/web`.

## Rules and limits
- No I/O, no Nest, no driver: types from `@libs/core` and `@libs/runtime/*` only (plus `ASKED_RUNS_REACHED_DETAIL` from `libs/runtime/api/application/asked-runs.ts`).
- Every string from the Runtime goes through `code()` (one line, no backticks, 120 characters, in a code span); links only to the dashboard (`runtimeLinks`).
- No raw id reaches the PR: an environment key and a skipped-trigger marker are digests.
- A check key moves only forward (`canClaim` with `CHECK_STATUS_RANK`); a `skipped` row is never claimed again.
- The Run page never shows a failure message: only the skip reasons in `SHOWN_SKIP_REASONS`.
- The primary environment keeps `environment_key = ''`, the legacy marker and the bare check name, so older comments stay edited in place.

## Where new code goes
- New wording on the PR: `render-runtime-comment.ts`, with a case in `render-runtime-comment.spec.ts` (snapshots in `__snapshots__/`).
- A new skip reason of `@kody runtime`: `SKIPPED_TRIGGER_REPLIES` in `render-skipped-trigger.ts`; the trigger in `libs/runtime/api` names the reason only.
- A new port: `runtime-publish.ports.ts`, bound in `../runtime-publish.module.ts`.

## Tests
- `API_NODE_ENV=test npx jest libs/runtime-publish/domain` (pure, no services).
