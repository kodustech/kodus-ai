# libs/runtime-publish/infrastructure

The publisher's adapters: the broker consumer and the redrive cron that drive the use cases, the product-Postgres stores behind the domain's store ports, the product readers behind its other ports, and the OpenTelemetry metrics. They run in the product worker; the API uses the target and publication stores and the Run page reader (`libs/runtime/api/runtime-api.module.ts`). `RuntimePublishModule` (`../runtime-publish.module.ts`) binds them.

## Owns
- Deliveries from the Runtime: `runtime-publish-requested.consumer.ts` `RuntimePublishRequestedConsumer` on `RUNTIME_PUBLISH_QUEUE`, channel `RUNTIME_PUBLISH_CHANNEL`, errors to the shared RabbitMQ handler (delayed retry, then dead letter).
- The redrive tick: `runtime-publication-redrive.cron.ts` `RuntimePublicationRedriveCron` (`RUNTIME_CRON_SCHEDULES.publicationRedrive`, never two sweeps at once in one process).
- `runtime_publications`: `typeorm-publication.store.ts` `TypeOrmPublicationStore` (atomic `claim` as one conditional UPDATE, else INSERT … ON CONFLICT DO NOTHING; `hasPublishedVerdict`, `findStale`, `reserveRedrive`, `giveUp`) and `TypeOrmPublicationReader` (the API's org-scoped, bounded read, without the stored request).
- `runtime_pr_comments`: `typeorm-comment-slot.store.ts` `TypeOrmCommentSlotStore` (lease upsert keyed by org, repo, PR and environment key; writes only under the holder's lease).
- `runtime_run_targets`: `typeorm-run-target.store.ts` `TypeOrmRunTargetStore` (Nest, the API's writer and the worker's reader) and `pg-run-target.store.ts` `PgRunTargetStore` (the same semantics over a plain `pg` pool, for the dev e2e scripts in `apps/runtime/src/e2e`).
- The TypeORM entities: `runtime-publication.models.ts` `RUNTIME_PUBLICATION_MODELS`, `runtime-run-target.model.ts` `RuntimeRunTargetModel`, registered in `libs/core/infrastructure/database/typeorm/entities.ts`.
- Product readers: `integration-config-repository.resolver.ts` `IntegrationConfigRepositoryResolver` (the org and team's REPOSITORIES config), `pull-request-suggestion.resolver.ts` `PullRequestSuggestionResolver` (the review's comment id from the product's `pullRequests` record), `product-preview-offer.reader.ts` `ProductPreviewOfferReader` (`runtime_settings.preview`, off without a valid `RUNTIME_PREVIEW_DOMAIN`), `platform-comment-author.ts` `PlatformCommentAuthor` (the token's account, and the GitHub App id).
- Metrics: `otel-publish.metrics.ts` `OtelPublishMetrics` (`PUBLISH_METRIC`: outcome, duration, redrive, stuck).

## Does not own
- The rules of a claim, a slot or a redrive: `domain/` (`canClaim`, `isStaleForRedrive` are the rules these queries implement).
- The tables' schema: the product migrations `MoveRuntimeProductStoresToPostgres2026111200000000` and `AddRuntimePullRequestCommentEnvironment2026111300000000`.
- The queue, exchange and binding names: `libs/runtime/run`.

## Rules and limits
- The stores' SQL must keep the semantics of the domain rule and of the in-memory double in `../testing.ts`; a change touches all three.
- The Run page's reads filter by the org in the query (`TypeOrmPublicationReader.listForRun`, `RunTargetStore.get` with a `RunTargetScope`). The publisher reads the target by `runId` alone: the org comes from that row, never from the message.
- A `RunTarget` is written once: the same target again is a no-op, another one is `RunTargetConflictError`.
- The Runtime's own database users cannot write these tables; they live in the product Postgres.
- Every replica runs the cron; `reserveRedrive` is what keeps two replicas off the same row.

## Where new code goes
- A new column: a product migration, the entity, the store's column table (`PUBLICATION_COLUMNS`, `SLOT_COLUMNS`) and a case in `typeorm-publication.stores.integration.spec.ts`.
- A new metric: `PUBLISH_METRIC` and the README's Metrics section; labels from closed sets only.

## Tests
- Unit: `API_NODE_ENV=test npx jest libs/runtime-publish/infrastructure`.
- Postgres (opt-in, `RUNTIME_IT_DATABASE_URL`, skipped with `SKIP_INTEGRATION=true`): `typeorm-publication.stores.integration.spec.ts`, `typeorm-run-target.store.integration.spec.ts`, `pg-run-target.store.integration.spec.ts`, with `--runInBand`.
